외부 게이트 리뷰 요청문을 만든다. 대상 리뷰: $ARGUMENTS (예: "13차 리뷰 8건 대응")

읽는 쪽이 사람이 아니라 **다른 LLM 리뷰어**다. caveman 의 통찰(기계가 읽는 텍스트는
밀도가 곧 품질)을 여기에만 적용한다 — 수사·재진술·완충 문장을 빼고 검증 가능한
사실만 남긴다. 사용자용 보고서에는 이 압축을 쓰지 않는다.

## 필수 요소

1. **대상 커밋 SHA** (리뷰어가 exact HEAD 를 fetch 해 검증한다) + 브랜치
2. **검증 숫자**: 전체 테스트 결과, strict smoke 결과 — **방금 실행한 출력에서**
   가져온다 (기억 금지). dirty 완화를 썼으면 밝힌다
3. **발견별 대응**: 발견 번호 → 무엇을 어디서 고쳤는가(`파일:함수`/검사 이름) →
   회귀 테스트 이름. 리뷰어가 준 반례는 그것이 이제 어떤 검사에 걸리는지 명시
4. **닫지 않은 것**: 신뢰 경계로 남긴 것과 그 이유. 숨기면 다음 라운드에서 더
   비싸게 돌아온다
5. **판단이 갈릴 수 있는 지점 → 명시적 질문**. 우리가 리뷰 의도와 다르게 해석했을
   수 있는 선택(예: 자기치유 vs 명시적 거부)은 되돌릴 수 있다고 적는다
6. **실측 첨부**: validator 검사 목록, tolerance 정책 등 리뷰어가 요구한 항목은
   실제 실행 출력을 붙인다
7. **다음 실행 계획**: GO 시 명령 순서와 보존할 증거 목록

## 형식 규칙 (기계용)

- 발견별 대응은 **표**로. 산문 문단 금지
- 경로·검사 이름·테스트 이름은 backtick 으로 정확히
- 같은 말 반복 금지. "말씀하신 대로", "감사합니다" 류 완충 제거
- 우리 주장에 근거가 없으면 주장하지 않는다 — "실측" 이라고 쓸 거면 그 출력을 붙인다

## 절차

1. 직전 리뷰 문서(`degradation-degeneracy/docs/1x_CODEX_*.md`)와 그 이후 커밋
   로그를 읽는다
2. 발견 ↔ 커밋/파일/테스트 매핑을 만든다 (빠진 발견이 없는지 대조)
3. **검증 명령을 지금 실행**하고 출력을 인용한다
4. 초안을 스크래치패드에 쓰고 사용자에게 파일로 전달한다 (저장소에는 리뷰
   왕복이 끝난 뒤 `docs/` 에 정리해 넣는다)

## 주의

요청문은 증거가 아니다 — 리뷰어가 재실행해 검증하는 것을 전제로 쓴다. 따라서
재현 가능한 명령을 적고, 우리 환경에서만 되는 것은 그렇다고 밝힌다.
