## 4. E1 의 규칙 — 결과를 보기 전에 지금 고정 (실행 중 바꾸지 않는다)

### 4-1. 단일 원점 · 단계 예산 (C4-E 단계 3 h = 10,800 s)

| 경계 (원점 t0 = `run` 시작 · monotonic) | 값 | 넘으면 |
|---|---|---|
| prep (identity · sha · 적재 · 대조 · 계획 — 작업자 시작 전) | t0 + 900 s | 작업자를 시작하지 않고 멈춘다 |
| 측정 마감 (`supervise` 의 measure) | t0 + 9,000 s | 신규 시작 중지 · 진행 중 호출 중단 |
| grace (terminate → join) | 60 s | kill |
| 기록 마감 | t0 + 9,900 s | 미완 기록으로 닫는다 |
| 단계 끝 | t0 + 10,800 s | — |

- reserve = 10,800 − 9,000 = **1,800 s** (중단 · 정리 · 기록 · 끝 대조).
- 기대 경과 ≈ 35–45 분 [산술 · C5 단가 5.113 ms × 최대 작업자 404,500 평가 ≈ 2,068 s + 초기화 · 기록 · v2 §3 의 추정 · 보증 아님].
- fetch (반입) 는 원점 전 별도 단계다 (§7 · 300 s).

### 4-2. 호출당 상한

시작한 호출의 경과가 **1,800 s** 를 넘으면 전역 중지한다 (v2 §3). 그 호출은 STARTED_INTERRUPTED, 나머지는 상태대로 기록한다.
GA 호출 (평가 100,000) 에서는 평가당 18 ms 를 넘으면 걸린다 [산술 · C5 단가의 약 3.5 배].

### 4-3. 비용 중단 규칙 (비용만 · 결과값 0)

| 항목 | 정의 |
|---|---|
| 기준 통계 | 완료 호출 (termination `returned`) 마다 c_i = wall_i / n_eval_i. 기준 m = **위쪽 중앙 순서통계** (오름차순 정렬 뒤 0-기반 index ⌊n/2⌋ — C5 표기와 같다) |
| 최소 표본 | **8 호출** — 그 전에는 판정하지 않는다 |
| 판정 창 | 누적 (완료된 `returned` 호출 전부) · tick 마다 다시 계산 |
| 투영 | 작업자 w 마다 R_w = (아직 시작하지 않은 배정 호출의 기대 평가 합 + 진행 중 호출의 max(기대 평가 − 관측 진행, 0)) × m |
| 경계 | now_rel + max_w R_w > **9,000 s** (측정 마감) 이면 전역 중지 "비용 중단 (투영)" — 남은 계획이 마감 안에 끝나지 않는다는 뜻이다 |

- 기대 평가는 C4-0a 계획의 산술 (pop × 세대 × seed) 이고 한도가 아니다. 실측 `n_eval` 과의 차이는 호출 행에 이미 기록된다 (`n_eval_minus_expected`).
- [산술] 첫 판정 무렵이라면 m 이 C5 단가의 약 4 배 (≈ 20–22 ms · 판정 시각에 따라) 를 넘어야 걸린다 — 심한 감속만 잡는다.
- 이 규칙은 과학 결과를 고르는 데 쓰지 않는다. X · F · G 는 판정 입력에 없다 (snapshot 정의 · 대조 r_3).

### 4-4. 자원 (감시 표본 · C5 · C4 v2 §3 계승)

RSS 표본 합 ≤ 4 GiB · 새 산출 ≤ 1 GiB (본체 · 기록 합산 · 끝에 다시 잼) · 디스크 여유 ≥ 5 GiB (실행 직전 다시 잼) · 두 감시기 freshness (C4-0A-N3).
동시 실행 금지 (CPU 4 독점) · 작업자 4 · BLAS 스레드 1.

### 4-5. 중지 조건 — 하나라도 걸리면 그 자리에서 멈추고 미완 기록을 보존한다 (재시도 0)

### 4-6. 자료 결속 (7-1 의 정신 — 실제 소비 바이트)

### 4-7. 판정

- **COMPLETE** = 아래 셋을 모두 만족할 때다.
  - 66 호출 모두 COMPLETED 행이다. termination `returned` 와 그들 util 의 지역 오류 (`error`) 는 따로 센다.
  - C4-0a 의 기록 필드 (§40) 가 모두 있다.
  - 끝 감시 파일 · 원천 sha 가 그대로다.
- 이 중 하나라도 어긋나면 **INCOMPLETE** 이고, C4-A 를 시작하지 않는다 (v2 §2).
- COMPLETE 는 코드 경로 재실행 완료일 뿐이다 (부속 A §6-1). 자료 · 목적 UNFIT 이나 P0 의 PRIOR_INCOMPATIBLE 을 통과시키지 않는다.

## 9. 밝힐 것

1. **감시 모듈 (닫힌 파일) 을 고친다.** 선택 인자 하나이고 기본 동작은 그대로다. 호출당 상한과 비용 규칙을 감시 밖에서 걸 방법이 없다 (작업자가 fork 프로세스라
   부모의 감시 루프 안에서만 시작 시각 · 진행 수를 본다).
2. **원자료를 다시 반입한다.** 컨테이너가 바뀌어 사라졌다. P0 와 같은 고정 커밋 · 같은 sha 이고, 다른 출처는 쓰지 않는다.
3. **util 은 고정 커밋의 원본 (`3c19e45e…`) 을 쓰자고 권한다** — P0 · C5 와 같다. 보존 사본 (`bdf78273…`) 과는 끝 줄바꿈 1 바이트만 다르다. 사본을 쓰면 반입 파일이
   하나 줄지만, 오류 위치 판정의 util 경로가 P0 · C5 와 달라진다.
4. 비용 규칙의 입력인 기대 평가는 산술이다 (실측 n_eval 과 다를 수 있음). 비용 추정은 C5 단가 기반이고 보증이 아니다 (C5 는 3.11.15 환경).
5. 노트북과 다른 점 둘 (C4-0a §40-4) 은 그대로다 — 호출마다 깊은 사본 · case 순 실행.
6. 지역 오류 (그들 util 의 예외) 도 "완료 행" 으로 세자고 권한다. 코드 경로 재실행의 관측 결과이기 때문이다. 다만 returned 와 따로 센다 (§11-4).
7. RED / GREEN 은 C4-0 전체로 각 8 회가 된다 (E0 을 더해서).
8. 이번 요청은 검토자의 사전 검토 전이다.
