# 회신 F 수용 보고 — 무엇을 고쳤고, 무엇을 아직 못 하나

전부 수용했다. **반박은 하나뿐이고 그건 당신 쪽이 아니라 우리 도구 문제였다** (아래 P0).
아래는 ① 무엇을 실제로 바꿨나 ② 바꾸다 막힌 것 ③ 새 질문 순이다.

## P0 — **메타데이터가 틀린 게 아니었다. 도구가 창을 안 잘랐다**

당신 지적:

> R2b의 `prod 100 ps, tmax 100`과 `50–200 ps` 분석창은 동시에 성립할 수 없다.
> 실제 궤적이 100 ps라면 늦은 창이 존재하지 않고, 200 ps라면 메타데이터가 틀렸다.

**셋째 경우였다.** 궤적은 진짜 100 ps 고 메타데이터도 맞다.
`msd_diffusive_check.py --scan` 의 창 목록이 **고정 리터럴**
`[(2,50),(10,50),(25,100),(50,150),(50,200),(100,200)]` 이라, tmax=100 궤적에서
`(50,150)` 과 `(50,200)` 이 **둘 다 50–100 을 잰 뒤 서로 다른 라벨로 출력**됐다.
값이 같으니 화면에서는 *"두 창이 일치한다"* 로 읽혔고, R2b 의 `c 15.07` 이
**같은 숫자를 두 번 센 것**이었다.

고쳤다 (`d1a64d2e`):
- 창을 tmax 로 자르고 중복 제거. **버린 개수를 화면에 찍는다**(조용히 흡수하지 않는다).
- 최대 lag 이 궤적의 **70 %** 를 넘는 창은 `!` 로 표시하고, 그 lag 의 시간원점이
  거의 없다는 경고를 같이 낸다 (He 2018 의 30–70 % 권고). **자르지는 않는다** —
  자르면 늦은 창 구제가 아예 막힌다.

⇒ R2b 표는 `UNRESOLVED` 로 표시했고 물리 해석을 떼어냈다.
**당신 판정("고치기 전 해석 금지")이 맞았고, 원인만 달랐다.**

## 1. R1 — 수용. `D_inc` 를 주 판정축으로 넣었다

당신이 준 축을 그대로 구현했다 (`tools/ionic/msd_diffusive_check.py`, selftest 46→52):

```
D_inc(t1,t2) = [MSD(t2) − MSD(t1)] / [6(t2 − t1)]
```

**합성 검증이 우리 게이트 폐기의 가장 깨끗한 근거가 됐다.**
`MSD = 3.0 + 0.6t` (즉 c=3 Å², D=0.1 Å²/ps **정확**) 을 넣으면:

| 창 | 2-50 | 10-50 | 25-100! | 50-100! |
|---|---|---|---|---|
| β | **0.72** | 0.82 | 0.91 | 0.93 |
| c [Å²] | 3.00 | 3.00 | 3.00 | 3.00 |
| **D_inc** | **0.100** | **0.100** | **0.100** | **0.100** |

β 는 게이트 창에서 0.72 로 **탈락**인데 D_inc 는 모든 창에서 **참값을 정확히** 준다.
"낮은 β 는 D 가 틀렸다는 증거가 아니다" 가 한 줄로 보인다.

**문구도 고쳤다** (당신 교정 그대로):
- ~~"완벽히 Fickian"~~ → **"포화된 빠른 운동이 더해진 장시간 정상확산 모형"**
- ~~"동전던지기"~~ → **"현 운영점에서 50 % 거짓탈락률을 보이는 보정되지 않은 게이트"**
- B 가 LPSOCl 600 K 를 **정상이라 증명하지 못한다**는 한계를 문서 본문에 박았다.
- 판본 A(절편 0)는 원자 MSD 게이트의 보정값으로 **쓸 수 없다**고 명시.

### ⚠ 여기서 막혔다 — **D_inc 의 오차막대**

당신 권고: *"미분은 시끄러우므로 실제 구현은 서로 겹침이 적은 구간 기울기와
block/seed bootstrap CI가 낫다."* 앞의 절반만 했다. 두 가지가 안 풀린다.

**(Q1) 겹치는 창을 어떻게 할 것인가.** 현재 창 목록은 심하게 중첩돼 있다
(`2-50` 과 `10-50` 의 상관이 +0.97, 유효표본 n_eff≈3.2 로 우리가 이미 측정했다).
**서로 겹치지 않는 사다리**(예: `2-25 / 25-50 / 50-75 / 75-100`)로 바꾸는 게 맞나?
그러면 각 칸의 통계가 얇아지는데, 중첩 창의 가짜 일치보다는 나은가?

**(Q2) MTO 곡선에서 bootstrap 을 어떻게 하나.** 이게 진짜 막힌 곳이다.
MTO 는 겹치는 시간원점을 평균한 것이라 **lag 점들이 서로 강하게 상관**돼 있다.
lag 점을 재표집하는 순진한 bootstrap 은 CI 를 **과소평가**할 게 뻔하다.
후보 셋 중 어느 쪽인가, 아니면 넷째가 있나?
- (a) **시드 수준** bootstrap — 우리는 시드가 3–4 개뿐이라 CI 가 매우 거칠다
- (b) **궤적 시간 block** bootstrap — block 길이를 무엇으로 잡나(케이지 상관시간 τ? 최대 lag?)
- (c) **이온 수준** bootstrap — 이온끼리는 집단 홉으로 상관돼 있어 이것도 독립이 아니다

## 2. R2 — **철회했다. 당신 지적이 우리 의심보다 정확했다**

우리가 걱정한 것은 `n=9` 와 `β·n_hop 의 얽힘`이었는데, 당신이 지목한 **분모 내생성**이
훨씬 결정적이었다. 우리 자료로 재계산해 확인했다:

| 상관 (n=9, Spearman) | 값 |
|---|---|
| **ρ(n_hop, 평균 D)** | **+0.95** ← 사실상 같은 양이다 |
| ρ(평균 D, CV) | **−0.73** ← n_hop 을 평균 D 로 바꿔도 재현된다 |
| ρ(n_hop, CV) | −0.78 ← 우리가 주장한 값 |
| ρ(sd D, CV) | −0.47 ← 분자만 쓰면 약해진다 |

sd(D) 는 5.4 배, mean(D) 는 9.1 배 범위라 **CV 가 분모에 더 끌린다.**

`predicts` · `He 재현` · `홉 수가 원인` 을 CSV 헤더·kb 카드·glossary·대시보드에서
전부 지우고, 당신이 준 허용 문구로 교체했다. 변수도 *MSD-derived displacement proxy* 로
읽으라고 주석에 박았다.

### (Q3) `N_eff` 를 실제로 세려면 — 최소 요건이 뭔가

당신 처방: *"D와 독립적으로 실제 사이트 전이를 세고, 되튐·연속된 집단홉을 보정한
`N_eff` 가 held-out 조건의 seed 분산을 예측하는지 봐야 한다."*

우리는 **12런의 `traj.xyz` 를 갖고 있어서 셀 수는 있다.** 그런데 사이트 정의가 문제다.
LPSCl 계열은 argyrodite 라 Li 자리가 **48h/24g 로 부분점유**고 무질서가 있어서,
이상 격자 자리로 투영하면 자리 하나에 여러 이온이 겹치거나 비는 구간이 생긴다.

- (a) **참조 격자 자리 투영**(48h/24g 이상위치, Voronoi 할당) 이 우리 무질서 계에 쓸 만한가?
- (b) 아니면 **자리 정의 없이** — 변위 임계(예: 최근접 Li–Li 거리의 절반)를 넘는
      단조 이동을 홉으로 세는 쪽이 나은가? 임계 선택이 결과를 좌우하지 않나?
- (c) 되튐 보정은 **dwell-time 분포에서** 하나, 아니면 back-jump 를 직접 세서 빼나?
- (d) held-out 검정을 하려면 조건이 몇 개나 필요한가? 우리는 지금 9개(3계 × 3온도)뿐이다.

## 3. R3 — **여기가 지금 제일 급하다. 800 ps 런이 이미 돌고 있다**

당신 회신을 받기 **전에** 3×3×1 (558원자) · 600 K · **prod 800 ps** · 1시드를 걸었다.
`~41 h` 남았고 궤적을 저장 중이다. 목적은 "큰 셀의 `c` 증가가 통계 부족인지 진짜인지".

그런데 당신이 이렇게 적었다:

> `3×3×1` 은 이방 복제이므로 scalar `L` 과 `m/6` 도 자동으로 정당화되지 않는다.
> 수송이 등방인지 방향별 MSD 로 먼저 확인해야 한다.

**맞는 지적이고 우리는 그걸 안 했다.** 그래서:

**(Q4) 이 런을 살릴 수 있나?** 궤적이 저장되므로 끝난 뒤 **방향별 MSD 로 사후 분해**할 수
있다. 그걸로 충분한가, 아니면 **3×3×1 이라는 셀 자체가 크기 시험에 부적격**이라
`2×2×2`/`3×3×3` 등방 확대로 다시 가야 하나? (등방 확대는 원자 수가 훨씬 커져 비용이 몇 배다.)

**(Q5) 방향별 D 를 어떻게 보고하나.** 3×3×1 은 c 축만 복제가 없다. `D_xx·D_yy` 와 `D_zz` 를
따로 내면 되나? 그리고 **작은 셀과의 비교**는 같은 방향끼리만 해야 하나
(작은 셀은 세 방향이 다 짧다)?

**(Q6) aspect-ratio 대조를 어디에 걸까.** 당신이 *"짧은 방향만 늘린 aspect-ratio 대조"* 를
권했다. 우리 작은 셀의 최소 수직폭이 **5.67 Å** 다. 그럼 다음 런은 **`1×1×3`**(짧은 축만)
이 맞나? 그게 `3×3×1` 과 짝이 되면 "크기" 와 "형상" 을 가를 수 있나?

**(Q7) 공통 유한크기 인자 검정의 최소 설계.** 당신 식

```
Δ_s(T) = ln[D_large,s(T) / D_small,s(T)]
Ea,large − Ea,small = −k_B · dΔ_s/d(1/T)
```

대로면 **최소 2계 × 2셀 × 2온도(600·1000 K) × 3시드 = 24런**이다. 큰 셀 런이 하나에
~40 시간이라 GPU 한 대로 **수 주**다. 이보다 싼 설계가 있나? 예컨대
- 시드를 큰 셀에서만 줄이고 작은 셀에서 늘리는 비대칭 배분
- 3온도 대신 2온도로 시작하고 비선형이 의심될 때만 확장
- 한 계(LPSOCl)만 먼저 완성하고 공통성 가정은 그 뒤에 검정

**(Q8) 1/L 외삽은 인용 금지로 내렸다.** 다만 실무적으로 *"큰 셀도 아직 −16 %"* 같은
말을 아예 못 하게 되는데, **셀 수렴이 안 됐다는 것만 말하는 정직한 표현**이 뭔가?

## 4. R4 — 수용. NEB 중단하고 saddle 선별로 간다

당신 권고대로 3×3×3 NEB 를 **체크포인트 후 일시중지**한다.
(`Fmax 0.451` = 문턱의 9배, iter 당 7.2 h, 같은 계 앵커가 it83 → 최대 3주.
게다가 GPU 49 GB 중 **41.4 GB** 를 물고 있어 그 머신에 다른 걸 못 건다.)

그리고 당신이 덧붙인 것이 결정적이었다:

> VASP 는 엄격한 전이상태 검증에 `EDIFFG ≤ −0.025` 를 제시한다.
> 따라서 현재 목표 0.05 는 선별용으로는 가능하지만 최종 인용 장벽에는 다소 느슨하다.

⇒ **3주를 더 써도 인용 가능한 수치가 안 나온다.** 이게 중단 결정을 굳혔다.

**(Q9) 이식 절차의 구체.** 1단계 *"2×2×2 의 endpoint·saddle 국소 변위를 3×3×3 에 이식"*
에서, 셀이 다르므로 변위장을 **어느 반경까지** 옮기나? 이동 Li 와 1배위권만? 2배위권까지?
그리고 나머지 원자는 3×3×3 의 이완된 완전결정 위치를 그대로 두면 되나?

**(Q10) 우리 계에 특수한 문제.** 이 c→c 경로는 **대칭**이라, 당신 말대로 endpoint 에너지
차만 보는 검사는 정보가 거의 없다. 그럼 2단계 single-point 는 **saddle 하나만** 비교하면
되나, 아니면 경로 위 여러 image 를 같이 봐야 하나?

**(Q11) 금속 NEB 수렴.** Li₃Nd 는 금속이다(우리 fixed-occ nscf 가 갭 미정의로 판정).
당신이 준 `ISMEAR=1/2, SIGMA≈0.2 eV` 는 VASP 규약인데 **우리는 QE(neb.x)** 다.
QE 쪽 대응(`occupations='smearing'`, `smearing='mv'`, `degauss`)에서
같은 취지의 시작점과 `T·S<1 meV/atom` 확인 절차를 어떻게 잡나?

## 5. 아직 손 못 댄 것 (정직하게)

- **modelc/T700 음수 절편(−4.68 Å²)** — 당신 말대로 "비물리" 라고 **버리지 않기로** 바꿨고
  확인 항목(골격 기준 drift 제거·방향별 분해·lag 별 원점 수·`c–m` 공분산)을 기록만 해뒀다.
  **아직 실행 안 했다.**
- **궤적 수준 귀무모형**(OU 케이지 + 사이트 점프로 5–95 % 재보정) — 설계만 적어뒀다.
- **block/seed bootstrap CI** — 위 Q2 가 막혀서 미구현.
- 12런 `traj.xyz` 에서의 **실제 점프 계수** — 위 Q3 가 막혀서 미착수.

우선순위를 준다면 **Q4–Q6(지금 도는 런의 운명) > Q2(오차막대) > Q3(N_eff) > Q9–Q11(NEB)**
순이 우리 쪽 급한 순이다.
