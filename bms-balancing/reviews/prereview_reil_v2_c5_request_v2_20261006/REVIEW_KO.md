# REIL C5 승인 요청 v2 재검토

2026-10-06 · 문서와 연결 코드의 정적 검토

## 판정

**주요 정정 수용. 환경 확인 호출의 승인 범위를 한 번 더 명확히 해야 한다.** 현재 v2의 §10(1)을 그대로 실행하는 것은 권고하지 않는다. 남은 차단 항목은 C5V2-N1 P1 한 건이며, C5 전체 설계나 P0 판정을 다시 여는 것은 아니다.

정정 후 사용자가 구현만 별도로 승인하면 한정 구현·무자료 검증·합성 건조 실행까지 진행하고 멈추는 순서는 적합하다. 실제 비용 측정, 원자료 개봉, 환경 재구축 및 C4는 여전히 별도 승인이다. 이번 첨부 수신이나 본 회신은 그 승인에 해당하지 않는다.

## C5V2-N1 P1 check는 환경 식별만 하는 호출이 아니다

**문서 좌표:** v2 §4-2 118–121행, §5 128–134행, §10(1) 190–192행, §11 202–203행.

v2는 실제 interpreter에서 reil_c6_profile.py check가 통과해야 한다고 정했다. 그러나 그 함수의 실제 호출 연결은 다음과 같다.

| 코드 | 실제 수행 |
| --- | --- |
| reil_c6_profile.py:237–246 | 임시 디렉터리를 만들고 emit(fresh)를 호출한 뒤 새 산출과 기존 봉인을 대조 |
| :222–234 | lock/profile뿐 아니라 cobyqa_options와 sobol을 실행하고 임시 봉인 파일 작성 |
| :149–181, 특히 :170–171 | 고정 옵션으로 합성 이차 함수의 실제 COBYQA minimize 1회 |
| :185–219 | seed 0·1의 unit cube, A0, A1/A2 배열 생성·쓰기; 지원되는 경우 옛 seed= 경로와 rng 경로 비교도 수행 |

따라서 이 check는 설치나 REIL 맞춤은 아니지만, 단순 읽기 전용 환경 식별도 아니다. §10(1)의 정식 Sobol 생성 금지 및 명시된 합성 실행 횟수와의 관계가 불명확하고, 비용 측정 때 “A0 배열만 대조”한다는 설명보다 넓다. 임시 파일이고 끝에 지워진다는 사실로 수행하지 않은 작업이 되지는 않는다.

tests/test_reil_c6_profile.py:114–144가 emit을 가짜로 바꾸고 :147–155가 네 측정 함수를 가짜로 바꾸는 것은 **그 시험 안에서만** 유효하다. 별도 실제 check 명령을 무자료·계산 0 호출로 바꾸지 않는다.

이전 C5 회신에서 “지정 interpreter의 check 확인”을 권고한 부분도 이번 호출 내용에 맞춰 좁혀 정정한다. 이전 권고를 추가 합성 최적화·배열 재생성의 포괄 허가로 사용할 수 없다.

### 권고하는 최소 정정

기존의 “구현 중 정식 배열 생성 금지”와 “파일럿 A0 배열만 먼저”를 유지하는 경로가 가장 작다.

1. **구현 단계:** full check를 호출하지 않는다. 새 C5 코드의 허용 범위 안에서 실제 interpreter/venv, 봉인 파일 해시, 설치 파일·RECORD와 기존 lock, profile, 옵션 값 및 봉인된 구현 파일 식별을 대조하는 환경 식별 경로를 정의한다. 기존 lock/profile 측정 함수를 재사용하되 cobyqa_options(), sobol(), emit(), check()의 실제 계산 경로로 이어지지 않게 한다. 봉인 파일끼리 해시만 맞는 것을 현재 설치 환경까지 일치한 것으로 대체하지 않는다.
2. **측정 단계:** 같은 환경 식별 뒤 §4-1의 A0 seed 0·1 배열만 재생성·바이트 대조한다. 전체 C6 check와 중복 실행하지 않는다. 준비 600초 및 전체 7,200초 안에 포함한다.
3. 전체 C6 check를 실행하지 않았으면 그 필드는 NOT_RUN으로 남긴다. 좁은 환경 식별 성공을 전체 C6 기능 확인 PASS로 부르지 않는다.
4. 이 연결을 두 허용 파일 안에서 구현·합성 검증하는 것으로 승인 범위를 명시한다. 기존 C6 코드·봉인 수정이나 새 설치가 필요하면 별도 승인이다.

다른 선택으로 full check를 유지할 수도 있으나, 그 경우 합성 최적화 1회·생성할 배열 전체·옛 seed 비교·임시 파일·호출 횟수·시간 상한을 **환경 자기검사라는 별도 작업으로 사용자에게 명시 승인받아야 한다**. 이는 128회 REIL 파일럿의 일부나 C4 정식 봉인으로 세지 않는다. 현재 문구를 두고 “환경 확인이므로 자동 포함”하는 해석은 수용하지 않는다.

두 경로 중 하나를 문서에서 택하면 된다. 이번 검토는 어느 추가 작업도 실행하거나 승인하지 않았다.

## 함께 고칠 표시와 구현 전 고정 항목

다음은 새로운 과학적 설계 결함이나 별도 게이트를 요구하는 항목이 아니다. 같은 정정본에 반영하면 된다.

### 실행 상태와 전체 기록 상태

§3은 RECORD_INCOMPLETE를 명확히 “전체” 상태로 표시했는데, §7 162행은 128행 각각을 “상태 다섯 중 하나”라고 한다. 다음으로 통일한다.

> 지역 실행은 NOT_STARTED / STARTED_INTERRUPTED / RETURNED_REEVAL_INTERRUPTED / COMPLETED 중 하나로 기록한다. 전체 기록 완결성은 별도 필드다. 최종 기록 실패가 앞서 확보한 개별 실행 상태를 덮지 않는다. COMPLETED는 성공 증인이라는 뜻이 아니라 필요한 결과 또는 지역 오류 행의 기록 완료다.

### 무자료 시험의 실제 입력 목록

§5 131행의 “합성 입력 + util 사본만”은 정확하지 않다. test_reil_p0.py:163–195는 보존된 NOTEBOOK_SOURCE_EXCERPTS.json도 텍스트로 읽어 합성 notebook JSON을 만든다. 이 검토에서는 그 발췌 JSON의 내용을 열지 않았으며, 실제 notebook을 여는 경로라고 판정한 것도 아니다.

그 기존 node들을 유지하려면 **이미 보존된 발췌 JSON의 텍스트 읽기**를 경로·식별과 함께 승인 입력 목록에 적는다. 이것도 제외하려면 해당 node를 뺀 정확한 시험 목록을 승인 전에 고정한다. 기존 시험 파일 자체를 자동 수정하지 않는다. tmp_path의 합성 xlsx를 생성·읽는 시험은 실제 LFP_Data.xlsx 개봉과 구분해 허용 목록에 적는다.

읽은 conftest는 감시 대상 모듈을 강제 import하지 않고 sys.modules에서 이미 로드된 것만 본다. 그 사실은 외부 pytest 플러그인까지 무자료라고 증명하지 않으므로, 구현 실행 전에 정확한 interpreter·pytest 경로·cwd·argv·플러그인 로딩 설정을 기록한다. “venv 밖 pytest”가 없으면 설치를 자동 포함하지 않는다.

### 구현 한도의 의미

§5의 3,600초는 **명령 실행 시간 합**이다. 문서 작성까지 포함한 전체 벽시계 상한이라고 보고하지 않는다. 이전 회신이 요구한 전체 벽시계 한도까지 채택하려면 숫자와 원점을 별도로 정하고 승인문에 넣는다. 현재 정의를 유지할 경우에도 측정 구간을 정확히 표시한다.

RED 1회의 명시적 timeout, 환경 식별과 기록 명령의 누적 포함 여부, 50MB 구현 증거 폴더의 기존 존재 시 처리와 fixture 포함 여부를 실행 전 고정한다. 권고는 RED도 최대 600초, 환경/시험/보존 명령을 모두 누적에 포함, 기존 증거 폴더는 재사용하지 않고 중지다. 하위 한도를 전부 최대로 쓰면 누적 상한을 넘을 수 있으므로 누적 한도가 항상 우선한다. 새 설치·재구축·부분 probe·추가 retry를 이 여유에서 만들지 않는다.

### 시간 관측과 오류 분류의 표현

작업자의 /proc Threads는 총 스레드 관측이지 BLAS 스레드 수 자체의 실측이 아니다. 설정값과 관측을 나누겠다는 v2 방향대로 보고한다. 시작/끝 소스 해시 일치는 그 두 경계의 식별이며, 중간의 변경 후 원복까지 탐지했다고 주장하지 않는다.

오류가 util 또는 optimizer에서 시작됐는지 식별할 수 없거나 우리 코드·감시 경로와 구분되지 않으면 구조 오류로 중지한다. broad except와 “traceback 어딘가에 util이 있음”만으로 다음 실행을 계속하는 구현은 이번 오류 우선순위와 맞지 않는다.

## 다음 순서

C5 전체 계획을 다시 만들 필요는 없다. 위 환경 확인 경로 한 건을 선택해 §4-2·§5·§10·§11에 일관되게 고치고, 표시 정정도 반영한 뒤 사용자에게 **구현만** 승인받으면 된다. 좁은 경로와 같은 제한을 유지하는 문장 정정만으로 동일 사전 검토를 자동 반복할 필요는 없다.

구현 후 코드 식별·합성 결과·건조 실행·환경 식별 기록을 제출하고 멈춘다. 실제 128회 비용 측정은 그 결과 수용과 별도 사용자 승인 뒤다. P0를 다시 실행하거나 COMSOL·게이트·PyBaMM 작업을 섞지 않는다.
