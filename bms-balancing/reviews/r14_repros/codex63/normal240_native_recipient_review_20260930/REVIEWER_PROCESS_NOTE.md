# 검토자 작업 범위와 방법

이번 검토는 수신 ZIP의 readonly 검사·안전한 로컬 추출, 검토자가 작성한 audit 스크립트에 의한 데이터 대조 및 새 수신 문서/ZIP 생성이다. 전달받은 Java/Python/PowerShell을 import하거나 실행하지 않았다. COMSOL/JVM·native 계산·받은 시험·외부 발송·설정 변경은0회다.

스프레드시트 분석 지침에 따라 대규모 CSV를 스트리밍하고 Decimal 연산으로 시간/좌표/단위/수치를 대조했다. 문서 작성 지침에 따라 직접 확인한 바이트, 보낸 측 기록, 사용자 전사, 검토자 제안을 분리했다. xlsx나 PDF를 새로 만들거나 그림을 검수하지 않았다.

audit_archives.py, audit_numeric.py, audit_records.py, audit_supplemental.py, seal_review.py는 검토자 작성 도구다. 과거 검토자 도구의 구조를 일부 재사용했으며 받은 생산/분석 프로그램은 실행하지 않았다. 기록 대조 수는 기능 시험 수가 아니다.

자료 읽기 중 큰 JSON 출력이 잘린 경우 필요한 필드로 좁혀 다시 읽었다. 존재하지 않는 요약 파일명 또는 잘못 선택한 JSON 필드 조회는 실제 근거의 누락 판정으로 사용하지 않았다. 번들 런타임 찾기 도구 한 경로가 제공되지 않아 동등한 앱 MCP 조회로 Python 위치를 확인했으며 권한/환경을 바꾸지 않았다.

이번 수치/기록/보충 검산은 PASS했다. 후기 보충 감사 b9fa41 rc0의45건은 단위·로그 표식·별도 최소값 일치·반환 출처/경계 데이터 검사다. 원 sender의 기능 시험 재실행이 아니다.

USER_SUPPLIED_FINAL_RETURN.json은 이번 사용자 메시지의 후속 수신 전사다. metadata와 output 문자열을 구분하며 도구 응답 이후까지의 예산 측정을 주장하지 않는다. 사용자 관측/승인 전사는 감사 가능한 제출 자료로 소비했으나 수신자가 해당 원격 콘솔을 직접 지켜본 것은 아니다.

입력 ZIP은 시작 및 최종 봉인 때 다시 크기/SHA를 확인한다. 새 수신 ZIP에는 리뷰·감사 결과·검토자 코드만 포함하고 대형 받은 원자료는 재포장하지 않는다. 생성 영수증과 자기 자신의 manifest를 자기 해시에 넣지 않는다.
