## 1. 14.38 % 는 아니다 (질문에 대한 확정 답)

`f_AM = 0.847` + freeze-probe 런이 **14.38 %** 에서 멈췄다.  이게 맞는 porosity 인가?

**아니다.  세 축 전부에서.**

### (a) 관례
| | h (µm) | union (MPM 부기) | ε_sphere (DEM 정본) |
|---|---|---|---|
| f_AM=0.847 런 | 29.40 | 14.38 % | **13.09 %** |
| DEM 정본 | 30.28 | 16.88 % | **15.626 %** |

공통 관례로 **−2.53 %p 과압축**.  14.38 을 15.6 옆에 세우는 것이 se-dump "15.93 ✓ / 29.95 ✓"
가짜 일치를 만든 그 오류다 (오차 둘이 상쇄).

### (b) 정지에 꽂은 상수가 틀렸다
`f_AM = 0.847` 은 DEM **벌크 접촉망**의 AM-AM 축하중 몫(Love-Weber)이다.  정지 조건이
요구하는 건 **플래튼 평면에서 얼린 AM 에 얹히는 몫** — 다른 양.  세 독립 경로가 후자를
≈ 0.97 로 지목한다:

| 경로 | 방법 | f_AM | ε_sphere |
|---|---|---|---|
| 하중-분담 모델 | H_AM = 4 GPa (NCM 문헌 앵커) | 0.971–0.980 | **15.66 %** (DEM Δ +0.03) |
| 같은 모델 역산 | DEM 두께 → H_AM = **3.85 GPa** | — | 문헌대 3–6 안 ✓ |
| q=95 기하 jam | 실제 멈춘 응력 0.0098 GPa | **0.967** | 15.44 % |
| 측정 국소기울기 | 정착 두 점 사이 | **0.971** | 15.63 % |
| ← 런이 쓴 값 | Love-Weber 벌크 | **0.847** | **13.27 %** |

0.847 하나만 바깥에 있다.  **14.38 은 틀린 상수를 꽂은 방정식의 정답**이다 (런은 자기 문턱
0.30×0.153 = 0.0459 GPa 를 0.051 에서 정확히 넘겼다 — 규칙은 지켰고 규칙이 틀렸다).

### (c) 애초에 결정 불가
σ_SE(h) 가 두께에 대해 거의 지수적이다 (측정 국소기울기 **1.40 %p 마다 e배**).  f_AM 을
0.847→0.97 로 바꾸면 정지점이 **2.3 %p** 움직인다.  f_AM 을 1 % 수준으로 모르면 이 규칙으로
porosity 를 **산출할 수 없다**.

### 반증 조건 (정직하게)
"14.38 이 맞다" 가 참이려면 DEM 의 15.63 이 과소압축이어야 한다.  real_14 조성에 독립
실험 앵커가 없으므로(우리 앵커 Minnmann 10 % @300 MPa 는 **순수-SE** = 다른 베드) 논리적으로
불가능하진 않다.  다만 현재 증거는 전부 반대편이고, 14.38 을 지지하는 독립 증거는 **0 건**.

## 2. 하중-분담 모델 (`scripts/am_load_balance_jam.py`)

```
P_target = A_supp(h)·H_AM + wallP_SE(φ_SE_local(h))
           └ 기하 (scaffold CSV)  └ 측정 응답곡선
```

* `A_supp(h)` = 평면 h 에서 AM 이 가리는 면적비 — **그림자**(d 를 r 로 캡).  단면적
  `π(r²−(r−d)²)` 은 완전통과 입자(d>2r)에서 0 으로 돌아가 **비단조**가 된다 (실측: q=75 66.5 %
  → q=70 64.4 %).
* `H_AM` = AM 압입 경도, **문헌 앵커** (NCM811 3–6 GPa).  porosity 를 보고 맞추는 값이 아니다 —
  그게 percentile jam(= q 를 DEM 두께에 맞춤)과의 결정적 차이.
* 자유 파라미터는 H_AM **하나**.

### φ_SE_local 색인 (2026-08-05 수정)
`wallP_SE` 를 **두께(µm)로 색인하면 안 된다.**  real_14 곡선(27.7–30.2 µm)을 6mAh 베드
(111–116 µm)에 대면 4배 외삽이 되어 **10케이스 전 행이 0.0000** 으로 붕괴했다.  SE 응력은
SE 가 자기 몫의 공간에서 얼마나 조밀한가에 달린 물성이므로

```
φ_SE_local = V_SE / (A·h − V_AM)
```

로 색인한다.  베드를 통째로 k 배 해도 φ 는 정확히 불변 → 곡선이 베드를 옮겨갈 수 있는 근거
(셀프테스트에 회귀 고정).  마진(φ 0.03) 밖은 **nan 으로 거부** — 조용한 0 이 "SE 항이 통째로
빠진 계산" 을 정상 결과처럼 보고하게 했다.

## 3. ★ 두께로는 시험할 수 없다 (VACUOUS)

### 조건수 비대칭
`A_supp` 는 자유표면에서 가파르다 — real_14 실측 **A_supp 1.5 % ↔ 7.3 % 가 평면 0.56 µm 차이**
(≈ 10 %/µm).  따라서

* **역산** h_DEM → H_AM : 서브미크론 두께 정의 오차를 1/(dA/dh) 배 **증폭**
* **정방향** H_AM → h : 같은 배수로 **억제**

역산으로 10케이스를 판정하니 H_AM 산포 **208 %** (FAIL).  그런데 그 산포는 물리가 아니라
표면 정의 노이즈다 — 10케이스가 전부 `6mAh_real*` 한 가족이고 두께도 111–116 µm(4 %)로
붙어있는데 A_supp 만 4.9× 벌어졌다.  같은 가족 안에서 물리가 4.9× 다를 리 없다.

### 정방향으로 바꾸니 PASS — 그런데 무의미
H_AM = 4 GPa 고정 → median |Δh|/h **0.09 %**, max 0.41 % (문턱 1.5/4 %).  PASS.
**그런데 H_AM 을 0.75~40 GPa (53배) 로 흔들어도 전부 PASS 였다.**

| 베드 | 통과 밴드 | 배수 |
|---|---|---|
| real_14 (30 µm) | 1.5 – 12 GPa | 8× |
| 6mAh (113 µm) | **0.75 – 40 GPa** | **53×** |

원인 둘, 둘 다 구조적:
1. `A_supp` 가 가팔라 h 가 H_AM 에 둔감 (모델을 **쓰기엔** 좋은 성질, **시험하기엔** 최악)
2. 등록한 문턱이 **상대**(|Δh|/h)라 두꺼운 베드에서 그대로 헐거워진다.  같은 0.57 µm 가
   30 µm 베드에선 1.9 %(fail), 113 µm 베드에선 0.5 %(pass) — 사전등록 설계 실수.

⇒ `--h-am-scan` 추가.  통과 밴드가 3배를 넘으면 **VACUOUS** 로 판정한다 — 떨어질 수 없는
시험은 시험이 아니다.

### 그래서 판별축은 압력 하나
고정 H_AM 에서 0.1→0.6 GPa 는 `A_supp` 가 2.5 %→15 % 로 **6배** 움직여야 한다.  기하 jam
(P 무관 상수)은 원리적으로 못 낸다.  **복합체 다압력 DEM 이 유일한 판별실험.**

## 4. pure-SE Heckel 재생성 (덤으로 얻은 것)

USB 에 4압력(100/200/300/400) 원자료가 살아있어 재분석했다.  세 결함이 한꺼번에 드러났다.

1. **D_sphere 가 1을 넘는다** (300 MPa 1.0234 · 400 MPa 1.1811) → `ln(1/(1−D))` 미정의.
   CLAUDE.md 가 이미 적어둔 "dense SE-only 는 ε_sphere 음수 → ε_union 을 쓸 것" 그 상황.
2. **D_union 이 4점 중 1점만 계산됐다** — contact 덤프에서만 렌즈를 읽었기 때문.  강체구에서
   LIGGGHTS 의 δ = rᵢ+rⱼ−dist 는 정확히 기하값이므로 **atom 덤프 좌표만으로** 계산된다
   (`lens_from_geometry`).  ★ 주기경계(`boundary p p f`) 최소상 이미지 필수 — 안 하면 경계층
   접촉 ~2 % 를 통째로 놓친다.  → **4압력 전부에서 contact 경로와 0.00 % 일치** 검증.
3. **contact 덤프는 다 있었다** — 덤프 간격이 atom/mesh 5000 vs contact 10000 이라 스텝이
   안 맞았을 뿐.  ★ 규약: **마지막 contact 를 기점**으로 atom·mesh 를 그 스텝에서 (webapp
   코퍼스와 동일).  기점을 5000 스텝 앞으로 옮겨도 plate_z 가 소수점까지 동일 → 플래튼이
   이미 완전 정지 = hold 프로토콜 정상 동작의 부수 확인.

### 결과 (`docs/data/heckel_pure_se_dem.csv`)
| P (MPa) | ε_union | ε_sphere |
|---|---|---|
| 100 | 30.92 % | +29.68 % |
| 200 | 19.01 % | +13.43 % |
| 300 | **10.08 %** | −2.34 % ⚠ |
| 400 | 3.40 % | −18.11 % ⚠ |

Heckel(D_union 4점): K=0.007257/MPa · A=0.3132 · **R²=0.9653 · P_y=137.8 MPa · σ_y≈46 MPa**
→ CLAUDE.md 값 그대로 재현.  **300 MPa → ε_union 10.08 % = Minnmann ~10 % 앵커**, union
관례에서 확인된 것은 처음.

### 판정 게이트가 "설계대로 동작함" 을 실패로 찍고 있었다
옛 게이트 `(R²>0.97 and 500<P_y<1200)` 의 P_y 구간은 **연화 안 한** LPSCl(H≈850)을 기대한
값이다.  우리 DEM 은 E 를 18× 연화한 것이 **설계**이므로 P_y 가 그 구간에 들어오면 오히려
이상하다.  → 판정을 둘로 분리: ① 직선성 R²≥0.95 (진짜 판정) ② 연화 배수 850/P_y = **6.2×**
(σ_y 축 6.5×) 를 **보고**한다.  문서(CLAUDE.md)는 원래 옳았고 코드가 어긋나 있었다.

## 5. SE 응답곡선 — 출처 소실과 재생성

### 무엇이 문제였나
`REAL14_SE_CURVE` 5점의 실행 조건(`--sub`, `--frames`, `n_grid`)을 **되찾을 수 없었다.**
* V100 전체 검색 → `--compact-to` 산출물 **0 건**
* metrics json 에 `n_grid`·`periodic`·`protocol`·`platen_mach` 는 있는데 **`sub` 미기록**
* 코드 주석의 `384 / sub 160` 은 기록이 아니라 기억

### 재현검증 (2026-08-05, 384/sub160/periodic/gpu-mem 8)
| | 기대 | 실측 | |
|---|---|---|---|
| 두께 | 28.92 µm | **28.92 µm** | ✓ |
| 정착 wallP | 0.1038 GPa | **0.1157 GPa** | **+11.5 %** |

두께가 맞는 건 당연하다 (`--compact-to` 가 기하로 정한다) — 정보는 응력에만 있다.  MPM 은
`random_seed` 고정 결정론이므로 11.5 % 는 런-투-런 노이즈가 아니라 **조건 차이**다.

⇒ **기존 5점 폐기, 11점 전부를 이 조건으로 재생성** (점당 26분, ~4.3시간).
`sub`·`frames_budget`·`compact_to_pct`·`dt`·`arch`·`lateral_box`·`e_se_gpa`·`nu_se`·
스캐폴드 파일명을 metrics 에 추가(커밋 1856a717) → 같은 일이 반복되지 않는다.

### GPU 크래시 — 범인은 `--gpu-mem 24`
| 런 | `--gpu-mem` | 결과 |
|---|---|---|
| 재현검증 ×2 | **24** | 침묵 사망 (트레이스백 없음) |
| smoke 128/192/256/**384** · sub 40/**160** | 8 | 전부 ✓ |

격자도 서브스텝도 무죄 (384 + sub 160 이 87 s 에 완주).  32 GB V100 에서 Taichi 가
`device_memory_GB=24` 를 **선점**하면 CUDA 컨텍스트·워크스페이스 여유가 모자라 커널이 하드
실패한 것으로 보인다.  실제 사용량은 7.2 GB.  ⇒ **`--gpu-mem 8`**.

빗나간 가설 둘을 기록해 둔다 (같은 곳을 다시 파지 않게): SIGHUP(→ setsid nohup 으로도 죽음),
cgroup OOM(→ 한도 56.8 GiB, `oom_kill 0`).

## 6. 다압력 DEM 3런 (진행 중)

`scripts/make_pressure_sweep_decks.py` 로 real_14 덱에서 100/300/600 MPa 생성.

### 덱 규약 (알고 쓴다)
헤더의 `Scale: r×1000, E×0.001, P×0.001` — **`target_press 0.300` = 실제 300 MPa**.
Hertz 접촉이 이 군에 정확히 실린다: 길이 k배 · 영률 1/k배 → `σ' = σ/k`, `δ/R` 불변.
`youngsModulus 0.135e7` = 1.35 GPa × 0.001 = **E_eff (18× 연화)** 가 덱에 박혀 있다.

`coefficientPlasticityDepth` 는 **비율**이다 (SE-SE 0.005 인데 r_SE=0.0005 → 절대길이면
반지름의 10배로 무의미; 비율이면 0.5 %).  무차원이므로 스케일 군에 정확히 실린다 → 소성
분기도 P×0.001 규약과 정합.

### 생성기가 막는 것
* **시드 불변** (79031) — 갈리면 압력효과와 패킹효과가 섞여 실험 무효
* **단위 1000× 가드** — target_press ÷ current-mpa 가 알려진 규약이 아니면 덱을 만들지 않고 죽는다
* **태그 끝 숫자 판별** — `SE_heckel_300` 의 300 은 압력이지만 `real_14` 의 14 는 **케이스 번호**.
  떼면 `post_real_100/` 이 되어 케이스 정체성이 사라진다 → `real_14_P100` 으로 접미
* **주석·print 의 MPa 표기 동기화** — 안 고치면 100 MPa 런 로그가 "COMPRESSION to 300 MPa"
  라고 거짓말한다
* **헤더 주석** — 원본에 MPa 표기가 없는 덱(real_14 이 그렇다)도 생성본이 자기 압력을 밝히게

검산: heckel 100/200/300/400 덱 4장을 300 하나에서 재생성 → **4/4 바이트 동일**.
real_14: 재료·접촉법칙·입자템플릿·삽입 블록 md5 세 덱 동일, 태그·압력 정규화 후
**P300 ↔ 원본 완전 동일**(통제군 성립).

### ⚠ 실행 중 관찰
Slurm 20코어 × 3잡.  `insert = 31,898` vs 원본 **33,289** (−4.2 %).  `insert/pack ...
overlapcheck yes` 는 **MPI 도메인 분할 의존**이라 랭크 수가 다르면 같은 시드여도 삽입 결과가
달라진다.  영향:
* 3점 **내부** 비교 → 무관 ✓ (세 베드 동일 조건, P 만 다름)
* P300 ↔ 기존 real_14 **통제군** → ⚠ 깨짐 (다른 패킹 실현)

완주 후 타입별 개수(1→36, 2→421, 3→32832)로 확인할 것.  다르면 **"3점 내부 비교" 로 한정**해
판정하면 되고 결론은 그대로 나온다 (H_AM 밴드는 세 점 사이의 관계이지 원본과의 절대 일치가
아니다).

### 600 MPa 는 외삽
접촉법칙이 300 MPa 에서 캘리브레이션됐다.  100 은 안쪽, **600 은 바깥**.  H_AM 밴드가
100·300 만으로 좁혀지면 깨끗하고, 600 이 있어야 좁혀지면 그 결론에 "접촉법칙 외삽" 단서를
단다.
