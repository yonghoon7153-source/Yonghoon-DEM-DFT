## 2. 반영

`source_map.md`의 문장별 근거에 따라 cap에서 목표점 경계를 만들지 않는 규칙, U6(c)의 중단·보류, 필수 상자 비교 결측, O7의 뜻, M0 자유도, LA25 측정 상태를 옮겼다. 2D 결과의 조건부 한정, DRD-01 보편 수렴·물리 자격의 미종결, 다른 DRD 한정도 보존했다. 수치 선택과 원문 자체의 과학적 검증은 이번 작업에 포함하지 않는다.

자세한 페이지는 `briefing_ko.md`, 처음 보는 분용 페이지와 DOCX는 `plan_newcomer_ko.md`에서 생성한다. 생성기의 제목 지위 선택만 새 문구에 맞췄다. 종결 가능 문구가 있으면 문서 범위와 전체 HOLD 근거가 모두 있어야 한다. 이전 원고·수식 그림 고정물에는 당시 지위를 유지한다. DOCX 빌더·웹앱 라우트·사이드바는 수정하지 않았다.

도구 환경은 Python 3.12, docx-js 9.6.1이다. 이전 DOCX는 다른 docx-js 판으로 만들었지만 위 서식5개는 바이트 동일하며 새 빌더 재생성 OOXML 대조도 통과했다. 웹 회귀의 Flask·requests는 작업 전용 의존성만 사용했다. 실제 원자료를 보지 않았다. `page_regression.log`는 원 stdout의 CRLF만 LF로 바꾼 사본이며 전후 해시는 `check_results.json`에 기록했다. 저장소 검사 결과도 그 파일로 구분한다. 전체 gate는 반입 담당 절차에 남긴다.

## 4. 전달과 재현

저장소 루트에서:

```text
python -I -X utf8 -B scripts/build_dem_redesign_plan.py --check
python -I -X utf8 -B webapp/test_dem_redesign_plan_v32.py
python -I -X utf8 -B webapp/test_dem_redesign_plan_page.py
```

세 번째는 Flask·requests와 docx-js 실행 환경이 필요하며, 데이터 폴더는 빈 시험 폴더로 지정한다. 실제 서버 시작 명령은 아니다. DOCX 재생성은 기존 `scripts/build_dem_redesign_plan_docx.js` 머리 절차를 따른다. `--out`이 없으면 rc2로 거부한다. 재현 시 기존 산출물을 덮지 않도록 새 출력 경로를 준다. ZIP의 before 스냅샷에 최종 11메서드를 적용하면 rc1이 기대다. 후보에는 rc0을 요구하며, 실패 재현을 수정 통과로 세지 않는다.

새 요약문은 `review_request.md`로 별도 확인 요청한다. 발송은 1저자. 원장 변경 제안은 없고 공유 진행 기록 한 줄만 `ledger_proposal.json`에 제안한다. 원 독립 증거 ZIP·연구 로그는 다시 넣지 않는다.
