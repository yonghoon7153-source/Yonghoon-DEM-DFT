# 새 7:3 RJ 한 잡에 연결할 이력 원판정과 기록 위치

## 이력 원판정 신원

운영 봉인 대상은 A5 수정 핀 `9fd6aa9d3bee`에서 나온 143파일과 A5 러너다. 복원 시 지정하는 `HIST_VERDICT`의 원바이트는 10-14 이력 시험 잡 283122의 기존 반환에서 확정했다. 아래 길이와 SHA256을 보존된 tar와 10-26 제출 준비표에서 대조했다.

|---|---:|---|

이력 JSON은 exit_code 0, H0–H5 각각 PASS, SYN·총힘 출력 시점 PASS, 판 법선 부호 −1이다. 같은 실행 장부에 NP6(H2는 NP4), 작업 283122 및 등록 바이너리 SHA256 `ee2d77261bac9e7fa4e9311c8709e74bf7583a13225a5bc35a791bef9be60a3f`가 있다. 11-20의 A5 현장 점검은 문법 판정과 A3/A4를 읽고 종료했다. 실제 복원 단계에서 읽는 이력 파일과 실행 장부의 **현재 ibb 원위치 바이트**, 새 출력 위치의 점유 여부는 다음 현장 확인 대상으로 남는다.

원 기록은 `docs/reviews/dem_unloading_history_test_20261014/README.md` §0–3과 `docs/reviews/dem_unloading_history_test_20261014/hist_20261014_094731.report.tgz`에 있다. 10-26의 원판정·장부·문법 파일 식별 근거는 `docs/reviews/codex_p1_preflight_complete_20261026/submit-one-rj.plan.sh`에 있다. 이 역사 스크립트는 읽기 근거로만 쓴다.

## 새 작업공간과 판독

- 종전 RJ 323957과 같은 침대의 report, KE 기준, 조건부 선택 자료 및 선행 시도 명부는 보존한다. 별도 안정된 작업루트의 7:3 입력에 등록된 재시작 파일·원자·접촉·판 메시·원 로그·마지막 덱 여섯 개의 바이트만 준비한다. 새 루트에 원 RJ·후속 팔을 복제하면 원 작업과 새 작업의 이력을 혼동하게 된다. 새 시도 장부에는 기존 323957과 새 시도의 관계를 별도로 남긴다.
- 선택 판독 발생 여부는 해당 침대의 UB 유무에 따라 발행 전에 결정된다. 기존 작업루트에 UB가 발견되면 새 독립 작업루트와 선택 문맥을 어떻게 맞출지 먼저 확인한다. 쓰기 가능한 옛 폴더로 이어지는 링크와 새 루트 충돌은 중단 사유다.
- A5 러너만 호출하고 NP6, 기존 병행 실행 검사, 입력 재대조, 원위치 A3, 문법 및 이력 식별을 유지한다. RJ용 원 gate는 잡 종류만으로 ALLOW하므로, 중복 제출을 막는 배타적 시도 기록과 새 작업공간 예약은 외부 제출 블록의 몫이다. 가용 공간·쿼터는 반환 시점을 표시한다. 7:3 입력 여섯 개의 길이 합계는 252,405,453 B이며 전체 출력 용량의 실측값이 아니다.
- 새 생성물은 새 작업루트에서 유지한다. A5 소비자는 증서가 발행된 실제 작업 경로와 완료 영수증을 같이 검사한다. 실행 후 루트 이동·복사로 원위치를 대체하면 후속 판독 근거가 달라진다. 원 출력을 별도로 회수해 확인할 때는 새 잡 장부와 증서 해시, 이력 보고서 해시, RT1/RT2 입력 신원 및 후속 소비 상태를 원위치와 연결한다.
- 운영 봉인 승인과 새 RJ 한 잡의 발사 GO는 별개다. 게이트가 허용해도 후속 U 팔로 자동 진행하지 않는다.

현재 수령 측 현장 조회·새 제출·엔진 실행은 0건이다. 기계가 반환할 메타가 새 루트 부재와 이력 원위치 일치를 확인하면 새 RJ 한 잡의 별도 GO를 요청할 수 있다.
