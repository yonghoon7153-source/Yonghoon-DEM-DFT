## 연결

후보를 빈 경로에 생성하면 `run_unload_a5_candidate.sh`가 생긴다. 이 후보의 7:3 RJ NP6 `--preflight-only` 경로는 기존 입력·엔진·문법 검사를 거쳐 A3 원 위치, 현재 실행 파일 해시, 수정 판독기, A4 영수증, 현재 reference·writer deck·writer log 신원을 대조한다. 기존 `orig_grid`를 호출한 뒤 완료 영수증에 증거 해시를 넣는다. 새 RJ에서 RT 복원과 후속 증서 소비에 쓰는 판독기도 같은 수정 lexer를 사용한다. 배타 발행 시 성공 보고서에 해당 RJ 영수증 접두부 SHA256을 기록하고, 발행된 증서 원바이트의 SHA256을 그 잡의 장부에 남긴다. 다음 관문은 이 두 해시·새 30열/연속성 증거·고유 완료 영수증을 재대조한다. 증서만 발행된 뒤 중단되면 복구 판정은 보류된다. 이전 가드는 옛 진입점에 그대로 있다. 새 진입점의 일반 호출은 별도 1저자 승인 토큰을 요구한다. 운영자는 심사와 봉인 뒤 이 후보의 신원을 다시 확인해야 한다.

A3 수정은 실제 덤프 헤더 끝 ASCII 공백 하나의 문법에 한정한다. 367546의 처음 실패 기록은 유지한다. A4의 네 번째 파일인 역사 복원 덤프는 11-20 고정 영수증으로 식별하며, 생산 사전 점검에서는 새 작업 전에 있는 원 입력 셋을 대조한다. 실행 경로의 자격, 새 RJ의 연속성·증서·압력·물리 결론은 해당 생산 산출물이 있어야 판정할 수 있다.
