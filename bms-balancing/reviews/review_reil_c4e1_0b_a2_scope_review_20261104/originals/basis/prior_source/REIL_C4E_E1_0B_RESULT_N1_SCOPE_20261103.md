## 1. 대조 v8 — l33 의 직접 호출을 fixture 에 묶는다

- **바꾸는 곳:** l33 의 `post()` 한 줄 — `L.postcheck("identity", t.ev, pre, prefix, {…}, env=env, repo=t.repo, records=records, …)` 에 fixture 값을 명시한다.

  (launcher v5 · v6) 는 바꾸지 않는다.
- **선택 (§6 의 3):**
  - **A — `extra=t.extra` · `data=t.data` · `data_files=t.data_files` 를 모두 명시 (권장).** identity 단계에서 `data` · `data_files` 는 읽히지 않지만, 명시하면
    l33 의 직접 호출에 실파일 기본값이 하나도 남지 않아 아래 정적 대조가 "읽히지 않음" 이라는 경로 논증 없이 닫힌다. 동작은 `extra` 만 바뀐다.
  - B — `extra=t.extra` 만 (회신의 최소 정정). `data` · `data_files` 는 "identity 경로에서 읽히지 않음" 으로 분류해 공개한다.
- **정적 재확인 (초안 때 · 실행 0):** v5 · v6 의 `postcheck` 를 따라가 정정한 l33 의 기본 기록이 문제 0 인지 (모듈 · 실행 파일 둘 · pycache · 그룹 · 기한 · 미종료 ·
  오류 · 기록), v5 에서는 1065 줄 근처의 기대 메시지로, v6 에서는 끝까지 통과하는지 다시 본다. RED 예측 줄은 새 바이트로 다시 적는다.
