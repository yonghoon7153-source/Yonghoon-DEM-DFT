## 0. 먼저 — 이 검토가 무엇을 근거로 하나

**코드를 눈으로 읽고 추측한 것이 아닙니다.** 주신 forward model 을 Python 으로
그대로 옮긴 뒤, **같은 파라미터를 넣어 두 구현이 같은 값을 내는지** MATLAB
쪽에서 직접 대조했습니다 (`dd_eval.m` → Python `verify eval --compare`).

4 조합(상태 × Si 소스 × 반쪽전지 소스) × (중간값 앵커 10 + rmse 16)
= **104 개 값이 파일이 담을 수 있는 자리수 안에서 전부 일치**했습니다.
`c_cell` · `E_PE(0.5)` · `E_NE(0.5, 0.25)` 는 마지막 자리까지 같았습니다.

즉 **아래 지적은 "우리가 코드를 잘못 읽어서" 가 아니라 그 모델 자체에 대한
것**입니다. 조건은 `w_dqdv = 0`(현재 기본 설정)입니다.

**고치지 않은 이유**: 저희 쪽 포팅은 결함까지 **일부러 그대로** 옮겼습니다.
고쳐서 옮기면 "규진팀 코드의 성질" 이 아니라 "저희가 만든 다른 모델의 성질"
을 재게 되기 때문입니다. 그래서 발견은 전부 제안으로만 정리했습니다.

## 1. 먼저 — 이미 잘 하고 계신 것

검토 중에 저희가 **잘못 지적할 뻔한 것**이 하나 있어 먼저 적습니다.

`MultiStart` 에 **데이터에서 뽑은 시작점**을 주고 계십니다:

```matlab
gfit = fit_gamma_si(NE_capacity_norm, NE_voltage_raw, ...);
initial5(5) = gfit.gamma_Si_fit;                    % 그 상태 raw NE 에서 γ 추정
...
[initial_combined, ~] = run(ms_pre, problem_pre, 10);   % pOCV 사전 적합
problem = createOptimProblem(..., 'x0', initial_combined, ...);
[fittedParams, ~] = run(ms, problem, 20);               % 그 결과에서 결합 적합
```

γ 초기값을 반쪽전지 실측에서 뽑고, `combined` 를 2 단계로 나눈 것 — **저희
Python 쪽은 이걸 안 하고 무작위 시작만 씁니다.** 이 항목은 제안 목록에서
뺐습니다.

그리고 이건 **추정이 아니라 측정된 결과**입니다. γ 를 0 ~ 0.5 로 21 칸 묶고
양쪽에서 각각 재적합해 봤더니:

- 21 점 중 **18 점은 0.03 %p 안에서 같습니다.**
- 갈린 두 점에서는 **규진팀 쪽이 더 좋은 해**를 찾았습니다.
  γ=0.150 에서 pOCV RMSE 5.52 vs 저희 5.59 mV,
  γ=0.450 에서는 **17.5 vs 40.6 mV** 로 저희가 골짜기를 아예 놓쳤습니다.
- 저희가 이긴 점은 없습니다 (γ=0 에서 0.04 mV 차이는 무승부로 봅니다).

즉 좁은 골짜기를 놓칠 위험은 저희 쪽에 있고, 그 원인이 바로 위 두 줄
(데이터에서 뽑은 시작점 · 2 단계 사전적합)입니다.

## 2. P0 — 답 자체를 바꾸는 것 두 가지

### 2-1. dV/dQ 모델에 연쇄법칙 인자 `1/a` 가 빠져 있습니다

`electrode_balancing_blend.m`:

```matlab
E_cell_model  = @(p, x) E_PE((x - p(2)) / p(1)) - E_NE_blend((x - p(4)) / p(3), p(5));
dv_cell_model = @(p, x) dv_PE((x - p(2)) / p(1)) - dv_NE_blend((x - p(4)) / p(3), p(5));
```

`E_cell` 이 전극 좌표를 `x_e = (x − b)/a` 로 바꾸므로, 그 도함수에는 `1/a` 가
따라와야 합니다:

```
dV_cell/dx = dE_PE/dx_PE · (1/a_PE) − dE_NE/dx_NE · (1/a_NE)
```

지금은 `dv_PE(...) − dv_NE(...)` 라서 **두 항이 각각 `a_PE`, `a_NE` 배만큼
어긋난 채로** 실측 dV/dQ 와 비교됩니다. 실측 확인:

- 합성 선형 예에서 `E_cell` 의 유한차분은 0.875 인데 `dv_cell` 은 1.5 를 냅니다.
- 실제 적합값에서 `a` 가 1.0~1.18 이므로 **7~15 % 의 계통 오차**입니다.

**수정안** (한 줄):

```matlab
dv_cell_model = @(p, x) dv_PE((x - p(2)) / p(1)) / p(1) ...
                      - dv_NE_blend((x - p(4)) / p(3), p(5)) / p(3);
```

**주의**: 이건 **목적함수를 바꾸는 수정**이라 `w_dvdq > 0` 인 모든 결과가
달라집니다. 고치실 거면 pristine 부터 전 상태를 다시 돌리고 전후를 비교해
주세요. `plotting == "all"` 의 `dv_cell_fit` 도 같은 수정이 필요합니다.

> 저희 판단으로는 이게 **가장 우선순위 높은 항목**입니다. 다만 고칠지는
> 규진팀이 정할 일이고, 만약 의도적으로 그렇게 두신 이유가 있다면 알려
> 주시면 저희 문서에 그렇게 적겠습니다.

### 2-2. 목적함수 scale 의 난수에 seed 가 없습니다 — 재현이 안 됩니다

```matlab
n_samples = 50;
samples = lb + rand(n_samples, 5) .* (ub - lb);
...
scale_pocv = lower_half_mean_local(pocv_vals) + eps;
```

`rand` 앞에 `rng` 가 없어서 **같은 데이터·같은 설정으로 두 번 돌리면 목적함수
자체가 다릅니다.** 최적화하는 대상이 실행마다 달라지는 셈입니다.

**실측 (규진팀 코드로 직접)**: `300_0009` · GITT · Si=Li 를 **seed 만 바꿔**
다섯 번 적합했습니다. 데이터·설정·시작점 전부 같습니다.

| seed | a_NE | γ_Si | pOCV RMSE |
|---|---|---|---|
| 0 | 1.080746 | 0.239608 | 7.579 mV |
| 1 | 1.080746 | 0.239604 | 7.579 mV |
| 2 | 1.080759 | 0.239475 | 7.568 mV |
| **3** | **1.087043** | **0.233189** | **7.308 mV** |
| 4 | 1.080881 | 0.239380 | 7.561 mV |

**잔떨림이 아니라 다른 해입니다.** 0·1·2·4 는 서로 붙어 있고 **3 번만 떨어진
곳**에 앉습니다 — 다섯 번에 한 번 다른 답이 나옵니다. 이걸 LAM_NE 로 옮기면
**0.54 %p** 차이입니다 (기준을 고정했을 때). 실제로는 `main_blend_final.m` 이
기준(pristine)도 같은 무-seed 적합으로 구하므로 **분자와 분모가 같이 흔들려
더 클 수 있습니다.**

자동 scale 도 실행마다 달랐습니다 — 화면에 `pocv=0.1173 dvdq=0.4322
dqdv=0.3665` 과 `pocv=0.1095 dvdq=0.3863 dqdv=0.4049` 이 각각 찍혔습니다.
최적화 대상 함수 자체가 매번 다릅니다.

**수정안**:

```matlab
if isfield(fit_params, 'scale_seed'), rng(fit_params.scale_seed, 'twister');
else,                                 rng(0, 'twister'); end
n_samples = 50;
samples = lb + rand(n_samples, 5) .* (ub - lb);
```

그리고 **계산된 scale 세 개(`scale_pocv`/`scale_dvdq`/`scale_dqdv`)를 `result`
구조체에 넣어 저장**해 주세요. 지금은 화면에만 찍히는데, 나중에 결과 파일만
보고는 그 실행이 어떤 목적함수를 썼는지 알 수 없습니다.

### 3-1. 경계 접촉을 결과에 기록 (실패시키지는 말 것)

```matlab
tolb = 1e-6 * max(1, ub - lb);
at_lb = abs(fittedParams(:) - lb(:)) < tolb(:);
at_ub = abs(fittedParams(:) - ub(:)) < tolb(:);
result.active_bounds   = find(at_lb | at_ub)';
result.inference_status = "ok";
if any(at_lb | at_ub)
    result.inference_status = "bound_limited";

            strjoin(string(find(at_lb|at_ub)'), ','));
```

**행을 지우거나 실패시키지 마세요.** 지우면 선택 편향이 생깁니다. 경고와
플래그만 남기고 그 행을 쓸지는 읽는 사람이 정하게 하는 편이 낫습니다.

### 5-2. γ_Si 와 `a_NE` 가 서로를 대신합니다

γ 를 고정하고 나머지 넷을 재적합하면:

|---|---|---|---|

**Si 가 많은 음극과 가로로 늘어난 흑연 음극이 풀셀 전압에서 거의 같아 보이기
때문**입니다. 그런데 `LAM_NE` 는 `a_NE` 에서 직접 나오므로, γ 가 흔들리면
LAM_NE 가 그대로 흔들립니다.

Schmitt 2022 는 본문에서 γ_Si 와 α_an 이 "같은 서명을 남긴다" 고 적어 놓고
그것을 재지 않았습니다 (논문에 identifiability · degeneracy · confidence
region 이라는 단어가 없습니다). 위 표가 그 자리의 첫 숫자입니다.

**제안 #8**: γ 프로파일을 결과에 첨부하는 함수를 하나 두시면, 그 상태의
LAM_NE 가 얼마나 잘 정해진 값인지 한눈에 보입니다. 다만 **오차막대가 아니라
민감도 곡선**이라고 적어 주세요 (아래 5-4).

### 5-3. 모델을 고정해도 답의 폭이 있습니다

`300_0009` · GITT · Si=Li · dQ/dV 제외 · 최적 목적함수의 **1 % 안**
(경계에 안 붙은 정상 적합):

| | 범위 | 폭 |
|---|---|---|
| LAM_NE | 5.89 ~ 9.50 % | **3.60 %p** |
| LAM_PE | 4.91 ~ 7.78 % | 2.87 %p |
| LLI | 15.15 ~ 16.24 % | 1.08 %p |

같은 데이터·같은 모델인데 음극 손실이 6.1 % 인지 9.5 % 인지 데이터가
가르지 못합니다. **이 값들도 "적어도 이만큼" 이라는 하한**입니다.

### 5-3b. `w_dqdv = 0` 을 택하신 판단을 뒷받침하는 것이 나왔습니다

주석에 "0 = dQ/dV 제외(방법3, 0.33C 데이터에서 가장 안정적이었음)" 이라고
적어 두셨는데, 저희 32 조합에서 그 안정성 차이가 숫자로 보였습니다:

| | 24 시작 중 비정상 종료 |
|---|---|
| `w_dqdv = 0` | 5 |
| `w_dqdv = 1` | **8~9** |

그리고 optimizer 개선 전후로 답이 1 %p 넘게 움직인 8 조합 중 **6 개가
`w_dqdv=1`** 이었고, 목적함수가 나빠진 6 조합은 **전부 `w_dqdv=1`** 이었습니다.

원인으로 보이는 자리: `compute_dqdv_rmse_blend` 의 `[v_u, uid] = unique(v_smooth)`
가 모델 전압이 단조가 아닐 때 점을 **조용히 버립니다.** 파라미터가 조금
움직일 때마다 버려지는 개수가 바뀌니 목적함수 표면이 매끄럽지 않습니다.
`peak_weight = 7` 이 그 위에 뾰족함을 더합니다.

**제안**: `unique` 가 버린 점 개수를 세어 경고하시면(예: 5 % 넘게 버리면)
그 적합이 왜 불안정한지 바로 보입니다. 저희 `dd_eval.m` 의
`local_rmse_dqdv` 가 그 두 개수를 이미 돌려주니 그대로 쓰셔도 됩니다:

```matlab
[v_u, uid] = unique(v_smooth);
nuniq = numel(v_u);                                   % 살아남은 점
idx   = (vol_dq_fit >= min(v_u)) & (vol_dq_fit <= max(v_u));
nin   = sum(idx);                                     % 보간 범위에 든 실측 점
if nuniq < 0.95 * numel(v_smooth)
    warning('dQ/dV: 모델 전압이 단조가 아니라 %d/%d 점이 버려졌다', ...
            numel(v_smooth) - nuniq, numel(v_smooth));
end
```

`nin < 5` 면 원본이 `rmse = 1e6` 을 내는데, 그 값이 그대로 목적함수에 들어가면
그 시작점은 사실상 죽습니다. 그것도 같이 세어 두시면 좋습니다.

### 5-4. 다만 — 이 폭은 신뢰구간이 아닙니다

목적함수가 likelihood 가 아니라 RMSE 합이라, "1 %" 같은 상대 문턱은 통계적
의미가 없습니다. 같은 곡률의 함수라도 기준값이 0.01 이냐 100 이냐에 따라
1 % 띠의 폭이 100 배 달라집니다. 진짜 오차막대를 말하려면 **반복 측정으로
잡음 크기를 추정**해야 합니다.

지금은 "분석자가 고른 민감도 값" 이라고 부르는 것이 정확합니다.

## 8. 저희 쪽 한계 (같이 적습니다)

- **상태는 넷을 봤습니다.** 위 본문의 숫자는 주로 `300_0009` 것이지만,
  2026-09-10 에 파우치 네 상태(`100`·`200`·`300_0009`·`300_0147`)를 같은
  설정으로 돌렸고 **폭 순위(LAM_NE 최광 · LLI 최협)가 네 번 다 같았습니다.**
  다만 **절대 폭(%p)으로 말해야** 합니다 — 상대 불확실성으로 보면 분모(최적값)가
  열화와 함께 커져 `100` 사이클에서만 순위가 뒤집힙니다. `100` 에서는 LAM_NE
  구간이 0 을 포함해 **부호도 못 정합니다.** (`FINDINGS.md` §1-10)
- **셀은 여전히 하나입니다.** 원통형 셀도 돌려 봤지만 그 셀들은 저희가 받은
  반쪽전지가 한 번뿐이라 같은 파일을 여러 상태에 복사해 넣었고,
  `c_lit = (a_PE + b_PE − b_NE)·c` 가 `a_PE`·`b_PE` 를 직접 쓰므로 그 대체가
  LLI 폭에 그대로 들어갑니다. 그래서 **대조 실험**을 했습니다 — 파우치를
  일부러 pristine 반쪽전지 하나로 고정해 다시 돌렸더니 LLI 폭이 0.03 ~ 0.20 %p
  밖에 안 움직였습니다. 원통형과의 격차는 2.23 ~ 5.64 %p 이므로 **저희 대체
  탓이 아닙니다.**

  남은 결과를 그대로 전합니다: **파우치와 원통형에서 무엇이 잘 정해지는지가
  서로 반대입니다.** 파우치는 LAM_NE·LLI 로 사이클을 가르고 LAM_PE 로는 못
  가르는데, 원통형은 반대로 LAM_PE 로 가르고 **LAM_NE·LLI 는 100 사이클과
  200 사이클조차 구간이 겹칩니다.** LLI 폭이 10.5 배입니다. 그러므로
  "LLI 는 잘 정해진다" 는 **파우치에서만** 성립합니다.

  ⚠ 저희가 배제한 것은 반쪽전지 대체 하나입니다. 남은 차이가 셀의 물성인지
  **그 셀 pOCV 자료의 잡음·분해능**인지는 안 갈렸습니다 — 원통형 pOCV 의
  계측 조건(전류·샘플 간격·필터 여부)을 알려 주시면 그것도 갈립니다.
  held-out 예측은 여전히 없습니다.
- **dQ/dV 항도 이제 댔습니다.** 본문 숫자는 `w_dqdv = 0` 조건이지만,
  2026-09-10 에 툴박스를 갖춘 기계에서 dQ/dV 항까지 포함해 대조했습니다.
  MATLAB 안에서 툴박스 대 저희 대체 구현이 `rmse_dqdv` **1.78e-12**,
  MATLAB 대 저희 Python 포팅이 네 조합 192 값에서 최대 **4.04e-12** 입니다.
  차이는 `rmse_pocv`(4e-15) < `rmse_dvdq`(2.8e-14) < `rmse_dqdv`(2.9e-12) 로
  커지는데, 두 대조가 독립적으로 같은 곳을 가리킵니다 — **잡음은 `sgolayfilt`
  에서 생기고 dQ/dV 미분이 그것을 증폭**합니다. 답을 바꾸는 크기는 아닙니다.
  §2-1 의 chain rule 은 그 항에도 똑같이 걸립니다.
- **부탁 하나** — dQ/dV 항의 두 함수만은 저희가 **옮겨 적었습니다.**
  `compute_dqdv_rmse_blend` 와 `build_peak_weights_local` 은
  `electrode_balancing_blend.m` 안의 로컬 함수라 파일 밖에서 부를 수가 없어서,
  나머지(`electrode_ocv`·`differential`·`build_blend_functions`)처럼 **그대로
  호출**하지 못하고 저희 쪽에 다시 썼습니다. 그래서 이 두 항목만은 저희 대조가
  "규진팀 코드 ↔ 저희 포팅" 이 아니라 "저희 전사 ↔ 저희 포팅" 입니다.
  아래를 원본과 **눈으로 한 번만** 맞춰 봐 주시면 그 구멍이 닫힙니다.

  ```matlab
  % (1) 피크 가중 — build_peak_weights_local
  w    = ones(size(dq));
  prom = 0.1 * (max(dq) - min(dq));
  [~, locs] = findpeaks(dq, 'MinPeakProminence', prom);
  sigma = sigma_ratio * (max(vol) - min(vol));          % sigma_ratio = 0.03
  for k = 1:numel(locs)
      w = w + (peak_weight - 1) * exp(-((vol - vol(locs(k))).^2) / (2*sigma^2));
  end                                                    % peak_weight = 7

  % (2) dQ/dV RMSE — compute_dqdv_rmse_blend (+ 가중판)
  v_model  = E_PE((x_model - p(2))/p(1)) - E_NE_blend((x_model - p(4))/p(3), p(5));
  v_smooth = sgolayfilt(v_model(:), poly_order, window);   % 3, 11
  dq_model = gradient(x_model(:)) ./ gradient(v_smooth);
  [v_u, uid] = unique(v_smooth);  dq_u = dq_model(uid);
  idx = (vol_dq_fit >= min(v_u)) & (vol_dq_fit <= max(v_u));
  if sum(idx) < 5, rmse = 1e6; return; end
  dq_i  = interp1(v_u, dq_u, vol_dq_fit(idx), 'linear');
  resid = dq_fit_data(idx) - dq_i;
  rmse  = sqrt(mean(resid.^2));                            % 무가중
  % 가중판:  rmse = sqrt(sum(w(idx).*resid.^2) / sum(w(idx)));
  ```

  특히 세 자리를 봐 주십시오. ① `x_model` 격자점 수(저희는 500),
  ② `unique(v_smooth)` 가 **어느 쪽 인덱스**를 남기는지(저희는 첫 번째),
  ③ 가중 RMSE 의 분모가 `sum(w)` 인지 `numel` 인지.
- **질문 하나** — `pOCV` 데이터가 계측기에서 나온 **원자료**인가요, 아니면
  평활·재표본을 한 번 거친 것인가요? 저희가 잡음 규모를 재 봤는데
  (`300_0009`·GITT) σ ≈ **0.0285 mV**, 모델 부적합 ≈ **7.586 mV** 로 비율이
  **267** 입니다. 이 비율이면 "목적함수 1 % 안" 을 신뢰구간으로 바꾸는 절차가
  성립하지 않습니다 — 부적합이 잡음을 압도해서 χ² 기반 구간이 **거짓으로
  좁아집니다.**

  다만 그 267 은 **원자료일 때**의 값입니다. 필터가 걸렸다면 σ 는 하한이고
  비율은 상한이 됩니다. 그리고 저희가 확인해 본 결과 **곡선만 보고는 그것을
  가릴 수 없습니다** (필터된 잡음과 신호의 곡률이 같은 스케일에 있으면
  원리적으로 안 갈립니다). 원자료 export 가 따로 있으면 그 파일 하나만
  주시면 저희가 재겠습니다.
- 목적함수 **총합끼리**는 비교하지 않았습니다. §2-2 의 seed 문제 때문에 애초에
  비교가 불가능합니다. 대조는 **항별로** 했습니다 — `rmse_pocv`·`rmse_dvdq`·
  `rmse_dqdv`·`rmse_dqdv_w` 네 항 각각.
- 저희도 이 과정에서 자체 버그를 여럿 고쳤습니다. 위 숫자는 **고친 뒤** 값입니다.
