## 지원 경로와 구현 계약

이 도구는 일반 로컬 경로를 입력받는 비활성 사본 검증기다. Windows에서는 보통 DOS 경로·상대경로, POSIX에서는 단일 루트 절대경로·상대경로를 사용한다. **Windows extended/device/UNC namespace 표기는 지원하지 않는다.** 두 구분자로 시작하는 표기와 NT namespace 접두사는 플랫폼에 관계없이 거부한다. 슬래시 종류를 바꾼 동등 접두사도 검사한다. 이 정책은 운영 호스트의 경로 자격을 결정하지 않는다.

- `snapshot`, `candidate`, `evidence` 세 인자를 네 모드 모두에서 검사한다. 원래 표기의 namespace 거부는 경로의 존재·동일성·조상 링크를 조회하기 전이다.
- 절대경로 변환 뒤와 `resolve()` 뒤에도 같은 지원 범위 검사를 적용한다. 원래 표기의 링크 검사와 기존 조상 링크 거부는 `resolve()` 전에 유지한다.
- 지원하지 않는 namespace의 공통 사유는 `unsupported Windows namespace path`다. 미지원 원문 입력은 경로 조회·mkdir/write·장치/공유 접근 전에 거부한다. 정규화 단계에서 나타나는 미지원 표기의 재검사는 쓰기 전에 이루어진다.
- namespace 접두사를 지워 일반 경로로 바꾸거나 `samefile()` 한 번으로 미존재 하위 경로를 인증하지 않는다. 일반 경로에서는 기존 동일/양방향 포함 거부와 snapshot 경계를 그대로 적용한다.

소스 변경은 기존 `verify_inactive.py`의 경로 사전 검사에만 있다. candidate43, 자산40, 메타8, 결속/비활성 계약, source inventory, 의존86 및 기존 loader는 재생성·변경하지 않는다. 이전 README·요청·대기 문구는 역사로 남기고 이 문서가 지원 경로와 잔여 상태를 보완한다.

## 시험과 독립 재확인

새 시험은 저자 측이 작성한 로컬 사본 시험이다. Windows extended 경로의 candidate/evidence 양방향, equal/child/ancestor, 아직 없는 build 경로를 실제 로컬 CLI로 확인한다. namespace 음성은 공통 사유와 파일·디렉터리 그래프 불변을 함께 검사한다. 원 verify 반례 뒤 형제 evidence 재검사도 기록한다. 장치·공유 경로는 파일시스템 접근을 차단한 계측으로 사전 거부만 확인하며 실제 장치나 공유에 접근하지 않는다.

같은 새 시험의 수정 전후 신원·실패·오류·호출 수, 기존 일반 경로 회귀 및 loader 회귀는 `verification_summary.json`과 전달 ZIP 원로그에 고정한다. 조건 수·CLI 호출 수·메서드 수·준비14·변이/반복을 합산하지 않는다. 정상 `old`의 옛 메타8 실패는 기대 결과이며 namespace 사전 거부와 별도다.

이번 시험은 Windows 로컬 합성 사본의 확인이다. 실제 symlink/junction 생성, 적대적 동시 변경, 모든 OS namespace/파일시스템 의미론의 인증을 주장하지 않는다. 기존 조상 링크 신호 시험은 mock이며 실제 링크 자격이 아니다. 범용 경로 보안 sandbox나 실제 운영 도구의 자격으로 확대하지 않는다.
