# REIL C5 사전 검토 회신

대상은 `7def9238c8fdac605decc5bf17c1428a93faad1d`의 승인 요청문이다. 첨부 원문과 저장소 바이트는 일치한다(15,765 bytes, SHA-256 `2656ab2bf142ea1ea64245f816cc8c7c4f5b6ac086d1ad28a50961d68bf85cc6`).

**판정: 설계 방향 수용, 승인문 정정 필요. C5 구현·비용 측정 승인 아님.** 셀 #1 선택은 P0 저장 JSON과 맞고, J_V=sqrt(f2), 옵션 8개, 구현 후 정지→별도 측정 승인이라는 구분도 적절하다. 다음 다섯 항목만 문서에서 정리해 달라.

1. **C5-N1 P1 — 봉인 시점 (§4·§9 Q1).** 부속 A의 파일럿 제외 규정은 부속 B의 “첫 지역 실행 전 전체 고정 배열 봉인”을 면제하지 않는다. 기존 등록을 유지하면 첫 실제 파일럿 전에 전체를 봉인해야 한다. 파일럿 사용 배열만 먼저 봉인하려면, 이를 현 규칙에 맞는 해석이라고 하지 말고 결과를 보기 전 별도 사전 정정과 사용자 결정으로 명시한다. 이번 회신으로 배열을 생성하지 않는다.
2. **C5-N2 P1 — 환경 재구축 (§4·§6·§11).** P0에서 특정 새 봉인을 채택한 결정은 미래 RECORD 차이를 일반 허용하는 규칙이 아니다. 기본은 지정 venv의 실제 interpreter·check·lock 결속 확인이며 부재/불일치면 중지한다. 재구축을 포함하려면 설치·차이 수용·변이·예산·횟수를 별도 승인 범위로 명시한다.
3. **C5-N3 P2 — 중단과 자원 (§3·§5–7).** 이미 시작해 시간 초과로 끊긴 실행은 미실행이 아니다. 시작 전/실행 중 중단/반환 후 재평가 미완/기록 완료를 구분한다. 전역 시간·자원 중단은 다음 실행 계속보다 우선한다. 7,200초 안의 준비·측정·소유 작업자 종료·최종 기록 경계, 단계 한도, 종결 여유를 정한다. RSS 1초 표본은 하드 제한이 아니며, 시작·끝 df/du만으로 실행 중 디스크 상한 준수는 확인할 수 없다.
4. **C5-N4 P2 — 오류 분류 (§2·§3·§6).** 예상 x 의존 평가 실패와 구조/IO/메모리 오류를 구분하고 후자는 전역 중단을 우선한다. 독립 재평가 예외는 반환점이 이미 있고 재평가 1회를 쓴 경우다. x·실제 solver termination을 보존하고 재평가 실패를 별도 기록한다. 이를 “반환점 없음/재평가 0”으로 쓰지 않는다. 비유한을 유한 벌점으로 치환하지 않는 방침은 유지하되 solver 처리 성공을 미리 가정하지 않는다.
5. **C5-N5 P2 — 구현 범위 (§5·§10 (1)·§11).** 구현·RED/GREEN·합성 건조 실행·보존의 숫자 한도, 횟수, 시험/명령 집합을 정한다. 건조 실행의 “maxfev 작게”를 수치로 바꾼다. “bms 전체”는 자료 개봉·설치·정식 Sobol 생성이 없는 경로임을 정적으로 확인한 승인 목록으로 한정한다. 재평가 실패·전역 중단·writer 실패·작업자 종료·최종 식별/자원 기록을 합성 시험에 포함한다.

추가 표시 정정: 작업자 4개 설정의 측정 한 번만으로 직렬 대비 병렬 효율을 주장하지 말고 wall/CPU·점유·대기·부하 불균형으로 보고한다. 직렬 시험을 추가하라는 뜻은 아니다.

원문과 P0 실패/누락 기록은 보존한다. 수정본 또는 부속 문서를 작성하고 **사용자가 새 §10 (1)을 승인하기 전에는 구현·시험·자료 개봉·Sobol 생성·환경 재구축·측정을 시작하지 않는다.** 구현 완료 후에도 측정은 별도 승인이다.

이번 검토는 지정 문서·P0 JSON·옵션 봉인·util 157–236행의 정적 대조뿐이다. REIL 원자료·pickle·노트북·COMSOL·시험·맞춤을 실행하지 않았다. C3 출력의 기존 한정 수용과 실행 기록 미완은 유지한다.
