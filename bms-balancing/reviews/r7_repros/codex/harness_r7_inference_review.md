## N7-01 · P2 — 현재 `--old`에도 역사 규칙이 적용되어 다른 정본을 인증

영향: **정본 선택·수치 대조의 의미**. 현재 커밋된 `out/` 수치가 잘못됐다는 발견은 아니다.

위치:

- `scripts/check_u14.py:34`–`:58`: `baseline_for`는 항상 가장 높은 `_vN` 선택.
- `scripts/check_u14.py:115`: 일반 `check(new, old)`도 그 helper를 호출.
- `scripts/check_u14.py:236`–`:245`: 현행 `--old` 디렉터리와 `--old-rev` 추출물이 같은 경로로 들어감.
- `scripts/check_u14.py:248`: 실제로 다른 규칙인데 “compare_states와 같은 규칙”이라고 출력.
- 대조: `scripts/compare_states.py:30`–`:43`의 현행 독자는 `_vN`을 경고하고 제외.

재현 명령:

```text
python harness_r7_inference_repros.py --target <R7/bms-balancing> --case baseline
```

상태 구성은 임시 디렉터리뿐이다. 공개된 `degeneracy_100_Li.json` 스키마로 정상 data/meta A와 B를
만들고, B는 LLI `max`·`span`을 각각 1 %p 높인다(`span=max-min` 유지). A/B의 data/meta는
실제 `read_unit` 검사를 통과한다. `current/`에는 unversioned A와 역사 `_v2` B가 있고,
`rerun/`에는 unversioned B가 있다.

관측:

```text
compare_states 현재 선택 = degeneracy_100_Li.json
현재 LLI span = 0.5736895850554351
새 실행 LLI span = 1.573689585055435
check_u14 --new rerun --old current:
  선택 = degeneracy_100_Li_v2.json
  'compare_states 가 표에 쓰는 것과 같은 규칙'
  '숫자: 정본과 전부 같다'
  rc = 0
```

음성 대조는 `_v2` 하나만 제거한다. 같은 A/B, 같은 명령이 이제 `max`·`span` 차이 2건과 **rc 1**을
반환한다. 그러므로 비교 계산 자체가 아니라 baseline 선택 축이 결과를 바꿨다.

현재 저장소의 `_v2`는 이미 archive로 옮겨졌으므로 커밋된 12개 결과의 동일성 주장은 유지된다.
그러나 R7은 현행 폴더에 역사 sibling이 남았을 때도 독자가 시끄럽게 무시하는 동작을 지원한다.
같은 정상 사본을 재실행 comparator에 주면 다른 정본이 된다. “옛 리비전에만”이라는 docstring은
그 구분을 실행하지 않는다.

최소 수정: `current`와 `historical-revision` baseline 선택을 명시적으로 구분한다. 현행 `--old`는
unversioned 하나만 사용하거나 sibling이 있으면 거부하고, 역사 추출 모드에서만 highest-version을
사용한다. 두 모드 모두 출력에 실제 선택 정책·파일을 적는다. 위 fixture는 현행 모드에서 차이 또는
명시적 거부, 역사 모드에서는 B와 같음을 반환해야 한다. 새 계산이나 원자료가 필요하지 않다.

## R6-06·Q3: 닫힌 것과 남는 문구

실제 `test_c6_06_profile_budget_is_stated_as_it_is_run`과
`test_c6_q3_precision_conflict_is_partial_only_when_the_option_absorbed_a_difference`를 실행해 둘 다 통과했다.

- 네 profile 파일은 각 21행, 총 **84행 전부 `n_tried=25`**.
- metadata의 요청 무작위 시작 수는 네 파일 모두 24.
- 코드의 `best[:4]` + 무작위 24이므로 실제 25회다. SLSQP 등식 프로파일의 3회와 구분된 점을 인정한다.
- `.125/.125` + 느슨한 precision 옵션은 conflict를 기록하고 complete.
- 선언으로는 못 흡수하지만 옵션이 흡수하는 `.125/.126`은 partial. 새 Q3 문구가 이 동작과 맞는다.

문구 개선은 별도로 필요하다:

- `FINDINGS.md:74`: “시작 예산 부족이 아니라”는 예산 충분성 배제까지 나아간다.
- `reviews/R6_LEDGER.md:152`–`:156`: “적어서 움직인 것이 아니다”, “입력 ULP … 야생에서 확인”을 확언.
- 바로 `:158`–`:159`에서는 구판 라이브러리 조합을 몰라 원인은 가설이라고 한정한다.

**25회라는 사실은 '3회라서 움직였다'를 철회할 근거이지 25회가 충분했다거나 실제 차이가 ULP 때문이라는
증거는 아니다.** `--case docs`는 실제 회귀 두 개를 통과시킨 뒤, 매끄러운 합성 목적함수
`J(x)=(x²−1)²+0.2x+2`를 같은 L-BFGS-B로 푼다. 서로 다른 시작 분포에서 각각 25회 모두 성공해도
최솟값은 `1.7975595656551782`와 `2.1974341528582766`으로 다르며, 두 번째 탐색에 시작 하나를 더하면
`1.797559565655261`이 된다. 이것은 **횟수만으로 탐색 충분성을 보증할 수 없다는 논리 대조**다.
실제 전지의 시작 분포·ULP 변화·SciPy 원인을 재현했다고 주장하지 않는다.

권장 대체문: “두 산출의 γ profile은 모두 25회 시작을 사용했다. 그 동일 예산 아래 일부 행이 달라졌으나
차이의 원인은 U16 미확정이다. 보존된 두 실행에서 본문 인쇄 정밀도의 해당 집계는 유지됐다.”
U16의 미해결 자체를 새 발견으로 세지 않고, 그 신고와 모순되는 확정 문구만 바로잡으면 된다.
