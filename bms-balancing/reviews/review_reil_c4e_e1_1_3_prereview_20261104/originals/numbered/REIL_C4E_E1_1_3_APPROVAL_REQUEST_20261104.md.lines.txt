303: ## 10. 밝힐 것 (공개 한계)
304: 
305: 1. **F2 — 장시간 관리:** 세 단계를 셸 도구의 호출에서 떼어 놓으려는 방식이다. 셸 도구 관리자 · 세션 · 컨테이너의 장시간 수명에 대한 영향은 미확인이고, 탐침의
306:    성공이나 분리 명령의 채택만으로 7,200 s · 10,800 s 의 동작을 보증하지 않는다. run 도중 세션 · 컨테이너가 끝나면 run 과 기록을 잃는다 → 멈춤 · 재시도 없음.
307: 2. **잔류 식별:** 표지 (세션 id · pycache 경로 · `<E>` 경로) 밖의 프로세스는 보지 않는다. /proc 관측은 원자적이지 않고, PID 재사용은 시작 시각 대조로 줄일 뿐
308:    없애지 못한다 (E1-0b 요청서 §8 의 17 과 같은 종류).
309: 3. **외곽 도구의 기다림:** wrapper 는 launcher 를 기다리기만 하고 죽이지 않는다. launcher 가 멈추면 wrapper 도 남고, 감시 기한 뒤 R1 이 둘의 그룹을 정리한다.
310: 4. **외부 코드 실행:** E1-3 의 prep 은 받은 `util_LFP.py` (고정 sha) 를 venv 자식 안에서 import · 실행한다. sha 대조가 바이트를 묶지만, 그 코드의 행동을
311:    이 저장소가 검증한 것은 아니다.
312: 5. **두 판정의 관계:** 실행 유효성과 실험 결과는 따로 적지만 독립이 아니다 (§5-3).
313: 6. **읽기 경로:** `add_repo` 는 세션에 저장소를 붙이는 바깥 동작이다 (공개 저장소면 붙이지 않고 프록시가 읽기를 이미 제공한다고 답할 수 있다). 그 응답의 상태
314:    문장만 기록한다.
315: 7. **승인 문구:** run 의 승인 문구는 launcher 의 `REQUEST` 대로 E1-0b 요청서 경로를 인용한다. 이 요청서와 §NN 의 결속은 상태 문서의 승인 기록이 맡는다.
316: 8. **분리 실행 명령의 셸 의미:** POSIX 목록 · `setsid` · `nohup` 의 공개 의미에만 기댄다. 이 환경의 `/bin/sh` 종류 · 설치본의 실제 동작을 이 요청서가
317:    관측한 것은 아니다 — 탐침 (p) 이 그 첫 관측이다.
318: 9. **E1-0b a2 의 범위:** 그 수용은 봉인된 대조 범위의 기능 종결이고, 실제 자료 성공이 아니다 (§101). A2_PROC_01 은 §101 의 문구로만 남는다.
