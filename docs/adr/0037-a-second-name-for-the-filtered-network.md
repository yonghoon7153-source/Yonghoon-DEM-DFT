# ADR 0037 — 웹 필터에 막힌 망을 위해 이름을 하나 더 단다

- 상태: **채택** (2026-09-13)
- 검증: 랩 기계에서 실측 — 아래 "무엇을 쟀나"
- 관련: ADR 0034(우리 VPS 를 앞에 둔다), ADR 0036(test 이름을 그대로 쓴다),
  `tools/vps-setup.sh`, `docs/guides/central-server.md`

## 맥락

VPS 를 세워 `https://test.bmlwork.kr` 을 고정 주소로 만든 날, **학교 안에서만
그 주소가 안 열렸다.** 폰 LTE 로는 열린다.

한양대 웹 필터가 막는다. 장비가 스스로 밝혔다 (평문 80 으로 물었을 때):

    URL:      test.bmlwork.kr/api/health
    Category: newly-registered-domain

`bmlwork.kr` 은 2026-08-26 에 샀다. 등록한 지 얼마 안 된 도메인이라는 이유로
막는 것이고, 시간이 지나면 재분류되지만 그 기준일이 벤더마다 다르다
(30일이 흔하고 90일도 있다).

## 무엇을 쟀나

여덟 번 두드려서 층을 갈랐다. 이 표가 이 결정의 근거 전부다.

| 재 본 것 | 결과 | 뜻 |
|---|---|---|
| `https://github.com` | 200 | TLS 일반은 안 막힌다 |
| `http://<IP>` + `Host: test.bmlwork.kr` | **차단 페이지** | 이름을 본다 |
| `https://<IP>` (SNI 없음) | reset | SNI 없는 TLS 도 끊는다 |
| `<IP>:22` (SSH) | **통과** | 포트를 안 가리는 것은 아니다 |
| `https://test.bmlwork.kr:8443` | reset | **TLS 는 포트를 가리지 않고 본다** |
| `http://193-123-161-75.sslip.io` | **200** | 다른(오래된) 이름은 통과한다 |

즉 이 필터는 **이름**을 보고, **포트는 안 가린다.** 그래서 포트를 옮기는
우회(8443)는 실패했고, 이름을 바꾸는 우회는 성공했다.

`bmlonly` 가 왜 이번엔 안 통했는지도 여기서 갈린다. 예전에 `lhr.life` 가
막힌 층은 **DNS** 였고 `bmlonly` 는 IP 를 손으로 줘서 그 층을 건너뛰는
도구다. 지금 막힌 층은 그보다 위라, IP 를 줘도 손잡기에 같은 이름이 실려
나간다.

## 결정

**같은 VPS 에 이름을 하나 더 단다.** 새 장치를 만들지 않는다 —
`vps-setup.sh` 를 다른 이름으로 한 번 더 돌리면 그만이다.

    sudo bash vps-setup.sh 193-123-161-75.sslip.io <메일>

nginx 가 사이트를 하나 더 갖고, 인증서도 따로 받고, 둘 다 같은
`127.0.0.1:5003` 으로 간다. **터널은 그대로 하나다** — 이름만 둘이다.
`bml share domain` 도 안 바꾼다 (그것은 `bml` 이 확인할 이름 하나를 정할 뿐,
nginx 가 받는 이름과 별개다).

    학교 안 (필터 뒤)   https://193-123-161-75.sslip.io
    학교 밖             https://test.bmlwork.kr
    같은 랜             bmlin 192.168.0.40   (가장 빠르다)

`sslip.io` 를 고른 이유: **등록할 것이 없다.** `193-123-161-75.sslip.io` 는
그 숫자가 곧 그 IP 로 풀린다 — 가입도, DNS 레코드도, 기다림도 없다. 그리고
오래된 도메인이라 "newly-registered" 에 안 걸린다.

## 왜 다른 길이 아니라 이것인가

- **포트 우회(8443)** — 재 봤고 안 된다. 필터가 포트를 안 가린다.
- **`bmlonly`** — 층이 다르다 (위 참고).
- **화이트리스트 요청** — 맞는 길이지만 우리 손 밖이고, 90일 기준이면
  두 달을 기다린다. 넣어 두되 이것에 기대지 않는다.
- **localhost.run 으로 되돌리기** — 된다. 다만 주소가 열 때마다 바뀌는
  그 굴레로 복귀하는 것이고, ADR 0034 가 없애려던 것이 정확히 그것이다.
- **기다리기** — 9월 25일쯤 저절로 풀릴 수 있다. 그때까지 랩이 멈춘다.

## 대가

- **주소가 둘이다.** 사람에게 어느 것을 줄지 한 번 더 생각해야 한다.
  화면이 그것을 안 가려 주므로 [[central-server]] 의 표를 본다.
- **주소가 안 예쁘다.** `193-123-161-75.sslip.io` 는 외울 이름이 아니다.
  대신 등록이 필요 없어서 오늘 안에 섰다. 예쁜 이름이 필요해지면
  `duckdns.org` 같은 데 하나 만들어 같은 절차를 한 번 더 돌리면 된다.
- **인증서가 둘이다.** 갱신도 둘인데, certbot 이 둘 다 자동으로 한다
  (`certbot renew --dry-run` 이 둘 다 시험한다).
- **IP 가 바뀌면 이 이름은 죽는다.** 이름 안에 IP 가 들어 있기 때문이다.
  공인 IP 가 Ephemeral 이므로 인스턴스를 삭제하면 이름을 다시 만들어야
  한다 (ADR 0036 의 Reserved IP 이야기가 여기서 한 번 더 걸린다).
- **8443 을 열어 뒀다.** 쓰지 않게 됐으므로 닫는 것이 맞다 — 안 닫으면
  다음 사람이 그 포트가 무엇인지 몰라 살려 둔다.

## 결과

학교 안 기계는 `bmlout https://193-123-161-75.sslip.io` 한 번이면 된다.
LAN 이 갈려 있든(이 랩에는 `192.168.0.0/24` 가 둘이다), 필터 뒤에 있든
상관없다. `test.bmlwork.kr` 이 풀리는 날 하나로 합치면 되고, 그때까지 이
이름이 랩 전체를 받는다.
