수학적 근거도 이전 경험적 봉인과 다르다. 고정 수동망에서 임의 후보 전위 p의 에너지 U는 참 G의 상계다. 임의 표현된 간선 유량 q에 대해 내부 보존 결손 d, 바닥·위판 총유량 FB·FT, W=Σq²/g를 쓰면, 참 전위가 `[0,1]` 안이라는 성질과 부분합·Cauchy–Schwarz로

`G ≥ max(0, FB−Σd⁺, FT−Σd⁻)² / W`

의 하계를 얻는다(W>0, d⁺=max(d,0), d⁻=max(−d,0)). 0 유량·정상 topology zero는 별도 처분이다. 트리 보정이 **정확히** 보존적이어야 성립하는 식이 아니다. 최종 표현 유량의 결손 여유를 포함하는 것이 핵심이다. `step3_conv_cert.py:427,494,519,541,572`에서 이 구조와 판정 비교를 확인했다. 승인식은 `|Ghat−Gtrue|≤10⁻⁴·Ghat`이다. 위 반례 표의 상대오차 분모 Gtrue와 구별한다.

별도 Fraction 가우스 소거로 참 G를 구한 180개 작은 망 × 후보 3개 = 540개에서 구간 누락 0, ⓓ 통과 192개 중 거짓 합격 0이었다. 이 유한 시험만으로 전칭 정리를 대신하지 않았고 위 증명·반올림 가정을 함께 검토했다.

**영향:** PF2의 same-code 봉인, 단계 간 결과 결합. 정상 수치 함수가 틀렸다는 판정은 아니다.

**자리:** `scripts/rint_r_chain.py:154,617–625,1017–1080`; S0 코드 비교 `:945`.

독립 입력 세 종류:

1. 실제 git 밖 고정 소스 사본에서 HEAD/dirty=None. `code_dirty_problem`·`code_verdict_problem` 모두 통과. 12파일 밖 실제 관련 모듈에는 `ca_ext_cjunc.py`, `additives.py`, `se_material.py`, `lens_geometry.py`, `step4_dyn.py`, `rint_cycle_traj.py`가 있다.
2. Git 조회 모사: HEAD 조회는 성공하고 **status 명령은 rc=128, stdout 빈 문자열**. 현재 `git_identity`는 status 종료코드를 보지 않아 **dirty=False**로 기록한다. 그러므로 저자 제안 “None이면 거부”만으로는 부족하다.
3. chain은 clean HEAD a, runner는 clean HEAD b; runner의 `step3_conv_cert.py`, `ca_ext_svcf.py`, `run_contract.py` 해시만 다르게 놓았다. 실제 same-code/S0/최종 검증 함수가 모두 통과한다. 자기 요약끼리 같다는 비교는 chain↔runner 동일성 검사가 아니다.

**최소 해결:** Git 두 조회의 종료코드·유효 전체 SHA·dirty의 엄격한 False를 검사하고, 미확인을 깨끗함으로 변환하지 않는다. 한 단계 안 chain↔runner의 핀·해당 의존 파일 해시도 대조한다. 또는 사전 고정한 완전 의존성/빌드 manifest를 사용한다. git 밖 12파일만으로는 그 대안이 되지 않는다. untracked import·외부 모듈 출처도 선택한 보장 범위에 포함해야 한다. 절대경로가 같다는 것은 동일 코드의 대체 증거가 아니다.

**재현:** `probes/provenance_probe.py`; `evidence/provenance_probe.json`의 F1/F2. F2는 작성자의 P3보다 **P2**로 평가: 등록 판정의 전제를 직접 깨며 현재 같은-판이라고 주장하고 있기 때문이다.

### RCA2-03 [P2] F8 — S0에서 센 침대와 R에 들어간 침대가 묶이지 않는다

**영향:** s_min·접합 census·못 가른 덩어리 판단을 R 팔에 이식하는 전제. S0 보고서 자체가 잘못 계산됐다는 결론은 아니다.

## 6. C2–C5·C7 — 실행 순서와 핵심 선택

### C2: 단계별 진입

1. **S0 단계 1: 조건부 GO.** 새 SBE 침대의 기하만 읽는다. 원침대·코드·설정·원 보고의 지문을 보존한다. 아직 모르는 R 문턱을 임의 확정할 필요는 없다. 이 회차에서 실침대 실행은 하지 않았다.
2. **⑥ 숫자 탐침: 조건부 GO.** SBE 개발 자료로 반복 수·메모리·비용·계획 상한을 탐색한다. 실제 사용 코드/침대/조건을 기록하고 DBE 결과를 보며 선택하지 않는다. 이것을 최종 등록 판정으로 인용하지 않는다.
3. **계획 하나 봉인.** S0 계획·R 계획의 정확 해시, s_min, 점수상한, 역상폭 상한 또는 `none`, SV 문턱·검사 범위, solver 설정, 시간·중단·재시도 정책 및 입력·코드 귀속을 결과 전에 고정한다. s_min 문서 숫자와 JSON이 둘 다 정본이라면 자동 생성/정확 대조한다.
4. **S0 단계 2: 조건부 진입.** DBE 열람 전에 3번을 끝내고, 실제 새 DBE 입력을 해당 봉인에 연결한다. 단계 2를 본 뒤 s_min·SV 문턱을 바꿔 같은 등록으로 계속하지 않는다. 현재 귀속 결함을 운영상 우연에 맡기지 말 것.
5. **R 런: 아직 HOLD.** RCA2-01–04의 실제 경로 수정/검증, 실행정책 봉인, 새 S0 자료·반복 비용 보충, 작은 정상·음성 끝-끝 증거를 먼저 요구한다. 일정 미달은 진행보고/미식별이며 팔 축소나 문턱 완화로 해결하지 않는다.

### C3: 현재 괄호는 충분한가 / 역할 분리가 필수인가

**같은 셀 그래프에서 간선을 삭제하는 family**에 대해서는 Rayleigh 괄호가 적절하다. RCA2-01의 수치구간을 포함하고, 못 읽거나 걸치면 UNCHECKED로 남기는 조건이다. 큰 위끝이 실제 SV 효과가 크다는 증거는 아니다. 참 다리 영향이 정확히 1인 대칭 두 성분 회로도 `[1,∞]`를 낸다. bypass를 추가한 회로의 위끝은 5.285714285714302였다.

섬유 역할을 나눠 새 DOF·경로를 만드는 표현은 그 삭제 family 밖일 수 있다. **현재 보수적 진단을 실행하려고 반드시 역할 분리판부터 만들 필요는 없다.** 그러나 실물 SDCP 제거의 인과 효과 한 값·넓은 SV 비의존을 주장하려면 현재 괄호만으로 부족하다. 합성 9개에서의 빈도를 실침대 빈도로 말하지 말고, 등록의 “드물게”는 “범위 밖일 수 있음”으로 바꾼다.

각 모서리의 “하나라도” 규칙 및 DEPENDENT와 UNCHECKED 동시는 타당하다. 예컨대 한 모서리에서는 의존이 증명되고 다른 모서리에서는 미식별일 수 있다. 한 표지로 다른 표지를 지우지 않는다.

### C4·C7: 같은 판 / 같은 침대

**현재 충분하지 않다.** F1의 “None이면 stop”에 동의하되 Git status 실패를 False로 바꾸는 갈래도 막아야 한다. F2는 실제 판정 전제의 구멍이므로 P2. F8도 같은 침대를 요구하는 명시적 계약과 실제 해시 대조가 필요하다. F3는 기록 계약 결함, F4는 시험 사각지대, F6는 fail-closed 처분/설명 결함이다. 셋을 모두 fresh-run 오계산으로 뭉뚱그리지 않는다.

### C5: 마감 문장이 결과 뒤 선택을 막는가

정책 방향에는 동의한다. 다만 **의도와 기계 봉인을 구별**해야 한다. 10-31 결과 없음 허용·팔 축소 금지 외에 시간상한/재시도·기계별 팔 귀속을 기록해야 한다(RCA2-05). 같은 단계 폴더를 여러 기계가 이어 쓰는 것은 현재 단계 단위 machine 표지의 범위 밖이다. 새 위끝·all3 비용도 재계산한다.

**세 origin이 충분한가:** 표본 연산자에 대한 답과 8팔 평균에 대한 답은 다르다. R=.5/1/2에서 arm0–2를 `3.02+1/(R+.1)`, arm3–7을 `1.02+3.2/(R+.1)`로 두면 모두 수동 저항망·R 단조다. 표본 셋은 서로 같아 확대가 발동하지 않고 **W=0.2930476574, PASS**. 고정8 평균은 **W=0.6803855313, WEAK**. 따라서 세 표본 결과를 전체8 결과로 부를 수 없다. 전체8을 주장하려면 지금 고정8을 택하고 SBE/DBE 추정량·비용을 같이 바꿔야 한다. 8개도 모든 연속 원점의 보장은 아니다.

**SV R0만 검사해도 되는가:** `Gfull=1/R+1`, `Gcut=1/R`이면 SV 비=1+R. R0에서 작고 hi에서 큰 수동 회로가 가능하다. 세 R 검사가 필요하지만 **현 all3도 arm0만** 검사한다. `rint_r_chain.py:1742`의 corner fetch는 SV를 켜지만 `:1760,1772`의 origin3/origin8 fetch는 끄고, `:2394`는 `pr.vals`만 판정한다. 따라서 확대 후 8팔 평균 envelope를 SV 비의존이라고 하려면 실제 포함 origin별 대조 또는 같은 평균 추정량의 full/cut 대조를 사전에 정의해야 한다. 현재 arm0 가드를 그 평균에 자동 이식하면 안 된다. all3/고정8도 모든 중간 R·연속 origin까지 증명하지는 않는다.

실제 `Predict(all3)` 호출 로그로도 확인했다. 12개 최종 값 모두 8팔 평균으로 확대되는 입력에서 SV 요청은 arm0 corner **12/12**, origin3 **0/12**, origin8 **0/12**였다. `registration/probe_results.json`의 `SV_all3_origin_scope`에 저장했다. 이는 외삽할 수 없는 가드 범위를 드러내는 것으로, 합성 입력의 σ를 실제 침대 결과로 주장하는 것이 아니다.

**DBE R 단조 검사 부재:** `rint_r_chain.py:1731–1782`는 c/origin만 본다. R=.5/1/2에 σ=4.2/4.7/4.4 mS/cm라는 불가능한 순서를 넣어도 PASS한다. 이는 실제 solver가 그 값을 냈다는 반례가 아니라 **방어 검사 틈(P3)**이다. 이미 구한 값으로 동일 origin 및 동일 최종 추정량의 `σlo≥σ0≥σhi`를 증서/등록 ln 여유와 함께 검사할 것을 권고한다. 추가 solve 불필요. 표본 통과를 연속곡선의 독립 증명이라 부르지 않는다.

**멈춘 단계 재실행:** RCA2-05대로 실패 부류·동일성·최대 횟수·채택순서·시도 연결을 먼저 등록한다. `CALIB_LADDER_EXHAUSTED`나 수렴 실패를 보고 상한/설정을 바꿔 같은 등록 결과로 덮지 않는다. 원 실패를 없애는 새 빈 폴더는 독립 재검증이 아니다.

```bash
# 현재 디렉터리 = 작성자 리포; 아래 REVIEW만 압축을 푼 위치로 지정
export REVIEW=/absolute/path/rint2_rereview_20261022
export RINT_REVIEW_SOURCE="$PWD"
export PYTHONDONTWRITEBYTECODE=1 PYTHONIOENCODING=utf-8
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1

python3 "$REVIEW/registration/probe_registration_current.py"
python3 "$REVIEW/certificate/probe_certificate.py"
python3 "$REVIEW/certificate/run_selected_tests.py"
python3 "$REVIEW/geometry/run_review.py"
python3 "$REVIEW/probes/provenance_probe.py"
python3 "$REVIEW/probes/s0_integration_probe.py" --fixture-argv
```

`--fixture-argv`는 셸/계획 Git 검증이 아니라 census 본체를 시험한다는 명시적 범위다. production이나 실침대 solve로 바꾸지 않는다. 전체 CLI 검증은 별도로 작성자 환경에서 해야 한다. 탐침은 리뷰 폴더의 결과 파일을 갱신하므로 배포 당시 결과를 보존하려면 묶음의 복사본에서 재실행한다.

| `source_manifest.json`, `evidence/zip_pin_comparison.json` | 고정 소스와 ZIP 대조 |
