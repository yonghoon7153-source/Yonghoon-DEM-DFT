# RTR-01 최종 폴더 audit 게시 — 한정 재확인 요청

**이번에 닫으려는 것:** RTA-02 잔여 RTR-01(P3), 최종 OUTDIR의 옛 audit이 새 팔 기록으로 읽히는 경로.
**닫지 않는 것:** 실제 연구/현장/⑥/GPU 실행, 물리·수치 자격, 지원 환경 내구성, 동시 작성, 운영 봉인, 전체 HOLD. RCPX-01–06·RTA-01의 기존 한정 수용은 보존한다.

리뷰 핀 = 이 요청서가 포함된 커밋(전달 ZIP PIN.txt). 비교 핀 = 97d8831a858fab5f92ed3e580817eea2eaa85f5f. 부모의 92bdd4e7b7e589518fc97cc6f898e60a456b5fbd는 1저자 결정 문서만 추가했으며 해당 소스는 비교 핀과 같다.

| 질문 | 확인할 것 | 작성 측 주장 |
|---|---|---|
| Q1 | 새 audit 없음/생성 실패·이동 실패에서 최종 옛 `hit` 재사용이 막히는가? | 새 팔 게시 전 옛 audit을 고유 보존 폴더로 퇴역; 누락은 소비자 `missing` |
| Q2 | 보존 폴더 생성·퇴역 이동 실패는 새 팔 게시 전에 멈추는가? 정상/기존 SKIP/store-off/옛 바이트 보존은 유지되는가? | 같은 10메서드 8실패→10/10, 기존13/13. 작은 해석 반례와 국소 변이로 직접 확인 요청 |
| Q3 | 최소 범위·기존 수용·시험 숫자·한정이 실제 diff와 일치하는가? | 생산 파일은 셸1개; writer·consumer·payload·조립기·공유 원장·봉인 무변경 |

실제 파일의 게시 조각과 SKIP 조각만 실행한다. 전체 러너를 source하거나 실행하지 않는다. 새 팔의 과학 자격은 합성 전제다. 새 audit은 자기 기록이며 새 payload hash/attempt 인증을 주장하지 않는다. 단일 작성자 계약에서의 오류 흐름만 대상으로 한다. Windows Git Bash 관측을 Linux/Lustre/실제 작업 자격으로 바꾸지 않는다.

전달물: 고정 snapshot/before, 같은 새 시험, 전후 결과, 원 독립 ZIP, 내부 공격 기록, 소스 매니페스트, 패치. 원 ZIP·원 로그는 공개 리포에 반입하지 않는다. 1저자가 이 요청과 ZIP을 반박 창에 전달하며 판정은 실무 창으로 돌려준다.
