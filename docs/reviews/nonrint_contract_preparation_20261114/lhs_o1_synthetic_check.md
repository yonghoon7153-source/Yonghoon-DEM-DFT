# LHS O1 초안 — 로컬 합성 읽기·거부 확인

## 1. 대상과 직접 결과

원 초안 핀0f7ea5ea5d3435e2416dbb5de8f92f21f1a8a24b의 ASCII 블록 SHA256=2026d61bb920599ca95870b62b8aee9ed3345f288da21ed4ff090a0064e0b8a3. 원 블록은 변경하지 않았다. Windows Git Bash5.3.15에서 새 합성 파일만 사용했다. 소스 문서가 당시 ‘미실행’이었던 사실은 후속 확인과 구분한다.

| 구분 | 직접 확인 | 범위 |
|---|---|---|
| 원 전체 블록 | 구문rc0, 기본 placeholder 상태 rc2·stdout0 | 확인된 실행 경로를 돌린 것이 아님 |
| 내부 collector 정상 | 일반 파일·빈 현재 파일 2사례 rc0, 각10키·크기/hash/선언 일치 | 원 바이트 읽기만, 파일 불변. 빈 파일은 덱 자격 아님 |
| 내부 거부 | 확인 없음·범위 밖 라벨2·부모/절대/공백 경로·부재/디렉터리·크기/숫자 예산3·hash/date 실패·읽는 사이 변경2 | 15사례 모두 rc2·stdout0 |
| 합계 | 원 기본 거부1+내부 정상2+내부 거부15=18관측 | unittest 메서드18 또는 전체 WSL18통과 아님 |

내부 블록에는 원래10키가 있고 마지막 command_rc는 바깥 감싸개가 추가해11키가 된다. 이번 정상 경로는 내부만 실행했으므로 전체11키 경로의 완료 자격을 주장하지 않는다. 실제 프로세스 rc와 출력 문자열은 여전히 별도 수령한다.

## 2. 대역과 보존

정상 파일은 합성 문자열이며 실제 덱 문법/결과를 담지 않는다. hash/date 실패는 셸 함수 대역으로 주입했다. 변경2사례는 시험용 sha256sum 감싸개가 첫 해시 후 합성 파일을 크기 증가 또는 같은 크기 다른 바이트로 바꿨다. 대상 코드가 그 파일을 쓴 것이 아니다. 다른 사례의 파일 SHA는 전후 동일하다. 기록의 source_unchanged는 대상 합성 파일이 시험 hook에 의해 바뀌지 않았다는 뜻이며 원 블록은18사례 모두 불변이다.

내부 추출·placeholder 대입·오류 hook 차이를 원문과 함께 비공개 재현 증거에 보존한다. 외부 timeout/TERM/KILL 경로·중단·실제 symlink·권한·동시 경합·WSL 자격은 이번에 시험하지 않았다. 실행 중인 실제 WSL/원자료/현장 접속0, 원 로그·값 열람0. Git Bash 통과를 WSL 수용으로 옮기지 않는다.

## 3. 다음

기존 O1은1저자가 대상/예산/변경 통제와 실행 시점을 확인한 뒤 수행한다. 이 합성 확인은 실행 GO가 아니다. 새 수집기/수정 원문 없음. 결과 수령 뒤에도 실행 신원 NOT_ESTABLISHED·동결 미승인·값GO NONE이다. LHS Q2–Q4는 재질문/자동 승인하지 않는다.
