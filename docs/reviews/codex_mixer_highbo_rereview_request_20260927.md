## 2. 새로 알게 된 것 (검토 부탁)

- **드럼은 39 각형이다** (`Drum.stl` 78 삼각형 · 꼭짓점 각 간격 9.23°).  면 한가운데는 꼭짓점 원보다 R·(1 − cos(π/39)) = **0.0426 mm** 안쪽 = SE 반경의 **56 %** ·
  AM_S 14 % · AM_P 6.3 %.  ⇒ 벽 겹침은 회전각 없이 잴 수 없다 (셀프테스트 ⑩b: 위상 0 으로 두면 2 % 겹침이 −159 % 로 보인다).
- **LIGGGHTS 재개와 드럼 기하** (LIGGGHTS-PUBLIC master 소스 읽음): `FixMesh::restart` 가 메시 꼭짓점을 재개 파일에서 복원 (`create_mesh_restart`: *"mesh file is required, but data will be taken from restart file"*) ·
  `FixMoveMesh::restart` 가 경과시간 `time_` 복원 · `MeshMoverRotate::initial_integrate` 는 매 스텝 `omega·dt` **누적** 회전.  ⇒ 스텝 s 의 각 = 2π·(s − 회전 시작)·dt/period 가 재개 뒤에도 이어진다
  (그래서 옛 생성기 주석 *"드럼은 축대칭이라 위상이 0 으로 돌아가도 기하가 같다"* 는 틀린 근거였지만 결과는 무해할 공산이 크다 — 검사기가 데이터로 확인).
- **등록 계약 1 % 와 충돌 겹침**: 09-21 자가 리뷰가 드럼 끝 속도 0.103 m/s 충돌에서 **SE–SE 1.03 % · AM_P–SE 0.92 % · SE–벽 0.90 %** 를 이미 추정했다
  (`docs/session_20260921_mixer_decisions.md` §문서 정정 · 겹침).  문자 그대로의 *"최대 겹침 실측 ≤ 1 %"* 는 본 캠페인 · 확장 모두 기각될 공산이 크다 → K1.

## 3. 판단 요청

**K1 — D-1 접촉 계약 1 % 의 해석 (본 캠페인 §1 과 공통).**  겹침 값은 아직 아무도 보지 않았다.  ① 문자 그대로 (창 전체 최대 ≤ 1 %, 입자–입자 + 벽) ② 두 층
(예: 지속 접촉 = 점착 평형이 정하는 겹침 → 1 % · 충돌 과도 겹침 → 따로 상한) — 두 층이면 *"결과를 보고 완화"* 가 아니게 하려면 무엇을 근거로 어떤 형태로 지금 고정해야 하나.
검사기는 판정을 등록 문구대로 **최대**로 내고, 프레임별 중앙 · 99 · 99.9 백분위 · 한도 초과 접촉 수 · 타입쌍별 최대를 기술 보고로 남긴다.

**K2 — 벽 회전각 처리.**  덱 스케줄로 계산 + 5 프레임에서 데이터로 되읽기 (허용 = 면 각의 2 % = 0.18°) + 벽 근처 입자가 20 개 미만이면 회전각과 무관한 해석적 상·하한
(변심거리 · 꼭짓점 반경) 으로만 판정.  이것으로 fail-closed 인가.  (실제 39 각형 · 합성 침대에서 되읽기 오차 ≤ 0.0002°.)

**K3 — D-2 상 대표성 문턱 0.90** (등록 bin 의 AM · SE 유지 부피 평균, 팔 · 시드마다 — 미달이면 그 짝 M 미식별).  아직 어느 런에서도 계산된 적 없다.  값 · 형태가 합리적인가.

**K4 — D-3 조건부 A 발동 = §5 "큰 차이"** (Δ ≥ 0.10 ∧ Δ ≥ 2·SE, 선행 조건 1–7 통과).  A 는 생성기 변경이 필요하다 (재현 시험 먼저).  발동 문턱을 판정선과 같게 둔 것이 적절한가.

**K5 — D-4 스모크 = 생산 `LH_s32452843` 의 bin 0, 세 시드 동시 발사.**  따로 버리는 스모크 대신 이렇게 하면 무엇을 잃나.

**K6 — 전 칸 M (`M_all`, n_min 없이 빈 칸만 뺌) 을 기술 보고로 늘 같이 내는 것** — 갈림길 (forking paths) 을 늘리는가, 아니면 지원 집합 진단으로 정당한가.  판정에는 쓰지 않는다.

**K7 — 본 캠페인 사전등록에 §5 (결론 문안 정정) 를 중간 열람 뒤에 더한 것** — §2 판정 규칙은 한 글자도 안 바꿨다.  이 형태로 충분한가.
