# DEM 세대 2 T12 준비 — 현재 P1 소비자 계약과 합성 경계 검사 (2026-10-24)

승인된 로컬 준비를 이어서, ULPR 소비자 기준을 `01c1aaf5be8acdf7d1716f34cc86fc77d8e27362`로 고정하고 실제 소비 함수의 양성·음성·관측 범위 반례를 만들었다. **`physical_ready=false`, 실제 P2 `T12=NOT_RUN`, 연구 계산 시작 0건**이다. P1 합성 검사의 PASS는 P2 생산기·등록·실제 복원 또는 언로딩 GO가 아니다.

현재 DEM 준비·계획 기준은 `2443a63eaa87d52e385a35f8bab4225efa0d25fe`이며 계획 `docs/reviews/dem_protocol_gen2_plan_draft_20261014.md` §12의 비준된 A1–A5 개정을 따른다. 최초 설계 요청서 기준 `962caea2d1857b0e34fe724e38815661936b7183`도 provenance에 보존한다. 이전 `docs/reviews/dem_gen2_t12_readiness_20261024.md`와 그 증거는 당시 ULPR `8347d32ea678c0174bd77d4c79cfbd7b0591e4a3`에 관한 역사 기록으로 보존한다. 이번 문서와 새 증거 폴더는 그 이후의 소비자 대조다. 별도 검토 중인 ULPR 소스·가지와 공용 검사·CI는 수정하지 않는다.

## 1. 고정 소스를 실행하는 방법

`scripts/test_dem_gen2_t12_consumer_contract.py`는 현재 checkout의 키트를 import하지 않는다. 고정된 전체 ULPR SHA의 Git blob에서 `ul_reader.py`, `ul_gates.py`, `ul_lib.py`, `ul_observers.py`, `ul_s3.py`, `unload_params.json`만 임시 폴더로 읽는다. `source-manifest.json`의 각 SHA256을 대조한 다음 그 사본의 실제 함수를 실행한다. 소스를 수정하거나 생산 경로에 복사하지 않으며 checkout·merge·fetch·네트워크 요청을 수행하지 않는다. Git object가 없거나 hash가 다르면 실행 전 rc 2로 종료한다.

아래는 Git 저장소 루트에서 실행하는 **합성 검사**다. Python 표준 라이브러리와 Git만 필요하며 LIGGGHTS·MPI·WSL 기계 접속·스케줄러를 사용하지 않는다. `TMPDIR`는 쓸 수 있는 임시 디렉터리여야 한다.

```bash
python3 -I scripts/test_dem_gen2_t12_consumer_contract.py --repo .
```

JSON 증거를 새 경로에 남기려면 `--json /tmp/t12-consumer-result.json`을 추가한다. 기존 파일은 덮어쓰지 않는다. 소스 object가 없다는 오류가 난 환경에서는 먼저 `git fetch origin codex/unloading-ulpr`로 소스를 확보하고 다시 실행할 수 있다. runner는 이 fetch를 대신 실행하지 않는다. branch 이름만 같아도 다른 소스를 받아들이는 방식이 아니므로 고정 commit이 여전히 필요하다.

`source-manifest.json`의 대조는 **어느 소스를 실행했는지**를 확인한다. 그 뒤 41개 합성 사례가 **그 소비 함수가 무엇을 읽고 거부하는지**를 검사한다. `fixture-results.json`에는 각 함수, 기대값, 관측값, `positive`·`negative`·`coverage_boundary`, 실행 소스와 시험 스크립트 SHA256을 따로 남긴다. 직접 검사를 공용 155개 검사나 CI에 자동 연결했다고 주장하지 않는다. 통합 트리 검사와 배선은 별도 인계 항목이다.

## 3. 아직 필요한 실자료·등록·외부 판정

새 `factual-input-form.blank.json`은 **기준 핀만 갱신한 빈 자료 수집 양식**이다. 실제 자료·외부 판정·생산자 정보·자격 시험 칸은 null이며 합성 fixture 값으로 채우지 않았다. 기존 비준을 반복 요청할 이유와 실제 사실이 없는 상태를 혼동하지 않는다.

| 조건 | 필요한 구체 사실 | 현재 처리 |
|---|---|---|
| 외부 판정 | 최신 ULPR 검토 대상 pin과 판정문·증거·hash; 세대 2 설계 검토 판정 | 사용자에게서 받으면 실제 pin·조건을 대조하고 반입한다. 현재 GO 칸은 null이다. |

현재는 P2 생산기·덱·인터페이스 등록이 없으므로 실행 가능한 P2 발사 명령을 제시할 수 없다. P1 `run_unload.sh`를 P2 명령으로 바꾸어 적지 않는다. 실제 R-a/S0 자료와 등록이 도착하면 그 계약을 읽는 생산기/소비자 변경을 별도 시험부터 작성한다. r8 머리에 P2 이름을 붙이는 사례와 h0 환산 생산기 구현은 이번 41개 검사에 포함되지 않았다.

## 4. 다음 통합 인계

현재 묶음은 새 문서·자료 양식·고정 소비자 합성 검사만 추가한다. ULPR 검토본 변경이나 중심 가지 `claude/stoic-knuth-NObVQ` 반입을 선행 조건으로 만들지 않았다. Claude 반입 시에는 각 트랙의 pin과 실제 합친 파일을 대조하고, 이 직접 검사 및 기존 D2·D3 직접 검사의 공용 검사/CI 포함 여부를 따로 확인해야 한다. 기존 155개 검사 통과 기록을 새 검사나 합친 트리의 통과로 확장하지 않는다.
