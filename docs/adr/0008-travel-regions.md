# ADR 0008 — 지방은 여행 기준으로 나눈다: 中部 → 北陸 · 甲信 · 東海, 도시 점은 데이터가 정한다

- 상태: 채택 (2026-09-28)
- 관련: `data/regions.json`(groups), `data/prefectures.json`, `src/data.ts`(regionTitle · regionNotes · cityTier), ADR 0005, 체크리스트 #62–#67

## 맥락

사이트를 톡방에 공유했더니 일본에 사는 친구(우파파)가 봐 주었다.
- "츄부에 호쿠리쿠 · 코신에츠를 다 포함시켜 놓으셨는데, 여행지를 보기 위한 지도니까 나누는 게 맞다 — 문화가 다르다."
- "도도부현마다 빨간 도시가 찍혀 있는데 기준이 애매하다. 대표 도시인가 싶다가도 하즈레가 있다."
- 新潟 메모 「거의 東北地方」: "호쿠리쿠가 맞다. 도호쿠라도 미야기는 눈이 적고, 눈 많기로 유명한 건 호쿠리쿠."
- "滋賀에는 琵琶湖가 지도에 있어야 한다."
- 金沢 메모 「조용한 곳 좋아하면 추천」: "県庁所在地라 조용하지 않다. 하나미 시즌엔 관광객이 미어터진다."

사용자는 v1 「내 마인드맵을 지도에 붙인 공부 노트」에서 v2 「여행지를 고르는 지도」로 방향을 잡기로 했다.
지방 구분 · 범례 모양 · 도시 기준은 취향이 갈려 권고안과 대안으로 물었고, 아래는 사용자가 고른 것이다.

## 결정

1. **中部 는 묶음(group)으로만 남고, 지도 · 범례는 北陸 · 甲信 · 東海 로 나뉜다.**
   - 北陸 新潟 · 富山 · 石川 · 福井 (北陸 4県 — 친구 말 · 교과서 · 北陸新幹線 · 눈 많은 지방이 모두 같은 짝)
   - 甲信 山梨 · 長野 (新潟가 北陸으로 가서 甲信越의 越가 빠진다)
   - 東海 岐阜 · 静岡 · 愛知 (三重 는 사용자 마인드맵대로 近畿 그대로)
   - `regions.json` 에 `groups: [中部]`, 세 지방에 `group: "chubu"`. 県의 `region` 은 늘 지방(묶음 아님).
2. **색은 中部 살구색의 이웃 톤 셋** (北陸 #FAE3C6 · 甲信 #FBD3AC · 東海 #F6BE9A): 멀리서 보면 지도는 여전히 9 덩어리.
   범례는 「中部」 자리에 세 알. 지방 페이지 · 図鑑 · 県 칩은 「中部 › 北陸」 처럼 큰 지방도 적는다.
3. **내 마인드맵의 中部地方 상자는 그대로**: `notes.regions.chubu` 는 묶음 키로 남고, 세 지방 페이지가 모두 「中部 메모 (내 마인드맵의 큰 지방 상자)」로 보여 준다.
   Canva 전수조사도 묶음 이름(中部地方 · ちゅうぶちほう)을 안다. 옛 링크 `#region/chubu` 는 北陸 을 연다.
4. **도시 점은 세 단계, 데이터가 정한다** (`cityTier`):
   ◎ 県庁所在地 · ● 볼거리 = 내 마인드맵이나 보충에 그 이름의 칸이 있는 곳 (箱根町 · 江の島 · 伊勢市 · 会津若松市 …) ·
   ○ 이름만 적어 둔 도시는 회색 · 작게, 더 확대해야 이름. 칸을 적으면 저절로 빨강이 된다 — 손으로 고르지 않는다.
5. **琵琶湖 는 지도에 그린다.** 지리 데이터(地球地図日本)에는 호수 구멍이 없어서 Natural Earth 10m lakes(퍼블릭 도메인)에서
   Biwa 만 `data/raw/lakes.geojson` 으로 두고, `nihon geo` 가 `japan.topo.json` 의 `objects.lakes` 로 넣는다. 이름은 `places.json` 의 `lakes`.
6. **내 메모의 틀린 곳은 내 글을 고치지 않고 회색 정정 줄로** (`gloss`, 「Claude 가 붙인 풀이」와 같은 자리):
   新潟 「거의 東北地方」 밑에 "지방 구분은 北陸 — 눈이 많기로 유명한 건 도호쿠보다 호쿠리쿠 (도호쿠라도 미야기는 눈이 적어요)",
   金沢 「조용한 곳 좋아하면 추천」 밑에 하나미 이야기. 원문과 전수조사는 그대로.

## 결과

- 톡방 피드백 하나 더 — "仙台는 宮城 안의 시(市)인데 소도시라 불린다": **政令指定都市 20곳의 시 구역을 점선으로 살짝** 그린다
  (国土数値情報 행정구역 데이터를 smartnews-smri 가 가공한 공개 파일에서 20곳만, `japan.topo.json` 의 `objects.cities`; 출처 표기는 화면 아래).
  전국 화면에선 숨고 조금 확대하면(1.5배↑) 보인다. 이름표는 따로 없다 — 도시 점이 이미 있다 (北九州市 점을 더함).
- 北関東(茨城 · 栃木 · 群馬)의 「시골 · 달동네」 메모는 사용자 지시로 뺐다 (지역 드립) — 「北関東地方 (きたかん)」 칸만 남고, 전수조사에 이유를 적었다.
- 지방 11개 + 묶음 1개. `regions.length` 를 세던 곳(README, 검사기 출력)은 고쳤다.
- 세 지방의 지도 라벨 위치는 `REGION_NUDGE` 로 손봤다 (北陸 은 바다 쪽, 東海 는 태평양 쪽).
- 앞으로 v2 에 더할 것: ✈🚄 가는 법 레이어(공항 · 신칸센), 🎆 축제 달력 — 모두 켜고 끄는 레이어나 따로 페이지로, 첫 화면은 그대로.
