# T12R-01 오프라인 실행 경계 수정·외부 재확인 요청 (2026-10-26)

외부 검토 핀은 `bffc42cab29da37b45f8a713e30e8572b91e7da3`이며, 고정 소비자는 `4c29705fa1c4ba94737a858b206fa4f4c5bb2bde`다. **P1 발췌/P2 등록 분리·합성 52개 관측의 해석·ULPRI-01/02의 좁은 종결은 수용된 상태를 유지한다.** 새 P2 `T12R-01`은 runner의 오프라인 실행 보장에 관한 결함이다. 이 요청은 수용된 소비자 의미를 다시 열거나 실제 물리 실행을 승인하지 않는다.

[외부 보고서 원문](codex_review_dem_gen2_t12_consumer_20261026/codex_review_dem_gen2_t12_consumer_20261026.original.txt)은 바이트 그대로 보존했다. 이전 문서의 무조건적인 “fetch·네트워크 없음” 설명은 아래 날짜가 붙은 실행 능력 조건으로 정정한다. 과거 문서·빈 사실 양식·이미 제출한 핀과 ZIP은 고치지 않는다.

## 1. 결함과 수정 범위

누락 객체가 있는 promisor 저장소에서 일반 `git show`는 암묵적 fetch를 시작할 수 있다. rc2만으로 fetch가 없었다고 결론 내릴 수 없으므로 과거의 `No fetch was run.` 오류 안내는 근거가 부족했다. 외부 로컬 file 반례의3회/금지 환경0회는 **그 외부 검토의 관측**이며 이번 로컬 실행 수로 다시 세지 않는다.

수정은 `snapshot()`의 각 Git 자식 환경에서 `GIT_NO_LAZY_FETCH=1`을 강제하고 Git 전역 `--no-lazy-fetch` 옵션을 사용한다. 상위 셸 값을 신뢰하지 않는다. Git이 이 옵션을 지원하지 않으면 객체 조회 전에 실패하며, 무시될 수 있는 환경 변수만으로 오프라인 보장을 주장하지 않는다. 시험하지 않은 최소 Git 버전·다른 플랫폼의 보장을 만들어 쓰지 않는다. 실제 시험 Git/Python/플랫폼과 trace를 새 증거에서 확인한다.

상주 회귀는 별도 로컬 fixture와 빈 로컬 remote를 사용하고 외부 전송을 금지한다. 실제 Git trace에서 fetch 자식 호출을 검사하여 **누락 객체 rc2와 fetch0회**를 함께 요구한다. 완전한 객체 양성은 같은52개 기대/관측값과 여섯 소비자 hash를 유지해야 한다. 소비자 코드·params·물리 판정선·P2 등록의 범위를 넓히지 않는다. 승인된 사전 소스 확보는 별도 준비 행위이며 runner가 수행한 것으로 합치지 않는다.

## 2. 재확인 질문과 증거의 지위

1. 모든 snapshot Git 자식이 금지 환경과 옵션을 강제하며, 호출자가 상충하는 환경 값을 줘도 보호되는가?
2. 실제 누락 commit/tree/blob promisor fixture에서 rc2와 fetch0회를 함께 확인하는가? 보호를 제거한 대조가 실제 자동 fetch를 노출하는가? 객체 DB 불변성도 확인하는가?
3. 완전한 로컬 객체는 같은52개 관측과 소스 hash를 유지하고, 기존 소스/계약 거부 및 표적 변이 시험은 지정한 오류를 계속 검출하는가?
4. 지원하지 않는 Git 능력·오류 안내·로컬 전송만 사용하는 fixture·시험 플랫폼의 한계를 정확히 설명했는가?

로컬 수정 검증이 끝나도 표지는 **claimed fixed / 외부 재확인 대기**다. 이 작업 자체로 T12R-01의 외부 종결을 선언하지 않는다. 각 시험 수는 서로 더하지 않는다. 직접52·오프라인 회귀와 공용155는 별도이며 공용 검사 목록/CI를 수정하지 않는다. 새 후보의 전체 게이트와 소스 결속은 실제 결과가 나온 뒤 별도 증거 커밋으로 남긴다.

## 3. 외부 §6 A–D의 후속 수용 조건

다음은 이미 예정된 P2 작업의 **미구현·미검증 후속 조건**이다. A1–A5·Q1–Q16의 재선택이나 기존 P1 소비자의 즉시 확장을 요구하지 않는다.

**A — 사실과 등록.** 실제 bed/arm·generation·params·활성 머리, h0 기준/단위 환산/정수 step, dt·시간창, 중력 예외·resume 전이를 원문과 연결한다. 결손 측정/생산값은 비워 둔다. P1 필드 이름이 같다고 P2 등록을 채우지 않는다.

**B — 구현 전 생산자→소비자 시험.** 정상 P2 생산자 형식부터 소비자·최종 상태까지 양성을 검증하고, P1 이름 재사용·잘못된 generation/params·동일 ID type/radius/mass/omega 변경·S0 재고 누락/추가/중복·BOX/mesh/벽 변화·잘못된 R-a 끝 step·창/중력 불일치의 판정을 명시한다. 관측 결손과 관측된 수치 불일치를 구분한다. G2c torque/periodic 제외를 유지하면 근거와 별도 관측을 등록하고, 접촉0행/식별력 없는 동일성을 이력 복원의 증거로 승격하지 않는다. 현재 G2/_atom_frame만으로 이 조건을 이미 인증한다고 쓰지 않는다.

**C — 실제 R-a/S0와 자격.** S0를 고정판 R-a 완료 시점에 연결하고 같은 실행의 원자/상/질량 재고·atom/contact/wall/mesh/restart/state·활성 fix·binary/run/hash를 결속한다. 지정 바이너리의 실제 숨은 이력 양성/음성 대조가 필요하다. T10은 같은 물리 시간 dt/2, T11은 등록 서보, 실제 T12는 복원·판독·관문, T13은 checkpoint 단계별 재개를 검증한다. 합성52와 외부729 분류 조합은 이 칸을 닫지 않는다.

**D — 통합.** 과거 고정 핀 회귀와 실제 통합 생산자/소비자 파일 및 기대 모델 계약의 검사를 구분한다. 향후 통합 commit·파일 hash·직접 검사·공유 게이트 영수증은 그 트리에서 남긴다. 옛 핀52 또는 과거155 PASS를 통합 트리 PASS로 복사하지 않는다. Q7–Q9 질량/지름/두께/불확도·측정 상태/시각은 별도 실측 축이며 기준 밀도/공극률에 맞춘 역추정으로 대체하지 않는다.
