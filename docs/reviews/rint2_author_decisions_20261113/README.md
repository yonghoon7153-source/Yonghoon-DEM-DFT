## 2. 이전 질문과 연결

원 작성 고침 README §8 Q1–Q5는 이 표 Q1–Q5와 같은 축이다. takeover author_decisions의 Q1/Q2/Q3은 여기 Q1/Q2/Q3, 기존 Q5(현장)는 여기 Q4, 기존 Q6(짧은 재확인 발송)는 이미 준비된 한정 요청으로 여기 Q5의 입력이다. 기존 Q4(최종 핀 S0/GPU 영향)는 여기 Q6의 선행 영향 점검으로 남긴다. 번호 변경으로 항목을 없애지 않는다.

## 3. 블록 작성의 선행 계약

반박 재확인 판정 수령 → 필요한 수정과 범위 시험 → 고정 최종 핀 → 현장 블록 초안 → 1저자 GO 순서다. 이 문서에는 실행 가능한 kgy 블록을 넣지 않는다. 같은 리포라도 shallow/replace/graft 확인 실패를 넘기지 않는다. 부분 복제의 내용을 sha로 확인하는 기존 한정도 유지한다.

시도3은 등록된 저장본 폴더가 없거나 비어 있음이 조건이다. 시도4는 시도3의 같은 폴더·같은 열쇠/환경을 그대로 써야 하므로 **시도4에 빈 폴더 조건을 적용하지 않는다**. 기존 파일을 지우거나 다른 저장본으로 바꿔 적중 결과를 만들지 않는다. interrupted/partial이면 자동 재실행하지 않고 파일 보존·상태 수령·새 판단으로 간다.

최종 블록에 적을 것: ASCII·주소 없음, 코드 핀/가지 끝 대조, 도구/블록 md5, 위 Git 관문, 기계별 개인 로컬 저장본, 자원/시간 상한, 중단/회수, 기대 status, rc와 단일 결과 기록의 결속. 다른 계정 그래픽 앱은 유지하고 1저자 DFT만 그동안 얼린다는 이미 받은 정책을 보존한다. 실제 계정·주소·포트는 공개 리포에 적지 않는다.

최종 핀이 ca_s0_census.py/mpm_webapp_payload.py 또는 풀이 경로에 영향을 주면 기존 S0/GPU 자료를 새 핀 자격으로 옮기지 않는다. 원1/2 Q14 기준의 재확인 범위를 별도 고정한다. 과거 개발 자료는 삭제하거나 새 결과로 덮지 않는다. 이 문서의 값0은 미실행이며 시험 통과가 아니다.

## 4. Q-A 비용과 환경 빈칸

고유 열쇠6은 2kit×3기원이라는 원 작성 보고다. 원 README §4-3은 두 kit SBE/DBE와 origin arm0/1/2를 명시하므로 그 여섯 행 이름만 계획 명부에 전사했다. 실제 키 문자열·입력 hash·환경은 아직 읽거나 생성하지 않았고 null이다. 넘침이 나면 해당 kit에 origin5개가 더해진다는 기존 계획도 보존한다. 그 추가 열쇠는 전6개 확인으로 덮지 않고 새 명부·비용·대조 범위를 먼저 고정한다. 한 환경의 전6개 대조 횟수는 정책상6칸이며 실제 실행 수가 아니다. 비용은 key별 독립 건설·저장본 생성·읽기·대조 회수와 환경 수를 분리해서 적고, 이미 독립 생성된 증거의 재사용 가능성은 고정 핀/환경/신원 대조 뒤에만 반영한다. 원 보고의 SBE 실측/DBE 추정은 섞어 확정 총시간으로 쓰지 않는다.
