## 2. 돌리는 법 (1저자)

1. 블록 파일 전체를 그 기계의 셸에 붙여 넣는다.  첫 줄의 이름표 (GBL=…) 만 바꾼다: kgy_busy (다른 프로세스가 도는 채로) · kgy_alone (kgy GPU 를 비우고) · gabia.
2. 블록이 하는 일: 홈 아래에 새 폴더 하나 (gpubench_이름표_시각) 를 만들고 그 안에 스크립트를 쓴다 → md5 가 맞을 때만 venv (홈의 dem-venv) 를 켜고 스크립트를 돈다.  md5 가 다르거나 폴더를 못 만들면 아무것도 돌지 않는다.
3. 끝나면 그 폴더의 세 파일을 보낸다: bench.json · bench.log · gpu_samples.tsv.
4. 걸리는 시간 (추정) = 행렬 만들기 1 분 안팎 + GPU 2–6 분.  쓰는 자원 (추정) = GPU 메모리 약 6–7 GB · 호스트 메모리 10 GB 안쪽.  GPU 빈 메모리 9 GB 미만 · 호스트 여유 16 GB 미만이면 시작 전에 멈춘다 (GPU 에 아무것도 올리지 않음).
5. 우리 R 팔 · 탐침이 도는 동안에는 돌리지 않는다 (그 팔을 늦춘다).  kgy_busy 는 다른 프로세스를 몇 분 늦출 수 있다.

## 4. 실제 풀이 시간으로 옮길 때의 한정

- 반복 **수** 는 재지 않는다 (정해진 수만 돈다).  실제 반복 수는 R_j · 법칙 · c · 침대마다 다르다 (미확인).
- 행렬 구조가 다르다: 실제 = 54.7 M 칸 격자 가운데 도체 26.5 M 칸 + 접합 간선 약 15 만 + 멤버십 미지수 · 행 길이가 고르지 않다.  그래서 절대 시간보다 **비** (같은 블록 · 다른 조건) 를 쓴다.
- CPU 몫은 들어 있지 않다: 팔마다 준비 4,567 s (실측) · 증서 CPU 약 408 s (관찰) · 저장.  준비의 기계 비는 이 벤치로 정해지지 않는다 (gabia CPU = Xeon Silver 4210R 2.40 GHz · 20 가닥 · kgy = i9-11900K 3.50 GHz · 16 가닥 — 현장 기록 `docs/data/rint2_siteq_20261109/gabia/siteq_result.json` · `docs/data/rint2_siteq_20261109/kgy/siteq_result.json` 의 33 줄).  두 기계의 cupy 는 같은 판 (12.3.0 · 같은 기록) 이다.
- 다른 프로세스의 부하는 시각마다 다르다 → kgy_busy 한 번의 s 는 그 순간의 값이다.
- B · C 는 생산 코드에 없는 꼴이다.  여기서 같게 나와도 실침대 · 생산 코드에서 같다는 증명이 아니다 (바꾸려면 시험 먼저 · 반박 리뷰).
- GPU 길 (cupy) 은 이 컨테이너에서 돌지 않았다.  첫 실행에서 멈추면 bench.log 의 마지막 줄을 보낸다 (B · C · 한 연산 재기는 실패해도 A 결과는 남게 짰다).
