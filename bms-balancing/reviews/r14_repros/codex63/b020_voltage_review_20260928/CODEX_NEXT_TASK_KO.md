## 구체적 작업

다음 목적은 실험 대응을 주장하는 완성 모델이 아니라 제한된 장시간 기능 진단입니다. 우선 동일 물리/운전 조건의 시간 연장을 기본 후보로 검토하세요. 충방전 전환·휴지·유한 sigma·열화 모델 변경이 필요하면 별개 제안으로 분리하고 임의로 포함하지 마세요.

실행 모델/소스 SHA·입력/초기화 방식·기준 해·물리/입자 해상도·요청 코어·전류·sigma·시간조건·guard를 기존 문서에 연결하세요. B020 후처리 입력 파일을 곧바로 새 장기 solve 실행본으로 간주하지 마세요. 원시 코어 실측이 없으면 요청 코어와 실제 관측을 계속 구분하세요.

### 2. 선행 조건표

각 항목을 `완료·재사용 / 다음 실행 전 필수 / 이후 정량 검증 / 목적 선택 대기`로 분류하고 파일/절 근거를 붙이세요.

- 정상 저장 결과의 Li/전압/조성/농도/미발동 관측과, guard의 실제 발동 시험을 분리합니다.
- 기존 기록상 미완인 전해질1198 발동 시험의 현재 상태를 확인합니다. 이미 후속 증거가 있으면 재사용하고, 없다면 최소 발동 시험안을 제시하세요. 1198은 시험용 임계값이며 장기 생산 한계값이 아닙니다.
- 기존 OCP/표면조성 보호 및 CDC/첫 충전 시험이 다음 고정 실행본에 적용되는 범위를 밝히세요. 현재 조건에 없는 전환 시험을 자동으로 요구하지 마세요.
- 소유 프로세스 정리·자원·출력·실패 보존 및 필요한 경우의 설정 원복을 확인합니다. 보안 완화를 당연한 선행 단계로 만들지 말고 실제 경로에서 필요 여부를 밝히세요.

### 3. 최소 시험 순서와 합격 기준

권고 첫 연장 시간 하나와 선정 근거를 제시하세요. 임의로 “5초 통과이므로 12시간 가능”으로 확장하지 마세요. 시작을 t=0으로 할지 검증된 저장 상태에서 이어갈지 제안하고 비교 가능성·기술 경로의 차이를 적으세요.

guard 발동 확인이 선행돼야 한다면 발동 시험과 첫 연장 실행을 별도 승인 단계로 나누세요. 미래 시험을 묶어 한꺼번에 실행하도록 하지 마세요. 기존 COMSOL StopCondition은 step 뒤 평가이고 연속 시공간/모든 내부 반복의 양수성 보증이 아니라는 한계를 유지하세요. 기존 구현 증거 또는 공식 문서를 인용하되 기능을 임의로 바꾸지 마세요.

전압·Li 수지·전해질 최소·표면 조성/OCP 범위·실제 시간 간격·solver 실패·저장 완전성·정리/원복에 대한 사전 기준을 제시하세요. 기존 전압1 mV/표면x1e−4는 비교 기준이지 절대 운전 한계가 아닙니다. 새 구간에 그대로 쓸 수 있는 기준과 근거/사용자 선택이 필요한 기준을 구분하세요. 서로 다른 종료 시각의 결과를 같은 시각 비교처럼 취급하지 마세요.

장기 정확도를 주장하기 위한 시간 허용오차·공간 해상도 민감도 확인은 필요 구간과 관측량에 맞춰 제안하세요. 후보 C 등 과거 미승인 시험을 자동 승인하지 말고, 모든 조합의 sweep도 요구하지 마세요. 제한 진단을 시작하는 조건과 검증된 장기 예측을 발표하는 조건을 분리하세요.
