## 1. 반박 — 입력 hash 불일치는 재현되지 않는다

우리 쪽에서 같은 커밋을 직접 뽑으면 선언값과 **정확히** 일치한다.

```bash
git show c1f278cd:db/structures/linio2_104_sym_1x4L4_relaxed.vasp | sha256sum
# 26a48473060243fef55e86d151050b6a27d6e65801b4d3ccd818678913aee25e   ← 선언값과 동일
git show c1f278cd:db/structures/ptfe_dimer_c4h2f8_r2scan3c.xyz | sha256sum   # dcc0f678…
git show c1f278cd:db/structures/ptfe_c10f22_r2scan3c.xyz       | sha256sum   # 66dd0bcc…
```

gabia 실행 로그도 `sha256 ✔ 일치 (26a48473060243fe…)` 를 찍었다.

**세 파일이 동시에 어긋난다**는 건 파일 세 개가 각각 바뀐 게 아니라 추출 경로의 계통 변환
신호다. `git show > file` 대신 텍스트 모드로 받았거나 `core.autocrlf`/`.gitattributes`
eol 설정이 개입하면 그렇게 된다. 확인 부탁한다:

```bash
git show <ref>:<path> | wc -c          # 바이트 수를 우리 값과 대조
git config --get core.autocrlf
```

다만 이 지적 안에 **진짜 구멍이 하나 있었고 그건 채택했다** — fragment sha/조성 불일치를
`inputs` 경고로만 흘려보내고 `atlas`/`score` 가 무시했다. 지금은 **hard fail** 이다.
이름만 맞고 내용이 다른 분자로 스캔한 결과가 남는 경로를 닫았다.

⚠ SDCP 단량체 2종이 repo 에 없다는 지적은 맞다. 회수해서 등재했고 sha 를 고정했다:
`sdcp_v7c_neutral.xyz` = `fc5ed6da…`, `sdcp_v7c_doped.xyz` = `4d0ca2ac…`.

## 2. ★ `FixAtoms.indices` 지적 — 라이브 런의 절반을 실제로 파괴하고 있었다

지적이 정확했고, 예상보다 나빴다.

```
freeze 0.85: 고정 144개 · z ≤ 17.39 Å
  앞 144개 중 **자유 원자 36개** (인덱스 36,37,38,…)
```

1×4 초격자는 층이 뒤섞여 있어 z 기준 고정 인덱스가 **비연속**이다. `positions[:nfix]` 로
drift 를 재면 "움직여야 하는 원자"를 재고, 임계 `1e-3 Å` 를 무조건 넘는다.

**실측 피해** — 지적을 받기 전에 이미 돌던 relax 런의 결과:

| 조각 | freeze 1.00 | freeze 0.85 |
|---|---|---|
| sdcp_neutral | 통과 19/20 | **통과 0/20** (FROZEN_DRIFT 19) |
| sdcp_doped | 통과 20/20 | **통과 0/20** (FROZEN_DRIFT 4 + EXTRACTION 16) |
| ptfe_dimer | 통과 10/21 | **통과 0/21** (FROZEN_DRIFT 10 + CAP 11) |
| ptfe_c10 | 통과 21/21 | **통과 0/21** (FROZEN_DRIFT 21) |

freeze 1.0 은 `nfix = 192 = 전체` 라 앞 192개가 곧 전체 고정 원자여서 **우연히 맞았다**.
그래서 그쪽 결과만 살아남았다. 0.85 는 전량 재실행 중이다.

이건 우리가 자체검사로 못 잡았다 — 정상 케이스만 봤기 때문이다. 지금은 자체검사가
"freeze 0.85 고정 인덱스가 비연속임"을 명시적으로 확인한다.

**되묻는 질문**: `vasp_stage.py:914-1039` 의 `fixed_indices_from_atoms()` 는 실제 constraint
인덱스를 쓰고 있어 같은 사고는 없어 보인다. `apply_bottom_half_constraint()` 가
`fixed_count != 96` 을 hard assert 하는 것도 좋은 방어다. 다만 UMA 단계는 슬랩 전체를 얼려
`range(len(slab))` 이므로 이 사고가 **원리적으로 발생할 수 없는 구성**이다 — 즉 검증된 게
아니라 노출되지 않은 것이다. 부분 고정을 도입할 때 회귀시험을 미리 넣기를 권한다.

## 4. 거리 gate — 너희 수치 공개에 대한 회답

수치를 그대로 열어 준 것과 F–Ni `<1.80 Å`(= 0.99 Σr_cov)가 Ni–F 정상 배위를
false quarantine 할 수 있다고 먼저 인정한 것, 둘 다 유용했다.

동의하는 부분:
- 이름은 `REACTION_CONFIRMED` 가 아니라 `OUTSIDE_NONREACTIVE_UMA_SCOPE` 가 맞다.
  우리는 `short_contact` 태그(0.80–0.92 Σr_cov)로 같은 역할을 만들었다.
- `0.80 Σr_cov` 가 "반응 경계"가 아니라 severe-overlap 경계라는 지적도 맞다.
  C–Ni 1.90 Å 같은 구조가 우리 hard gate 를 통과한다는 것도 사실이다.

다만 우리 입장은 이렇다: **거리는 죽이는 데 쓰지 않고 태그를 다는 데 쓴다.**
죽이는 건 ① 분자 내 결합 위상 변화 ② 깨끗한 슬랩 대비 변위 + 배위 상실, 두 가지뿐이다.
거리로 죽이면 우리가 두 번 겪은 오판이 세 번째로 반복된다.

**되묻는 질문 (숫자로 답해 주면 좋겠다)**:
너희 실행 산출물에서 **F–Ni `<1.80 Å` hard gate 로 죽은 자세가 몇 건**이고, 그중 몇 건이
분자 결합 위상 변화나 슬랩 재구성을 동반했나? 우리는 같은 감사를 했다가 33건이 전부
"거리만" 이었을 가능성을 발견했다. 같은 형태의 감사를 권한다.

## 6. 대조쌍 — 채택하되 못 닫은 것을 밝힌다

`relax-stage pair 는 basin 탐색용, rigid matched start 의 DFT relaxation 은 반사실 control 용`
이라는 정리에 동의한다. 우리 쪽 상태:

- ✔ relax shortlist 에서 Li/Ni 짝 강제 보존 — **4조각 모두 5쌍 확보**(§7)
- ✘ **rigid matched pair 를 DFT handoff control 로 별도 보존** — 미구현
- ✘ **`PAIR_COLLAPSED` / `PAIR_MIGRATED` 판정** — 미구현. 지금 verdict 는 표는
  final registry(`site_from_geometry`)로 만들지만 **대조쌍은 여전히 시작 `site` 로 짝짓는다.**
  두 끝점이 같은 basin 으로 합쳐지거나 서로 자리를 바꿔도 ΔE 를 낸다. 지적대로다.
- ✘ pair 선정 점수 `min(E_Li, E_Ni)` → pair-balanced rank — 미구현

다음 판에 넣는다. 우선순위는 `PAIR_COLLAPSED/MIGRATED` 가 가장 높다 — 지금 낸 ΔE 의
해석 자격이 거기 달려 있다.

착시였다는 판정을, 짝지은 데이터가 독립적으로 뒷받침한다.

`ptfe_dimer` 에서는 검열 편향 검사가 걸렸다(`CAP_ARTIFACT` 11건 중 Ni 접촉 9건, 그중 5건이
살아남은 Ni 최저보다 낮음). 그래서 그 조각의 **분포 비교는 무효**로 찍힌다. 다만 대조쌍
판정은 양쪽 모두 게이트를 통과한 5쌍만 쓰므로 별도로 유효하다 — 이 구분을 출력에서
분리해 두었다.

### 부수 발견 — `E_pose` 부호를 결합으로 읽으면 안 된다

SDCP 두 조각은 `E_pose` 최저가 **양수**(+0.077 ~ +0.134)이고 PTFE 는 음수(−0.256 ~ −0.103)다.
`E_pose = E_complex − E_slab − E_mol(기체상 ORCA 기하)` 이라 이완 중 분자가 휜 **변형 몫**이
함께 실린다. 유연한 SDCP 는 그게 커서 부호가 뒤집힌다. 같은 조각 안 순위와 대조쌍 Δ 에서는
상쇄돼 무해하지만, **부호를 "결합 안 됨"으로 읽으면 오독**이다. 도구가 이 경우 경고를
찍도록 했다. 너희 `pose_score_eV` 도 같은 성질일 텐데, 문서에 한 줄 있으면 좋겠다.
