## 2. 한 것

**DQ P1-1 — 판정이 읽는 것 전부를 지문에 · 앞 판정의 성격으로만 자동 대체.**
- 판정 지문 (provenance) 이 묶는 것: 원자료 다섯 (plan · thermo · traj · final · result) · 파생 md_init_raw.xyz (seed_gate 가 이미 있으면 읽고 traj 원시와 대조한다) · 보존 폴더 `seed<N>.<붙임>` 의 실행 전 기록 (`stage1_attempt.json` — 판정이 그 폴더에서만 읽는다) · 폴더 이름 [계 폴더, 시드 폴더] (식별 입력) · G4 밴드 카드 (gate_check 가 **실제로 읽었을 때만** — li2s-2 고정 밀도 NVT 는 밴드를 읽기 전에 돌아가서 not_read) · 판정 규칙 지문 `judge_values_sha16` (판정이 읽는 카드 열쇠 `JUDGE_VALUE_KEYS` 만 — 상한 · 재시도 · 증언 · 시드 · 2 단계 칸은 빠진다 · selftest 가 판정이 실제로 읽는 열쇠를 추적해 대조) · 카드 값 전체 · 도구 · 실행 환경 (파이썬 · ase · numpy 판).
- 판정은 성격을 적는다 (`judge_nature`): errors = 판정 도중 예외 · input_mismatch = 끝까지 보고 찾은 입력 불일치 (md_init_raw.xyz 가 있고 traj 원시와 다르다). 파생 파일은 임시 → 교체로 쓰고, 이 판정이 처음 만들었는지 (`derived_written`) 는 판정 전후 존재로 적는다 (seed_gate 가 쓴 뒤 예외가 나도).
- 자동 대체 (`supersede_block` — 장부 판정 · 장부가 빈 때의 폴더 판정 기록 모두): ① 판정이 읽은 입력 전부가 같고 ② 앞 판정이 예외로 못 끝났고 입력 불일치를 찾지 않았을 때만. 파생 파일 하나만 예외 — 앞 판정 뒤에 **없었고** 지금 있으면 (누가 만들었든) 같다고 본다. 앞 판정 뒤에 있던 파일이 바뀌었거나 사라졌으면 다르다. 성격 기록이 없거나 · 예외 없이 끝났거나 · 입력 불일치를 찾은 앞 판정은 대체하지 않는다 (충돌 관측 · 보류). 대체 근거 문구 ('앞 판정은 판정 도중 오류로 못 끝남') 는 이 조건이 참일 때만 남는다.
- 장부 판정이 비과학적 (invalid · incomplete) 이면 그 폴더의 판정 기록 (`folder_verdict_chain` — 쓴 순서) 도 본다: 못 읽는 판정 · 다른 pass · fail 은 어디 있든 충돌 · 장부 판정 자신의 기록 (같은 상태 · 같은 지문의 **첫** 것) 뒤의 비과학적 기록은 하나하나 같은 대체 규칙 (그 뒤 재판정이 본 입력 변경 · 그 변경을 되돌린 복구는 보류 — DP Q2 '원자료 복구') · 그 **앞** 의 비과학적 기록 (실행 중 사람이 들여다본 incomplete 같은 앞선 상태) 은 막지 않는다 · 장부 판정의 기록을 못 찾거나 장부 판정이 없으면 전부 대체 규칙.
- 시험: DQ 재현 (raw 를 다른 이름으로 보존 → 확인 → 보류 · 발사 0 · 요약 invalid) · 맞는 파일로 바꾸거나 지워도 보류 · 일시 I/O 오류 (입력 그대로) → 회복 · 그 사이 문서대로 상한을 올려도 회복 · 원자료 (final.xyz 셀 · plan · traj) 를 바꿨다 원래 바이트로 되돌림 → 보류 · 실행 중 들여다본 incomplete 뒤 일시 오류 → 회복 · 같은 바이트의 판정 사본이 뒤에 생겨도 기준이 안 밀림.

**DQ P1-2 — 정본 없는 미해결 기록 (현재 · 옮긴 폴더).**

## 3. 이것을 특히 봐 달라

1. **판정 입력이 정말 다 묶였나** — 위 목록 밖에 판정이 기대는 것이 있는가 (환경 변수 · ase 의 판독 동작 · 파일 시각 …). 하나라도 있으면 '같은 입력 + 판정 도중 예외 = 일시 오류' 대체가 다시 틀린다.
2. **파생 파일 예외** — 앞 판정 뒤에 없던 md_init_raw.xyz 가 지금 있으면 누가 만들었든 같다고 본다 (사람의 `--seed_gate` 포함). 근거는 '새 판정이 과학적이면 그 seed_gate 가 traj 원시와 대조해 맞다고 봤거나 아예 안 읽었다' 이다 — 맞는가.
3. **쓴 순서의 기준 (장부 판정이 비과학적일 때)** — 장부 판정 자신의 첫 기록 앞의 비과학적 기록은 막지 않는다 (실행 중 들여다본 incomplete). 판정 기록 자체를 지우거나 고친 경우 (꾸민 기록) 는 못 잡는다 (DQ 때와 같은 한계). 받아들일 만한가.
4. **다른 판정 규칙의 기록** — 그래서 ⓐ 도구 고정값을 바꾼 뒤에는 그 전 도구로만 판정한 보존 폴더를 손으로 다시 판정해야 읽히고 (현재 폴더는 러너가 시작 때 다시 판정한다) ⓑ 끊긴 런 + 다른 규칙의 과학적 기록은 다시 판정해도 incomplete 라 사람이 본다 (Q7 대로 해결 명령은 만들지 않음). 첫 담금질 전에 바꿔야 할 운영상 문제인가.
5. **①-3b 시작 점검** — 미해결 기록이 있으면 읽을 수 있는 과학적 결과를 먼저 장부에 적고 멈춘다 (닫힘이면 melt). 이 순서가 맞는가.
6. **못 하는 것** (카드 v11 `⛔_못_하는_것` · `자동_대체_규칙` 의 '알려진 한계') — 예외 원인은 안 가름 · 실행 환경은 셋만 · 밴드 카드 경로 해석 · 상한 경로 이중 고장 · seed_gate 를 안 거친 fail 의 md_init_raw.xyz · 도구 고침 뒤 판독 불가 · 끊긴 런 + 다른 규칙 기록 · 장부 판정이 없는 고아 런을 실행 중 들여다봤으면 보류. 이 중 첫 담금질 전에 막아야 할 것이 있는가.
7. **변이 제외** (하네스 머리글) — DQ Q9 대로 좁힌 설명이 맞는가.
8. **새로 생긴 조용히 틀린 경로** — 내 고침이 퇴행을 여섯 번 만들었다. 꼴은 대개 같다: 한 경로의 보류를 풀려고 넓힌 규칙이 다른 경로의 증거 (fail · 입력 변경) 를 지운다. 같은 꼴이 남았는가.
