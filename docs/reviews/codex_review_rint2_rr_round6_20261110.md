## 4. 새 발견 두 건 — 모두 P3

### RR6-01 [P3] C02b가 자식 실패 rc를 버리고 PASS할 수 있음

대상 핀 aec8ca2f6cbc…의 probe:372–383. subprocess.run 결과에서 stdout의 환경 JSON만 비교하고 returncode를 확인하거나 결과에 남기지 않는다.

동일한 실제 함수 AST에 외부 입력만 메모리로 대체한 반례:

| 제공된 자식 결과 | C02b 판정 |
| --- | --- |
| unit 일치, rc=0 | PASS |
| **동일 unit, rc=1** | **PASS** |
| unit 불일치, rc=0 | FAIL |
| JSON 불량, rc=0 | FAIL |

이번 메모리 반례 재현에서 실제 subprocess·호스트 탐침은 0회다. 같은 환경 정보를 인쇄한 뒤 실패한 인터프리터도 “환경 대조 정상 종료”처럼 보일 수 있다. 결과 JSON에 자식 rc가 없어 제공된 JSON·로그만으로 과거 두 C02b의 실제 rc를 독립 확인할 수 없다.

**무너지는 것:** C02b PASS만으로 PATH python3 탐침의 정상 종료까지 인증하는 해석.
**무너지지 않는 것:** 출력된 환경 단위의 일치, C02 본체, 다른 현장 체크. 실제 kgy/gabia 자식이 rc1이었다는 증거는 없다.

최소 수정: PASS에 returncode==0을 함께 요구하고 rc를 직렬화하며, “정상 JSON+rc1” 음성을 추가한다. stderr 요약도 실패 진단에 남길 수 있다. 기존 두 현장 기록의 C02b를 정상 종료 증서로 올리려면 해당 항목의 종료 증거 보강이 필요하다. 전체 연구·siteq 재실행을 자동 요구하지 않는다.

증거: rr6_siteq_semantics/probe_siteq_predicates.py, .json. 세부 담당 문서의 Q4-CX01과 같은 발견이며 중복 건수가 아니다.

fix_plan:53/request:50의 목록을 “남는 모든 조건”으로 쓰는 것은 부족하다.
