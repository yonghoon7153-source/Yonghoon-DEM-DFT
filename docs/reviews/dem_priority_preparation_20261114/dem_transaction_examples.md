# DEM 상태 복원 — 구현 전 합성 기록 사례

## 1. 지위와 근거

바탕 69db2eb8357571f8389e9dd1e3c9b52cfddcb705의 docs/reviews/nonrint_contract_preparation_20261114/dem_p2g_transaction_contract.md §2–5를 유한 사례로 구체화했다. 권고안 전제 DTX-Q1은 그대로다. 기존 TX01–12 생산 자격 시험을 실행한 것이 아니며 solver·접촉·수치적분·재색칠·현장 명령 구현0이다. 부적합 기록을 만드는 예시와 정상 기록의 문서 계산기만 추가했다. 전체 HOLD.

물리 상태는 실제 배열이 아닌 이름표 문자열이고 step/time도 무차원 정수다. 장 수2·시도 상한2·메모리 예산10은 작은 예시 숫자이며 연구 설정/비준값이 아니다. physics 목록의 완료 표시는 수기 예시 선언이다. 실제 구성식/접촉 검사가 실행됐다는 뜻이 아니다. 실제 자료 수령기로 사용하지 않는다.

## 2. 12기록의 예상과 관측

| 사례 | 반례/정상 의미 | 직접 관측 |
|---|---|---|
| OK_DISCARD | 실패 시 상태와 공개 완료 수를 보존 | 수용1 |
| OK_CAPACITY_FAIL | 용량 초과를 TECH_FAIL로 기록하고 원 상태 보존 | 수용1, 물리 성공 아님 |
| OK_RETRY | 원 상태에서 다음 시도번호만 진행 | 수용1 |
| OK_COMMIT | 모든 선언 검사·같은 부모·한 번 시간 진행 | 수용1 |
| TX05 | 일부 grid를 남긴 폐기 | trial_not_cleared 거부 |
| TX06 | grid만 비우고 응력/소성 상태 이름표를 남김 | rollback_state_changed 거부 |
| TX07 | 용량 초과인데 완료로 발표 | capacity 거부 |
| TX08 | 동시 old3+new4+rollback2를 max4로 셈, 예산8 | peak_accounting 및 memory_budget 거부 |
| TX09 | 재시도 전에 step/time를 진행 | rollback_state_changed 거부 |
| TX10 | 이전 시도1 뒤 다시1 | retry_order 거부 |
| TX11 | 확인한 부모9가 commit 전에10으로 바뀜 | parent_changed 거부 |
| TX12 | G2P 완료 선언 없이 commit | physics_incomplete 거부 |

정상4·부적합8 기록이 각각 예상과 일치했다. 같은 사례의 stdout을 처음 콘솔로 확인한 뒤 별도 보존 실행을 했으며 반복을 고유 사례 수에 더하지 않는다. 구본 생산 코드→수정본의 red/green이 아니다. 생산 TX05–12의 구현 반례로 옮길 때는 실제 상태 배열·코드 핀에서 expected-correct 시험을 먼저 실행해야 한다.

## 3. 보호조건 대조

rollback 상태10필드(접촉 이력·응력/소성·ID·질량/부피·단계·좌표/속도·강체·RNG·step·time)를 각각 하나 바꾸면 모두 거부했다. 부적합8사례에 대해 해당 보호조건을 무시하도록 한 문서 계산기 변형이 거짓 수용함을 확인했다. 서로 다른 보호조건 이름은7개이며 TX06/TX09는 같은 rollback 조건이다. 이를 독립 변이8종 또는 생산 수정8건으로 세지 않는다. TX08 변형은 예산을10으로 바꿔 peak 합계 조건만 분리했다.

attempt에 bool·float·NaN·inf·문자열·null·음수를 넣은7관측은 예시 스키마로 거부했다. 임의 JSON 전체·물리 배열·부동소수점 극단·파일 경합을 검증한 것은 아니다. 상태 이름표의 같음이 실제 메모리 내용 불변을 보증하지 않는다. 정상 commit의 불필요 필드 변경, 여러 시도 사이 연속성, 프로세스/파일 atomicity·내구성은 이 계산기가 인증하지 않는다.

## 4. 다음 구현 연결

TX01–04는 기존 ID/이동/회전·변형/주기 사례와 연결한다. TX05–12는 실제 P2G/상태 소유 구현이 고정되면 이름표를 원 상태 배열·접촉 이력·RNG snapshot으로 치환하고 실패 주입 후 완전 불변을 검사한다. 자원 peak는 전체 동시 생존 항목·예약 용량과 실제 할당 기록으로 확대한다. 지금의 세 숫자 합으로 메모리 자격을 대신하지 않는다.

새 solver 또는 runtime guard의 구현/등록 전에는 별도 고정 핀과 독립 반박 검토가 필요하다. 이번 문서 예시로 P1 A/B·T0/T5/T11/T12·DEMP·U자격이나 물리 GO를 닫지 않는다. 별도 독립 검토 미수령, 원장 변경0.

재현: 이 폴더에서 python -I -X utf8 -B check_transaction_examples.py. 표준 라이브러리·동봉 합성JSON만 읽고 stdout으로 낸다. 원자료/엔진/네트워크/외부 프로세스를 사용하지 않는다. 출력 명칭 accepted는 예시 기록의 일관성만 뜻한다.
