## 3. (C) BML 열화모드 폭 — 이 라운드의 과학 내용

### 3-1. pyDMA 외부 검증 (§12) — **정답 있는 데이터로 독립 도달**

규진팀 폴더의 `validation_pydma_example/` 이 공개 도구 pyDMA 의 검증된 결과와 대조하는
예제였다. 외부 문헌 경로(`--si-source external --literature`)를 만들어 우리 포팅을 걸었다.

- **LLI 는 세 구현이 0.18·0.09 %p 안에서 일치한다.**
- **LAM 두 축은 1.0~1.5 %p 로 흩어지고 CU2 음극은 부호까지 갈린다.**
- **우리만 다른 게 아니다** — pyDMA **자신의 두 방법도** 같은 축에서 부호가 갈린다.

축퇴 행렬의 "LLI 가 가장 좁다" 와 **같은 결론에 외부 데이터로 독립 도달**했다.

### 3-2. 결정 실험 (§12-5~12-8) — **설정이 아니라 식별 가능성이다**

`fit_gamma_si` 를 포팅해 `--gamma-prefit --gamma-lb 0.02` 로 Track C 설정을 맞춰 재실행.

**γ 초기값을 0.25→0.02 로, 하한을 0→0.02 로 바꿨는데 CU2 의 네 값이 표시 자리까지
전부 같다** (LLI 3.00 · LAM_ca 1.98 · LAM_an −1.26 · γ 0.2407).
pyDMA blend 는 3.18 · 1.55 · **+0.27** · 0.2240.

→ **차이는 설정이 아니라 식별 가능성이다.** 이 데이터에서 **LAM 분할은 점추정으로
보고할 수 없고 폭과 함께 보고해야 한다.** LLI 결론은 안 흔들린다.

### 3-3. 결론을 도구에 넣었다 (§13) — tagged union

`fit_cycles --widths` 가 사이클마다 근최적 집합 폭을 **점추정과 같은 행에** 낸다
(`width_status`·`width_tol`·`width_is_lower_bound`·`LAM_*_lo/hi`·`LLI_lo/hi` 아홉 열,
`LLI` 바로 뒤). 별도 파일이면 표로 옮길 때 또 떨어진다.

계약은 **tagged union**: `measured` 면 여덟 칸이 전부 차 있고 `not_requested`·`failed` 면
전부 비어야 한다. **안 잰 것과 0 은 다르다** — 0 은 "완벽히 식별됐다" 로 읽힌다.
폭은 `verify.near_optimal_extrema` 재사용이고 **하한**이며 행이 스스로 그렇게 말한다.
문헌 곡선 선택이 만드는 더 큰 폭은 **여기 안 들어간다** (두 축을 합치지 않는다).

### 3-4. 실데이터 폭 측정 (§14) — dQ/dV 항은 폭을 **안 좁힌다**

`--w-dqdv` 만 바꾼 두 실행 (`width_report` rc 0 = 축 하나만 달랐음을 **기계가** 확인):

| | `w_dqdv 0` | `w_dqdv 1` | 배 |
|---|---:|---:|---:|
| LAM_PE | 3.137 | 3.388 | 1.08 |
| **LAM_NE** | **2.439** | **7.099** | **2.91** |
| LLI | 1.172 | 1.402 | 1.20 |

그리고 `w_dqdv 1` 의 **cycle 1 에서 LAM_NE 가 [−0.60, +6.50] %p 로 0 을 가로질러
부호 식별을 잃는다** — 난간도 `a_NE` 하한 접촉으로 같은 자리를 독립으로 짚었다.
LLI 가 두 설정 모두에서 가장 좁아 **세 번째 경로**로 같은 결론.

**§14-8: 이것이 전수다** — 워크북의 사이클이 `[0,1,2]` 셋뿐이라 파일럿이 곧 전체였다
(설정 21/21 · 본문 digest 동일 실측).

### 3-5. γ 항목을 닫았다 (§15) — 원인은 **RMSE 의 크기**였다

pyDMA 쌍에서 RMSE **0.473923** 을 자릿수까지 재현하고, 가설 셋(방향 규약 · "늘 끝에
붙는다" · 측정 전압 범위)을 **전부 실측으로 배제**했다.

진짜 원인: **합성 대조군 0.00065 vs 실데이터 0.4739·0.4959 — 세 자릿수 차이.**
"하한에 붙는다" 는 하한의 문제가 아니라 **어느 γ 에서도 안 맞는다는 것의 증상**이다.
진단은 `scripts/gamma_prefit_report.py`.

⚠ `mode_profile_extrema` 를 `--width-grid N` 으로 붙였으나 **합집합 이득 0** · 벽시계
**+64 %** 라 **기본 꺼짐**이다. 이득 없는 축을 켜 두지 않는다.

## 5. ★ 이 라운드의 핵심 질문 — chain rule 편향을 어떻게 할 것인가

**아직 저장소에 고정하지 않았다.** 이 절은 발견의 신고이고 수정의 보고가 아니다.

### 5-1. 무엇을 쟀나

`bms_balancing/model.py` 의 `dv_cell` 이 합성 함수의 미분에서 **`1/a_PE`·`1/a_NE` 를
누락한다**:

```python
def dv_cell(self, p, x):
    return (self.half.dv_PE((x - p[1]) / p[0])
            - self.blend.dv(np.atleast_1d((x - p[3]) / p[2]), p[4]))
    # ⚠ 1/a_PE, 1/a_NE 누락
```

`FINDINGS.md` §1-2 는 이 결함을 **이미 알고 있었다.** 이 라운드에서 새로 한 것은
**결과를 잰 것**이다:

| 측정 | 값 |
|---|---|
| 합성 truth 왕복, `rmse_pocv(p_true)` | `4.97e-17` (정상) |
| 같은 점에서 `rmse_dvdq(p_true)` | **`1.05e-01`** — 참값에서 잔차가 0 이 아니다 |
| 코드 미분 vs 참 미분, 상대 rms | **7.87 %** |
| `1/a` 를 넣으면 | **0.12 %** |
| **A (현행) LAM_NE 오차** | **−3.3921 %p** |
| **B (chain rule 고침) LAM_NE 오차** | **−0.0171 %p** |

**200 배다.** 그리고 `w_dvdq`(dV/dQ 항, chain-rule 영향받는 항)의 기본값은 **1.0 = 항상
켜짐**이다. `w_dqdv`(dQ/dV)는 0.0 이고 **다른 항이다** — 섞지 말아 주기 바란다.

### 5-2. 왜 아직 안 고쳤나

**원본 MATLAB 도 같다.** 우리 포팅의 버그가 아니라 **충실한 이식**이고, 저쪽 모델 자신의
불일치다 (`FINDINGS.md` §1-2). 그래서 고치는 것은 **포팅 충실성을 깨는 결정**이다.

### 5-3. 리뷰어에게 묻는 것

1. **고쳐야 하는가, 충실 포팅으로 유지하고 편향을 문서로 고정해야 하는가.** 우리 판단은
   "둘 다" — 기본은 A(충실) 유지 + `--chain-rule-fix` 로 B 를 열고, **회귀가 200 배를
   고정**한다. 이 설계에 반대할 근거가 있는가.
2. **B 가 옳다는 것을 합성으로만 보였다.** 실데이터 A vs B 는 미실행(사용자 기계).
   합성에서의 200 배가 실데이터로 이전된다고 가정하지 않는다 — 이 가정을 어디서 깰 수 있는가.
3. **§3-4 의 폭 측정은 A 에서 쟀다.** chain rule 을 고치면 폭이 좁아지는가. 우리는
   **모른다** — 편향과 폭은 다른 축이고, 편향이 사라져도 축퇴는 남을 수 있다.
   이 구분이 맞는가.
4. **`w_dvdq` 기본 1.0 이 위험한가.** 항상 켜져 있고 chain rule 영향을 받는 항이다.
   기본을 0 으로 바꾸면 편향은 줄지만 **정보도 줄어든다**. 어느 쪽이 덜 나쁜가.
