# 정상 60초 후보 — 독립 수신 검토

2026-09-30. **오프라인 준비본 수용. 제안한 변경부 12군 46사례 검증은 진행 가능한 범위다. 기능 검증 완료나 실제 60초 실행 GO는 아니다.**

검토 범위에서 한정 검증 착수를 막을 새 결함은 찾지 못했다. 다음은 같은 준비 문서 반복이나 30초 재계산이 아니라, 사용자가 별도로 승인한 변경부 검증이다. 첨부된 승인 초안을 실행 지시로 취급하지 않았다.

## 2. 변경 범위와 두 기준 비교

Java의 7개 선언 치환 항목과 entry의 4개 치환 항목을 순방향 적용한 전체 바이트가 새 소스와 같고, 역치환한 전체 바이트가 30초 소스와 같다. Java의 변경은 목적/클래스/완료 표식, 시간 상한과 요청 tlist다. 물리·물성/OCP·초기화·메시·전류·sigma·solver/guard·출력 API 본문을 바꾼 차이는 없다.

요청시각은 기존 437개 전체를 정확한 앞부분으로 보존하고 30.1–60초 0.1초 간격 300개를 추가한 **737개**다. 중복 없이 증가하며 마지막은 60이다. 이는 실제 accepted/stored 상태 개수의 고정값이 아니다.

PS 부모 `GDecision`도 B020 결과의 존재·PASS·시간 범위·누락 배열·유한값·허용치를 필수 소비한다. 정상60, 보호중단 미완, 오류 미완은 구분돼 있다. 실제 함수가 해당 분기를 정확히 실행하는지는 다음 제한 검증 대상이다.

## 3. 다음 검증안 수용 범위

계획은 중복 없는 **12군 46사례 = Python 27 + COMSOL-free Java helper 4 + Windows PowerShell 5.1 15**다. 아직 실행된 사례는 없다.

실제 consumer→entry 연결, checkShape/TIMES 추출 Java, 실제 GDecision을 해당 엔진에서 검증하는 구조가 적합하다. 보호중단25/45초, 30/60.1초 잘못된 종료, 두 기준의 독립 반례, 30초 뒤 요청 누락, 후기 구간, 옛 승인/결과 식별을 다룬다. 이미 수용된 전체111개·C2·Job·1198·30초 시험을 반복할 필요는 없다.

다음은 기존 계획의 실행 전 봉인 조건을 구체화한 것이며 별도 재설계 요구가 아니다.

1. 시험 전 harness·fixture·엔진 경로/현재 SHA·추출 함수/호출·기대값을 봉인한다. 정확한 후보 manifest는 위 값 그대로다. native/process/실제 입력 진입은 대상 import 전에 inert adapter로 차단한다.
2. PY02-03은 어느 threshold 필드를 변이했는지에 맞춰 정확한 기대 이유를 고정한다. PY03-05/06은 빈/0초 교집합이 요청 누락 검사에 먼저 걸릴 수 있으므로, 사전 고정 fixture의 실제 선행 검사와 기대 이유를 특정한다. 임의 예외 또는 함수 도달 전 fixture 오류를 성공으로 세지 않는다. 기존 사례 수를 늘릴 필요는 없다.

4. 각 엔진 1회, 첫 실패에서 중지하고 남은 사례/엔진을 미실행으로 보고한다. 자동 수정·부분 재시험·추가 probe는 이 범위가 아니다. helper/fixture 구성에 범위 밖 변경이 필요하면 실행 전에 보고한다.
