- **C4-A = H Phase A.** 등록 시작점 77 unit × 128 = **9,856** (C4 요청 §1). 이미 수용된 P0 끝점 조건으로 H4 22 unit 이 미실행 대상이라 **끝점 게이트만 반영한

  C4-A 의 경고 정책은 H 경로에 맞춰 구현 요청에서 따로 명세한다.
- **만들 것 (§3):** 실자료 진입점 · launcher 단계 · 외곽 / 판정기 / 끝 기록 작성기 · `reil_c4_hb` 의 Phase A 연결부 재사용 · 입력 / 판정 계약 · 무자료 시험.

2. **Phase A 연결부** — `reil_c4_hb` 의 `stage_a` · `phase_a_complete` · `rho_wave` 를 재사용하거나 동등한 동작을 보존한다 (끝점 · J_D 조건 · 단일 목적 Phase A

3. **launcher 단계 · 외곽 / 판정기 / 끝 기록 작성기** — v6 의 세 단계 밖이므로 새 판에서 C4-A 단계를 더한다.

### 3-2. 수의 판정 (N2)

- 기록 · 판정은 **등록 9,856 / 조건 제외 (H4 끝점 게이트 22 unit · J_D 마스크 · ρ 선행 조건) / 착수 / 완료 / 중단 / 미착수** 를 나눠 세고 이유를 남긴다.
- 판정기를 "9,856 (또는 7,040) 회 반환해야 정상" 으로 만들지 않는다 — 금지된 H4 실행을 요구하거나 정당한 미실행을 오류로 볼 수 있다. 미완 · 중단을 UNFIT
  이나 완료로 바꿔 세지 않는다. 기존 H4 판정을 뒤집거나 다시 시험하지 않는다.

### 3-3. 입력 / 판정 계약 — 구현 요청의 산출물 (N3)

1. **소스 식별:** H / HB · 새 진입점 · launcher · 외곽 · 판정기 · 끝 기록 작성기 등 실제로 소비되는 소스의 정확한 목록과 승인된 식별값 (sha · bytes).
