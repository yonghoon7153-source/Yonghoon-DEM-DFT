## 4. 리뷰가 확인해준 것 (반박 불필요)

- α = (1−LAM)/r, β 부호 규약, `inventory.py`의 LLI 유도 — **전부 정확**
- 상수 w_PE=0.2909 / w_NE=0.7091 / κ=0.7057 — manifest 실측치와 일치
- `to_modes_halfcell`의 Δ(테이블 구간) 약분 — LAM·LLI 모두 성립.
  잔존하는 것은 **범위 오프셋**뿐이고 ocp 테이블(≈[0,1])에서 1e-4 수준으로 무시 가능
  (단 sim 테이블이면 ε≈2.2 Ah로 크게 틀림 → F11로 가드 추가함)
- truth 라벨 lli와 fitting LLI가 같은 정의 (de-type 격자에서)
- 불능 조건 924개 → 3993−924=3069 계산 재현
- `"Battery negative electrode bulk open-circuit potential [V]"`는 pybamm 소스상
  **흑연(primary) 단독**이지만, LAM_NE가 Gr·Si vf를 같은 비율로 줄이므로
  평형 사상이 모든 셀에서 동일 → affine 관계 보존. 규약 정합 확인

## 5. 만들지 않기로 한 것 — 엔지니어링 유보 (2026-08-05)

### 목적함수 JAX/GPU화  → **유보 (지금 만들지 않음)**

발단: "PyBaMM/DFN을 CUDA에서 못 돌리나"라는 질문에서, DFN GPU화는 경로 부재로
확정(→ `docs/GPU_NOTES.md`)되었고, **대신 Phase 6 가중치 sweep이 GPU의 유일한
후보**로 남았다. 그것도 만들지 않기로 한다.

**계산량 (V100 실측 6.65 s/cond → (조건×목적함수)당 ≈53 thread-초 기준)**

| 시나리오 | 계산량 | 32스레드 CPU |
|---|---|---|
| 목적함수 4종 비교 (sweep 없음) | 3,069 × 4 | 5.7 h |
| `w_dqdv` 1차원 9단계 | 3,069 × 9 | 12.7 h |
| 3차원 5×5×5 | 3,069 × 125 | **176 h** ← 유일한 문제 지점 |

**GPU보다 먼저 쓸 수단 (합쳐 50~100배) — Phase 6 구현 시 기본 포함**

1. 조건 층화 subsample ~400개 — 가중치 선택에 3,069개가 필요 없다.
   degeneracy 비율을 ±2%p로 추정하면 충분. **7배**
2. warm start — 가중치를 조금 바꾸면 최적해도 조금 움직인다. 직전 해에서 출발. **4~5배**
3. sweep 단계 허용오차 완화 — `xatol=1e-7`은 dQ/dV 항 때문에 조인 값이고,
   LAM 정밀도 0.005면 충분하다. **2배**

→ 3차원 sweep이 **176 h → 2~5 h**. 하룻밤이면 끝나고 GPU가 불필요해진다.

**만들 때 치르는 값**

- 목적함수 JAX 재작성 + 배치 optimizer = 며칠
- **새 정합성 검증 표면**: JAX판 J와 numpy판 J가 같은 답을 주는지 조건마다 확인해야
  하고, 안 하면 "Phase 6 결과가 어느 쪽이냐"는 질문이 생긴다. 이 코드베이스는 이미
  미묘한 규약 함정(기준 곡선, LLI 부호, α 소프트 벽)을 여럿 안고 있어
  **검증 표면을 늘리는 것이 가장 비싼 선택**이다.
- 순서 문제: 주 결과("degeneracy X% → Y%")를 손에 넣기 전에 인프라부터 만드는 것은
  거꾸로다. 3차원 sweep이 실제로 필요한지도 Phase 6을 해봐야 안다.

**재검토 트리거 (이 셋을 모두 만족할 때만)**

1. Phase 6의 `w_dqdv` 1차원 sweep 결과가 애매해서 3차원 격자가 **정말** 필요하고
2. 위 CPU 최적화 3종을 **이미 적용했는데도**
3. 하룻밤(8시간)을 넘길 때

### surrogate NN 학습  → **유보**

용도가 "PyBaMM solve 대체"인데 곡선 3,069개를 이미 확보했다. 훨씬 촘촘한 격자가
필요해지면 그때 의미가 생긴다. 지금은 **없는 문제를 푸는 것**.

### DFN GPU화 (JAX)  → **불가 확정, 유보 아님**

`docs/GPU_NOTES.md` 참조. terminate event 미지원으로 우리 프로토콜을 표현할 수 없고,
DFN은 JAX 컴파일 자체가 35분 내 미완료. 재검토 조건 없음 — 경로가 존재하지 않는다.
(SPMe는 JAX에서 2.7초에 돌므로, 모델 하향을 감수한다면 vmap 배치는 가능. 단
DFN→SPMe 곡선 손실이 degeneracy 신호보다 크면 무의미 → Phase 7-2에서 정량화)
