# 심층 리뷰 ② — 통제 RVE 에 **VGCF 팔 추가** (항목 ②) 실행 전 검토 (2026-08-18)

계기: 실침대 구 스탬프가 σ_e 이득 **+12.3 %** 인데 통제 RVE(CL-31)는 **5~6 %** 라 2배 어긋났고,
후보로 (a) RVE 의 SDCP 배치가 균일 랜덤 합성 (b) RVE 에 VGCF 가 없음 을 열거했다.
그것을 가르려고 **RVE 에 VGCF 팔을 추가**하려던 참이었다.

읽은 것: `sdcp_stamp_confound.py` · `step3_transport_resolution.py` · `step3_sigma.py` ·
`fibre_segment_raster.py` · `sr01_realbed_ab.py` · claims CL-31/CL-34.

---

## 총평 — 계획 ②는 **현 상태로 실행 불가**이고, 실행돼도 판별력이 없다

세 겹으로 막힌다: ① `build()` 의 point 경로가 CL-31 이 아직 못 채운 **vox 0.15 에서 실제로
죽는다**(재현) ② "참 구" 팔이 vox 0.4/0.3/0.25 에서 **구가 아니다**(입자의 78.7/47.8/19.3 % 가
셀 0 개 — 생산 게이트가 거부하는 영역) ③ VGCF 를 넣으면 SDCP 와 **똑같은 종류의 격자-의존
표현부피 인공물**을 새로 들여온다.  그리고 2배 격차의 후보 (a)(b) 열거가 **불완전**했다 —
최소 3개가 빠져 있다.

## 1. `lattice_shift` 두 경로의 격자 위상 규약 — **같다** (오염은 다른 데서 온다)

`rasterize_spheres` 는 셀 중심을 `(i+0.5)·vox − sh` 에 놓는다 → 그 셀의 경계는
`[i·vox − sh, (i+1)·vox − sh)` → 점이 드는 셀은 `floor((p − origin + sh)/vox)` 로
`sdcp_stamp_confound.py` 의 point 경로와 **정확히 일치**한다.  무작위 2,000 점 × 8 팔 전수
대조에서 불일치 **0 건**.  payload 의 `--step3-origin-shift`(`_lo3 = tuple(-_osh)`)와도 같다.
⇒ **위상 규약은 문제 없다.**  문제는 **포함창과 클립**이다.

## 2. BLOCKER — `build()` 가 `sid.shape[0]` 로 세 축을 클립 → IndexError (재현)

`rasterize_spheres` 는 **이동한 축만** +1 셀을 준다.  `--len-um 20 --vox 0.15`, sh=(0.075,0,0)
이면 격자가 **(134, 133, 133)** 인데 옛 코드는 y·z 도 134 로 클립했다:

```
IndexError: index 133 is out of bounds for axis 1 with size 133
  sdcp_stamp_confound.py:66  sid[ijk[:,0], ijk[:,1], ijk[:,2]] = SID_SDCP
```

**재현했다.**  ⇒ CL-31 이 "진행중" 이라 적어 둔 vox 0.2/0.15 팔은 **오늘 그대로 죽는다.**
docstring 기본 `--len-um 12` 는 12/0.15 = 80 이 정수라 우연히 안 죽고, **옛 selftest 는
`build()` 를 한 번도 부르지 않아** 원리적으로 못 잡았다.

부수(H1): point 팔은 축별 크기가 갈리는 팔에서 SDCP 를 최대 2.2 % 잃는데 sphere 팔은 하나도
안 잃는다 ⇒ 팔간 표본 이동 + **점↔구 팔 간 SDCP 개수 불일치** = CDX-R2-01 이 crop 에 대해
지적한 결함이 클립에서 재발.

→ **수정 완료** (`fa1145d1`): 축별 `n3` 클립 + 사전 창 제거(클립이 유일 판정자) + 재현 회귀 ④④b④c.

## 3. BLOCKER — "참 구" 팔에 생산 게이트가 없다.  거친 격자에서 입자가 통째로 사라진다

`build()` 의 sphere 경로에 `d/vox ≥ 2` fail-closed 게이트(`step3_sigma.py:286`)가 **없었다**.
실측 (Ø0.30 구, 입자 5,659, 재현):

| vox | d/vox | 셀/입자 | **셀 0개 입자** | 부피/참 | 생산 게이트 |
|---|---|---|---|---|---|
| 0.40 | 0.75 | 0.213 | **78.7 %** | 0.961 | **거부** |
| 0.30 | 1.00 | 0.522 | **47.8 %** | 0.991 | **거부** |
| 0.25 | 1.20 | 0.915 | **19.3 %** | 1.006 | **거부** |
| 0.20 | 1.50 | 1.775 | 1.0 % | 1.000 | **거부** |
| 0.15 | 2.00 | 4.120 | 0.0 % | 0.979 | OK |

⇒ **vox 0.4 의 "참 구" 팔은 사실상 "점 스탬프에서 입자의 79 % 를 무작위로 지운 것"** 이다
(생존 입자당 정확히 1 셀).
⚠⚠ **총 부피비가 0.96~1.01 로 멀쩡해 보인다** — 입자 수 감소와 개당 부피 증가가 상쇄하기
때문이고, **부피비 검증을 통과한 것이 이 결함이 오래 산 이유**다.

⇒ **CL-31 의 "참 구 이득 5~6 % 로 평평하다" 는 무효**다.  평평함을 주장하려면 두 점 이상이
필요한데 합법 점은 **vox 0.15 하나**뿐이다.  h1 방향 판정도 근거를 잃는다 (h1 예측이 참 구
11.20 % 였고 그 값이 나온 격자가 불법).
⇒ 따라서 **CL-34 의 "통제 RVE 와 2배 어긋난다" 도 철회**한다 — 비교 대상이 무효였다.

부수 확인: 발표된 값 자체가 이것을 말한다 — 이득/표현부피가 **0.065~0.076 %/µm³ 로 상수**다.
즉 이 RVE 에서 이득은 표현부피의 선형함수이고 **공간 분산에 둔감**하다 = (a)(b) 가 묻는 바로
그 변수에 반응하지 않는 계측기였다.

→ **수정 완료**: 생산 게이트 미러 + 재현 회귀 ⑤⑤b.

## 4. BLOCKER — VGCF 를 넣으면 **SDCP 보다 나쁜** 서브복셀 인공물이 들어온다

단위 확인: `additives.py:36` `VGCF_D, VGCF_L = 0.15, 10.0` **µm**.  (CLAUDE.md 의 "VGCF Ø
min=med=max=1.0" 은 **상대 Ø**(`dia_rel`, 무차원)이고 물리 Ø 가 아니다.)

선분 스탬프의 표현부피 (섬유 200개, `segment_cells`):

| vox | 0.40 | 0.30 | 0.25 | 0.20 | 0.15 |
|---|---|---|---|---|---|
| Ø/vox | 0.375 | 0.500 | 0.600 | 0.750 | 1.000 |
| 표현부피/참부피 | **13.83×** | 7.86× | 5.45× | 3.41× | **1.91×** |

⇒ 같은 vox 스윕에서 **7.2배 변동**하고 가장 고운 격자에서도 **1.91배 과대**다.
`diameter_preserving_sigma` 는 단위길이당 컨덕턴스만 보존하고 부피·밀어냄·SDCP 와의 접촉면은
안 고친다.  절대 규모: 20 µm RVE 에 3 wt% VGCF = 참 5.20 vol% 인데 표현부피는 **vox 0.4 에서
상자의 72 vol%** (내줄 SE 24 % + 기공 16 % 밖에 없다).

**피할 수 있는 규약이 없다** — 1 복셀 관으로는 못 피한다.  ① Ø 를 해상하는 진짜 원통 래스터
(`Ø/vox ≥ 2` → **vox ≤ 0.075 µm**, 20 µm RVE = 267³ = 1,900 만 셀, CPU 8팔×2모드는 무리)
② 또는 1D 저항망 결합(`fibre_1d_network.couple_to_voxel_grid` 가 **아직 없다** — CL-23).
어느 쪽도 "CPU 로 돌리는 값싼 팔" 이 아니다.

## 5. BLOCKER — RVE 에 **AM-AM 브리지가 없다**

실침대는 접촉마다 반경 **0.48 µm 고정 볼**(`step3_sigma.py:237-250`, 8arm `--step3-bridge-um 0.48`)을
넣는데 `rasterize_spheres` 에는 브리지 코드가 없다.  킷 AM-AM 겹침 중앙값 **0.037 µm** =
모든 격자에서 서브복셀, 89 % 가 0.15 µm 미만 ⇒ **AM 골격 연결이 격자 추첨**이 된다.
실측 σ_none 의 팔간 폭이 **20.6 %(L=12) / 21.9 %(L=16)** 로 재려는 이득(5 %)의 4배다.

## 6. VGCF 팔에 실제로 필요한 것 (없는 코드 경로)

- **SID/σ 표** — `step3_transport_resolution.py:37` 에 `SID_VGCF` 가 **없다**.  `SID_VGCF=3` +
  `SIGMA_E_VGCF` 추가로 족하다 (`sig = np.zeros(9)` 는 인덱스 3 을 이미 담는다).
- **래스터라이저** — 원통 래스터가 **리포에 없다**.  `segment_cells` 는 1 복셀 관만 굽고
  (파일 자신이 "σ 절대값에 쓰지 말 것"), **`lattice_shift` 인자를 받지 않는다** → 새 코드 필요.
- **`solve_sigma_z`** — 세 곳이 조용히 틀어진다: (i) `am_occ` 는 AM(sid 1|2)만 보고 `z_plate` 를
  정하는데 `k_bot` 은 **모든 도체**를 본다 ⇒ VGCF 가 최하층에 있으면 `z_b` 가 팔·모드마다 바뀐다
  (ii) 최상단 AM 보다 위의 VGCF 는 상판 접촉으로 **자동 승격**된다 — `none` 팔에 없는 접촉
  (iii) 실침대는 payload 가 `z_top_um/z_bot_um` 을 **명시**하는데 RVE 는 아무것도 안 넘긴다
  (iv) 상 우선순위: 생산은 SDCP 가 VGCF 를 덮는다 — 뒤집으면 계면 수가 정반대.
- **σ_VGCF** — 실침대는 vox 마다 재척도한다 (0.4 → 11.0447 · 0.3 → 19.6350 · 0.25 → 28.2743 ·
  0.2 → 44.1786 · 0.15 → 78.5398).  ⇒ RVE vox 스윕이 **격자와 σ 표를 동시에 바꾸는** 스윕이
  된다(7.1× 변동).  고정하면 실침대와 비교 불가.  **어느 쪽도 깨끗하지 않다.**

## 8. 더 싼 판별 실험 — VGCF 팔보다 셋이 낫다

1. **[공짜] 이득 %/vol% 정규화** — 기존 JSON 만으로 끝난다.  적재량·표현부피를 논쟁에서 제거.
   (단 RVE 쪽은 §3 재측정 후.)
2. **[CPU 수 분, 솔브 없음] sid-쌍 face 센서스** — 실 DBE 격자에서 SDCP↔VGCF / SDCP↔AM /
   SDCP↔SE·기공 **면 수**를 센다.  `carbon_se_contact_area` 가 이미 같은 면-순회를 하고 마스크만
   일반화하면 된다(~10줄).  `--step3-rasterize-only` 로 **GPU 없이** 돈다.  SDCP↔VGCF 면 분담이
   무시할 수준이면 **(b)는 그 자리에서 죽는다.**  ★ 최고 가성비.
3. **[CPU, 새 래스터 불요] RVE 의 SDCP 를 `seed_sdcp` 로 교체** — SDCP 는 **구**라
   `rasterize_spheres` 가 이미 처리한다.  σ 재척도도, 원통 래스터도, 서브복셀 문제도 **없다**.
   (a)를 직접 시험하며 VGCF 팔보다 압도적으로 싸고 안전하다.  ⚠ vox ≤ 0.15 로 제한.
4. **[GPU ~1.5 h × 2] 실침대에서 VGCF 를 전기적으로 죽인다** — `--sigma-vgcf 0`.
   **이미 있는 플래그**이고 `--extra-flags` 에 한 토큰 추가면 끝, **새 코드 0줄**.
   "SDCP 이득이 VGCF 채널을 통하는가" 를 정면으로 답한다.  ⚠ SBE 가 퍼콜을 잃을 수 있으나
   그 자체가 정보다.
5. **[권장 안 함] `phase_current_share`** — 그 docstring 자신이 (i) 전류가 아니라 **소산**이고
   (ii) 포락선 정리로 `∂lnσ_eff/∂lnσ_a` 와 **같은 양**이라 끝난 σ_SDCP 스윕과 독립 증거가
   아니라고 적었다.  게다가 상별이지 **경로별이 아니라** "SDCP 가 VGCF 를 잇는가" 를 못 가른다.
