## 1. 질문 · estimand (Codex §5-3 ①)

- **주 estimand (효과)**: `d_s(E_ref) = M_final(LC, s, E_ref) − M_final(LH, s, E_ref)` — SE 강성 E_ref (접촉 계약 ≤ 1 % 를 만족하는 수준) 에서의
  LC ↔ LH 차이.  판정선 · 칸 (16×16×4 · n_min 20 · x · r 0.013138) · bin 7 · 실패 규칙은 모체 §2-3 · §5 그대로.
- **보조 estimand (강성 민감도 = D-1 독립 근거)**: `q_s = d_s(E_soft) − d_s(E_ref)`.  soft = 현 생성기 (E0 최대 겹침 4.7–5.8 %) · ref = §3 의 경화 수준.
  q 의 동등성 구간 `[−b_E, +b_E]` 에 95 % CI 전체가 들어야 *"soft 결과도 유효"* 라 쓴다 (§5).  못 들면 **판정 불능** — soft 결과는 보조로만.
- **모집단**: 새 holdout 시드 분포 (§7 의 세 시드).  n = 3 (시드) — 프레임은 독립 n 으로 세지 않는다 (Codex ⑤).
- 쓰지 않는 문장: 실재 물질 영률 검증 · 실제 혼합 성능 검증 (Codex §5-3 끝) · "문헌 재현" (모체 §1-3).

## 3. 강성 축 — 무엇을 불변으로 두는가 (HBR6-02)

- **경로**: **SE 만 경화** (AM 불변) — 이름 그대로 *"SE-only stiffness sensitivity"* 로 한정한다.  전 상 비례 경화는 다른 경로 (후보일 뿐 · 이번 등록 밖).
- **E_ref = SE ×14** (dt 0.7055 → 0.3132 µs · step ×2.2525 — Codex §5-1 산술 · 실측 아님).  ⚠ 15.857 (같은 힘 환산으로 1 % 가 되는 배수) 는 **추천 입력값이 아니다** (Codex).  E_ref2 = SE ×28 (개발 · 자격화 전용).
- **불변량 (등록)**: 쌍별 **점착 힘 척도** F0 = B³/A² (생성기 근사: A = (4/3)E*√R*, B = 2πR*·CED) — 모든 쌍 (AM_P–SE · AM_S–SE · SE–SE · SE–벽 · AM–AM · AM–벽) 에서 soft 와 같게
  CED 를 **쌍별로** 역산한다 (현 생성기의 동일상 `CED ∝ E^(2/3)` 는 혼합쌍 ×1.272 · 벽 ×1.182 로 어긋난다 — HBR6-02).  ⇒ 생성기에 쌍별 목표-Bo 역산 옵션 (`--stiffen-se 14 --hold-bo-pairwise`) 을 만들고 **실제 내보낸 전 CED 행렬**로 시험한다 (셀프테스트 = 여섯 쌍 힘 척도 비 1.000).
- **남기는 차이 (보존 못 함 · 기록)**: 분리 일 U_sep (= B δ0²/10 · ×14 에서 0.172 배) · 접촉 시간 · 접선 강성 · 감쇠 · 이력 · AM/SE 영률비 103.7 → 7.41.  이들의 영향은 **최종 관측량 (q_s) 수렴 시험으로만** 제한한다 — 그것이 §1 의 보조 estimand 다.
- 덱 계약: 같은 E 안의 LC ↔ LH 허용 diff = **B** (다섯 쌍 CED · 모체 §2-2) 그대로.  E 사이의 계획된 차이 (영률 · dt · CED 행렬 · 덤프 간격 · 정착 step) 는 **새 허용목록 `E`** 로 따로 검사한다 (Codex ⑩ — B 를 끄는 방식이 아니다).  `mixer_deck_diff.py --allow E` 신설 · 반례 (E 밖 필드 변경 · 한 쌍만 다른 CED) 먼저.

## 5. 오차 예산 · 판정 규칙 (Codex §5-3 ⑤ ⑥ ⑧)

- **b_E = 0.02** — 최소 중요 차이 (MID) 0.10 의 20 % 를 강성 오차에 배정한 **저자 오차 예산** (문헌 상수 아님).  ⚠ 저자가 판단 근거가 없다고 위임했으므로 이 값은 **내 제안**이다 — Codex 7 차가 검토한다.  나머지 예산: 수치 반올림 (영수증 위치 경계) · 프레임 수 (N/N) · 정규화 (E0) 는 §5 의 불확정 규칙으로 흡수.
- **q_s 판정**: 세 holdout 시드의 q_s 평균과 표준오차 → t(2) 95 % CI ⊂ [−0.02, +0.02] 면 *"soft 결과 유효"*.  아니면 **판정 불능** (동등성 아님 · 차이 유의도 아님).  개별 팔 오차 0.02 두 개로 contrast 를 인증하지 않는다 (Codex ⑥) — q_s 를 직접 본다.
- **주 판정 (E_ref)**: 모체 §5 판정선 `Δ ≥ 0.10 ∧ Δ ≥ 2·SE` 에 불확실성을 전파 — Δ 의 반올림 · 영수증 위치 경계 · 프레임 결손 (N/N) 을 합한 폭 u 를 두고, `Δ − u < 0.10` 또는 `Δ − u < 2·SE` 면 **불확정** (Codex ⑧ — Δ = 0.101 을 무조건 확정하지 않는다).
- E0 정규화: `M = (S0² − S²)/(S0² − SR²)` 의 SR² 은 **같은 강성의 E0** 에서 (Codex ⑦).

## 8. 실행 규약 (Codex §6 · §7)

### 8-1. 같은 환경
ibb 같은 바이너리 (`lmp_mpi` sha256 봉인) · 같은 MPI launcher · **같은 rank 수 NP (모든 팔 · E0 포함)** · 같은 분할/스레드/바인딩 · 같은 dt 규약 · 재개 없음 (fresh) · 봉인 `launch_record.json` (`launch_policy.json` id · sha256 포함).  rank 수가 20 이 아니면 그 수의 **빈 메시 A/B 위상 영수증** (Q2 순서 불변 비교기 · 선택 rank) 을 먼저 만든다.

### 8-2. 순서 (§9 D-4 유지 · Codex §6 끝 · §7-2)
1. 개발 블록 (§2 · 7 짧은 런) → §4 자격화 → 이 문서 §3 수준 확정 (Codex 7 차 GO 전에 가능 — *"D-1 개발 실험은 막지 않는다"*).
2. Codex 7 차 GO.
3. **확인 18 런을 한 번에 제출** — 첫 holdout 시드 블록 (6 런) 은 즉시 · 나머지 두 시드 블록 (12 런) 은 `sbatch --hold`.  같은 시드의 LC/LH 쌍은 같은 블록 (Codex: 처치와 실행 블록을 완전히 정렬하지 않는다).
4. 첫 시드 `LC_ref`/`LH_ref`/`LC_soft`/`LH_soft` 의 bin 0 → `mixer_smoke_blind.py` 증서 (M 비열람) → `launch_highbo.sh rest` 관문 → 통과면 `scontrol release` (관문이 release 명령을 낸다 · 사람이 손으로 풀지 않는다) · 실패면 전체 HOLD.

### 8-3. 코어 분배 (*"다 병렬로"*)
QOS `cpu-60` = 60 CPU.  같은 NP 를 모든 팔에 쓰므로 동시 실행 수 = ⌊60/NP⌋; 나머지는 대기열이 순서대로 채운다 (backfill).  총 처리량은 NP 와 무관하게 60 코어 상한이므로 hold 는 벽시계를 늘리지 않는다 — 다만 stiff 팔은 step 이 2.25 배라 먼저 끝나는 soft 팔의 코어를 대기열이 바로 재사용하도록 **전 런을 처음에 제출**한다.
NP 는 개발 블록에서 **실측** (step/s at NP ∈ {5, 10, 20} — 1 h 프로브) 뒤 이 문서에 적는다 (⬜).  ETA 도 그때 (지금은 어림 ≈ 10-14 ~ 10-20).

### 8-4. 실패 · 교체 규칙 (Codex §7-1)
기술 실패 (TECH · 완주 못 함 · 덤프 결손) → 같은 시드 새 폴더에서 **한 번** 재실행 (옛 폴더 보존 · 봉인 기록) · 두 번째도 실패면 그 시드는 탈락으로 보고 (교체 시드 없음 — M 을 보고 고를 수 없게).  QC 실패를 빌미로 유리한 시드만 남기지 않는다.  unblind = 18 런 완주 뒤 한 번 (blind_log 에 시각 · 사람).
