## 3. 승인할 작업 단위와 변경 경계

후처리 작업 1건, 대상 복사본의 새 Desktop 열기 최대 1회다. 한 번의 세션 안에서 아래 성공 순서대로 여러 Results 평가·내보내기를 할 수 있으며 실제 횟수를 기록한다. ‘한 건’을 Evaluate 호출 한 번으로 오해하지 않는다. 실패 후 재열기·재제출·표현식 치환 재시도는 허용하지 않는다.

허용할 변경은 **열린 복사본의 메모리 안에서 Results 하위의 평가/표/내보내기 노드와 필요한 결과 전용 데이터셋을 추가·설정하는 것**뿐이다. 이 과정은 모델 메모리 상태의 변경이므로 ‘모델 변경 0’이라고 표현하지 않는다. 원래 dataset은 수정하지 않으며, 물리·기하·메시·Study·solver·초기조건·OCP·threshold·coupling 설정은 읽기만 한다. 입력 MPH Save/Save As, Java 저장/생성은 하지 않는다.

현지 사용자가 GUI 조작을 담당한다. 조작 도구가 없으면 안내하고 사용자의 실제 화면/내보낸 파일을 기다린다. 보지 않은 화면을 가정해 일괄 조작하지 않는다. 현재 보안 정책에서 정상적으로 허용되는 파일 선택과 결과 내보내기만 사용한다.

## 4. 순차 절차

### A. 사전 확인과 저장 해 식별

- 입력 전 크기·SHA, 기존 비교 자료, 기존 미저장 모델/계산 유무를 확인한다. 충돌·자원 부족이면 다른 작업을 종료하지 말고 알린다.
- 해당 복사본을 최대 1회 연다. 로드 시 계산·복구·변환·제한 해제를 요구하면 중지한다.
- 기존 dataset의 표시 이름, 태그가 실제 보이면 태그, 연결된 solution/component와 시간 선택을 기록한다. 예상은 daudit→sol1/comp1이지만 아직 UI 태그 확인은 안 됐다. 이름이 아니라 저장 시간의존 해와 component 연결까지 확인한다. 초기화 해나 t=0만 선택된 상태로 진행하지 않는다.
- 결과 평가의 Time selection을 **All**로 고정한다. `First`/`Last`/`Interpolated`나 187개 시각을 직접 입력하는 방법으로 저장 시간 목록을 대신하지 않는다. 공식 문서에서 All은 전체 시간 step, Manual은 인덱스, Interpolated는 입력 시각 평가로 구분된다. [시간 선택](https://doc.comsol.com/6.3/doc/com.comsol.help.comsol/comsol_ref_results.37.004.html)

### B. 최소 확인 — 시간과 전해질 최소값

새 Global Evaluation/새 표에서 다음을 평가한다. 다른 시점의 기존 표에 append하지 않는다.

| 항목 | 기존 모델에서 사용할 표현식 | 확인 단위 |
|---|---|---|
| 시간 | `t` | s |
| 전체 최소 | `comp1.minguardall(comp1.cl)` | mol/m³ |
| 영역 1/2/3 최소 | `comp1.minguard1(comp1.cl)` / `comp1.minguard2(comp1.cl)` / `comp1.minguard3(comp1.cl)` | mol/m³ |
| 정상 임계값 | `ce_stop_threshold` | mol/m³, 값 0 |
| 전해질 조건 | `comp1.minguardall(comp1.cl)<=ce_stop_threshold` | 1 |

좌표 argmin은 **이번 평가에 넣지 않는다**. 기존 `comp1.x` 오류를 수정·시험하는 작업도 이번 범위 밖이다. 전체/영역 최소값을 GUI의 다른 기본 Minimum 연산으로 대체하지 않는다. 목적은 solver guard가 사용하는 같은 coupling 식을 되읽는 것이다.

처음에는 자동 추론 단위를 기록하고, 지원되는 표준 Results 단위 설정으로 명시 단위를 적용한 결과를 별도 파일에 남긴다. 단위가 없거나 예상과 다르면 임의 표기만 바꿔 성공 처리하지 않는다. 의도한 단위 확인을 위한 두 평가는 사전 계획된 비교이지 실패 후 재시도가 아니다.

전체 정밀도·열 이름·단위를 포함해 새 CSV로 내보낸다. COMSOL Table Export의 Precision=Full을 사용하고 GUI 표시 반올림 값을 수동 전사하지 않는다. 기존 파일 overwrite/append 대신 고유 새 파일을 사용한다. [표 내보내기](https://doc.comsol.com/6.3/doc/com.comsol.help.comsol/comsol_ref_results.37.218.html)

OS 측 읽기/분석으로 행 수, 유한값, 증가하는 중복 없는 시간, 첫/끝 시각, 전체 시각 목록을 확인한다. 과거 메타데이터의 987개와 다르면 이유를 조사·보고하며 숫자를 맞추지 않는다. 이 단계가 불완전하면 뒤의 큰 평가를 시작하지 않는다. All+t 표가 확보됐다는 사실만으로 바이너리 해 필드 전체를 읽었다고 주장하지 않는다.

### C. 필수 물리·비간섭 출력

B를 완료한 경우 같은 세션·같은 저장 해·같은 All 시간 선택으로 다음을 분리해 회수한다. 식은 기존 검토된 정상/기준 소스와 대조해 확정한다. 새로운 물리식을 만들거나 부호를 추정하지 않는다.

1. **기존 두 OCP/고체 표면 guard**의 정확한 식과 상태. 기존 stguard 배열에서 읽되 수정하지 않는다. 전체 세 조건의 활성 상태와 정상 threshold를 화면/기존 기록과 대조한다.
2. **전압**: 기존 boundary1/4의 전위 출력과 동일한 식·경계·부호를 사용한다. 임의의 global 전위 한 개를 셀 전압으로 바꾸지 않는다.
3. **전극별 표면 조성 프로파일**: 기존 전극당 241개 입력 좌표·단위·순서·전극 측 선택과 같은 평가로 회수한다. 표면 조성을 입자 평균값이나 전극 평균값으로 대신하지 않는다. 경계에서 어느 전극의 값을 읽는지 확인하고, 정의 불명확/범위 밖/NaN이면 중지한다.
4. **Li 재고·OCP 범위·초기값·기존 필수 전류/수지 출력**: 기존 보고서와 분석기의 수치 판정에 필요한 항목을 같은 정의로 회수한다. 시각별 값과 단위를 보존한다.

고정 좌표 평가에 표준 Cut Point 1D/Point Evaluation을 사용하는 경우 기존 공간 평가와의 대응을 기록한다. COMSOL은 좌표 목록 및 파일 입력을 지원하며 snapping을 선택할 수 있다. 본 비교에서는 임의의 정규 격자로 바꾸거나 가장 가까운 경계로 snap하지 않는다. 기존 유한요소 해를 지정 공간좌표에서 평가하는 것과 없는 시간 값을 시간 보간으로 만드는 것은 다르다. [Cut Point](https://doc.comsol.com/6.3/doc/com.comsol.help.comsol/comsol_ref_results.37.049.html)

표준 GUI에서 기존 프로파일 평가 정의와 동등하게 설정할 수 없으면 그 항목을 미완으로 남기고 중지한다. 새로운 Java/API 호출로 자동 전환하지 않는다. 모든 가능한 출력식·내보내기 설정은 각 평가 전에 검토하고 잘못된 메뉴/식에서 생긴 오류를 반복 실행으로 덮지 않는다.

### D. 독립 수치 대조

현재 승인안은 COMSOL과 통신하지 않는 별도 Python 등으로 새 CSV를 읽고 비교하는 것을 포함한다. 기존 파일은 읽기만 하며 새 폴더에만 결과를 쓴다. 분석 전에 사용할 기준 파일·식·좌표·시간 목록·허용기준을 고정하고 기록한다.

- 기존 계약의 요청 187개 시각과 정확 공통 저장 시각을 **별도로** 비교한다. 0.1–1, 1–5, 0–1, 0–5초 네 구간 × 두 시간 집합, 총 8개 비교다.
- 요청 시각이나 좌표가 누락되면 보간·반올림·근접 대체하지 않는다. 출력 정밀도/직렬화 표현 때문에 대응이 불명확하면 그대로 조사하고 통과를 보류한다. 내보낸 숫자의 정밀도가 내부 double 비트 증명은 아님도 기록한다.
- 기준은 최대 |ΔV| ≤ 0.001 V 및 최대 pointwise |Δx| ≤ 0.0001. V/mV를 명확히 구분하고 최대의 시각·전극·좌표를 남긴다.
- 전체 최소값과 세 영역 최소의 min을 대조한다. 기존 복구 분석기의 절대 허용차 1e−9 mol/m³를 유지하고 결과를 보고한다. 정상 threshold=0, 감시 최소>0, 세 guard 미발동을 확인한다. 동률 영역은 모두 기록하며 argmin 좌표를 유일한 발생 위치로 추정하지 않는다.
- 기존 Li/OCP/초기값/전류 기준을 완화하지 않는다. 기준을 특정할 자료가 없으면 새 허용차를 만들어 PASS를 내지 않는다.

### E. 종료 보존과 보고

수치 성공 여부와 무관하게 안전하게 종료할 수 있는 범위에서 입력 후 해시·보안 관련 기록값·실제 조작·내보낸 파일을 기록한다. 필수 후검사를 옵션 좌표 출력 성공 뒤에 두지 않는다. UI가 응답하지 않는 등 후검사가 불가능하면 불가능 상태를 남기고 다른 작업을 일괄 종료하지 않는다.

모델은 저장하지 않고 닫는다. Results 노드의 메모리 변경은 폐기하지만 원시 CSV·설정 화면·식/단위/시간 선택 기록은 새 폴더에 보존한다. preferences 자동 쓰기는 기존 정책 검토대로 의도적 설정 변경과 구분한다. 전후 입력 SHA 동일은 디스크 보존 확인이며 메모리 내 모든 해 벡터의 불변 증명이 아니다.

## 5. 기존 분석기를 그대로 쓸 수 없는 이유

검토한 기존 복구 `analyze.py`는 completed worker, Java console marker, 1,143개 속성 및 Java before/after 내보내기를 전제한다(40–61행). 95–101행에서는 argmin 좌표 CSV도 필수로 읽는다. 이번 GUI 절차에는 그런 실행 증거가 없다.

따라서 가짜 completed/marker/Java 파일을 만들거나 검사를 삭제한 뒤 옛 RECOVERY_GATE 성공값을 재사용하지 않는다. 새 GUI 출처의 별도 검증표를 만든다. 각 항목을 **이번 직접 수치 확인 / 과거 식별된 설정 기록 재사용 / 이번 미확인 / 이번 범위 제외**로 구분한다. 특히 좌표 argmin은 의도적으로 제외했음을 명시한다. 이 변경은 옛 기준 전체 통과 선언이 아니다.

이번 제출물의 최상위 판정은 ‘Desktop 필수 수치 회수 완료/부분/실패’와 ‘표본 비간섭 기준 충족 여부’다. **기존 정상 gate의 전체 종결은 회수 자료와 잔여 증거의 독립 검토 뒤 판단한다.** 발동1198은 수치가 좋아도 자동 승인하지 않는다.

- 사용자 조작·COMSOL 열기/평가/내보내기 횟수, 새 solve 0 및 batch/API 재제출 0의 관측 범위.
- 입력 전후 해시와 보안값 기록, 실패/미완 항목. 원본 worker/gate/영수증은 보존.

자원은 기존 300/320 해를 여는 Desktop 후처리 범위다. CPU 설정을 바꾸거나 이전 batch의 1800초를 GUI timeout으로 옮기지 않는다. 평가에 필요한 메모리 여유를 확인하고 응답 불명확 시 중복 실행하지 않는다. 새 출력만 작은 기록 ZIP으로 묶는 것은 가능하나 1.27GB MPH나 과거 전체 자료를 재포장할 필요는 없다. 묶지 않은 자료는 명시적인 외부 의존으로 기록한다.

## 7. 최종 경계

새 적분·메시 생성·모델 파라미터 변경·보안 완화·API 재제출·모델 저장은 승인안 밖이다. 정상 수치 복구를 시도하고 결과를 보고한 뒤 정지한다. 전체 수렴 미완·장시간 보류·OCP 외삽 금지·원본/실패 보존을 유지한다. 발동1198, 후보 C, 추가 시간/메시 계산, 전체 프로토콜·12시간 휴지·유한 sigma·sweep은 별도 승인이다.
