### 2-1. PTFE 규약 선택은 **편집 결정**이지 판정이 아니다

측정 전 등록(`ptfe_convention_prereg_20260829.md`)이 물은 것은 *"교정됐는가"* 였고
기준은 표현부피/참부피 밴드 [0.5, 2.0] 이었다.  centerline 은 **0.428 / 0.422 = 밴드 밖**
⇒ **채택 안 함**.  그럼에도 사용자가 centerline 을 본문 값으로 쓰기로 했다.

⇒ 원고는 *"selected for reporting, but not calibrated"* 로 적고 **같은 문단에 off 값 1.124
를 병기**하며, 민감도는 **Table S3c** 별도 표에 싣는다 (형식 근거 = 같은 재료계·같은 코드의
Bazzoun 2025 가 OAT 민감도를 별도 절에 싣고 본문은 공칭값 하나를 쓴다).

⛔ **원고에 쓰면 안 되는 여섯 문장** (정본 = `ptfe_convention_prereg` §이후결정):
*"centerline 이 참값에 가깝다"* · *"부피를 더 그리니 전도가 더 맞다"* ·
*"실험에 더 가까워서 골랐다"* · *"부피 측정이 centerline 선택을 지지한다"* ·
*"0 % 보다 43 % 가 물리적으로 더 가깝다"* · *"centerline 이 더 현실적인 규약이다"*.
이유: 부피비는 *"어느 쪽이 교정됐나"* 를 잰 양이고 *"어느 쪽이 전도를 더 맞게 내나"* 는
**재지 않았다** — 차단은 부피가 아니라 **연결 위상**을 따르므로 방향조차 미정이다.

### 5-2. 가져갈 것 / 가져가면 안 되는 것

정본은 `absorb_prompt_stoic_knuth_20260825.md` 이고 요지는 그대로다:

**가져갈 것 = "어떻게 검사하는가"** — `run_contract.py`(실행 계약 단일 출처) ·
`check_method_discipline.py` 규칙 J·K·L·M · `sdcp_gain_verdict.py` 매니페스트 전수 훑기 ·
`check_review_findings.py` 원장 SHA 조상 검사 · `mutation_sweep_20260825.py` ·
`.github/workflows/discipline.yml` · `reduce_arm_payloads.py`(스칼라 감사 패키지).

**가져가면 안 되는 것 = "값이 얼마인가"** 중 `quotation_ban` 등재분.  등록부가 정본이고
`check_review_findings.py --ban-sweep` 이 표지 없는 인용을 오류로 낸다.

**가져오면 즉시 생기는 일**: 규약 축이 늘어 `physics_protocol_id` 해시가 달라지고,
**옛 payload 로 만든 팔은 전부 `unknown:` 규약이라 fail-closed 로 HOLD** 된다.
이것은 결함이 아니라 의도다 — HOLD 는 *"틀렸다"* 가 아니라 *"확인 불가"* 다.

⚠ **그 규율 층의 종료조건은 독립 리뷰가 아니라 자기검증이다.**  두 관문을
**너희 기계에서** 돌려 초록이면 그것이 증거고, 아니면 가져오지 마라:
```bash
bash scripts/check_all.sh                    # 검사기 selftest + 리포 실물
python3 scripts/mutation_sweep_20260825.py   # 돌연변이 배터리 (~20 분)
```

### 5-3. 이 브랜치가 자기 자신에 대해 남긴 경고

- 자기 게이트가 **과잉차단**을 여러 번 냈고 자기 검사기가 **가짜 초록**을 여러 번 냈다
  (`SELF-02`~`SELF-09`).  전부 잡아 회귀를 붙였지만 **그 빈도가 이 층의 실제 신뢰도**다.
- 특히 마지막 둘은 5차 리뷰 대응을 **마친 뒤에** 나왔다.
- ⇒ **초록을 믿지 말고 배터리를 돌려라.**  그조차 *기대집합이 옳다* 는 전제 위에 있다 —
  관문은 '실재하지 않는 id' 는 잡지만 '실재하는 **다른** 시험을 가리키는 id' 는 못 잡는다.
