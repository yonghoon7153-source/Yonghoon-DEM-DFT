# 교차리뷰 D — 심포지엄 세션(덱 + 녹취) 표준

## ⚖ 판정 (2026-08-25 수령)

> **방향 조건부 찬성 · 10편 일괄 적용 HOLD.**
> · 첫 기준판을 **draft 로 계속 쓰기**: GO
> · v2 를 **10편 고정 표준으로 확정**: **HOLD**
> · 수치·직접인용을 downstream 에 전파: **P1 수정 후 재리뷰**

### P1 4건 — 우리가 묻지 않은 것들

| | 지적 | 상태 |
|---|---|---|
| **1** | `[말]` 과 STT 가 **같은 증거처럼** 섞여 있다. 증거층은 셋이다 — 덱 · **실제 음성** · **STT(음성의 오류 많은 파생물)**. 우리는 음성을 들은 적이 없고 **파일도 없다** ⇒ `[말 12:34]` 은 전부 `[STT 12:34]` 여야 한다. 안 그러면 **STT 환각을 발표자의 실제 발언으로 승격**한다 | ⛔ **미수정** — 양식 전면 재작업 필요 |
| **2** | **원본 사슬·공개 권한이 없다** — PDF/audio/STT 의 sha256, STT 엔진·모델, 음성 실제 길이 vs coverage, 공개/내부전용, Q&A 동의·익명화, off-record 여부. 세션마다 `source_manifest.json` 을 먼저 고정해야 한다 | ⛔ 미수정 |
| **3** | **백지로 버린 슬롯이 manifest 에서 사라진다** — 26쪽×2 = 52 슬롯인데 figures.json 엔 50개뿐이고 이유가 안 남는다. 표준의 "안 본 것도 기록한다" 와 정면 충돌. 합성 테스트에서 `Q&A` 글자만 있는 희소 슬라이드가 백지로 삭제됨 | ⛔ 미수정 |
| **4** | `_shrink()` 가 **고색상 이미지를 256색으로 양자화** — `getcolors(maxcolors=4096)` 이 초과 시 None 인데 `or []` 로 빈 목록 취급 ⇒ 조건이 뒤집혀 **색이 가장 풍부한 이미지가 가장 심하게 뭉개졌다** | ✅ **수정** (아래) |

### 즉시 수정한 것 (직접 재현 후)

- **P1-4** `_shrink()` — `None` 을 "너무 많다" 로 읽게 고쳤다. 65,536색 합성 이미지가
  `P` 모드 250색이 되던 것 → **RGB 보존 확인.** ⚠ talks 뿐 아니라 **모든 그림 추출**에
  걸려 있던 버그다.
- **nup=3 라벨** — `'ab cdef'[2]` 가 **공백**이라 `1a, 1b, "1 "` 이 됐다. `"abcdefgh"` 로 교체.

### 찬성해 준 것

- **균등 분할 유지** — "실제 확인 없이 흰 줄 자동 탐지를 넣는 편이 더 위험하다."
  내가 되돌린 판단이 옳았다. 다른 레이아웃이 오면 자동 탐지보다 **`--layout` · `--split-y`
  명시 override** 를 먼저 열라는 처방까지 받았다.
- 블록 단위 정렬 · `?/–/skip` · 불일치 세분화 · STT 6분류 · 판독 메타 (v2 추가분 전부)

### 남은 큰 숙제 (10편 전에)

1. **증거층 3분리** — 출처(`deck/audio/stt`) × 판정(`agree / transcript_error /
   deck_corrected_by_speaker / spoken_conflict / unresolved`) **두 축**으로 분리.
   badge 하나에 합치면 경우의 수가 계속 는다.
2. **`source_manifest.json`** — 해시·권한·coverage. 음성 미보유면 **direct quote 와
   `[말]` 금지**.
3. **모든 슬롯을 manifest 에** — `blank_candidate` 로 남기고 `kept:false` · `reviewed:false`.
4. **사전 외부화** — `talk_lexicons/base.json` + `_lexicons/<slug>.json`.
   현재 13개는 실제 오탈자·정상 표기(`디퓨션`,`SOC`)·의미 분기(`conversion/convection`)를
   한 목록에 섞고 있다.
5. **전문가 판단 → `전문가 관찰·가설`** 로 이름을 낮추고 `allowed_use:
   hypothesis_generation_only`. **직접 인용은 음성 재청취를 한 경우에만.**
6. **Q&A 를 별도 절로** — 질문자의 전제와 즉석 답변을 본 발표와 합치면 안 된다.
7. **coverage 헤더** — slides reviewed 50/50 · audio reviewed 0/83:11 · unresolved N ·
   citation-ready N. 부분 digest 는 정상 상태로 허용하되 `citable=no`.
8. Windows CP949 에서 selftest 상태기호가 `UnicodeEncodeError` · `12:61` 허용 ·
   시각 역행 허용 · pipe escaping 누락 · SRT/VTT 미지원.

### §4 우리 의심 셋에 대한 답

- **`?` 빈칸**: Markdown 문자만으로는 부족 — machine-readable 상태 + digest 상단 coverage.
  부분 digest 를 **정상 상태로 허용하되 citable=no** 로 막는 게 대충 채우는 압력을 줄인다.
- **500장**: 전수 1회는 봐야 한다. 단 3단계로 — ① 전수 훑기 ② 숫자·범례·불일치만 3–8×
  ③ 실제 전파할 claim 만 음성 재확인. **전수 훑기 안 한 digest 는 partial/non-citable.**
- **다리 vs 억지**: `σ→iR` 은 **결과 비교가 아니라 입력 변수의 연결**이다.
  허용: *"원자수준 이온전도도는 셀 ohmic polarization 을 구성하는 **한 입력 변수**다."*
  금지: *"우리 bulk σ 향상이 실제 셀 분극 감소를 **입증**한다."*
  **중간 전달식·추가 변수(두께·면적·공극률·tortuosity·입계·접촉)·적용 스케일을 명시할 수
  있으면 다리, 생략하고 용어가 비슷하다고 잇는 것이 억지.**

## 0. 무엇을 리뷰해 달라는 것인가

2026 전지기술 심포지엄 세션이 **자료집 PDF + 음성 녹취(STT)** 쌍으로 들어오기 시작했다.
기존 `litdb/talks/` 5편은 **덱만** 있었으므로 규약이 없었다. 2026-08-25 에 새로 세웠고,
첫 기준판(오승모 「셀 분극에 의한 이차전지의 성능」)을 만드는 중이다.

**리뷰 대상 = 그 표준 자체.** 구체적으로 셋:

| | 무엇 | 어디 |
|---|---|---|
| ① | 규약 (세 갈래 표기·필수 절·인용 등급) | `litdb/talks/README.md` 의 "🎙 녹취…" 절 |
| ② | 도구 A — 2-up 자료집 분할 | `tools/litdb/extract_figures.py` `--nup` |
| ③ | 도구 B — 녹취 파싱·오탈자 후보·정렬 뼈대 | `tools/litdb/talk_transcript.py` |

## 1. 배경 사실 (판정에 필요한 것만)

- 심포지엄 자료집 PDF 는 **텍스트 레이어가 0자인 스캔**이다(PyMuPDF `get_text()` 실측,
  26쪽 전부 0). ⇒ 슬라이드 텍스트로 키워드 정렬하는 경로가 **원리적으로 막혀 있다.**
- 자료집은 **2-up**(한 쪽에 슬라이드 2장). 쪽 렌더만 하면 두 장이 한 그림에 뭉친다.
- STT 는 전문용어를 심하게 망가뜨린다. 실측: `오승목`=오승모 ·
  `셀 코리라리제이션`/`세레콜라겐`=cell polarization · `a미타`=η · `IR 포탈`=IR drop.
- 첫 자료 규모: 슬라이드 50장(2-up 분할 후) · 녹취 80블록 / 1:23:11 · 오탈자 의심 15건.
- `litdb/talks/README.md` 에는 이미 **덱 전용 규율**(§1–4)이 있다 — 덱 수치는 논문
  digest 보다 **낮은 등급**, "저 그룹은 ~을 안 한다" 금지, 저해상 판독 금지 등.
  이번 녹취 규약은 그 **위에 얹은 것**이다.

## 2. 우리가 내린 설계 결정 — 각각 반박해 달라

### D-1. 자동 정렬을 **하지 않기로** 했다

도구는 시각 블록과 빈 표만 만들고, 슬라이드 칸은 사람/에이전트가 **이미지를 보고** 채운다.
빈칸은 `?` 로 남기고 지우지 않는다("빈칸이 곧 아직 안 봤다는 기록").

- 근거: PDF 텍스트가 없어 매칭 신호가 없다.
- **반박해 달라**: OCR 을 붙이면 되지 않나? 붙였을 때의 실패 모드(수식·한글 혼재·
  저해상)가 "정렬을 자동화했다는 착각"보다 나은가? 우리는 **틀린 정렬이 빈칸보다 나쁘다**
  고 봤는데, 이 판단이 맞나?
- 대안이 있다면: 발화 시각의 **단조성**(슬라이드는 대체로 순서대로 넘어간다)을 이용한
  약한 정렬은 어떤가 — 그게 "약한 근거"임을 화면에 표시할 수 있나?

### D-2. STT 오탈자를 **자동 치환하지 않는다**

후보만 띄우고 확정은 사람이 한다. 사전은 하드코딩된 13개 정규식(`SUSPECT`).

- 근거: 무엇이 맞는지는 슬라이드를 봐야 안다. 조용히 고치면 근거 없는 창작이 된다.
- **반박해 달라**: 13개 하드코딩 사전이 10편을 감당하나? 세션마다 용어가 달라지면
  (예: 전고체·리사이클링·안전성 세션) 이 사전은 곧 무용해진다.
  세션별 사전을 어디에 두는 게 맞나 — digest 안? 별도 json? 아니면
  **슬라이드에서 추출한 용어**로 그때그때 만드나(그런데 텍스트가 없다)?
- 지금 사전에 **오탐**이 있나? 특히 `컨버전|컨벡션` 은 "conversion 반응"과 "convection"
  둘 다 될 수 있어 일부러 애매하게 뒀는데, 이런 항목이 도움이 되나 방해가 되나?

### D-3. 세 갈래 표기 — [덱] / [말] / [덱+말] / ⛔[불일치]

숫자는 원칙적으로 **[덱]만** 인용하고, [말]의 숫자는 `구두 ≈`.

- **반박해 달라**: 이 구분이 실제로 지켜질 수 있나? digest 를 쓰는 쪽에서
  "이건 덱에도 있었나" 를 매번 확인하는 비용이 실제로는 얼마인가?
  더 싼 규칙이 있나 (예: 기본을 [말] 로 두고 덱 확인된 것만 승격)?
- **⛔[불일치]** 를 만났을 때 "어느 쪽도 인용 금지" 가 맞나? 덱이 인쇄물이니
  덱을 믿는 게 낫지 않나 — 아니면 **말이 정정한 것**일 수도 있나(발표자가 슬라이드
  오타를 구두로 고치는 일은 흔하다)? 그 경우를 어떻게 다뤄야 하나?

### D-4. "전문가 판단" 을 따로 모은다

교과서에 없고 경험에서 나온 문장을 별도 절에. 단 **"저 교수님이 그랬다" 를 논거로
쓰지 않는다** 는 단서를 달았다.

- **반박해 달라**: 이 절이 **가장 값어치 있으면서 가장 위험**하다. 검증되지 않은
  구두 발언이고, 맥락이 잘리면 왜곡되기 쉽다. 우리 단서("논거로 쓰지 않는다")가
  충분한가? 더 강한 장치가 필요한가 — 예: 인용 시 **반드시 원문 그대로 + 시각**?
  아니면 이 절 자체를 두지 말아야 하나?
- 권위 편향(authority bias)을 어떻게 막나. 선별된 전문가의 말이라 **더** 위험하다.

### D-5. 필수 절 9개를 고정

`0 한 줄 / 1 메타 / 2 정렬표 / 3 내용 / 4 전문가 판단 / 5 STT 교정표 /
6 우리 접점 / 7 인용 금지 / 8 안 본 것 / 9 INDEX·comparison 줄`

- **반박해 달라**: 10편에 이 뼈대가 과한가 부족한가? 세션마다 성격이 다를 텐데
  (튜토리얼 vs 기업 발표 vs 패널토론) 하나의 뼈대로 되나?
- 빠진 절이 있나 — 예: **질의응답**을 따로 둬야 하나(녹취에만 있고 종종 가장 날카롭다)?

## 3. 도구 쪽 — 코드 리뷰

### `extract_figures.py --nup N`
- 균등 분할이다. 위아래 여백이 다른 레이아웃에서 경계가 어긋날 수 있다(docstring 에 명시).
  **더 나은 분할 신호**가 있나 — 여백의 흰 줄 탐지? 슬라이드 테두리?
- 반쪽이 백지면 그 반쪽만 버린다(`keep_blank`). 문턱 0.995 가 맞나?
- 라벨이 `<쪽>a`/`<쪽>b` 인데 **덱 인쇄번호와 다르다**. digest 에 대응표를 넣게 했는데,
  도구가 인쇄번호를 읽어 줄 방법이 있나(스캔이라 어렵지만)?

### `talk_transcript.py`
- `_TS` 정규식이 `참석자 1 12:34` 꼴만 받는다. **다른 STT 도구의 출력**(SRT/VTT,
  `[00:12:34]`, 화자 이름 직접)도 받아야 하나? 지금은 못 읽으면 **앞 5줄을 찍고 1 로 종료**한다
  — 조용히 0개를 주지 않는 것은 맞다고 봤는데, 형식 자동 감지까지 해야 하나?
- 5분 목차(`chapters`)가 정렬 표의 행이 된다. 5분이 맞나? 83분 → 17행인데,
  슬라이드가 50장이면 **행보다 슬라이드가 많다** — 이 불일치를 어떻게 다뤄야 하나?
- selftest 는 음성 3건 포함 11건. **빠진 음성 경로**가 있나?

## 4. 우리가 스스로 의심하는 것 (먼저 적어 둔다)

1. **`?` 빈칸이 정말 지켜질까.** "빈칸이 곧 기록" 은 우리 규율이지만, digest 를 읽는
   사람에게는 그냥 미완성으로 보인다. 빈칸이 많은 digest 가 "덜 된 것" 으로 취급돼
   결국 대충 채워지는 압력이 생기지 않나?
2. **50장을 다 볼 것인가.** 논문 digest 에서도 "그림 34장 중 8장을 봤다" 같은 일이
   반복됐다. 슬라이드 50장 × 10편 = 500장이다. **전부 보는 것이 현실적인가**, 아니면
   "안 본 것을 정직하게 적는다" 로 충분한가?
3. **접점 없음을 적는 규율이 실제로 지켜지나.** §6 에 "없으면 없다고 써라" 를 넣었지만,
   억지 연결의 유혹은 자료가 좋을수록 커진다. 이 튜토리얼은 **소자 수준**이고 우리는
   **원자 수준**이라 층위가 다르다 — 그런데 "우리 σ 가 결국 iR 로 나타난다" 는 다리는
   진짜다. **어디까지가 다리이고 어디부터가 억지인가?**

## 5. 원하는 산출

- D-1 ~ D-5 각각에 **찬성/반대 + 근거**. 반대면 **대안을 구체적으로**.
- §3 도구 리뷰에서 **지금 고쳐야 할 것 / 나중에 해도 되는 것** 구분.
- §4 의 셋에 대한 판단.
- 우리가 **묻지 않았는데 위험한 것**이 있으면 그것부터.

⚠ 리뷰 대상은 **양식**이다. 첫 기준판 digest 의 내용 정확성은 별도 문제이고
지금 만드는 중이라 아직 리뷰 대상이 아니다.
