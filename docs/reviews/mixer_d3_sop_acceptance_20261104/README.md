## 판정과 핀의 범위

외부 수용 대상은 `df9a4623e2f9e6302e6bc8922bd0612ab48e120c`의 D3 SOP 및 연결 문서다. 원문 판정은 `external_verdict.txt`, 범위는 `scope_verdict.json`, 받은 원본은 `codex_d3_sop_review_evidence_20261104.zip`으로 보존했다. 원문 내 상대 경로는 받은 ZIP의 루트를 기준으로 읽는다.

받은 ZIP은 109,866 B, SHA256 `71706a409469fde4cdb0d2ed349ff0fbad6e30a4bd83510de304f920a5fab3a3`이다. 7멤버의 CRC·경로·중복·symlink와 자체 해시 목록6개를 확인했다. 안에 포함된 과거 전달 ZIP은 보관 중인 101,186 B 원본과 바이트가 같다(SHA256 `7ad7020be45b8de645a01783c1009163853b7beb6447014f947422e40eabf501`). 그 안의 문서6개를 로컬 고정 Git 객체와 바이트·크기·SHA256·blob SHA1로 대조하고 포장 해시17개도 확인했다. 포함 관계이므로 6과17을 더해 별도 성적으로 세지 않는다.

외부 `verify_documents.py`를 읽은 뒤 오프라인 무결성 대조만 다시 실행했다. rc0이고 외부 `verification_results.json`과 기록 시각을 제외한 값이 같다. 외부가 기록한 원격 메타데이터는 증거로 보존했고, 이 재실행이 새 GitHub blob 조회였다고 주장하지 않는다. `intake.json`과 `offline_verifier.json`에 범위와 결과가 있다. 판독기·전체 게이트·기계 실행·연구 자료 열람은 하지 않았다.

## 이번 문서 변화

외부 §4의 비차단 제안 D3S-NOTE01을 아래와 같이 **그대로 한 문장** SOP §3의 열람 순서 표 직후에 추가했다.

> 단위별 계산·봉인은 순차적으로 할 수 있으나, 먼저 열람한 단위 결과에 맞춰 후속 단위의 예측 생성·판독/제외·재시도 규칙을 바꾸면 기존 무맞춤 검증으로 집계하지 않고 변경 이력과 새 분석 지위를 별도로 기록한다.

기존 단위별 순차 계산·봉인·열람은 계속 허용한다. 전 단위를 동시에 계산/봉인하라는 새 조건을 추가하지 않는다. 기존 S1/S3의 고정 규칙과 무맞춤 검증의 경계를 명료화한 것이며, 수치·시드·반복·물성·허용폭·등록 상태를 바꾸지 않았다. 추가 후 SOP에서 그 문장과 빈 줄만 제거하면 외부 수용 핀의 원문과 바이트가 같다. 이 대조는 `clarification_delta.json`에 있다.

**외부 수용은 과거 고정 핀에 한정한다. 문장 추가 후 새 핀을 외부 수용 완료나 자기 종결로 표시하지 않는다.** `review_request.md`는 제안 문장 반영과 판정 이력 보존만 확인하는 짧은 후속 요청이다. 수용된 기존 초안 전체의 반복 감사나 새 통계 정책 비준을 요청하지 않는다. 발송은 1저자가 한다.
