# 제1저자 새 PC — 최소 로컬 환경 구성안

2026-09-29. **대부분의 본 계산은 모델 제공자 워크스테이션에서 계속한다.** 새 PC의 목표는 전달 자료를 이해하고, 결과를 분석하고, 필요할 때 작은 PyBaMM 재현을 할 수 있는 상태다. 이 문서는 설치 완료 보고가 아니다.

## 1. 권장 역할 분리

| 기능 | 기존 워크스테이션 | 제1저자 PC의 기본 구성 |
|---|---|---|
| 진행 중인 COMSOL 30초/후속 검증 | 기존 승인 체계로 계속 | 기존 결과 읽기; 실행은 별도 |
| 장시간·대량 sweep·연구 본 계산 | 주 실행 장소 | 기본 설치 확인에 넣지 않음 |
| CSV/JSON/그림·문서 분석 | 가능 | 바로 활용할 핵심 역할 |
| PyBaMM 작은 재현/회귀 | 가능 | 전용 venv와 회귀 4건으로 사용 가능성 확인 |
| P6 적합·다른 파라미터·프로토콜 확장 | 작업별 결정 | 기본 환경 이후 한정 작업으로 승인 가능 |
| 실험 원자료 | 제공 권한에 따른 자료만 | 제1저자 관리 공간에 보관; AI 열람/외부 공유 별도 |

## 2. 우선 설치·준비할 것

Windows PC를 가정한 우선안이며, OS/CPU 아키텍처는 새 PC에서 확인한다.

- **Codex를 사용할 공식 데스크톱 앱**: 제1저자 본인의 계정으로 로그인한다. 상대방의 인증 파일·대화 기록·`.codex` 폴더를 통째로 복사하지 않는다. 앱은 기본 사용자 권한으로 사용한다.
- **Git**: 기준 커밋 확보와 변경 확인용. 공개 저장소 읽기에는 제공자의 GitHub 토큰이 필요하지 않다.
- **Python 독립 가상환경**: 해당 OS에서 지원되는 Python을 사용한다. 기록된 Python 3.11.15와의 차이를 적되, 이 문자열 때문에 출처 불명의 바이너리를 설치하지 않는다. 설치안에서는 3.11/3.12 계열의 호환 배포부터 확인한다.
- **연구 기본 패키지**: PyBaMM `26.8.0.0`, NumPy, SciPy, pandas, openpyxl, pytest. matplotlib는 결과 그림용으로 추가한다. 필요하지 않은 JAX/GPU·전체 개발 extras·Jupyter·VS Code는 필수가 아니다.
- **COMSOL/JDK/LiveLink/MATLAB**: 기본 세팅의 필수 항목이 아니다. 이미 설치됐다면 버전·라이선스 가능 여부를 기록만 한다. 실제 사용이 필요할 때 별도 설치/라이선스/실행 경로를 정한다.

PyBaMM 26.8.0.0은 공식 배포 페이지에서 확인했으며 Python `>=3.10,<3.15`를 명시한다. 다만 모든 종속 패키지·솔버가 모든 Windows/CPU 조합에서 실행된다는 보장은 아니다. 대상 PC에서 의존성 해결과 작은 회귀를 확인해야 한다. [PyBaMM 공식 배포](https://pypi.org/project/pybamm/26.8.0.0/)

기존 `bms-balancing/requirements.txt`에는 PyBaMM이 없다. 전체 의존성도 하한만 있는 목록이므로 이것만으로 제공자 환경이 재현됐다고 할 수 없다. 설치한 버전 목록·Python 실행파일·OS/아키텍처를 새 환경 기록에 남긴다.

## 3. 폴더와 권한

사람이 할 최초 준비는 간단하다. 공식 앱을 설치하고 본인 계정으로 로그인한 뒤, 새 PC의 빈 MSC 작업 폴더를 로컬 프로젝트로 연다. 초기 권한은 읽기/승인 요청 중심으로 두고 `FIRST_AUTHOR_PROMPT_KO.md`를 붙인다. 설치안이 나온 뒤 동의하면 `SETUP_EXECUTION_PROMPT_KO.md`를 다음 메시지로 사용한다. 앱 설치 자체와 연구 패키지 설치는 다른 단계다. 표시 명칭이 다르면 해당 설치 버전의 공식 안내를 따른다.

아래는 구조 예시이며 실제 절대 경로는 사용자와 정한다.

```text
MSC-local/
  source/       고정 커밋의 저장소 사본, 연구 코드/기존 산출 변경 금지
  environment/  이 PC에서 새로 만든 venv와 설치 기록
  outputs/      새 분석·회귀 결과·그림
  handover/     받은 공개 인계 자료

private-data/   별도 위치, 기본 Codex 프로젝트/읽기 권한 밖
```

가상환경은 다른 PC에서 복사하지 않고 새로 만든다. venv의 Python 절대 경로로 `-m pip`, `-m pytest`를 호출하면 활성화 스크립트 실행 정책을 바꿀 필요 없이 사용할 수 있다. [Python venv 문서](https://docs.python.org/3/library/venv.html)

프롬프트의 “source 수정 금지”는 운영 규칙이지 OS 보안 경계가 아니다. 앱에서 가능하면 source 읽기와 outputs/environment 쓰기를 구분한다. 실제 허용 범위를 확인하고, 설치 때문에 전체 PC Full access를 기본값으로 선택하지 않는다. 공식 문서도 작업에 필요한 범위의 권한을 권한다. [Codex 권한](https://learn.chatgpt.com/docs/permissions)

Windows-native 앱/PowerShell로 시작할 수 있으며 WSL은 필수가 아니다. 단, **에이전트 환경과 통합 터미널 설정은 별개**이므로 양쪽의 Python 경로와 버전을 확인해야 한다. COMSOL의 사용자 직접 입력 콘솔과 에이전트 PTY를 같은 것으로 간주하지 않는다. [공식 Windows 안내](https://learn.chatgpt.com/docs/windows/windows-app)

## 4. 세 단계로 끝낸다

### A. 인수 확인 — 첫 메시지

`FIRST_AUTHOR_PROMPT_KO.md`를 사용한다. 문서·환경 메타데이터를 읽고, 설치 위치/패키지/권한/한정 시험 계획을 받는다. 설치·받은 코드 실행 없음. 자료 읽기에 모델 파일이나 라이선스가 없어도 진행할 수 있다.

### B. 기본 환경 구축 — 설치안 확인 후

`SETUP_EXECUTION_PROMPT_KO.md`를 사용한다. 합의한 새 경로에만 기준 커밋 사본과 venv를 만들고 패키지를 설치한다. 자동 setup script, 받은 launcher, 문서 속 COMSOL 명령은 실행하지 않는다. 기존 폴더 충돌·설치 권한/정책 문제·종속성 해결 실패는 원인을 보고하고 멈춘다.

의존성 설치 성공 뒤 `pip check`, 지정 패키지 로딩/버전 확인을 하고, 허용된 회귀 4건을 1회 수행한다. 이 시험은 작은 PyBaMM solve를 포함하므로 단순 텍스트 검사로 보고하지 않는다. 로그는 별도 outputs에 둔다. 원본 결과 JSON은 그대로 보존한다.

### C. 연구 작업 — 기본 구축 이후

기존 산출물 분석은 전달받은 데이터 범위로 수행한다. 전체 부호표 재계산·P6 다중 시작점 적합·새 셀/조건/실험자료 작업은 목표/입력/자원을 정한 뒤 별도 작업으로 준다. 주요 계산을 우리 쪽에 요청할 때는 목적·입력 식별·필요 출력만 전달하고, 제1저자 PC에서 기존 COMSOL 승인 파일을 만들어 보내지 않는다.

## 6. 넘어오면 안 되는 것

다른 PC의 `.venv`, `.codex/auth.json`, API/GitHub 토큰, COMSOL 라이선스 파일, 전체 preferences/registry 사본, 실제 승인·release·runtime/token, 다른 사용자의 절대 경로 launcher. 연구 코드/문서와 허용된 결과만 인계한다. `.gitignore`는 Git 추적 편의 기능이지 비밀 접근 통제나 ZIP 유출 방지가 아니다.
