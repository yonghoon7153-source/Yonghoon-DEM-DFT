## 1. 바탕과 범위

바탕 = `6efb44eac2b92f49418c2d791c6ff51612a1f5e7`. 정본 = docs/reviews/dem_unloading_ps45_prereg_20261009.md §15-4·15-4b. 차례 = docs/reviews/p1_g2cp_mpi_development_20261116/results_20261116/next_steps.md §3. 1저자 11-16 밤 지시를 적용한다. B의 남은 소비자/실패 경로 자격을 A의 정적 구현 관문으로 쓰지 않는다.

`prepare_rt_decks.py`는 docs/data/ps45_unload_20261009/의 **94파일을 새 폴더로 그대로 복사**하고 덱 12개와 fixture 표 1개를 추가한다. 원 키트·원 SHA256SUMS·원 러너·원 판독기는 수정하지 않는다. 복사본의 옛 SHA256SUMS는 역사 입력의 목록이며, 추가 RT 층을 봉인하거나 실행 승인하는 목록이 아니다. `RT_DECK_LAYER.json`에 원 94파일과 추가 13파일을 따로 기록한다.

생산 RT의 head/r_params는 각 침대 R의 바이트 그대로다. 따라서 10:0 RJ의 기본 S0=3600000도 유지된다. RT1과 RT2의 명령 차이는 setup 뒤 `write_restart` 한 줄이다. 30열 순서, %.17g, 원자 16열, 벽 10열 관측, run 0 뒤 undump, post/obs 구분을 생성한다. 작은 fixture는 기존 소비자 머리와 history_params.json의 합산 step=2000·입자20·big 값을 쓴다. 생산/fixture의 rt 블록은 동일한 생성 함수에서 나온다.

## 2. 확인

12메서드. RT 미구현 빈 추가 층을 기준으로 실패 15관측/오류0 → 구현 뒤 12/12. 메서드와 subtest 관측을 합산하지 않는다. 준비 과정에서 dump 토큰 위치를 시험이 7로 잘못 센 오류를 6으로 정정했다. 덱 자체는 30열이었다. 최종 동일 시험으로 앞/뒤를 다시 확인한다. fixture run 0→1, 10:0 기본 S0 변이도 거부한다. 시험은 정적 바이트와 작은 임시 파일만 다룬다.
