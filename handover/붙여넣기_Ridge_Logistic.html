이 코드의 두 축 — Ridge와 Logistic

코드가 쓰는 학습 모델은 이 둘뿐이다. 신경망도 랜덤 포레스트도 없다. 셀이 수십 개뿐인 자료에서 복잡한 모델은 외우기만 하고 일반화가 안 되기 때문에, 일부러 가장 단순한 선형 모델 두 개로 제한했다.

모델맡은 타깃내놓는 값벌점 세기후보 값
Ridge cap, cc_frac 연속값 (Ah, 0–1) alpha 0.001 ∼ 1000 (7개)
LogisticRegression true_label 불량일 확률 (0–1) C 0.001 ∼ 10 (5개)
둘 다 scikit-learn 구현을 그대로 쓴다. 자체 구현한 학습 알고리즘은 없다.

Ridge — 용량을 숫자로 맞힌다

보통의 최소제곱은 목표가 하나다. 실측과 예측의 차이를 제곱해서 더한 값을 가장 작게 만드는 계수를 찾는다. Ridge는 거기에 항을 하나 더 붙인다. 

최소제곱    Σ(y − ŷ)²                    ← 이것만 최소로
Ridge       Σ(y − ŷ)²  +  α·Σb²          ← 둘의 합을 최소로
                          └─ 계수가 커지면 붙는 벌점

더해진 항이 하는 일은 단순하다. 계수를 크게 쓰면 손해를 보게 만든다. 그래서 모델은 “정말 필요한 만큼만” 계수를 키운다. alpha가 그 손해의 크기다.

alpha → 0
벌점이 사라져 보통의 최소제곱과 같아진다. 계수가 자유롭게 커진다.
alpha → ∞
벌점이 압도해 모든 계수가 0에 눌린다. 결국 전체 평균만 내놓는 모델이 된다.

실제로 어떻게 움직이는지는 데모 자료로 직접 그려 볼 수 있다. 아래는 가상 12셀 자료에 alpha만 바꿔 가며 Ridge를 맞춘 결과다.

표준화가 선택이 아니라 필수인 이유

벌점이 계수의 크기에 걸리기 때문이다. 위상은 수십 단위, 임피던스는 0.0x 단위인데 그대로 두면 같은 물리적 기여를 내기 위해 임피던스 쪽 계수가 훨씬 커져야 하고, 그러면 벌점도 훨씬 많이 문다. 단위를 고른 것뿐인데 모델이 특정 열을 싫어하게 되는 셈이다. 그래서 모든 열을 평균 0, 표준편차 1로 맞춘 뒤에 벌점을 건다.

절편 b₀에는 벌점이 걸리지 않는다. 절편까지 0으로 끌면 예측값 전체가 0 쪽으로 밀려 버리기 때문이다.

Logistic — 불량일 확률을 낸다

라벨은 0 아니면 1이다. 여기에 직선을 그으면 예측값이 -0.3이나 1.4처럼 확률일 수 없는 값으로 나간다. 그래서 직선의 결과를 한 번 더 통과시켜 0과 1 사이로 눌러 준다. 그 눌러 주는 함수가 로지스틱 함수다. 

z = b₀ + b₁x₁ + b₂x₂ + ⋯          ← 여기까지는 Ridge와 같은 1차식
p = 1 / (1 + e−z)              ← 0~1 사이로 누른다
판정 = p ≥ 0.5 이면 1(불량), 아니면 0
C는 alpha가 아니다. 뒤집혀 있다

Ridge에서는 alpha가 클수록 벌점이 세다. Logistic에서는 C가 작을수록 벌점이 세다. C는 벌점의 세기가 아니라 그 역수이기 때문이다. 

Ridge       Σ(y − ŷ)²       +  α·Σb²
Logistic    −Σlog(맞힌 확률)  +  (1/C)·Σb²
                                 └─ 여기가 뒤집힌 지점

C = 0.001이 가장 강한 규제이고 C = 10이 가장 약한 규제다. 표에서 두 값을 나란히 읽을 때 방향을 반대로 잡기 쉬우니 주의한다.

class_weight = “balanced”

불량 셀이 정상 셀보다 훨씬 적으면, 모델은 전부 “정상”이라고 답하는 것만으로도 높은 정확도를 받는다. 그걸 막으려고 코드는 수가 적은 쪽 셀의 오답에 더 큰 벌점을 준다. 가중치는 전체 셀 수 / (2 × 그 부류의 셀 수)로 자동 계산되므로, 두 부류가 반반이면 가중치는 양쪽 다 1이 되어 아무 효과가 없다.

둘을 감싸는 3단 파이프라인

Ridge든 Logistic이든 혼자 돌지 않는다. 항상 아래 세 단계가 한 덩어리로 묶여 움직인다. 

1. select    36개 중 이번 후보가 쓸 열만 골라낸다
2. scale     고른 열을 평균 0, 표준편차 1로 맞춘다
3. model     Ridge 또는 LogisticRegression을 맞춘다
2단계가 왜 덩어리 안에 있어야 하나

표준화를 하려면 평균과 표준편차가 필요하고, 그 값은 학습에 쓰는 셀만 보고 계산해야 한다. 전체 자료로 한 번 표준화해 놓고 시작하면, 가려 둔 셀의 값이 이미 평균 속에 섞여 들어간 것이라 채점이 오염된다. 티가 안 나지만 점수를 올려 주는 전형적인 누출이다.

세 단계를 한 덩어리로 묶어 두면 검증 분할이 바뀔 때마다 표준화도 자동으로 다시 계산된다. 각 분할에서 실제로 쓰인 평균은 folds.json의 scaler_mean에 남아 있어서 나중에 확인할 수 있다.

데모에서 실제로 무엇이 뽑혔나

가상 12셀 데모를 돌리면 바깥 분할 12번마다 후보 선택이 새로 일어난다. 그 결과가 folds.json에 그대로 남는데, 읽어 보면 이렇다.

이래서 계수 시트가 비어 있다

회귀 쪽은 12번 중 10번이 EIS를 하나도 안 쓰고 개방전압 하나로 이겼다. 후보 59개를 놓고 경쟁시켰더니 가장 단순한 것이 이긴 것이다. 그래서 최종 모델에 EIS 계수가 없고, 03_reg_coefs 시트가 빈다. 버그가 아니라 결과다.

실제 자료에서도 이런 일이 일어나면 그건 나쁜 소식이 아니라 중요한 정보다. EIS를 재는 수고가 값을 못 한다는 뜻이므로, 모델을 키우기 전에 측정 조건부터 봐야 한다.

분류 쪽은 경고가 떠 있다

분류는 12번 모두 C = 10을 골랐다. 그런데 10은 후보 다섯 개 [0.001, 0.01, 0.1, 1, 10]의 끝값이다. 끝값이 계속 뽑힌다는 것은 더 바깥에 더 좋은 값이 있는데 후보에 없어서 못 고르고 있다는 신호다.

코드가 이걸 스스로 잡아내서 metrics.json에 남긴다. 실제 데모 출력에 이렇게 찍혀 있다. 

logistic boundary: 12 of 12 folds selected C at an edge of logistic_cs

이 경고를 보면 config.json의 logistic_cs에 100, 1000을 더 넣고 다시 돌려야 한다. 실측 자료에서 이 줄이 보이면 그냥 넘기지 않는다.
