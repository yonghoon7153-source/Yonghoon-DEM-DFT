## 수령과 검산의 구분

원 독립 ZIP은 1,567,229바이트, SHA256 `30eac8f7872502910a5db443b75c8f307104efb09dfd65278b915e917daa18a8`다. 외부 증거 190파일의 CRC·경로·중복을 확인하고, 루트 SHA256SUMS 189항·package 104항·중첩 original_input.zip 104항의 범위와 해시를 모두 검산했다. 내장 원 ZIP은 기존 요청 ZIP과 원바이트가 같으며, 펼친 package의 105파일도 모두 같다. 고정 스냅샷 17개(원 후보14·기준3)의 크기·SHA256·Git blob과 추가 patch/원증거83항을 대조했다. 붙여넣은 판정문도 ZIP 보고서 원바이트와 같다.

이것은 **수령 바이트 감사 PASS**다. 첨부 probe·검사기·시험을 수령 과정에서 실행하거나 독립 판정을 재발행하지 않았다. 리뷰어가 보고한 기존15+15 단위 시험과 추가106 음성 관측은 그 보고서의 증거로 수령하며 서로 합산하지 않는다. 이번 수정의 실제 회귀 시험 수·source hash·현재 결과는 새 `verification_summary.json`과 전달 패키지의 고정 증거를 따른다. 외부 검토 원 ZIP에는 리포 밖 위치·주소 문구가 있어 원본 전체는 외부 전달 증거로 보존하고 리포에는 `intake_receipt.json`의 신원·한정 요약만 둔다.

위 표는 후보 구현이 만족해야 할 계약이다. 통과 여부와 구체 코드는 최종 고정 후보의 diff·새 회귀 영수증·별도 재확인으로 판단한다. 사용자가 제공하기 전에 float에서 이미 사라진 정보를 복원했다는 주장은 하지 않는다. 안정적인 산술 또는 명시적인 지원 범위 거부는 새로운 물리 허용폭을 선택하는 일이 아니다.

G2PREP-01 후보는 raw 반력을 한 번 얼린 뒤 **같은 고정 raw × 명시적 극성**으로 정규화 힘을 만든다. raw·극성·정규화 힘의 진단 기록은 먼저 남기고, 정규화 힘이 음수면 control/gate/restart 전에 정지한다. 잘못된 부호의 진단 기록 자체를 금지하는 계약은 아니다. 설정 극성은 정확한 정수 ±1이며 실제 T0 극성은 null, 실제 엔진 T0는 NOT_RUN이다. 생성 문자열·합성 유한 입력의 정적 대조를 실제 엔진의 부호 자격으로 승격하지 않는다.

G2PREP-02의 보완 후 수렴 상태는 지정한 합성 모델·관찰 예산·종료 창/큐에 한정된 관측이다. 무한 시간 안정성·모든 지연의 안정성·실제 침대 제어 자격을 인증하지 않는다. G2PREP-03은 기하 원판 면적이며 force-law/electrical area가 아니다. 여기서 정확 입력 산술은 받은 int/float 표현과 유리수 중간 계산에 대한 한정이고, π와 최종 면적은 binary64 표현이다. G2PREP-04의 수평면 합성 검사는 실제 STL/PBC/연속 이동 궤적 자격이 아니다. 네 지적은 실제 연구 런 실패나 HOLD 우회가 관측됐다는 판정이 아니다.

## 유지하는 한정과 다음 단계
