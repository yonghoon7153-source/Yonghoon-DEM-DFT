## New P3 — empty zero-column ATX headings do not end §3

Location: **`source/scripts/supp20_input_receipt.py:108`**, with consequence at `:160–168` and `:182–194`.

`_MD_HEADING = re.compile(r'^(#{1,6})[ \t]+(\S.*?)[ \t]*$')` requires both whitespace after the marker and nonempty non-whitespace title content. However, a line containing `#` or `##` is a valid empty zero-column ATX heading. `# `, `##\t`, etc. are also headings. They must terminate a level-2 section. This is expressly inside the declared “ATX headings (`#` at column 0)” contract, not one of the excluded indented headings, lists, quotes, HTML blocks, or indented code blocks.

Minimal added suffix after replacing the original active `## 3.` with `## 30.` and removing the pending declaration from an isolated copy of the real registration:

```markdown
## 3. Active section without a value

##

`code_fp 2149f8738bb20b6a311b3c5b344b9745271a3f1324cabfb4582c175c3983c3eb`
```

Independent markdown-it tokens have an empty h2 after the active h2. Thus §3 contains no `code_fp`. Current `_md_section` ignores the empty h2 and includes the final token in §3. The complete production **`receipt()` returns rc0, `bad=[]`, accepting the current fingerprint**. See `evidence/s01_new_cases/h2_empty.md` and full `evidence/s01_receipt_h2_empty.json`.

Reproduced for h1 and h2 with six suffixes: end of line, space, tab, space+tab, space+NBSP, space+U+2003. All **12/12 return rc0** while the independent oracle says the token is outside §3. The Unicode forms have heading content rather than an empty title, but share the same overly restrictive `\S` condition. The old pinned parser reads the same wrong fingerprint in all 12, so this is a **newly discovered pre-existing defect**, not a newly introduced regression.

The reverse protection also fails: place the valid current `code_fp` inside §3, then a plain empty h1 or h2, then a different historical token (`0` × 64) outside §3. The oracle preserves the valid registration; production instead reads both values, returns `code_fp=None`, and fails R0/D1. Both variants are saved as `h1_live_before_blank_history` and `h2_live_before_blank_history`. A repair must preserve these valid registrations, not merely reject every document containing an empty heading.

Controls: ordinary named h1/h2 boundaries correctly cause R0/D1 failure, fenced-only value correctly causes R0/D1 failure, ordinary active value succeeds, and ordinary active value plus a conflicting fenced value succeeds while reading the outside value. No current production document is claimed affected, and receipt rc0 still is not launch authorization.

Minimum resolution: recognize all supported zero-column ATX headings as boundaries, including empty title and Unicode title content; keep matching active §3 separately from boundary recognition. Alternatively, explicitly reject these forms before accepting the document. Add the empty h1/h2 fail-open examples and named-heading/fenced-value controls. No need to expand to the explicitly excluded Markdown constructs.

Primary specification: [CommonMark 0.31.2 §4.2](https://spec.commonmark.org/0.31.2/#atx-headings), especially [example 79](https://spec.commonmark.org/0.31.2/#example-79), explicitly permits empty ATX headings; opening markers may be followed by end of line. Fence comparisons follow [§2.2](https://spec.commonmark.org/0.31.2/#tabs) and [§4.5](https://spec.commonmark.org/0.31.2/#fenced-code-blocks), independently checked online as well as with markdown-it-py.
