# MSC 제1저자 인계 프롬프트·인계본 검토

검토 2026-09-29–30. **판정: 원 프롬프트는 수정 뒤 발송. 이번 수정 프롬프트 + 원 인계본 + 정정 메모 조합으로 인계하는 것을 권고한다.** 과거 계산을 다시 할 이유는 없고, 새 PC의 기본 사용 가능성만 이후 좁게 확인하면 된다.

사용자 추가 의도도 반영했다: **주 계산은 우리 쪽 기존 워크스테이션, 제1저자 PC는 읽기·결과 분석·작은 PyBaMM 재현이 가능한 기본 환경.** COMSOL 전체 운영 환경 복제는 지금의 선행 조건이 아니다.

**이번 받은 코드 import/시험/컴파일/PyBaMM/COMSOL 실행 0. 설치·원격 발송·push·운영 원장 수정 0.** 문서 읽기·우리 쪽 텍스트/해시 검사·새 안내문 작성만 했다.

## 3. 발송 전에 고칠 핵심

### H1 — 첫 작업의 실행 경계를 하나로 만든다

위치: A §2 발견 처리/완료 주장, §5 설치·실행, §9 첫 작업.

“PyBaMM은 COMSOL이 아니므로 실행 승인 대상이 아니다”와 “따로 설치한다”가 첫 읽기 단계에 섞였다. 또한 버그는 무조건 RED를 보고 수정하라는 규칙은 읽기 전용 인수 단계에서 시험·수정을 유도한다.

대체: 첫 작업은 자료/환경 메타데이터 확인과 설치안. 다음 명시 승인에서는 새 가상환경·의존성 설치·네 회귀만. 연구 확장/COMSOL은 별건. 버그는 첫 단계에서는 소스 근거와 영향만 보고하고, 수정 승인 후 적절한 한정 회귀를 쓴다. 이미 올바른 동작의 설명 정정까지 무조건 실패 시험을 만들 필요는 없다.

“방금 실행한 출력으로만 통과를 말하라/아마 금지”도 바꾼다. **이번 직접 관측 / 제공 기록상 PASS / 추론 / 미확인**을 구분하면 된다. 이력이 유효하다고 인용하기 위해 재실행하지 않는다. 불확실성을 명시하는 것은 금지 대상이 아니다.

### H2 — `9d4746ce3 이상` 대신 발송 커밋을 정확히 고정한다

위치: A §3. B는 마지막 `a32218a7e`에 추가됐으므로 더 이른 커밋도 허용하는 “이상”은 충분하지 않다. 기준을 전체 `a32218a7e3cefc9c6d4b1eaa174612ea1ad55d29`로 쓰고 A/B 식별을 붙인다.

최신 원장을 읽는 것은 유용하지만, 자동 pull/checkout·운영 승인 승계는 아니다. 문서/브랜치 이름은 실행 권한을 만들지 않는다. §30 상태는 **해당 커밋 시점**의 상태로 표시하며 상대 워크스테이션의 현재 상태로 단정하지 않는다.

### H3 — 새 PC는 복사 환경이 아니라 독립 기본 환경이다

위치: A §5·§9. requirements에는 NumPy/pandas/SciPy/openpyxl/pytest 하한만 있고 PyBaMM이 없다. 시험 소스 line 10은 `pytest.importorskip("pybamm")`다. 네 시험 중 일부는 실제 작은 solve를 한다(`simulate` 등).

따라서 “requirements 설치 후 rc0”만으로 사용 가능을 판정하지 않는다. PyBaMM 버전을 명시하고 **실제 네 ID 실행, 4 PASS / 0 FAIL / 0 SKIP**, 환경 버전 기록을 확인한다. 원 `result.json`은 덮지 않는다. Python 3.11.15는 과거 환경의 관측이며 새 Windows 바이너리 공급을 보증하지 않는다. 이번 조회로 PyBaMM 26.8.0.0 공식 배포 존재는 확인했으나 새 PC의 설치/실행은 미시험이다.

### H4 — ZIP 원본 보존과 외부 공개를 분리한다

위치: A §10 “원 파일을 바이트 그대로”.

보존은 맞지만 공유 대상 선별이 먼저다. 원본은 로컬에 보존하고, 허용된 공개 문서/코드/보고서만 공유 묶음에 넣는다. private_data, `.codex`, 토큰/라이선스, 전체 prefs, 연구 원자료, venv, 광범위한 전체 로그/환경변수는 자동 포함하지 않는다. 마스킹한 자료는 원본과 별도로 식별한다.

A/B 본문에서 계정 토큰이나 비밀번호를 발견한 것은 아니다. 그러나 키워드 grep 무검출은 개인정보·연구 공개 적합성의 완전 증명이 아니다. 공개된 정본에는 세미나 출처/발표자/정성 발언도 있으므로 연구 내용의 공유 승인은 소유자가 판단한다. 이번 인계본이 미공개 데이터의 AI 입력까지 허용하지 않는다.

## 4. 연구 문장의 보완 — 추가 계산 없이 고칠 수 있다

동봉 `SCIENCE_QUALIFICATIONS_KO.md`의 내용을 함께 전달한다.

1. **P2:** B:73·442 / A §6. 고정 Rs여도 `V/Rs`이므로 전류는 엄밀히 SOC 불변이 아니다. 전압 의존 몫과 OCV 기울기를 구분하고, 작은 dU/dQ의 불안정성을 숨기지 않는다.
2. **P10:** B:81 / A §6. 저항 on/off가 모든 원 신호의 부호를 반전해야 한다는 규칙은 부적절하다. 같은 B의 P8 D_down/MSC 결합 표가 부호는 그대로이고 크기는 달라지는 사례다. 사전 정의한 대비량으로 바꾼다.
3. **P5/P8/두 장부:** “누설만 남는다/≈1이면 MSC”를 일반 정리로 쓰지 않는다. B의 두 장부 표에는 SOC 0.2의 혼합도 1.04라는 자체 한계가 있다. 이는 새 반증 실험이 아니라 기존 결과가 이미 말해 주는 범위다.
4. **M3/M8:** 원본 검토 M3:326–343은 표 덮어쓰기 가능성·원곡선 대조 미완을, M8:436–437은 solution 이름만으로 모든 해의 설정을 확정하지 말 것을 명시한다. A §7에 이 단서를 덧붙인다.

원장과 같은 문장을 복사했다는 사실은 그 문장의 과학적 일반화를 보장하지 않는다. 원 데이터/수치를 바꾸지 않고 범위와 해석만 한정하면 된다.

## 5. R6 상세 — 되살릴 것과 그대로 덜어도 되는 것

유지해도 되는 편집: 다른 연구(ASSB/게이트) 대응표 제거, 과거 전달 보류 이력 제거, 취소선의 폐기된 가설 제거, 내부 태그 정리, §7 표의 이동. M3/M8·실셀 검증 0·SPMe 한계·SEI/히스테리시스·COMSOL 미승인 경계는 남아 있다. §6 실셀 제안은 인계 목적상 유용하므로 편지체라는 이유만으로 없앨 필요가 없다. 재현 표의 네 커밋 해시도 B:533에 그대로 있다.

복원할 한정: C:571은 “새 계산은 하지 않았고 옛 산출을 다시 읽어 맞는지만 봤다”라고 명시한다. B:537은 이를 “합성 모델의 판정”으로 바꾸며 재검증 행위 범위가 약해졌다. B §7-3 앞에 **“회귀 4건 재실행과 기존 JSON 표 값 대조이며, 부호표 전체/P6 적합 재계산은 아님”**을 추가하면 된다.

“남긴 글은 모두 원문 바이트 그대로/쓸모없는 글만 삭제”는 엄밀한 설명이 아니다. §8-2에도 재서술·참조 수정이 열거돼 있다. **“주요 수치와 한계를 보존하며 인계용으로 발췌·재배열하고 일부 안내/참조 문장을 고친 문서”**라고 쓰는 것이 정확하다. 숫자 토큰 비교는 보조 검사이지 의미 보존 증명은 아니다.

## 6. 질문 Q1–Q7 / 사람 확인 사항

- Q1: 워크스테이션/발신 PC/BML PC는 문서상 연결돼 보이지만 동일 기계 실측은 아니다. 이름 대신 사용자가 확인한 장치/소유자를 한 번 적는다.
- Q2: 제1저자는 자신의 새 PC 작업을 승인한다. 제공자 PC 실행은 그 PC의 소유자/운영 승인도 필요하다. 기존 §30 작업을 가져오는 것으로 해석하지 않는다.
- Q3: 기준 source 읽기·출력 분리 기본값은 적절하다. 쓰기 개발이 필요하면 별도 작업 사본/브랜치와 승인 범위를 정한다. Gitignore는 보안 경계가 아니다.
- Q4: 지금은 P6의 의존 모듈과 문서까지 읽을 수 있으면 충분하다. α·β 하네스 전체 재검증이나 제1저자 원자료 이관을 첫 작업에 넣지 않는다.
- Q5: 공유 파일 allowlist를 넣는다. 보존 원본과 외부용 사본의 경계를 분리한다.
- Q6: 프롬프트에 짧은 상태 스냅샷+고정 커밋+원장 포인터를 두는 편이 좋다. 모든 과거 실패를 긴 첫 메시지에 반복할 필요는 없다.
- Q7: 위 §5대로 재현 범위 한정을 복원하고, 기존 재현 해시는 유지한다. 과거 전달 보류/다른 연구 대응표를 되살릴 필요는 없다.

U1 제1저자/팀 신원, U2 실제 기계 매핑, U3 상대 PC 최신 상태, U4 경로/권한은 이번 문서만으로 확정하지 않았다. 사용자가 이미 분명히 한 것은 **대부분 계산은 기존 환경에서 하고 새 PC도 기본 사용 가능하게 준비한다**는 역할 분담이다.

## 7. 공식 설정 문서가 이번 권고에 미친 영향

OpenAI 문서를 확인해 Windows-native와 WSL을 혼동하지 않고, 에이전트/통합 터미널의 독립 환경 확인과 한정 권한을 설치안에 넣었다. Python 문서에 따라 다른 PC venv 복사가 아니라 현지 재생성을 권고했다. 이것은 지금 앱 설정을 변경했다는 뜻이 아니다.

- [OpenAI Windows 안내](https://learn.chatgpt.com/docs/windows/windows-app): native PowerShell/선택 WSL, 에이전트와 터미널 환경 구분.
- [OpenAI 권한](https://learn.chatgpt.com/docs/permissions): 작업에 필요한 파일/네트워크 범위 설정.
- [Python venv](https://docs.python.org/3/library/venv.html): 가상환경 생성 및 직접 인터프리터 사용.
- [PyBaMM 26.8.0.0 공식 배포](https://pypi.org/project/pybamm/26.8.0.0/): 버전 존재·Python 요구조건·플랫폼/가상환경 안내.
