## 4. 검토해 주실 것

1. 감시 보완이 v2 §4-4 의 필수 합성 사례를 덮는지 봐 주세요 (시험 01–04).
2. **E3a 호출 기록이 v2 §1 · §4-1 을 채우는지.** 필드는 다음과 같습니다.
   - 평가 수 (예외로 끝난 평가 포함) 와 비유한 (optimizer 가 받은 목적 · 넷 전체).
   - 영역 밖 평가 수 (PE / NE / 어느 쪽이든 · 빈 슬라이스는 미확인 따로). 정의는 그들 슬라이스 `[argmin|q| : argmax q]` 밖 실험 Q 점이
     ≥ 1 인 평가이고, C5 `n_out_labels` 와 같은 식입니다. 그들 `dVdQ_hc` 를 감싸 얻으므로 추가 계산은 없습니다.
   - X · F · G 원형과 `G_status` (없음 · 보고됨 · 미반환).
   - G 재계산 (그들 float 식 · 정확 유리수 · 상자 잔차).
   - `success_reported` 와 `success_is_evidence=false`.
   - P0 추출 기록, Model / halfcell digest (전후 다르면 구조 오류), 경고 개수.
3. **오류 위치 규칙.** C5 `classify_exception` 은 자기 파일만 "우리" 로 압니다. 그래서 계수용 감싸기 안의 오류가 바깥 util frame 때문에
   "지역" 이 될 수 있었습니다. E3a 는 안쪽부터 처음 만나는 util frame 을 util, e3a · monitor · c5 frame 을 우리 (구조 오류) 로 봅니다.
   라이브러리 frame 은 건너뜁니다. 이 규칙을 받아들일 수 있는지 봐 주세요.
4. **범위 변경 — 수용 여부를 묻습니다.**
   - §39 3 은 C4-0a 에서 "A1 / A2 Phase A · profile Sobol 2 · 동시 Sobol 16 · label-seed 배열" 을 봉인한다고 했습니다.
   - 실제로는 Phase A 넷만 봉인했습니다. profile Sobol 2 · 동시 Sobol 16 · label-seed 는 C4-0b 로 옮겼습니다.
   - 이유: 셋 다 펼칠 상자가 P0 사전표 · max_q 와 H 격자에서 나오므로 (부속 A §3-3 · §3-4 · §3-6) H 실행기와 같은 코드 경로에서 만듭니다.
   - v2 §4-3 의 시점 "C4 첫 국소 실행 전" 은 지켜집니다.
   - 실행 중 사용자 확인 없이 제가 내린 결정입니다.
5. **노트북과 다른 점 둘 (값 무관 주장).**
   - (a) 노트북은 case 여섯이 Model 객체 하나를 공유합니다 (발췌 cell 8). 실행기는 호출마다 깊은 사본을 넘깁니다. 그들 objective 가
     읽는 키와 쓰는 키가 다르기 때문입니다 (util 157–236).
   - (b) 실행 순서는 case 순입니다 (노트북은 셀 순). 호출마다 그들 seed 로 다시 시작하므로 값과 무관하고, 작업자 부하 때문에 택했습니다.
6. **GREEN 전에 자체 정적 검토로 고친 것 셋** (실행 0 · 시험 파일 불변):
   - 감시 끝 조건 — 마감 작업자의 이중 계수를 합집합으로 고쳤습니다.
   - 건조의 P0 행 대조 — `sorted(key=str)` 를 집합 대조로 고쳤습니다.
   - 반환 F 가 None 일 때 — nan 으로 바뀌어 비유한 1 로 세는 것을 막았습니다.
7. **남은 한계.**
   - 합성 NSGA2 1 회가 끝까지 돌았는지 그들 util 오류로 끝났는지는 기록에 없습니다. 시험은 둘 다 허용하고, pytest 가 통과 시험의 출력을
