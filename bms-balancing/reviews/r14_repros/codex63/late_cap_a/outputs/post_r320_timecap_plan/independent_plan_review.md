# 다음 5초 후보의 독립 검토

계획 검토만 수행했다. 새 COMSOL 실행·작업 제출·Java 생성·기존 증거 변경은 하지 않았다. 아래 후보는 실행 승인을 대신하지 않는다.

## 고정 기준

두 후보의 기준은 동일한 완료 결과다. 이름·소스 경로·SHA·job을 함께 고정하고, 이전 H0250 또는 R160 조상 정보를 기준으로 혼용하지 않는다.

| 항목 | 기준 |
|---|---|
| 이름 | `Caps300R320H0125` |
| 소스 | `outputs/comsol63/radial320_timecap/Caps300R320H0125.java` |
| SHA-256 | `8d35be8fab513f5e2def316c4d00e0fdc19983a5dd3bf492f4ffe47a58248be3` |
| Job | `18a00b03e38d4694b9ba30d88e7008f4` |
| 물리 / 입자 요소 | 전체 300 = N120 / separator60 / P120; 입자 N320 / P320 |
| 기존 시간 상한 | `if(t<0.1[s],0.000125[s],0.1[s])` |

기준의 요청 시각은 187개, 공간 표본은 전극마다 241개다. 실제 저장 시각은 987개이고 accepted interval은 986개다. 이 수와 후속 후보의 저장 시각 수가 같을 필요는 없다.

## 후보 A: 0.1초 이후 시간 상한만 강화

제안식은 `if(t<0.1[s],0.000125[s],if(t<1[s],0.005[s],0.025[s]))`다. `maxstepconstraintbdf=expr`를 유지하며, 비활성 상수 슬롯 `maxstepbdf`를 바꾸는 것으로 대체하지 않는다. 물리·입자 메시와 나머지 입력은 기준 그대로다.

기존 [accepted interval CSV](../radial320_timecap/Caps300R320H0125_accepted_steps.csv)를 Decimal로 독립 집계했다. 구간에 완전히 포함된 interval을 세었고, 상한 비교에는 기존과 같은 1e-12초 부동소수점 허용량을 적용했다.

| 구간 | 기존 interval 수 | 기존 최대 h | 제안 상한 | 1e-12초 허용량을 넘어 상한을 초과하는 기존 interval |
|---|---:|---:|---:|---:|
| 0.1–1초 | 98 | 0.01초 | 0.005초 | 87 |
| 1–5초 | 81 | 0.05초 | 0.025초 | 80 |

0.1–1초에서는 0.01초 간격 87개가 해당한다. 1–5초에서는 0.03초 간격 1개와 0.05초 간격 79개가 해당한다. 따라서 이 후보는 현재 관측된 시간 간격보다 실제로 작은 상한을 제시한다. 기존 설정의 0.1초를 0.05초로만 낮추는 후보는 기존 최대 간격 0.05초를 그대로 허용하므로 같은 근거가 없다.

별도 [원시 시각 분포 감사](accepted_interval_distribution.json)도 987개 원시 시각의 986개 차분이 기존 accepted CSV와 정확히 일치함을 확인했고, 위 98/81개 및 허용량 적용 초과 수 87/80개와 일치했다. 0.00500000000000001초 한 개는 0.005초 대비 1e-17초 차이여서 위 초과 수에 포함하지 않았다.

추후 실행이 별도로 승인되면 구간별 실제 최대 h가 각각 0.005초·0.025초 이하인지 확인하고, interval 분포·개수·상한에 걸린 수를 기존 분포와 함께 보고해야 한다. 서로 다른 adaptive 분할 사이에서 모든 interval을 일대일로 짝지어 절반이 됐다고 주장하지 않는다. 위 조건은 구간별 관측 최대 간격 감소를 확인하는 조건이다.

`strict` 요청 시각에 있는 0.1초와 1초를 정확히 저장해야 한다. 0.1초 도착 interval은 0.000125초, 1초 도착 interval은 0.005초 이하인지 별도로 확인한다. 각 경계에서 출발하는 interval은 다음 상한을 적용해 따로 보고한다. 경계를 건너뛴 interval은 미해결 항목으로 남긴다. 이 검사는 accepted interval 근거이며 COMSOL 내부의 cap 평가 시점이나 거절된 trial step을 추정하지 않는다.

A는 두 후반 구간을 함께 강화하는 단일 후보다. 1–5초의 해 차이에는 0.1–1초에 만들어진 상태 차이가 이어질 수 있으므로, 이를 1–5초 상한 변경만의 인과 효과로 해석할 수 없다. 기존 초기 cap 반감의 작은 차이도 0.1초 이후 시간 정확도를 증명하지 않는다.

## 후보 B: 물리 메시만 600으로 세분

전체 물리 요소만 300에서 600 = N240 / separator120 / P240으로 바꾸고 입자는 N320 / P320을 유지한다. 비교 기준은 위 H0125 완료 결과이며, 시간식은 원래 `if(t<0.1[s],0.000125[s],0.1[s])` 그대로다. A의 새 시간식을 B에 자동으로 적용하지 않는다.

같은 전극별 241좌표를 유지하면 기존 300 메시에서는 전극별 120요소의 꼭짓점·중간점, 600 메시에서는 전극별 240요소의 꼭짓점에 대응한다. N/P domain 선택과 물리 좌표를 각각 확인하고, 계면 양쪽 값을 합치지 않는다. 공간값은 COMSOL의 domain별 FE 평가이고 시간 보간은 하지 않는다.

물리 메시 입력만 바뀌어도 adaptive 시간 이력은 달라질 수 있다. 따라서 B는 동일 시간 설정 아래의 표본 메시 민감도이며 엄밀하게 분리된 공간 이산화 오차의 상한은 아니다. 실제 메시 개수·입자 설정·시간 속성·accepted interval 분포를 함께 검토해야 한다.

## 비교·순서·한계

A 검토를 먼저 진행하고, 그 결과를 확인한 뒤 B를 별도로 승인하는 순서가 타당하다. A의 후반 시간 민감도가 크거나 판정 기준을 넘으면 자동으로 B 또는 시간·메시 동시 변경을 실행하지 말고 계획을 다시 검토한다. B를 수행하더라도 고정 기준은 위 H0125이며 A 결과로 바꾸지 않는다.

- 각 후보에서 187개 요청 시각의 직접 비교와 전체 정확히 공통인 저장 시각의 교집합 비교를 구분한다. 누락 요청 시각을 다른 공통 시각·최근접 값·보간으로 채우지 않는다.
- 요청 표본 수는 0.1–1초 91개, 1–5초 81개, 0–1초 107개, 0–5초 187개다. 1초는 인접 두 구간에 의도적으로 포함되므로 표본 수를 더해 전체 수로 해석하지 않는다.
- 각 구간의 최대 전압 차이와 최대 고체 표면 분율 차이는 각각 1 mV·1e-4와 비교한다. 각 최대 시각·전극·좌표를 다시 찾고, 그 같은 시각의 전압 분해를 함께 기록한다. 다른 시각의 성분 최대값을 합하지 않는다.
- 표본 기준 통과는 참값 오차·연속 시간/공간 최대·전체 수렴·수렴 차수를 입증하지 않는다. 추가 시간이나 메시 민감도를 확인할 필요가 없어졌다는 의미도 아니다.
- 물성표·Li 재고·초기화·0.1C·sigma 1e-20 S/m·허용오차·scale·OCP 외삽 금지·고체 표면/OCP StopCondition을 유지한다. 전해질 양수는 후처리 검사이며 실시간 중단으로 바꾸어 설명하지 않는다. 기존 `failed / INCOMPLETE_RANGE_STOP` 기록을 보존한다.

이번 수신 확인의 967 범위는 현재 ZIP에 직접 대응하는 56개 항목 중 55개 불변과 NEXT의 변경 전 백업 검증이다. 현지 967개 전체가 외부에서 직접 검증되었다고 확대하지 않는다. 원본 ZIP·영수증은 당시 바이트 그대로 보존하고 이번 확인을 별도 기록한다.
