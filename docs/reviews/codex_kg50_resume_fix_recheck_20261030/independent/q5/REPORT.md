## 판정

- **Q3는 좁은 범위에서 수용 가능하다.** §12-4 W1 네 줄/W2 네 줄은 현재 생산 Python 검사에서 확인되고, W2 준비 구간의 다섯 상태 변이를 생성기 허용 목록이 모두 거부한다. 생성 덱이 등록 변환에 맞는다는 검사로 수용한다. 체크포인트 상태의 독립 복원·물리 의미·실제 실행 인증으로 확대하지 않는다.
- **이번 Q3 수용은 W2 실험이나 Q5 전체 GO가 아니다.** §12-2는 비준 전이며 W2-6의 두 침대 문제도 남았다. 현재 판독기는 생성된 W2 네 가지를 비준 전으로 거부한다.
- **실제 사슬 `-T`와 본 제출을 구별해야 한다.** 합성 216개, 이번 원문 Python 실행, 구판 D2 보고는 최신 wrapper/helper/binary를 사용한 D0.7 `-T`를 대체하지 못한다. 다른 검토가 도구 변경을 수용하더라도 먼저 **실제 `-T` 증거를 확보하는 단계만** 열고, 본 제출은 그 증거와 신원을 검토한 뒤 별도로 판단하는 표현을 권고한다.
- **KG50R-06의 원본 미수령 문제는 실질적으로 해소됐다.** 09:42 보고와 덱 묶음이 존재하고 tgz 10개 멤버가 반입 파일과 모두 일치한다. 다만 README에 수령/미수령 문구가 함께 남은 P3 문서 잔여가 있다.
- **별도 부수 발견 P2 후보 Q5-PROV-01:** 판독기의 로그 echo 검사는 명령 부분열만 대조한다. 추가 상태 명령이 있는 로그도 정상 판정을 낼 수 있다. 이는 이번 W2 생성 허용 목록의 실패가 아니며, Q5 실행 출처 인증의 한계로 별도 취급한다.

권고 문구는 “D0.7 `-T` 증거 수집 단계 승인”과 “본 제출 GO”를 분리한다. 전자는 다른 재개 검토에서 확인된 결함이 해소되었다는 조건 아래 최신 wrapper·실제 helper 신원, NP56, 실제 checkpoint, 시도 폴더, 덱/러너/바이너리 신원, 원/시험 로그 및 G0–G3 자료를 받는 단계다. 후자는 그 원자료를 검토한 뒤 정해야 한다. 보고가 자동으로 출력한 본 제출 명령과 `-A/-H` 값만으로 실제 사슬 검토가 수행된 것은 아니다.

기대 시험 길이는 체크포인트 종류에 묶어야 한다. settling 중 checkpoint이면 보통 첫 run 2000만, after_settling이면 준비 `run 1`+짧은 긴 run 2000으로 총 2001이다. 예를 들어 S0=200001인 after_settling의 기대 끝은 202002이지 202001이 아니다. 실제 선택 checkpoint와 생산 trial의 run 합으로 확인해야 한다.

G1 KE 일치 및 G2의 대체 경로는 별도 checkpoint reader를 생략한 한정과 함께 읽는다. Q6의 상태 reader를 넣지 않은 선택이 승인되어 있다는 사실은 원자별 위치·속도·회전·접촉 history 전체의 독립 동일성 증명을 만들어 주지 않는다. Q5 물리 해제도 별도다.

## 재현 파일

- `probe_q5.py`: 생산 모듈 호출, 추출 Python 정적 검사, 등록의 별도 본문 변환, 변이, D2 원자료, Q5 provenance 반례. 기존 증거를 덮지 않도록 첫 실행 뒤에는 출력 폴더가 있으면 중단한다. 새 증거 경로에 복제해 실행할 것.
- `finish_evidence.py`: 최신 생산 D2 trial 절단 및 Decimal 산술을 결과에 추가.
- `results.json`: 실제 반환값·rc/stdout/stderr·SHA와 수치.
- `pinned_embedded_cli.py`: 원문 wrapper에서 추출한 Python 바이트.
- `generated/`, `generated_w2_draft/`, `mutations/`, `syn/`: 생성·검증·판독에 실제 공급한 자료. `SYNTHETIC_main_w2.log` 및 `syn/` 로그·덤프는 모두 합성이다.

최종 재현 결과의 생성기·판독기·등록 문서 해시는 시작 때와 동일하다. 이번 보고를 실제 클러스터 실행 또는 원문 셸 시험 통과로 요약하지 말아야 한다.
