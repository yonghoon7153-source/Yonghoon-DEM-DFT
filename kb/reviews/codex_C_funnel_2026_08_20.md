# 교차리뷰 C — cascade 깔때기는 잘 작동했나

> **왜 이 카드가 따로 필요한가**: codex_A 는 **방법 축**(ML 위생 · UMA 정확도 · 부피 편향)을
> 봤고, codex_B 는 **NEB·MD·도구**를 봤다. **"깔때기 자체가 후보를 걸러냈는가"** 는
> 아직 정면으로 리뷰받은 적이 없다. 1저자 질문(2026-08-20): *"우리 cascade 깔때기가
> 잘 작동한 건지 알고 싶다."*
>
> ⚠ 이 카드는 **새 계산을 요구하지 않는다.** 판정에 필요한 자료는 전부 repo 에 있다.
> 묻는 것은 **해석과 보고 형식**이다.

## 0. 리뷰어에게 — 먼저 알아야 할 사실 5개

### 0-1. 깔때기 실측

```
47 → 47 → 43 → 25 → 11 → 1
     G1    G2    G3   G4   G5
```

| 게이트 | 이름 | standalone_kill | **unique_kill** | 판정 |
|---|---|---|---|---|
| G1 | structural_stability (Δe<0) | 0 | **0** | 💤 vacuous |
| G2 | electrochemical_window | 4 | **0** | 💤 완전 중복 |
| G3 | oxidation_onset | 22 | 1 (LaF₃) | 실질 |
| G4 | li_transport (BVSE) | 27 | 6 | 실질 |
| G5 | mechanical | 32 | 10 | 실질 — 그러나 §0-3 |
| **G6** | cathode_reactivity (2026-08-20 신규) | 5 | **0** | 💤 G2 와 동종 |

⇒ **여섯 중 셋이 `unique_kill = 0`**. 출처: `db/properties/cascade_screening_funnel.json`
(`gate_power`) · `db/properties/cathode_reactivity_verdict.json`.

### 0-2. 우리가 이미 자체 감사한 것 (리뷰어가 다시 할 필요 없음)

- **순서 민감도**: 120개 순열 **전수**. 게이트가 전부 정적 boolean 이라 **최종 생존자
  집합은 순서 불변**. 순서가 바꾸는 것은 중간 숫자와 "탈락의 공" 배분뿐 —
  *깔때기 그림의 모양은 서사 선택이지 결과가 아니다.*
- **문턱 민감도**: G3 를 −0.2 V 로 밀면 코어 15종, −0.1 V 면 13종. 그런데
  `n_full_with_G5` 는 **어느 쪽이든 1**이다 (G5 가 다른 축의 민감도를 전부 덮는다).
- **문헌 대응 종점 확정**: G1–G4 까지 **11종**. G5 는 우리가 추가한 축이라 문헌 대비에
  넣으면 사과와 오렌지다.

### 0-3. G5 는 제일 세면서 근거가 제일 약하다

`final_survivors_warning` (우리가 쓴 것):

> G5 의 median 컷은 **host 앵커가 없는 자의적 컷**이고, percentile 을 0.25→1.00 으로 훑으면
> 최종 생존자가 **0→11 로 전 구간을 움직인다**. '우리 깔때기의 최종 승자'로 인용하지 말 것.

⇒ 최종 1종(WO₃)은 **인용 불가**로 이미 표시돼 있다.

### 0-4. 부피 사건의 실제 범위 — **하위 축은 오염되지 않았다**

1저자가 이 리뷰를 요청한 직접 계기다: *"부피 측면부터 뭔가 잘못된 거 아니었나."*
2026-08-19 심야 판정(`kb/projects/cascade_pipeline_fixes_2026_08_19.md` §6):

```
fmax 0.05  → 27.478 Å³/atom  ( 58 스텝)  잔류압 +0.186 GPa   ← cascade 설정
fmax 0.01  → 20.442          (1124 스텝)         −0.007
fmax 0.002 → 20.415          ( 917 스텝)         −0.001      ← 진짜 최소점
```

UMA 실제 최소점 20.415 는 우리 DFT 19.55 대비 **+4.4 %** — MLIP–DFT 정상 범위다.
그리고 하위 축 실측:

```
eos_V0_per_atom  n=622  중앙 20.232  [16.79, 23.41]
   19–22 (물리적)      591행  95.0 %
   25 이상(미수렴 셀)    0행   0.0 %    ← 하나도 없다
```

Stage 04 의 500 K/50 ps MD 가 대칭을 깨고 재배열한 뒤 FIRE 이완이 제대로 수렴했다.
**미수렴 셀이 하위로 흘러간 행은 0 개.**

| | 판정 |
|---|---|
| `screen_dV_over_V0` | ⛔ 무의미 (미수렴 기준 대비 미수렴 값) |
| 부피 게이트 100행 탈락 | ⛔ **잘못 뺐다** (단 base_species 손실 0) |
| `screen_de` **절대값** | ⛔ 인용 금지 |
| `screen_de` **순위** | ⚠ r(\|ΔV\|, de) = **−0.373** — "얼마나 이완됐나" 가 섞임 |
| **Stage 03 Top-1 선발** | ⚠ **흔들린 잣대로 뽑았다** |
| EOS B₀·V₀ · elastic C_ij · BVSE(post-anneal) | ✅ 건전한 구조 위 |

⇒ 구조가 이렇다: **깔때기 계산은 멀쩡한데, 깔때기에 들어간 후보가 흔들린 기준으로
뽑혔다.** 이게 이 카드의 중심 질문(Q3)이다.

### 0-5. ✅ **닫힘 (2026-08-20) — 전제는 참이었고, 닫힌 방향이 나쁜 쪽이다**

`cascade_pipeline_fixes_2026_08_19.md` §5-3 이 스스로 "최우선" 이라 적어 놓고 안 했다:

```
preflight : relax_steps 500   (check_baseline_relax 하드코딩)   ← 27.478 은 여기 값
screen    : --steps 1500      (tier_cascade Stage 02)          ← dV 를 만드는 것은 여기
```

> **같다고 가정하고 전 계산을 했다. 확인 안 했다.** 다르면 §0 표의 절대 밀도가 전부 틀어진다.

**실측 (gabia, 2026-08-20)** — `dualx_v23/*/02_screen/baseline.json` 5종:

```
V/atom: 27.478273 / 27.478272 / 27.478272 / 27.478272 / 27.478272
steps : 58 (전부)          fmax_setting: null (전부)
```

⇒ **preflight 와 screen 이 같은 값이다.** `relax_steps 500` vs `--steps 1500` 차이는
**무의미했다** — 둘 다 **58 스텝**에서 멈췄으므로 한도가 아니라 **fmax 0.05 수렴 판정**이
종료 조건이었다. 따라서:

1. **§0-4 의 결론은 유지된다.** 하위 축 `eos_V0` 중앙 20.232 · 미수렴 셀 0행은 그대로다.
2. **`screen_dV_over_V0` 의 "미수렴 기준 대비 미수렴 값" 판정이 추정에서 확정으로 바뀐다** —
   baseline 이 27.478 로 못박혔다.
3. ⚠ **§0-4 의 "27.478 은 preflight 값" 서술은 부정확했다** — screen 도 같은 값이다.
   (이 카드에서 정정한다.)

### 0-6. ⭐ 그 조회에서 **새 결함이 나왔다** — 산출물이 자기 수렴 조건을 안 적는다

```
fmax_setting: null      ← 5개 전부
```

`02_screen/baseline.json` 은 **58 스텝에서 왜 멈췄는지를 기록하지 않는다.** fmax 0.05 로
수렴 판정이 났는지, 다른 이유인지 파일만 봐서는 알 수 없다 — 우리가 그것을 알아낸 것은
**코드를 읽어서**지 산출물을 읽어서가 아니다.

⇒ **F9 와 같은 패턴이다**(산출물이 자기 한계를 스스로 적지 않는다). 그리고 이 결함이
**부피 사건을 5개월 늦게 발견하게 만든 직접 원인**일 수 있다 — `dV` 를 쓰는 모든 하류가
"이 기준값이 수렴한 것인가" 를 물을 방법이 없었다.
⚠ `uma_relax_check.py` 는 `fmax_setting` 과 `max_atomic_force_eV_A` 를 **기록한다**(L136–139).
**Stage 02 만 안 한다.** → Q9.

## 1. 오늘 새로 들어온 것 — G6 와 Li 흡수

`db/properties/cathode_reactivity_verdict.json` (2026-08-20 실행, 94쌍 전수):

1. **게이트가 vacuous** — 탈락 5종(BaO·MnO·Na₂O·Sb₂O₅·TiF₄)이 **전부 이미 G1–G4 에서
   죽어 있다** → `unique_kill = 0`. 물리는 맞다(황화물 SE↔산화물 양극은 큰 구동력,
   산화물↔산화물은 작다). **맞는 물리가 변별을 주지는 않는다.**
2. **S1 조건② 는 YES 지만 자명하다** — "host LPSCl(−322.7)보다 완화되는 코팅" 47/47.
   비교가 *황화물 vs 산화물 양극* 대 *산화물 vs 산화물 양극*이라 화학이 다르다.
   **코팅 개념의 타당성을 재현한 것이지 후보 간 변별이 아니다.**
3. ⭐ **진짜 신호는 게이트가 놓친 쪽** — Li 흡수 25행 검출, 그중 **게이트를 통과하면서**
   흡수하는 것이 **23행**: Al₂O₃→LiAl₅O₈ · WO₃→Li₂WO₄ · Nb₂O₅→LiNbO₃ · MgF₂→LiF ·
   Ta₂O₅→LiTaO₃. 전부 |dE_rxt| < 100 meV 로 통과한다.
   **Al₂O₃ 코팅의 Li inventory 소모는 실험적으로 알려진 현상**인데 dE_rxt 축이 못 잡는다.
   ⚠ **그리고 WO₃ 가 여기 있다** — §0-3 의 "최종 승자" 후보다.
4. **리튬화 비대칭이 기구 차이를 드러낸다** — host 는 반충이 나쁘고(S 산화 구동),
   코팅 18종은 반대로 만충이 나쁘다(Li 흡수 구동). 같은 방향은 9종뿐.
   ⇒ 두 계를 같은 "반응성" 언어로 묶으면 기구를 뭉갠다.

⇒ 우리는 **G6 를 깔때기에 조인하지 않기로** 했다 (vacuous 게이트를 단계로 올리면
깔때기가 실제보다 촘촘해 보인다). 이 판단이 맞는지가 Q6.

## 2. 리뷰어에게 묻는 것

## 3. 손대면 안 되는 것 (리뷰어 유의)

- **순서 민감도 120 순열 전수**는 이미 했다. 다시 요구하지 말 것.
- **문헌 수치**(104,082 / 12,831 / 15,855 등)는 **소환값**이고 우리 db 값과 섞어 계산하지
  않았다. 섞는 처방 금지.
- **G3 의 ox_V 는 19종이 2.14 V 에 축퇴**(S²⁻-limited) — 통과/탈락 판정만 유효하고
  **축퇴군 내 순위는 무의미**하다.
- **G4 BVSE 는 정적 기하 프록시** — 절대 σ·D 로 읽지 말 것.
- **G5 의 E·G/B 는 UMA 상대값** — 절대 인용 금지.
- **전자절연·계면 반응성 두 축은 문헌에 있고 우리 게이트엔 없다** — "문헌 게이트를 전부
  재현했다" 고 쓰면 틀린다.

## 4. 우리 쪽 잠정 결론 (반박 환영)

**"작동은 했는데, 작동한 부분이 좁다."**

- 실질적으로 거른 것은 **G3·G4·G5 셋뿐**이고, 그중 **가장 강한 G5 가 로스터 의존
  median 컷**이다 (풀이 바뀌면 문턱이 따라 움직인다).
- **G1·G2·G6 는 장식**이다 — 다만 그 사실 자체가 결과다: *우리 풀이 이미 그 조건으로
  큐레이션돼 있었다*는 증거이고, Sendek 2017 의 "전제조건 > 전도도" 순위가
  **우리 풀에서는 역전된다**(전제조건이 소진된 풀에서는 구속이 수송/기계로 이동).
- 종점 **11종은 방어 가능**, **1종은 방어 불가**.
- 부피 사건의 피해는 **Stage 02–03 에 국한**되고 하위 축은 건전하다 — 단 **선발 잣대가
  흔들렸다**(Q3).
