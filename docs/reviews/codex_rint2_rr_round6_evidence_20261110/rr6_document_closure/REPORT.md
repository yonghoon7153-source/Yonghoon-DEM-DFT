## 2. Q2 — Q6 좁힌 수용 문장

**수용 — 지정 코드·합성 범위에 관한 판정 전사와 한정 공개. 재개 정책 전체 GO는 열림/범위 밖.**

- `docs/reviews/rint2_rr5_fix_plan_20261109.md:22`의 인용문은 이전 판정 `:95`와 문자 그대로 같다. 지정 수정의 수용, 원천 미확인 시 결과 기록 보류, 확인된 모순의 재개 불가 기록, summaryless prefix·실제 호스트·I/O·프로세스·R 캠페인 GO 제외를 모두 보존한다.
- `CLAUDE.md:114`는 옛 “GO 조건 두 문장”을 취소하고 위 판정 §5에 결속한다. 괄호 안의 “재개 불가 결과 줄 + 다음 재개 거부”는 회차 ⑤ §6-1에서 관측한 동작과 같다. 모든 모순에서 결과 파일 자체를 쓰지 않는다는 주장으로 바뀌지 않았다.
- 수정 계획 `:23`, `CLAUDE.md:114`는 요약 없는 재개에서 이미 복사된 앞 런과 원천 사이 불일치를 못 잡는다는 한정을 남긴다. 수정 계획 `:25`는 더 넓은 비교 구현을 하지 않았고 필요해지면 별도 수정임을 명시한다.

잔여 반례는 이전 판정 `:105–124`의 summaryless copied-prefix 단일 payload 변경이다. 같은 반례를 이번 회차에 재실행하지 않았다. 이 문서는 그 반례를 닫거나, 실제 정직한 복사/디스크 부족이 같은 손상을 만든다고 입증했다고 주장하지 않는다. 따라서 이번 문서 수용으로 그 무결성 범위를 종결할 수 없다.

## 3. Q3 — S0 importer 경계

**수용 — 특정 rc 보완/기존 원자료 채택과 일반 자동 인증을 분리한 문면. 자동 인증은 열림/범위 밖.**

- 수정 계획 `:40`은 두 기존 반례를 빠짐없이 적는다: 실제 `rss.log`에 rc가 없고 `old_rss.log`에만 rc=0인 경우, rc=0 뒤에 RSS 표본이 더 있는 경우. 이들은 후보로 받아들여지는 코드 경계로 남는다.
- `:41`은 DBE S0 단계 2 반입에서도 사람이 **정확한 `rss.log` 하나, 마지막 rc의 종결 위치, 생산자 `run2.sh` 결속**을 직접 확인하도록 정한다. “자동 생산자 / 최종 rc 인증기로 쓰지 않는다”가 명시되어 있다.
- `:42`와 `findings.json:16585`는 SELF-159의 수용을 원 다섯 rc 반례와 확인한 실제 묶음으로 제한한다. 이미 봉인된 SBE README/ADOPTION_CHECK를 덮어써 범위를 바꾸지 않았다.

별도로 보관된 이전 판정 `:146`, `:165`가 확인한 것은 그 특정 TGZ의 `s0mem_1106b/rss.log:1079` 마지막 유일 rc=0과 `run2.sh:15` 자식 종료값 결속이다. 이번 문면 대조는 TGZ를 재실행·재채택하거나 미래 DBE 로그에 대해 그 사실이 이미 성립한다고 인증하는 작업이 아니다. 미래 반입에서는 위 수동 확인의 대상 경로·원문 줄·신원 근거를 실제로 기록해야 한다.

## 4. 재현과 한계

동봉 `document_compare.py`는 제공된 문서만 읽고, 독립 보관된 판정문과 바이트 대조 및 인용문/조건 문구의 정적 비교를 수행한다. 프로젝트 모듈을 import하지 않고 프로젝트 시험·연구 계산·원격 호스트를 실행하지 않는다. 정적 체크 목록은 문면 위치를 남기기 위한 것이며 물리·코드 동작 인증 시험 수가 아니다.

```powershell
python document_compare.py --repo <해제된-ZIP>/repo --prior-verdict <이전에-보관한-회차5-판정문> --out document_comparison.json
```

실제 실행 rc=0. 좁힌 수용 인용문은 정확 일치, 최소 `s_min` 문안은 공백 제외 일치, 남은 조건 문구와 역사 문장 철회가 확인되었다. 정적 문구 존재 검사는 의미 판정의 대체물이 아니며 위 판정은 해당 문단을 함께 읽은 결과다. 새 실행·현장/물리 자격·원장 수정은 수행하지 않았다.
