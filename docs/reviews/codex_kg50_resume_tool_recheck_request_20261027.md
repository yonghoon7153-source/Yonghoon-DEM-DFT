## 4. 이 요청서를 쓰며 새로 본 것 (합성 · 원장 등재 전 · 고침 = 1저자 결정)

### 4-1. after_settling 재개는 정상 시험도 G0 에서 떨어진다 (닫힌 실패 · 안전 쪽)

- 기대 끝 = `EXP = S0 + NT` (NT = 시험 덱 **마지막** `run` 의 수 · 483 · 490 행).  after_settling 재개 덱은 체크포인트 (write_restart · step 200001) 뒤 첫 긴 run (안정화 `run 200000`) 앞에 판 높이 계산 `run 1` (덱 172–174 행 꼴) 이 있어 시험 = `run 1` + `run 2000` → 실제 마지막 step = S0 + 2001.  G0 은 `마지막 step 202002 (기대 202001)` 로 실패 → 본 제출 안 함.
- 합성 재현 (이 요청서 · 가짜 SLURM · 가짜 `dem_restart.py` FAKE_MODE=after_settling): 본 덱 = v2 `kg50_d07_b40` · 재개 덱 = 그 본 덱에서 `create_box` · 템플릿 · 분포 · 삽입 블록 · 정착 `run 200000` · `write_restart …after_settling` 을 빼고 `processors` 뒤에 `read_restart …/restart_after_settling.bin` · 원 로그 = 정착 끝 200001 → `run 1` (c_zmax · 200001 · 200002) → 안정화 중 230,000 에서 멈춘 꼴 · 시험 로그 = `run 1` (200001 → 200002) + `run 2000` (→ 202002) + `Loop time of`.  결과 = 정적 대조 통과 (문제 0) · 시험 냄 · **G0 실패** (`마지막 step 202002 (기대 202001)`) · G1 통과 · G2 통과 (`PLATE HEIGHT` 줄 같음) · G3 5 % 안 · 본 제출 안 함.
- 09-27 r050 실제 재개 (after_settling · step 200001 · G1 첫 줄에 `zmax` 열 · G2 = `PLATE HEIGHT` 줄 · `docs/resume_ckpt_procedure_20260927.md` §1 표) 가 같은 꼴이다 → 그 덱 · 로그를 지금 도구로 다시 돌린 것은 아니지만, 같은 꼴이면 지금 도구는 본 제출을 하지 않는다 (추정).
- 걸리는 곳: Q5 등록 초안 (D0.7 본 런을 정착 끝에서 멈춘 뒤 이어 돌리는 길) · D1 · D2 를 정착 끝에서 기다리게 하는 안.

### 4-2. write_restart · 압축 루프 체크포인트 재개 덱은 첫 긴 run 의 길이를 대조하지 않는다 (fail-open 쪽 · 크기 미정)

- 정적 대조 D (남은 step) 는 restart 명령 체크포인트 · 앞에 반복 없음 일 때만 돈다 (`check()` 198–226 행).  E (뒤 순서) 는 첫 긴 run **다음** 줄부터 본다 (228–234 행).  그래서 첫 긴 run 자체의 길이는 settling 꼴 밖에서는 아무도 보지 않는다.
- `-C` 합성 (이 요청서): after_settling 재개 덱 (v3 `kg50_d07_b50` 본 덱에서 위와 같은 규칙 · 템플릿 줄 포함) 의 안정화 run 200000 → 199999 · 100000 · 400000 = 셋 다 **통과** (rc 0 · "남은 step 확인 해당 없음 (write_restart 체크포인트)") · 같은 덱의 안정화 감쇠를 정착 값 그대로 둔 변이 = 실패 (상태 C 는 잡는다).  실제 09-27 r075 압축 쌍: 루프 안 `run 5000` → `run 4000` = **통과** · 이완 `run 100000` → `run 50000` = 실패 (E).
- 시험 (`-T`) 은 첫 긴 run 을 2,000 으로 자르므로 G0–G3 도 그 길이를 못 본다.  실제 `dem_restart.py` 가 after_settling · compress 에서 그 길이를 바꾸는지는 모른다 (소스 없음).
