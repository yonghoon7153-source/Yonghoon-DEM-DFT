## 2. 결정 질문 (권고 = 첫 줄)

**Q1 (RCA2-01 · P2 + RCA2-04 · P3) SV 문턱을 증서 구간으로 판정**
- (가) **권고** — 정밀 구간 전달: 주 해 · 각 cut 끝 (아래 · 위) 의 목표량 구간 (`target_lo` · `target_hi`) 과 G 의 결합을 SV 기록에 보존하고 (투영에서 버리지 않음), 아래비 = Gfull_lo / Gcut_lower_hi · 위비 = Gfull_hi / Gcut_upper_lo 로 판정 — 아래비 > t → `SV_DEPENDENT` · 위비 ≤ t → 표지 없음 · 나머지 → `SV_UNCHECKED` · ∞ 는 topology 가 증명한 0 분모에만.  같은 묶음 (RCA2-04): computed 끝마다 현 증서 필수 · 증서 ↔ 그 끝의 G · target · 분자 · 등록 rule / version 결합 · 실제 census 와 제거 수 · 셀 수 일관 · 무증서 실행 = 진단 지위 (R 판정 입력 아님).  Codex 반례 (증서 구간 [10.29125393534377, 10.291253935346631] 전체가 문턱 10.291251705345072 위) = `SV_DEPENDENT`.
- (나) 모든 computed 해의 인증을 먼저 강제한 뒤 nominal 괄호를 [(1−τ)/(1+τ), (1+τ)/(1−τ)] (τ = 1e−4 = 지금 증서 허용선 · 새 숫자 아님) 로 넓힘 — 같은 반례 = `SV_UNCHECKED` (정보량이 줄어든다).
- 둘 다 상주 회귀: 경계 양쪽 · 같음 · ∞ · 한 끝 실패 · 무증서 · 외부 증서 · 임의 rule · 제거 수 변이 (판정문 §9 첫 줄).  웹앱 SV 줄 · 설명 페이지 = 같은 묶음.

> **★ 쉽게 말하면 ④ — nominal 비 vs 증서 구간 (Q1)**
>
> - 지금 사슬은 풀이가 낸 비 하나 (nominal) 를 문턱과 비교한다.  풀이는 허용오차 안에서 조금 틀릴 수 있다.
> - 증서는 "참 비는 이 구간 안에 있다" 를 보장한다.  Codex 반례는 구간 전체가 문턱 위 (= SDCP 에 기댄다가 확실) 인데, nominal 비는 문턱 바로 아래라 표지가 안 붙었다.
> - (가) 는 구간의 양끝으로 판정해 이 반례를 `SV_DEPENDENT` 로 잡는다.  (나) 는 모든 비를 같은 폭으로 넓혀 "모름" (`SV_UNCHECKED`) 으로 둔다 — 안전하지만 덜 알려 준다.

**Q2 (RCA2-02 · P2 + 판정문 §9 F5) 같은 코드의 보장**
- (가) **권고** — git 엄격 + 한 단계 대조: ① `git rev-parse` · `git status` 둘의 종료코드를 보고, HEAD = 40-hex · dirty = 엄격한 False 일 때만 통과 (조회 실패 · git 밖 = 미확인 = 멈춤 · False 로 바꾸지 않음 = C6 #13) ② untracked 범위 — (가-1) **권고** ignore 밖 untracked 전부를 dirty 로 / (가-2) untracked `*.py` · `*.sh` 만 ③ 한 단계 안 chain ↔ runner 의 HEAD · 파일 지문을 서로 대조 (자기 요약끼리 비교 아님) ④ 파일 지문 키 = 저장소 상대 경로 (절대경로 대조 뺌 = C6 #14) · 목록에 Codex 가 짚은 모듈 (`ca_ext_cjunc.py` · `additives.py` · `se_material.py` · `lens_geometry.py` · `step4_dyn.py` · `rint_cycle_traj.py`) 더함 ⑤ 환경 지문 (python · numpy · scipy 판) 단계마다 기록 · 다르면 멈춤 ⑥ F5 = `plan_source` 문법 (`commit:` + 40-hex) + 그 커밋 안 계획 파일 blob sha256 = 계획 sha256 대조.
- (나) 완전 의존성 manifest — 각 단계의 실제 import 관측 (사슬 · payload 프로세스의 저장소 모듈 + sha256 · 194 러너 `--observe-imports` 꼴) 을 다음 단계가 대조 · git 밖에서도 성립 · 구현 큼.

**Q3 (RCA2-03 · P2) 같은 침대의 보장 (S0 → R)**
- (가) **권고** — 원 입력 바이트 지문: S0 보고의 `inputs` (역할 7 개 파일 sha256 · 크기 · `metrics` 상자 · 두께) 를 사슬 요약에 보존하고, R 런 직전 · 재판정 때 같은 발견 함수로 실제 킷 파일을 다시 해시해 대조 · 다르면 멈춤 · **공통 원침대 지문** (원 입력 · 설정) 과 **파생 격자 지문** (vox · origin · 격자 · `cells_by_sid`) 분리 (파생 = 같은 규약일 때만 대조) · 경로 문자열은 대조에서 뺌 · 재압밀 · 재생성 침대 = 새 S0 (등록 §2-1 · §11 문장).  Codex 반례 (섬유 0.04 이동 · 셀 수 같음 · 접합 1 → 0) = 멈춤.
- (나) 배열 수준 canonical 지문 (값만 · 파일 형식 무시) — 형식만 바뀐 같은 침대를 통과시킴 · 구현 큼.

> **★ 쉽게 말하면 ⑤ — 같은 코드 · 같은 침대 (Q2 · Q3)**
>
> - 등록 판정은 "S0 에서 센 것과 R 에서 푼 것이 같은 코드 · 같은 침대" 라는 전제 위에 선다.
> - 지금 관문은 그 전제를 다 보지 않는다: git 조회가 실패해도 "깨끗함" 으로 적히고, 사슬과 러너가 다른 판이어도 각자 자기 요약끼리만 비교하고, S0 뒤에 섬유가 움직여도 (셀 수가 같으면) 통과한다.
> - (가) 는 git 조회 실패 = 멈춤, 한 단계 안에서 사슬 ↔ 러너를 서로 대조, R 직전에 킷 파일을 다시 해시해 S0 보고와 대조한다.

**Q4 (RCA2-05 · P2 사전등록 절차) 시간 · 중단 · 재시도의 봉인**
- (가) **권고** — R 계획 JSON 에 실행 정책 칸을 넣어 같은 봉인 (계획 sha256) 안에 둔다: 시간 상한 (`--max-hours` = 계획 값과 같아야 · 다르면 거부) · 최대 시도 수 · 재시도 규칙 = **결과 전 멈춤 (관문 · 환경 · 기계 자원) 만 재시도 가능 · 결과 뒤 멈춤 (불수렴 · 사다리 소진 · 수치 · 물리) 은 같은 등록의 재시도 아님 (= 결과 열람 뒤 개발 / 개정)** · 동일 설정 요건 (계획 · 코드 · 침대 지문) · 채택 순서 (처음 완주한 시도) · 시도 폴더 `attempt_<n>` + 실패 시도 · 원 사유 · 다음 attempt ID 보존 (빈 폴더 요구 대신) · 기계 귀속 (팔마다 기계 이름 필수 · 빈 이름 금지 · 등록된 기계 목록 = C6 #15) · 문서 숫자 (s_min 등) = 계획 JSON 에서 생성 · 정확 대조 (C6 #30).  숫자 (시간 · 횟수 · 기계 목록) = SBE 탐침 뒤 1저자.
- (나) 사람 규율 + 실행 영수증 기록 (한계를 등록에 명시 · 기계 봉인 아님).

> **★ 쉽게 말하면 ⑥ — 재시도 봉인 (Q4)**
>
> - 마감이 와도 팔을 줄이지 않는다는 원칙은 이미 있다.  빠진 것은 "멈춘 단계를 다시 돌릴 때의 규칙" 이 계획 안에 기계적으로 묶여 있지 않은 것이다.

> - (가) 는 "결과 전 멈춤만 재시도 · 시도마다 기록 · 처음 완주한 시도를 채택" 을 계획 해시 안에 넣어 사슬이 확인하게 한다.
