## 3. 실행 당시 신원과 현재 파일 신원을 분리

행은 실제 승인된 증거가 도착한 뒤 추가한다. **현재 파일 SHA256는 현재 바이트의 식별자이며 실행 당시 사용 증명이 아니다.** 같은 SHA가 맞더라도 그 영수증의 출처·실행 결속까지 확인해야 한다. SHA 자체는 작성자 진위나 승인 권한을 인증하지 않는다.

| 입력/증거 별칭 | 종류 | case/run/segment 참조 | 현재 bytes / SHA256 | 실행 당시 SHA256 | 실행 당시 봉인·영수증 별칭 / 그 현재 SHA256 | 대조 결과·미확정 사유 |
|---|---|---|---|---|---|---|
| null | deck / include / restart / execution_receipt 중 하나 | null | null / null | null | null / null | NOT_ESTABLISHED |

| 순서 있는 연결 항목 | 기입할 비결과 근거 | 현재 상태 |
|---|---|---|
| 진입 덱과 실행 인자·변수 결속 | 기존 영수증의 안전한 참조, 적용 순서·분기 근거. 원문 명령/외부 위치는 복사하지 않음 | UNKNOWN |
| include/jump/read_data 등 의존 | 부모·자식 별칭, 순서, 유효 의존 여부를 뒷받침하는 기존 근거 | UNKNOWN |
| 재개 사슬 | checkpoint 별칭, producer/parent/child·run/segment 연결, 실행 당시 신원 근거 | UNKNOWN |
| 완전성·제한 | 어떤 입력/의존/재개 항목이 누락·미확정인지; 현재 hash만 있는 항목과 구분 | UNKNOWN |

파일을 검색하거나 덱을 실행/eval해 의존을 추측하지 않는다. 현재 입력 한 파일의 hash, 재고의 restart 계수0, 파일명·mtime·크기는 전체 사슬이나 동일 실행의 증명이 아니다. 실행 당시 증거가 없으면 `NOT_ESTABLISHED`/`UNRESOLVED`를 유지한다.

## 4. 두 로그의 run/segment 경계 — 원로그를 읽지 않는 수령

이 양식에서 로그는 A/B 별칭으로 구분한다. **A/B 별칭은 A/C 처리 경로와 무관하며 어느 로그도 정본으로 선택하지 않는다.** 각 별칭이 기존 로그 명칭 중 무엇을 뜻하는지는 승인된 비결과 메타 참조로만 결속한다.

| 항목 | 로그 A | 로그 B | 출처·제한 |
|---|---|---|---|
| 로그 신원 참조 | null | null | 기존 영수증/승인 메타의 별칭; 원로그 hash 신규 계산도 이 명령에 넣지 않음 |
| run / segment | null / null | null / null | 동일하다고 미리 가정하지 않음 |
| 헤더 신원 참조 | null | null | 승인 메타에 이미 있는 비결과 참조만; 원 헤더/본문 자유 텍스트 출력 없음 |
| first_step / last_step | null / null | null / null | 승인된 메타 사본에 이미 있는 정수 또는 UNKNOWN; 새 원로그 scan 없음 |
| 재개 parent / child 참조 | null / null | null / null | 기존 관계 증거; step만으로 재개 순서·동일 사건 판단 불가 |
| 겹침·연결·결손의 비결과 근거 | null | null | 안전한 근거 참조와 미확정 사유만; 행을 합치거나 중복 제거하지 않음 |

**헤더·step 범위의 비결과 메타 자체는 이번 Q1에 이미 허용됐다.** 원로그 본문 제외를 지키기 위해 이 명령 초안은 원로그에서 이를 자동 추출하지 않는다. 허용된 헤더·step 메타는 1저자가 출처·승인 사본·고정 해시로 제공한다. 해당 사본이 없으면 이 명령은 **UNKNOWN/STOP**이며, 이 초안으로 `cat`, `head`, `tail`, `grep`, 원로그 parser 또는 임시 전체 사본을 만들어 채우지 않는다. 이는 명령의 좁은 범위이며 비결과 메타 허용을 취소한 것이 아니다. 기존 자료가 다른 형식이면 그 형식·출처·비결과 한정을 먼저 제시하고, 없는 실행 신원을 확정하지 않는다. 같은 B7 줄 수·다른 파일 크기로 동일 실행/정본성을 결정하지 않는다.

## 6. 수령 후 남는 경계

Codex는 받은 범위와 명령 rc·출처·SHA를 문서로 대조하고 사실/1저자 증언/미확정을 분리한다. 지정 범위 밖 파일이나 원로그 본문이 섞이면 읽기·분석을 확장하지 않고 분리 보류한다. 메타 수령 성공은 실행 신원 확정, 코호트·고정쌍 생성, 정본/A/C 선택, 압력 자격, PHASE4 완료, 평형, 실제 N 확인 또는 값 GO가 아니다.

후속 순서는 **비결과 증거 수령 → 실제 정본/구간·A/C 선택안 → 명부·종점/동일 사건·필드·담당/노출/보존의 실제 동결안 → 1저자 동결 승인 → 별도 최소 값 GO**다. Q2–Q4의 실제 선택·승인 참조는 계속 null이다. 기존 B7 REFUSED 보존, C 변경 시 별도 시험/고정 후보 검토, porosity/tau·압력 재기록·단계 A·다른 재고 범위 제외를 유지한다.

명령 초안은 [lhs_wsl_readonly_command_draft.md](lhs_wsl_readonly_command_draft.md)에 있다. 이 양식과 명령은 새 reader·활성 schema·승인 토큰·완전한 사전등록이 아니다.
