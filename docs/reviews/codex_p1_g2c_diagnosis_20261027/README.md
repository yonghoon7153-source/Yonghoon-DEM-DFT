# RJ 323957: G2c 불일치의 읽기 전용 수치 분석

**RJ는 한 번 실행됐고 복원 판정은 VALUE_MISMATCH다.** 사용자 전달 기록에서 G2c의 562,605쌍 중 545,583쌍(약 96.9744%)이 달랐다. 원자 비교 G2는 160,417개 모두 일치했고 다른 보고된 조건은 통과했지만, 이것이 G2c 실패를 지우지 않는다. 실행 단계 rc=0·fails=0과 복원 reader_rc=2를 구분한다. 물리 시도 한 번을 소비했으며 재실행·후속 UB/UT/UC·기준 완화는 하지 않는다.

이 도구는 **이미 있는 두 contact 파일에서 어느 성분이 차이를 만드는지 읽기만 한다.** 아직 실제 파일에 실행하지 않았다. 접선 이력이나 특정 힘 성분이 원인이라고 미리 단정하지 않는다. 기존 verdict·원본·봉인 코드를 수정하거나 새로운 수용 판정을 만들지 않는다.

## 사용 방법

1. [붙여 넣을 명령 전체](paste-diagnostic.sh)를 기존 ibb 터미널에 붙여 넣는다. 지정된 myenv Python을 -I -B로 실행하며 파일 저장·전송·설치·fetch가 필요하지 않다.
2. 끝날 때까지 기다린 뒤 출력 JSON 전체를 전달한다. 출력만 있으며 서버 파일을 만들지 않는다. subprocess, LMP/MPI, sbatch, 기존 복원 판독기나 새 DEM 시뮬레이션을 실행하지 않는다. 기존 자료의 수치 분석만 수행한다.
3. COMPLETE_NUMERIC_BREAKDOWN_NOT_A_VERDICT와 recorded_gate_match=true일 때만 성분별 집계를 읽는다. PARITY_DISCREPANCY 또는 INCOMPLETE이면 반환값 2이며 성분별 해석을 하지 않는다. 오류를 우회하거나 입력 행을 지우지 않는다.

두 고정 입력은 staged in/contact_3200000.liggghts와 RJ/R/g2/contact_3200000.liggghts다. 경로는 [소스](diagnose_g2c.py)에 고정되어 있다. 원본의 149,687,008바이트와 SHA256 `53ae293b4586d091dfca58ab430c174f36b641dcd24678eb10d10fc3f416e65c`를 확인한다. 시험 파일의 크기·해시는 새 출력에 기록된다.

## 어떤 계산을 그대로 재현하나

기준은 수용된 ULPRI `4c29705fa1c4ba94737a858b206fa4f4c5bb2bde`의 G2c다. 실제 job kit의 봉인과 ul_gates/ul_lib/ul_reader 해시, job 323957의 manifest·VALUE_MISMATCH verdict를 먼저 대조한다. 키트 모듈을 import하거나 실행하지 않고 동일 계산을 별도 표준 라이브러리 코드로 수행한다.

- 쌍 ID는 정확한 양의 정수로 읽고 방향이 뒤집혔으면 위치를 교환하고 힘 9개 부호를 반전한다.
- 비교 상자는 dump 헤더의 길이가 아니라 기존 기본값 x/y 각각 0.05다. 기존과 같은 주기 정규화를 쓴다.
- **원본 전체의 정규화된 절댓값으로 비교 성분 20개의 중앙값을 각각 계산한다. 샘플 중앙값을 쓰지 않는다.**
- 각 성분의 차이를 기존 식 delta > 1e-5 × max(abs(original), 해당 원본 열의 중앙값)으로 비교한다. 작은 양의 허용폭을 새로 넣거나 경계를 느슨하게 하지 않는다.

| 원래 열 | 비교 의미 |
|---|---|
| c_cpl[1–6] | 양 끝점 위치 |
| c_cpl[10–12] | 전체 힘 |
| c_cpl[13–15] | 법선 힘 |
| c_cpl[16–18] | 접선 힘 |
| c_cpl[22] | 면적 |
| c_cpl[23] | delta |
| c_cpl[24–26] | 접촉점 |

출력은 성분·계열별 **첫 실패 쌍 수**와 **어느 위치에서든 실패한 쌍 수**를 구분한다. 기존 gate의 첫 실패 중단 순서를 재현하므로 first_fail 총합이 불일치 쌍 수다. 한 쌍이 여러 성분에서 달라질 수 있어 any_fail 합계는 더 클 수 있다. 성분별 예시는 최대 3쌍이며 원본/시험 값·주기 처리한 절대차·허용폭을 함께 보여 준다. 예시는 집계용 표본이 아니다. 방향 반전 수와 canonical 힘의 0/부호 변화도 보조 정보일 뿐 원인 판정은 아니다.

**562,605/562,605쌍, 불일치 545,583쌍, discriminating_frac=1.0을 먼저 재현해야 한다.** 다르면 job binding·입력 해시·집계 차이만 출력하고 성분/계열/힘 분석을 숨긴 채 rc=2로 끝난다.

## 읽기·메모리 제한

원본 값은 행당 double 20개 배열과 pair→index 사전에 보관하고, 시험 파일은 한 행씩 읽는다. 기존 reader의 큰 row dictionary 두 벌을 만들지 않는다. 중앙값용 정렬은 한 열씩 한다. 실제 562,605행의 숫자 배열만 약 86 MiB이고 pair 사전·Python 객체·정렬 공간이 추가되므로 수백 MiB의 여유가 필요하다. 정확한 최대 RSS를 측정했다고 주장하지 않는다.

선언 행 수 최대 600,000, 한 줄 최대 8,192바이트, 각 파일 최대 512 MiB를 할당/파싱 전에 제한한다. 헤더·열 순서·step·비유한 값·잘못된 ID·복수 frame·중복 쌍·빠진/추가 쌍을 발견하면 미완료로 거부한다. 동일 값 중복도 이 진단에서는 거부한다. 기존 gate가 일부 동일 중복을 처리할 수 있다는 점과 구분하며, 이번 기록의 중복 수는 0이다. 기울어진 BOX 표지도 거부하는 좁은 진단 입력 범위다. 행을 조용히 누락하거나 중복을 중앙값에 섞지 않는다.

파일의 inode/크기/mtime/ctime을 읽기 전후 및 전체 분석 끝에 다시 대조한다. 변경 탐지 보조 장치이며 원자적 snapshot 보장은 아니다. job manifest/verdict와 모듈 해시도 끝에 재확인한다. 출력에 진단 코드 자체의 SHA256과 제한값을 남긴다.

## 검증과 근거

[국소 oracle 결과](oracle-results.json)는 accepted 4c의 실제 ul_gates/ul_lib 파일을 해시로 결속한 **66개 작은 합성 검사**다. 20개 성분 각각의 변화, 방향·주기, 홀수/짝수 전체 중앙값, 경계값·0 중앙값, 중복/잘못된 파싱/자원 제한, 입력 변경 및 provenance 거부, 집계 불일치 시 출력 억제와 rc2를 포함한다. 실제 dump나 full155·과학 실행을 반복한 것이 아니다. [검사 소스](test_diagnose_g2c.py)의 임시 파일은 로컬 합성 검사에만 썼다.

재현하려면 기존 accepted 4c 키트 위치를 --oracle-dir로, 이 디렉터리를 --binding-fixtures로 주어 Python -I -B로 test_diagnose_g2c.py를 실행할 수 있다. 사용자에게 이 검사를 다시 돌려 달라는 요청은 아니다.

[기록된 RJ 결과](diagnostic-receipt.json), [전달 verdict](restore_verdict.user-relayed.json), [전달 manifest](run_manifest.user-relayed.txt)는 사용자가 채팅으로 준 내용을 전사한 자료다. JSON 공백을 정규화했으며 실제 서버 파일의 바이트 사본으로 주장하지 않는다. 실제 진단은 서버 파일을 의미상 대조한 뒤 그 원문 해시를 출력한다.

과거 좁은 CLOSED 판정은 유지하지만 이번 실제 복원의 VALUE_MISMATCH는 별도 실패다. 허용폭·봉인 코드·원본을 수정하거나 재시도하지 않는다. 이 도구가 mainboard 인계에 포함되더라도 실제 dump 분석 결과나 물리 GO가 이미 생겼다는 뜻은 아니다.
