## 1. 왜 나누나

- 지금 사슬 (`scripts/rint_r_chain.py`):

## 3. 설계

### 3-1. 단위 (1저자 Q9 (가) · 개정 1 Q15 (가) · 개정 3)
- 단위 = (c, 법칙, R) 12 개.

- 위 출처 칸이 모든 채택 폴더에서 같다.  다를 수 있는 것 = 기계 이름 · 원장 항목 · 단위 이름 · 환경 지문의 기록 전용 칸 (§3-3) 뿐.

  - **(개정 4 · R4-03 — 위 근거 문장을 바꿈)** 채택 뒤 같은 단위의 항목은 풀기 전 대조가 먼저 거부한다 (결과 전이 아닌 앞 시도가 있으면 거부 · 예외 = 재실행 자격으로 멈춘 사슬의 다음 재실행뿐 · §3-2) — 거부 기록만 남은 항목은 멈춤이 아니다 (기록만).  그래서 이 멈춤은 **풀기 전 대조를 거치지 않고 돈 흔적** (표지 · payload 가 있는 폴더) 에만 걸린다 (대조 우회 = 구현 결함 또는 사람의 손).  늦게 드러난 실수 (판이 다른 venv · 채택된 단위를 실수로 다시 시작 · 거부된 재실행) 는 풀기 전 대조가 결과 전에 막으므로 되돌릴 수 있다 (4차 사전 공격 R4-03 (a)–(c) · 탐침 S3 · S5).

### 3-5. 시도 원장 (개정 1 · Q16 (가) · 사전 공격 D3 · 개정 2 · 개정 3)
- 원장 = 덧붙이기만 하는 파일 하나 (계획 봉인과 같은 리포 · 계획 sha256 에 묶임).  시도를 시작하기 **전에** 항목을 커밋한다: (단위 | 넘침 점 | 재실행 | (개정 4 · Q5) 사다리 (법칙)) · 기계 · 시도 번호 (원장 안 순서) · 계획 · 코드 · 침대 · 환경 지문 · (재실행이면) 원 시도 번호 · 멈춘 런.
  - **(개정 3 · 3차 사전 공격 P3)** 원장은 실행 트리와 다른 체크아웃에 둔다 — 실행 트리는 핀 고정 (원장 커밋이 실행 트리의 HEAD 를 바꾸면 `code_key` 의 chain_head · runner_head 가 단위끼리 달라진다).
- **항목 하나 = 시도 폴더 하나 = 결과 줄 하나 (개정 2)** — 결과 줄 = 완주 / 멈춤 (원 사유 · 원인 · 결과 전 · 뒤) + 폴더 요약 sha256 (폴더 안 파일 전부의 상대 경로 · sha256 목록의 sha256).  같은 항목의 둘째 결과 줄 = 멈춤 `ATTEMPT_LEDGER_MISMATCH`.
- **같은 단위 시도는 차례로만 (개정 3 · 질문 3 · 3차 사전 공격 P2 셋째)** — 같은 단위 (또는 넘침 점) 의 항목 k+1 은 항목 k 의 결과 줄이 커밋된 뒤에만 커밋하고 시작한다.
  - 시도 폴더는 시작 때의 원장 커밋 sha 를 싣는다 (풀기 전 대조 §3-2).  합치기는 그 커밋에 자기 항목과 같은 단위 앞 항목들의 결과 줄이 모두 있는지 본다 (없으면 `ATTEMPT_ORDER_MISMATCH`).  **(개정 4 · R4-07)** 그리고 그 커밋의 원장 파일이 합칠 원장의 바이트 접두이고 그 커밋이 합칠 원장 커밋의 조상인지 본다 (곁가지 커밋에 결과 줄 자리표를 두고 시작한 꼴 = `ATTEMPT_ORDER_MISMATCH` · 탐침 `docs/reviews/rint2_rr_fix_evidence_20261023/preattack4/probes/ledger_branch_probe.py`) — 합치기 입력 = 원장 git 저장소 (파일 하나로는 커밋 대조 불가).
  - 첫 · 끝 합치기의 원장은 바이트 접두 관계여야 한다 (항목 줄 지우기 · 바꾸기 = `ATTEMPT_LEDGER_MISMATCH` · 3차 사전 공격 P3).
  - 이유: 원장 순서 ≠ 시작 순서이고 동시 시도를 허용하면, 뒤 항목을 먼저 돌려 결과를 본 뒤 앞 항목을 일부러 결과 전 멈춤으로 만들어 (예: 금지 환경 변수) 뒤 항목을 채택시키는 길 · 마음에 안 들면 앞 항목을 정상으로 돌려 앞 항목을 채택시키는 길이 열린다 — 파일 편집 없이.
- **시도 폴더는 모두 보존한다 (개정 2)** — 합치기는 단위마다 **원장의 시도 전부와 그 폴더 전부**를 받는다:
  - 원장에 없는 폴더 · 폴더 요약 sha ≠ 결과 줄 = 멈춤 `ATTEMPT_LEDGER_MISMATCH`.
  - **폴더 없는 원장 시도 (개정 3 · 질문 2)** — **풀기 전 거부 기록이 있으면 결과 전** (유일한 예외): 실행이 풀기 전 대조 (§3-2) 에서 거부하면 거부 기록 (항목 · 사유 · 시각 · 원장 커밋 sha) 을 시도 폴더에 쓰고, 시도 폴더를 만들 수 없으면 (예: 이미 있는 폴더) 그 옆의 정해진 자리 (`<시도 폴더>.rejected.json` 꼴 · 이름 = 구현 때) 에 쓴다.  그 밖의 폴더 없는 시도 (기계 · 디스크 소실 · 기록 없는 사라짐) = **엄격 — 결과 뒤** (그 단위 재시도 불가 → 예측 STOPPED → 이 등록의 주 판정 = 판정 없음 · 비용).  (개정 4 · R4-13) 거부 기록만 있는 시도의 폴더 요약 sha = 그 거부 기록 파일 하나의 (상대 경로 · sha256) 목록의 sha256 · 이미 결과 줄이 있는 항목 번호로 실행하면 시도 폴더 · 거부 기록을 만들지 않고 화면 · 종료 코드로만 거부한다 (원장 · 폴더 무변경 · 그 항목의 둘째 결과가 생기지 않는다).
  - **결과 전 · 뒤 판정 = 첫 풀이 끝 표지 (개정 4 · Q2 · R4-02 · R4-09 — 아래 개정 3 의 "폴더 + 원인 목록" 규칙을 바꿈)** — 결과 전 = 그 시도 폴더 (안 `.unchecked/` 포함) 에 팔 payload (`p2_*.json`) 도 첫 풀이 끝 표지도 하나도 없을 때 (원인 무관).  하나라도 있으면 결과 뒤.
    - 첫 풀이 끝 표지 = payload 프로세스가 그 팔의 첫 σ (첫 풀이 결과) 를 돌려받는 즉시, 그 σ 를 화면 · 로그 · 파일 어디에 쓰기 **전에** 시도 폴더 안 정해진 자리에 쓰는 표지 (이름 · 자리 = 구현 때 · 원자적 쓰기).  그래서 σ 를 볼 수 있었던 시도는 늘 결과 뒤다 — 남는 틈 = σ 를 얻고 표지를 쓰는 사이에 죽은 꼴 (그 σ 는 어디에도 쓰이지 않았다 · 한정).
    - 원인 = 사슬 부모 (`rint_r_chain.py`) 가 기록 (개정 4 · R4-09 — 개정 3 의 "러너" 두 뜻을 하나로) · 진단 칸 + 재실행 자격 (아래) 만.  결과 전 · 뒤를 가르지 않는다 — 시간 초과 · 러너 · payload 의 풀기 전 실패 (러너 ABORT · ImportError · 영수증 조립 실패) · 디스크 부족 · 신호 · CUDA OOM 이 모두 같은 규칙 (표지 · payload 유무) 이다.

## 10. 개정 5 (10-26) — Codex 회차 ① 인수 조건 · ⑥ 원장

근거 = Codex 회차 ① 판정 §7 ① ② ③ · §10 · 1저자 10-26 *"권고대로해"*.  결과 0 건 · 문서만 (구현 = 묶음 C).

- **① 같은 프로세스 → 같은 사슬 부모의 동결 환경** — 정상 경로의 확인 팔과 no-op 은 같은 사슬 부모가 동결한 실행 환경에서 수행한다.  재개는 새 프로세스에서 수행하며 원 시도의 전체 환경 지문을 대조한다.  남은 payload 는 bytes 를 대조하고, 없는 결과의 동일성은 결정성 가정으로 남긴다 (판정문 권고 문구 그대로).  부모 PID 만 같다고 "같은 solver 프로세스" 로 통과시키지 않는다 · 문자 그대로 같은 solver 프로세스가 필요하면 persistent worker 와 죽은 worker 의 재개 예외를 따로 설계한다 (지금은 하지 않음).  §3-5 :144 의 사다리 재실행 (끝난 확인 팔 복사 + 실패한 no-op 만 새로) 도 이 재개 규칙을 따른다.
