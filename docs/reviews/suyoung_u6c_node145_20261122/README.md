## 중단 원인과 수정

노드 2976에는 물체 4개가 속도를 주고받을 수 있는 접촉 후보 6쌍이 있었다. 노드 질량의 최대/최소 비는 약 107,486이었다. 구본은 512회 갱신 뒤 추정한 접촉 상태에서 최대 두 쌍까지 바꾸어 검사했다. 원래 허용치를 만족하는 해 하나에는 세 쌍의 접촉을 함께 풀어야 했다. 이 해의 나머지 세 쌍은 고착 둘, 미끄러짐 하나다.

| 속도 단위의 판독 | 값 |
|---|---:|
| 고정 허용치 | 6.1440 × 10⁻¹³ |
| 구본의 마지막 잔차 | 2.4614 × 10⁻⁵ |
| 같은 충격량을 70자리 산술로 재검사한 잔차 / 허용치 | 40,062,656.4 |
| 독립적으로 찾은 해의 70자리 산술 잔차 | 1.957 × 10⁻¹⁶ |
| 수정 코드가 선택한 충격량의 70자리 산술 잔차 | 1.233 × 10⁻¹⁷. 같은 충격량이 운동에너지 관문도 통과 |

`scripts/suyoung_multicontact_dev.py`의 고침은 앞선 탐색이 모두 실패한 4체 이하 노드에서, 활성으로 추정한 접촉을 셋 이상 함께 여는 조합을 검사한다. 4체에서 추가 시도는 최대 42조합이다. 각 후보에 기존의 비선형 정상·접선 잔차 기준과 최종 운동에너지 검사를 적용한다. 검사 범위에서 해를 찾지 못하면 계산은 기존처럼 중단한다.

## 고정 노드와 합성 점검

| 대조 | 관측 |
|---|---|
| 물체 ID 재부여 24가지 | 구본 24/24 중단. 수정본 24/24 수용. 물체 순서를 맞춘 수정본의 속도는 24가지에서 비트 일치 |
| 독립 해와 수정 속도의 최대 성분 차이 | 1.18 × 10⁻¹⁶ (저장 노드, Windows NumPy 2.3.5) |
| 기존 접촉 회귀 | 15/15 |
| 같은 고정 노드 회귀 6개 | 구본 3실패·오류 0 → 수정본 6/6. 정·역 저장 순서까지 교차한 48가지에서 물체별 속도 비트 일치 |
| 기존 합성 노드 묶음 | 72/72 및 360/360 |
| 접선 미끄러짐 합성 해 | 두 부호에서 기준 속도와 일치 |

기존 회귀와 순열 수는 측정 단위가 달라 합산하지 않는다. 접촉 모드 전부를 탐색한 결과나 임의의 형상에서의 유일성은 미확정이다.

노드 비교를 재현할 때는 1저자 반환의 `run/capture/failing_nodes.json`을 개인 작업 폴더에 두고 그 경로를 `CAPTURE`에 지정한다. 추가 증인 파일 없이도 독립 방정식으로 접촉 해를 복원한다.

```bash
python3 -I -B docs/reviews/suyoung_u6c_node145_20261122/test_captured_contact.py \
  --capture "$CAPTURE" --subject scripts/suyoung_multicontact_dev.py
```

## 다음 1저자 개발 비교

배포본을 검증한 뒤 WSL CPU 1개에서 F8 원 ID, 역순 ID를 이 순서로 한 번씩 계산한다. 각 팔의 시간 상한은 600초다. 두 팔의 곡선은 모두 도달한 같은 판 변위에서만 대조한다. 과거 곡선 두 개와 수정 후 두 개를 비교할 때는 네 곡선 모두 도달한 구간을 쓴다. 같은 변위에서의 최대 반력 차이, 그 변위와 공통 종점을 기록한다. 새 중단이면 그 실행에서 남긴 진단과 성공한 앞부분을 판독한다. 이 개발 비교를 마친 뒤 반박 창에 고정 후보와 결과를 함께 보낼 시점을 정한다.
