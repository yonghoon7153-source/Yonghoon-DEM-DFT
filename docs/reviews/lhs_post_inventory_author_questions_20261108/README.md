## W30-Q1: 신원 확정의 범위

제안 범위는 WSL30에 한정한다. 실제 호스트 읽기나 파일 반입은 1저자가 담당·출처·범위를 정한 뒤의 별도 단계이며 이번에는 수행하지 않았다. 값 열람을 정적 신원 확인에 끼워 넣지 않는다.

요청할 명부는 case/run/segment 식별자, 실행 당시 입력 봉인·영수증, 현재 파일의 종류·길이·SHA256, 실행 진입 인자와 include/jump/read_data 등 의존의 순서·변수 결속 근거, checkpoint와 producer/parent/child 관계다. 원 덱 하나의 hash를 유효 입력 전체의 신원으로 쓰지 않는다. 실제 주소·외부 위치 대신 리포에 들어갈 기록에는 식별자와 허용된 상대 참조를 쓴다.

실행 당시 봉인이 없거나 의존·변수·재개 연결이 불명하면 현재 정적 바이트와 실행 신원을 구분해 `NOT_ESTABLISHED`/`UNRESOLVED`로 남기는 것을 권고한다. 미확인 hash·시간·계보를 생성하거나 덱을 실행/eval하여 빈칸을 채우지 않는다. 재고의 restart 관련 계수 0은 이 명부를 대신하지 않는다.

## W30-Q2: 정본 하나 또는 둘 다의 규칙

정본 후보의 파일명은 선택 근거 자체가 아니다. 다음 조건을 값 열람 전에 고정할 것을 제안한다.

- 같은 실행·같은 구간의 출력임을 비결과 결속 근거로 입증할 수 있을 때만, 실행 기록에 연결된 `log.liggghts`를 정본 후보로 고정한다. `log.txt`는 삭제·덮어쓰기 없이 대조 자료로 보존한다. 줄 수가 같음, 파일 크기, 수정 시각 또는 더 좋은 압력값으로 고르지 않는다.
- 서로 다른 구간을 모두 소비할 정당한 필요가 있으면, run/segment·재개 순서·연결 경계·겹침/중복 처리·모순/결손의 거부 규칙을 먼저 정한다. 현재 두 로그를 곧바로 합치거나 행 수에 맞춰 중복 제거하지 않는다. 소비자 변경이 필요하면 W30-Q3의 C 절차로 넘긴다.
- 위 어느 근거도 성립하지 않으면 두 후보를 보존하고 정본은 미확정으로 둔다. 파일 크기 차이만으로 원본/사본 또는 선후 관계를 선언하지 않는다.

이번 문서는 파일 선택·이동·로그 내용 비교·결합을 하지 않는다. 원 로그와 거부 기록은 그대로이며, 정본을 선택해도 기존 B7이 REFUSED이면 그 결과를 보존한다.

## W30-Q3: A/C의 결정과 구현을 분리

A 우선은 조건부 권고다. 현재 재고가 성공했다는 사실로 A가 선택되거나, 두 로그가 있다는 사실만으로 C가 승인되지는 않는다. 원 실행 신원이 미확보라는 이유만으로 C를 자동 선택하지 않는다.

C가 필요하다는 비준을 받으면 B7 핀·등록에 미치는 영향, 고치기 전 실패 확인, 양성 보존, 변경 시험과 짧은 독립 검토의 범위를 먼저 준비해야 한다. 이번 단위에는 그 구현·시험·등록 개정이 없다. 어느 경로도 봉인 폴더 덮어쓰기·REFUSED 삭제·수동 TSV 결합을 허용하지 않는다.

## W30-Q4: 값 열람의 경계

원 정본 Q3의 P_Rend 제안, Q4의 N/독립 단위와 Q1/Q2의 코호트·노출 규칙은 12질문 정본의 별도 검토·비준 대상이다. 이 질문지가 그 정의를 확정하거나 실제 종점·쌍 명부를 채우지 않는다. 승인되지 않은 PHASE 4 완료·평형·N 인과 해석은 주장하지 않는다.

제안하는 열람 기록은 대상 case/run/segment, 사용 정본 또는 구간, 비준된 종점/프레임 규칙, 허용 필드·목적·담당, 노출 시점과 보존 규칙을 먼저 고정하는 것이다. 미완료/결측은 null+사유로 두며 결과를 본 뒤 대상·종점·허용폭을 바꾸면 별도 변경 기록으로 구분한다. porosity·tau 재열람, 압력 재기록, 단계 A, ibb184·전체214 접근은 이 질문의 자동 후속이 아니다.

답은 W30-Q1–Q4별 선택·한정으로 남기되, 실제 파일 접근·값 열람 GO는 승인 범위를 따로 지정한다. 새 승인 토큰이나 자동 gate는 만들지 않는다. 공유 기록은 `ledger_proposal.json`의 제안만이며 직접 적용하지 않는다.
