## 3. 설계

### 3-1. 단위 (1저자 Q9 (가) · 개정 1 Q15 (가) · 개정 3)
- 단위 = (c, 법칙, R) 12 개.
  - 한 단위 = 그 점의 모서리 arm 0 (+ SV 반사실 아래 · 필요하면 위끝) + origin 표본 arm 1 · 2 — 이 차례 (런 1 = corner · 런 2 = origin).
  - 한 단위는 한 기계에서 끝까지 돈다.  그래서 origin 퍼짐 비교 (arm 0 ↔ arm 1 · 2) 는 한 기계 안이다.
  - **시도 하나 = 단위 하나 (또는 넘침 점 하나 · 개정 3 · 3차 사전 공격 P3)** — 한 시도에 단위 · 점을 여럿 넣지 않는다 (CLI 단수 · 한 단위의 payload 가 다른 단위의 자원 멈춤까지 결과 뒤로 만드는 것을 막는다).
- **no-op = 단위가 아니다 (개정 3 · 질문 4)** — 사다리 단계 끝에서 같은 프로세스로 돈다 (§2-1).  그래서 no-op ↔ 그 법칙 사다리 확인 팔은 늘 같은 기계 · 같은 환경 (같은 프로세스) 이고, 개정 1 · 2 의 no-op 단위 · `NOOP_MACHINE_MISMATCH` · `NOOP_ENV_MISMATCH` 는 쓰지 않는다 (이름 폐기).
  - 이유 (3차 사전 공격 P2 다섯째 · 질문 4): 따로 도는 no-op 은 셸의 스레드 환경 변수 하나만 달라도 합치기에서 영영 멈출 수 있었다 (막다른 길) · 클라우드 VM 이 바뀌면 다시 맞출 길도 없었다.
  - 그 전 이유 (사전 공격 D2 · 실측 · 그대로 유효): 같은 코드 · 같은 스레드 수라도 BLAS 계산 경로 (`OPENBLAS_CORETYPE`) 만 바뀌면 σ 가 상대 1.3e-10 – 5.8e-10 다르다 → float 같음 대조는 한 프로세스 안에서만 뜻이 있다.
  - 사다리 요약에 환경 지문을 남긴다 (개정 2 · 단계끼리 대조 §3-3).
- 환경 지문 칸 = python · numpy · scipy 판 · BLAS 라이브러리 정보 (내부 API · 판 · 계산 경로) · `OPENBLAS_CORETYPE` · 스레드 수 환경 변수 · backend (cpu / cupy) · cupy · CUDA 판 · GPU 이름 · (개정 3 · P3) CPU 모델 · numpy SIMD 디스패치 (칸 이름 = 구현 때 정하는 꼴).
- (개정 3 · 3차 사전 공격 P3) 지금 사슬을 두 대로 돌릴 때 (사다리 P0 · P1 을 두 기계에 · 예측은 한 기계) 도 no-op 이 사다리 단계에 들어 있으므로 그대로 돈다 (§6 '2 대 · 지금 사슬' 줄 — 개정 2 의 §3-1 아래에서는 예측 기계의 no-op 이 다른 기계 사다리 값과 float 비교돼 못 돌았다).

### 3-2. 세 명령 (이름 · 인자는 구현 때 정하는 꼴)
1. 단위 실행 — `--stage predict --unit <단위> --machine <이름> --attempt <원장 항목>` (개정 3 = 단수).
   - **풀기 전에 대조 (개정 3 · 3차 사전 공격 P2 다섯째 · 질문 2)** — 허용 기계 · 원장 항목에 커밋한 환경 지문 = 지금 환경 · 계획 · 코드 · 침대 지문 · 원장 차례 (§3-5) 를 먼저 보고, 어긋나면 **풀이 없이 거부** = 결과 전 멈춤 + 거부 기록 (§3-5).  기계 이름 오타 · 셸 환경 변수 하나 다름 · 쓰던 출력 폴더 재사용이 여기서 걸린다 (그 시도는 결과 전이라 다시 할 수 있다).
   - 고른 단위의 늘 필요한 런만 돈다.  단위 폴더 요약에 출처 (§3-3) · 원장 항목 (§3-5) · (개정 3) 런마다 결과 (완주 / 멈춤 이름 · 원인) 를 남긴다.
   - **재실행 (개정 3 · 질문 1)** — `--resume <원 시도 항목>` = 같은 기계 · 같은 환경 지문에서 원 시도가 멈춘 런부터만 (조건 · 대조 = §3-5).
2. 합치기 — `--stage predict --merge <시도 폴더 전부…> --ledger <시도 원장> --out <예측 폴더>`.
   - 채택된 시도의 런으로 다시 계산한다 (같은 판정 함수 · fetch = 키로 찾기 · 한 번씩) — §3-4 · §3-5.
   - **대조 시점 = 그 단위가 처음 요청될 때 (개정 2)** — 다시 계산이 어떤 단위의 런을 처음 요청할 때 그 단위의 원장 채택 (§3-5) → 출처 (§3-3 · §3-4) → `read_run` 순으로 대조한다.  요청되지 않은 단위의 대조 결과는 `unused_runs` 에 기록만 한다 (멈춤 아님 · 판정 입력 아님).
   - **부분 채택 (개정 3 · 3차 사전 공격 P2 첫째)** — 단위의 채택 시도 (§3-5 · 재실행 사슬 포함) 가 런 k 에서 멈췄으면, 런 k 앞의 런은 그 시도의 것을 읽고, **그 멈춤은 다시 계산이 런 k 를 요청할 때 낸다** (한 기계 사슬이 그 런에서 멈추는 것과 같은 자리).
     - 그래서 사슬 순서상 앞선 다른 단위의 멈춤이 먼저 나면 그것이 결과다 — 예: U(c0,P0,R_j0) 의 origin 런 = NOT_COMPUTED · U(c1,P1,R_j_hi) 의 corner 런 = ARM_CONTRACT → 개정 2 규칙 = NOT_COMPUTED · 런 5 (단위 첫 요청에서 그 단위 결과를 냄) ↔ 한 기계 사슬 = STOPPED · ARM_CONTRACT · 런 14 (corner 루프가 origin 루프보다 먼저) → 개정 3 = 사슬과 같음 (탐침 `docs/reviews/rint2_rr_fix_evidence_20261023/preattack3/probes/lazy_merge_probe.py`).

- 합친 예측 폴더 요약에 `units` (채택 폴더 · 요약 sha256 · 기계 · 원장 항목) · `unused_runs` · 결정 기록 sha256 · 원장 sha256 · (개정 3) 모든 시도 폴더 목록 · 첫 합치기 환경 지문을 남긴다.  판정 · 다시 판정이 같은 대조를 다시 한다.

### 3-5. 시도 원장 (개정 1 · Q16 (가) · 사전 공격 D3 · 개정 2 · 개정 3)
- 원장 = 덧붙이기만 하는 파일 하나 (계획 봉인과 같은 리포 · 계획 sha256 에 묶임).  시도를 시작하기 **전에** 항목을 커밋한다: (단위 | 넘침 점 | 재실행) · 기계 · 시도 번호 (원장 안 순서) · 계획 · 코드 · 침대 · 환경 지문 · (재실행이면) 원 시도 번호 · 멈춘 런.
  - **(개정 3 · 3차 사전 공격 P3)** 원장은 실행 트리와 다른 체크아웃에 둔다 — 실행 트리는 핀 고정 (원장 커밋이 실행 트리의 HEAD 를 바꾸면 `code_key` 의 chain_head · runner_head 가 단위끼리 달라진다).
- **항목 하나 = 시도 폴더 하나 = 결과 줄 하나 (개정 2)** — 결과 줄 = 완주 / 멈춤 (원 사유 · 원인 · 결과 전 · 뒤) + 폴더 요약 sha256 (폴더 안 파일 전부의 상대 경로 · sha256 목록의 sha256).  같은 항목의 둘째 결과 줄 = 멈춤 `ATTEMPT_LEDGER_MISMATCH`.
- **같은 단위 시도는 차례로만 (개정 3 · 질문 3 · 3차 사전 공격 P2 셋째)** — 같은 단위 (또는 넘침 점) 의 항목 k+1 은 항목 k 의 결과 줄이 커밋된 뒤에만 커밋하고 시작한다.
  - 시도 폴더는 시작 때의 원장 커밋 sha 를 싣는다 (풀기 전 대조 §3-2).  합치기는 그 커밋에 자기 항목과 같은 단위 앞 항목들의 결과 줄이 모두 있는지 본다 (없으면 `ATTEMPT_ORDER_MISMATCH`).
  - 첫 · 끝 합치기의 원장은 바이트 접두 관계여야 한다 (항목 줄 지우기 · 바꾸기 = `ATTEMPT_LEDGER_MISMATCH` · 3차 사전 공격 P3).
  - 이유: 원장 순서 ≠ 시작 순서이고 동시 시도를 허용하면, 뒤 항목을 먼저 돌려 결과를 본 뒤 앞 항목을 일부러 결과 전 멈춤으로 만들어 (예: 금지 환경 변수) 뒤 항목을 채택시키는 길 · 마음에 안 들면 앞 항목을 정상으로 돌려 앞 항목을 채택시키는 길이 열린다 — 파일 편집 없이.
- **시도 폴더는 모두 보존한다 (개정 2)** — 합치기는 단위마다 **원장의 시도 전부와 그 폴더 전부**를 받는다:
  - 원장에 없는 폴더 · 폴더 요약 sha ≠ 결과 줄 = 멈춤 `ATTEMPT_LEDGER_MISMATCH`.
  - **폴더 없는 원장 시도 (개정 3 · 질문 2)** — **풀기 전 거부 기록이 있으면 결과 전** (유일한 예외): 실행이 풀기 전 대조 (§3-2) 에서 거부하면 거부 기록 (항목 · 사유 · 시각 · 원장 커밋 sha) 을 시도 폴더에 쓰고, 시도 폴더를 만들 수 없으면 (예: 이미 있는 폴더) 그 옆의 정해진 자리 (`<시도 폴더>.rejected.json` 꼴 · 이름 = 구현 때) 에 쓴다.  그 밖의 폴더 없는 시도 (기계 · 디스크 소실 · 기록 없는 사라짐) = **엄격 — 결과 뒤** (그 단위 재시도 불가 → 예측 STOPPED → 이 등록의 주 판정 = 판정 없음 · 비용).
  - **결과 전 · 뒤 판정 = 폴더 + 원인 (개정 2 · 개정 3 · 질문 6 · 3차 사전 공격 P2 둘째)** — 결과 전 = 그 시도 폴더 (그 안 `.unchecked/` 포함) 에 팔 payload (`p2_*.json`) 가 하나도 없고, **러너 (사슬 부모 프로세스) 가 쓴 멈춤 기록의 원인이 결과 전 목록**일 때만:
    - 결과 전 목록 = 풀기 전 대조 거부 (관문 · 환경 · 계획 · 코드 · 침대 · 원장 차례) · 자식 신호 9 · CUDA 메모리 부족 (자원).
    - 결과 뒤 = 검사 거부 (`--check-arm`) · 불수렴 · 수치 · 물리 (Q4 의 *"불수렴 = 결과 뒤"* 그대로) · 팔 payload 가 하나라도 있는 모든 꼴 (개정 2 · 보수 쪽).
    - **러너가 바뀐다 (구현 = 묶음 C)** — ⓐ 자식이 끝난 원인 (신호 · CUDA OOM 표지 · 검사 거부 사유 · 불수렴) 을 멈춤 기록에 싣는다 ⓑ 검사에 실패한 payload 를 킷 런 폴더 (`$RUN`) 에 남기지 않고 시도 폴더 안 `.unchecked/` 로 옮긴다 — 지금 `scripts/sdcp_gain_vox015_8arm.sh` 는 *"옮기지 않는다 … 원본을 남겨 둔다"* (킷 런 폴더 · 시도 폴더 밖) 라 폴더 판정이 그 payload 를 못 봤다 (3차 사전 공격 P2 둘째 · 메인 재확인).
