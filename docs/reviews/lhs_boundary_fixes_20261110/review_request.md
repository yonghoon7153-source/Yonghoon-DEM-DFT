# L-2 봉인 밖 경계 보완 — 독립 검토 요청

대상은 이 문서와 같은 고정 후보의 `g2_network_reread.py`, `lhs_release_build.py`, `single.html` 및 새 시험 세 파일이다. 바탕은 `6add88f264d2c651b467f3906e755824ed6e40ad`다. 일일 묶음의 핀·파일 목록과 원시 증거를 먼저 대조한다. 발송은 1저자가 한다.

| 질문 | 확인할 것 | 확대하지 않는 범위 |
|---|---|---|
| Q1 K05 | 지정 소비자의 일반 예외가 현재 case/run_id의 실패 기록·rc1로 이어지는지, 다음 케이스와 정상 입력을 보존하는지 | 모든 CLI 오류·파일 쓰기 실패·중단/복구 자격 아님 |
| Q2 K08 | OK/MBCB의 f·τ²·τ를 각각 검사하고 기존 disconnected/미계산/모형 한계의 공란 의미를 유지하는지 | 기존 fresh build의 원천 재독 부재를 주장하지 않음 |

작성측은 24/24 및 유효 보호조건 대조6개를 확인했다. 독립 판정은 아직 받지 않았다. AST로 선택한 함수와 합성 소비자, 실제 Jinja의 header 조각만 실행했으며 전체 모듈/웹앱/게이트를 실행하지 않았다. 실제 `summarize`는 실패 check 수를 더하므로 시험의 합성 집계와 rc 의미가 일치함을 소스에서 확인했다. 이 대조를 전체 CLI 통합 시험으로 부르지 않는다.

이번에 한정 종결 근거를 요청하는 것은 K05·K08·S05의 위 경계다. 현재 실행 신원, 실제 값, 현장/운영 자격, 봉인 항목 및 전체 HOLD는 닫지 않는다. D5 문서의 깨진 파일명 참조 하나도 별도로 바로잡았다.
