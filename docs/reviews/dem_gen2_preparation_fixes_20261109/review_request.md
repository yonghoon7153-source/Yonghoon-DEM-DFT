# G2PREP-01–04 수정 후보 한정 재확인 요청

발송은 1저자다. 새 후보 핀은 전달 ZIP의 SOURCE_PIN/PIN_MAP을 따르며, 비교 원 후보는 `9241933b983605e3210753369a7cae5d6fc43432`다. 최신 B 위의 동일 blob 사본 `08fb8b178eae3010aa6658b571c83a0bc8eef12d`와 새 수정 diff·시험 원증거·수령 원 ZIP을 함께 제공한다. source pin 없는 이동 가지나 과거 검토의 PASS를 새 후보 PASS로 대체하지 않는다.

이번 질문은 원 검토의 G2PREP-01/02(P2), G2PREP-03/04(P3)가 고정 후보의 오프라인 구현에서 막혔는가다. 이미 수용한 문서/null/비활성 경계는 보존 여부를 확인하며, 실제 T5/T11/T12 완료·실제 호스트/DEM 실행·운영 재봉인·원장 종결은 요청하지 않는다.

1. **G2PREP-01:** 생성 문자열에 raw signed 반력이 남고, 명시적 극성의 정규화 압축 힘과 따로 freeze/capture되는가. ±target·±0.8target 두 극성 짝에서 정상은 보존하고 반대 부호는 제어 사용 전에 거부되는가. abs로 양쪽을 합치거나 합성 극성을 실제 바이너리 자격으로 표시하지 않았는가.
2. **G2PREP-02:** 원 `a=1/256, delay=512, tolerance=1/128, budget=10000` 및 작은 `a=1/16, delay=32, tolerance=1/8, budget=1000` 반례가 최초 window hit로 수렴 종료하지 않는가. 전체 예산/발산과 종료 연속창·pending queue를 실제 반환 계약에서 확인하는가. 정상 무지연과 안정적인 지연 예는 보존하고, 결과를 유한 예산의 합성 관찰로 한정하는가.
3. **G2PREP-03:** 원 `r=100000000,s=1,d=100000000` 및 반경 교환의 기하 원판 면적이 독립 고정밀/해석 오라클과 맞는가. 일반 크기, 양의 스케일 변환, 접선/포함 분기, overflow/양성 underflow가 대칭적 계산 또는 명시 거부로 처리되는가. 수치 조건과 실제 물리 접촉 허용폭을 섞지 않는가.
4. **G2PREP-04:** 원 `bottom=10^16-10, top=z=10^16, radius=1, max_surface_penetration=0` 및 원점 이동 대조가 같은 거부 판정인가. 상/하판, 양/음 큰 좌표, 기존 일반 크기 양성/음성을 보존하는가. 기존 허용폭을 늘리거나 입력 전에 잃은 float 정보를 복원했다고 하지 않는가.
5. 기존 생성기/자격 함수 양성·음성과 7단계 정지·판 신원·감쇠 분리·R-a S0·capture 순서를 보존했는가. 새 회귀 메서드와 원 독립 탐침 관측 수를 합산하지 않고, 작성자의 before/after 원증거와 이번 독립 재현을 구분하는가.

첨부 원 검토 ZIP은 수령 바이트 감사 PASS(루트189/package104/중첩104, 고정17)다. 이 감사는 첨부 probe의 실행 또는 새 독립 판정이 아니었다. 외부 원증거의 경로·주소를 리포에 반입하지 않는다. 원 검토의 발견 여부와 최종 후보의 판정·한계는 별도로 남겨 달라.

**전체 HOLD·과학 등록 T5/T11 NOT_RUN·T12 NOT_RUN·physical_ready=false.** 모의 단위 시험이 있다는 사실과 완결된 등록 자격은 다르다. 별도 저자 결정·실제 값 열람·현장/운영 자격 또는 실행 GO를 발급하는 요청이 아니다.
