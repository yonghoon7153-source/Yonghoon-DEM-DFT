# ADR 0011 — 데이터는 git 이 아니라 중추 서버 한 대에 둔다

- 상태: 채택 (2026-08-21)
- 관련: `tools/bml`, `tools/backup.py`, `apps/api/app/routers/exports.py`,
  ADR 0001, ADR 0003

## 맥락

두 번째 노트북에서 워크벤치를 띄웠더니 라이브러리가 비어 있었다. `data/` 는
git 에 올리지 않으므로 당연한 결과지만, 쓰는 사람 입장에서는 "내 데이터가
안 따라왔다" 다. 자연스럽게 나오는 요구는 **"`bml` 이 알아서 push 해 주면
안 되나"** 인데, 그 길은 막혀 있다.

- `.wrd` 하나가 20 MB 다. git 은 파일의 **모든 판본**을 영구히 보관하므로
  올린 것을 지워도 저장소는 줄지 않는다. GitHub 은 100 MB 파일을 거부하고
  저장소는 몇 GB 에서 경고가 뜬다. 한 학기치 실험이면 넘긴다.
- 되돌릴 수도 없다. 한 번 커밋된 큰 파일을 빼려면 히스토리를 다시 써야 하는데,
  이 저장소는 **push 된 히스토리를 절대 rewrite 하지 않는다** (CLAUDE.md §2).
- 무엇보다, 동기화가 필요한 상황 자체가 **각자 자기 데이터를 들고 있을 때만**
  생긴다.

## 결정

**인스턴스를 하나만 둔다.** 한 대가 워크벤치를 띄우고, 나머지 사람은 아무것도
설치하지 않고 브라우저로 그 주소를 연다.

그러면 동기화라는 단계가 사라진다. A 가 올린 `.wrd` 는 이미 그 서버의 디스크에
있고, B 는 같은 데이터베이스를 보고 있다. push 도 pull 도 없다 — git 은 **코드**
를 옮기는 도구로 남고, 데이터는 애초에 옮길 일이 없어진다.

설정은 셋뿐이고 전부 이미 있던 것이다.

| 무엇 | 값 | 왜 |
|---|---|---|
| `WORKBENCH_DATA` | 외장 드라이브 경로 | 원본과 DB 가 노트북 수명과 무관해진다 |
| `WORKBENCH_HOST` | `0.0.0.0` | 같은 네트워크의 다른 기계가 접속할 수 있다 |
| `.bml/env` | 위 둘을 적어 두는 곳 | git 에 올라가지 않으므로 **그 한 대에만** 남는다 |

이 결정이 요구하는 세 가지를 함께 넣었다.

1. **원본을 되받을 수 있어야 한다.** `GET /api/export/runs/{id}/original.wrd`
   가 올린 바이트를 그대로 돌려준다. 되받을 수 없으면 "워크벤치에 올려" 가
   편도 여행이고, 아무도 유일본을 그렇게 맡기지 않는다.
2. **드라이브가 빠진 채로 뜨면 안 된다.** `WORKBENCH_DATA` 가 가리키는 폴더가
   없으면 `bml` 은 시작을 거부한다. 그냥 두면 그 자리에 빈 `data/` 가 새로
   생기고, 화면에는 셀이 하나도 없는 멀쩡한 워크벤치가 뜬다 — 사람은 데이터가
   날아갔다고 읽고, 그 상태로 올린 파일은 나중에 드라이브를 꽂으면 보이지 않는
   곳에 남는다.
3. **백업이 push 를 대신한다.** `bml backup <폴더>` 가 다시 만들 수 없는 것만
   복사한다: 원본 `.wrd` 와 데이터베이스. 파싱 캐시(`data/runs/`)는 원본에서
   다시 만들어지므로 뺀다 (ADR 0003) — 용량의 대부분이라, 같이 복사하면 백업이
   몇 배 느려지고 얻는 것이 없다.

## 결과

- 데이터가 한 벌이므로 **누가 무엇을 올렸는지 다툴 일이 없다.** 프리셋·그룹·
  질량이 전부 한 곳에 있다.
- **화면이 스스로 따라온다.** 서버가 "무엇인가 바뀌었다" 를 번호 하나로 흘려
  보내고(`/api/events`, SSE), 각 화면은 자기가 보여 주는 것만 다시 읽는다.
  무엇이 바뀌었는지는 보내지 않는다 — 그러면 엔드포인트마다 자기 변화를 설명해야
  하고, 새 편집 종류가 생겼을 때 한 군데를 빠뜨리면 **그 종류만** 남의 화면에서
  안 보인다. 가장 알아차리기 어려운 낡음이다. 대가는 편집 하나에 필요한 것보다
  조금 더 읽는 것이고, 이 규모에서는 없는 비용이다.
- 쓴 사람은 자기 공지를 무시한다(`X-Workbench-Revision`). 저장할 때마다 방금
  보낸 것을 도로 읽어 오지 않는다.
- 타이핑 중인 칸은 갱신이 건드리지 않는다. 남의 편집이 들어와도 입력하던 질량과
  조성은 남는다 — 반쯤 친 값이 소리 없이 사라지면 저장한 줄 알고 넘어가고, 그
  셀의 모든 mAh/g 가 옛 질량으로 남는다.
- 대가: **그 한 대가 꺼져 있으면 아무도 못 쓴다.** 실험실 PC 처럼 늘 켜 있는
  기계를 쓰는 것이 맞고, 그래서 백업이 선택이 아니다.
- 외부 네트워크에서 접속하려면 별도 장치가 필요하다. 이 앱에는 **로그인이
  없다** — 주소를 아는 사람은 다 볼 수 있고 지울 수도 있다. 공유기 포트를 여는
  것은 하지 말고, Tailscale 같은 사설 네트워크로 묶는다.

## 대안

**Git LFS**: 큰 파일을 git 처럼 다룰 수 있다. 무료 한도가 1 GB / 월이라 `.wrd`
20 MB 기준 50개면 끝이고, 결국 유료 저장소를 사는 것이 된다. 그렇게 살 것이면
파일 서버를 사는 편이 낫다 — 그게 이 결정이다.

**각자 인스턴스 + 자동 동기화**: 오프라인에서도 쓸 수 있다는 장점이 분명하다.
대신 같은 셀의 질량을 두 사람이 다르게 고쳤을 때 무엇이 이기는지를 정해야 하고,
그 규칙이 틀리면 **조용히** 틀린다 — 이 저장소가 가장 피하려는 종류의 실패다.
필요해지면 그때 붙이되, `.wrd` 는 내용 주소(sha256)라 합치기가 안전하다는 점이
출발점이 된다.
