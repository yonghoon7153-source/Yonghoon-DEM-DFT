UC(373359)는 6코어에서 1시간 18분 15초 후 완료했다. 스케줄러 종료값 0:0, 실행기 rc 0, 정지 대조 control_ok 및 technical_ok는 모두 참이다. NO_CROSSING으로 회복률 산출값은 없다. 로컬 부분 반환 ZIP의 SHA256은 0d671b30ff768fe6bace1176bd30cdee5c46c1e5ba4d9b75d39bc18cf51a49c9이며 내부 해시 11/11과 UC의 시도·판정 일치를 확인했다. 같은 시점에 UB 368469·UT 373358은 실행 중이었다.

1저자는 11월 25일 UC가 비운 슬롯에서 UVa 한 팔을 먼저 계산하도록 승인했다. 원 RJ 368315에서 복원한 S0·원 UVa 덱·NP6·5일 한도를 사용한다. 이전 덱과 같이 판 속도는 기본의 절반, 유지 시간은 두 배다. 제출 직전 사용자 전체 실행·대기 코어에 6을 더해 60 이내인지 원 컨트롤러로 확인한다. 07:17 화면의 구성은 제출 뒤 58코어에 해당한다.

UVa 전용 일시 예약은 기존 감시가 읽는 팔별 보류 파일을 이용한다. 별도 제출 기록과 이 파일을 하드링크로 결속한다. 기존 잡이 먼저 제출됐으면 그 번호를 사용하고, UB가 이미 완료 경로에 들어갔으면 기존 감시에 맡긴다. UC 판독과 원본 복원 신원을 확인한 뒤 단 한 번 제출한다. Slurm 번호를 받은 첫 구간만 기존 시도 목록에 원자적으로 공개한다. 일시 예약 해제는 자신이 만든 파일로 한정한다. 작업과 재개·최종 판독은 기존 러너와 감시가 담당한다. 제출 응답이 모호하면 예약을 보존하고 STATUS로 확인한다. 기존 UB 작업 경로는 출처 확인에만 읽는다.

최종적으로 UB와 UT의 유효 회복률 차가 0.10 %p 이내면 UVa를 속도 대조로 쓰고 초과하면 보조로 둔다. UVb는 별도 GO다. 이번 변경은 계산 순서에 한정된다. 현장 제출은 1저자가 WSL 블록에서 실행한다.
