# C4-ENV 새 환경 준비 — 비활성 승인 초안

2026-10-13. **DRAFT / approved=false / usable=false. 이 문서 자체는 설치·자기점검·C4 착수 권한이 아니다.**

목적은 사라진 이전 실행 환경을 현재 interpreter에서 새 환경 세대로 준비하고 차이를 명시하는 것이다. 과거 환경과 비트 동일하다고 가정하지 않는다. 이전 C6 봉인·P0/C5 기록은 그대로 둔다.

## 승인 전에 실행 측이 채울 고정 표

다음 항목이 비어 있으면 아래 채택 문구는 활성화할 수 없다.

- 저장소 작업 HEAD와 보호할 원본 목록.
- 실제 interpreter 절대 경로·버전·빌드·파일 식별. 제출된 3.11.17과 다르면 재확인.
- 새 venv, 다운로드/캐시, tmp, 새 봉인, 기록의 **정확한 경로 목록**. 존재하는 경로의 덮어쓰기나 다른 이름 fallback 금지. 저장소의 새 봉인은 예컨대 `bms-balancing/reil_c6_rebuild_20261013/`를 제안하되 실제 존재 여부를 먼저 확인.
- 기존 과학 lock의 전체 30개 배포판 이름/판과 설치용 고정 목록의 해시. 임의 업그레이드·추가 패키지·소스 빌드로 대체하지 않음.
- 설치 원천, 허용 네트워크 범위 또는 보존된 설치 아티팩트, 정확 설치 argv와 수신 아티팩트 기록 방법. 다운로드 바이트 식별과 설치 후 RECORD 대조를 구분.
- 별도 시험 도구 경로와 배포판·판·해시. 기존 시험 도구를 식별해 재사용할지, 별도 위치에 새로 준비할지 명시. 새 준비를 택하면 패키지/설치/디스크를 이 승인에 포함하도록 먼저 적음. 과학 30개 환경에 pytest를 임의로 추가하지 않음.
- `reil_c6_profile.py`와 호출 의존 소스의 고정 SHA, emit/check 각각 정확한 argv·cwd.
- 허용 old→new 차이 목록과 이전값. Python 판/빌드 변화는 명시하되 libc/BLAS/옵션/배열/RECORD의 미상 차이를 포괄 승인하지 않음.
- 단일 시간 원점, 단계별 배정, 디스크 합산 범위·관측 방법·실패 시 소유 정리/기록 경계.

## 제안된 사용자 채택 문구

> 위 고정 표와 이 문서의 범위로 C4-ENV 새 환경 준비 1건만 승인합니다. 기존 환경의 동일 복원이라고 표현하지 않습니다.
>
> 지정된 새 경로에서 확인된 interpreter에 기존 과학 lock의 전체 30개 배포판을 같은 판으로 준비합니다. 사전에 명시된 별도 시험 도구 범위만 포함합니다. 기존 환경·코드·봉인·C5 원문을 덮어쓰거나 삭제하지 않습니다.
>
> **emit 1회와 check 1회만** 허용합니다. check 내부의 emit을 포함하여 **합성 COBYQA 최적화 총 2회, 전체 Sobol 생성 경로 총 2회**임을 수용합니다. 여기에는 seed/rng 비교 생성과 check의 임시 파일 쓰기도 포함됩니다. pytest·변이 시험·C5 재측정은 포함하지 않습니다.
>
> 전체 1,800초·디스크 2,000,000,000 B를 한도로 합니다. venv·다운로드/캐시·별도 시험 도구·봉인·임시 파일·기록의 새 파일을 합산합니다. 이 수치는 메모리 한도가 아니며 설치 완료 보증도 아닙니다. 미측정은 0 또는 PASS로 바꾸지 않습니다.
>
> 설치 실패·배포판 집합/판 불일치·기존 경로 충돌·예산 초과·예상 밖 차이는 최초 오류와 확보된 기록을 남기고 중지합니다. 임의 재시도·패키지 판 완화·다른 interpreter·새 경로 fallback·코드 수정은 하지 않습니다.
>
> old→new 차이표와 새 MANIFEST를 제출하고 멈춥니다. 새 emit/check 성공만으로 새 봉인을 자동 채택하지 않습니다. 차이 검토 수용과 정정된 C4-0 범위 확인 뒤 그 봉인을 C4 환경으로 명시 연결합니다.
>
> REIL 원자료·pickle·노트북 개봉, 실측 자료 맞춤, E3a/H 실행, COMSOL, 기존 사본 정리는 승인하지 않습니다.

## 결과 제출·수용 조건

1. 승인 원문/고정 표·명령·cwd·원점·시작/끝 HEAD·작업트리 파일 목록을 보존한다.
2. 과학 배포판 전체 집합/판, Python 판·빌드, 플랫폼/libc, BLAS/LAPACK, RECORD·파일 대조·충돌 표를 old/new로 나란히 적는다.
3. COBYQA 옵션 8개 및 구현 파일 4개, 기존 Sobol 6개 배열의 .npy SHA와 raw payload SHA를 각각 대조한다. 허용하지 않은 차이는 성공으로 채택하지 않는다.
4. 새 봉인과 기존 봉인을 각각 독립 식별한다. 새 lock을 과거 C5가 사용했다고 소급 기록하지 않는다.
5. 시간·디스크·최종 기록의 실제 관측 경계를 적는다. 내부 snapshot과 외부 반환 wall time을 더하지 않는다.
6. 승인된 차이 이외의 미결이 없고 새 봉인을 검토 수용한 뒤, C4 실행기의 봉인 경로와 기대 MANIFEST를 고정한다. 옛 기본 경로의 암묵적 사용 금지.
7. 수용된 check 1회를 C4 전체 환경 자기점검 1회분으로 인정하는 안을 권고한다. C4-0의 남은 고정 배열 봉인·합성 시험·건조는 별도 횟수/시간 장부로 이어진다. 환경이 다시 달라지면 무효인 결속을 유지하지 않는다.

## 이후 컨테이너 교체 규칙 제안

- 이미 승인된 **동일 아티팩트**를 동일 프로필로 복원하는 범위는 경로·횟수·예산·identity 대조·실패 중지를 고정해 사전 승인할 수 있다.
- interpreter/빌드/배포판/미설명 RECORD가 달라지는 **새 환경 세대**는 별도 차이와 채택 승인을 받는다.
- 매번 설치 후 새 emit/check를 만드는 것만으로 “동일 환경 복원” 처리하지 않는다.
- 이 제안은 미래 설치나 컨테이너 구축을 지금 포괄 승인하지 않는다.
