> 전에는 사실로 쓰지 않는다.

## §0 틀 — 목적별 분리 환경 (PyBaMM 라운드와 같은 방식)

PyBaMM 환경 고정 라운드 (degradation-degeneracy 원장 §135) 는 환경을 목적별로 나눴다: C = 지금 검증 환경의 기록 대조 · B = 역사 정본의
기록 · D = 새 생산 전에 봉인한 profile 에 결속. REIL 실행 (P0 · 비용 측정 · 맞춤) 은 **새 계산의 생산**이므로 D 쪽 틀에 가깝다 —

- 실행 승인 **전에** 프로필 파일 (아래 §1 의 축을 정확한 판으로 채운 것) 을 봉인하고 sha256 을 승인 문서에 적는다.
- 실행 기록에는 실제 환경 (판 · 옵션 · 시작점 배열 sha256) 을 남겨 봉인 프로필과 대조한다 — 기록이 사전 결정을 대신하지 않는다 (부속 A §3-1).
- 다르면 실행하지 않는다 (부속 A §3-1 의 fail-closed: 옵션 이름 · 의미가 다르면 표를 새 등록으로 고친다).

PyBaMM 쪽 C lock (`degradation-degeneracy/requirements-validation-C.lock.txt`) 은 **기록 대조 전용**이라 이 결속을 대신하지 않는다.

## §2 부속 A §3-1 옵션 — 고정 판에서 대조할 목록

| 옵션 | 사전 고정 값 (부속 A) | 고정 판에서 확인할 것 |
|---|---|---|
| `maxfev` | 2000 | 이름이 있는가 · 함수 평가 상한의 뜻인가 |
| `maxiter` | 4000 | 이름 · 뜻 (반복 상한) |
| `f_target` | −∞ | 이름 · 목표값 조기 종료의 뜻 · −∞ 를 받는가 |
| `feasibility_tol` | 1e-12 | 이름 · 제약 위반 허용의 뜻 (증인 수용 1e-10 과 독립 — 부속 A §3-1) |
| `scale` | True | 이름 · bounds 로 [−1, 1] 정규화의 뜻 |
| `initial_tr_radius` | 1.0 | 이름 · 정규화 좌표 기준인가 |
| `final_tr_radius` | 1e-6 | 이름 · 정규화 좌표 기준인가 |
| `disp` | False | 이름 |

- Sobol: `scipy.stats.qmc.Sobol(d, scramble=True, <seed>)` — seed 인자 이름과 생성 배열이 판에 따라 다를 수 있다 (부속 A §3-1). 그래서
  **모든 시작점 배열을 맞춤 전에 만들어 sha256 으로 봉인**하고 (부속 A §3-1 · 부속 B §2-1), 프로필에는 "배열을 만든 판" 을 함께 적는다.
- 실행 기록에는 solver 가 **실제로 받은** 옵션을 남겨 위 표와 대조한다 (부속 A §3-1).

| 후보 | 장점 | 단점 · 확인할 것 |

범위까지 승인 문서에) → N3 (P0 승인 요청).

## §5 이 문서가 하지 않는 것

설치 · 버전 실측 · import · 옵션 introspection · 시작점 배열 생성 · 자료 개봉 · 실행 · 비용 측정 · 맞춤. 판 번호를 고르지 않는다.
REIL 원자료 · 논문 (N1 · C1-core) 과 섞지 않는다. 게이트 차수 밖 문서다.
