# v2.0 — D2 개발 소비자 재검토 반영: 생성기 문법만 · 접촉 제외 거부 · 파일 바이트 해시 (2026-11-03)

> Codex 10-27 재검토 (HOLD · MXD2R-01–03) 의 반례를 시험으로 먼저 옮기고, 1저자 11-02 비준 (Q1–Q3 (가)) 대로 세 개발 소비자를 고쳤다. 개발 검사 PASS 는 여전히 실행·코호트·발사 인증이 아니며, Codex 재확인 전에는 MXD2-01 개발 소비자 하위 범위가 닫혔다고 하지 않는다.

## 쉬운 판

v1.8 의 개발 검사는 명령의 이름과 순서만 보고 옵션의 뜻은 보지 않았다. 그래서 두 덱에 같은 변경 — run 에 `upto` 붙이기, timestep 을 맨 뒤로 옮기기, 삽입을 9000000 step 에 시작하기, 앞판만 0.1 초에 한 바퀴 돌리기, SE–SE 접촉을 이웃 목록에서 빼기 — 을 넣어도 통과했다. 이제 개발 덱은 **생성기가 쓰는 꼴**만 받고, 모르는 뜻은 이유를 적어 거부한다.

재료 fix (영률 · 포아송 · 반발 · 마찰 · 구름 마찰 · 점착 행렬 · 특성 속도) 도 생성기 목록과 정확히 같아야 하고, 접촉 법칙보다 먼저 정의돼야 한다. 마찰 행렬을 지우거나 값을 바꾼 덱은 거부한다.

덱 해시는 이제 **실제 파일 바이트**로 잰다. 예전에는 텍스트로 읽어 줄바꿈이 바뀐 뒤에 해시를 쟀다. 생성기는 LF 만 쓰므로 CRLF 덱은 그 이유를 적어 거부한다.
