# ADR 0030 — 이름이 막힌 기계에서는 hosts 를 고치지 말고 중계기를 띄운다

- 상태: 채택 (2026-08-26)
- 관련: ADR 0011(중추 서버 하나), ADR 0014(터널과 공유 암호),
  `tools/bml_relay.py`, `tools/bml` 의 `cmd_only`

## 맥락

한 사람의 기계에서 워크벤치가 계속 안 열렸다. 실측으로 갈라 본 결과 막힌 것은
**이름 하나**였다:

- 랩 망의 DNS 가 터널 도메인(`*.lhr.life`)을 거른다.
- 그 기계에서는 공용 DNS 세 곳(1.1.1.1 · 8.8.8.8 · 9.9.9.9)도 다 막혀 있다 —
  스스로 IP 를 구할 길이 없다.
- 그런데 **IP 를 손에 쥐여 주면 HTTPS 는 그대로 간다.** `curl --resolve` 로
  200 을 봤다. 길은 멀쩡하고 이름만 안 풀린다.

그래서 `bmlonly` 는 IP 를 받아 `/etc/hosts` 에 이름표를 박았다. 그 방식이 이
랩에서 특히 나쁜 이유가 셋인데, 셋 다 실측으로 부딪혔다:

1. **브라우저가 Windows 에 있다.** 이 명령이 고치는 것은 WSL 의 `/etc/hosts`
   이고 크롬은 그 파일을 아예 안 본다. `curl` 은 WSL 안이라 200 이 나오고
   크롬은 `ERR_CONNECTION_CLOSED` 를 낸다 — 화면 둘이 정반대를 말한다.
   그래서 관리자 PowerShell 로 Windows 쪽에도 같은 줄을 박아야 했다.
2. **WSL 은 켤 때마다 `/etc/hosts` 를 다시 만든다.** 재부팅하면 사라진다.
3. **터널 주소는 열 때마다 바뀐다.** 등록한 키를 써도 그렇다 — 지문이 같은데
   주소가 `653712d5fb509b` → `d1c47a7b4af191` 로 바뀌는 것을 확인했다.
   그러니 1·2 를 주소가 바뀔 때마다 처음부터 다시 한다.

셋을 합치면 "주소 하나 바뀔 때마다 관리자 창을 연다" 가 된다. 그게 실제 비용
이었다.

## 결정

### `/etc/hosts` 대신 이 기계 안에서만 도는 중계기를 띄운다

`bmlonly <주소> <IP>` 는 이제 OS 파일을 안 건드린다. 대신 `127.0.0.1:5013` 에
평문 HTTP 를 열고, 받은 요청을 터널 엣지의 **IP** 로 다시 보낸다 — TLS 의 SNI
와 HTTP 의 `Host` 만 원래 터널 이름으로 적어서. 그 둘이 곧 엣지가 "어느
터널이냐" 를 가르는 값이라, 이름을 안 물어보고도 정확히 같은 곳에 닿는다.

브라우저는 `127.0.0.1` 만 본다. 이름 풀이가 **아예 일어나지 않으므로** 위의
셋이 통째로 사라진다:

- sudo 도 관리자 PowerShell 도 없다. OS 파일을 안 고치니까.
- WSL 은 localhost 를 Windows 와 나눠 쓰므로 크롬이 같은 주소로 그냥 열린다.
- 재부팅하면 중계기만 죽는다. 대상을 `.bml/relay.target` 에 적어 두고 다음
  `bml` 이 되살린다.
- 주소가 바뀌면 `bmlonly <새 주소> <그 IP>` 한 줄. sudo 없음, 관리자 창 없음.

### 인증서는 검증한다

`server_hostname=<터널 이름>` 으로 붙는다. **IP 로 붙되 이름을 증명하게 하는
것**이라, 검증을 끄는 것과 다르다. 끄는 길은 코드에 두지 않는다 — 한 번 두면
"안 되면 그걸로" 가 되고, 그 기계는 이름이 막힌 망 안에 있다.

### 127.0.0.1 에만 연다

`0.0.0.0` 에 열면 같은 망의 아무나 우리 암호 화면까지 온다. 이 기계는 그런
문을 열어 달라고 한 적이 없다.

### 포트는 5003 이 아니라 5013

이 기계가 나중에 제 서버를 띄울 수도 있다. 둘이 같은 포트를 다투면 "왜 남의
데이터가 보이지" 가 된다.

### 표준 라이브러리만 쓴다

이 기계는 브라우저 노릇만 할 수도 있고 (ADR 0011), 실제로 `python3-venv` 가
없어서 한 번 막힌 적이 있다. 의존성을 만들면 그 자체가 새 걸림돌이 된다.
`python3` 조차 없으면 예전 `/etc/hosts` 길로 되돌아간다.

## 결과

`bmlonly` 의 이름과 뜻은 그대로다 — "이 기계의 DNS 가 막힐 때만 쓰는 길".
바뀐 것은 그 안의 방법뿐이라, 화면 곳곳에 이미 적혀 있던 안내가 그대로 맞다.

**남는 것**: 주소가 바뀌면 여전히 사람이 새 주소와 IP 를 한 번 받아 와야 한다.
`bml share` 가 그 두 값을 붙여 넣을 수 있는 한 줄로 찍어 주므로 왕복 한 번이다.
자동으로 받아 오게 하려면 주소를 어딘가 올려야 하는데, **이 저장소는 공개라
거기에 올리지 않는다** — 암호가 걸려 있어도 주소가 인터넷에 남는다. 주소를
아예 안 바뀌게 하려면 우리 도메인이 필요하고, 그것은 별개의 결정이다.
