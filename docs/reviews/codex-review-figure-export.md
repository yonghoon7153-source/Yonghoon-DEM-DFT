# Codex 리뷰 과제 — 그림을 파일로 내보낸다, 그리고 값이 아닌 축

[codex-session-bootstrap.md](codex-session-bootstrap.md) 로 세션을 연 뒤 아래
"붙여넣는 프롬프트" 를 그대로 붙여넣는다.

주제는 **하나**다: 화면의 그림이 저장·인쇄물로 나갈 때 무엇이 보존되고 무엇이
바뀌는가. 새로 생긴 길 셋이 모두 "화면에서는 맞는데 파일에서는 다를 수 있는"
자리다.

1. **PNG 저장** — 캡처가 아니라 **3 배로 다시 그린다.** 옵션 한 벌을 배수를
   받는 함수로 바꿨으므로, 화면과 저장이 어긋날 여지가 새로 생겼다.
2. **이격 보기** — 곡선을 위로 옮겨 그린다. **세로 눈금이 값이 아니게 된다.**
   §0.4(모르면 모른다고 적는다) 와 맞닿는다.
3. **가로축 넷 · Ω·cm²** — 추세와 표가 이제 면적으로 나눈 수를 낸다.
   **Ω 인 파라미터만** 나눠야 하는데, 스캔에는 서버가 단위를 안 실어 보낸다.

## 1. PNG 저장 — 다시 그리는 것의 대가

화면 캔버스는 CSS 크기 그대로라 키우면 뭉갠다. 그래서 **같은 옵션으로 3 배
캔버스에 새로 그린다** — 글꼴·선 굵기·눈금 간격·글자 띠·표시선 바탕판까지
같은 배로. `uPlot.pxRatio` 로는 안 된다: 그것은 읽기용 사본이라 값을 넣어도
내부 변수가 안 바뀐다 (uPlot 1.6.32, `setPxRatio` 가 모듈 지역 변수만 고친다).

**눈금은 지금 보고 있는 것을 그대로 박는다** (`frozen`) — 확대해 둔 화면은
확대한 그대로 저장된다. 저장용에는 커서·훅을 뗀다: `setCursor`/`setScale` 훅이
`setState` 를 부르면 저장하는 동안 화면 그래프가 다시 그려지며 확대가 풀린다.

### 실제로 있었던 결함 (이미 고쳤다)

`space`(눈금 사이 최소 픽셀)와 `size`(글자 띠 두께)를 안 키워서 저장한 그림의
눈금이 세 배로 촘촘했다. 진짜 크롬(Playwright)에서 uPlot 이 고른 눈금을 세서
고쳤다:

| 구간 | 화면 | 고치기 전(배3) | 지금 (x2·y1.5) | x2·y2 |
|---|---|---|---|---|
| 사이클 1~43 | 8 / 7 | 21 / 20 | 4 / 4 | 4 / 4 |
| 0~225 mAh/g | 10 / 5 | 23 / 23 | 5 / 5 | 5 / **2** |
| 0~1.5 mAh/cm² | 8 / 4 | 31 / 18 | 4 / 4 | 4 / 4 |

`PNG_TICK_ROOM = {x: 2, y: 1.5}` 로 화면보다 **한 번 더 성기게** 한다 — 화면은
커서를 올려 값을 읽지만 종이에는 커서가 없다. 가로를 더 성기게 하는 것은 가로
글자만 나란히 누워 서로 부딪히기 때문이다.

### 이 부분에서 봐 줬으면 하는 것

- `Plot3D` 는 SVG 라 배만 키우면 되는데, `<img>` 로 불러들인 SVG 는 **문서와
  분리된 세계**라 `var(--line)` 도 클래스도 안 산다. 복제본에 살아 있는
  원본의 `getComputedStyle` 값을 **인덱스로 짝지어** 베껴 박는다
  (`svgToCanvas`). 두 트리의 구조가 같다는 가정에 기대고 있다 — 질문 1.
- `composePng` 이 범례를 다시 그린다 (캔버스 밖 DOM 이라 안 담긴다).
  **화면의 범례와 다른 코드**이므로 어긋날 수 있다 — 질문 2.

## 2. 이격 — 세로 눈금이 값이 아니게 된다

논문이 SOC 스캔을 실을 때 쓰는 그림이다. 곡선마다 일정한 양을 올려 그린다.

```ts
export const STACK_GAP = 0.6
// 올릴 양 = (보이는 곡선 높이들의 **중앙값**) × STACK_GAP
```

최댓값이 아니라 중앙값인 이유: 스캔 하나 안에 유난히 큰 스윕이 하나 있는 것이
보통이고 (마지막 SOC 의 확산 꼬리), 그 최댓값으로 간격을 잡으면 나머지 열
곡선이 서로 아주 멀리 떨어져 각자 납작한 선이 된다.

**§0.4 를 지키려고 한 것들:**

- 올린 양을 화면·PNG 꼬리말·클립보드 **셋 다에 숫자로** 적는다.
- 축 이름이 `−Z″ + 이격 (Ω·cm²)` 로 바뀐다.
- `equalAspect` 와 `y ≥ 0` 을 끈다 — 둘 다 세로가 진짜 −Z″ 라는 전제 위에 있다.
- 클립보드는 본값과 이격 **두 벌**이고, 이격 쪽은 **이격을 보고 있을 때만** 뜬다.
- 꺼 둔 스윕은 칸을 안 지킨다 (접힌다) — 지키면 빈 띠가 남고, 그 띠가
  "여기 측정이 없다" 로 읽힌다.

질문 3·4 가 여기 있다.

## 3. Ω·cm² 를 추세와 표까지

위 나이퀴스트가 Ω·cm² 인데 추세의 세로축과 스윕 표의 파라미터 열만 Ω 이었다 —
같은 `R₁` 이 한 화면에서 두 번 다르게 나온다. 셋이 같은 자를 쓰게 했다.

**Ω 인 파라미터만** 바꾼다:

```ts
export function isOhmParam(name: string): boolean {
  if (/^R\d+$/.test(name)) return true
  return /_(Rct|Ri|Re|Wr|R)$/.test(name)
}
```

`_Q` 는 S·sⁿ 이라 오히려 **곱해야** 하고, `_n`·`_Wn` 은 무차원, `_tau`·`_Wt` 는
초다 — 그래도 나누면 화면에는 `Ω·cm²` 라고 적힌 아무 뜻 없는 수가 남는다.

**이름으로 판정하는 것이 이 변경에서 가장 약한 고리다.** `wrdkit` 에는 이미
단위로 가리는 `scalesWithArea(unit)` 가 있는데 (`areanorm.ts`), 스캔의
파라미터에는 서버가 단위를 안 실어 보낸다 — `ScanPoint.values` 는 이름 → 수
뿐이다. 질문 5.

## 질문 (답이 필요한 순서)

1. **`svgToCanvas` 의 인덱스 짝짓기.** `svg.querySelectorAll('*')` 과 복제본의
   같은 목록을 순서로 짝짓는다. 복제가 순서를 보존한다는 것은 표준이지만,
   이 방식이 깨지는 경우가 있나 (`<use>`, 그림자 DOM, 순서를 바꾸는 확장).
   더 나은 방법이 있으면 그것을 알려 주세요.
2. **범례를 두 곳에서 그린다.** 화면은 `PlotLegend`(DOM), 저장은
   `composePng`(캔버스). 색·점선·꼬리표(`note`)를 각자 해석하므로 언젠가
   갈릴 것이다. 한 곳에서 나오게 하는 현실적인 길이 있나.
3. **이격이 §0.4 를 어기나.** 값을 옮겨 그린 그림이고, 옮긴 양은 적어 두지만
   **그림 자체에서는 되돌릴 수 없다** (`stackStep` 이 보이는 곡선 집합에
   달렸으므로, 스윕을 하나 껐다 켜면 올린 양이 바뀐다). 클립보드에 이격값을
   내보내는 것이 특히 위험한가 — 붙여 넣은 표는 화면 없이 혼자 다닌다.
4. **`stackStep` 이 보이는 것에 달린 것이 맞나.** 지금은 켜 둔 곡선들의
   중앙값이라, 스윕을 끄면 남은 곡선들이 **다시 배치된다.** 대안은 전체
   집합으로 한 번 정하고 고정하는 것 — 그러면 끌 때마다 그림이 안 움직이지만
   몇 개만 켜 두면 간격이 지나치게 넓다. 어느 쪽인가.
5. **`isOhmParam` 이름 판정.** 이 정규식이 놓치는 이름이 있나
   (`Ws4_R` · `TL1_Rct` · `R12` 는 잡고, `CPE1_Q` · `TL1_Wt` · `L1` 은 안 잡는다).
   더 나은 길은 서버가 스캔 응답에 단위를 실어 보내는 것인데, 그 값을 그만한
   변경으로 볼 만한가.
6. **`--filter-control-h: 31px`.** 거르개 줄의 칸 높이를 **실측 픽셀**로
   박았다 (드롭박스 31 · 단추 줄 27 · 검색칸 29 였다). 여백이나 글꼴을 바꾸면
   같이 봐야 하는 값이다. CSS 로 이것을 재지 않고 맞추는 길이 있나.
7. **저장 실패를 말하는 방식.** 이 문서를 쓰다가 스스로 찾아 **고쳤다** —
   원래는 `try/finally` 로 상태만 되돌리고 아무 말도 안 했다 (캔버스가 없거나
   `toBlob` 이 null 이면 조용히 끝났다). 지금은 단추가 `⤓ 실패` 로 바뀌고
   그림 아래에 사유가 적힌다. `toBlob` 은 **비동기**라 `throw` 로는 못
   알린다 — 부르는 쪽의 `try` 가 이미 끝나 있어서 — 그래서
   `downloadCanvas(canvas, name, onFail)` 로 콜백을 받는다. 콜백이 맞는
   모양인가, 아니면 `Promise` 를 돌려주는 편이 나은가.
