# v2.1 — D2 개발 소비자: 명령 전부를 생성기 꼴로 (MXD2R-04 · 2026-11-03)

> v2.0 의 사전 공격이 남긴 '범위 밖 공통 변조 17' 을 1저자 11-03 비준 (Q1 = 권고대로) 대로 닫았다. 원리는 v2.0 (MXD2R-01–03) 과 같다 — 생성기가 쓰는 꼴만 받고 모르는 것은 이유를 적어 거부한다. 개발 검사 PASS 는 여전히 실행·코호트·발사 인증이 아니고, Codex 재확인 전에는 닫혔다고 하지 않는다.
>
> **뜻이 같아도 표기가 다르면 거부한다 (생성기 꼴 엄격).**  **LIGGGHTS 실행 · Windows · Python 3.8 실행은 확인하지 않았다.**

## 쉬운 판

v2.0 은 시간 · 삽입 · 회전 · 접촉 · 재료 줄만 생성기 꼴로 묶었다. 그래서 두 덱에 같은 변경 — `boundary p p p` (주기 경계) · `newton on` · 템플릿 뒤 옵션 · 분포 · 둘째 삽입의 난수 시드 · 삽입 영역 반지름 · 메시 크기 · `dump_modify` 추가 · `thermo` 간격 · `write_restart` 삭제 — 을 넣어도 통과했다.

이제 덱의 **명령 전부**를 생성기가 그 계획에서 쓸 토큰으로 다시 만들어 한 줄씩 대조한다. 드럼 크기와 삽입 영역은 덱의 입자 수 · 반지름 · 밀도에서 생성기와 같은 식으로 다시 낸다. 값이 같아도 표기가 다르면 (`0.0144707` ↔ `0.01447070` · `5000` ↔ `5e3` · `0.3` ↔ `0.30`) 거부한다.

글자 꼴도 본다. 탭 · 제어 문자 · 명령 줄의 비 ASCII 글자 · 따옴표 · `$` · 주석 줄 끝의 `&` 는 생성기가 쓰지 않는다. 특히 주석 끝 `&` 뒤에 보이지 않는 공백 (NBSP) 한 글자를 두면 우리 파서는 다음 줄을 주석으로 이어 붙여 못 보는데 (예: `neigh_modify exclude type 3 3`), 그런 덱이 예전엔 통과했다 — 이제 거부한다.

## 자세한 판

- 대조 (`_d2_generator_form`): 전역 설정 일곱 줄 · 상자 · 이웃 · 재료 (영률 · ν = 등록 값의 생성기 표기 · 반발 · 마찰 · 구름 · CED 표기 · 특성 속도) · pair · timestep (k 배 표기) · 중력 · 메시 셋 (이름 · 파일 · 타입 · scale = 2R) · 벽 · 템플릿 (id · 시드 · 밀도 · 반지름) · 분포 (시드 32452867 · 둘째 32452883 · 분율) · 삽입 영역 (0.9R · ±0.45L · 층상 위 블록 = 이분법 그대로) · 삽입 (첫 시드 = 메타 · 둘째 = 다음 소수) · 적분기 · 출력 (compute · thermo_style · thermo 5000 · thermo_modify) · 체크포인트 (restart 간격 규칙 · a/b 파일 · settled) · dump (간격 규칙 · 열 · 전 정밀도 형식 줄은 메타가 선언할 때만) · 회전 셋 (주기 = 메타). 차례 · 개수 · 토큰이 전부 같아야 한다.
- 자유 칸 하나: neighbor skin 값 (양의 ASCII 수만 · 기존 시험이 단일 덱 PASS 를 요구). 짝 대조는 두 덱의 skin 이 다를 때만 잡는다 — 두 덱에 같이 바꾼 skin 은 세 소비자가 통과시킨다 (남은 같은 부류 · 고정은 1저자 결정). CED 값 · 삽입 총수 · run 수 · dt 값은 기존 검사 (힘 규칙 · 계획수 · 메타) 가 묶고 여기서는 표기만 본다.
- 글자 꼴 (`_d2_text_form`): 끝 줄바꿈 · C0/C1 제어 문자 거부 (주석 안 포함) · 명령 부분 = 인쇄 가능 ASCII · 따옴표 · `$` 금지 · 이음은 명령 줄 끝 ` &` 만. 토큰 사이 공백 수 · 빈 줄 · 주석 글은 고정하지 않는다.
- 생성기보다 엄격한 곳: 배플 덱 (D2 메타에 배플 칸이 없다) · 시드 2^31−1 초과.
