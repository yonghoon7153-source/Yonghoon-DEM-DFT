- 최소 수정: 바 행 '틀리면' = §4 문구 그대로 ("'주기 ↔ 명령 차이 = 저장 shear 뿐' 서술 거둠 · 다시 봄") — 좁히려면 §0 범위 "고치는 것" 에 이유와 함께 올리고 (예: 바-1 ✗ = §4 그대로 · 바-2 · 3 만 ✗ = 사영식 서술만 거둠) Q8 에서 따로 비준.

### G2CPR-08 · P3 · 실행기: Ctrl-C 가 듣지 않고 · TERM 뒤에는 LIGGGHTS 가 고아로 계속 돈다

- 원인: GNU `timeout` (`--foreground` 없음) 이 자기 프로세스 그룹을 따로 만든다 → 터미널 SIGINT 는 bash 에만 닿고 bash 는 자식이 SIGINT 로 죽지 않으면 계속 간다 (wait-and-cooperative-exit).
- 재현 (네임스페이스 안 · 신호 = 내가 만든 bash 자식 pid 에만): `cd EXP && timeout -k 10 120 unshare -pf --mount-proc --kill-child python3 -I sig_driver.py COPY sleep:A:15 SIGINT` (그리고 `SIGTERM`) · 그룹 확인 = `… pgid_driver.py COPY`
- 본 결과: 프로세스 그룹 bash 0 · timeout 71 · 가짜 lmp 71 (따로).  **SIGINT**: 실행기가 멈추지 않고 팔 아홉을 다 돌아 rc 0 · STOP 없음.  **SIGTERM**: bash 즉시 죽음 (−15) · timeout + lmp 는 남아 그 팔을 끝냄 · STOP.txt · rc.txt 없음.  틀린 결과를 받는 길은 아니다 (끝난 팔 출력은 정상) — 사람이 멈추려 할 때 못 멈추거나, 죽인 뒤에도 OUT 에 쓰기가 계속된다 (A · A2 한도 1800 s).
- 최소 수정: `trap` INT TERM → 저장한 timeout pid (`$!`) 에만 TERM → STOP.txt · rc 4 (또는 `timeout --foreground`) · README "멈추는 법" 한 줄.
- 신호 대상 자체는 안전: 실행기는 kill 을 부르지 않고, timeout 은 자기 자식과 자기 그룹 (= LIGGGHTS) 에만 TERM → 30 s 뒤 KILL.
