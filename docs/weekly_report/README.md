## 1. 읽는 사람 = 교수님

- **교수님이 아는 말만 쓴다.**  분야 말 (DEM · MPM · SE · AM · SBE · DBE · PTFE · SDCP · VGCF · porosity · tortuosity · DC 분극) 과 과제 이름 (이종기술융합 · 50Kg · 영진 논문) 은 써도 된다.
- **우리 작업 기록의 말은 쓰지 않는다.**  시도 번호 · 원장 · 넘김 · 회복 · 종료 코드 · 잡 번호 · 서버 이름 · 커밋 · 해시 · 게이트 · 봉인 · 파일 경로 · 결함 원장 번호 · 내부 단계 코드 · 리뷰 판정 말 · 판독 · 팔 · 사다리 · 개발 자료가 그렇다.  꼭 필요하면 §5 의 쉬운 말로 바꾼다.
- **장마다 네 가지를 쓴다.**  목적 (왜) → 한 일 (어떻게 · 조건) → 결과 (숫자와 기준) → 의미 · 다음.
- 맨 아래 한 줄 (`< … >`) 은 교수님이 그 장에서 가져갈 **한 문장**이다.
- 숫자는 단위와 비교 기준을 같이 쓴다.  예: "최대 81 % 차이 (기준 5 %)", "DBE 1.89 vs 실측 4.68 mS/cm".
- 확인하지 않은 것은 "추정" · "분석 중" · "예정" 으로 쓴다.  결론이 아닌 것은 결론처럼 쓰지 않는다 (예: 시드 1 개 → "아직 결론 아님").
- 비공개: 주소 · 포트 · 계정 · 홈 경로를 쓰지 않는다.  Rint σ 판정 전 값과 중간 열람 값, 대외비 자료도 쓰지 않는다.

## 2. 덱 구조 (랩 양식)

참고 = 랩 주간보고 3 부 (1저자 11-23 전달 · 리포에 넣지 않음) + 지난주 1저자 수정본.

| 장 | 내용 |
|---|---|
| 1 | 요약표 — 연구주제 · 구분 · 전주 수행 업무 (기간) · 금주 수행 업무 (기간) · 연구 관련 (`1) 과제 묶음` → `(1)` 항목) · 기타 |
| 2 | `1) 주간 업무 수행` — 요일 표 (월–일 · 연구수행 내용 · 비고) · 하루 한 줄 · 쉬운 말 |
| 3 | Part 표지 (틀 그대로) |
| 4 ~ | 과제별 장 — `N) 제목` · `(k) 부제` · bullet 3–6 개 (`•` · `-` · `→`) · 그림 · 표 · 그래프 1–2 개 · 아래 한 줄 |
| 피드백 | 최근 교수님 피드백이 있으면 그 과제의 첫 장 = `(1) 교수님 피드백 사항 및 보완 계획 (날짜)` — `1. 피드백 사항` · `2. 보완 계획` |
| 끝 | `N) 기타 사항` — (1) 금주 계획 · (2) 문헌 정리 · (3) 기타 |

- 글꼴 = 맑은 고딕.  본문 13.5–14 pt · 그림 캡션 10.5 pt · 개조식 끝 (~ 진행 · ~ 확인 · ~ 예정).
- bullet 하나에 사실 하나를 쓰고, 두 줄을 넘기지 않는다.
- 아직 1저자가 채울 칸은 `[[1저자 작성]]` 으로 둔다.  덱에서 빨강 굵게 보인다.

## 3. 그림

- **실제 그림을 먼저 쓴다** (계산 결과 렌더 · 실험 사진 · 원고 그림).  개념도만으로 채우지 않는다.
- 아직 없는 그림은 **빈칸**으로 둔다 (점선 상자 · `그림 ①` · 무엇을 · 넣을 것).  가져오는 **명령은 채팅으로** 1저자에게 준다.  1저자가 그림을 붙여 넣는다.
- 실데이터 그래프는 덱 안 차트로 넣어 편집할 수 있게 한다.  위 · 오른쪽 축선은 없다.  세로축을 0 에서 시작하지 않으면 캡션에 적는다.
- 그림 출처의 꼴은 아래와 같다.  명령에 들어갈 주소 · 포트는 1저자가 아는 값으로 채운다.

| 무엇 | 어디서 | 도구 |
|---|---|---|
| 믹서 단면 | ibb 계산 폴더의 덤프 (폴더마다 한 장 · 렌더러가 폴더의 마지막 장을 그림) | `scripts/viz_mixer_bed.py --dir … --label … --out …` |
| 7:3 전극 압축 과정 | 리포 `docs/data/ps73_compaction_curve_20261006/stages_20261012/t1_geometry/` | 그대로 |

| 2D MPM (수영) | 1저자 WSL 반환 자료 | Codex 실무에 그림 요청 |
| 실험 (SEM · DC 분극) | 영진 원고 · 랩 자료 | 1저자 |

## 4. 절차

1. **재료 모으기.**  진행 기록 (`docs/session_20260923_progress.md` 그 주 줄), CLAUDE.md 날짜 줄, 데이터 README, Codex 쪽지 (`docs/collab/codex_to_claude/`) 를 본다.  숫자는 기록에서 그대로 옮긴다.
2. **개요.**  JSON 으로 쓴다 (예: `docs/weekly_report/outline_20261123.json`).  장마다 아래 한 줄부터 쓴다.  ★ 다음 주부터는 아래 한 줄 목록을 1저자에게 먼저 보여 확인받고 만든다.
3. **만들기.**  `python3 docs/weekly_report/build_weekly.py --outline <개요> --template <지난주 1저자 수정본.pptx> --out <덱>` 을 실행한다.  틀은 1저자가 고쳐 낸 지난주 판이며, 리포에 넣지 않는다.
4. **검사.**  셋을 모두 통과해야 전달한다.
   - `python3 docs/weekly_report/lint_weekly.py <덱>` → 금지어 0.
   - 렌더해서 눈으로 본다 (넘침 · 겹침 · 빈 칸).
   - 처음 읽는 사람 검사: 독립 조수가 렌더 그림만 보고 장마다 목적 · 결과 · 의미 · 다음을 답하고 모르는 말을 적는다.  내부 용어 0 · "알 수 없음" 0 이 될 때까지 고친다.
5. **전달.**  PPTX + PDF 와 빈칸마다 가져오는 명령 (채팅) 을 준다.  덱은 리포에 넣지 않는다 (공개 리포 · 개인 자료).
