- 기존 0–5초 요청 187개를 토큰 그대로 보존했고, 5.1–30초의 0.1초 간격 250개를 추가했다. 총 437개는 Java tlist와 계약이 같고 순증가한다. 실제 저장 상태 개수는 고정하지 않았다.
- threshold 0 복귀, 정확30초 정상 종료와 보호중단/오류의 분리, 전체 시간 교집합과 비교 prefix의 분리는 타당한 준비 방향이다. 정확30초에서 guard가 켜져도 정상 완료로 올리지 않는다.

## 3. 수정 요구 — 유한 목록 두 건

### N30-N1 · P1 — 초기 Li 기준을 총량 상대변화 기준으로 대체함

근거: `src/diagnostic_consumer.py:183–188`, `PARENT_COMMAND.ps1:105–108`, `CONSUMPTION_CONTRACT_KO.md`의 수치 항목, `CONTRACT.json` limits.

현재 코드는 각 초기 Li의 `abs((current-reference)/reference) <= relative_Li(1e-6)`를 쓴다. `relative_Li`는 시간에 따른 총 Li 상대변화에도 쓰인다. 이전 작업의 초기 Li 각 항 절대차 `1e-9 mol/m²`와 다른 기준이며, 이번 준비는 기존 수치 허용치 유지를 전제로 했다. 동봉 직전 검토문에도 초기 각 항은 `1e-9 mol/m² 참고 대조`로 남아 있다. 과거 검토자의 참고 대조를 과거 producer가 강제한 기능으로 소급해서 표현해서도 안 된다.

수학적 반례: 기준 N/P가 각1 mol/m²이고 현재값을 1.0000005/0.9999995로 바꾸면 합계는 같으며 각 상대차5e-7은 새 기준을 통과한다. 그러나 각 절대차5e-7 mol/m²는1e-9를 초과한다. 이는 실제 COMSOL 데이터나 후보 함수 실행 결과가 아니라 **두 기준이 동등하지 않다는 산술 반례**다. 기준량에 따라 상대 기준이 더 엄격한 경우도 있으므로 일률적으로 완화라고 부르지 않는다.

요구:

1. 초기 각 항 전용 단위 있는 절대 한도 `initial_Li_component_abs_mol_m2=1e-9`를 명시한다. 총량 drift의 상대1e-6은 별도로 유지한다.
2. Python 결과에 current/baseline/absolute_delta_mol_m2/적용 한도를 남기고 부모도 그 필드를 소비한다. 상대차는 참고 지표로 남길 수 있으나 절대 기준을 대체하지 않는다.
3. 계약·설명·부모·검증안을 함께 맞춘다. 비교 기준을 바꾸고 싶다면 계산 전에 별도 변경 근거/사용자 결정을 받아야 하며, 이번 최소 보완은 기존 절대 기준 복원으로 충분하다.
4. PY06-03/PS03-01 안에 동일값, 정확 경계, 경계 직후, 총량 상쇄 및 상대통과/절대실패 반례를 봉인한다. 부모에서는 absolute 필드 누락/NaN/한도초과도 거부한다.

### N30-N2 · P2 — 최종 쓰기 후 예산 초과가 이전 within_limits=True로 남음

근거: `PARENT_COMMAND.ps1:168–172`, 제한 검증안 PS04-03/PS05.

`$snapshot`과 `$within`을 FINAL_BOUNDARY 쓰기 전에 계산한 뒤, BSave의 쓰기/flush/read-back과 BRef의 해시 읽기를 수행한다. 마지막 반환에는 새 `snapshot_seconds`가 있지만 `within_limits`와 `limited`는 이전 값을 재사용한다. 성공한 I/O만으로도 전체5099.9→5100.1초 또는 delivery299.9→300.1초가 될 수 있다. 이때 오류가 없으면 자동으로 INCOMPLETE가 되지 않는다. 실제 이번 실행 초과가 아니라 소스 순서에서 확인한 경계 사례다.

요구:

1. 최종 boundary 파일 쓰기/재읽기 및 그 식별 확보 뒤, 마지막 출력 직전에 전체/전달 경과를 다시 계산한다. 그 시점이 한도를 넘으면 마지막 반환의 limited=INCOMPLETE/within_limits=false 및 이유를 남긴다.
2. 내부 FINAL_BOUNDARY는 pre-write snapshot으로 보존해도 된다. 뒤의 실제 반환이 실패/초과이면 이전 정상 판정을 승격 근거로 소비하지 않도록 최종 수용 규칙을 연결한다. 파일을 무한히 재작성하여 마지막 쓰기까지 증명하려 하지 않는다.
3. 전체/전달 두 예산 각각에 대해 쓰기 직전 통과→성공한 쓰기/해시 뒤 초과하는 clock/writer 반례와 정확 경계 대조군을 실제 부모 finalization 분기로 시험한다. 파일 I/O 예외 검출과 시간 초과 검출은 별개다.
4. 마지막 출력 이후의 사용자 업로드 시간이나 -NoExit 프로세스 생존시간까지 측정했다고 쓰지 않는다. 유한한 최종 관측 경계를 명시하면 된다.

## 4. 한정 검증안 판정과 다음 작업
