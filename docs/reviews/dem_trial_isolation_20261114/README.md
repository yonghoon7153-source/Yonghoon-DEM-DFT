# DEM 수영 — 실패 시도 격리 합성 모델

## 1. 이번 진전

바탕 34131838cdf2e212be3b8949f83689af777ddda7의 `docs/reviews/dem_source_state_map_20261114/README.md` §3–6에서 찾은 point·profile·host·rod 완료 경계를 작은 실행 가능한 모델로 옮겼다. 실패한 시도는 버리고, 앞서 완료한 걸음과 누적값을 보존하는지 확인한다.

**새 합성 모델의 16메서드 통과. 의도적으로 약화한 5변형 모두 검출.** 연구 결과 0, 생산 코드 변경 0, 전체 HOLD. 기존 MPM/DEM solver의 수정·실행이나 독립 반박 판정이 아니다. Rint·믹서·LHS의 실행 핀·기존 명령·원장도 그대로다.

## 2. 모델과 실제 소스의 연결

| 합성 표현 | 소스 지도와의 연결 | 이번 확인의 범위 |
|---|---|---|
| point의 x/v/C/F/dg_acc/eps_acc | substep의 지속적 상태 쓰기 | 각 값은 정수 표지 하나다. 벡터·텐서·구성식·실제 변형을 계산하지 않음 |
| profiles 4칸 | amf_zdn/amf_zup/szz_zs/szz_zn의 frame 누적 | 이미 성공한 앞부분을 유지하고 새 성공 기여만 더함. z 배열 대신 4개 정수 사용 |
| host 4칸 | sacc/wacc/amdn/amup | 첫 칸만 갱신된 실패도 밖에 반영하지 않음 |
| rods 선택 단계 | rod_pass 후 rod_setv의 완료 순서 | 위치·속도 표지에 서로 다른 정수 증가분. rod 물리·반복 수·실제 kernel은 없음 |
| step/time_ticks | 같은 목표 걸음의 완료 | 실패 때 그대로, 성공 때 각각 1/10 증가. 10은 단위 없는 합성 표지이며 dt 선택 아님 |
| point_id/particle_id | point와 원 입자 구분 | 한 입자의 두 point 및 같은 좌표의 다른 입자를 보존. 실제 P2G 소유 표나 ID 승계 자격은 아님 |

`trial_model.py`는 Python 표준 라이브러리만 쓰는 단일 소유자·동기 모델이다. 생성자에서 입력 사본을 만들고 매 시도는 깊은 사본에서 진행한다. profile → point → 선택적 rod 위치/속도 → host → step/time 순서를 모두 마친 뒤 마지막에 보관 상태를 교체한다. 실패는 예외로 돌려주며 자동 재시도하지 않는다. 시험의 재시도는 호출자가 별도로 한 번 호출한다.

반환 사본도 교체 전에 만든다. 따라서 이 모델조차 old·trial·return 사본이 함께 살아 있는 순간이 있다. 실제 배열 구현의 메모리를 old+trial 두 벌만으로 산정하지 않는다. snapshot을 보유하는 호출자, Python 객체·allocator 비용은 추가이며, 이번에 실제 메모리 사용량을 측정하지 않았다.

## 3. 시험 먼저와 의도한 실패

먼저 같은 expected-correct 시험 파일을 썼다. 그 뒤 완료 전부터 trial을 보관 상태로 공개하는 **고의로 잘못 만든 새 기준 모델**에 적용했다. 16메서드 중 서로 다른 7메서드에서 실패 30건, 오류 0을 확인한 뒤 조기 공개 한 줄을 제거했다. 같은 시험 바이트로 최종 16/16, 실패 0·오류 0이다.

이 전후 비교의 구본은 역사 생산 코드가 아니다. 새 준비 모델의 검사 감도를 확인한 것이며, 기존 MPM 결함 30건 또는 생산 수정 종결로 세지 않는다. 실패 건수에는 subtest가 포함된다.

| 입력 | 메서드 수 | 실패 건수 / 오류 | 실패한 서로 다른 메서드 | 뜻 |
|---|---:|---:|---:|---|
| 조기 공개 기준 모델 | 16 | 30 / 0 | 7 | 미완료 기여가 부모에 남음 |
| 최종 모델 | 16 | 0 / 0 | 0 | 등록한 합성 전이·보존 기대 충족 |
| 얕은 복사 변형 | 같은 16 | 30 / 0 | 7 | 중첩 point/profile/host 별칭이 부모를 오염 |
| frame profile 초기화 변형 | 같은 16 | 34 / 0 | 8 | 이미 성공한 앞부분을 지움 |
| 프로토콜식 v/C 초기화 변형 | 같은 16 | 33 / 0 | 7 | 같은 걸음의 기존 motion 표지를 잃음 |
| rod 속도 갱신 생략 변형 | 같은 16 | 24 / 0 | 4 | rod 위치만 갱신한 결과를 완료로 반영 |

조기 공개는 위 기준 모델과 같은 변형이므로 한 번만 센다. 다섯 약화 모델·반복 16·subtest 수를 새 고유 시험 수로 합산하지 않는다. 테스트와 모델 SHA256, 반환값, 원출력 해시는 `test_results.json`에 있고 변형의 정확한 치환은 `negative_variants.json`에 있다. 모든 변형의 오류·건너뜀은 0이다.

## 4. 직접 확인한 실패 위치와 보존

기본 경로의 실패 위치는 trial 생성 직후, P2G 표지 누적 후, 첫 point 갱신 후, point 전체 후, 첫 host 누적 후, host 전체 후, 교체 직전의 **7곳**이다. rod 경로는 첫 rod 위치·전체 위치·첫 rod 속도·전체 속도의 **4곳을 추가한 11곳**이다. 기본 7과 rod 11의 공통 위치를 서로 다른 18곳으로 세지 않는다.

각 위치에서 부모 전체가 동일한지, 이후 명시적인 재시도 결과가 끊김 없는 기준 결과와 같은지 대조했다. rod 경로는 앞서 한 번 성공한 뒤의 모든 11위치 실패도 검사하여 이전 성공분이 초기 상태로 되돌아가지 않는지 확인했다. 부분 point 갱신은 여섯 필드, 부분 host 갱신은 누적·step/time 보존을 별도로 검사한다.

profile의 손 계산 기준은 앞부분 2에서 실패한 증가분을 버린 뒤, 성공 증가분 3만 더한 5다. 반환 snapshot·생성자 입력과 내부 상태의 별칭, 중복 point ID·빈 point 목록·잘못된 shape/타입·비활성 rod 실패 위치도 검사했다. 큰 정수 표지는 2**53+1을 float로 바꾸지 않고 보존한다. 이것은 실제 부동소수점 MPM의 비트 재현성 시험이 아니다.

## 5. 아직 연결하지 않은 것

실제 Taichi field 복사·GPU 비동기 완료·다중 writer·커널 내부의 임의 중단·할당 실패·프로세스 중단·파일 내구성을 검증하지 않았다. 선택한 checkpoint에서의 동기 예외 보존 결과를 그 보장으로 확대하지 않는다. 실제 dt, 색 수, 메모리 한도, 재시도 예산도 정하지 않았다.

기존 load-state가 v/C를 0으로 두는 것은 프로토콜 전환의 의도다. 이번 v/C 변형은 그 의미를 같은 걸음 rollback에 대입하면 안 된다는 합성 대조이며, 실제 loader를 실행한 반례가 아니다. wall_z와 소속은 모델에서 보존하지만 실제 wall clamp·주기 node·색 계획을 시험하지 않았다.

다음 연결에는 **실제 사본 생성/완료 장벽, 시도별 profile 누적, rod까지 포함한 성공 경계, 자원 수명**의 구체 구현이 필요하다. 현재 P1 A/B 독립 설계 판정 대기, 실제 T0/T5/T11/T12·물리 자격·운영 GO는 그대로다. 이 합성 모델을 생산 실행기에 자동 연결하지 않았다.

## 6. 재현과 저장소 점검

리포 루트에서 `python -I -X utf8 -B docs/reviews/dem_trial_isolation_20261114/test_trial_model.py`로 최종 16메서드를 재현한다. 소형 합성 입력은 시험 파일 안에 있으며 실제 자료를 읽는 인자는 없다. Python 3.12.14에서 확인했다.

약화 비교는 원본을 수정하지 않는 새 사본에서 `negative_variants.json`의 old가 정확히 한 번 등장하는지 확인한 뒤 new로 교체하고 같은 시험 파일을 실행한다. 최종 모델은 rc0, 다섯 약화 모델은 각각 rc1·오류0이 기대다. 약화 모델의 rc1을 최종 후보의 성공과 혼동하지 않는다.

필수 저장소 점검은 `check_results.json`, 변경 범위와 원본 보존은 `scope_check.json`에 남긴다. 전체 연구 게이트·현장·원자료·운영 봉인 실행은 없다.
