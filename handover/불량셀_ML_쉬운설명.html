임피던스 한 번으로 불량셀을 거른다

배터리 셀의 용량을 알려면 원래 충전과 방전을 직접 돌려 봐야 한다. 이 코드는 그 대신 전기화학 임피던스 측정(EIS) 한 번의 결과만 보고 그 셀의 용량을 예측하고, 기준에 미달하는지 판정한다. 아래는 이 코드를 처음 보는 사람이 직접 돌려 보고, 나온 숫자를 잘못 읽지 않게 하는 데 필요한 최소한의 설명이다.

읽는 데 약 12분 데모 실행 약 35초 필요한 것 Python 3.12 필요 없는 것 머신러닝 지식

1무슨 문제를 푸나

셀 하나가 실제로 얼마나 담을 수 있는지 알아내려면, 그 셀을 끝까지 충전했다가 방전시켜 보면 된다. 확실한 방법이지만 셀 하나에 몇 시간이 걸린다. 백 개를 검사하려면 그만큼 곱해진다.

EIS는 다르다. 셀에 아주 작은 교류 신호를 여러 주파수로 흘려 보고, 셀이 그 신호에 어떻게 반응하는지를 잰다. 몇 분이면 끝나고 셀을 상하게 하지 않는다. 문제는 그렇게 얻은 임피던스 값이 곧바로 “용량 몇 Ah”를 알려 주지는 않는다는 것이다.

그래서 이 코드는 이미 두 가지를 다 아는 셀들을 먼저 모은다. 임피던스도 재고, 충방전도 직접 돌려서 실제 용량도 아는 셀들이다. 거기서 “임피던스가 이런 모양이면 용량은 이 정도”라는 관계를 찾아낸다. 그 관계가 잡히고 나면, 다음부터는 임피던스만 재고 용량을 추정할 수 있다.

한 줄로: 시간이 오래 걸리는 측정을, 빠른 측정으로 맞혀 보는 코드다.

“불량”이 무슨 뜻인지부터 정확히

이 코드에서 불량은 지정한 조건에서 용량이 기준값에 못 미쳤다는 뜻이다. 기본 기준은 0.01802088 Ah이고, 이는 설계 용량 0.0200232 Ah의 90%다. 이 값 이하면 1(불량), 넘으면 0(정상)으로 라벨이 붙는다.

이건 안전 검사가 아니다

내부 단락이 있는지, 발화 위험이 있는지, 앞으로 수명이 얼마나 갈지를 판별하는 코드가 아니다. 그런 뜻으로 “불량”이라는 단어를 읽으면 결과를 완전히 잘못 쓰게 된다. 오직 용량이 기준보다 작은가 하나만 본다.

2무엇을 준비하나

학습을 하려면 셀 하나마다 파일 두 개가 필요하다. 충방전 장비가 뱉은 이력 파일과, EIS 장비가 뱉은 스펙트럼 파일이다.

파일확장자어디서 나오나무엇에 쓰나
충방전 이력.txt사이클러(충방전기)정답이 되는 실제 용량을 뽑는다
EIS 스펙트럼.mptEC-Lab예측에 쓸 입력을 만든다
 둘 다 탭으로 구분된 텍스트 파일이다. 엑셀 파일은 받지 않는다.
가장 자주 걸리는 지점

파일 이름 안에 cell 다음에 숫자가 붙은 부분이 반드시 있어야 한다. 코드는 그 숫자로 “몇 번 셀인가”를 알아낸다. cell41.txt, cell41_0.5MPa.txt는 된다. Cell_41, C41, 41_EIS는 안 된다.

더 위험한 경우가 있다. pouchcell12_cell3.txt는 오류가 나지 않고 12번 셀로 읽힌다. 앞에서 처음 만나는 cell+숫자를 쓰기 때문이다. 이름에 cell이라는 글자가 두 번 들어가지 않게 한다.

파일은 폴더 두 개에 나눠 담는다. 하나는 .txt만, 다른 하나는 .mpt만 들어간다. 그 폴더 바로 아래에 있는 파일은 전부 데이터로 취급하므로, readme.txt 같은 것을 같이 두면 실행이 중단된다.

아직 실제 데이터가 없어도 된다

코드에는 가상으로 만든 12셀 예제가 들어 있다. 파일을 하나도 준비하지 않고도 전체 과정을 끝까지 돌려 볼 수 있다. 다음 절이 그것이다.

3세 줄로 돌려보기

압축을 풀면 defective_cell_ml 폴더가 나온다. 그 폴더 안에서 PowerShell을 열고 아래를 순서대로 친다.

  1. 1 이 프로젝트 전용 파이썬 공간을 만든다

    컴퓨터에 이미 깔린 다른 파이썬 패키지와 섞이지 않게 격리하는 단계다. 한 번만 하면 된다.

    py -3.12 -m venv .venv

    py라는 명령이 없다면 python -m venv .venv로 바꿔 친다. 단 python --version이 3.12여야 한다.

  2. 2 필요한 라이브러리를 정확한 버전으로 설치한다

    인터넷 연결이 필요하다. 버전이 고정돼 있어서 나중에 결과가 달라지지 않는다.

    .\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
  3. 3 가상 12셀로 전 과정을 돌린다

    약 35초 걸린다. 끝나면 results\demo 폴더가 생긴다.

    .\.venv\Scripts\python.exe -X utf8 export_for_origin.py --demo --output results\demo

    -X utf8은 한글이 섞인 경로에서 글자가 깨지는 것을 막는다. 빼지 않는 편이 안전하다.

다시 돌릴 때는 폴더 이름을 바꾼다

이 코드는 기존 폴더에 절대 덮어쓰지 않는다. 같은 명령을 한 번 더 치면 Output directory already exists라며 멈춘다. results\demo_02처럼 새 이름을 준다. 실수로 결과를 날리지 않게 하려고 일부러 이렇게 만든 것이다.

실제 데이터로 돌릴 때

--demo 자리에 폴더 두 개를 지정하면 된다. 

.\.venv\Scripts\python.exe -X utf8 export_for_origin.py \
  --config config.json \
  --cycle-dir "D:\my_data\cycle" \
  --eis-dir   "D:\my_data\eis" \
  --output    results\measured_01

실제 장비 설정은 config.json에서 맞춘다. 몇 번째 사이클을 볼지, 어떤 주파수를 쓸지, 셀 번호 범위가 어디까지인지 같은 것들이다. 처음 한 번은 셀 하나를 골라 원시 파일의 값과 코드가 뽑아낸 용량을 직접 대조해 보는 편이 좋다.

4결과 파일 세 개

실행이 끝나면 폴더에 파일이 열몇 개 생긴다. 처음에는 이 중 세 개만 보면 된다. 나머지는 나중에 필요해질 때 찾으면 된다.

  1. 1 run_summary.md — 먼저 이것부터

    사람이 읽으라고 만든 요약이다. 메모장으로 열린다. 점수 표, 셀이 몇 개 쓰였는지, 계산하지 못한 항목이 있으면 무엇인지가 전부 여기에 있다.

  2. 2 results_for_origin.xlsx — 그래프 그릴 것

    Origin에 바로 붙일 수 있게 시트 11장으로 정리된 엑셀 파일이다. 수식 없이 값만 들어 있다. 산점도, ROC 곡선, 잔차, 혼동행렬이 각각 별도 시트다.

  3. 3 oof_predictions.csv — 셀 하나하나 확인

    셀별로 실제 용량, 예측 용량, 그 차이, 최종 판정이 한 줄씩 들어 있다. “몇 번 셀을 틀렸나”를 볼 때 여기를 본다.

엑셀에서 CSV 첫 칸이 깨져 보인다면

정상이다. CSV는 한글이 안 깨지도록 UTF-8 BOM으로 저장된다. 엑셀에서 그냥 더블클릭하지 말고 데이터 > 텍스트/CSV 가져오기로 열면 제대로 나온다. 프로그램으로 읽는다면 인코딩을 utf-8-sig로 지정한다.

계수 시트가 비어 있다면

03_reg_coefs 시트가 텅 비어 있을 수 있다. 버그가 아니라 “이번 모델은 EIS를 안 쓰고 개방전압만 썼다”는 뜻이다. 가상 데모에서 실제로 이런 일이 일어난다. run_summary.md가 같은 내용을 굵은 글씨로 알려 준다.

5점수 읽는 법

이 문서에서 가장 중요한 절이다. 나온 숫자를 상식대로 읽으면 거의 확실하게 틀린다. 왜 그런지부터 봐야 한다.

먼저, 점수를 어떻게 매기는가

모델을 만들 때 쓴 셀로 그 모델을 시험하면 안 된다. 시험지를 미리 보고 시험을 치는 것과 같아서 실제보다 훨씬 좋은 점수가 나온다. 그래서 이 코드는 셀을 하나씩 가려 놓고 채점한다.

그리고 여기서 함정이 생긴다

가려 놓은 셀을 맞히는 방식이기 때문에, 아무 정보도 안 쓰는 모델의 점수가 0이 아니다. “나머지 셀들의 평균값”을 그대로 답으로 내는 가장 무성의한 모델을 생각해 보자. 이 모델조차 자기 자신을 뺀 평균을 쓰게 되고, 그래서 정답에서 체계적으로 조금씩 빗나간다.

셀이 12개일 때 이 무성의한 모델의 Q² 점수는 우연이 아니라 계산으로 정해지는 상수 −0.190이다. 셀 수만 알면 미리 알 수 있다.

가장 흔한 오독

“Q²가 음수네, 모델이 나쁘구나”는 틀렸다. 비교 대상은 0이 아니라 결과 표의 baseline_으로 시작하는 줄들이다. 그 줄보다 위에 있으면 EIS가 실제로 정보를 준 것이고, 그 줄 근처면 정보를 못 준 것이다.

같은 이유로 분류 표의 baseline_mean_threshold 줄은 AUC가 정확히 0으로 찍힌다. 이것도 고장이 아니라 계산 구조가 그렇게 만드는 값이다.

그래서 이 코드는 결과 표에 기준선 줄을 항상 같이 찍는다. 숨기지 않고 같은 표에 나란히 둬서, 보는 사람이 눈금을 잘못 잡지 않게 하려는 설계다.

표에 나오는 줄뜻어떻게 보나
capacity_nested_selection실제로 만든 모델이 줄의 점수가 결과다
baseline_mean평균만 내놓는 모델여기보다 높아야 의미가 있다
baseline_prior특징을 하나도 안 쓰는 분류기찍었을 때의 수준
baseline_mag@1000Hz1 kHz 임피던스 하나만 쓴 단순 모델복잡한 모델이 이길 값이 있나 확인
 마지막 줄이 중요하다. 단순 모델이 복잡한 모델과 비슷하다면 복잡한 쪽을 쓸 이유가 없다.
점수가 너무 좋으면 의심한다

가상 데모에서는 AUC가 1.000, 즉 완벽하게 나온다. 데이터를 일부러 깔끔하게 만들었기 때문이다. 실제 측정 자료에서 이런 값이 나오면 좋아할 일이 아니라 점검할 일이다. 셀 번호와 파일 대응이 틀어졌거나, 같은 셀이 학습과 채점에 함께 들어갔을 가능성부터 본다.

6자주 나오는 오류

오류가 나면 화면 마지막 줄에 영어 한 문장이 뜬다. 처음 돌릴 때 마주치는 것들은 거의 아래에 있다.

화면에 나온 말실제 원인고치는 법
missing cell<number> in filename 파일 이름에 cell+숫자가 없다. 혹은 데이터가 아닌 파일이 폴더에 섞여 있다. 이름을 cell41.txt 형태로 바꾸고, 폴더에서 데이터 외 파일을 뺀다
Output directory already exists 같은 출력 폴더 이름을 두 번 썼다 results\demo_02처럼 새 이름을 준다
required header not found 장비가 내보낸 열 이름이 코드가 기대하는 것과 다르다 내보내기 설정에서 열 이름을 맞추거나, 열 이름 줄이 파일 앞 300줄 안에 오게 한다
units row … not recognized 용량을 mAh로, 전류를 mA로 내보냈다 Ah와 A 단위로 다시 내보낸다. 단위를 바꾸면 결과가 1000배 틀어진다
ocv required EIS 파일에 개방전압 <Ewe>/V 열이 없다 그 열을 포함해 다시 내보내거나, 설정에서 use_ocv를 false로 둔다
outside configured cell range 파일의 셀 번호가 설정한 범위 밖이다 config.json의 cell_min, cell_max를 넓힌다
글자가 ???나 네모로 깨진다 Windows 콘솔 인코딩 문제 명령에 -X utf8을 빠뜨리지 않았는지 본다
add the instrument code page … to config encodings 영문 로케일 EC-Lab 파일이라 글자 코드가 다르다 설정의 encodings 목록에 "cp1252"를 넣는다
오류로 멈출 때 프로그램은 종료 코드 2를 낸다. 정상 종료는 0이다.
오류가 안 났는데 셀이 빠져 있다면

결과의 셀 개수가 넣은 파일 수보다 적을 수 있다. 왜 빠졌는지는 data_audit.json에 셀마다 사유가 기록된다. 파일 이름의 번호를 잘못 읽은 경우가 대부분이다.

7새 셀 판정하기

학습이 끝나면 그 결과 폴더 안에 모델 파일이 저장된다. 다음부터는 새 셀의 EIS만 재서 다시 학습하지 않고 바로 판정할 수 있다. 12셀 기준 1초 남짓 걸린다. 

.\.venv\Scripts\python.exe -X utf8 predict.py \
  --run      results\measured_01 \
  --features new_cells.csv \
  --output   results\pred_01.csv
학습 폴더는 통째로 옮긴다

모델 파일만 따로 복사하거나 이름을 바꾸면 거부된다. 코드가 실행할 때마다 폴더 안의 파일들이 학습 당시와 같은지 해시로 대조하기 때문이다. 폴더 전체를 그대로 보관하고 그대로 옮긴다.

남이 준 학습 폴더를 그냥 쓰면 안 된다

모델 파일은 읽는 순간 그 안에 든 코드가 실행되는 형식이다. 해시 대조는 파일이 상했는지 보는 것이지 믿을 수 있는 파일인지 확인해 주는 것이 아니다. 웹앱을 만든다면 사용자가 올린 폴더를 그대로 예측에 넘기는 기능은 만들지 않는다. 서버가 직접 학습해서 만든 폴더만 쓴다.

예측 결과 CSV의 열 구성은 실행마다 다를 수 있다. 그 학습에서 만들어지지 않은 모델이 있으면 해당 열이 통째로 빠진다. 열이 항상 같다고 가정하고 읽는 프로그램은 깨진다.

8하지 않는 것

마지막으로, 이 코드가 해 주지 않는 일을 분명히 해 둔다. 여기를 오해하면 결과를 잘못 쓰게 된다.

실제 셀로 성능이 검증된 완제품 모델이 아니다

지금까지 이 코드가 돌아간 자료는 전부 가상으로 만든 것이다. 문서에 적힌 점수는 코드가 제대로 도는지 확인한 값이지, 실제 불량셀을 얼마나 잘 골라내는지를 말해 주지 않는다. 실제 성능은 실제 측정 자료를 넣어 봐야 알 수 있다.

안전 결함이나 수명을 판별하지 않는다

내부 단락, 발화 위험, 앞으로 몇 사이클을 갈지는 이 코드의 판정 대상이 아니다. 오직 지정한 조건에서의 용량이 기준보다 작은지만 본다.

기본 설정은 방전이 아니라 충전 용량을 본다

첫 충전에는 되돌릴 수 없는 소모분이 섞인다. 부반응이 큰 셀이 오히려 용량이 커 보일 수 있다는 뜻이다. 가역 용량 기준으로 판단해야 한다면 설정에서 방전 구간을 지정해야 한다.

화면 프로그램이 없다

클릭해서 쓰는 창은 없다. 명령줄에서 스크립트 세 개를 실행하는 것이 전부다. 웹 화면이 필요하면 이 코드를 감싸는 프로그램을 따로 만들어야 한다.

계산이 빠르지 않다

셀 하나당 약 2.7초다. 50셀이면 2분, 100셀이면 4~5분쯤 걸린다. 버튼을 누르고 기다리는 웹 화면 안에서 그대로 돌리면 시간 초과로 끊긴다.

그래서 무엇을 믿어도 되나

계산 과정 자체는 검증돼 있다. 자동 시험 152개가 통과하고, 배포 전 검사 7개와 파일 무결성 대조 102건이 매 실행마다 확인된다. 셀이 자기 채점에 끼어들지 않는다는 점도 별도로 검증했다. 믿어도 되는 것은 계산의 정확성이고, 아직 확인되지 않은 것은 실제 셀에서의 성능이다.
