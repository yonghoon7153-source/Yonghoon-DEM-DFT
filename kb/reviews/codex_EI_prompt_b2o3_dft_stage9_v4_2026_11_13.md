- 출처 인증 — 형식 · 내부 관계까지 일관된 다른 계산의 블록 · 중간 SCF 묶음 바꿔치기는 못 가린다 (EH Q2 · 범위 문구로 명시).
- 응력 행렬의 대칭 검사 — 소비하는 값은 P 뿐이라 넣지 않았다 (실측 1016 블록 비대칭 0).

## 6. 질문

- **Q1** EH 의 반례 (P1-1 · P1-2 · P2-1 · P2-2) 가 v4 에서 막히나 — 가능하면 EH 때의 재현 자료 (`value_results.json` · `bfgs_cli_results.json` · `stress_body_results.json`) 로 다시 돌려 보고. 거부될 때 성공 판정 파일 · 실행 대상이 새로 남지 않는지.
- **Q2** 숫자 토큰 규칙을 출력의 모든 숫자 칸에 건 것 (줄 단위 · 토큰 전체 · 유한 · 목록 차례) 에 빠진 칸이 있나 — 판정 · 대상에 들어가는 값 (E · 힘 · P · V · 최종 좌표 · BFGS · 전자 수 · ecut · 문턱 · k 점 · 셀 · 처음 좌표 · Zval) 기준으로.
- **Q3** 응력 일관성 허용 (0.01 · 0.006 kbar — 반올림 상한) 이 맞나 · 너무 좁아 정상 7.4.1 출력을 거부할 경로가 있나.
- **Q4** 검사 뒤 쓰기 (`_commit`) 가 확인 목록 2 를 닫나 — 디스크 오류처럼 쓰기 도중 실패는 막지 못한다 (그때도 판정 파일은 맨 끝이라 없다) 는 범위로.
- **Q5** DY 확인 4 (EOS 의 (E, P, V) 결과 파일 결속) 를 이제 해제할 수 있나 — 파일 결속 + 값 판독 유효성.
- **Q6** DFT 진입 전에 더 닫을 것이 있나 — 없으면 사용자 비준만 남는가.
