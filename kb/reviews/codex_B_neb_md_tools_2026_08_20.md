### 2-1. ⚠ 문턱이 **양의 크기에 안 스케일한다** — 실측 반례가 오늘 나왔다

`MAX_IMAGE_JUMP_EV = 0.8` 은 "이웃 이미지 에너지 도약이 이보다 크면 밴드가 터진 것" 이라는
**절대 문턱**이다. 그런데 cc333 의 현재 밴드는:

```
0 → +0.619 → +1.762 → +2.279 → +1.761 → +0.618 → −0.000     (image 1 기준)
        ↑ 도약 1.14 eV — 문턱 0.8 초과
```

**이 밴드는 멀쩡하다.** 매끄럽고 대칭이고 끝점이 −0.0002 eV 로 닫힌다. 장벽 자체가 2.28 eV 인데
이미지 7개로 나누면 도약이 클 수밖에 없다. ⇒ **문턱을 장벽 높이의 분수**(예: Ea/3)로 두지 않으면
**장벽이 큰 계에서 멀쩡한 밴드를 불연속이라 부른다.**

⚠ 지금 오탐이 난 것은 **아니다** — cc333 은 QE `neb.x` 출력이라 우리 검출기가 안 돈다.
하지만 우리 MLIP NEB 를 장벽 큰 계(예: 이 c–b 홉, 2.07 eV)에 걸면 바로 걸린다.
Q4 의 "문턱이 자의적이다" 가 **추상적 우려가 아니라 실제 반례를 가진 문제**가 됐다.

## 3. 자기 지적 — 리뷰어가 이미 알고 시작할 것

오늘 내가 **같은 종류의 실수를 반복**했다. 리뷰 때 이 패턴을 의심할 것:

import json,glob,math
def beta(t,y,lo=2,hi=50):
    p=[(math.log(a),math.log(b)) for a,b in zip(t,y) if lo<=a<=hi and a>0 and b>0]

### B-R12. ⛔ **framework_check 가 fail 원소를 놓친다 — codex 반례를 그대로 재현했다**

내가 어제 "부동소수 잡음이 대표를 정한다" 를 고치려고 **β 를 0.05 로 양자화**했는데,
그게 **새 오탐**을 만들었다. codex 반례를 코드로 돌려 확인:

```
P  β=0.610  ratio=0.0100     ← β ≥ 0.60 ⇒ melting 이어야 한다
S  β=0.590  ratio=0.0200     ← 양자화가 같은 통, 비가 커서 대표로 뽑힘
대표 = S · 판정 = framework_mobile      ⛔ P 가 판정에서 빠졌다
```

**구조적 결함**: 대표 원소를 **먼저 고르고** 그 원소만 판정했다. 원소별 판정을 OR 하지 않았다.
비(ratio)에서도 같은 false-negative 가 난다.

**고쳤다** (2026-08-20): **원소마다 severity(0/1/2)를 내고 전체 max 로 판정**한다.
대표 표시는 판정과 **분리**했고 규칙도 나눴다 — fail 이 있으면 유발 원소 중 β 최대,
전부 rigid 면 β 가 1e-15 급 잡음이라 **비로** 고른다. `drivers`(판정 유발 원소)를 새로 보고한다.
selftest 3건 추가(codex 반례 · drivers 보고 · β 낮아도 비로 잡히는 OR).

⚠ **이미 나온 표는 재산출해야 한다** — §0 의 b2o3/modelc 표는 **고장난 판정기로 만든 것**이다.
값(β·ratio) 자체는 유효하지만 **verdict 열은 못 믿는다.**
