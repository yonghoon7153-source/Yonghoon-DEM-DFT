## Q3. voice-auto — 예산·자동화는 조건부 수용

- 기본 **대본 글자 수 ×3**, ep01은 **1저자 승인으로 누계 ×4**. v3 자동 보고의 **15,401/19,048자**와 v3.1 원장의 **15,572/19,048자**는 다른 시점이다. 뒤의 171자는 저자 피드백을 받아 한 문장의 후보 세 개를 더 만든 기록이다. 상한을 지킨 증거로 두 시점을 혼합하지 않는다. `16_voice_auto_report.md` 6행, `09_DECISIONS.md` 26행, `17_rubric` 31행.

## Q5. 공개 안전 — 현 공개 ZIP 수정 필요

**정적 재현.** 공개 ZIP의 `episode.json` 8행에서 공개 상태, 파일표에서 `script.md`, 끝부분 `public_check`에서 검사 통과를 확인한다. 그 ZIP에서 같은 대본 34행의 참고문헌 머리를 읽으면 짧은 리포 커밋 두 개가 나온다. `01_SKILL` 89–94행의 금지 규칙과 동시에 성립한다. 스킬 307–308행에 따르면 시청자는 대본을 내려받거나 화면에서 펼칠 수 있다. **같은 MP4로도 시청자용 대본과 공개 부속물을 교체해 이 반례를 고칠 수 있다.** 외부 게시가 이미 일어났다는 증거는 없다.

1. **공개 내용.** S0에서 허용된 연구 자료와 청중을 정하고, S2부터 공개 대본을 내레이션·자막·공개 문헌·허용된 설명으로 만든다. 제작 대본·에이전트 지시·내부 쪽지는 검토용에 둔다. 최종 ZIP에 실제 들어가는 각 텍스트, 첨부 이미지·썸네일·화면·오디오, 파일 메타데이터가 승인한 범위와 맞는지 점검한다. 금지 숫자 28개와 철회 패턴 42개는 알려진 표기에 한정된다. 한글 읽기·반올림·단위 변환·값 없는 방향 서술도 맥락으로 확인한다. 숫자가 우연히 겹친 경우에는 필드·단위·근거를 남긴다. 공개 README가 밝힌 타임라인 0.5 ms 반올림은 이런 오탐의 실례다.
2. **홈 경로와 준거 집합.** Windows·POSIX 절대 홈 경로, 상대 경로 속 개인/내부 식별자, 문구·파일명·참고문헌 머리를 검사한다. 공개 DOI와 **내부 Git 식별자**, 결과 숫자와 재생 시각은 서로 다른 필드다. 검사 보고에는 파일·위치·규칙만 적는다. `12_qc_final_check` §5의 **제작 텍스트 10개**와 배포 `episode.json`의 **공개 검사 파일 9개**는 서로 다른 집합이다. 이번 리뷰 재료에도 비공개 맥락이 있는 원문이 있어 이 재료 ZIP은 시청자용 전달본으로 쓸 수 없다.
3. **외부 TTS 경계.** 오디션·본합성·재시도·예비 서비스 각각에 보내는 실제 문장을 검사한다. 공개 한 줄이라도 smart 설정의 앞뒤 문장이 내부 자료면 전송을 멈춘다. 내부판의 추론·오류 처리·로그는 로컬 경로를 사용한다. 승인된 모델 파일 다운로드와 내부 대본 전송을 구별한다. 예비 공급자 전환, 측정용 외부 받아쓰기, 보이스 클론으로 묵시적으로 넘어가지 않는다. 내부 로컬 경로가 준비되지 않으면 무음 후보로 둔다. `00_instructions_verbatim.md` 176–182행.
4. **공개 직전.** 청취용 후보의 접근 범위와 실제 공개 ZIP 해시를 기록한다. 현 ZIP은 ‘배포용 대본 재생성 → 모든 공개 역할 확인 → 기존 영상과 새 ZIP 연결 → 저자 승인’까지 보류다. 검사기가 기록한 ‘0 hits’는 보존할 역사적 실행 기록이다. 이번 지적은 스킬과 산출물의 대조에서 나온 것이며 웹앱 구현의 작동 여부를 새로 판정하지 않았다.
