# T12 현재 소비자 계약·합성 경계 인계

사용자는 메인보드를 `claude/stoic-knuth-NObVQ`로 명확히 지정했고 Claude 반입은 나중에 함께 하기로 했다. 그 반입과 별개로 승인된 로컬 T12 준비를 계속했다. 새 가지는 `codex/dem-gen2-t12`이며 기존 DEM 준비 끝 `2443a63eaa87d52e385a35f8bab4225efa0d25fe`에서 분리했다.

## 반입 범위

- 구현 후보 자리: `<<sha:Add pinned T12 consumer contract and synthetic boundary probes>>`. 최종 전체 SHA·범위는 외부 PIN.txt와 실제 원격 가지로 전달한다. 이 쪽지는 실제 push 완료를 미리 주장하지 않는다.
- 최신 ULPR 소비 핀은 `01c1aaf5be8acdf7d1716f34cc86fc77d8e27362`다. 사용자가 외부 반박 검토 중인 그 가지와 ZIP은 변경하지 않았다.
- [소비 계약과 합성 시험](../../reviews/dem_gen2_t12_consumer_contract_20261024.md), 새 자료 양식·소스 지문·직접 검사 영수증, [실자료와 WSL 명령 안내](../../reviews/dem_gen2_t12_external_inputs_20261024.md)를 추가한다. 옛 readiness 문서·증거는 역사 기록 그대로다.
- 이 가지의 변경은 DEM 준비 끝 이후만이다. 앞선 DEM 트랙을 이미 받았다면 그 커밋을 중복 반입하지 않는다. 독립 트랙의 cherry-pick 뒤 SHA 대응은 기존 인계 규칙대로 기록한다.

## 검사와 공유 배선

새 직접 시험은 `python3 -I scripts/test_dem_gen2_t12_consumer_contract.py --repo .`다. 실행할 ULPR 소스는 현재 checkout이 아니라 위 고정 Git object의 5개 모듈·params다. 누락 객체나 다른 hash는 오류이며, 자동 fetch는 없다. 객체가 없는 환경에서는 해당 원격 가지를 명시적으로 fetch해야 한다.

현재 공유 `check_all.sh`·`discipline.yml`·자기검사 원장은 변경하지 않았다. 따라서 새 T12 시험과 앞선 D2·D3 직접 시험은 기존 공유 155개에 자동 포함되지 않는다. Claude가 공유 파일을 반영할 때 아래를 함께 처리한다.

1. 새 T12 직접 명령을 공용 검사와 CI에서 실제 호출하고 필요한 ULPR 고정 object가 있는지 확인한다. CI의 기존 `fetch-depth: 0` 선언만으로 새 시험 호출을 대신하지 않는다.
2. 앞선 D2·D3 쪽지의 신규 직접 시험도 두 경로에 연결한다. 통합된 트리의 실제 실행 결과를 남긴다.
3. 공유 155개는 현재 DEM 파생 트리를 검사하고, T12 직접 시험은 고정 ULPR 소비 함수를 검사한다. 서로 다른 소스 범위와 사례 수를 합산한 하나의 인증 수치로 쓰지 않는다.

독립 검토·새 전체 게이트의 실제 결과는 후속 증거 쪽지로 남긴다. 새 원장 결함을 임의 생성하거나 기존 claimed_fixed를 closed로 바꾸지 않았다. 공유 원장·CLAUDE·봉인 파일 수정은 없다.

## 실제 조건

`physical_ready=false`, P2 `T12=NOT_RUN`이다. 실제 P2 생산 덱·인터페이스 등록·R-a 끝 S0·이력/복원/dt/2/재개 자격·Q7–Q9 원자료·지정 핀 외부 판정은 합성 시험으로 채우지 않는다. P2 발사 명령은 아직 없다.

LHS B7은 LHS 리뷰 핀과 다르다. 정본 묶음의 B7 정의는 등록·수정이 반영되어 push된 메인보드의 전체 커밋이다. 실제 B7과 새 ROOT·WSL 경로가 정해지기 전에는 안내 §2의 읽기 전용 신원 확인만 바로 사용할 수 있다. 사용자 WSL·물리 계산·스케줄러·Claude 통합은 이번 로컬 준비에서 실행하지 않았다.
