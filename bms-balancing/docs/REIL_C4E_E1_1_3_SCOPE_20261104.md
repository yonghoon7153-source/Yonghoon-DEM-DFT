## 2. 정할 것 1 — 긴 run 을 어떻게 띄우나 (셸 도구 상한 < run 기한)

- **사실:** 이 세션의 셸 도구는 전경 600 s · 배경 7,200 s 가 상한이고, 배경 상한에 닿으면 명령을 멈춘다. run 의 자식 timeout 은 10,800 s, run 모듈의 측정
  마감은 9,000 s 다. 그래서 E1-0b 처럼 "배경 실행으로 띄우고 끝 알림" 만으로는 run 이 2 h 를 넘을 때 셸 도구가 launcher 를 끊는다 (기록 없이).
- **A (권장) — 분리 실행 + 읽기 전용 감시:**
  - run 줄을 셸 도구의 호출과 떨어진 프로세스로 띄운다: `setsid nohup sh -c '<고정 run 줄>; rc=$?; set -C; printf "%s\n" "$rc" > <E>/05_run.outer_rc.txt'
    > /dev/null 2>&1 < /dev/null &` (정확한 문자열은 요청서에 고정). launcher 의 timeout · 정리 · 기록은 그대로다.
  - 끝은 감시 루프로 기다린다: 셸 도구 배경 실행의 `until [ -e <E>/05_run.outer_rc.txt ]; do sleep 30; done` (읽기만 · 개입 0). 감시가 2 h 상한에 닿으면
    감시만 다시 건다 (run 에 영향 없음). 외곽 반환 파일이 생긴 뒤 판정기를 전경으로 띄운다.
  - 위험 (공개): run 도중 세션 · 컨테이너가 끝나면 run 과 기록을 잃는다 → 멈춤 · 재시도 없음 · 결과 검토.
  - **탐침 한 번 (채택하시면 · 요청서 작성 전):** `SP/detach_probe_20261104/` 에서 `sleep 150` 뒤 표지 파일 하나를 쓰는 분리 프로세스를 띄우고, 띄운 셸 호출이
    돌아온 뒤 (다른 도구 호출에서) 표지가 생기는지 본다. 연구 코드 · 네트워크 · 저장소 쓰기 0 · 결과는 원장에 적는다. 안 되면 A 를 접고 C 를 다시 묻는다.
- **B — 셸 도구 배경 실행 (2 h 상한):** 고정 예산 10,800 s 와 맞지 않는다 (2 h 를 넘으면 기록 없이 끊긴다). 권장하지 않는다.
- **C — run 의 기한을 2 h 안으로 줄인다:** run 모듈 · launcher 바이트가 바뀌어 새 RED / GREEN · 검토가 필요하다. 권장하지 않는다.
- identity 는 전경, fetch 는 셸 도구 배경 실행 (최악 약 860 s) 으로 띄운다 — A · B · C 와 관계없다.
