### RR2-01 — P2: malformed rc가 성공 런으로 건너뛰어져 결과 이후 재개가 허용됨

**위치:** scripts/rint_r_chain.py:3869, 관련 :3771–3775, :3893–3911, :4460–4485.

orphan_cause의 성공 분기가 by == 'chain' and cause is None and rc == 0을 사용한다. Python에서 JSON false와 0.0은 0과 같으므로 성공한 런으로 건너뛴다. 같은 파일의 runner_rc_failed와 ResumeRunner._src_done은 정수형 여부를 검사한다. 서로 다른 소비자가 같은 필드를 다르게 읽는다.

**재현 조건:** 같은 토큰·이름에 결속된 confirmed 종료 기록, 첫 결과 표지 있음, 단계 요약 없음, 로그에 Traceback / KeyError 있음, payload 산출물 없음. 종료 기록의 rc 한 칸만 바꾼다. 호스트 신원은 고정 모의값이고 부모는 종료된 것으로 제공한다.

| rc | 원인 판정 | 실제 Git recover 결과 | 다음 --resume 자격 |
|---|---|---|---|
| 정수 1 | runner_rc | interrupted / post / resume_ok=false | RESUME_NOT_ALLOWED |
| 불리언 false | parent_dead | interrupted / post / resume_ok=true | 통과 |
| 실수 0.0 | parent_dead | interrupted / post / resume_ok=true | 통과 |

표의 recover는 사전 계산만이 아니라 임시 Git 원장에 결과 줄을 실제 커밋한 결과다. 다음 attempt_order_problem도 실제 함수로 검사했다. 해당 런은 _src_done에서는 미완료로 읽혀 재실행 대상이 되고, 비교할 기존 payload가 없으면 determinism=assumed 경로로 간다.

**무너지는 결론:** 결과 이후 코드 실패를 자원·인프라 중단으로 잘못 승격하지 않는다는 재시도 정책의 완전성. PC6-13의 전체 경로 종결은 부분이다. PC8-02의 토큰·이름 결속 수정 자체는 유효하지만, 그 뒤의 rc 의미 검사는 덜 닫혔다.

**한계:** 정상 내부 생산자가 false/0.0을 생성하는 경로는 발견하지 않았다. 최초 recover 전 잘못 기록되거나 한 필드가 편집된 종료 기록이 전제다. 모든 원장·해시를 동시에 고친 위조가 아니다. 실제 물리 런의 잘못된 재실행이나 최종 숫자 false-green까지 실행한 것은 아니다. 이 조건을 명시한 채, 재개 자격에 직접 영향을 주므로 최종 통합 등급을 P2로 정했다.

**최소 수정:** 성공 건너뛰기에 type(rc) is int and rc == 0을 요구한다. 또는 공통 성공/실패 판독 함수를 모든 소비자에 쓴다. 숫자 0, false, 0.0, 문자열 "0", null에 대해 요약 없는 by-chain → recover → 결과 줄 → 다음 resume까지 시험한다. 메모리 안에서 한 줄을 바꾼 대조에서는 false/0.0이 runner_rc/resume_ok=false로 돌아오고 정상 정수 0은 유지됐다. 제출 코드는 고치지 않았다.

재현:
~~~text
python -B runtime_review/probe_runtime.py
~~~
증거: runtime_review/residual_rc.json, residual_rc_integration.json, candidate_fix_results.json. Linux 신원·잠금 대체 범위는 같은 폴더 REVIEW.md와 스크립트 머리말에 명시했다.

## 10. Q10 — ⑦ SBE 물리 개발 탐침

**조건부 허용을 권고하되, 미결 숫자를 둔 즉시 열람 허용은 아니다.** S0-1 → s_min → ⑥ 뒤, SBE만 열고 추가 DBE 입력/결과는 열지 않으며 모든 시도·실패를 보존한다. 개발 R_j,0를 등록 캠페인 값으로 재사용하지 않는다.

⑦의 σ 사다리를 본 뒤 아직 빈 점 수 상한·역상 폭·SV 문턱·등급 관련 값·실행 정책을 유리하게 최초 선택하는 것도 사후 적응이다. “기존 값을 바꾸지 않았다”로 회피할 수 없다. 결과에 민감한 선택을 **⑦ 열람 전에** 고정하거나, ⑦을 숫자 봉인 뒤로 미루는 것이 최소 조건이다. 비용으로 정하는 설정은 ⑥의 근거를 먼저 기록한다.

독립 근거가 있는 버그는 별도 finding·실패 시험·수정 diff를 남길 수 있다. 마음에 드는 결과를 위한 법칙/문턱 조정은 금지한다. 다시 보정해도 이미 본 개발 정보는 사라지지 않으므로 최종 문서에 노출 이력을 남긴다. 기존 DBE 실험값이 알려져 있다는 사실도 유지하며 이를 새 독립 holdout이라고 부르지 않는다.
