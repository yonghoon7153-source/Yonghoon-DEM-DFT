# 코팅 코어-쉘 표현의 ⓪단계 관문 — δ(겹침) 분포 실측 (2026-08-19)

**질문**: 코팅된 AM 을 **반경 R+t 의 한 구**로 그리면, 압축이 진행돼 **코어가 서로 닿는**
전이(So 2022 의 "저압 차폐 → 고압 해제")를 우리 DEM 이 낼 수 있는가?
기하 조건은 하나다 — **δ ≥ 2t**.

**코드 리뷰(2026-08-19)의 판정**: *"코퍼스 실측 ⟨δ⟩ ≈ 0.0739 µm 인데 코어가 닿으려면
δ ≥ 2t = 0.5 µm 이므로 δ_max ≪ 2t ⇒ 스위치가 **영구 OFF**"* → **이 판정을 실측으로 검증**했다.

**결론: 절반만 맞다.  판정의 논거(평균 비교)가 틀렸다.**

---

## 1. 방법

기존 접촉 덤프 4개 + 같은 타임스텝의 atom 덤프 4개.  GPU·재실행 없음.
- `compute cpl all pair/gran/local pos id force force_normal force_tangential torque contactArea delta contactPoint`
  ⇒ `delta` = `c_cpl[23]` (`scripts/parse_liggghts.py:37` 의 정본 매핑).
- **단위**: LIGGGHTS 시뮬 길이 = **mm** (박스 0.05 = 50 µm RVE, `r_AM_P 5.0e-3` = 5 µm) → ×1000 = µm.
- 타입: `dem_scripts/thin6_seed.liggghts:71-73` — **1 = AM_P · 2 = AM_S · 3 = SE**.
- 도구: `/tmp/delta_bytype.py` (일회성 프로브, 리포 파일 무변경).

★★ **정정 (같은 날, §6 추가) — 이 네 덤프가 바로 4압력 세트였다.**  처음에는 "타임스텝만 다른
세트" 로 봤는데, 각 atom 덤프의 phase-virial f_AM 이 CLAUDE.md 의 4압력 실측
(**0.726 / 0.768 / 0.794 / 0.763** @ P=100/200/300/600)과 **소수 셋째 자리까지 일치**한다:
측정 **0.7258 / 0.7676 / 0.7938 / 0.7625** (`scripts/dem_am_load_fraction.py --atom-dump`).
⇒ 1910000=P100 · 1940000=P200 · 2440000=P300 · 2870000=P600.  **압력 분해가 가능하다 (§6).**
아래 §2–3 은 네 압력을 **풀링한** 분포다.

그 접촉들이 AM 백본에서 차지하는 위치**로 결정된다 (퍼콜레이션 문제).

## 3. ★ 판정 — 코어가 닿는 AM–AM 접촉 비율

| 쉘 두께 t | 필요 δ ≥ 2t | 도달 접촉 | 비율 |
|---|---|---|---|
| 0.02 µm | 0.04 | 1,221 / 2,052 | **59.5 %** |
| 0.05 µm | 0.10 | 573 | **27.9 %** |
| 0.10 µm | 0.20 | 192 | **9.4 %** |
| 0.15 µm | 0.30 | 85 | 4.1 % |
| 0.25 µm | 0.50 | 14 | **0.68 %** |
| 0.50 µm | 1.00 | 0 | **0 %** |

**⇒ 리뷰 판정의 재판정**

- ✅ **So 2022 규약(SE primary Ø0.5 µm ⇒ t = 0.25 µm)에서는 리뷰가 맞다** — 0.68 % 는
  퍼콜레이션을 만들 수 없다.  그 논문의 "200 MPa 초과에서 해제" 를 **단일구 반경확대로는
  재현 못 한다**.
- ⛔ **그러나 "영구 OFF" 라는 일반 진술은 틀렸다** — t ≤ 0.10 µm 에서는 **9~28 %** 가 닿는다.
  얇은 코팅에서는 스위치가 **살아 있다**.
- ⛔ **논거가 틀렸다**: 리뷰는 **평균**(⟨δ⟩ 0.0739)으로 문턱을 논했는데, 문턱 통과는
  **꼬리**가 정한다.  실제 분포는 med 0.055 · p99.9 0.681 · **max 0.757 µm** 로
  평균의 **10배**까지 뻗는다.  ⇒ **평균으로 문턱 논증을 하지 말 것** (일반 교훈).

## 4. ⚠ 이 측정이 말하지 **않는** 것

1. **코팅 없는 침대에서 잰 값이다.**  실제로 쉘을 씌우면 유효 반경이 커져 패킹이 바뀌고
   δ 분포 자체가 이동한다.  ⇒ 이것은 **자릿수 선별(screen)** 이지 예측이 아니다.
2. ~~압력 분해가 없다~~ → **§6 에서 해소됐다** (네 덤프가 곧 4압력 세트였다).
   남는 유보는 §6 의 단서 3개(계수 잡음 · n(AM–AM) 비단조 · 코팅 없는 침대)다.
3. **접촉 수 ≠ σ_e.**  §2 의 0.59 % 지적대로, 닿는 접촉이 AM 백본을 잇는지는 별개 문제다.
4. **A3(질량·조성 규약 4곳 파손)은 그대로 살아 있다.**  이 측정은 A1 만 다룬다.
   단일구 반경확대를 쓰려면 A3 를 따로 해결해야 하고, 그것이 **B1 ①(SE 좌표 편향)** 이
   여전히 유리한 이유다.

압력 식별은 §1 정정대로 **실측 대조**로 확정했다 (추측 아님).
`/tmp/delta_pressure.py`, part1+part2 전부 사용.

| P (MPa) | n(AM–AM) | med δ | p90 | p99 | MAX | t=0.02 | t=0.05 | **t=0.10** | t=0.15 | t=0.25 | t=0.50 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 100 | 437 | 0.0186 | 0.0771 | 0.2342 | 0.3494 | 29.5 % | 7.6 % | **1.4 %** | 0.5 % | 0 % | 0 % |

**★ 단조성 — t ≤ 0.25 µm 에서 네 압력 전부 단조 증가.**
t = 0.10 µm 에서 **1.4 → 24.4 % (18배)**.  ⇒ **So 2022 의 "저압 차폐 → 고압 해제" 는
우리 DEM 이 단일구 반경확대만으로 낼 수 있다** — 단 **쉘이 충분히 얇을 때만**.

⚠ 세 가지 단서:
1. **t = 0.25 µm(So 자신의 규약)은 600 MPa 에서도 1.9 %** 다.  So 의 결과를 그 규약 그대로
   재현하는 것은 여전히 불가능하다 — §3 결론 유지.
2. **계수 잡음**: n(AM–AM) 이 437~550 뿐이라 t=0.25 의 1.9 % = **10 접촉**이다.
   √n 기준 ±30 % 수준의 불확실성 ⇒ 작은 칸은 **자릿수로만** 읽을 것.
   ⚠ 표의 t=0.50 행이 전부 0 인 것은 "평탄" 이지 단조성 위반이 아니다 (프로브의 라벨 규칙이
   전부-0 을 "비단조" 로 찍는데, 그것은 도구의 표기 결함이다).
3. **n(AM–AM) 자체가 단조가 아니다** (437 → 550 → 549 → 516).  압력이 오르면 접촉이
   생기기만 하는 게 아니라 **재배열로 없어지기도 한다** ⇒ 비율 분모가 압력마다 다른 모집단이다.

★ **§4 의 유보는 그대로다** — 이것도 **코팅 없는 침대**에서 잰 값이라 자릿수 선별이다.

## 7. A3 정량 — 단일구 반경확대의 **대가** (⓪단계 #1)

§6 이 "얇은 쉘이면 스위치가 산다" 를 보였으므로, 이제 그 표현의 **비용**이 결정적이다.
`verify_deck` 은 현행(무코팅) 덱에서 **+0.01 %** 로 통과한다 — 규약이 맞다는 뜻이고,
코팅 덱에서 그것이 얼마나 깨지는지를 산술로 낸다.

기전: LIGGGHTS `particledistribution/discrete` 는 질량분율 → 개수를 `ρ·(4/3)πr³` 로 만든다.
반경만 R+t 로 올리고 `density constant 4800` 을 두면 입자질량이 `(1+t/R)³` 배 과대 ⇒
**같은 질량분율에서 개수가 그만큼 준다.**  반경은 `dem_scripts/thin6_seed.liggghts:19-20`
(`r_AM_P 5.0e-3` = 5.0 µm · `r_AM_S 2.5e-3` = **2.5 µm**).

| t (µm) | AM_P 개수 | AM_S 개수 | AM_P 부피 | AM_S 부피 | ρ_eff AM_P | ρ_eff AM_S |
|---|---|---|---|---|---|---|
| 0.02 | -1.2 % | **-2.4 %** | +1.2 % | +2.4 % | 4767 (-0.7 %) | 4734 (-1.4 %) |
| 0.05 | -2.9 % | **-5.8 %** | +3.0 % | +6.1 % | 4718 (-1.7 %) | 4639 (-3.4 %) |
| 0.10 | -5.8 % | **-11.1 %** | +6.1 % | +12.5 % | 4639 (-3.4 %) | 4489 (-6.5 %) |
| 0.15 | -8.5 % | **-16.0 %** | +9.3 % | +19.1 % | 4562 (-5.0 %) | 4351 (-9.4 %) |
| 0.25 | -13.6 % | **-24.9 %** | +15.8 % | +33.1 % | 4419 (-7.9 %) | 4104 (-14.5 %) |

### ★ 이것이 A3 의 실체다 — "개수가 준다" 보다 나쁘다

1. **AM_S 가 AM_P 의 2배로 민감하다** (R 이 절반이므로).  ⇒ 코어-쉘을 단일구로 넣으면
   **bimodal 비율 P:S 가 조용히 바뀐다**.  우리 Furnas dip·패킹 트랙 전체가 P:S 위에 서 있으므로
   이것은 부수효과가 아니라 **설계 변수를 건드리는 것**이다.
2. **ρ 보정도 입자별로 달라야 한다** (표의 ρ_eff 열; t=0.10 에서 AM_P −3.4 % vs AM_S −6.5 %).
   그런데 `particletemplate/sphere` 는 ρ 도 r 도 **단일값**이라, 보정하려면 템플릿을 쪼개야 한다.
3. **`verify_deck` 이 자동으로 안 잡는다** — 그 검산은 무코팅 덱 규약에 대해 도는 것이고,
   코팅 덱에 대해 다시 돌리는 게이트가 **없다**.

⇒ **판정**: t = 0.05 µm 이하면 개수 편차 ≤ 5.8 % 로 감내 가능하고, §6 이 그 두께에서
스위치가 산다고(P100 7.6 % → P600 58.3 %) 말한다.  **t ≈ 0.05 µm 가 두 제약이 겹치는 창**이다.
t ≥ 0.15 µm 에서는 AM_S 개수가 16 % 이상 틀어져 **P:S 를 오염**시키므로,
그 두께에서는 **B1 ①(SE 좌표 편향)** 이 여전히 옳다.
⚠ 이 창은 **산술**이지 검증이 아니다 — 실제로 그 덱을 돌려 `verify_deck` 과 P:S 를 재확인할 것.
