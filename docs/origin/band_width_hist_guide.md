# Origin — 대표 구조 선택 폭 분포 (가로 히스토그램)

세미나 12장 오른쪽 작은 패널. **가로로 누운 히스토그램**이다 —
세로축이 폭(eV/atom), 가로축이 종 수.

원본: `db/properties/seminar_table_stability_band.csv` 의 `band_width_eV_per_atom` 열 (88행).
파이썬 판: `tools/figures/plot_seminar_2026_08.py: fig_stability_band` 의 오른쪽 패널.

---

## 왜 두 가지 길이 있나

Origin 의 Histogram 은 **세로**로만 나온다(도수가 Y). 우리가 원하는 건 그 반대다.
두 길이 있고, **A 를 권한다.**

| | 방법 | 장점 | 단점 |
|---|---|---|---|
| **A (권장)** | 원자료로 Histogram → **X-Y 축 교환** | Origin 이 구간을 계산 — 구간 바꾸기 쉬움 | 버전에 따라 메뉴 위치가 다름 |
| B | 미리 구간화한 표로 **가로 막대** | 확실하게 가로로 나옴 | 구간을 바꾸려면 표를 다시 만들어야 함 |

⚠ **A 와 B 의 입력을 섞지 말 것.** 구간화된 표를 Histogram 에 넣으면 Origin 이
그걸 **다시** 구간화한다 (X 축이 0–500 으로 나오는 사고, 2026-08-18). B 는 반드시
**막대(Bar)** 로 그린다.

---

## A. 원자료 → Histogram → 축 교환  (권장)

### A-1. 자료 넣기

`seminar_table_stability_band.csv` 를 Import 한 뒤 **`band_width_eV_per_atom` 한 열만**
쓴다 (88행). 그 열을 선택.

### A-2. 그리기

```
Plot ▸ Statistical ▸ Histogram
```

### A-3. 구간 맞추기 (파이썬 판과 같게)

그래프의 막대를 더블클릭 → **Data** 탭:

```
Bin Size (Increment)     0.02
Begin                    0
End                      0.20
```

이렇게 하면 10 구간이 되고 도수는 아래 표와 같아야 한다. **다르면 구간 설정이 안 먹은 것.**

| 구간 | 중심 | 종 수 |
|---|---|---|
| 0.00 – 0.02 | 0.010 | **26** |
| 0.02 – 0.04 | 0.030 | 19 |
| 0.04 – 0.06 | 0.050 | 16 |
| 0.06 – 0.08 | 0.070 | 13 |
| 0.08 – 0.10 | 0.090 | 8 |
| 0.10 – 0.12 | 0.110 | 4 |
| 0.12 – 0.14 | 0.130 | 0 |
| 0.14 – 0.16 | 0.150 | 0 |
| 0.16 – 0.18 | 0.170 | **1** (V₂O₅ 0.164) |
| 0.18 – 0.20 | 0.190 | **1** (ZrO₂ 0.180) |
| | 합 | **88** |

### A-4. 눕히기

```
Graph ▸ Exchange X-Y Axis
```

(Origin 2018 이전이면 `Graph: Exchange X-Y Axis` 메뉴가 없을 수 있다 → **B 로 간다**.)

### A-5. 서식

그래프 창을 활성화하고 Script Window 에 `band_width_hist.ogs` 를 붙여넣는다.

## B. 미리 구간화한 표 → 가로 막대  (A 가 안 될 때)

### B-1. 워크시트를 손으로 만든다

| A(X) = bin_center | B(Y) = count |
|---|---|
| 0.010 | 26 |
| 0.030 | 19 |
| 0.050 | 16 |
| 0.070 | 13 |
| 0.090 | 8 |
| 0.110 | 4 |
| 0.130 | 0 |
| 0.150 | 0 |
| 0.170 | 1 |
| 0.190 | 1 |

### B-2. 그리기

```
Plot ▸ Basic 2D ▸ Bar          ← Column 이 아니라 Bar (가로 막대)
```

Bar 는 X 열이 **세로축**으로 간다 — 그래서 축 교환이 필요 없다.

### B-3. 막대를 붙이기 (히스토그램처럼)

막대 더블클릭 → **Spacing** 탭 → `Gap Between Bars (in %)` = **0**

### B-4. 서식

같은 `.ogs` 를 쓴다. 다만 **B 는 축 범위가 구간 중심 기준**이라 `layer.y.from/to` 를
`0.0` / `0.20` 대신 `0.0` / `0.20` 그대로 두면 맨 위 막대가 반쯤 걸린다 →
`.ogs` 안의 해당 줄 주석을 보고 `0.205` 로 바꾼다.

## 기준선 두 개 (둘 다 필요하다)

이 그림의 요점은 막대가 아니라 **어디에 선이 있느냐**다.

| 선 | 값 | 서식 | 뜻 |
|---|---|---|---|
| 중앙값 | **0.0373** | 검정 점선(dot), 1 pt | "대표 하나 골라도 된다" 의 근거 |
| 넓음 기준 | **0.10** | 빨강 파선(dash), 1.3 pt | 이 위 **6 종**은 대표 선택이 실제 선택 |

넣는 법 — 레이어 더블클릭 ▸ **Grids** 탭이 아니라 **Reference Lines** 탭:

```
Y = 0.0373   Line: Dot    Color: #404040
Y = 0.1      Line: Dash   Color: #BE123C
```

(Reference Lines 탭이 없는 버전이면 `Insert ▸ Straight Line` 로 수평선 두 개.)

## 축 제목

```
Y (세로) :  band width  (eV / atom)
X (가로) :  species
```

⚠ **"band width" 가 무엇인지는 캡션이 진다** — 한 종의 세 챔피언 구조 사이의
host 상대 안정성 최대−최소다. **재현 산포가 아니다** (세 구조는 자리·시드가 다르다).
그림 안에 그 문장을 넣지 않는다.

---

## ⛔ 축 제목이 안 보인다 — 진단과 해법 (2026-08-18, 두 번 헛짚고 잡음)

### 증상 구분이 먼저다

| 어디서 안 보이나 | 원인 | 해법 |
|---|---|---|
| **Origin 창에서는 보이는데** 붙여넣기·내보내기에서 없다 | 제목이 **흰 종이 밖(회색)** 에 있다. 복사는 종이만 가져간다 | 아래 ① |
| Origin 창에서도 없다 | 제목 개체 자체가 없다 | `label -xb species;` / `label -yl …` 다시 실행 |

우리가 밟은 것은 **위쪽**이다. 레이어를 12 → 5.2 cm 로 줄이면 종이는 따라 줄지 않고,
`page.margincontrol = 1`(tight)을 걸면 이번엔 종이가 **레이어에만** 맞아 제목이 밖으로 밀린다.

### ① 종이를 라벨까지 포함해 키운다 — 전용 기능이 있다

```
Graph ▸ Fit Page to Layers...
```

이 대화상자가 **라벨을 포함해서** 페이지를 다시 잡는다. 여백(Margin)을 조금 주고 OK.
그림이 종이 안으로 들어오면 끝이다.

### ② 그래도 남으면 손으로

```
Format ▸ Page...   ▸ Dimensions  → Unit cm, Width 9, Height 12
Format ▸ Layer...  ▸ Size        → Left 2.4, Top 0.6, Width 5.2, Height 9
```

레이어를 종이 안쪽으로 들여놓아 왼쪽 2.4 cm(y 제목) · 아래 2.4 cm(x 제목) 자리를 만든다.

⛔ **LabTalk 로 `page.width` / `page.height` 를 대입하지 말 것.** 버전에 따라 안 먹는다
   (2026-08-18 실패). `.ogs` 에서 뺐다 — 페이지는 GUI 로만 만진다.

### ③ 가져갈 때

- PowerPoint 로: 그래프 창 제목줄 **우클릭 ▸ Copy Page** → 붙여넣기
- 파일로: `File ▸ Export Graphs` 의 `Margin` 을 **Tight 가 아니라 Page**
  (Tight 로 내보내면 방금 만든 제목 자리를 다시 잘라낸다)

⚠ 눈금 글씨 28 pt 는 **12 cm 패널 기준(BML)** 이다. 5.2 cm 에서는 상대적으로 커 보이는데,
   슬라이드에서 작게 들어가는 패널이라 그게 맞다. 줄이지 말 것.

## 이 안내가 **못 하는 것**

- 왼쪽 큰 패널(88종 밴드 + 이름표)은 다루지 않는다. 그건 종마다 세로선 하나라
  Origin 에서는 **Floating Column / Y Error** 로 따로 만들어야 한다.
- 두 패널을 한 그래프에 합치는 법(Layer 관리)은 안 적었다. 슬라이드에서는 파이썬 판을
  그대로 쓰거나, 이 패널만 Origin 으로 다시 그려 옆에 붙이면 된다.
- Origin 버전별 메뉴 차이를 다 담지 못한다 — A-4 가 안 되면 B 로 간다.
