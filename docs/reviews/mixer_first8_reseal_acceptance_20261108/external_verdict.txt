## 4. 반박 결과와 남는 미검증

**새 필수 반례·수정 요구 없음.** 누락 의존·해시 변조·활성화·운영 `source_pin`/`allowed_submissions` 추가는 거부됐다. 소스/자산의 같은 값 비교를 실제 관측으로 확대하거나, 새 후보 핀을 기존 수용 핀과 같은 역할로 표시한 부분도 발견하지 못했다.

수용의 한계는 다음과 같다.

- 후보 파일 수용은 **운영 sibling seal 교체 승인이나 operational activation이 아니다**. 임의로 이름/위치를 바꾸거나 driver를 실행하지 않았다.
- 원 Git 저장소를 갖춘 `verify_candidate.py --repo ... --output ...`의 전체 양성 CLI 실행은 이번 독립 환경에서 하지 않았다. Git 객체 읽기 모의를 그 실행으로 표기하지 않는다.
- Python/NumPy/SciPy·실행 바이너리·사이트 환경은 12소스 봉인 밖이다. 일반 악의적 파일시스템·동시 변경·ABA 방어, 미래 소비자, 임의 새 JSON 운영 키 전수 방어까지 인증하지 않는다. README의 한정과 일치한다.
- STL은 바이트만 대조했다. 새로운 형상 검증·실제 접촉/혼합 지표·MPM 피복 인증은 없다.
- 기존 launch의 **추적 73파일** 보존을 확인한 것이지 디렉터리의 임의 비추적 파일 부재까지 확인한 것은 아니다.

## 5. 로컬 재현 안내

증거 ZIP을 새 검토 폴더에 풀고 Python 환경에 NumPy/SciPy를 준비한다. 다음은 소스 사본·합성 텍스트·검토용 로컬 Git만 사용하며 운영 driver를 호출하지 않는다. 기존 결과를 보존하려면 별도 복사본에서 실행한다.

```text
python -I -B -X utf8 independent_static.py
python -I -B -X utf8 verifier_main_mock.py
python -I -B -X utf8 verifier_probe.py
```

첫 명령이 기존 준비14를 실제 수용 소스 사본으로 실행한다. 둘째는 **Git 경계 모의**이며 셋째는 후보 계약 변이와 **새 로컬 누락 객체** 시험이다. 실제 ibb/WSL·원자료·sbatch·MPI·DEM·제출·등록·배포·원장 수정은 포함하지 않는다. 상세 정적 근거는 `boundary_review.md`, `verifier_attack.md`를 함께 보존했다.
