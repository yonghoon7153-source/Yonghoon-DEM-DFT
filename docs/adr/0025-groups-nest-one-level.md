# ADR 0025 — 그룹은 한 단계만 겹친다, 그리고 셀은 한 자리에만 산다

- 상태: 채택 (2026-08-25)
- 관련: ADR 0024(세 섹션 한 셀), `apps/api/app/deps.py:group_scope`,
  `apps/web/src/components/GroupFilter.tsx`

## 맥락

그룹은 지금까지 평평했다. 한 사람의 실험이 쌓이면서 그 평평한 목록이
"건식 시리즈", "건식 시리즈 80wt%", "건식 시리즈 80wt% 재현", "건식 시리즈 2차"
처럼 **이름 안에 계층을 적는** 방식으로 늘어났다. 이름으로 적은 계층은
거르개가 되지 못한다 — 드롭다운에서는 그냥 네 개의 다른 그룹이다.

노션에서 페이지 안에 페이지를 두듯, 그룹 안에 그룹을 두는 것이 요구였다.

## 결정

### 1. `ExperimentGroup.parent_id` — 자기 자신을 가리키는 nullable FK

깊이는 **2 로 제한한다**. 그룹 → 소그룹 → 셀. 소그룹이 또 소그룹을 갖는 것은
API 가 422 로 거절한다 (`_validate_parent`).

이유는 화면이다. 고르는 자리는 드롭다운 **둘**이고 (`GroupFilterFields`),
그것이 이 구조의 유일한 표현이다. 임의 깊이를 허용하면 **저장은 되는데 화면에
없는** 상태가 생긴다 — 3단에 넣은 셀은 저장되고 나서 어느 드롭다운 조합으로도
보이지 않는다. 실패가 조용하다.

깊이를 2 로 묶으면 순환도 생기지 않는다. 자기 자신을 부모로 삼는 것과, 이미
자식을 가진 그룹을 남의 밑으로 미는 것 — 둘만 막으면 끝이고, 재귀도 방문
표시도 필요 없다.

### 2. 셀은 **한 노드**에만 속한다

`Sample.group_id` 는 여전히 하나다. 소그룹에 든 셀은 그 소그룹을 가리키고,
상위 그룹은 가리키지 않는다. 컬럼을 하나 더(`subgroup_id`) 두지 않은 이유:

- 기존 행이 그대로 유효하다 — 마이그레이션이 컬럼 추가 하나로 끝난다.
- "이 셀은 어느 그룹인가" 에 답이 둘일 수 없다. 둘이면 언젠가 어긋나고,
  어긋난 쪽을 아무도 못 본다.

### 3. 대가: 상위 그룹으로 거를 때는 자손까지 편다

셀이 소그룹에만 있으므로, 상위 그룹으로만 거르면 **셀이 가득한 그룹이 비어
보인다**. 그래서 필터도 개수도 전부 한 곳을 지난다:

```python
def group_scope(session, group_id) -> list[int]:   # apps/api/app/deps.py
    return [group_id, *children_of(group_id)]
```

화면 쪽 짝은 `GroupChoice.includes()` 다. **드롭다운에 적힌 수와 그것을 골랐을
때 보이는 목록은 같아야 한다** — 이 규칙이 깨지면 사람은 데이터가 사라졌다고
읽는다. 그래서 `GroupOut.sample_count` 도 자손을 포함해 센다.

### 4. 그룹을 지워도 안의 것은 남는다

셀이 "그룹 없음" 이 되는 기존 동작 그대로, 소그룹은 **최상위 그룹**이 된다.
폴더를 지운 것이 그 안의 실험을 지운다는 뜻은 아니다. 계단식 삭제를 넣으면
클릭 한 번이 실험 묶음 하나를 통째로 날린다.

### 5. 이름 묶음(`nameFamily`)은 라이브러리에서 뺀다

같은 조건 반복분을 이름 앞자리로 묶어 주던 열과 필터가 있었다. 소그룹이
그 일을 **사람이 명시적으로** 하는 길이므로, 둘을 나란히 두면 같은 셋이
화면마다 다른 덩어리로 보인다. `nameFamily` 자체는 남는다 — 업로드가 파일
이름에서 셀 이름을 뽑을 때 쓴다.

## 결과

- 업로드: ① 그룹 · ② 소그룹 · ③ 셀. 두 드롭다운 모두 그 자리에서 만들 수 있다
  (`creatable`) — 올리다 말고 라이브러리로 갔다 오지 않는다.
- 비교·대시보드·라이브러리(충방전/EIS/GITT 전부): 같은 부품, 같은 순서.
- 비교 화면은 오른쪽 340 px 레일을 버리고 그래프를 폭 전체로 썼다. 고르는
  조건이 그룹·소그룹까지 늘어나 레일에 다 안 들어간다.

## 안 한 것

- **임의 깊이 트리.** 위의 이유. 3단이 정말 필요해지면 그때는 화면부터 바꾼다
  (드롭다운 둘이 아니라 트리 하나로), 저장 구조만 먼저 늘리지 않는다.
- **셀을 여러 그룹에 넣기.** 태그가 하고 싶은 일이고, 그것은 다른 기능이다.
