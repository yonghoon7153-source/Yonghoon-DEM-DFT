# T12R-01 외부 종결 기록 (2026-10-26)

**T12R-01 (P2)은 CLOSED다.** 외부 재확인은 고정 소비자 snapshot 읽기의 자동 fetch 차단과 정상 52개 결과 보존을 수용했다. 이미 닫힌 이 결함의 추가 재검토를 다시 요청하지 않는다.

검토 핀은 `96f15ed17e03181b6096fb65f71ec7f577f17523`, 실제 코드 후보는 `3eecce8af503556b678f8f4a02343e6bce3d0b83`, 비교 기준은 `bffc42cab29da37b45f8a713e30e8572b91e7da3`, 고정 소비자는 `4c29705fa1c4ba94737a858b206fa4f4c5bb2bde`다. 이 새 기록은 날짜·핀·범위를 가진 후속 상태다. 과거 OPEN/claimed-fixed·실패 기록·보고서·빈 사실 양식·제출 ZIP을 고쳐서 종결처럼 보이게 만들지 않았다.

## 1. 수용된 경계와 근거

외부 환경은 **Windows / Python 3.12.14 / Git 2.55.0.windows.3**다. 다음은 외부 보고서와 원본 영수증에서 확인한 결과이며 이번 문서 반입 과정의 새 로컬 실행이 아니다. 저장소 전체 파일 불변은 외부 harness가 기록한 결과다. 이번 반입은 제공된 trace와 영수증을 검증했으며, 동봉되지 않은 시험 저장소의 전후 파일을 다시 대조했다고 주장하지 않는다.

| 관측 | 외부 결과 | 한계 |
| --- | --- | --- |
| 누락 commit 1개·tree 4개·blob 6개 | 11개 조건 모두 rc 2·fetch 자식 0회·시험 저장소 전체 파일 해시 불변 | 오류 코드만으로 판단하지 않고 trace의 옵션/환경과 파일 해시를 함께 확인 |
| 완전한 필요 객체 입력 | 52/52, 전체 cases 배열·여섯 소비자 해시 동일, fetch 0회 | runner 자체 해시는 수정판으로 바뀐 것이 정상 |
| 보호 환경 강제 + 옵션 모두 제거 | rc 2지만 실제 로컬 fetch 3회 | 원래 반례가 살아 있고 보호효과를 구분하는 대조 |
| 기존 소스/계약 거부와 표적 변이 | 8/8 및13/13 검출 | 충돌을 의미 검출로 세지 않음 |
| 옵션 미지원 | 첫 호출 거부·출력 소스 0개·보호 없는 재시도 없음, mock PASS | 옛 Git 실물이나 모든 플랫폼 검증이 아님 |

수정된 실제 loader는 외부 독립 13개 조건(양성 1 + 누락 11 + 보호 제거 1)에서 실행됐다. 외부 검토자가 작성자 오프라인 회귀 자체를 Windows에서 원 명령으로 재실행했다고 쓰지 않는다. 외부는 그 구조를 읽고 별도 구현으로 핵심 주장을 재현했다. 상위 `GIT_NO_LAZY_FETCH=0`에도 실제 읽기는 금지 환경 1과 `--no-lazy-fetch`를 유지했다.

기존 Linux Git 2.52.0 기록과 이번 Windows Git 2.55.0 기록은 각각의 검증 환경 근거다. 전역 옵션을 인식하는 정상 Git과 신뢰할 수 있는 실행 파일이라는 전제를 유지하며, 악성 실행 파일/임의 환경 전체를 격리한 보안 sandbox 인증으로 확대하지 않는다. 이 한정은 종결을 다시 여는 조건이 아니다.

## 2. 현재 상태와 남은 작업

P1 계약/P2 등록 분리, 합성 52개 관측의 제한된 해석, ULPRI-01/02의 좁은 종결은 유지한다. **실제 P2 T12는 NOT_RUN, physical_ready=false이며 물리 실행 GO는 없다.** 범용 P1 GO·세대2 설계 전체 GO·새 등록값·실제 생산자·WSL/연구 계산·Claude 통합도 이 종결이 승인하지 않는다.

남은 것은 실제 P2 사실과 등록, R-a/S0 결속, 지정 바이너리/숨은 이력, T10–T13 실제 자격, Q7–Q9 실측과 불확도다. 결손을 P1 값이나 기준 밀도/공극률에 맞춘 역추정으로 채우지 않는다. G2만으로 mass/omega 동일성을 인증하지 않는다.

향후 CI는 과거 고정 핀 회귀와 실제 통합 생산자/소비자·기대 모델 계약 검사를 구분해야 한다. 통합 commit/file hash/직접 검사/공용 게이트 근거는 그 실제 트리에서 남긴다. 과거 52/155 PASS를 미래 통합 트리 PASS로 옮기지 않는다. 구체적 후속 조건은 [이전 요청의 §3](dem_gen2_t12r_offline_recheck_request_20261026.md)에 보존돼 있다. 이 종결 기록은 그 조건을 구현하거나 새 선택을 재승인하지 않는다.

## 3. 이번 반입의 검증 범위

새 파일만 추가하고 기존 runner·회귀·소비자·params·공용 검사/CI·공유 원장·CLAUDE 기록은 바꾸지 않는다. 원문/ZIP/manifest/고정 핀·표적영수증 provenance와 새 문서 참조·원장 일관성·인용 금지·독립 범위 감사를 확인한다. 완료 증거는 전달물 verification/에 둔다.

공용 155는 실제 코드 후보3eecce8af503556b678f8f4a02343e6bce3d0b83의 기존 실행 결과다. 이번 문서 전용 종결 트리에서 새 155를 돌렸다고 주장하지 않는다. 외부도 제출 로그/영수증을 감사했으며155를 독립 재실행하지 않았다. 직접 52·오프라인 회귀·8·13·외부 13개 조건은 중첩되어 합산하지 않고 공용 CI 배선과 구분한다.
