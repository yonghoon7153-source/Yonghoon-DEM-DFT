현지 사용자가 모델을 열지 않고 적용/원복 UI를 조작하고, 제한된 시간 안에 관측을 확인한다. 설정 파일 값 비교와 사용자 UI 관측을 구분한다. 자동 최근 파일/캐시/로그 쓰기0을 주장하지 않는다. 원복은 같은 전용 prefs에서 원래 제한 항목으로 되돌리는1세션이며 기본 prefs를 덮어쓰지 않는다.

## 고정 경로·인자와 실행 순서

PLANNED_COMMANDS.json의 argv 배열만 사용한다. shell 문자열 조합·fallback 경로는 없다. 모든 runtime 하위 경로는 contract.json에 고정되어 있으며 b001이 이미 있으면 실행하지 않는다. 특히 data_apply/data_compile/data_batch/data_restore는 각각 새로운 빈 전용 디렉터리이며 입력/prefs/output/evidence/configuration과 겹치지 않는다.

1. B 승인/코드 SHA·입력/기준/보호 파일·기존 job/프로세스·자원·pending 확인. 불명확하면 제출하지 않는다.
2. durable pending 상태를 먼저 만든 후 전용 prefs 로컬 복사, 적용 UI1회, 기본 파일 및 보안키 비교.
3. 고정 Java를 compile 폴더에 복사하고 SHA를 다시 확인. compile1회 후 class 집합·SHA를 봉인.
4. classpath와 class 입력,16코어,-nosave를 명시한 batch1회. Java 안에서는 loadPreferences→기존 입력 SHA→로드전 기록/정책 조회→loadCopy→저장 해/시각 식별→before 속성/U/이력→필수 Results→after 검사 순서다.
5. 프로세스 종료/잔류 확인, 외부 원본 식별 확인, 원복 UI1회, 원복값/기본 설정 재확인.
6. 새 고유 결과만 별도 분석기에 전달해8창·Li/물리·보존/정리 상태를 대조하고 봉인한다. 분석에서 드러난 수치 위반은 사후 검출이라고 기록한다.

`-nosave`를 임의 Java 실행 차단 장치로 설명하지 않는다. 금지 호출은 study/solver run·continue/recover, 초기화, 해 set/clear, 자동 sequence/메시/기하 생성, 물리·재료·파라미터/coupling/guard 수정, MPH save다. 기존 Results/dataset은 변경하지 않고 고정된 새 numerical9개만 추가한다. before/after Java 이력2개는 증거로 저장할 수 있으나 실행하지 않는다.

## 수치·보존 기준

OUTPUT_CONTRACT.md에 적힌 원래241좌표·domain1/3·8식/단위·ext0/recover off/시간 비보간·전체 실제 저장 시각을 유지한다. getPVals와 모든 반환 시각/형상·각 좌표/index/domain/finite를 확인한다. 없는 점을 보간/대체하지 않는다. 요청187/정확 공통 저장×4창에서 전압≤1mV·표면x≤1e-4, 총Li 상대변화≤1e-6·초기Li 각항≤1e-9mol/m² 및 원래 구성식 기준을 적용한다.

전해질 coupling 최소와 영역별 최소 차≤1e-9mol/m³, threshold0, 세 guard0을 검사하되1198발동이나 연속 시공간 양수성 증명이 아니다. argmin은 제외 상태로 남기며 옛 gate를 수정해 통과시키지 않는다.

원래 두 failed, 입력/원본/기준 CSV, ZIP/생성 영수증 recipient=null, Desktop 부분 회수, OCP 외삽 금지, TIME_CAPS 차이 미확인을 보존한다. 전후 Java 이력은 완전 snapshot이 아니며, 선언 속성 read-back과 시각별 real U digest를 함께 비교한다. after-U가 없으면 미완이다.

## 실패와 정리

보안/로드/식별/구조/단위/유한값 오류, 예산 초과, 기본 파일/데이터셋/보호 설정 변화, 새 적분 징후가 있으면 더 진행하지 않는다. 기본 설정을 덮어쓰거나 허용치를 고쳐 재시도하지 않는다.

일반 예외에는 Java 내부 보존 검사를 각각 시도한다. 강제 종료/전원 상실은 finally를 보장하지 않는다. 외부 launcher는 예약/pending·원본·프로세스 상태·정책 원복을 담당한다. 종료 권한은 private job 및 직접 소유한 미재개 root handle에만 있다. 이름/PID 목록에 있다는 이유로 다른 작업을 종료하지 않는다.

root 생성과 job 배정 사이 crash 또는 job 밖 helper는 자동 정리 보장 범위 밖이다. 그러면 pending으로 남기고 자동 재제출하지 않는다. `cleanup`은 아직 쓰지 않은 원복1세션만 수행할 수 있다. 원복 세션을 이미 소진했거나 프로세스 귀속이 불명확하면 정지·회신한다. 기본 prefs를 임의 복구하지 않는다.

numeric_recovery / sampled_comparison / preservation / process_cleanup / policy_restore를 따로 보고한다. 숫자가 통과해도 보존·정리가 미완이면 전체 완료가 아니다. 정상 전체 gate 종결은 독립 검토 뒤 판단한다.
