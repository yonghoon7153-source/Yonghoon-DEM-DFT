# REIL C5 승인 요청문 사전 검토

2026-10-06. 판정은 **설계 방향 수용, 승인문 정정 필요**다. 현 요청문 그대로의 구현 착수나 비용 측정을 승인하지 않는다. 아래 C5-N1–N5를 문서에서 닫고 사용자가 §10 (1)을 따로 승인하는 순서가 적절하다. C3 출력의 기존 한정 수용과 실행 기록 미완은 유지한다.

## 대상과 확인 범위

고정 커밋은 `7def9238c8fdac605decc5bf17c1428a93faad1d`다. 첨부 승인 요청문은 이 커밋의 파일과 15,765 bytes 전체가 같았다. SHA-256은 `2656ab2bf142ea1ea64245f816cc8c7c4f5b6ac086d1ad28a50961d68bf85cc6`, Git blob은 `5d9fe84b8a4f676baa810f5b11f6ae719648fb89`다. 아래 좌표는 이 원문 기준이다.

읽은 근거는 요청문, 사전 검토 요청, 상태 §19·§22–25, 지정된 v2·부속 A/B 조항, P0_RESULT.json, COBYQA_OPTIONS.json, util_LFP.py.txt 157–236행이다. P0는 저장 JSON만 읽었으며 원자료에서 다시 계산하지 않았다. util은 지정 구간만 읽었고 함수나 의존 코드를 실행하지 않았다.

REIL xlsx·pickle·노트북 열기, 자료 처리, 맞춤, 계산·시험, Sobol 생성, 설치·환경 재구축, COMSOL/Java 실행은 하지 않았다. 검토 산출물 작성과 파일 식별 대조는 수행했다. 현재 실행 기계의 환경·자원·동작을 검증한 결과는 아니다.

## 정정이 필요한 사항

### C5-N1 P1 전체 고정 배열의 봉인 시점을 예외 없이 늦출 수 없다

**좌표:** 요청문 §4 63–64행, §9 Q1 109행. 기준은 부속 B §2-1 95–102행, 부속 A §3-9 275–285행이다.

부속 B는 첫 지역 실행 전에 자료 무관 고정 배열 전부를 봉인하도록 한다. 부속 A는 파일럿을 확인적 분석에서 제외하고 나중에 해당 단위를 다시 실행한다고 정할 뿐, 그 사전 봉인 의무를 면제하지 않는다. 따라서 “확인적 분석에서 제외되므로 사용 배열만 대조하면 현 등록을 충족한다”는 해석은 받아들이지 않는다.

**기존 등록을 유지하는 기본 경로:** 첫 실제 C5 지역 실행 전에 전체 고정 배열을 정식 봉인한다. 이미 봉인된 동일 배열은 재사용 근거를 연결하고, 필요한 생성·대조는 사용자 승인 범위와 준비 예산에 넣는다. 이 검토로 생성을 시작하지 않는다.

**다른 경로를 원할 때:** 결과를 보기 전에 C5 한정 예외를 별도 명시하고 사용자에게 결정받는다. 예외 범위는 파일럿의 A0 seed 0·1 배열만 먼저 봉인하고 나머지는 C4 전에 봉인하는 것으로 적되, 생성 규칙·환경·label 형식·배열 목록/유도 규칙은 파일럿 전에 고정하고 파일럿 결과에 따라 바꾸지 않는다. 이는 현 부속 B의 자동 해석이 아니라 **새 사전 정정**이다. 본 검토는 예외를 채택하거나 승인하지 않는다.

자료 없는 합성 시험·건조 실행과 실제 연구용 C5 지역 실행은 구분한다. 구현 단계에서 정식 배열을 생성하라는 뜻이 아니다.

### C5-N2 P1 P0의 한정 환경 결정을 미래 재구축에 자동 적용하면 안 된다

**좌표:** 요청문 §4 62행, §6 79–80행, §11 128–129행. 상태 §19 306–317행과 §22 353–356행을 함께 읽어야 한다.

상태 §19의 차이 허용은 특정 P0 재구축에서 새 봉인을 채택한 결정이다. 상태 §22도 이를 “이번에 승인한 새 기준 봉인”에 한정해 수용한다. 현재 §4는 venv가 없을 때 그 규칙을 미래 재구축에 그대로 적용하고 변이 12/12까지 실행하도록 확대한다. 같은 배포판 집합·판·집계와 Sobol/옵션 일치만으로 새 RECORD 차이가 콘솔 경로 변경뿐이라고 증명되는 것도 아니다.

**권고 정정:** C5의 기본 경로는 지정 봉인 venv의 존재·실제 interpreter·check·lock 결속 확인으로 제한한다. 부재나 불일치면 파일럿 전 중지한다. 재구축이 필요하면 설치/재구축/새 봉인/차이 판정/변이의 대상·시도·예산·중단 조건을 별도 범위로 사용자에게 요청한다. 이전 P0 결정이 미래 RECORD 차이에 대한 상시 허가라고 쓰지 않는다.

사용자가 이번 요청에서 재구축까지 새로 승인하려면 그 사실과 차이 수용 기준을 명시적으로 추가해야 한다. 현재의 간접 참조만으로 구현 승인과 비용 측정 승인에 이를 숨겨 넣지 않는 편이 명확하다. C5 리뷰를 위해 환경을 지금 재구축할 필요는 없다.

### C5-N3 P2 이미 시작한 실행과 미실행을 분리하고 예산의 마지막 경계를 정해야 한다

**좌표:** 요청문 §3 47–54행, §5 71·73행, §6 83–87행, §7 91–96행.

50행은 시간 상한에 걸린 진행 중 실행을 “미실행”으로 기록한다. 이미 목적 평가를 쓴 실행의 비용과 중단 사실이 사라지므로 정정이 필요하다. 단위별 maxfev/maxiter의 `budget`과 파일럿 전체 시간·자원 중단도 서로 다르다.

최소한 다음을 구분한다.

| 실제 도달 상태 | 남길 기록 |
|---|---|
| 시작 전 | NOT_STARTED와 전역 중단 사유 |
| 최적화 중 강제 중단 | STARTED_INTERRUPTED, 마지막 확인된 단계·시간·평가 수, 전역 중단 사유 |
| 반환점 확보 후 재평가 전/중 중단 | 반환 x와 solver status 보존, 재평가 미완, 증인 미확정 |
| 재평가·행 기록 완료 | 실제 termination과 witness 그대로 |
| 최종 기록 실패 | 앞선 행 보존, 전체 기록 미완 |

이 이름들은 제안이며 승인 전에 실제 필드/값을 고정하면 된다. 강제 중단으로 정확한 nfev를 알 수 없으면 마지막 관측과 미확인을 구분하고 0으로 채우지 않는다. 중단된 실행의 경과시간은 우측 검열된 관측이며 완료 실행의 소요시간처럼 평균에 섞지 않는다.

자원·시간은 다음과 같이 좁혀 적는다.

- 7,200초는 128회 완주 예상이 아니라 승인 상한이다. 준비·대조·측정·소유 작업자 종료·최종 기록을 어느 원점부터 어느 경계까지 포함하는지와 단계별 한도/종결 여유를 숫자로 정한다. 측정 종료에 시간을 모두 쓰고 그 뒤 무제한 기록하는 구조는 피한다.
- 부모의 최종 기록 후 시간 관측과 바깥 호출 rc를 구분한다. 강제 종료나 writer 실패 시 완전 기록을 보장한다고 쓰지 않는다. 새 출력 경로의 충돌 처리·종료 시간·잔존 작업자 처리를 고정한다.
- 부모와 작업자의 RSS 합을 1초마다 관측하는 것은 **표본 감시**이지 하드 4 GiB 제한이나 순간 피크의 증명이 아니다. 표본 누락·감시 실패·초과에 대한 전역 중단과 확인 가능한 소유 작업자 정리를 시험 대상으로 한다.
- 시작/끝 df·du만으로 실행 중 새 산출 1 GiB 초과를 감시할 수 없다. 실행 중 크기/여유 관측 또는 쓰기량 제한, 관측 주기·실패 처리·종결 기록 여유를 정한다. 그렇지 않으면 “실행 중 상한 준수 확인”이라고 보고할 수 없다.
- 내부 평가·재평가·라벨 계산 카운터를 나눈다. 라벨 계산을 위해 objective_fun을 한 번 더 호출하면 ≤128 재평가 조건을 벗어날 수 있으므로 같은 재평가의 산출을 재사용한다고 명시한다. 예외로 끝난 호출도 소비한 평가로 센다.
- BLAS 환경변수 1은 설정값이다. 실제 적용 상태를 무엇으로 기록할지 정하고, 관측하지 못한 상태를 실측 1로 표현하지 않는다.

### C5-N4 P2 지역 평가 오류와 구조 오류의 우선순위 및 재평가 실패가 빠졌다

**좌표:** 요청문 §2 35–40행, §3 48행, §6 86–87행, §5 71행. 부속 A §2-1 116–117행은 SOLVER_ERROR를 “예외 — 반환점 없음”으로 설명한다.

일반적인 x 의존 평가 실패를 큰 벌점으로 바꾸지 않고 해당 지역 실행을 끝내는 방향은 맞다. 그러나 “평가 중 예외”를 전부 solver_error로 처리하면 메모리·입출력·코드 결함까지 지역 무효 증인으로 낮춰 다음 실행을 계속할 수 있다. 예외의 **발생 단계와 원인**을 기록하고 구조/자원 오류의 전역 중단이 우선한다고 정해야 한다. ValueError라는 형 이름 하나만으로 모든 경우를 예상 평가 실패로 볼 수도 없다.

반환점의 독립 재평가에서 예외가 나는 경우도 따로 필요하다. 이때는 이미 반환 x가 있고 재평가 시도 1회를 썼다. solver의 실제 termination·status와 x를 유지하고, 재평가 실패와 witness 무효/미확정을 별도 기록한다. 이를 “SOLVER_ERROR는 반환점 없음 → 재평가 0회”에 넣으면 사실과 카운터가 모두 잘못된다. 새 재평가 실패 이유를 쓰려면 C5 적용 범위의 사전 정정임을 명시한다. 원 프로토콜의 no-return 설명을 조용히 넓히지 않는다.

비유한 f2를 임의의 유한 벌점으로 치환하지 않는 방침은 유지할 수 있다. 다만 solver가 비유한을 정상 처리한다고 보증하지 않는다. 래퍼가 비유한을 넘긴 사실, solver가 반환했는지/예외로 끝났는지, 독립 재평가 결과를 각각 기록하는 설계를 합성 입력으로 검증해야 한다.

### C5-N5 P2 구현 승인의 시험 집합과 자체 한도가 아직 충분히 고정되지 않았다

**좌표:** 요청문 §5 70–75행, §10 (1) 118–119행, §11 128행. 상태 §22-4 386–388행.

“합성 시험 + 합성 건조 실행 후 멈춤”이라는 분리는 적절하다. 다만 구현 단계의 벽시계·시험별 횟수/한도·산출 한도가 없고, 건조 실행의 `maxfev 작게`는 숫자가 아니다. “bms 전체 시험”도 현재 읽기 범위만으로 실제 자료·Sobol·외부 실행과 무관하다고 확인할 수 없다.

승인 전에 구현/한정 시험/합성 건조 실행/보존 단계의 수치 한도와 허용 명령·시험 집합을 정한다. RED→수정→GREEN은 의도한 순서로 사전 횟수에 넣고, 무제한 수정·부분 probe·재시도 권한으로 쓰지 않는다. 기존 전체 시험이 꼭 필요하면 자료 접근·설치·정식 Sobol 생성이 없는 경로임을 먼저 정적으로 확인해 승인 목록에 명시한다. 확인하지 못하면 §10 (1)의 무조건적 “bms 전체”는 한정된 무자료 시험 집합으로 바꾼다.

실제 util을 쓰는 합성 건조 실행은 향후 구현 승인에 포함할 수 있다. 고정 util SHA와 로딩 방식, 필요한 의존 코드, 합성 입력, 시작점 네 개, 정확한 옵션·평가/시간 상한을 실행 전에 고정한다. 원 xlsx 추출 경로를 호출해서는 안 된다. 과거 AST 선별은 범용 import 안전 보증이 아니라는 상태 §22-2의 제한도 유지한다.

현재 제안에 보태야 할 시험은 아래와 같다. 이번 검토에서 실행하지 않았다.

1. 반환 없이 발생한 예상 평가 오류, 반환 후 재평가 오류, 구조/메모리/IO 오류의 우선순위와 카운터.
2. 시작 전·최적화 중·재평가 중·최종 기록 중 timeout. 이미 확보한 행/반환점 보존, 숨은 재시작 없음.
3. 작업자 비정상 종료·감시 실패·RSS 초과·디스크 초과·기록 실패의 전역 중단, 확인 가능한 소유 작업자만 종료.
4. 부모/작업자의 실제 interpreter와 lock 결속, 코드·옵션·시작점 식별 변조 거부.
5. 기록 종료 HEAD·작업 트리 원문·자원 표본·외부 rc 연결. 실행 중 소스 변경을 허용할지/거부할지와 산출물로 생긴 dirty를 구분.
6. 실행 간 Model 격리와 독립 재평가 새 사본. 합성 입력/반쪽 곡선의 원본 불변.
7. 비용 기록에 시작한 실행과 미실행을 빠짐없이 배치하고, 임의 상한 도달 시 완료로 승격하지 않는 소비 경로.
8. 자료 경로 접근 금지와 실제 fitting 진입이 없는 구현 시험 경계. 정식 Sobol 재생성은 구현 시험의 fixture 생성과 구분.

## 수용할 수 있는 정적 사실

- P0_RESULT.json에서 #0은 A0 τ=0이 PRIOR_INCOMPATIBLE이다. #1 LLI-1은 A0 τ=0/0.02/0.05 모두 PRIOR_COMPATIBLE이고 추출 OK, sheet/cell_idx/step_idx가 요청과 같다. 따라서 제시된 번호순 규칙은 #1 선택과 일치한다. 이는 P0 JSON 대조이며 실험 원자료·cycle/방향 재확인이 아니다.
- util 217행의 f2는 평균제곱 전압 오차이고 v2 125행은 J_V를 sqrt(f2)로 정의한다. util 190·203–205·211행에는 Model 갱신이 있어 사본 격리가 필요하다는 근거도 있다.
- COBYQA_OPTIONS.json의 명시 옵션 8개와 요청문 값이 일치한다. 고정 환경에서 향후 구현이 이를 전달하는지 검증한 것은 아니다.
- 원 objective_fun은 f2만 골라 쓰더라도 앞뒤 용량·미분·다른 목적 계산을 수행한다. 그 내부 비용·예외도 현 평가 경로의 일부다. util의 f3 내부 except는 원 코드에 이미 있으므로 “벌점 추가 없음”은 새 래퍼가 임의 벌점을 추가하지 않는 뜻으로 한정한다. 다른 계산을 제거한 새 f2 전용 구현을 조용히 도입하지 않는다.

## 비차단 표시 정정

§7 96행의 “작업자 4의 실제 병렬 효율”은 같은 작업의 직렬 대조가 없으므로 speedup/강한 확장 효율 실측으로 부르지 않는다. 이 파일럿에서 기록 가능한 wall·CPU·작업자 점유/대기·부하 불균형을 보고한다. 별도 직렬 파일럿을 추가하라는 요구가 아니다.

완료된 실행, 지역 오류로 끝난 실행, 전역 상한에 중단된 실행의 비용 분포를 나눈다. 유효 증인이 적거나 128회가 모두 끝나지 않으면 C4 예산 예측의 한계를 함께 둔다. C5가 끝나도 E3a/E3b·H1–H4의 선행 조건을 자동 완료하지 않는다.
