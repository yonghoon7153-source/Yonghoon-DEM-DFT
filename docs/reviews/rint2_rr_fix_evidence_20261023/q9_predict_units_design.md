## 1. 왜 나누나

- 지금 사슬 (`scripts/rint_r_chain.py`):

  - 예측 = 한 단계 = 한 기계 (`stage_predict` 가 네 모서리 × 세 R + origin + SV 를 한 프로세스에서 차례로 · 등록 ㊵).

## 3. 설계

### 3-1. 단위 (1저자 Q9 (가) · 개정 1 Q15 (가))
- 단위 = (c, 법칙, R) 12 개.
  - 한 단위 = 그 점의 모서리 arm 0 (+ SV 반사실 아래 · 필요하면 위끝) + origin 표본 arm 1 · 2.
  - 한 단위는 한 기계에서 끝까지 돈다.  그래서 origin 퍼짐 비교 (arm 0 ↔ arm 1 · 2) 는 한 기계 안이다.
- **no-op 단위 (개정 1 · Q15 (가) · 개정 2)** = 법칙마다 하나 (no-op_P0 · no-op_P1).  **그 법칙의 사다리를 돈 기계 · 같은 환경 지문에서 돈다** — 사다리 요약에 환경 지문을 남기고 (개정 2 · 지금 `summary_base` = 기계 이름 · 코드 기록뿐 · 환경 지문 없음), no-op 단위의 기계 이름 **과** 환경 지문 전체가 그 법칙 사다리 확인 팔 (R_j,0) 의 것과 같아야 한다 (다르면 합치기 멈춤 `NOOP_ENV_MISMATCH` — 개정 1 의 `NOOP_MACHINE_MISMATCH` 를 넓힌 이름).
  - 개정 2 이유 (2차 사전 공격 P3): 기계 이름이 같아도 BLAS 계산 경로가 바뀌면 (아래 D2 실측) 정상 런이 `SAME_P_CONSISTENCY` 로 멈춘다 — 이름만으로는 못 막는다.
  - 환경 지문 칸 = python · numpy · scipy 판 · BLAS 라이브러리 정보 (내부 API · 판 · 계산 경로) · `OPENBLAS_CORETYPE` · 스레드 수 환경 변수 · backend (cpu / cupy) · cupy · CUDA 판 · GPU 이름 (칸 이름 = 구현 때 정하는 꼴).
  - 이유 (사전 공격 D2 · 실측): 같은 코드 · 같은 스레드 수라도 BLAS 계산 경로 (`OPENBLAS_CORETYPE`) 만 바뀌면 σ 가 상대 1.3e-10 – 5.8e-10 다르다.  no-op 은 사다리 값과 float 같음을 대조하므로 (등록 §4-1 · ⑩ 그대로) 기계를 넘으면 정상 런도 `SAME_P_CONSISTENCY` 로 멈춘다.
  - 이 규칙은 지금 사슬을 두 대로 돌릴 때 (사다리는 나누고 예측은 한 기계) 도 같다 — 예측 기계가 한 법칙의 사다리 기계와 다르면 그 법칙의 no-op 은 사다리 기계에서 따로 돈다.

### 3-2. 세 명령 (이름 · 인자는 구현 때 정하는 꼴)
1. 단위 실행 — `--stage predict --units <단위…> --machine <이름> --attempt <원장 항목>`.
   - 고른 단위의 늘 필요한 런만 돈다.  단위 폴더 요약에 출처 (§3-3) 와 원장 항목 (§3-5) 을 남긴다.
2. 합치기 — `--stage predict --merge <단위 · 넘침 시도 폴더 전부…> --ledger <시도 원장> --out <예측 폴더>`.
   - 채택된 시도의 런으로 다시 계산한다 (같은 판정 함수 · fetch = 키로 찾기 · 한 번씩) — §3-4 · §3-5 대조 시점 = 바로 아래.
   - **대조 시점 = 그 단위가 처음 요청될 때 (개정 2 · 2차 사전 공격 P3)** — 다시 계산이 어떤 단위의 런을 처음 요청할 때, 그 단위의 원장 채택 (§3-5) → 출처 (§3-3 · §3-4) → `read_run` 순으로 대조한다.
     - 요청되지 않은 단위의 대조 결과는 `unused_runs` 에 기록만 한다 (멈춤 아님 · 판정 입력 아님).
     - 이유: 한 기계 사슬이 일찍 끝나는 꼴 (예: 모서리 단위 하나가 NOT_COMPUTED → 런 4 에서 끝) 에서 뒤쪽 단위의 원장 문제 (예: 결과 전 멈춤으로 최대 시도 넘김) 가 결과를 바꾸면 같음이 깨진다 (같은 상태 · 같은 런 수여야 한다).
   - **fetch = 지금 사슬의 `read_run` 을 채택된 단위 폴더의 런 폴더에 그대로 돌린다 (개정 1 · D4)** — 러너 기각 표지 (`.rejected_*`) · 영수증 없음 · 증서 · 기록 계약 실패 = 한 기계 사슬과 같은 멈춤.  통과한 런 폴더는 **통째로** (팔 · 영수증 · 표지 · 로그) 바이트 그대로 복사한다 (sha256 대조).  팔 파일만 옮기지 않는다.
   - **첫 합치기 = origin 판정까지만 (개정 1 · D5)** — no-op · 모서리 · same_p · W0 · origin 표본 판정을 같은 함수로 다시 계산해 넘침 목록 (모서리, R) 을 정한다.  지금 코드처럼 모서리마다 origin8 을 바로 부르지 않는다 (그 순서로는 첫 넘침 모서리에서 끊겨 목록 전체가 안 나온다).  origin8 · 8 팔 평균 · R 단조는 자리 표시 값으로 돌리지 않는다.
     - **이른 단조 검사 (개정 2 · Q24 (나))** — origin 판정까지 계산한 뒤, 넘침 런을 요청하기 **전에** 이미 있는 점으로 같은 판정 함수 (`r_monotone_problem`) 를 지금 `_r_monotone` 과 같은 순서 (법칙 → c → 최종 추정량 → origin) 로 부른다.
       - 이미 있는 점 = 넘침이 없는 모서리 (세 R 모두 통과) 의 최종 추정량 (= arm 0) · 모든 모서리의 origin 점 (corner_a0 · origin_a1 · origin_a2).
       - 아직 없는 점 (넘친 모서리의 8 팔 평균 · origin8_a0–a7) 은 건너뛴다.
       - 모순 = 멈춤 `R_MONOTONE_VIOLATION` (넘침 런 없이 · 결정 기록 없이) — 사유의 점 이름 = 새 순서에서 처음 만난 모순.
       - 한 기계 사슬도 같은 자리에서 같은 함수를 부른다 (묶음 C).
     - 넘침 없음 → 바로 끝까지 (아래 "끝 합치기" 와 같음).
     - 넘침 있음 → 상태 `EXPANSION_NEEDED` + 결정 기록 (넘침 목록 · 채택된 단위 폴더 요약 sha256 집합 · W0 · 원장 sha256).  멈춤도 판정 입력도 아니다.
   - **끝 합치기** = 넘침 런까지 모인 뒤: 첫 합치기 계산을 다시 해 결정 기록과 대조 (넘침 목록 · 단위 sha 집합 · W0 같아야 · 다르면 `UNIT_PROVENANCE_MISMATCH`) → **묶음 C 의 `Predict.run` (§2 새 순서 · 개정 2) 과 같은 요청 순서**로 끝까지 (이른 단조 → origin8 · 8 팔 평균 → 끝 단조 (지금 `_r_monotone` 그대로) → 값) → 지금과 같은 꼴의 예측 폴더.
     - 런 기록 (`runs`) = `Predict.run` 이 요청한 런만 · 요청 순서 그대로 (판정 단계 `Replay` 가 지금 그대로 읽는다).
   - **등록된 결과로 일찍 끝날 때 (개정 1 · D1)** — `NOT_COMPUTED` (단락 · 증서 실패) · 등록 멈춤으로 다시 계산이 일찍 끝나면 그 결과가 곧 예측 결과다 (한 기계 사슬과 같은 상태 · 같은 런 수).  요청되지 않고 남은 단위 런은 출처 칸 `unused_runs` (폴더 · sha256) 에만 남긴다 — 멈춤 아님 · `runs` 에 넣지 않음 · 판정 입력 아님.
   - 다시 계산이 끝까지 갔는데 남는 런 = 멈춤 `UNIT_EXTRA` (요청되지 않은 origin8 등) · 요청된 런이 없음 = `UNIT_MISSING` (넘침 런만 없으면 `EXPANSION_NEEDED`).
3. 넘침 실행 — `--stage predict --expand <결정 기록> --points <(모서리, R)…> --machine <이름> --attempt <원장 항목>`.
   - 결정 기록이 요구한 origin8 런만 돈다.  결정 기록 sha256 을 출처에 남긴다.  끝나면 끝 합치기.
- 지금처럼 `--stage predict` 한 번 (단위 전부 · 한 기계) 도 그대로 둔다.  끈 경로 = 묶음 C 의 한 기계 사슬과 비트 같음 (개정 2 — 묶음 C 가 §2 순서로 바꾸므로 지금 코드와는 넘침이 있는 꼴에서 요청 순서가 다르다 · 넘침 없는 꼴은 요청 런 · 순서 · 판정이 같고 요약에 이른 검사 기록 칸만 더해진다 (칸 이름 = 구현 때) · 결과 0 건).
- **폴더 이름 (개정 2 · 2차 사전 공격 P3)** — 단위마다 러너 번호가 R01 부터라 `R01_corner` 같은 런 폴더 · `logs/*.log` 가 단위끼리 겹친다.
  - 합친 예측 폴더 안에 `units/<단위 이름>/<원장 시도 번호>/` 를 두고 런 폴더를 그 아래로 통째로 복사한다.
  - `runs[].outdir` = 합친 예측 폴더 기준 상대 경로 (그 접두어 포함 · 절대 경로 · `..` = 거부) · `Replay` 는 지금처럼 `self.dir / outdir` 로 찾는다.

### 3-3. 단위 · no-op · 넘침 폴더 출처 (묶음 B · C 의 칸을 그대로 쓴다)

### 3-5. 시도 원장 (개정 1 · Q16 (가) · 사전 공격 D3)
- 원장 = 덧붙이기만 하는 파일 하나 (계획 봉인과 같은 리포 · 계획 sha256 에 묶임).  시도를 시작하기 **전에** 항목을 커밋한다: (단위 | no-op | 넘침 점) · 기계 · 시도 번호 (원장 안 순서) · 계획 · 코드 · 침대 · 환경 지문.
- **항목 하나 = 시도 폴더 하나 = 결과 줄 하나 (개정 2)** — 결과 줄 = 완주 / 멈춤 (원 사유 · Q4 분류: 결과 전 멈춤 = 관문 · 환경 · 기계 자원 / 결과 뒤 멈춤 = 불수렴 · 사다리 소진 · 수치 · 물리) + **폴더 요약 sha256** (폴더 안 파일 전부의 상대 경로 · sha256 목록의 sha256).  같은 항목의 둘째 결과 줄 = 멈춤 `ATTEMPT_LEDGER_MISMATCH`.
- **시도 폴더는 모두 보존한다 (개정 2)** — 멈춘 시도도 지우지 않는다.  합치기는 단위마다 **원장의 시도 전부와 그 폴더 전부**를 받는다:
  - 원장에 없는 폴더 · **폴더 없는 원장 시도 (사유가 있어도 — 개정 1 의 예외를 없앤다)** · 폴더 요약 sha ≠ 결과 줄 = 멈춤 `ATTEMPT_LEDGER_MISMATCH`.
  - **결과 전 멈춤 = 합치기가 폴더에서 정한다 (개정 2 · 2차 사전 공격 P2)** — 결과 줄의 글이 아니라, 그 시도 폴더에 팔 payload (`p2_*.json`) 가 하나도 없고 **러너 (사슬 부모 프로세스) 가 쓴 멈춤 기록** (멈춤 이름 · 원 사유 · 자식 종료 코드 / 신호 · 멈춤 이름 = Q4 의 결과 전 목록) 이 있을 때만 결과 전이다.  그 밖 = 결과 뒤.
    - 팔 payload 가 하나라도 있으면 원인이 자원 멈춤이어도 결과 뒤로 친다 (부분 결과를 본 뒤 고르기를 막는다 · 보수 쪽 · 그 단위는 재시도 불가 = 비용).
    - 러너 멈춤 기록이 없는 시도 (사슬 부모까지 죽은 꼴 — 컨테이너 재시작 · 정전) 도 결과 뒤로 친다 (보수 쪽).  비용이 커서 **봉인 때 1저자가 다시 정할 자리**로 남긴다 (최대 시도 수와 함께 · ⬜).
  - 채택 = 원장 순서로 처음 완주한 시도.  그 앞의 시도는 모두 결과 전 멈춤이어야 한다 — 결과 뒤 멈춤이 앞에 있으면 그 단위는 같은 등록의 재시도가 아니다 → 그 단위의 결과 = 그 멈춤 (Q4 · 뒤 시도를 채택하지 않는다).
  - 최대 시도 수 (Q4 · 숫자 = 봉인 때 1저자) 넘침 = 멈춤.
- 그래서 단위 ↔ 기계 배정은 봉인하지 않아도 된다 (기계 하나가 멈추면 다른 기계가 이어받는다) — 대신 어떤 시도를 썼는지는 사람이 아니라 원장 · 폴더 · 규칙이 정한다.
- **기계적 보장의 범위 (한정 · 개정 2)** — 원장 항목의 결과 전 커밋 (git 순서) · 폴더 보존 · 폴더 요약 sha · 폴더에서 정하는 결과 전 판정으로 "멈춘 시도 폴더 지우기" · "결과 줄만 고쳐 쓰기" · "한 항목에 폴더 둘" · "결과 줄 여러 번" 을 막는다.  사람이 폴더 파일 · 멈춤 기록 · 결과 줄을 함께 지우거나 고치는 것, 풀이 로그에 값이 찍힌 뒤 payload 를 쓰기 전에 죽는 좁은 틈은 막지 못한다 (§9 Q-D).
- **칼날 (개정 2 · Q23 (가))** — 기계마다 비트가 조금 다르므로 (§3-1) 배정에 따라 판정이 뒤집힐 수 있는 자리는 **origin W0 (점 값의 퍼짐 ↔ 문턱) · SV 걸침** 둘이다 (빈도 = 작을 것 · 추정).
  - R 단조는 목록에서 뺀다 — C4 이후 단조 검사는 증서 구간끼리의 비교다 (`r_monotone_problem`).  참값이 R 에 단조이고 두 구간이 각각 참값을 품으면 (정직한 런) 위끝 (R 작음) ≥ 참값 (R 작음) ≥ 참값 (R 큼) ≥ 아래끝 (R 큼) 이라 어느 기계에서도 모순이 날 수 없다.
  - SV 판정은 DEPENDENT ↔ UNCHECKED 또는 clear ↔ UNCHECKED 로만 뒤집힌다 — DEPENDENT ↔ clear 는 두 구간이 모두 참값을 품어 불가 (2차 사전 공격 질문 1).
  - same_p 는 목록에 넣지 않는다 — 정직한 런의 c 0 ↔ c 1 차는 Rayleigh 로 0 이상 (풀이 오차만큼 아래) 이고 문턱 −τ_mono = −1e-3 은 기계 간 실측 차 (≤ 5.8e-10 · CPU) 보다 여섯 자릿수 크다 (추정 — 풀이 오차를 증서 허용 ε_I 이하로 본다).
  - 원장은 결과를 본 뒤 배정을 고르는 길을 막는다 — 칼날 자체를 없애지는 않는다 (한정).
