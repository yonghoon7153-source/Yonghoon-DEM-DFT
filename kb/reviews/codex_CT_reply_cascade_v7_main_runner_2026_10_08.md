2. 강제종료 뒤 미정산 시간이 있어도 이전 누적으로 재시작합니다

즉, "끊긴 런 시간도 누적된다"는 설명은 정상 정리된 중단에만 맞아요.
최소 수정은 미종료·미정산 시도가 있으면 자동 재개를 막는 것입니다. 확인 가능한 경과시간과 근거를 남겨 정산해야 해요. 단순히 현재 시각에서 시작 시각을 빼면 서버가 꺼져 있던 시간까지 비용으로 세므로 그것도 정확한 복원은 아닙니다.

3. 자식을 띄운 직후에는 중단 정리가 보호되지 않습니다
위치: run_cascade_v7_probe.py (line 711)

```

```

자식 생성과 PID 기록이 `try` 밖에 있습니다. 그 사이 `_Stop` 예외가 발생하면 자식 정리와 비용 누적을 건너뛰고, 상위 처리에서 **"돌던 런은 없었다"**고 출력해요.
잠자기만 하는 실제 Python 자식으로 재현했습니다.

* 러너 rc 130.
* 자식은 살아 있음.
* 누적 0, 종료 시각·소요 시간 없음.
* 같은 예외를 보호된 polling 안에 넣으면 자식을 정리하고 시간을 기록함.

시험 자식은 모두 종료·회수했어요. Windows에서 예외를 주입한 제어흐름 시험이며, Linux의 실제 신호 전달·프로세스 트리 종료를 검증했다는 뜻은 아닙니다.
최소 수정: 자식 생성부터 종료까지 전체 수명을 정리 블록으로 감싸야 합니다. 생성된 자식이 있는 모든 탈출 경로에서 상태 확인·정리·비용 기록이 이어져야 해요.
시점: 다음 운영상 재시작 전에 보완하면 됩니다. 이미 정상적으로 수시간 진행된 MD를 이 짧은 생성 시점의 문제 때문에 죽일 이유는 없어요.

여섯 질문에 대한 답
Q-CT-1 — 선언과 실행이 다른가?
정상 경로의 핵심 설정은 일치해요. 40런 명단, T*=1000 K, 시드 1·2, 생산 400 ps, dt 2 fs, 저장 100 fs, default 모드, 런 사이 집계 없음은 연결되어 있습니다.
확정된 불일치는 비정상 종료까지 포괄하는 듯한 비용 승계 설명과 실제 복구 동작입니다. 위 P1-2·3이 해당해요.
Q-CT-2 — 끝에서 그대로 읽고, 자격 정의도 같은가?
정상 입력에서는 예. 다만 최종 입력의 신원 검증이 부족해요.

* 러너 경로·태그 그대로 만든 합성 40런을 최종 판독기가 읽음.
* 하나 누락하면 rc 3.
* 탐침 시드 3·4, 다른 온도, H0는 최종 대상에서 제외.
* 자격 조건·경보 상태 12조합에서 탐침과 본 판독이 동일.
* 별도의 4000프레임 합성 궤적을 실제 재구성 경로로 처리해도 양쪽 모두 통과.
* `msd.json`의 옛 D를 집계값으로 쓰지 않고 카드 정의 곡선을 재구성하는 것도 확인.

따라서 T*를 선택한 자격 정의가 본 라운드에 전달되지 않는 문제는 찾지 못했어요. 보완 대상은 그 정의에 넣을 파일을 고르는 단계입니다.
Q-CT-3 — 시드 우선인가, 부모 우선인가?
지금 순서를 유지해도 됩니다.
시드 우선이면 20런 시점에 두 시드를 모두 가진 부모가 0개이고, 부모 우선이면 5개입니다. 중단 후 남는 완결 단위는 부모 우선이 많아요.
하지만 현재 규칙은 40런 전 집계 금지입니다. 완결 부모가 많다고 그 부분집합을 판정에 쓸 수 있는 것은 아니에요. 완주하면 계획된 분석 집합은 같으므로, 이미 고정한 순서를 바꿀 이유는 없습니다.
Q-CT-4 — 실측 최댓값 비용 게이트가 적절한가?
다음 런 시작 여부를 정하는 보수적 운영 규칙으로는 타당해요. 미래 비용의 상한을 보증하지는 않습니다.
첫 완료 런이 생기면 탐침 추정치 대신 본 라운드 완료 런의 최댓값을 사용합니다. 단독 GPU에서 빨라지면 추정치가 내려가는 것은 선언과 맞아요.
반대로 뒤에서 GPU 경합이나 느린 런이 생기면 예상보다 초과할 수 있습니다. 원장도 **"도는 런은 끝낸다"**고 명시하므로, 그것 자체는 위반이 아니에요. 수정할 핵심은 추정식을 새로 만드는 것이 아니라 이미 쓴 중단 시간을 누락하지 않는 것입니다.
Q-CT-5 — 사람 규율만으로 충분한가?
현재 기본 감시 경로는 적절합니다. 다만 "중간 집계 자동 호출 없음"과 "중간 집계 불가능"을 구분해서 써야 해요.
v7의 partial 우회와 watcher의 임의 로그 출력은 닫는 편이 좋습니다. 이후에도 고의적 열람을 막는 마지막 장치는 사람 규율이에요.
Q-CT-6 — 계속할 것인가?
조건부 계속입니다.

1. 정상 진행 중인 MD는 이 리뷰 때문에 중단하지 않아요.
2. 비정상 종료 뒤에는 미정산 비용·남은 자식 프로세스를 확인하기 전 재개하지 않아요.
3. 최종 판독 전에 중복 거부와 실행 기록 결박을 보완해요.
4. 운영 수정은 완료 경계에서 적용하고, 설정·명단·판정 문턱은 그대로 유지해요.

주의할 점은 이미 실행 중인 Python 러너는 파일만 수정해도 새 함수로 바뀌지 않는다는 것이에요. "다음 런 사이에 수정"하려면 완료 경계에서 안전하게 러너를 교체·재개하는 절차가 필요합니다. 현재 MD에 무작정 종료 신호를 보내라는 뜻은 아니에요.
