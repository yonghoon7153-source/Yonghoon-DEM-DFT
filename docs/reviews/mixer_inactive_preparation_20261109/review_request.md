# first8 현재 소스·새 메타 사본의 한정 독립 확인 요청

발송은 1저자다. 리뷰 핀은 전달 ZIP의 `PIN.txt`이며, 부모 B는 `e48e5fa0498ab7ee8fd84163d9af024d07cbb135`다. 전체 HOLD·연구 결과0·운영 재봉인 및 실제 실행 미승인이다.

다음 네 항목만 확인해 달라.

1. 원527 출처의 덱8/STL24와 이전69b6 검증 출처를 보존하면서, 현재 B 생성기에 맞춘 메타8의 변경이 `generator_sha256` 한 값뿐인지. 최초 옛 메타8 실패와 새 결속8·D2짝3·준비14 결과의 범위가 정확한지.
2. 제한된 소스12와 launch73의 누적 차이가 기존 반입 결과와 맞고, 이번 변경이 새 폴더·쪽지만으로 한정되는지. 원 자산40·운영 봉인·기존 정책·Rint는 불변인지.
3. 후보 schema·manifest·bindings가 완전히 결속되고, 33거부 탐침과 process/network audit 경계가 주장한 한도에서 유효한지. 내부 보완의 별도 5메서드(수정 전4실패→수정 후5통과)가 closed snapshot graph·검증 원소스 전용 loader·cache 및 링크 신호 거부를 뒷받침하는지. 실제 OS 링크/적대적 동시 변경 자격으로 확대하지 않았는지. 기존 드라이버가 이 후보를 자동 채택하지 않는다는 설명은 정적 확인으로 제한되는지.
4. 채택된 NP20·초기1/조건부 최대2·순서 정책을 실제 현장 자격, 후속 wave, 운영 봉인 교체 또는 실행 GO로 확대하지 않았는지.

새 덱/메타 생성과 합성 시험은 로컬 사본에서만 허용 범위다. 실제 호스트·원자료·시뮬레이터·Slurm·MPI·관측 파이프라인을 호출하지 말아 달라. README의 고정 스냅샷 재현 명령은 최초 실패1과 통과0을 구분한다. 원 콘솔 기록은 외부 증거 영역, 원 JSON과 해시는 리포 evidence에 있다. build/verify, 8케이스/3짝/준비14를 서로 독립된 총 시험수로 합산하지 않는다.

이는 과거 수용된 비활성 후보나 MLA/MLAR/MGS의 원 결함을 다시 판정하는 요청이 아니다. 운영 재봉인·실제 100k·실행 자격과 GO도 검토 범위 밖이다. 이 창의 내부 읽기 점검은 독립 판정을 대신하지 않는다.
