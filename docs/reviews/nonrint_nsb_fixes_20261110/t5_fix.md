## 2. 수치 계약

`_number()`는 정확한 내장 `int`를 원값으로 보존한다. 정확한 내장 `float`는 유한성을 검사하고 그 이진 값을 그대로 보존한다. `bool`과 숫자 하위형은 변환 hook 호출 전에 거부한다. 입력 정수에 임의의 `2**53` 상한을 붙이지 않는다.

| 계산 | 최종 처리 | 경계 |
|---|---|---|
| interval 순서·oracle 포함 | 보존한 내장 숫자를 직접 비교 | 정수·실수 혼합 비교에서 먼저 float로 바꾸지 않음 |
| 개별 오차 | `Fraction(value) - Fraction(oracle)` | 뺄셈을 끝낸 뒤 Fraction으로 감싸지 않음 |
| 평균·최대 절대오차 | 정확한 유리수 산술 | 원래 float의 이진 값을 십진수 의도로 바꾸지 않음 |
| ABS/REL 예산 판정 | 정확한 평균과 정확한 예산 비교 | REL은 `Fraction(budget) * abs(Fraction(oracle))`; 표시 숫자는 판정에 사용하지 않음 |
| 공개 평균·최대오차 | 정수이면 JSON 정수, 그 밖에는 유한 float 표시 | 비정수 표시는 반올림될 수 있음 |
| 정확한 보조 값 | `mean_bias_exact_ratio`, `max_abs_error_exact_ratio`, `effective_bias_budget_exact_ratio` | 각 `[분자, 분모]`; Fraction 객체를 공개하지 않음. 유효 관측이 없으면 앞의 두 값은 null |
| RMSE | 정확한 개별 오차를 입력으로 한 기존 형태의 float 진단 | 참값 오차나 정밀도 인증이 아니며 승인 flag에 사용하지 않음 |

평균·최대오차의 비정수 표시 또는 RMSE가 유한 float 범위를 벗어나면 전체 호출을 `REJECTED`로 돌린다. 0이 아닌 파생 값이 float 표시에서 0으로 underflow되는 경우도 거부한다. RMSE의 중간 float 계산 범위까지 포함한 한정이며, 모든 유한 입력에서 진단 출력이 성공한다고 보장하지 않는다. 예를 들어 `10**400`의 정확한 같은 값끼리 비교한 오차 0은 처리하지만, 그 크기의 0 아닌 오차를 유한 RMSE로 표시하지는 않는다. 자원·자릿수 무제한 처리나 다른 JSON 소비자의 큰 정수 정확성을 인증하는 계약도 아니다.

`2**53 + 0.25` 같은 비정수 평균의 float 표시는 예산과 같아 보일 수 있다. 이 경우 보조 비율이 정확한 값을 보존하고, `declared_toy_bias_budget_met`는 정확한 평균으로 계산하므로 거짓 수용하지 않는다. 기하 interval을 `[0, 1]`로 자르지 않으며 signed porosity도 그대로다. missing/failed의 계획 분모, family·seed·pin·권한 경계는 바꾸지 않았다.

## 3. 시험 순서와 독립성 한계

수령 스크립트는 정적으로 읽고 기대 정답 두 사례를 새 회귀에 반영했다. 수령 측 재생기의 “실패가 예상됨” 결과를 후보 성공 증거로 쓰지 않았다. 신규 회귀는 저장한 기존 fixture를 사용하지만 숫자 기대치는 `2**53` 인접 정수, 한 단위 차이, 4회 평균, 반 단위 REL 예산의 손계산으로 정했다. 새 geometry estimator나 CI 생성기는 없다.

| 순서 | 소스 | 시험 | 결과 |
|---:|---|---|---|
| 1 | 구본 원바이트 | 최초 기대 정답 14 메서드 | rc 1, 실패 16, 오류 0 |
| 2 | 같은 구본 | 표시 범위 두 메서드를 보탠 최종 16 메서드 | rc 1, 실패 17, 오류 0 |
| 3 | 최소 수치 수정 후보 | 같은 최종 16 메서드 | rc 0, 16 / 16 |
| 4 | 같은 후보 | 기존 무변경 23 메서드 | rc 0, 23 / 23 |
| 5 | 후보의 별도 복사본 5개 | 같은 최종 16 메서드 | 각각 실패 16·3·2·2·1, 오류 0 |

2단계 red 기록 뒤에만 구현을 수정했다. 메서드·subtest·전후 반복·변이 실패 수를 더해 고유 시험 수로 세지 않는다. 최초 14 메서드와 최종 16 메서드는 중첩한다.

로컬 Python 3.12에서 `-I -B`로 실행하고, 각 프로젝트 소스 실행 전에 프로세스·네트워크 감사 차단을 설치했다. 감사 시도 0, 실제 엔진 호출 0, 원자료·원로그 본문 읽기 0, 전체 gate 미실행이다. 이 기록은 이 합성 호출들에 한정한다. 구본/후보/시험/runner 바이트, 시각, rc, 오류·실패 구분은 원증거에 남겼다.

변이 준비 helper의 첫 경로 계산이 잘못되어 읽기 단계에서 한 번 중단됐다. 그때 프로젝트 시험 0회이며 원 stderr는 도구 출력에만 있다. 원 helper를 보존하고 별도 `prepare_mutants_v2.py`에서 경로 계산만 고쳤다. Git 읽기 중 소유권 검사로 중단된 한 번도 시험 결과로 세지 않았고, 명령 한정 `safe.directory`로 다시 읽었다. 전역 Git 설정은 바꾸지 않았다.

## 4. 미수행과 인계

실제 T5 자격, 해석 기하의 현장 검산, CI 생성법·참 coverage 인증, 결과 전 외부 등록, PBC 자격, 물리 정량값 선택, 실제 데이터 수령, 운영 봉인과 실행 GO는 수행하거나 승인하지 않았다. D9′의 `epsilon_sphere` 기준 및 `epsilon_union` 기록 전용 정책을 이 산술 수정으로 바꾸지 않는다. NSB-F01의 한정 종결 여부는 반박 창 재확인 뒤 처분한다.
