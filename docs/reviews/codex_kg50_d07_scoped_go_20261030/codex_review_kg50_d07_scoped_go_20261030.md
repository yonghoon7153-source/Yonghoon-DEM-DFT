## 2. Q1 — 원 덱 이후와 같은 물리인가

## 5. 남은 항목 — 일반 종결과 한 건 수용의 구분

### D07S-01 / P2 — 기존 PAI-02 재현: 새 호출 영수증은 검토 영수증과 자동 대조되지 않음

**상태: 일반 도구에서는 열림. 이 한 건은 아래 §6 수동 절차를 조건으로 수용. 새 P1로 올리지 않는다.**

위치: `scripts/resume_ckpt.sh:1584–1588`, `:1879–1893`, `:1970–1990`, `:2092–2104`, `:2118`; 요청서 67행.

독립 반례:

1. 스크래치의 원 덱 첫 정착 run을 200000→210000, 대응 재개 덱을 180000→190000으로 함께 바꾼다.
2. 실제 `deckcheck.check()`는 문제 0, **끝 210001**로 통과한다.
3. 실제 `cut_trial(...,2000,...)`는 여전히 **같은 `94db4187…` 시험 바이트**를 만든다.
4. 본 제출 직전 코드는 `MIS`를 **이번 호출에서 새로 만든 영수증**과 비교한다. 옛 승인 영수증 `29ff619a…`는 명령의 인자도 비교값도 아니다.

이는 **이미 제공된 정상 덱이 210001로 바뀌었다는 발견이 아니다.** 제공 덱은 200001이 맞다. 또한 시험 중 외부 쓰기를 가정한 반례가 아니다. 새 호출 전에 다른 원 덱을 사용했을 때의 승인 신원 경계다. 수동 대조를 완수하면 이 반례의 새 영수증은 거부할 수 있다.

최소 해결:

- **이 한 건:** 새 호출 영수증의 전체 SHA-256을 위 승인값과 본 제출 전에 대조한다. 이를 수행할 수 있는 작업자·시간 여유가 없으면 자동 승격 명령을 사용하지 않는다. 아래 절차의 불일치·미확인 대응을 따른다.
- **일반 도구 종결:** 승인 영수증 값을 입력받아 새 영수증과 불일치·누락이면 본 제출 전에 거부하거나, 준비/검토/제출 단계를 분리한다. 일반 도구 수정 완료를 이 한 건 GO의 선행조건으로 추가하지 않는다.

반례 산출물: `independent/new_call_duration_change.json`, `new_call_trial.liggghts`. 실행 명령은 §7. Bash 제출 블록 직접 실행은 이 Windows 환경의 MSYS 제한으로 시작하지 못했다. 별도 조건 모형은 새 영수증만 맞으면 통과함을 보였지만, **실제 Bash/SLURM 제출 재현 성공으로 세지 않는다**. 기존 사전 공격의 끝-끝 수치는 저자 증거이며 이번 검토의 독립 실행 수치가 아니다.

### D07S-02 / P3 — “정착 끝 200001에서 멈춤”은 자동 종료가 아닌 운영 지시

위치: 받은 `input_kg50_d07_b50_r56.liggghts:157–164`, `:190–215`; 등록 `kg50_q5_dt_damping_registration_draft_20261027.md:239–243`, `:268`, `:410`.

정적 명령 순서는 다음과 같다.

| 동작 | step |
|---|---:|
| `run 180000` | 20001→200001 |
| `write_restart …/restart_after_settling.bin` | 200001 |
| 다음 `run 1` | 200002 |
| 안정화 `run 200000` | 400002 |
| 이후 압축 `run 5000` 반복 | 계속 진행 가능 |

즉 `write_restart`는 저장이지 종료가 아니다. 하지만 **등록 Q6가 원래 작업자의 scancel과 안정화 일부 진행을 허용한다.** 자동 정지가 없다는 이유만으로 새 P1 또는 독립 HOLD를 부과하지 않는다.

권장 보고 문구:

> 정착 종료 step 200001의 체크포인트를 생성한 뒤, 등록 Q6에 따라 수동 중단. 자동 종료 덱은 아니며, 중단까지 진행된 후속 구간은 이번 물리 검토·생산 결과 수용 범위 밖.

체크포인트는 이 덱에서 같은 이름으로 한 번 쓰인다. 중단 완료·실제 마지막 step·보존 체크포인트 해시를 기록한다. Q5 이전의 후속 계산을 검토 완료 산출물로 승격하지 않는다.

### 그 밖의 한정

- **PAI-01:** 제공된 실제 본/재개 덱의 판 파일명은 같고 상대 경로다. 면제 노트 0줄만 믿지 않고 실제 줄도 비교했다. 외부 STL 허용을 사용하지 않으므로 이 한 건의 차단 사유가 아니다.
- **PAI-04:** 시험 로그의 8×7×1 실행과 경로가 양성 증거다. `/home`↔`/lustre` 일반 배치 형태를 인증한 것은 아니다.
- **PAI-05/06/08:** 고정 명령, 작업 중 외부 파일 변경 없음, 알려진 경로라는 운영 전제는 유지한다. 임의 인자·모듈 가림·동시 편집을 허용하는 일반 GO로 확대하지 않는다.
- **PAI-07:** 삽입 덱/본 덱 첫 166행을 독립 대조했다. 바이너리 SHA는 로그 기록이며 실행 차단 조건은 아니다. 본 잡에서도 시험 때와 같은 바이너리 신원을 확인해 기록할 것.
- **G2 대체:** KE 일치는 입자 상태 전체의 지문이 아니다. “G0–G3 PASS”를 네 개 독립 물리 증거라고 서술하지 않는다.
- **포장:** tgz 41멤버는 고유 파일 23개 + 동일 바이트 중복 파일 17개 + 디렉터리 1개다. 시도 폴더 고유 파일은 17개다. 경로 이탈·링크와 서로 다른 바이트의 중복은 없었다. 요청서의 “시도 폴더 18파일”은 집계 표기 정정 사항이며 판정에 영향 없다.

## 6. Q3·Q4 — 수동 확인과 실제 제출 조건

**Q3: 한 건에 한정하면 제안한 수동 확인을 수용한다. 다만 확인을 생략하거나 늦게 수행해도 기계가 막는다는 보장은 없다.**

**Q4: 요청서 §5 명령은 아래 절차와 함께 사용하는 경우에만 한 건 GO다.** 이 판정문은 그 명령을 실행하지 않았다.

1. 서버의 원 삽입 로그와 도구가 읽은 사본을 보존하고, 받은 로그의 해시 `b1b298bb…6657f5`와 대조한다. 원본↔사본 해시·cmp 결과는 이번에 받은 첨부에 없으므로 서버에서 별도 기록한다. 이것은 기존 5파일 영수증에 포함된 검증이라고 쓰지 않는다.
2. 본 호출이 새로 만든 **그 시도 폴더**의 `main_inputs.sha256` 전체 해시가 **`29ff619a666f29131a9d582f27e555590316e8516dcf9d0a7d2af01715bde6fa`**인지, 시험 잡이 종료되어 자동 본 제출로 넘어가기 **전에** 확인·기록한다. 와일드카드로 옛 시도 폴더를 읽지 않는다. 파일 5개 자체의 일치도 도구가 다시 검사한다.
3. 불일치 또는 적시에 확인할 수 없는 경우 진행하지 않는다. 이미 시험 중이면 승격 전에 시험을 취소하고 종료 상태를 확인한다. **취소가 늦어 본 job이 이미 나갔는지 불명확하면, 시험 취소만으로 끝내지 말고 본 job 유무와 종료를 확인한다.** 이 시간 조건을 보장할 수 없으면 준비/확인 후 제출하는 방식이나 승인 영수증 관문을 사용한다.
4. 새 G0–G3 통과 및 입력 대조를 보존한다. 본 잡 `LMP_IDENTITY`도 위 본 덱·체크포인트 값과 대조한다. 시험에서 기록한 바이너리는 `ee2d77261bac9e7fa4e9311c8709e74bf7583a13225a5bc35a791bef9be60a3f`; 다르면 이 GO의 같은 환경 전제를 적용하지 않는다.
5. Q6대로 `restart_after_settling.bin` 생성 뒤 수동 중단한다. 중단 기록과 체크포인트 신원을 남기고 이후 Q5/안정화·압축 자격은 별도 절차로 넘긴다. 정확히 200001에서 자동 종료했다는 문장은 사용하지 않는다.

이는 새 결정을 다시 비준받으라는 목록이 아니라, **요청서가 이미 내건 수동 절차를 이 GO의 적용 조건으로 명시한 것**이다. 조건을 충족할 수 없거나 파일이 달라지면 해당 제출에는 이 GO를 적용할 수 없다.

배포 묶음의 `evidence/`에서 다음을 실행한다.


원문 제출 블록의 가짜 실행 시험은 `probe_submit_gate.py`에 별도로 둔다. 실제 스케줄러는 호출하지 않으며 가짜 체크포인트임을 명시한다. 이 검토 환경에서는 Bash 초기화가 `NtCreateDirectoryObject … 0xC0000022`로 차단되어 실행 검증을 완료하지 못했다. 따라서 `gate_probe/results.json`의 실패 기록을 PASS로 전용하지 않는다. `gate_model/`은 독립 조건 모형 설명용이며 실제 제출 증거가 아니다.

저자의 433개 전수 시험은 이번 좁은 검토에서 다시 실행하지 않았다. 원격 ibb/SLURM/WSL/LIGGGHTS에 접근하거나 계산·제출·생산 코드 수정을 하지 않았다. 제공된 시험 로그의 수용과 앞으로의 본 잡 성공 보장은 다르다.
