## 2. 관문과 동작

두 ASCII 초안은 전체 본문 MD5 확인 뒤 별도 단계·핀 GO, 1저자 DFT만 일시 정지, 환경 고정, 자원·운영자 확인을 요구한다. 이 표지는 사용자 진술을 기록하는 관문이며 사실을 독자적으로 증명하지 않는다. 자동 승인·임의 PIN 대체는 없다.

첫 현장 검사는 fetch/작업 트리 생성/계산 앞의 shallow=false·refs/replace 빔·info/grafts 부재다. graft/shallow/다른 replace 환경은 거부하고 저장소 선택 환경은 제거한다. fetch 후 받은 끝=고정 PIN, Git 역사 다시 대조. S0 작업 트리는 HEAD·clean을 확인한다. Q11은 고정 old/new/material blob을 새 폴더에 쓴다.

S0 로그·출력·저장본·묶음 자리는 새 경로다. 기존 등록 경로·계획·저장본을 덮거나 자동 삭제하지 않는다. 원 S0 감시 셸은 자식 rc·5초 RSS·출력 해시·묶음을 기록한다. DONE은 감시가 끝났다는 표지일 뿐: 자식 rc, 여섯 출력, SHA, E1–E4·T1–T3 대조가 별도다. 포장 명령 실패가 DONE을 막는 보장도 원 감시 셸에는 없으므로 CRC·목록·외부 해시까지 따로 확인한다. 이 동작을 이번에 수선했다고 하지 않는다.

S0 시작 표지가 없거나 숫자 PID가 아니면 LAUNCH_UNCONFIRMED rc2. 자식이 남아 있을 수 있어 자동 재시도하지 않는다. 표지가 있어도 START_OBSERVED는 완료나 채택이 아니다. 신호·중단 회수는 이번 로컬 검사의 대상이 아니다. 실제 시작 전 1저자 운영자가 프로세스/세션 식별과 중단 뒤 종료 확인 절차를 정한다.

경로는 해당 운영자가 통제하고 실행 중 소스·입력·경로를 바꾸지 않는 전제다. 기존 검사 뒤 동시 교체나 경로 별칭 전부를 봉쇄하는 파일시스템 격리 도구로 인증하지 않는다. S0 이전 로그의 끝 표지 검사도 다른 작업/계정의 동시 실행이 없다는 증명이 아니다. 실제 설치 링크·권한·동시 작업 확인은 운영자 몫이다.

**지원 진입점은 Q14_S0_FINALPIN_DRAFT.txt와 Q14_Q11_FINALPIN_DRAFT.txt 단일 블록뿐이다.** 감시 셸·Python helper의 별도 사본은 바이트 대조용 증거이며 직접 호출은 미지원이다. 내부 분리 모의에서 원 감시 셸의 자식 발사 부분은 GO/PIN/새 출력 검사를 반복하지 않고 기존 run.log를 덮을 수 있음을 확인했다. 이 부분은 원 동작이며 이번에 새로운 하위 프로세스 승인 체계를 구현한 것이 아니다. helper를 따로 실행해 바깥 관문을 우회하면 이 블록 계약 밖이다.

## 4. 1저자가 정할 것

Q1. S0와 ⑥는 현 감시 로직을 유지하고 운영자 감시+절대 UTC 중단 시각 표시로 준비할지?
권고: 이 방식을 유지한다. 자동 시간 중단 추가는 실행 로직 변경으로 따로 시험·고정 핀·반박 재확인한다. 이번에 실제 운영자·UTC·자원 또는 실행 GO를 대신 정하지 않는다.

Q2. 실제 실행 준비가 되었을 때 execution_intake_form.json의 환경·자원·운영자·시작/중단·중단 회수·단계별 GO를 채울지?
권고: 빈칸이 남으면 발사하지 않고, S0와 Q11을 따로 승인한다. ⑥은 두 결과 수용과 S0 계획 채택 위치 검토 뒤 다시 확정한다.

게이트 추가는 1저자에게 전달된 Claude 권고대로 명령·기대만 준비했다. check_all.sh는 바꾸지 않았고 Claude가 반입 때 넣는다. 자세한 결과 전 기준과 실패 분기는 s0_preregistration.md·q11_consumption_matrix.md, 검증 범위는 checks.json에 기록한다.
