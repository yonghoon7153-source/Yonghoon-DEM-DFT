# 11-16 WSL 결과 수령

1저자 실행 결과의 수령 기록이다. Codex는 제공된 두 압축 파일과 화면 기록을 읽었으며 현장 계산을 실행하지 않았다. 원 압축 파일과 경로가 포함된 원 로그는 리포 밖에 보존한다.

| 대상 | 수령 결과 | 처분 |
|---|---|---|
| 믹서 A/B | command_rc=1. A 네 검사, B validate8, SELF-170 여섯 검사는 기대 반환값과 일치. 일곱 번째 smoke_blind에서 launch_highbo.sh 부재 | INCOMPLETE. 나머지 Linux 검사는 미실행. 원 실패 보존 후 V2 새 사본으로 재실행 |
| 수영 S/F | command_rc=0, DEVELOPMENT_COMPLETE. 각 팔 1200단계. S/F=2.469217025330513 | 개발 자료 수령. 압축 경고 때문에 계산을 다시 요구하지 않음 |
| 회수 압축 | 두 블록 모두 작업 폴더 내부에 tar를 생성해 tar rc1 보고 | 받은 gzip·tar는 끝까지 읽힘. 개별 파일·소스 manifest 대조 완료. V2는 작업 폴더 밖 새 디렉터리에 압축 |

수영 시간은 S 3.8585초, F 4.4297초다. 최대 메모리 37,380,096 B는 두 팔을 차례로 실행한 전체 프로세스의 최고 사용량이다. 이번 작은 정규화 설정에서는 공통 속도장 S의 마지막 구간 평균 판 반력이 F보다 컸다. 이 비를 실제 물성 보정 배수로 해석하지 않는다.

`suyoung_input.json`, `suyoung_summary.json`은 원 멤버 바이트다. 원 코드 SHA와 패키지 소스가 일치하고, 각 trace의 표본 51행은 출력 규약(첫 단계와 매 24단계, 마지막 단계)에 맞으며 마지막 행이 SUMMARY와 일치한다. 기록된 두 평균의 나눗셈으로 비를 검산했다. 240단계 전체 값은 trace에 없으므로 평균 자체를 독립 재계산했다고 기록하지 않는다. 최초 수령 점검에서 trace를 매 단계 출력으로 가정한 assertion은 실패했으며, 소스의 실제 표본 규약을 확인한 뒤 점검 가정을 수정했다. 계산 파일은 변경하지 않았다.

Python 3.12.3·NumPy 2.5.2는 수영 INPUT에 기록돼 있다. SciPy 1.18.1과 기존 프로젝트 venv 사용은 1저자 보고다. V2 블록은 같은 기존 venv의 Python을 직접 선택하고 버전을 출력하며 자동 설치하지 않는다.

G2c′ NP4 N200·NP2/NP4 N40000은 1저자가 순차 실행 중이라고 보고했다. 아직 개별 결과를 받지 않았으므로 완료 상태나 새 수치를 만들지 않는다.
