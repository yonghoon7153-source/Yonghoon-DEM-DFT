새 시험이 쓴 인자 꼴 (코드 기준):
- 단위 항목: `--stage ledger --ledger <원장> --add --ledger-target unit:<단위> --machine <이름표> --plan <계획> --runner <러너> --root <킷 뿌리>` (재실행은 `--resume <원 시도>`)
- 단위 시도: `--stage predict --ladders <P0 시도 폴더> <P1 시도 폴더> --runner … --root … --registration … --max-hours … --out <단위 바탕> --machine <이름표> --ledger <원장> --attempt <n> --unit <단위>`
- 합치기: 같은 예측 인자 + `--out <합친 폴더> --ledger <원장> --merge <시도 폴더 또는 바탕 …>` (끝 합치기는 `--expand <결정 기록>`)
- 넘침 점: 항목 `point:<단위 이름>`, 시도는 `--point <단위 이름> --expand <결정 기록>`
- 늦은 결과 줄: `--stage recover --out <시도 폴더> --ledger <원장>`

관찰:
- **(가) 팔 JSON 바이트** — 인터프리터 절대 경로 (`exec_env.python`)가 실리고, 픽스처 체크아웃에서는 `collector.anchors_source`에 절대 경로 문구가 실립니다. 사슬은 기계 사이 팔 바이트를 견주지 않습니다.
- **(나) 재실행 자격** — 실물 payload는 증서 단계의 파이썬 예외를 잡아 진단본을 쓰므로 그 시도는 재실행 자격 False입니다 ([R] 650의 한정 그대로).
- **(다) 틀린 바탕 재실행** — 다른 바탕에서 재실행이 한 번 거부되면 원 바탕의 재실행도 거부됩니다 ([사슬] 3806). 푸는 길은 문서에 없고 시험하지 않았습니다.
- **(라) 원장 없이 끝난 사슬** — 화면이 `ATTEMPT_LEDGER_MISMATCH` (원장 잠금 파일을 못 연다) · rc 3으로, 진짜 대조 실패와 같은 이름입니다.
- **(마) 게이트 주석** — `scripts/check_all.sh`의 kgy 판 단계 주석 "실측 ≈ 6–7 분"은 낡았습니다 (고치지 않음).
