# Rint Q12 — 두 지원 환경 조립 비교 등록 초안

## 1. 지위·비준 범위

1저자11-13 Q1 전6개/지원 환경, Q3 개발 등록안 준비를 이어간다. 바탕 ef88be68b08e8b427a331bd6471c449616c0504d, 실행 소스64e4d213e8267bafaf3ae5af00a42996cefd3f33 고정. 결과0·현장0·풀이/σ 열람0·전체 HOLD. 실제 환경·입력·시간/자원·등록 동결·실행 GO는 아직 없음.

권고안 전제(Q12-PREP-1): 이 새 등록에서는 **양쪽 실제 조립 순서의 원 DOF ID 목록을 모두 기록**하고 같은 code/input 신원과 연결한 뒤 바이트 주장을 검토한다. 기존 비교기의 원 ID 없는 조건부 비교를 더 강한 양성으로 바꾸지 않는다. 엄격한 등록 전제의 초안이지 기존 코드 정책을 변경한 것이 아니다. 새 결과 수집기·실행 블록·조립기 변경0.

## 2. Q-A와 Q12를 분리한 명부

| 축 | 대조 대상 | 동일해야 할 신원 | 결과가 뜻하는 것 |
|---|---|---|---|
| Q-A | 각 지원 환경·각6개 slot에서 저장본 없는 독립 건설과 해당 저장본 경로 | 기하/입력/코드/환경/문턱·각 독립성 근거 | 해당 slot의 저장본 대조; ⑥ hit 자기 기록만으로 대체 못 함 |
| Q12 | 선택한 두 지원 환경의 같은 slot 조립 기록 | 같은 논리 입력/코드·기하 slot, 환경은 각각 별도 기록 | weighted graph와 assembly bytes를 별도로 보고 |

slot은 SBE origin0/1/2, DBE origin0/1/2의6개다. 실제 key 문자열·입력 hash는 null로 남긴다. 두 환경이 확정될 경우 기본명부는12환경-slot 행/6대조쌍이며 실제 실행12회 또는 독립 조립 총12회로 확정한 수가 아니다. Q-A의 별도 건설/저장본 생성·읽기·비교 횟수가 추가될 수 있다. 추가 origin5가 발생하면 기존6칸으로 덮지 않고 명부·비용을 다시 고정한다.

Q12 환경 A/B는 전달용 slot 이름뿐이다. 실제 두 설치의 신원·Python/NumPy/SciPy/BLAS/SIMD/스레드·변경 통제와 불변 기간은 결과 전 고정한다. 환경은 열쇠 밖이라는 기존 정책을 유지하며 다른 기계를 동일 환경이라고 간주하지 않는다. 비용은 각 건설/생성/읽기/비교/준비 항목의 미정 상태를 보존한다.

## 3. 결과 한 행에 필요한 결속

| 묶음 | 필수 내용 | 보류 조건 |
|---|---|---|
| 등록 | 등록ID/revision/digest·승인 참조·목표slot·독립/저장본 모드 | null/다른 버전은 결과전 등록 미완료 |
| 실행 | 환경 별칭·attempt·source핀/도구hash·입력 사슬·모드·실제rc·완결 원본 참조 | 이름/시각만 같아서는 같은 실행 아님 |
| graph | 완료·사유없음·유효한 nonempty main 지문·graph 규칙 | null/빈/조기반환/미확인은 양성 근거 아님 |
| CSR | format/shape/nnz/sorted_indices, data/indices/indptr의 dtype·shape·SHA | 값의 수치 근사나 임의 dtype 정규화로 바이트 동일 대체 금지 |
| RHS | dtype·shape·SHA | CSR만 같다고 생략 금지 |
| DOF | n, Ab/gb/At/gt descriptors, 실제 번호 차례 ids | 한쪽 ids 없음은 이 등록의 바이트 주장 보류 |
| 대조 | comparable, graph_equal, csr_equal, rhs_equal, dof_equal, bytes_equal, claims, why | true 하나만 떼거나 why를 버리지 않음 |

일관된 hash라도 원 실행/배열에서 기록을 만들었는지는 별도 출처 계약이다. 원 배열과 σ를 공개 기록에 넣지 않는다. 원 DOF 목록은 번호/순서 메타이며 실제 접근 범위는 실행 전 별도로 고정한다. 실제 기록이 없는 지금 placeholder로 양성 결과를 생성하지 않는다.

기존 assembly_record는 유효한 원 DOF 번호를 int64 배열로 기록한다. 따라서 ids descriptor는 그 번호와 순서의 정규 기록이며 원 입력 ID 배열의 dtype 바이트까지 같다는 뜻은 아니다. CSR/RHS/판 결합 배열의 실제 dtype·shape·바이트 대조와 이 ID 기록 규약을 구분한다.

## 4. 도구 출력과 수령 판단 — 정적 소스 대조

고정 cjunc_asm_compare의 main은 **comparable이면 rc0**이다. bytes_equal=false도 rc0일 수 있다. 이는 비교 가능과 같음의 구분이며 이번에 고칠 코드 결함으로 계상하지 않는다.

| 조건 | 도구/기존 의미 | 이번 등록에서 받을 주장 |
|---|---|---|
| 미완료·null main·빈 main·꼴 불량 | comparable=false, claims 없음 | 없음; 미완료/사유 보고 |
| graph만 같고 CSR 다름 | graph=true, bytes=false, rc0 가능 | weighted graph만 |
| CSR 같고 RHS 또는 판 결합/DOF 순서 다름 | bytes=false, rc0 가능 | graph가 같을 때 graph만 |
| 두 기록이 graph-only | graph 주장까지만 | assembly bytes 주장 금지 |
| 한쪽/양쪽 원 ids 없음 | 기존 함수는 같은 코드의 번호 매김에 기대는 조건부 bytes 주장과 why를 낼 수 있음 | 권고안 전제 Q12-PREP-1 미충족, 바이트 주장 보류 |
| 모두 같고 ids도 양쪽 있음, 실행/환경/등록 결속 충족 | 두 비교 주장 분리 기록 | 해당 입력·두 환경 범위 두 주장, 풀이/σ/수렴·운영 GO 아님 |

그래프 같음은 CSR 바이트 같음을 함의하지 않는다. 같은 병렬 항이라도 합산 차례 때문에 조립 바이트가 달라질 수 있다는 기존 K1a 범위를 이어간다. 기록의 dtype/endian·정렬·DOF 차이를 숨기기 위해 양쪽을 사후 canonicalize하지 않는다. 비교기와 기존7회귀는 변경/재실행하지 않았으며 이번 표는 새 시험 통과 수가 아니다.

## 5. 완전성·실패·공개 범위

필수6쌍 중 빠진 쌍은 분모에 남긴다. graph6/6과 bytes5/6, 미완료1/6 같은 축을 각각 보고하며 실패/결측을 제외해6/6로 만들지 않는다. 양쪽 기록이 같은 오류인 것은 같은 성공이 아니다. 등록 밖 입력·추가 origin·다른환경은 별도 묶음으로 분리한다. 오류/시간 초과/중단·미수렴과 조립 바이트 불일치를 하나로 합치지 않는다. 자동 재시도/예산 연장 없음.

원본·원 로그·원 배열·현장 경로는 비공개 수령, 공개에는 pin/hash·별칭·필수 개수·판정과 한정만. 실제 원본 열람 범위가 정해지기 전 파일을 찾아 읽지 않는다. 새 양식은 DRAFT_NOT_REGISTERED이며 공유 원장 직접 수정0.

실제 조립 출력을 이 기록 형식으로 수집하는 연결 코드의 핀·모드·비결과 필드 추출 계약도 아직 미정이다. 기존 비교 도구4파일의 신원을 고정했다고 현장 수집 블록이 완성된 것은 아니다. 연결 구현이 필요하면 합성 입력의 시험·고정 핀·반박 검토를 먼저 하고, 기존 최종 핀 재확인 범위에 주는 영향을 따로 기록한다.
