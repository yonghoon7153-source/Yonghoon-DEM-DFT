# 조용히 틀린 경로 — 하루에 **여섯 번** 나온 한 부류 (2026-09-13)

> 회신 BQ-2 가 §4b 를 NO-GO 한 문장이 이 카드의 씨앗이다:
> *"이번 해제의 핵심은 시험 개수를 늘리는 것이 아니라, **'미수렴·실패' 를 실제 후속
> 차단에 연결하는 것**이에요."*

## 1. 부류의 정의

**문서·의도·기록은 맞는데 실행 경로가 다른 일을 하고, 오류가 나지 않는다.**

셋이 다 있어야 이 부류다.
1. 선언(docstring·`_method`·규약 문서)이 존재하고 **맞다**
2. 코드가 그 선언과 **다른 일**을 한다
3. **예외도 경고도 안 난다** — 그럴듯한 값이 계속 나온다

그래서 selftest 가 초록이어도 살아남는다. 실제로 여섯 건 전부 시험을 통과하고 있었다.

## 2. 하루치 실측 여섯

| # | 어디 | 선언 | 실제 | 얼마나 살았나 |
|---|---|---|---|---|
| 1 | `run_mlip_postproc` P0-1 | 수렴을 기록한다 | 기록만 하고 **자격 판정에 배선 안 함** | 1일 |
| 2 | 〃 Q2 | 높이·모양을 분리한다 | 분리해 **기록만**, 게이트는 원시 `dE/span` | 1일 |
| 3 | `webapp.list_papers` | digest 등록일 최신순 | 머리말 **첫 18줄**만 읽어 7편이 목록 맨 뒤로 | 4일 |
| 4 | webapp claim 결속 | 철회값은 `data-claim` 으로 묶인다 | `forbidden_phrases` 가 없어 **스캐너가 찾을 문자열이 없음** | 당일 |
| 5 | `sei_product_gaps` | *"ground-state (lowest e_above_hull) entry"* | `x or 9e9` — **0.0 이 거짓**이라 최소 E_hull 항목을 구조적으로 배제 | **81일** |

운이지 설계가 아니다.)

## 3. 왜 시험이 못 잡았나 — 시험 자체가 같은 병을 앓는다

이날 내가 쓴 시험 **세 개가 엉뚱한 것을 쟀다**. 전부 통과했고, 전부 무의미했다.

| 내가 친 것 | 왜 무의미했나 | 고친 뒤 |
|---|---|---|
| digest 파일에 `paper_pis` 돌려 "jwlee 안 붙는다" | 막는 것은 창이 아니라 `INCLUDE` 필터였다 — 창을 35→400 으로 넓혀도 **통과** | `_alias_hit` 를 **직접** 친다 |
| 호출부만 옛 방식으로 되돌려 음성 확인 | 시험은 `_alias_hit` 를 직접 부른다 — **함수를 깨야** 잡힌다 | 함수를 순진한 substring 으로 바꿔 빨간불 확인 |
| `hasattr(bi, "LATE_AXIS_TAGS")` | 리스트의 **존재**만 봤다 — `append` 를 `pass` 로 끊어도 통과 | 합성 파일로 **채워지는지**를 친다 |

**교훈: 시험을 쓴 뒤 반드시 대상을 깨보고 빨간불을 확인한다.** 초록은 아무것도
증명하지 않는다. 이 절차 없이 쓴 시험은 세 번 중 세 번 헛것이었다.

## 4. 규율 (채택)

### 4-1. 계산했으면 **어디서 쓰이는지** 한 줄로 답한다
새 필드를 기록에 넣을 때 *"이 값을 읽는 게이트가 어디냐"* 를 못 대면 배선이 없는 것이다.
기록은 진단이고, **판정에 쓰이지 않는 진단은 판정을 바꾸지 않는다.**

### 4-2. `or` 를 기본값으로 쓰기 전에 **0·""·[] 가 유효한지** 묻는다
```python
x or DEFAULT      # ⛔ x == 0 / "" / [] 이면 DEFAULT 가 이긴다
DEFAULT if x is None else x   # ✅ 결측만 덮는다
```
특히 **정렬·min·max 키**에서 치명적이다 — falsy 값이 센티넬로 덮이면 순서가 뒤집힌다
(#5 가 정확히 이것: 최선값 0.0 이 최악값 9e9 로 둔갑).

### 4-3. **"못 찾음" 과 "없음" 을 구분한다**
잘린 창에서 메타데이터를 찾을 때, 창 밖에 있으면 *"없다"* 로 퉁치지 않는다.
- 창이 **우연**이면 넓힌다 (`list_papers` 18 → 60)
- 창이 **정책**이면 유지하되 창 밖 발견을 **보고한다**
  (`build_index._AXIS_WINDOW = 20` + `LATE_AXIS_TAGS`)
- 둘을 구분하지 않으면 나중 사람이 정책을 우연으로 착각해 넓힌다

### 4-4. 시험은 **기전을 직접** 치고, **깨보고** 확정한다
복제 함수(`_fit_in_window` 같은)를 만들어 치면 실물이 바뀌어도 초록이다.
시험을 쓴 뒤 **대상 함수를 일부러 깨서 빨간불을 확인**한다. 확인 안 한 시험은 없는 것과 같다.

### 4-5. 화면·출력에서 **없는 값을 0 으로 그리지 않는다**
`or 0.0` 은 결측을 0 으로 만든다. 없는 것은 `—` 다 (#6).

## 5. 이 카드가 **하지 않는 것**

- 이 부류를 자동으로 잡는 도구를 주지 않는다. `or` 패턴은 대부분 정당하고
  (`main() or 0`, 3×3 셀 파싱 `[:3]`, 로그 잘라내기 `[:8]`) 정규식으로는 못 가른다.
  **실측으로 한 건씩** 확인해야 한다 — 이날도 후보 30여 개 중 실제 결함은 3개였다.
- 여섯 건이 전부라고 말하지 않는다. 같은 부류가 더 있을 가능성이 높다.
- 과거 산출물을 소급 재계산하지 않는다. #5 는 정정했으나 다른 도구가 낸 값은 손대지 않았다.
