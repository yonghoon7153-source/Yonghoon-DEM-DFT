# 불량셀 ML 2차 반증 검토

검토일: 2026-09-15

**현재 자료만으로 가능한 코드 조건 검증과 저장 지표 대조를 마쳤다. 회귀 16개·분류 16개 조합의 지표는 저장된 예측값에서 다시 계산해 모두 일치했다. 그러나 모델 선택과 평가의 독립성에는 문제가 있고, 결측·중복·입력 형식 처리에도 수정할 동작이 확인되었다.**

이번 결과는 **2차의 데이터 독립 검토 완료분**이다. 원본 `.txt/.mpt` 또는 셀별 X·y가 없어 학습 재현과 성능 변화 측정은 남아 있다. 원본 코드·Excel은 변경하지 않았다.

## 3. 모델 선택과 평가에서 먼저 고칠 문제

### 3.1 전체 자료에서 고른 파라미터를 CV에서 재사용한다

코드의 호출 순서는 다음과 같다. 줄 번호는 첨부 ZIP 소스 기준이다.

| 경로 | 전체 자료로 선택 | 선택값을 고정한 CV 예측 |
|---|---|---|
| `export_for_origin.py`, `fit_ridge` | 109줄 `gcv.fit(X, y)` | 112줄 `cross_val_predict(...)` |
| 같은 파일, `fit_logistic` | 127줄 `gcv.fit(X, y_bin)` | 132줄 `cross_val_predict(...)` |
| 같은 파일, `fit_ridge_threshold` | 146줄 `gcv.fit(X, y_cap)` | 149줄 `cross_val_predict(...)` |
| `ridge_capacity.py`, `run_ridge` | 174줄 `gcv.fit(X, y)` | 178줄 `cross_val_predict(...)` |

검증 셀의 정답이 파라미터 선택에 이미 참여한다. StandardScaler가 Pipeline 안에 있다는 점은 적절하지만, 파라미터 선택까지 바깥 검증 셀에서 독립화되지는 않는다. 예측 후 계수 표시를 위해 전체 자료에 다시 fit하는 것 자체가 이 문제의 원인은 아니다.

수정 방향은 바깥 평가 셀을 제외한 안쪽 데이터로만 alpha/C를 선택하는 것이다. 대역·특성·모델을 결과에 따라 고른다면 그 선택도 포함해야 한다. 이 원칙은 [scikit-learn의 중첩 검증 설명](https://scikit-learn.org/stable/auto_examples/model_selection/plot_nested_cross_validation_iris.html)과 일치한다. 현재 자료에서 낙관 편향이 정확히 몇 점인지는 원시 특징 없이 계산할 수 없다.

### 3.2 7셀에서 LOOCV AUC로 C를 선택할 수 없다

저장 결과의 라벨은 불량 3, 정상 4다. `export_for_origin.py:344`는 소수 클래스가 5보다 작으면 LOOCV를 선택한다. `fit_logistic`은 이 분할에 `scoring='roc_auc'`를 사용한다.

LOOCV의 평가 fold에는 셀 하나, 즉 클래스 하나만 있다. 양성과 음성 간 순위를 비교할 쌍이 없어 fold AUC가 정의되지 않는다. 현재 scikit-learn 원전 구현은 이 조건에서 경고와 NaN을 반환한다. 원래 실행 버전의 구체적 동작은 별도 확인해야 한다. [scikit-learn AUC 구현](https://github.com/scikit-learn/scikit-learn/blob/main/sklearn/metrics/_ranking.py)

반면 **7개의 저장된 CV 점수를 모은 AUC는 계산할 수 있다.** 불량 3×정상 4 = 12쌍이 있다. 그러므로 Excel의 전체 AUC=1이 불가능한 수치라는 뜻은 아니다. 문제는 C가 유효한 평가로 선택되었는가이다. 저장된 Logistic 8개 조합의 C는 모두 탐색 하한 `0.001`이다. 이 사실만으로 NaN 때문에 첫 후보가 선택되었다고 확정하지 않는다.

다음 재현에서는 각 분할의 클래스 수, 유한한 탐색 점수 수, 선택 C, 경고를 기록해야 한다. 7셀의 바깥 LOOCV에서 남는 학습 셀은 6개이고 소수 클래스는 2 또는 3개다. 독립 셀이라는 전제 아래 안쪽 2-fold 구성은 검토할 수 있지만, 작은 평가 집단의 불확실성은 그대로 남는다. stoic 코드의 기본 안쪽 5-fold를 그대로 복사하지 않는다.

## 4. 결측·중복·제외 규칙에서 확인된 동작

### 4.1 결측 용량이 정상 라벨이 되는 경로

가상 셀 41에 `cap=NaN`, 유한한 EIS·OCV를 주면 `assemble`은 셀을 유지한다. 이후 `y_cap <= THRESHOLD`가 False가 되어 **정상 0**으로 변한다. 회귀 루프는 유한 타깃을 따로 골라 이 셀을 제외하므로, 회귀와 분류의 모집단도 달라질 수 있다. 근거: `export_for_origin.py:231–258`, `:290`, `:315`; 검증 S01.

다만 이 경로가 끝까지 정상적으로 Excel을 저장한다는 뜻은 아니다. 이후 Ridge→threshold 학습이 NaN 타깃 때문에 중단될 수 있다. **확인한 것은 잘못된 라벨 생성까지이며, 실제 잘못된 최종 결과를 저장했다는 증거는 없다.**

EIS의 무한대도 `isna()` 검사를 통과했다(S02). NaN EIS가 제외되는 정상 동작도 대조했다(S03). 필요한 정책은 타깃·특성의 유한성을 검사하고, 결측 타깃에 이진 라벨을 부여하지 않는 것이다. 물리적 범위 밖 값은 유한성 검사를 통과하므로 별도 프로토콜 기준이 필요하다.

### 4.2 반복 EIS는 파일 순서가 측정 선택을 결정한다

`load_spectra`는 동일 셀 키에 새 DataFrame을 대입한다. 가상 EIS 두 개의 읽힌 순서만 바꾸자 선택된 실수부가 `[9,10]`에서 `[1,2]`로 바뀌었다(S07). 별도 중복 경고나 선택 사유는 없다. 근거: `ridge_capacity.py:46–58`.

단순히 파일명을 정렬하면 순서는 일정해질 수 있지만, 올바른 압력·시점의 측정을 선택했다는 의미는 아니다. 반복 측정이 유효하다면 셀·시점·압력 등으로 키를 구분하고, 분석용 측정을 고르는 명시적 규칙이 필요하다.

cycler 쪽은 동일 셀 번호 두 행을 넣었을 때 병합에서 길이 불일치 ValueError가 발생했다(S06). 양쪽 자료 모두 결합 전에 키의 유일성을 확인해야 한다.

### 4.3 제외될 셀도 주파수 격자에는 영향을 줄 수 있다

격자는 `export_for_origin.py:275`에서 만들고, 지정 제외는 281줄 이후에 적용한다. 가상 셀 41의 범위가 1–1000 Hz일 때 격자는 `[1,10,100,1000]`이다. 나중에 제외할 셀 60의 범위를 10–100 Hz로 추가하면 격자가 `[10,100]`으로 줄어든다(S08).

이것은 제외 규칙이 특성 설계에 완전히 반영되지 않는 동작이다. 시험 셀의 주파수 지원 범위도 전체 격자 결정에 사용되므로, 새 셀 평가를 목표로 한다면 측정 프로토콜로 격자를 미리 고정하거나 학습 자료만으로 정하는 정책을 검토해야 한다. 현재 동작이 정답을 사용한 누수와 같은 방식이라는 뜻은 아니다.

### 4.4 Z-only 모델도 OCV가 있는 셀만 평가한다

`assemble`은 OCV가 없으면 셀을 제외하고, 이후 모든 모델이 공통 자료를 쓴다(S04). 같은 셀 집단에서 OCV 추가 효과를 비교하려는 설계라면 타당할 수 있다. 다만 결과의 적용 집단은 ‘EIS가 있는 모든 셀’이 아니라 **용량·EIS·OCV를 모두 확보한 셀**이다.

이 조건은 오류로 단정하지 않고 목적을 명시해야 한다. OCV 결측 셀이 많이 빠졌다면 7셀 결과의 출처를 설명하는 한 요인이 될 수 있으나, 실제 제외 수는 알 수 없다.

## 5. 용량 추출은 프로토콜 검증이 필요하다

`read_cycle`은 메타데이터 16줄을 건너뛴 뒤 읽힌 첫 행을 무조건 제거하고, cycle 안에서 Step No.가 바뀐 순서로 `step_i`를 만든다. 선택된 구간의 마지막 행 용량을 타깃으로 쓴다. 근거: `extract_capacity.py:44–69`.

| 가상 입력 조건 | 확인 결과 | 해석 |
|---|---|---|
| 단위행이 있고 Step No. 10→20→30 | `step_i=1`이 Step No.20을 선택, 용량 0.020 Ah | 정상 대조. raw Step No.=1을 찾는 코드가 아님 |
| 같은 자료에 단위행이 없음 | 실제 첫 행 제거 후 순서가 바뀌어 Step No.30 선택, 0.025 Ah | 단위행 존재를 확인하지 않으면 다른 구간을 선택할 수 있음 |
| 대상 구간이 없음 | IndexError | 누락 구간에 대한 명시적 오류 처리가 필요 |
| 충전 구간의 시간 순서를 바꿈 | 총용량 0.010, CC 0.020, CV −0.010 Ah | 행 순서·용량 일관성 검증이 필요 |
| 첫 전류 0 또는 NaN 뒤 전류 감소 | CV 시작을 찾지 못함 | 시작 전류를 기준으로 삼는 조건을 확인해야 함 |

이 가상 입력들은 실제 장비 파일이 이런 형태였다는 증거가 아니다. 단위행·시간 정렬을 보장하는 장비 출력이라면 일부 조건은 발생하지 않을 수 있다. 따라서 첫 행 삭제를 무조건 제거하거나 용량을 무조건 최댓값으로 바꾸는 수정도 성급하다. 실제 헤더와 프로토콜을 기준으로 검증·오류 처리를 설계해야 한다.

CC 종료는 시작 전류의 99% 아래로 처음 떨어진 행이고, 그 행까지의 용량을 CC로 센다. 샘플 간격이나 CC/CV가 서로 다른 Step No.로 기록되는지에 따라 의미가 달라질 수 있다. 이번 검토로 실제 CC/CV 분할의 정확성을 확정하지 않았다.

파일명은 `cell번호_숫자MPa`를 요구한다. `cell41_cycle.txt`는 내용이 정상이어도 셀 키가 None이 된다(S16). README의 `cell<번호>` 포함 조건보다 엄격하다. 또한 빈 입력 폴더는 `cell_number` 열이 없는 DataFrame을 정렬하다 KeyError가 발생했다(S18). 입력 계약과 누락 보고를 먼저 정리해야 한다.

## 6. 보간에서 재현된 세 가지 차이

### 6.1 ‘외삽 허용’은 실제로 끝값 고정이다

측정 범위 1.04–990 Hz에 5% 허용오차를 적용하면 1–1000 Hz 격자가 생긴다. 범위 밖 1 Hz와 1000 Hz에서 실수부는 각각 원시 양 끝값 4와 9가 되었다(S09). `np.interp`는 별도 지정이 없을 때 범위 밖에서 끝값을 반환한다. [NumPy 공식 설명](https://numpy.org/doc/stable/reference/generated/numpy.interp.html)

이를 측정 기반의 기울기 외삽처럼 설명하면 안 된다. 끝값 고정을 허용할지, 격자를 제한할지, 해당 특성을 결측으로 둘지는 측정 조건을 보고 정해야 한다.

### 6.2 중복 주파수는 먼저 처리해야 한다

주파수 `[1,10,10,100]`에서 10 Hz의 두 실수부 값이 `[2,20]`인 경우, 순서를 바꾸자 10 Hz 보간값이 20에서 2로 바뀌었다(S10). 정렬만으로 중복이 해결되지 않는다. NumPy도 보간 x 좌표의 증가 조건을 전제로 한다.

중복이 반복 측정인지, 정방향/역방향 sweep인지, 장비 출력 중복인지 확인한 뒤 선택·집계 정책을 정한다. 서로 다른 상태를 단순 평균하는 수정은 피한다.

### 6.3 각 성분을 따로 보간하면 복소 임피던스 관계가 깨질 수 있다

가상 원시 두 점을 1 Hz의 `Z=1+0i`, 100 Hz의 `Z=0−1i`로 주었다. 둘 다 크기는 1이다. 10 Hz에서 코드가 만든 값은 다음과 같다(S11).

| 값 | 결과 |
|---|---:|
| 보간된 실수부 | 0.5 |
| 보간된 허수부 | −0.5 |
| 별도로 보간된 크기 | 1.0 |
| 보간된 실수부·허수부로 계산한 크기 | 0.707107 |

차이는 서로 다른 보간 표현을 함께 사용한 결과다. **실제 데이터에서도 29% 오차가 났다는 뜻이 아니다.** 네 성분을 일관된 복소값으로 만들지, 서로 다른 공학적 특징으로 명시해 사용할지 결정해야 한다. 원시 주파수 사이에서 어떤 보간이 물리적으로 적절한지도 별도 검토 사항이다.

## 7. 저장된 결과에 대한 산술 반증

### 7.1 지표·라벨·판정은 서로 일치한다

Excel은 수식 태그가 없는 저장값 중심 파일이고 외부 연결 부분도 발견하지 못했다. 저장된 실측·예측값을 직접 읽어 Q², RMSE, MAE, MAPE, 표본 수 및 용량 단위 환산을 재계산했다. 분류는 TP/TN/FP/FN, 민감도·특이도·정밀도·정확도·F1·MCC·AUC를 계산했다. AUC는 불량–정상 점수 쌍의 순위 비교로 계산했다.

| 대조 | 결과 |
|---|---|
| 회귀 지표 | 16/16 조합 일치 |
| 분류 지표 | 16/16 조합 일치 |
| 저장 점수에서 재계산한 판정·TP/TN/FP/FN 문자열 | 모든 조합 일치 |
| 용량 임계값에서 재계산한 라벨 | 7/7 셀 일치 |

연속 지표의 비교 허용오차는 절대 1e−10, 상대 1e−9이며, 판정과 개수는 정확히 대조했다. 이는 파일의 산술적 일관성을 확인한 것이다. 입력 행렬, 분할, 파라미터 선택이나 독립 일반화 성능을 재현한 것은 아니다.

근거 영역은 `01_reg_scatter!A1:AF8`, `02_reg_metrics!A1:P17`, `06_clf_metrics!A1:N17`, `07_clf_cellwise!A1:BC8`, `08_label_summary!A1:B14`이다.

저주파 Logistic의 FN은 M1·M2 모두 셀 **85**다. 다만 AUC는 M1이 11/12≈0.9167, M2가 9/12=0.75다. 판정 결과가 같아도 점수 순위는 다를 수 있다. 이 결과만으로 OCV가 일반적으로 해롭다고 판단하지 않는다.

### 7.2 완전 분류와 확신도는 다르다

1 kHz Logistic 점수 범위는 M1 약 0.493907–0.505179, M2 약 0.493805–0.505139다. 두 모델 모두 다음과 같은 판정 변화를 보인다.

| 판정 임계값 t | TP | FN | FP | TN |
|---|---:|---:|---:|---:|
| 0.49 | 3 | 0 | 4 | 0 |
| 0.50 | 3 | 0 | 0 | 4 |
| 0.51 | 0 | 3 | 0 | 4 |

근거: `07_clf_cellwise!Z2:Z8`, `!AX2:AX8`의 점수, `!F2:F8`의 라벨. 위 표는 저장 점수에 사전에 명시한 세 임계값을 적용한 산술 예시다. 새 임계값 추천이나 최적화가 아니다.

점수가 0.5 근처라는 사실만으로 모델의 순위 구분 능력이 나쁘거나 입력 잡음에 취약하다고 결론 내리지는 않는다. 다만 저장된 100% 판정을 ‘매우 높은 불량 확률로 확신했다’고 읽을 수 없으며, AUC만으로 판정 정책이 정해지지도 않는다. 코드의 클래스 가중치도 확률 해석 때 고려해야 한다. 임계값 선택과 확률 보정은 별도 평가가 필요하다. [scikit-learn 임계값 설명](https://scikit-learn.org/stable/modules/classification_threshold.html), [확률 보정 설명](https://scikit-learn.org/stable/modules/calibration.html)

### 7.3 실행 출처를 확정할 정보는 여전히 부족하다

Excel 내부 생성·수정 표기는 `2026-09-09 12:39:27`, ZIP 항목의 Excel 시간은 `2026-09-09 21:39:26`이다. 시간대가 다른 저장 관례와 일관될 수 있으므로 두 표기 차이를 실행 불일치의 증거로 사용하지 않았다. 둘 다 실행 로그나 데이터 버전의 증명은 아니다.

ZIP에는 원본 `.txt/.mpt`, 셀별 전체 X, 실행 로그, 의존성 버전 목록이 없다. 코드의 작성자 PC 입력 경로도 현재 환경에 존재하지 않는다. 전체 사용자 폴더에서 새 위치를 찾았다는 뜻은 아니며, 원본 위치는 사용자에게 요청했다.

## 8. 3차에서 검토할 구체적 수정안

아래는 **수정 후보와 수용 기준**이다. 아직 원본 코드에 반영하지 않았다. 기존 평가와 비교할 때 성능 상승을 성공 조건으로 삼지 않는다.

| 수정 묶음 | 제안 | 수용 기준 |
|---|---|---|
| R1 입력·라벨 계약 | 라벨 생성 전 유한 타깃 확인, 특성의 NaN/Inf 검사, 키 유일성 검사, 결측 타깃을 미확인으로 유지 | NaN이 정상으로 바뀌지 않고, 제외·오류 사유가 셀/파일별로 남음 |
| R2 반복·제외 규칙 | 셀·시점·압력 등 측정 키와 선택 정책 명시, 제외 정책과 격자 설계 순서 정리 | 디렉터리 열거 순서가 선택 측정을 바꾸지 않음. 제외 표본의 영향이 설계와 일치 |
| R3 용량 파서 | 실제 형식에 맞는 헤더·단위행 확인, 구간 존재·시간 순서·용량 관계 검증 | 잘못된 구간을 조용히 타깃으로 삼지 않음. 정상 장비 파일의 해석 보존 |
| R4 보간 | 중복·공통 범위·경계 정책과 복소 성분 표현 명시 | 범위 밖 값과 중복 처리의 출처가 추적 가능. 정의한 성분 관계 유지 |
| R5 검증 구조 | 바깥 평가와 안쪽 튜닝 분리, 클래스 수와 유한 점수 확인, 선택 범위 제한 | 평가 셀의 정답이 선택에 참여하지 않음. 정의되지 않은 지표로 후보를 고르지 않음 |
| R6 재현성·추적 | 입력 목록·해시·버전·설정·분할·선택 파라미터·경고·예측을 저장 | 동일 입력과 설정에서 결과 생성 과정을 추적할 수 있음 |
| R7 실행 경로 | 보조 진입점의 `target_cycles`를 함수 계약에 맞춤. 경로 설정과 import 시 출력 폴더 생성 분리 | 호출 오류 해소, 읽기 전용 import가 외부 경로를 변경하지 않음 |

R1·R5가 결과의 의미에 가장 직접적이다. R2–R4는 실제 측정 계약에 따라 선택지가 달라지므로 원본 확인이 중요하다. R7의 인자 수정은 단순하지만 그것만으로 전체 파이프라인의 타당성이 확보되지는 않는다.

검증 설계는 다음 순서로 구체화한다.

1. 원본을 셀·측정 키와 연결하고, 7셀/약 54셀 실행의 관계 및 포함·제외 이유를 확인한다.
2. 예측 시점, 용량 라벨 기준, 같은 배치의 새 셀인지 새 배치인지 목표를 고정한다.
3. 비교 집단과 바깥 분할을 고정하고, 단순 기준선·Ridge·Logistic의 제한된 비교부터 수행한다.
4. 각 바깥 학습 집단 안에서만 전처리 통계와 파라미터를 선택한다. 안쪽 분할이 성립하지 않으면 설정을 미리 제한하고 그 한계를 남긴다.
5. 셀별 예측과 FN/FP 개수·회귀 오차를 함께 비교한다. 원인 해석과 추가 모델 도입은 이 결과를 본 뒤 판단한다.

## 10. 다음 단계에 필요한 자료

**실제 성능 반증에 필요한 핵심은 입력 데이터다.** 다음 항목이 확보되면 이번에 확인한 코드 조건을 실제 데이터 발생 여부와 연결할 수 있다.

- `.txt/.mpt` 원본 폴더 또는 셀·측정 키가 있는 전체 X·y와 특성 정의.
- 7셀 결과와 약 54셀 기록의 관계, 실행 버전·로그, 60·70·93 제외 사유.
- EIS 측정 순서·SOC·휴지시간·온도·압력·배치, 용량 측정 프로토콜.
- 실제 선별 시점과 용량 미달 라벨의 사용 목적.

현재까지의 판단은 **저장된 수치의 산술 일관성은 확인되지만, 독립적인 성능 근거는 아직 확립되지 않았다**는 것이다. 추가 모델을 먼저 붙이기보다, 입력 추적과 선택/평가 구조를 확립한 뒤 같은 자료에서 재현하는 순서가 적절하다.
