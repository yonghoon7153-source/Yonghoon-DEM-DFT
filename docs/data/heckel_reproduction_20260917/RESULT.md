# `GAP3-01` 재현 — pure-SE Heckel 4압력 (2026-09-17)

저자가 외장 매체의 원자료를 올려 줘, `docs/data/heckel_pure_se_dem.csv` 의 4행을
**리포 밖 도구 없이** 재계산해 대조했다.  `verify_heckel.py` 가 그 계산이다.

## ① 밀도 재현 — 4/4 일치

```
   P       N    D_sph(계산)  D_sph(CSV)         Δ    D_uni(계산)  D_uni(CSV)         Δ      쌍

 400   40250       1.1811      1.1811   +0.0000       0.9660      0.9660   +0.0000  208838
```

규약은 CSV 헤더가 정한 것을 그대로 썼다 (새로 만들지 않았다):
`D = Σ V / (A·h)`, `A = 0.05²`, `h = plate_z`, 겹침은 **x·y 주기 최소상**,
같은 반지름 렌즈 `V = π(2R−d)²(d+4R)/12`, `D_union` 은 **pair-only 차감**(원장 `L1-05`).

## ② `plate_z` 도 독립 확인 — CSV 가 고리에서 빠진다

mesh STL 의 정점 z 를 직접 읽었다.  네 스텝 모두 **min = max**(플래튼이 평면) 이고

## ③ 기전 확정 — 커밋본을 de-escape 하면 **실제 돌아간 덱과 바이트 동일**

저자가 올린 `input_SE_heckel_{100,200,300,400}.liggghts` 는 `${` 17개 · `${{` **0개** 다
(= 렌더된 사본).  커밋본에 `${{x}}` → `${x}` 만 적용하면 **4/4 바이트 동일**하다.

⇒ `GAP3-01` 의 진단이 정확했다: 템플릿이 `.format()` 식 이스케이프인데 렌더는
`str.replace()` 연쇄라 `{{` 가 풀리지 않았다.  `make_heckel_inputs.py` 에 de-escape 와
fail-closed 를 넣어 재생성하니 **네 파일 모두 실제 돌아간 덱과 바이트 동일**하다.

## 무엇이 닫혔고 무엇이 남았나

- ✅ **`P_y=137.8 · R²=0.9653 · σ_y≈46` 사슬의 수치가 원자료에서 재현된다** (4/4).
  옛 판정문의 *"P300 만 재현, 100/200/400 미재현"* 은 **해소됐다**.
- ✅ 커밋된 덱 = 실제 돌아간 덱 (생성기 수리 후).
- ✅ **mesh 4개는 리포에 넣었다** (`mesh/`).  16줄짜리 평판이라 파일당 ~500 B 로 비용이 없고,
  이것만 있으면 `plate_z` 를 **리포 안에서 영구히** 재확인할 수 있다.
- ⬜ **atom 덤프 4개(약 21.7 MB)는 리포에 없다** — 저자 보관처에 둔다.
  `raw_manifest.csv` 가 파일명·step·크기·**sha256** 을 등록한다 (LHS 의 `area_s2_cohort.tsv` 와
  같은 규약).  ⚠ 그 표가 닫는 것은 **내부 보관 사슬**이지 제3자 재현이 아니다 — 보관 경로가
  저자 기계 로컬이기 때문이다.  파일을 받은 사람은 `sha256` 으로 **동일성**을 확인한다.
  ⚠ `archive_path` 열은 저자가 위치를 확정하면 채운다 (지금은 비어 있다).
  ⚠ 보관처를 고를 때 — 이 자료는 **순수 SE DEM 시뮬레이션**이지 `이종기술`(소립 SC-NCM 실험
  EIS 라인)이 아니다.  같은 폴더에 두면 나중에 섞인다.
- ⬜ contact 덤프는 이번 검증에 **쓰지 않았다** — CSV 헤더가 *"기하↔contact 0.00 % 일치"*
  라고 적은 그 대조는 재확인하지 않았다.
