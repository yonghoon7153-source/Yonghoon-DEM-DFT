# PRE8-01·02 외부 판정 수령과 보완 — 2026-11-05

**첫8 정적 준비는 외부 범위 수용. 관측 연결은 PRE8-01·02/P2 보완의 독립 재확인 대기. 전체 HOLD, 실제 실행·활성 등록·배포·통합·원장 종결 미승인.** 작성 측 시험 통과만으로 두 항목을 닫지 않는다.

## 1. 수령 대상과 원본 보존

외부 검토 핀은 `189930cc68b6e58beb6b4546d80353dc03852195`, 가지는 `codex/mixer-1104`다. `external/`에 판정 원문·범위 JSON·원본 ZIP을 보존했다. 받은 ZIP은1,041,859 B, SHA256 `908d6194f3e522d50aadc826bafeefa68801401c7880b9e27336a7872764f949`다. 포장 해시105항목과 내장된 이전 제출 ZIP의 바이트 동일성을 확인했고, snapshot54파일은 로컬 고정 핀의 Git bytes와 대조했다. 원격 대조는 외부 검토자의 기록이며 이번 수령에서 반복 실행했다고 세지 않는다.

외부 Windows/Python3.12.14에서 준비14·관측20 메서드가 통과했고, 추가 접촉·군집·M 검산에서 새 결함을 찾지 않았다는 판정을 수령했다. 이는 이 창의 새 Linux 실행 수치가 아니다. 외부 래퍼 초기 실패와 최종 성공, mock/소형 합성 범위도 원본 그대로 보존했다.

## 2. 발견과 보완 계약

| 항목 | 외부 반례 | 이번 보완 계약 | 상태 |
|---|---|---|---|
| PRE8-01/P2 | 처음 없던 n_expected가 판독 중 생겨도 값 반환 | run과 E0 각각의 존재·부재를 최초에 고정. dangling symlink도 존재로 취급. 반환 전까지 상태 변경이면 TECH·값 제거 | 외부 재확인 대기 |
| PRE8-02/P2 | import된 옛 코드로 계산하면서 바뀐 디스크 소스 SHA를 출처로 기록 | 의존 코드를 해시한 bytes에서 실제 compile/exec하고 그 고정 SHA를 기록. 진입·반환 시 디스크 불일치 거부. 기존 sys.modules/pyc로 우회하지 않음 | 외부 재확인 대기 |

검토 대상은 입력·실행 코드 출처 결속이다. 정적 준비기·기존 생성기·접촉/M 수식·조건표·SOP는 변경하지 않는다. 소스 경계의 범위와 자기 코드 대조 한정은 증거의 `validation_summary.json`에 명시한다. Python/NumPy/SciPy/운영체제 전체의 공급망이나 임의의 메모리 monkeypatch를 인증하는 기능은 아니다.

별도 모듈 집합의8의존 소스는 실제 해시한 bytes를 컴파일하며 기존 전역 모듈과 pyc를 사용하지 않는다. 생성기의 자기 파일 읽기도 캡처 bytes에 연결한다. observer 자신은 기록한 bytes가 현재 실행 중 module code와 동등하게 컴파일됨을 대조하므로, 주석만 다른 역사적 소스 원문을 유일하게 식별한다는 보장은 아니다. 총9개의 출처 레코드와 실제 입력 해시는 별도 항목이다. bootstrap 실패의 TECH 응답에 남는 부분 캡처 해시는 전체 집합 로딩 성공을 뜻하지 않는다.

## 3. 재현·회귀 근거

원본 외부 탐침을 임시 사본에서 먼저 실행해 두 반례를 재현했다. 원본 ZIP/수령 파일은 바꾸지 않았다. 로컬 시험·실패·보완 후 결과와 각 소스 해시는 `evidence/`에 기록한다. 이전 핀의 수용·중간 실패·최종 후보 시험을 구분하며 서로 다른 시험 개수와 조건 수를 합산하지 않는다. 관측 fixture의 prepare binding mock 및 회전 wiring의 cell_stats mock은 그대로 공개한다.

새 회귀는 기존 관측 직접 시험에 포함되며 기존 check_all/CI 연결을 이용한다. 전체 게이트를 반복하지 않고 관련 직접 시험·최소 문서/등재 검사를 수행한다. 전체 HOLD를 변경하지 않는다. 실제100000입자 양성 전체 경로·실제 로그 호환성·호스트/바이너리/MPI/물리 자격은 여전히 미검증이다.

최종 관측28개 메서드는 Python3.11.17/3.8.20에서 각각 통과했다. PRE8-01의8개 생성 반례, PRE8-02의 로딩 경계 회귀는 그 안에 포함되므로 따로 더하지 않는다. 원 외부 탐침을 기대 판정만 바꿔 실행한9개 관측도 통과했다. 별도 내부 점검의3그룹(import 후 변경/새 프로세스, 동일 mtime·size의 stale pyc와 전역 모듈, 컴파일 실패)은 Python3.11 합성 범위이며 독립 외부 종결은 아니다. 준비기 소스·시험은 불변이므로 이전14개 전체 시험을 반복하지 않았고, 새 private 로딩 아래 모의 없는8조건 입력 경계만 다시 확인했다.

## 4. 체크포인트 정정과 후속

첫8 준비 기록 README §4에 사용자가 전달한 Claude 정정을 추가했다. `write_restart`도 원 런 접촉 덤프와 비트 동일함을 보장하지 않으며, force_normal은 쌍 전체 힘의 중심선 사영이라는 설명이다. 향후에는 같은 방식으로 재계산한 값끼리의 비교 정의를 먼저 고정한다. Claude의334/3,111쌍 관찰은 전달 자료이고 이 창이 재현한 P1 결과가 아니다. P1 코드·허용폭·RJ323957은 손대지 않는다.

첫8은 fresh 전용이다. 실제 ibb 후속은 D0.7 종료 후·1저자 승인 후이며 지금 큐/제출 계획은 없다. 기존 MXD2R 별도 재확인은 그대로 대기한다. 공유 기록은 쪽지와 `ledger_proposal.json`만 제안하고 원장은 수정하지 않는다. 통합 시점은1저자가 정하며 Claude가 cherry-pick -x로 처리한다. 발송은1저자, Rint② 우선.
