## 1. `[실측]` 우리 클론은 온전하다 — 깨진 것은 **공개된 아카이브**다

```
$ git -C /home/user/xtangai/est-d-24-12331 fsck --no-progress   → rc 0, 출력 없음
$ ls -l "ISC Data."*   ↔   git ls-tree -l HEAD
  7 × 24,117,248 B + 19,736,307 B = 188,557,043 B — 디스크와 git blob 크기가 전부 일치
```

즉 **다운로드 문제가 아니다.** 그런데 조각을 이어 붙이면 깨진다:

```
$ cat z01..z07 "ISC Data.zip" > combined.zip && unzip -l combined.zip
```

### 2-1. ⚠ `[실측]` README 는 16 열을 적는데 파일은 **17 열**이다

README 의 열 정의 (1–6 셀 전압 V · 7–10 환경 온도 °C · 11 pack 전류 A ·
12 대상 셀 균등화 전류 A · 13 나머지 셀 균등화 전류 A · 14 대상 셀 번호(−1 = 없음) ·
15 내부용(9 또는 0 이면 HW 균등화 정지) · 16 내부 카운터(100 ms 마다 +1)).

실제 첫 행 (`55_passive.xlsx`):

```
4.0932 4.0972 4.0976 4.0975 4.0975 4.0974 | 25.29 25.37 25.47 24.85
| 0.0025 | 0 | 0.00125 | -1 | 0 | 1 | 355711
   ↑11     ↑12  ↑13      ↑14  ↑15  ↑16   ↑17 ← README 에 없다
```

16 열은 `1,2,3,4…` 로 README 의 "100 ms 마다 +1" 과 맞고, **17 열은 `355711` 에서
시작해 같이 1 씩 는다** — 또 하나의 카운터로 보이지만 **문서화되어 있지 않다.**
`[해석]` 절대 시각 또는 세션 전역 카운터일 가능성이 높다 (미확인).

**100 ms 샘플링 × 행 수 = 지속 시간** 은 README 와 일관된다 (위 표의 `h` 열).

## 3. `[실측]` 첫 측정 — 누설 셀은 보이고, 균등화가 그 위에 겹친다

`55 Ω` 두 파일을 전수 스트리밍해서 쟀다 (전체 행, 표본 아님).

| | `55_passive` | `55_active` |
|---|---|---|
| 행 | 135,000 | 150,000 |
| 첫 행 전압 폭 | 0.0044 V | 0.0080 V |
| 끝 행 전압 폭 | 0.0098 V | 0.0099 V |
| **최대 전압 폭** | **0.4195 V** @ 0.08 h | **0.5702 V** @ 4.11 h |
| **최저 셀** | **1 번** (첫·끝 모두) | **1 번** (첫·끝 모두) |
| `target battery` 값 | `-1, 0, 1, 2, 3, 4, 5` | 같음 |
| **∫\|대상 균등화 전류\|** | **12,768 A·s** | **22,813 A·s** |
| **∫\|나머지 균등화 전류\|** | **14.5 A·s** | **2,572 A·s** |
| pack 전류 범위 | −9.85 ~ +4.32 A | −10.17 ~ +4.33 A |

읽기:

1. ★ **누설 셀은 1 번이다** — 두 파일 모두 첫 행·끝 행에서 최저 전압이 셀 1 이다.
   `[해석]` ISC 저항이 셀 1 에 달려 있다는 뜻으로 읽히지만 **논문이 그렇게 적었는지
   확인하지 못했다**(PDF 미수령).
2. ★★ **passive/active 구분이 데이터로 확인된다.** 나머지 셀 균등화 전류의 적분이
   passive 14.5 A·s(≈0) ↔ active 2,572 A·s(**177 배**)다. README 가 "passive 면
   0 이거나 0 에 가깝다" 고 적은 그대로다.
3. ⚠ **최대 전압 폭 0.42/0.57 V 를 불균형으로 읽으면 안 된다.** pack 전류가
   −9.85 A 까지 가므로 그 폭에는 **IR 성분이 섞여 있다.** 휴지 구간을 골라내지
   않았다 — **아직 OCV 불균형을 재지 않았다.**
4. `target battery` 가 `0`~`5` 를 모두 돈다 → 균등화기가 **여섯 셀을 번갈아
   잡는다.** 즉 대상 선택 자체가 시간에 따라 바뀌는 신호다.

## 4. `[추론]` 왜 우리에게 걸리는가 — 그리고 **무엇이 다른가**

먼저 **다른 점을 분명히 한다.** ISC/누설은 **LLI·LAM 이 아니다.** 우리 본진 문제는
열화 모드 지분의 식별성이고 이것은 **결함 검출**이다. 그러므로 이 데이터가
`degradation-degeneracy/` 의 결론을 직접 건드리지 않는다.

겹치는 자리는 셋이다.

1. ★★★ **문제의 모양이 같다 — 두 원인이 같은 관측을 만든다.**
   셀 하나가 계속 내려가는 것은 (a) 내부단락/누설일 수도 (b) 자기방전 산포·용량
   편차일 수도 있다. **그리고 균등화기가 그 위에 전하를 실어 보내면서 관측을
   덮는다.** 우리 `NEW_MODEL_REQUIREMENTS.md` §3 의 "후보 원인 칸" 과 §4 의
   "구분 시험" 이 그대로 적용되는 형태다.
2. ★★★ **여기에는 우리가 계속 못 가졌던 것이 있다 — `measured` 라벨.**
   ISC 저항이 **설계된 값**(55·110·165·220·330 Ω)이다. `NEW_MODEL_REQUIREMENTS.md`
   §5·§8-6 이 "라벨 출처가 없다" 로 막혀 있었는데, 이 데이터는 **정답을 알고
   만든 것**이다. ⚠ 다만 **라벨이 우리 축(LLI/LAM)의 라벨이 아니다.**
3. ★★ **passive ↔ active 가 분리 연산자로 쓸 수 있는 쌍이다.**
   같은 ISC 저항에서 균등화 전략만 바꾼 두 실행이 있다 — `assb` 쪽에서 모은
   "율 스윕(`i→0`)" · "압력 되돌림(`P↑`)" 과 같은 **조작 쌍**의 구조다.
   ⚠ **직교성은 모른다**: 균등화가 SOC 를 바꾸면 누설 전류 자체가 바뀔 수 있다
   (`assb` 5호에서 `η = η(i, P)` 로 겪은 것과 같은 비직교 위험).

**그리고 `bms-balancing/` 쪽 보류 항목과 이름이 겹친다** —
`docs/COMSOL_REBUILD_SPEC.md` 의 금지·보류 목록에 **"유한 누설"** 이 있다.
⚠ **같은 물리량인지 확인하지 않았다.** 그쪽은 COMSOL 전기화학 모델의 누설 항이고
이쪽은 팩 레벨 ISC 저항이다 — **지금은 이름만 겹친다고 적는다.**
