## 2. SUP20-02 (P3) — mono 덱의 P 슬롯 열 사전 문구

**지금** (`scripts/lhs_design_dataset.py` DESIGN_DEFINE): `lhsx_w_AM_P` · `lhss_w_AM_P` = *"AM_P 질량분율 (덱 · 셋의 합 = 1) — ps_frac = w_AM_P / (w_AM_P + w_AM_S)"*.
실제: type 2 개 덱 (mono_AM_P · mono_AM_S) 의 P 슬롯 = **단일 AM 자리** (`scripts/lhs_ext_materialize.py` 머리 규약 · 어댑터가 kind 로 상을 옮긴다).
보충 lhss_001 · 002 · 003 · 020 (mono_AM_S) 은 P 슬롯 0.3 · 0.3 · 0.3 · 0.375 · S 슬롯 0 → 저 식은 1 · 올바른 `ps_frac` = 0 (어댑터 값은 0 — 계산 정상).

**고친 뒤** (문구만 · CSV · 계산 변경 없음 · lhsx · lhss 같은 문구):
- `*_w_AM_P` = *"P 슬롯 질량분율 (덱 · 셋의 합 = 1) — bimodal = AM_P · mono (type 2 개) = 단일 AM 자리 (크기 라벨 = `*_kind`) · `ps_frac = w_AM_P / (w_AM_P + w_AM_S)` 는 bimodal 에만 · mono_AM_P → ps_frac 1 · mono_AM_S → ps_frac 0 (어댑터가 kind 로 정한다)"*.
- `*_w_AM_S` = *"S 슬롯 질량분율 (덱 · 셋의 합 = 1) — bimodal = AM_S · mono = 0"*.
- 시험 먼저: 인계 생성기 자체시험에 문구 단언 하나 (mono 규약 낱말 · 식의 bimodal 한정) — 지금 FAIL → 고친 뒤 PASS · 보충 어댑터 4 행 대조 (Codex `design_probe` 와 같은 표).
- 옛 인계 열 사전 (`docs/data/lhsx_handover_2026092*_columns.tsv` · `…20261001_columns.tsv` · v1.2 인계 `lhsx_handover_v12_20261006_columns.tsv`) = 생성 기록 → 고치지 않는다 (원장 노트).
  배포 v1.1 · v1.2 묶음에는 이 열이 없다 (검색 확인) → 정오표 불요.  v1.3 은 고친 생성기로 만든다.
