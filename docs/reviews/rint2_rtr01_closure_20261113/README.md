## 2. RTRR-01 최소 정정

이전 audit는 새 팔 게시 전에 퇴역한다. 최종 경로에 새 audit가 없으면 `missing`, 읽을 수 없으면 `unreadable`이다. 이동 오류는 경고로 남기며 목적지 생성 후 실패의 source·destination 상태를 일률적으로 보장하지 않는다. 옛 audit을 새 팔의 기록으로 재사용하지 않는 것이 코드 보완 범위다.

| 독립 모의 전이 | 소비 결과 | source audit | 옛 audit |
|---|---|---|---|
| 이동 전에 실패 | missing | 남음 | 별도 보존 |
| 실제 이동 뒤 실패 보고 | 새 built_written, problem=null | 없음 | 별도 보존·재사용0 |
| 목적지에 불완전 JSON 쓴 뒤 실패 | unreadable: JSONDecodeError | 남음 | 별도 보존·재사용0 |

이것은 실제 교차 파일시스템 장애 측정이 아니다. 새 정책이나 실패 정규화 구현을 추가하지 않는다. 이번 실행 코드 변경0, 셸 주석과 설명만 정정했다. 동일 셸의 주석을 제외한 텍스트·기존 시험은 비교 핀과 같음(preservation.json). 원장에는 RTR-01 코드 한정 수용과 RTRR-01 문구 정정을 제안만 한다. verified/closed 자동 변경 없음.
