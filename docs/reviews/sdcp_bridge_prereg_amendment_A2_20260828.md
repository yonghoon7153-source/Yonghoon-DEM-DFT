# 사전등록 개정 A2 — 브리지 판정을 **두 PTFE 규약에서** 낸다 (2026-08-28, 두 번째 규약 unblinding 전)

> 대상: `sdcp_bridge_prereg_20260825.md` §4 + 개정 A1(`..._amendment_A1_20260827.md`).
> **문턱(30/70 %)도 estimator 도 바꾸지 않는다.**  등록된 통계량 `A` 를 **두 번째 PTFE 규약에서
> 한 번 더 측정**한다고 선언하는 것뿐이다.

## 1. 왜 — 규약 차이가 재려는 효과보다 크다

같은 침대·같은 격자·같은 코드에서 PTFE 표현만 바꾸면 이득이 **+12.37 % ↔ +30.78 %** 로 움직인다
(Table S3 §2·§3, 8팔 origin factorial, 계약 검증 `measured`).  **18.4 %p** 다.

그런데 1차 A 트랙이 재고 있는 SDCP 브리지 효과는 vox 0.15 에서 **+0.98 %p** 다
(쌍대응 ΔR = +0.00982, origin-phase SD 0.00130, 8/8 동일 부호).

⇒ **교란 축이 신호의 약 19배**다.  한 규약에서만 재고 기전 결론을 일반화하면,
그 결론이 규약에 의존하는지 **원리적으로 알 수 없다**.

⚠ 이것은 "브래킷" 논증이 **아니다** — R8 Q2 가 그 서술을 철회시켰고 여기서 되살리지 않는다.
실험 대칭셀 +23.1 % 가 두 값 사이에 오는 것은 **numerical straddling** 이지 물리적 상·하한이
아니다.  A2 의 근거는 오직 **교란 크기**다.

## 2. 무엇을 도는가 (3 런 — 4 가 아니다)

| # | vox | PTFE | SDCP 브리지 | 상태 |
|---|---|---|---|---|
| 1 | 0.15 | centerline | 0 | **이미 있다** = W4 / Table S3 §2 (`..._ptscenterline_lean2_rddb33647303c`, 16/16) |
| 2 | 0.15 | centerline | 0.01 | 신규 |
| 3 | 0.125 | centerline | 0 | 신규 |
| 4 | 0.125 | centerline | 0.01 | 신규 |

★ 1번은 러너가 같은 OUTDIR 을 만들어 **자동 SKIP** 된다.  W4 가 이 트랙의 대조팔을 겸한다
(PTFE-off 쪽에서 W4b 가 그랬던 것과 같은 구조).

## 3. 분석식 — **개정 A1 과 글자 하나 다르지 않다**

```
R_i          = σ_e(DBE, arm i) / σ_e(SBE, arm i)          (같은 origin 쌍대응)
ΔR_i(off/on) = R_i(vox 0.125) − R_i(vox 0.15)             (정규화 비트 튜플로 짝짓기)
A            = 1 − ΔR̄(on) / ΔR̄(off)
```
SE(A) 는 A1 §3 의 델타법 그대로.  팔 8개 전부 사용, **사후 제외 없음**.

## 4. 판정 — 문턱 불변

A1 §4 의 표를 그대로 쓴다 (`h1` ≥ 0.70 · `h0` < 0.30 · `BOTH_REJECTED` · 두 종류의
`INDETERMINATE`).  **PTFE 규약마다 독립적으로** 판정한다.

## 5. ★ 두 규약이 갈리면 — 그것이 결과다

미리 못 박는다 (사후에 고르는 통로를 막기 위해):

| 두 규약의 판정 | 어떻게 적나 |
|---|---|
| 같은 판정 | 기전 결론이 **PTFE 표현에 강건**하다.  두 값을 나란히 적는다 |
| 다른 판정 | **기전 결론이 PTFE 규약에 의존한다** — 그 사실 자체가 결과다.  둘 중 하나를 고르지 **않는다** |
| 한쪽이 `INDETERMINATE` | 그쪽은 판정 없음으로 적고, 다른 쪽 판정을 **그 규약에 한정해서만** 서술한다 |

⚠ **어느 경우에도 "더 그럴듯한 쪽" 을 고르지 않는다.**  두 규약 중 어느 것이 실물에 가까운지는
**미정**이다 (R8 Q2: `exact-zero` 는 국소 차단을 과대할 수도, 코팅 범위를 과소할 수도 있다).

## 6. blind 상태 (A1 §0 과 같은 형식)

이 개정을 쓰는 시점에 **PTFE centerline × SDCP 브리지 조합은 한 번도 돌지 않았다**
(런 2·3·4 미실행).  1번(W4)은 이미 관측됐으나 그것은 **대조팔**이고, `A` 는 처치팔 없이는
계산되지 않는다 ⇒ 등록량 `A` 에 대해서는 여전히 blind 다.

⚠ 다만 정직하게 적는다: **PTFE-off 쪽 A 트랙은 진행 중이고 vox 0.15 쌍을 이미 봤다**
(위 §1 의 +0.98 %p).  그러므로 A2 는 "완전 blind 재현" 이 아니라 **두 번째 규약에서의
사전등록 측정**이다.  PTFE-off 의 `A` 는 아직 안 봤다 (vox 0.125 미완).

## 7. 비용

vox 0.15 브리지 16팔 (~9 h) + vox 0.125 두 런 32팔 (~27 h) ≈ **36 h**.
1번이 SKIP 되어 4런이 아니라 3런이다.

## 8. ⚠ 다른 기계에서 돌릴 때 — `code_sha` 길이 함정 (2026-08-28 실측으로 잡음)

A2 3런은 **V100 인스턴스**에서 돌린다 (kgy 는 PTFE-off 쪽을 돌고 있다).  기계를 옮길 때
같은 커밋인데 **`code_sha` 문자열이 달라지는** 자리가 있다.

`_code_sha` 는 `git rev-parse --short HEAD` 를 쓰고, 그 **길이는 저장소마다 다르다** —
git 이 그 저장소 안에서 모호하지 않은 최소 길이를 고르기 때문이다.  실측:

| | 저장소 | `--short HEAD` |
|---|---|---|
| kgy `~/dem-mt` | 전체 이력·여러 브랜치 | **`c2f5b047`** (8) |
| V100 `~/dem-mt` | 번들 하나에서 clone | **`c2f5b04`** (7) |

`code_sha` 는 `FIELD_CONTRACT` 에서 `across_dir=True` 이고 비교는 **문자열 동일성**이다
⇒ 같은 커밋으로 돌아도 **대조쌍 검증이 HOLD** 된다.  런이 끝난 뒤에야 드러난다.

**대응** (V100 에 적용함):
```bash
git -C ~/dem-mt config core.abbrev 8
git -C ~/dem-mt rev-parse --short HEAD      # → c2f5b047
```

★ 이것도 이 리포가 반복해서 만나는 형태다 — **요청한 것(같은 코드)과 기록되는 것(다른
문자열)이 어긋나는데 실행은 조용하다.**  그래서 첫 팔 완주 시점에 `code_sha` ·
`input_digest` · `cg_info` 를 **눈으로 확인하고 넘어가는 것**을 이 트랙의 절차로 둔다.

⚠ 근본 해결은 `_code_sha` 가 **전체 40자 SHA** 를 쓰거나 길이를 고정하는 것이다 (미착수).
지금은 저장소 설정으로 막았으므로, **새 기계를 붙일 때마다 같은 설정이 필요하다.**
