# S1 OPEN 오프라인 연결 후보 전달

한 번의 오프라인 준비 제출물이다. COMSOL·JVM·compile·solve·후보 import/기능 시험·입력 gate·process/Job 시험·정책 변경·네트워크 조회는 하지 않았다. 원 수용 source/manifest/계약·기록·영수증은 보존했다.

먼저 `REPORT_KO.md`와 `CONNECTION_DETAILS_KO.md`를 읽으면 된다. 새 코드는 `candidate/`의 비활성 텍스트뿐이다. P0의 새 사본은 helper 삽입 외 전체 바이트가 동일하며 실행 차단과 기존 본문을 유지한다. `CODE_MANIFEST.json`이 새 후보/계약/검증안의 정확 바이트를 결속한다.

`STATIC_CHECKS.json`: 정적 대조 74항목 일치, 기능 시험 0회. 선택 원본 33개 보존 확인은 그 집합에 한정하며 PC/MPH/prefs 전체 관측을 뜻하지 않는다. `FUNCTION_SPANS.json`은 새 Python 함수의 LF 정규화·마지막 LF 제외 span SHA와 전체 파일 SHA를 구분하는 인덱스다.

`VALIDATION_PROPOSAL_KO.md` / `LIMITED_VALIDATION_PLAN.json`: **8군50사례(Python44/Java6), 제안1350초**, 실행되지 않은 별도 검증안이다. 기존 R1 전체 검증을 반복하지 않는다. 원 Parent 불변이라 현재 PS 재시험은 제안하지 않았다. 미래 native→Parent adapter 구현은 별도 검증 대상이다.

`SEPARATE_ALLOWLIST_DRAFT_KO.md`: 설치본 t0/계수/raw 의미와 Windows counter/commit cap/중단 provider에 필요한 별도 근거·관측·결정 목록이다. 네 OPEN은 유지한다. `native_ready=false / approved=false / usable=false`. P0·P1–P3·K·장시간 cohort 실행과 microshort 효과 결과 주장은 없다.

`PACKAGE_MANIFEST.json`은 ZIP payload만 결속하며 자신은 제외한다. ZIP 밖 `DELIVERY_RECEIPT.json`, `FINAL_PACKAGE_TOOL_RETURN.json`, `FINAL_SUBMISSION_CHECK.json`, `FINAL_CHECK_TOOL_RETURN.json`은 나중 경계를 별도로 기록한다. 내부 snapshot, 그 뒤 파일 쓰기, 외부 도구 반환을 동일한 시점으로 읽지 않는다. 최종 반환을 기록하기 위한 후속 전사 역시 당시 직접 OS 감사와 구분한다.

자료를 제출한 뒤 중지한다. 이번 준비 수용·새 검증의 별도 승인/수용을 거쳐도 실제 설치 관측/OS 구현의 OPEN이 해결되기 전 native 실행으로 넘어가지 않는다.
