# REIL C4-0a N1–N4 보완 결과 재검토

2026-10-13 · 정적 코드·기존 실행 기록 검토

## 판정

**N1–N4를 모두 닫고, C4-0a의 한정 구현을 종결 수용한다.** 새 차단 P1/P2는 발견하지 못했다. 이전 C4-0a의 증거 한정 수용에 이번 보완 코드·회귀 근거를 합친 판정이다. C4 전체, 실자료 연구 결과, C4-0b 착수 또는 계산 GO를 수용한 것이 아니다.

다음은 C4-0b 범위와 배열 세 종류의 목록·배정을 담은 사용자 확인이다. 이번 회신만으로 구현·자료 개봉·맞춤·설치·환경 재구축·COMSOL을 시작하지 않는다. 같은 결과를 얻기 위한 검증 재실행도 요구하지 않는다.

- 요청문이 추가된 커밋: `cbcf0896bdb3f7acd3fd6f1fe13b693b79907e15`. 이후 고정 HEAD까지 REIL 생산 소스·시험·배열·이번 실행 증거 변화는 없다. 뒤의 COMSOL 문서 변경은 검토 범위에서 제외했다.
- 다운로드 첨부와 고정 저장소의 발송문은 SHA-256 `d5981024f76e3418caaf0c953346e45dfc2a3045a57de9a27d4c5333571de7f5`로 같다.
- 고정 파일 37개를 읽어 보존했고 전부 Git blob 식별과 일치했다. 이전 리뷰의 수신본과 함수 원문·선택 해시도 대조했다.

후보·동봉 시험을 import하거나 실행하지 않았다. Sobol 생성, 자료·pickle·노트북 개봉, 연구 계산, 설치, 환경 재구축, COMSOL 호출은 하지 않았다. 제출자 실행 로그를 검토했으며 실행 호스트의 원시 OS 감사를 새로 수행한 것은 아니다.

근거 사본은 `source/`, 식별 목록은 `CAPTURE_INDEX.json`, 변경 이력은 `IMPLEMENTATION_HISTORY.json`과 `POST_RESULT_HISTORY.json`에 있다. 아래 줄 번호는 그 고정본 기준이다.

## 2. 네 지적의 종결 근거

| 지적 | 코드·시험 근거 | 판정 |
|---|---|---|
| N1 수용 C6와 배열의 독립 결속 | `reil_c4_e3a.py:392–405`에서 명시 SHA로 C6 MANIFEST를 먼저 인증하고 NPY 네 개를 그 항목에 직접 대조. 로컬 자기일치는 406–423행에서 별도 검사. `dryrun:479`는 같은 seal·SHA를 전달. 새 n1_a/b/c와 기존 정상 dryrun 대조가 연결됨 | 닫힘 |
| N2 마지막 기록 이후 시간 한도 | `reil_c4_monitor.py:365–379`에서 쓰기·재읽기·해시·용량 조회 후 snapshot 한 번을 얻어 판정과 반환에 공통 사용. 시간·크기 동시 위반도 둘 다 남김. n2_a/b/c/d는 마지막 쓰기 지연·용량 조회 지연·정상·동시 위반을 대조 | 닫힘 |
| N3 느린 조회 뒤 감시 최신성 | `Watch.stale:69–76`는 상태를 갱신하지 않는 조회. `supervise:224–226,285,302,310`에서 RSS 뒤·디스크 뒤·정상 종료 직전에 두 감시기의 gap을 검사. n3_a/b는 같은 대본에서 6초 지연 거부·1초 정상, n3_c는 조회가 마지막 유효시각을 바꾸지 않음을 고정 | 닫힘 |
| N4 구조 오류의 부분 기록 전달 | `worker_loop:176–179`에서 partial을 구조 오류 이벤트에 포함. `_states:188–203`에서 같은 작업에 `structural_partial`을 남기되 `STARTED_INTERRUPTED` 유지. n4_a 직접 전달, n4_b 실제 fork 경계와 계수 `(3,1,2,1)`, n4_c wrapper 내부 구조 오류 분류 보존 | 닫힘 |

N1의 핵심은 배열과 로컬 기록을 함께 고쳐도 인증된 C6 항목까지 바뀌지는 않는다는 것이다. n1_a는 바로 이 위조 후 실제 dryrun이 거부되고 출력 폴더도 생기지 않는지 본다. n1_b/c의 패치 전 TypeError는 신설 인자의 부재이지 별도의 동작 결함 두 건이 아니다.

N2의 시간 수용은 해당 함수의 마지막 snapshot까지다. 반환 후 호출자가 추가로 쓰는 파일·포장·외부 전달까지 관측한 것으로 확대하지 않는다. 파일과 해시를 보존하면서 `RECORD_INCOMPLETE`를 반환하는 구조는 적절하다.

N3의 실행 반례는 느린 디스크 조회가 RSS gap을 가리는 방향을 직접 덮는다. 반대 방향과 세 호출 위치 각각의 독립 동적 증거를 얻었다고 주장하지 않는다. 두 감시기를 함께 확인하는 코드와 조회의 무변경 성질을 정적으로 대조했으며, 이번 요구를 닫는 데 충분하다. OS 조회의 영구 정지, hard limit, 표본 사이 RSS 최대치의 보증은 별개다.

N4는 완료 결과를 만들어 버리는 수정이 아니다. 구조 오류 직전까지 실제로 모인 계수를 중단 상태로 전달하는 수정이다. 모든 종류의 강제 종료에서 부분 기록을 복구한다는 보장은 아니다.

## 4. 실행 기록과 신고 사항 수용

| 단계 | 기록 결과 | 외부 경과 / 한도 |
|---|---|---:|
| identity | rc0, ok, problems 없음 | 21.893 / 60초 |
| RED, 새 14개 | rc1, 10 failed / 4 passed | 12.284 / 600초 |
| GREEN, 기존 26 + 새 14 | rc0, 40 passed, 외부 stderr 0 bytes | 18.307 / 600초 |

RED의 10개 실패는 **행동 반례 7개 + 새 인터페이스 부재 3개**다. 후자 세 개는 n1_b/c의 `seal` 인자 TypeError와 n3_c의 `stale` 부재다. 4개 선행 통과는 n2_c·n3_b·n4_c·out이며 기능 유지·양성·관측용 대조다. 이 구분은 요청문과 원문 로그에 맞는다.

GREEN 내부 pytest 시간은 17.68초, 외부 단계 경과는 18.307초로 서로 다르다. 출력에 있는 argparse 오류는 test_08의 예상 SystemExit에서 포착된 출력이며, 별도 실패나 외부 stderr 비어 있음과의 모순이 아니다.

합성 NSGA2는 승인된 세 번이다. RED와 GREEN의 신규 outcome 두 파일은 모두 `returned`, 5,000평가, 50해, 비유한 0, 경고 없음이며 wall 외 8개 저장 필드가 같다. 기존 test_07의 GREEN 출력도 `returned 5000`이다. `n_out_eval_any=4987`도 두 파일에서 같으므로 이를 영역 문제 해소나 실자료 타당성으로 읽지 않는다. 과거 C4-0a 실행에서 남기지 않은 분기를 이번 기록으로 소급 채우지 않는다.

단계 실행기는 이전 실행기 대비 증거·scratch 경로, env 두 개와 해당 기록, 설명문 차이이며 제어 흐름을 확대하지 않았다. identity 스크립트는 이전 바이트와 같다. identity가 컨테이너 재시작 후 21.9초였다는 기록은 수용하되 원인을 추정하지 않는다.

원장 §43의 사용자 승인 전사를 확인했다. GREEN에 기존 26개 포함·독립 건조 재실행 없음은 승인 요청 §4에도 명시되어 있어 §6 권장 해석이 실행 범위를 새로 넓힌 것으로 보이지 않는다. 다만 원장 전사는 사용자 대화의 원시 감사와 구분한다.

시간 합은 **52.484 / 1,260초**다. `04_end.json`의 **103.5 / 7,200초는 커밋·push·문서 작성 전 snapshot**이다. 전체 작업의 마지막 외부 반환까지 연속 계측한 값은 없으므로 최종 전체 7,200초 준수를 별도로 입증했다고 쓰지 않는다. 명확히 공개된 이 경계는 이번 코드·시험 한정 종결을 막지 않는다.

## 5. 다음 단계와 남는 경계

1. 원장에는 N1–N4 닫힘과 C4-0a 한정 종결을 기록할 수 있다. 재시험 요구는 없다.
2. C4-0b는 새 사용자 확인 뒤에만 착수한다. profile Sobol 2, 동시 Sobol 16(앞 12 사용), label-seed 배열의 목록·배정·생성 및 봉인 시점·중복 없는 집계를 확인 범위에 넣는다. 이번 Phase A 네 배열 수용이 그 세 종류까지 봉인했다는 뜻은 아니다.
3. 실제 실행 진입점에서 이번 배열 결속·감시·최종 기록 판정을 빠짐없이 소비하는 연결은 그 구현 범위에서 검토한다. 함수 단위 수용을 미래 실행의 안전·정상 종료 보증으로 바꾸지 않는다.
4. C4-E/A/B, E3a 실자료 결과와 H1–H4 확인적 주장, 비용·장시간 연구 계산은 이번 회신 범위 밖이다. 승인·실행·자료 개봉을 자동으로 이어 하지 않는다.

비차단 개선 메모: n1_a/b는 예외 클래스 위주 assertion이다. 향후 해당 시험을 승인 범위 안에서 손댈 때 정확 거부 이유까지 고정하면 방어층 변화에 더 견고해진다. 현재 고정 입력·코드 경로·양성 대조를 함께 보면 부당 통과 근거는 없으며, 이를 이번 추가 수정·재시험 조건으로 삼지 않는다.

## 6. 검토 수행 범위

검토용 사본·회신·식별/포장 기록만 새 로컬 폴더에 작성했다. 생산 소스, 기존 증거, 승인 상태, 원장, 원본 첨부는 수정하지 않았다. 외부 발송도 하지 않았다. 문서 작성 스킬에 따라 판정·근거·한계·다음 승인 경계를 분리했다.

검토자 도구의 메타데이터 URL 인코딩 오류, 자체 읽기 명령의 문법 오류 및 비저장소 폴더의 git status 실패가 있었다. 원격 저장소·수신 코드 실행 오류가 아니며 읽기 방법만 정정하거나 해당 관측을 미확인으로 남겼다. 추가 사본 두 개의 끝 줄바꿈도 전송 직후 원 blob 대조로 바로잡았다. 최종 37개 사본은 모두 원 Git blob과 일치한다. 이런 검토 도구 사건을 제출자의 RED/GREEN 결과에 합산하지 않는다.
