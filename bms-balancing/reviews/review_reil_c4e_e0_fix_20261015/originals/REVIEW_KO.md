- SHA 인자 형식, 비JSON, 크기만 다른 항목, 모듈 경로 집합 자체 불일치는 구현 정적 근거가 있으나 이번 6개 시험의 직접 분기 실행 근거는 없다. 27 PASS를 모든 분기 시험으로 확대하지 않는다.

## 4. Q3 — E1 승인 요청서로 넘어가는 조건
작성은 가능하나 다음을 고정해 사용자 별도 승인을 받아야 한다.

1. 위 SOURCES.json 전체 SHA·5파일 식별·실행 경로/cwd 및 구현 커밋을 명시한다. 목록·모듈이 바뀌면 다시 봉인·검토·승인한다.
2. **run 프로세스를 시작하기 전**, 실행 모듈 밖의 stdlib-only 사전 검사에서 승인 목록 SHA와 정확한 5경로/크기/SHA를 검사한다. checker 자신·명령·입력도 고정하고, 실제 실행/적재 경로와 대조 대상 경로가 연결돼야 한다. 불일치면 run을 띄우지 않고 외부 meta에 남긴다.
3. 최종 단계 수용은 **독립 사전 대조 성공 AND run 최종 판정 성공 AND 실제 외부 rc0 AND timeout=false**로 한다. 현재 stage_verdict 자체가 독립 사전 대조를 이미 포함한다고 쓰지 않는다.
4. fetch의 실제 argv/env를 고정한다. 기존 고정 URL·커밋·두 경로·no-checkout·크기/SHA 검사는 유지하고 named origin·https 제한·prompt 금지를 연결한다. 네트워크 성공은 아직 미검증이며 실패 시 대체 출처·자동 재시도 없이 중지한다.
5. E1의 자료 반입·개봉·66호출 범위, 각 시간/자원·출력 폴더·첫 예상 밖 실패 중지·외부 기록 및 제출 경계를 별도 승인문에 명시한다. E0 정정 승인을 E1로 전용하지 않는다.

특히 runner:43–54의 e3a/monitor/c5/p0 import는 prepare보다 먼저다. 내부 source 검사가 util 적재 전이라는 사실만으로 실행 모듈 import 전 검증까지 완료됐다고 설명하면 안 된다. 이 점은 현 정정 범위의 새 실패가 아니라, 제출자도 명시한 E1 독립 경계의 이유다.
