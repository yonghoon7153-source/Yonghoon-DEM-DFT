# Codex 회신 프롬프트 — 불량셀 ML v2.0.0 독립 리뷰 결과

아래 전문을 Codex에게 그대로 전달하면 된다. 근거 파일은 `docs/reviews/불량셀_ML_3차_리뷰반박갱신.md`와
브랜치 `review/defective-cell-ml-v2.0.0`의 커밋에 있다.

---

네가 만든 `불량셀_머신러닝_최종_v2.0.0.zip`(SHA-256 `644ca806014d48d9939f0441c3fccc50771236a555f87a05239ba75f8015fe95`)을
독립 리뷰했다. 아래는 결과와 요청이다. 방어하지 말고 사실만 확인해서 답해라.

## 1. 내가 한 일

ZIP을 새 폴더에 풀어 Linux/Python 3.12.3 + `requirements.lock.txt` 고정 버전으로 검증했다.
**네 주장은 먼저 전부 재확인했고 모두 사실이었다.** 단위 테스트 34개 통과, `tests/verify_release.py` 7단계 통과,
`MANIFEST.sha256` 86개 파일 일치. 그다음 11개 관점(정확성, ML 방법론·누수, 실측 파일 입력, 전기화학 타당성,
예측 경로, 테스트 적정성, 문서 일치, 보안·공급망, 재현성·이식성, 사용성)으로 훑어 119건을 찾고 중복을 병합해
80건으로 정리한 뒤, 각 항목에 회의론자·재현자·영향판정자 세 관점을 독립으로 붙여 반박 검증했다.
검증은 대부분 실제 실행으로 했다. 합성 픽스처를 만들어 코드를 돌리고, 패키지 사본에 변이를 주입해
테스트가 잡는지 확인했다.

## 2. 결론부터

**치명적 결함도, 정보 누수도 없다.** 이건 형식적인 말이 아니다. 실제로 확인한 내용이다.

- **중첩 검증은 진짜 중첩이다.** `candidate_grid`는 열 이름만 쓰고, StandardScaler·대역·OCV 포함 여부·alpha·C
  선택이 전부 `GridSearchCV` 안쪽(바깥 학습 분할)에서 일어난다. 바깥 평가 셀의 정답이 선택에 참여하는 경로를
  찾지 못했다.
- **무신호 실험으로 확인했다.** 순수 잡음 특징 n=40에 대해 LOO 12 seed를 돌린 결과 pooled Q² 평균 −0.214(전부 음수),
  AUC 0.472/0.370. 같은 실험을 LOGO 4배치로 해도 Q² −0.243. 데모 12셀 라벨 순열 20회에서도 Q² 평균 −0.671.
  **낙관 편향이 아니라 체계적 비관 편향(LOO 인공물)이 나온다.** 누수가 있었다면 반대 방향이 나왔어야 한다.
- **반증으로 확인했다.** `select_model`에 바깥 test 셀까지 넘기는 진짜 누수 변이를 주입하면
  `test_outer_target_cannot_change_its_own_training_selection`,
  `test_scaler_and_inner_folds_use_outer_training_only`, `test_nested_group_separation` 세 개가 즉시 실패한다.
  R5의 핵심은 테스트가 실제로 구속하고 있다.

원래 high로 분류했던 6건은 반박 검증에서 **전부 medium 이하로 내려갔다.** 최종 분포는
medium 14, low 32, note 32, 기각 2다. 즉 **v2는 v1 대비 실질적인 개선이고, 남은 것은 실측 자료를 처음 넣을 때의
견고성과 검증 체계의 공백이다.**

## 3. 내가 틀렸던 것 (먼저 정정한다)

- **F54 기각.** "소표본에서 안쪽 fold가 2~4셀인데 경고가 없다"는 지적은 틀렸다. `outer_splits`의 오류 문구
  (`this is an execution minimum, not evidence of adequacy`)와 README §5가 이미 같은 취지를 적었고,
  `folds.json`이 fold별 `training_cells`와 선택된 36개 열 이름을 전부 기록한다. 추적 불가라는 주장은 성립하지 않는다.
- **F62 기각.** "100 kHz–1 MHz 특징이 지그 인덕턴스에 오염된다"는 측정 위생 조언이지 코드 결함이 아니다.
  격자는 사용자 설정이고 `boundary_policy='error'`가 측정하지 않은 주파수를 이미 거부한다.
  `predict.py`의 `outside_training_range`가 지그 교체 시 발동하는 것도 오탐이 아니라 의도된 OOD 신호다.
- **F33의 "원시 파일을 편집해야 한다"는 서술 정정.** `--features` CSV 경로가 1급 입력이므로 cap을 외부에서
  계산해 넣으면 된다.
- **F02의 "릴리스 게이트가 실행 완료만 보증한다"는 표현은 과장이었다.** 게이트는 raw/CSV 두 경로의 OOF 동일성,
  중첩 CV 그룹 비중복, artifact 해시 무결성을 실제로 검증한다. 빠진 건 값의 **방향·부호** oracle이다.

## 4. 네가 확인하고 판단해야 할 것 — 우선순위 순

각 항목은 실행으로 재현했다. 재현 절차와 출력은 리뷰 보고서에 있다.

### 4.1 실측 자료를 처음 넣을 때 막히거나 조용히 틀리는 것

| ID | 무엇이 | 왜 중요한가 |
|---|---|---|
| **F32** | 기본 `encodings=['utf-8-sig','cp949']`가 cp1252로 저장된 EC-Lab `.mpt` 헤더(`cm²`, `°C`)를 디코딩하지 못한다 | 셀 하나의 디코딩 실패가 `load_raw`에서 전체 실행을 중단시킨다. 셀 건너뛰기 경로가 없다. 반대로 `Cs/µF`처럼 뒤가 ASCII면 cp949가 "성공"해 헤더가 조용히 mojibake가 되고 audit에 `cp949`라는 틀린 출처가 남는다 |
| **F33** | CC와 CV가 별도 `Step No.`로 기록되는 프로토콜에서 `target_step_i`가 한 구간만 읽는다 | 5.79% 과소평가로 **같은 셀의 라벨이 정상에서 불량으로 뒤집히는 것**을 재현했다. `cc_frac`은 1.0으로 고정되고 경고가 없다. 설정으로 두 구간을 합칠 방법이 없다(`target_step_i=[1,2]`는 `DataError`) |
| **F06** | `find_cv_start`가 구간 첫 샘플 전류 하나와 1% 밴드로 CV 시작을 판정한다 | 첫 행 1.5% 오버슈트면 `cc_frac`이 0.945에서 0.004로, 전류 잡음 σ=0.5%면 0.026으로 조용히 붕괴한다. 20 mAh 셀의 C/10은 2 mA라 0.3~0.5% 잡음이 현실적이다 |
| **F27** | `cap`에 `design_capacity_ah` 대비 타당성 검사가 없다 | mAh 단위로 잘못 넣거나 soft short로 용량이 부풀어도 전 셀이 조용히 "정상"으로 라벨링된다. 설계용량의 250%인 셀도 통과한다 |
| **F19** | 다중 sweep `.mpt`에 sweep 선택 수단이 없다 | `"select a sweep"` 오류를 내면서 정작 고를 방법이 없다. 유일한 우회인 `'mean'`은 SOC가 다른 스펙트럼을 평균해 어떤 실제 상태에도 대응하지 않는 값을 만든다 |
| **F13** | manifest·features CSV를 `cfg.encodings` 없이 UTF-8로만 읽는다 | 한국어 Windows Excel이 저장한 CSV(cp949)가 세 CLI 모두에서 실패하고, `extract_capacity.py`에서는 traceback + exit 1로 끝난다 |

### 4.2 검증 체계의 공백 — 이게 제일 중요하다

| ID | 무엇이 |
|---|---|
| **F03** | 패키지 사본에 변이 25개를 주입하고 34개 테스트를 돌렸더니 **23개가 살아남았다.** Ridge 후보 전체 제거, `fixed_baselines`를 바깥 테스트 셀 포함 전체에 적합하는 누수, 대역 열 목록 교환, Q² 공식 변경, 안쪽 선택 지표 변경이 전부 통과한다 |
| **F02** | 같은 변이를 `tests/verify_release.py` 7단계에 올려도 **4/4 검사, 7/7 명령이 "passed"다.** Logistic 확률 클래스를 반전시켜 `TP=0 FN=6 FP=6 TN=0`, `AUC=0.0`이 된 완전 반전 분류기도 통과했고, `predict.py`의 불량 판정 부등호를 뒤집어 정답과 0/12 일치가 돼도 통과했다 |
| **F04** | "배치 분리" 검사는 `make_demo`가 `batch_id`를 `i//4`로 주어 배치가 셀 순서와 연속이라, `GroupKFold`를 그룹 무시 `KFold`로 바꿔도 통과한다. 배치를 `(i%3)+1`로 교차시키면 위반 6건이 잡힌다 |

**원인은 데모 데이터가 너무 쉽다는 것이다.** `make_demo`에서 `cap`과 `ocv`가 둘 다 `severity`의 선형 함수라
`corr(cap, ocv)=0.9944`이고, 37개 특징 전부가 단일 임계값으로 클래스를 완전 분리한다. 그래서 릴리스 검증 3회 모두
최종 용량 모델이 **EIS를 전혀 쓰지 않는 OCV 단독 선형회귀**로 선택됐고, `baseline_ocv`의 Q²(0.983)가
중첩 선택(0.967)보다 높다. Ridge 경로가 망가져도 아무것도 실패하지 않는다.

### 4.3 지표 해석

| ID | 무엇이 |
|---|---|
| **F11** | LOO 평균 예측기의 `baseline_mean` Q²는 자료와 무관한 상수 `1−(n/(n−1))²`다(n=12에서 −0.190, 실제 값과 부동소수점까지 일치). 같은 이유로 threshold AUC가 **정확히 0**이 된다. 즉 **무정보 기준선은 0이나 0.5가 아니다.** 분류 표에 기준선 행이 없어 이를 알 방법이 없다 |
| **F31** | Logistic 안쪽 선택 지표(비가중 log loss)가 학습 목적(`class_weight='balanced'`)·판정선 0.5와 불일치한다 |
| **F07** | LOGO에서 OOF 평가는 성공하고 `save_final`만 실패하면 `metrics.json`에 logistic 지표와 `unavailable['logistic']`이 동시에 기록되고 모델 파일은 없는 모순 상태가 된다. 13셀 배치 구조 (2,3,3,3,2)/불량 (1,1,0,0,1)로 재현했다 |

### 4.4 예측 경로

| ID | 무엇이 |
|---|---|
| **F01** | **네가 동봉한 `release_check` 산출물 자체에 이미 나타나 있다.** `new_predictions.csv`의 12셀 중 3셀(61, 69, 72)이 `review_required=True`다. 이 셀들은 학습 셀 41·49·52의 바이트 동일 복사본인데도 그렇다. 원인은 `pd.read_csv` 기본 파서의 1 ulp 왕복 오차와 허용오차 없는 `<`/`>` 비교다. `float_precision='round_trip'`으로 읽으면 0건이 된다. `verify_release.py`는 `seen_in_training`만 검사해 이를 놓쳤다 |

## 5. 내가 이미 고친 것

브랜치 `review/defective-cell-ml-v2.0.0`에 모듈별로 커밋했다. **원본 ZIP과 네 원격 브랜치는 건드리지 않았다.**
확인하고 받아들일지 판단해라.

- `extract`: 인코딩(cp1252 추가), CC/CV 판정 견고화, 다중 sweep 선택, CLI 종료 규약 통일, cap 타당성 검사,
  manifest/CSV 인코딩 헬퍼
- `predict`: 범위 비교 허용오차와 `float_precision='round_trip'`, 선택 특징 기준 플래그와 이탈 특징 열,
  artifact 해시 대조, 의존성 버전 기록, provenance 확장
- `tests`, `models`: 값 수준 oracle, 변이 저항 픽스처, 기준선 행, 진단 기록

**검증 결과: 단위 테스트 84개 통과, 배포 검증 11개 항목 전부 통과. `raw_group`의 OOF 예측은 수정 전과
비트 단위로 동일하다(최대 상대차 0.0). 평가 의미론을 바꾸지 않았다는 뜻이다.** 예측 오탐은 3건에서 0건이 됐다.

## 6. 요청

1. **4.1과 4.2를 먼저 판단해라.** 특히 F33과 F06은 실측 프로토콜을 알아야 올바른 수정을 정할 수 있다.
   내 수정은 조용한 실패를 시끄러운 실패로 바꾸는 방향으로 보수적으로 했다. 네가 랩의 실제 cycler 출력 형식을
   안다면 더 나은 선택이 있을 수 있다.
2. **F03·F02의 변이 테스트를 네 쪽에서도 재현해 봐라.** 내가 쓴 변이 목록은 보고서에 있다. 데모 데이터를
   어렵게 만들거나 별도 픽스처를 추가하는 방향 중 어느 쪽이 나은지 의견을 달라.
3. **동의하지 않는 항목은 근거를 들어 반박해라.** 나도 2건은 스스로 기각했다. 내 판단이 틀렸으면 그렇게 말해라.
4. **문서 수정은 아직 안 했다.** README §4 설정표에 빠진 7개 키(`logistic_class_weight`, `feature_sets`,
   `encodings` 등), `inner_splits` "최대 3"이라는 오기, LOO 풀링 편향 설명, 원시 입력 형식 요건
   (파일명 `cell<번호>` 규칙, cycler 7개 열 이름, 탭 구분)이 필요하다. 네가 쓰는 게 맞다고 본다.
