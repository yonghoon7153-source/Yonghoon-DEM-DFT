### 고치는 중에 새로 드러난 것 (모두 같은 커밋에서 닫음)

- `dataset.py` 설명의 "rlvtEpsdSumNtslAmt 는 261회부터 정확히 절반" 은 틀렸다 (79회가 0.0002% 안에서 어긋남) — 항등식으로 쓰지 않고 설명만 고침. B2 를 측정하다 발견.
- 궁합수 하위 목록은 내림차순을 뒤집어 만들어, 안정 정렬 뒤에는 동점이 번호 역순이 됐다 — N1 테스트가 잡음.
- `content.raw()` 는 확인하는 폴더와 읽는 폴더가 달랐다 (`load_*` 기본 인자는 import 때 고정) — 그리고 로또 파일 mtime 만 봐서 연금만 바뀌면 못 봤다. view 테스트가 잡음.
- 확산 모델 '잡음을 핫 번호로 과장' 의 근거 상관 r = 0.294 는 45개 번호에서 p = 0.050 (경계) — 이제 p 로 판정한다.
- **fixture 가 진실을 가린 사례**: `test_site_js.py` 의 파이썬 대조 기준이 make.js 의 잘못된 규칙(1~3등 공개 금액 그대로)을 베껴 써서 H1 을 못 잡았다. 기준을 옳은 규칙으로 고치자 그 테스트가 먼저 깨졌다.
