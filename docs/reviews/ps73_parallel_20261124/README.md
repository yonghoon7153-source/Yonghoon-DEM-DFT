# 7:3 탈압 병렬 개발 계산

1저자 2026-11-24 승인. UT와 UC는 RJ 368315에서 검증한 7:3 S0를 각각 NP6으로 읽는다. UB 368469가 정상 종료되면 UVa를 같은 NP6으로 먼저 계산한다. UB·UT·UC·UVa를 모두 회수한 뒤 원 판독기의 0.10 %p 규칙으로 한 번 선택한다. UT의 시간 간격은 기본값의 절반이다. UC는 판을 정지하고 50,000걸음을 관측한다. UVa는 기본 시간 간격, 절반 판 속도, 두 배 유지 조건이다.

## 경계와 관측

- 기존 UB와 직렬 단계별 예약을 읽어서 등록 잡, 덱, 기계 코드, 복원 증서, 초기 체크포인트, 판과 기준 파일을 확인한다. 단계별 예약이 소모됐거나 다른 팔이 이미 등록됐으면 멈춘다. 이 묶음이 쓰는 폴더는 기존 복원 폴더 및 기존 컨트롤러의 상태 폴더와 분리한다. 기존 UB 자체는 원래 러너로 계속 실행한다.
- 첫 제출 전 사용자 전체 실행·대기 코어와 12코어를 합산한다. 각 제출 직전에는 6코어를 다시 더한다. 조회에서 잠시 사라진 미완료 승인 잡도 포함한다. 외부 계정 정책 및 다른 도구가 조회와 제출 사이에 바꾼 코어 배정은 스케줄러가 관리한다.
- 시간 한도는 잡마다 5일이다. UB·UT·UVa가 TIMEOUT이면 가장 최근의 완전한 단계 끝 restart와 상태 파일을 맞추고 직전 출발점보다 진전이 있는 경우에만 새 NP6 할당을 요청한다. 이 할당의 첫 동작은 사본 경로에서 봉인 덱의 재개 부분을 읽어 운동을 진행하지 않는 run 0 점검이다. 6프로세스, 걸음, 단계, 입자 수를 확인한 뒤 정규 덱을 이어 돌린다. 소스 덱은 보존한다. UC는 정지 대조 덱의 기록 규약상 시간 초과 때 기술 결측으로 남긴다.
- 원 UB가 시간 초과되면 종료 확정 뒤에만 별도 작업 공간에 원자료를 복사하고 파일별 해시와 독립 파일 여부를 검증한다. 새 UB 구간은 그 사본에 기록한다. 원래 UB 시도는 별도 출처로 남긴다. 체크포인트가 없거나 짝 파일이 불완전하거나 진전이 없으면 해당 팔의 재개가 멈춘다.
- 개별 결과는 팔별로 기록한다. 종합 판정 직전에 원자료를 재판독한다. 등록 허용폭 내이면 UVa를 속도 대조로 채택하고, 초과하면 UVa는 보조 자료이며 UVb는 별도 1저자 GO 대상이다. 끝점 미확정은 그대로 기록한다. 자동 제출 범위는 UT·UC·UVa 및 위에서 승인한 TIMEOUT 재개이다.
- 운영자 TXT는 GO, STATUS, RETURN, RESUME 네 모드를 제공한다. STATUS는 원 UB의 Slurm 경과·한도와 활성 잡 잔여시간, 팔별 잡·재개 걸음 및 감시 상태를 보여준다. RETURN은 가벼운 현재 기록과 그 해시를 매번 새 폴더로 받는다. FINAL은 전체 판정 파일이 있을 때만 표시한다. RESUME은 원 승인 기록을 재사용해 종료된 감시를 다시 띄운다. 제출 응답이 모호하면 새 잡을 보내지 않는다.

## 검증

테스트는 기존 원 작업 트리에 쓰지 않는 경로, 승인 중복 차단, 예상 합계 58, 첫 제출 뒤 생긴 대기 잡으로 인한 두 번째 제출 거부, UB 반환과 UVa 시작 순서, 5일 시간 초과와 체크포인트 진전, 재개 검사 실패, UC 기술 결측 및 원 판독기의 0.10 %p 경계를 모의 환경에서 확인한다. 운영자 배포본에 쓰는 판독기와 러너의 기존 소스는 현재 Git 트리의 docs/reviews/ps73_development_sequence_20261121에서 가져온다. 현장 발사와 결과 수집은 1저자 WSL에서 한다.
