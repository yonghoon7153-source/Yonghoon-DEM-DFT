## 4. Q1–Q4 판정

**Q1 — LPI-01 출력/flush/종료: 수용.** 명령 `pressure_inventory.sh:258`의 계산/직렬화 try와 `:274`의 출력 try가 분리되어 있다. `:275`에서 short write를 거부하고 `:277`에서 flush, `:286`에서 즉시 종료한다. 최초/부분/지속 write·short write는 정확한 프로세스 rc2이며 두 번째 write가 없었다. 실제 `TextIOWrapper(BufferedWriter(RawIOBase))`의 첫 raw write가 prefix를 내고 실패한 경우 raw 호출 1회·rc2, 종료 재flush 표지 없음. 실제 CPython의 정상 pipe stdout은 완전한 JSON 하나·rc0이었다. custom Sink 정상 시험만으로 결론내리지 않았다.

**Q2 — 계산 오류·shell 상태·수신 계약: 수용.** 계산 예외와 직렬화 불가 객체는 각각 고정 `INVENTORY_ERROR` JSON 하나·rc2였다. 완전한 `INVENTORY_COMPLETE/rc0` JSON이 이미 나간 뒤 flush를 실패시켜도 프로세스 rc2이며 수신 조건상 거부된다. shell의 `exec` (`:5`)에서 fake exit2→2, exit7→7, 부분 출력 후 exit7→7, SIGTERM→subprocess returncode -15(셸의 통상 143 표현과 구분)를 확인했다. missing/non-executable interpreter는 각각 127/126, stdout 빈 값, fallback 없음. 이번 셸에서 stderr도 비었으나 외부 shell 자체 실행 실패까지 공통 보장으로 확대하지 않는다. README:31,35 및 수정 증거 README의 범위 한정이 충분하다. 단일 write의 원자성·어떤 장애에서도 JSON 존재·치명적 런타임 실패의 rc2를 보장한 것은 아니다.

**Q3 — LPI-02: 설명과 반례 보존만 수용.** README:33은 크기 상한과 시간 상한을 명확히 구분하고 regex·디렉터리 열거·파일시스템 대기·wall-clock 무제한을 명시한다. 원격 이전 PIN 명령과 현재 명령에서 main/entry를 제외한 Python AST 전체가 동일하다. B7 바이트와 정규식도 동일하다. 원격 compare 58개 변경 경로는 해당 리뷰·인계 문서에 한정되며 등록/생산/B7 변경은 없다. 기존 느린 반례와 원본 ZIP이 보존됐다. 같은 형태의 120,019자 입력을 이번에도 각 버전에서 1회 실행했으며 5초 제한을 넘었다(약 5.006/5.007초). 이는 탐침의 제한이고 명령의 시간 제한이 아니다. 시간 위험 해결·현장 지연 적격성으로 종결하지 않는다.

**Q4 — 최초 audit 관찰: 보존 적절, 원인 미확정 유지.** 보존된 `test_pressure_inventory_py311.log`는 최초 20개 중 19 성공·1 FAIL, suite rc1이며 test17의 expected0/observed2를 담고 있다. 이 assertion은 쓰기 검출 assertion보다 먼저 실패하므로 '쓰기 발생을 검출했다'고 해석할 수 없다. 구현측 후속 단독 진단/순차20 통과는 별도 기록이고 최초 실패를 무효화하지 않는다. 이번 순차20과 wrapper 단독 진단도 두 버전에서 통과했으나 역사적 실패의 원인을 밝힌 것은 아니다.

## 6. 재현 명령·자료 배치

압축을 풀면 `evidence/`, `source/`, `mutations/`가 같은 부모 아래 놓인다. source는 검토한 고정 PIN의 부분 스냅샷이다. 원본 저장소를 변경하지 말고 별도 임시 폴더에서만 실행한다. 실제 CLI `ibb|wsl`를 연구 기계에서 실행하는 지침이 아니다.
