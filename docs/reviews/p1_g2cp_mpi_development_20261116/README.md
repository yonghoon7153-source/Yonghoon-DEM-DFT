## 2. 구현

- `docs/reviews/p1_g2c_sandbox_20261104/run_g2cp.sh`: 변수 없음 = 직렬, 변수 있음 = NP 2 또는 4. MPI N은 200/40000만. SLURM job·task 수·provenance·MPI 실행 파일/버전·wrapper 꼴을 확인한다. 네 wrapper는 기존 덱을 include하며 여덟 원 덱 바이트는 보존한다.
- 같은 NP로 아홉 팔을 순차 호출한다. NP2 = 2×1×1, NP4 = 2×2×1. 실제 로그의 모든 Loop procs와 단일 grid 줄이 안 맞으면 남은 팔을 중단한다. `-h`는 기존처럼 MPI 없이 호출한다. 실제 엔진을 이 창에서 호출하지 않았다.
- 고정 기본 장부에 prestop/attempt를 남긴다. attempt 뒤 폴더 생성 실패는 rc4. 임의 장부 경로·빈 경로 우회는 거부한다. MPI OUT은 장부 단어 경계를 보존하도록 공백 없는 경로만 받는다.
- 대조기는 직렬/MPI 모두 로그를 확인한다. np 줄만 지운 병렬 출력을 직렬로 받아들이지 않는다. 같은 NP 왕복·직렬 기준 제외·랭크 경계와 애매 쌍·마-3p를 분리한다. helper와 wrapper 신원도 검사한다.
- MPI JSON은 `development_only=true`, `registered_conclusions_adoptable=false`. 판정 다/라의 PASS는 해당 덤프 비교 판정이며 등록 결론①–③·RJ·물리 자격 승격이 아니다.

## 3. 시험과 보존

`checks.json`에 같은 최종 10메서드의 구본/후보 대조를 기록한다. 수정 전 16개 실패 관측·오류0 → 후보 10/10. 실패 관측은 subtest를 포함하므로 16개 고유 메서드라고 쓰지 않는다. 가짜 LMP·가짜 MPI만 사용했다. 동일-NP 합성 왕복을 실제 대조기에 넣었고 np 삭제 시 NOT_COMPUTED도 확인했다.

기존 직렬 시험 중 순수 판독·합성/CLI 26메서드는 통과. 별도 경로 시험 1메서드는 Windows 링크 생성 권한 때문에 완료하지 못했다. 나머지 POSIX 실행기·신호 이름공간 시험은 미실행. 전체 41개나 전체 gate 통과를 주장하지 않는다.

Windows에서 옛 fixture의 기본 텍스트 쓰기가 CRLF를 만들어 POSIX md5 목록 계약에서 먼저 거부됐다. 시험 생성물에 UTF-8·LF를 명시하고 Python CLI의 UTF-8을 명시했다. 생산 md5 파서는 약화하지 않았다. 가짜 로그에는 실제 로그 형식의 processor-grid 줄을 보탰다. 기존 시험 assertion을 삭제하지 않았다.

재현 (로컬 가짜 도구만): `python -I -X utf8 -B docs/reviews/p1_g2c_sandbox_20261104/test_g2cp_mpi.py --bash bash`. 실제 Linux에서는 POSIX 셸로 같은 시험을 돌릴 수 있다. Windows 시험은 Git Bash이며 실제 Slurm/Open MPI 검증이 아니다.

## 4. 남은 한계와 운영

| 항목 | 현재 | 개발 계산에서의 처리 |
|---|---|---|
| 실제 Linux·Slurm·MPI·신호 정리 | 미실행 | 새 폴더, 잡 하나씩, scheduler 시간 상한과 기존 팔 timeout, 실패 뒤 자동 재시도 없음 |
| 재큐 독립 이력 | 미수령 | no-requeue 요청과 scheduler 기록을 회수. 요청만으로 재큐 부재를 인증하지 않음 |
| 최초 내용 판정·NP당 시도 한도 소비자 | 자동 채택/동결 도구 미구현 | JSON의 등록 결론 채택=false 유지. 등록/논문에 쓰기 전 별도 완결 필요 |
| 장부 append 신호 경계·동시 쓰기 내구성 | 현장 자격 미확인 | 한 운영자·한 잡씩. 독립 장부 감사와 같은 NP의 등록 판정 자동 승격 없음 |
| 임의 MPI 분할·NP6·생산 침대·교차 NP | 범위 밖 | 호출 허용 없음·결론 확장 없음 |
| A 생산 키트·RT·봉인 | 변경 없음 | 별도 작업 |
