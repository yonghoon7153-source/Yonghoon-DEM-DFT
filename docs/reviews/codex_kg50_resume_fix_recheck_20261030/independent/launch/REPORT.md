# 실행 경계 독립 재검토 — resume_ckpt.sh

- 검토 핀: `bf8cf21c6466cdb9411f9320711b871c2d1c651e` 제공본.
- 읽은 제품: `repo/scripts/resume_ckpt.sh`, SHA-256 `77c242375c4093023e609703ef471c64c2370d374e7533824412d96da5b1b9f8`.
- 범위: 시험 제출 → G0–G3 → 본 제출, 현재 호출/attempt, 큐 재조회, 도구/입력 신원, 본 sbatch 응답.
- 제품 변경 없음. 증거는 `independent/launch/`에만 작성했다.
- 실행 범위: **원문 embedded Python 함수 실행**, 셸의 제한된 grep/sed/hash 조건 **독립 Python 전사**. Bash, fake-SLURM 전체 흐름, 실제 SLURM, MPI, LIGGGHTS는 **미실행**. 알려진 Bash 시작 실패를 우회하거나 권한을 바꾸지 않았다.

## 결론

이전 KG50R-04의 “이번 호출에서 시험을 내지 않았는데 옛 성공 파일로 승격” 경로는 소스상 닫혔다. 승인 hash와 본 제출 직전 재조회, 본 sbatch 응답 검사도 요청한 방향으로 구현돼 있다.

그러나 **검사한 덱과 러너가 실제로 읽는 덱의 대응이 보장되지 않는 새 P1 경로 반례**가 남는다. 정상 러너의 `-in input_C_r56.liggghts` 뒤에 `.bak`만 더한 입력은 러너 검사 세 조건을 모두 만족한다. 이때 시험은 검사한 시험 덱과 바이트가 같은 `.bak` 시험 덱으로 성공할 수 있지만, 본 러너는 첫 긴 run 뒤 물리 명령이 추가된 별도 `.bak` 덱을 읽는다. 검증한 덱/러너 hash도 그대로다. 따라서 Q1의 최소 해제 목록 5 및 Q2의 무조건 본 제출 GO를 이 범위에서는 지지하지 않는다.

이는 **소스 경로 반례**다. 실제 본 제출을 관측했다거나 실제 물리 런이 수행됐다는 주장은 아니다.

## 새 P1 — 부분문자열 러너 검사와 hash 영수증이 실제 입력 파일을 묶지 못함

**위치:** `repo/scripts/resume_ckpt.sh:1145`, `:1151`, `:1168`, `:1180`, `:1186`, `:1279`, `:1283`. 시험의 빈틈: `repo/scripts/test_resume_ckpt.py:69–83`, 특히 `:81`은 러너를 실행하지 않고 제공된 로그를 복사한다.

`:1168`의 전체 프로그램 검사는 `$D = $W/input_${C}_${SFX}.liggghts`를 읽고, `:1180`의 `main_inputs.sha256`은 그 `$D`와 `$RN` 두 파일을 기록한다. 그러나 `:1151`은 셸 프로그램의 실행 위치, 실제 `-in` 인자, 명령의 유일성을 확인하지 않는다. 본 러너에는 MPI 부분문자열만, 시험 러너에는 다음 부분문자열만 요구한다.

```text
-np 56 lmp_mpi -in input_kg50_d2_b50_r56t.liggghts
```

토큰 끝을 고정하지 않아 다음 실제 명령도 통과한다.

```bash
mpirun --oversubscribe --bind-to none -np 56 lmp_mpi -in input_kg50_d2_b50_r56t.liggghts.bak
```

본 러너도 같은 `.bak` 인자를 가지며, `:1145`의 전역 이름 치환은 이를 그대로 보존한다. 주석, `echo`, 조건 분기, 제출 후 파일 변경은 반례에 필요하지 않다.

`probe_launch.py`는 제공된 실제 D2 r4 재개 덱을 정상 `$D`로 복사했다. 별도 `.bak` 본 덱에는 첫 `run 180000` 다음에 `velocity all set 1.0 0.0 0.0` 한 줄만 추가했다. `.bak` 시험 덱은 그 별도 본 덱에서 원문 `cut_trial()`로 만들었다. 덱의 첫 run 전과 2,000-step 시험은 그대로이므로 두 시험 덱은 바이트 단위로 같다. `.bak` 파일은 멈춘 폴더에 남아 있거나 helper 산출로 함께 존재할 수 있고, 현재 코드가 지우거나 거부하지 않는다.

| 검사/관측 | 독립 결과 | 증거 수준 |
|---|---|---|
| 정상 `$D` 전체 프로그램 검사 | 문제 0, 잔여 끝 200001, 뒤 명령 64개 같음 | 제품 embedded Python 실행 |
| 정상 시험 절단 | `180000 2000 0 157` | 제품 embedded Python 실행 |
| 정상 시험 run 합 | `2000 1 [run 2000]` | 제품 embedded Python 실행 |
| `.bak` 본 덱을 실제로 검사한다면 | 문제 1: `velocity all set ...`는 재개 덱에만 있음 | 제품 embedded Python 실행 |
| `.bak` 시험 덱과 검사한 시험 덱 | SHA 및 모든 바이트 같음 | 실제 파일 비교 |
| :1151의 러너 조건 3개 | 전부 true | 제한된 grep 의미의 Python 전사 |
| 본 제출 직전 `$D`/`$RN` hash | 모두 일치 | 실제 파일 SHA 비교, 셸 명령은 미실행 |
| 실제 본 `-in` 파일의 manifest 포함 여부 | false | 경로 대조 |
| 실제 시험/본 sbatch | 미실행 | 관측 제출 횟수 없음 |

G0–G3는 시험 로그와 상태를 보지만, 어느 입력 경로가 실행됐는지는 보지 않는다. 따라서 위 바이트가 같은 시험에서 정상 관측이 나오는 조건이면 게이트 결과가 같고, 본 제출만 검사하지 않은 `.bak` 덱으로 간다. 실제 자료의 정상 D2 러너 자체가 `.bak`를 읽는다는 주장은 아니다. 외부 helper 산출을 검증하는 관문의 누락이다.

**최소 해결:** wrapper가 제한된 규격의 시험/본 러너를 직접 만들고, 작업 폴더와 `-in`을 검증된 절대 경로로 고정하는 방식이 가장 작고 명확하다. 기존 helper 러너를 받아야 한다면 임의 셸의 부분문자열 검사를 안전 증명으로 사용하지 말고, 허용한 정확한 명령 구조/단일 실행/실제 cwd/실제 입력 경로를 검사해 모르는 형태를 거부한다. `grep`에 문자열 끝만 붙이는 것은 `.bak` 한 사례만 막으며 주석·다른 cwd·둘째 명령 반례를 닫지 못한다. 본 제출 manifest는 실제 실행할 덱을 포함해야 한다.

**회귀 조건:** 가짜 sbatch가 로그를 복사하는 것에 그치지 말고, 실제 러너가 어느 cwd와 `-in`으로 실행되는지 기록하도록 한다. 정상 입력은 허용하고 `.bak`, 잘못된 `cd`, 주석에만 존재하는 정상 명령, 둘째 MPI 실행, 절대 경로의 다른 덱은 제출 전에 거부해야 한다. 실제 LIGGGHTS를 돌릴 필요는 없다.

## 영수증과 엄밀한 유한성의 잔여 한계

1. **체크포인트 원문 hash는 기록되지만 본 제출 때 다시 확인되지 않는다.** :1183은 `$W/$RR` hash를 tool.txt에 남긴다. :1180의 manifest에는 `$D`와 `$RN`만 있다. 시험 후 체크포인트 placeholder 바이트만 바꾼 독립 파일 실험에서도 그 두 hash는 계속 일치했다. :1175의 attempt 복사에도 체크포인트 원문은 없다. 이는 요청서의 “체크포인트 신원”이 기록 수준임을 의미한다. 일반적인 파일 변경/TOCTOU만으로 별도 P1을 주장하지 않는다. 같은 checkpoint 바이트를 시험과 본 실행에 묶겠다는 계약이라면 실제 읽을 checkpoint 경로를 manifest와 제출/실행 검증에 포함해야 한다.
2. **실제 작업 환경의 lmp_mpi 신원은 아직 아니다.** :1179/1184는 호출 셸의 PATH 바이너리를 기록하고 잡 환경은 다를 수 있음을 정확히 쓴다. 제공 D2 러너에는 `source ~/.bashrc`와 `conda activate myenv`가 있다. 실제 잡의 resolved binary/path/hash 영수증이 추가돼야 실제 바이너리 인증으로 읽을 수 있다. 이 한계는 도구/요청서에 이미 드러나 있고 새 회귀로 세지 않는다.
3. **fin()은 숫자 토큰 문법 검사다.** `1e9999`는 :1062/:1068 regex를 통과한다. 독립 전사에서도 true이며 Python의 double 변환은 inf이다. 실제 awk 처리/실제 LIGGGHTS 출력 경로는 시험하지 않았고, 이 사실만으로 새 false-green 본 제출을 주장하지 않는다. “모든 칸이 유한”이라는 엄밀한 계약에는 범위/변환 결과 검사도 필요하다. 일반 `nan`/`inf` 철자 거부와 별개의 한정이다.

원본 데이터/코드로 계산한 결과: `results.json`. 최소 반례 파일: `runner_suffix/run_kg50_d2_b50_r56.sh`, `runner_suffix/run_kg50_d2_b50_r56t.sh`, 정상 두 덱 및 `.bak` 두 덱. `.bak` 확장자는 이 반례의 실제 입력 이름이며 백업 여부를 시스템이 보장하는 표지가 아니다.
