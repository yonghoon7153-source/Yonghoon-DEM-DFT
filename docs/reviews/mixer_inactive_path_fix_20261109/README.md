## MIP-01의 원인과 변경 계약

원 검증기는 `build`에만 candidate/evidence 상호 중첩 금지를 적용했다. `verify`에서 evidence를 candidate 아래 새 폴더로 지정하면, 빈 증거 폴더를 만든 뒤 파일43개를 정상 검증하고 그 안에 `report.json`을 추가했다. 독립 재현은 최초 rc0, 기존43파일의 바이트 변경0, 파일집합43→44, 다음 검증 rc1이었다. 경로 조작이나 소스 변조 없이 정상 인자로 입력 보존 계약을 위반했다.

이번 수정 계약은 다음과 같다.

- `old`, `build`, `verify`, `preparation-tests` 모두 동일한 경로 검사를 사용한다. 경로를 정규화한 뒤 candidate/evidence의 동일 경로와 양방향 포함 관계를 거부한다.
- 거부는 증거·후보 디렉터리 생성이나 파일 쓰기보다 먼저 일어나야 한다. 정규화 전에 기존 조상 링크 검사를 유지하고, 링크 검사 후 정규화한 경로로 포함 관계를 확인한다. snapshot과 쓰기 대상의 경계도 정규화한 경로로 확인한다.
- 거부 시험은 입력의 파일 바이트뿐 아니라 파일집합과 디렉터리집합도 보존되는지 확인한다. 직접 표기와 `..`를 포함한 동등 표기를 구분해 확인한다.
- 별도 형제 evidence 경로의 기존 정상 동작과 반복 읽기 검증은 유지한다. `build`는 새 후보에만 쓸 수 있고, 기존 evidence·candidate를 덮어쓰지 않는다.

기존 폴더에서는 `verify_inactive.py`만 변경한다. 후보43·자산40·메타8·결속·비활성 계약·source inventory 및 고정 의존86의 내용은 바꾸지 않는다. 이전 README·요청서·증거는 역사 기록으로 보존하며, 이번 README가 검증기의 경로 보존 구현 상태를 보완한다. 기존 요청서의 `PIN.txt` 표기는 고치지 않고 새 요청서는 실제 파일명 `SOURCE_PIN.txt`를 사용한다.

## 시험 범위와 남는 한계

새 `test_evidence_boundary.py`는 고정 입력의 로컬 사본에서 네 모드의 경로 거부와 정상 형제 경로를 확인하는 회귀 시험이다. 동일 시험 바이트의 **5메서드: 수정 전 33 assertion failures/오류0·rc1 → 수정 후 5/5 PASS·오류0·rc0**다. 각 단계는 정상 형제4모드 + 중첩36조건(4모드×3관계×3경로표기) + 원 반례 재검사1 = 로컬 검증기 CLI41회다. 수정 후 36조건 모두 공통 사유로 거부되며 파일·디렉터리 그래프가 그대로이고, 원 반례 후보는43파일 보존 후 재검사 rc0이다. 경로 경우의 수·CLI 수를 메서드 수와 혼합하거나 기존 8케이스·3짝·준비14·캐시5와 합산하지 않는다.

수정 전 실패33은 오염33건이 아니다. 중첩36조건 중 그래프 변경15, 기존 경로 존재 검사로 먼저 거부되어 공통 경로 사유가 다른18, 기존 build 가드로 이미 거부된3을 구분한다. 원입력과 고정 스냅샷은 전 과정에서 보존했으며, 결함 재현을 위해 오염된 red **복사본**과 그 원로그도 삭제하지 않았다. 시험 docstring의 보존 설명은 원입력 보존 및 시험 사본의 증거 보존으로 읽어야 하며, red 사본까지 불변이었다는 주장이 아니다. 최초 부모 harness의 Windows argv 표현 처리 오류는 자식 CLI0회에서 차단된 별도 준비 오류이고 대상 검증기의 red 결과로 계상하지 않는다.

같은 시험 바이트, 수정 전후 검증기 신원과 원로그 해시는 리포의 `verification_summary.json`과 전달 ZIP의 `evidence_extra/before/red/report.json`·`evidence_extra/after/report.json`에 결속한다. 이전 폴더의 `evidence.json`은 원 후보의 역사 증거이며 이번 경로 수정의 새 실행 근거가 아니다. 수령 감사 agent는 새 결과 JSON·소스 바이트를 대조했으며 시험을 다시 실행하지 않았다.

기존 loader 회귀5도 수정 검증기로 5/5 PASS이며 cache 표식 실행0·실제 링크 생성0·과학 모듈 import0이다. 이 별도 합성 회귀를 위 CLI41회나 경로5메서드와 새로운 고유 시험 수로 합산하지 않는다.

이번 검증은 로컬 Python 합성 시험이다. 기존 검증기의 source-only loader·닫힌 스냅샷 그래프·제한된 subprocess/socket 차단 경계를 보존하며, 실행 환경 전체에 대한 보안 보증으로 확대하지 않는다. 링크 신호 mock과 실제 OS symlink/junction 자격은 다르고, 적대적 동시 파일시스템 변경은 검증 범위 밖이다. 정상 `old` 모드의 옛 메타8 실패는 기대 결과이며 MIP-01 거부 결과와 구분한다.

연구 결과0, 실제 원자료·호스트·시뮬레이터·Slurm·MPI·관측 파이프라인 접근0이다. 기존 드라이버의 자동 채택이나 운영 봉인 교체는 없다. 채택된 NP20·초기1/조건부 최대2·순서 정책을 현장 자격·후속 wave·실행 GO로 확대하지 않는다. 기존 운영 준비와 자격·승인 조건은 계속 남는다.

`ledger_proposal.json`은 MIP-01의 수정 주장과 독립 재확인 대기만 제안한다. 원장 적용은 Claude 몫이며, 이 후보를 `closed` 또는 `verified`로 기록하지 않는다. 재확인 발송은 1저자다.
