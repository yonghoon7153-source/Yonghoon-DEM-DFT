# 믹서 N0 회전 한 팔 · 개발 자료

| 트랙 | 계산 | 상태 | 숫자 | 다음 |
|---|---|---|---|---|
| 믹서 | ibb PRECAL_N0 | 1저자 GO 수령 · 현장 실행 대기 | 이번 결과 0건 | WSL에서 N0 블록 1회 |

11-18 1저자가 E0 366423을 개발 자격으로 수용하고 다음 회전 한 팔을 승인했다. E0의 종료 직후 런타임 신원은 미확인(MXE0-02)으로 기록한다. N0의 결과는 개발 자료다.

- E0 반환과 회전 자료량 산정은 `docs/data/mixer_e0_pilot_20261116_return/receipt.json`과 `docs/data/mixer_e0_pilot_20261116_return/storage_review.md` §2에 있다. A/B V2의 B 283파일과 A/B 영수증을 확인한 뒤 N0의 덱·메타·STL 3개를 복사한다. 기존 제출기와 작업 시작기는 원래 바이트로 실행한다.
- 승인 범위는 ibb CPU 한 노드, MPI 20, 동시 한 팔, CPU 사용자 합 60 이하다. E0의 3시간 53분 26초를 7,716,595 / 1,121,213배 하면 약 26.8시간이다. 회전 접촉과 출력 빈도가 달라 이는 시간 근사치다. 블록의 Slurm 상한은 48시간이다. 제출 전에 QoS·사용자·파티션의 한도와 MPI·바이너리·링크 라이브러리·패키지, 디스크·inode를 확인한다. 디스크 하한은 E0의 기존 보수적인 32,193,231,348 B다.
- 덱 SHA256은 `adbbc8fa8f46730779fbf4f028f95a7aaf90c27ef2697c0dbe21a9ae1b5c6de3`. 32,976 step마다 1장, 총 234장, 실수 17자리를 유지한다. 컨트롤러는 종료 후 예상 프레임 이름 전체와 원 작업의 Slurm 상태·종료 코드, 러너 종료 기록을 확인한다. 반환의 프레임 수와 이름만으로 물리 판정을 하지 않는다.
- 감시는 원격 분리 프로세스에서 진행한다. SSH가 끊기면 회수 전용 블록으로 같은 작업을 조회한다. 제출 여부가 불분명하면 수동 확인하고 자동 재시도하지 않는다. Slurm에서 잡이 지워지면 정확한 원 잡의 회계 기록으로 종료를 확인한다. 완결·실패 자료는 별도 반환 폴더에 저장한다. 보고 파일에는 종료 시각과 수집 시각을 따로 둔다.
- `scripts/mixer_rotation_n0_ibb.py`는 회전용 승인·감시·회수 진입점이다. `scripts/test_mixer_rotation_n0_ibb.py`의 로컬 검사는 덱, 시간 상한, 종료 판독, 프레임, 단일 승인 및 반환 해시를 다룬다. 원격 제출 및 실제 계산은 1저자가 수행한다.
