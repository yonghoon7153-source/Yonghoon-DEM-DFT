- 그 밖의 기준 앞 기록 — 완료된 invalid (입력 불일치 · 결정적 실패 · 일시 오류) · MD 출력이 바뀐 뒤의 incomplete — 은 뒤 기록과 같은 대체 규칙을 받는다. 입력 불일치는 앞뒤와 무관하게 보류 근거로 남는다.

**DR P1-2 — 경로 상태 (부재 / 정상 파일 / 링크 / 그 밖).**
- `path_state` 가 판정 지문의 묶인 파일 칸 (`files_sha256`) 을 적는다: 없음 → None · 정상 파일 (링크 아님) → sha256 · 파일을 가리키는 링크 → `link:` + 내용 sha256 (정상 파일과 다르다) ·
  그 밖 → `nonfile:dir` · `nonfile:symlink` (깨진 링크 · 디렉터리를 가리키는 링크) · `nonfile:other` (특수 파일). `path_kind` 로 먼저 가르고 정상 파일 · 링크만 연다 (FIFO 에서 안 멈춘다).
- 파생 파일 생성 예외 (`same_judge_inputs`) 는 **None → 64 자리 16진수** 에만 걸린다. 그 자리에 디렉터리 · 링크 · 특수 파일이 있었다가 치우고 다시 만든 것은 입력 상태 복구라 다르다 (사람이 본다).
- seed_gate 도 경로 상태로 가른다: 없음 → 쓴다 (남은 임시 경로는 — 링크 포함 — 지우고 `O_EXCL | O_NOFOLLOW` 로 새로 만든다) · 정상 파일 → 대조 · 그 밖 (깨진 링크 · 파일 링크 · 디렉터리 · FIFO) → 읽지도 덮지도 않고 멈춘다.
  판정은 그것을 **입력 불일치** 로 적는다 (판정 도중 오류가 아니다 — 그래서 자동 대체 대상이 아예 아니다). 경로 상태 (생성 예외 안 걸림) 와 함께 이중 방어다.
  plan.json 을 OSError 로 못 읽으면 판정이 예외로 죽지 않고 invalid (경로가 정상 파일이 아니면 입력 불일치 · 아니면 판정 도중 오류).
- 지문 값의 꼴 검사 (`path_state_problem` — None · 64 hex · `link:` + 64 hex · `nonfile:*` 만) 를 판정 기록 꼴 검사 · 완료 필드 검사가 같이 쓴다.
- 시험: DR 재현 (raw 자리 디렉터리 → invalid · 입력 불일치 → 디렉터리를 옮기고 확인 → 정상 raw 가 생겨도 보류 · 발사 0 · 요약 invalid) · 대조 (진짜 부재 + 일회성 I/O 오류 → 회복) ·
  경로 상태 진리표 (실제 파일 시스템 — 없음 · 파일 · 파일 링크 · 디렉터리 · 깨진 링크 · 디렉터리 링크 · FIFO) · 진짜 판정 (plan 디렉터리 · 깨진 링크 raw · FIFO raw · 임시 경로 링크).

## 3. 이것을 특히 봐 달라

1. **'실제 진행 중' 의 경계** — ③ 의 두 갈래 (MD 가 돌던 중 · 끝났으면 MD 출력이 지금과 같음) 가 DR 조건 ① 의 '실제 진행 중 incomplete' 와 맞는가. 내 첫 고침은 상태만 봐서 넓었다 — 아직 넓거나, 거꾸로 정상 복구를 막는 경우가 남았는가.
2. **경로 상태의 가름** — 파일을 가리키는 링크를 정상 파일과 다른 상태로 두고 (seed_gate 는 링크 raw 를 입력 상태로 멈춤) · 깨진 링크 · 디렉터리 · 특수 파일을 따로 적는다. 더 갈라야 할 상태가 있는가.
3. **이중 방어** — 비정상 raw 경로는 ⓐ 판정 성격이 입력 불일치라 자동 대체 대상이 아니고 ⓑ 지문이 `nonfile:*` 라 생성 예외도 안 걸린다. 둘 중 하나가 다른 하나를 가리는 경우가 있는가.
4. **못 하는 것** (카드 v12 `⛔_못_하는_것`) — 이 중 첫 담금질 전에 막아야 할 것이 있는가.
   - 진행 중 (MD 도중) 들여다본 판정 뒤에 그 판정이 **이미 본 줄** 을 고친 것은 못 가른다 (통째 해시로는 자람과 고침을 못 가른다 — 앞부분 해시를 적어야 한다). 고친 파일은 그 뒤 판정 전부에 그대로 실린다 — 들여다봄이 없었어도 못 잡는 변경 (첫 판정 기록 전의 변경) 과 같은 급이다.
   - 진행 중 (MD 도중) 들여다본 판정이 판정 도중 예외로 invalid 가 되면 면제가 아니다 (면제는 incomplete 만 — DR 조건 ① 의 문구대로) — 그 뒤 MD 가 이어져 입력이 달라지므로 그 뒤 일시 오류 회복은 보류된다 (깨기 DS2 를 잡는 진리표가 이 동작을 박는다).
   - gate_check 의 일정 끝 허용 (t_max ≥ 전체 − 저장 간격) 때문에 MD 의 마지막 저장 간격 (li2s-2 는 MD 벽시계의 약 1/129) 에 들여다본 판정 · 그 간격에 떨어진 상한 정지는 '일정 끝 · 프레임 하나 모자람' 으로 invalid 가 된다 (incomplete 가 아니다). 그 뒤 일시 오류 회복 · 재시도는 보류된다 (원래 있던 동작 · 판정 문턱을 안 건드리려고 고치지 않았다 · DS 전 3 차 P3).
   - FIFO 가 plan.json · 보존 폴더의 실행 전 기록 · STOP 자리에 있으면 판정 · 시작 점검이 멈춘다 (Windows 에는 FIFO 가 없다).
   - final.xyz · result.json 을 쓰는 도중 들여다본 판정 (오류) 뒤의 회복은 보류 · final.xyz 자리의 디렉터리를 'final.xyz 없음' 으로 말함 (incomplete · 보류) · rc 0 런의 끝 판정이 incomplete 면 묶음이 멈추지 않음 (요약 pending · 잘못된 통과 없음).
   - 옛 꼴 판정 기록 (`md_done` · `md_complete_seen` 칸 없음) 은 '진행 중' 지름길이 없다 — MD 출력 동일 조건만 받고 아니면 보류 (첫 담금질 전이라 생산 기록에는 없다).
5. **새로 생긴 조용히 틀린 경로** — DR 때 내 고침의 퇴행 꼴은 '한 경로의 보류를 풀려고 넓힌 규칙이 다른 경로의 증거를 지운다' 였고, 이번 1 차 P2 도 같은 꼴이었다 (진행 중 복구를 살리려는 면제가 완료 흔적을 지움). 증거 (입력 불일치 · 완료 흔적 · MD 출력 변경 · 비정상 경로) 를 지우는 경로가 남았는가.
