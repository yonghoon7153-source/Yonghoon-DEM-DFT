# 믹서 점착 비 0.20·0.50 개발 비교

1저자 11-24 승인. 두 AM상의 γ_AM/γ_SE를 함께 0.20 또는 0.50으로 바꾼다. 기준은 B2-U와 B2-C에 쓴 시드 32452843, 초기 삽입 배치와 순서, B2의 세 메시, 벽 입력 γ_W/γ_SE=0.00256, Fr 0.0827, CGF 151.4, 회전 덱이다. 두 케이스의 자료 경로는 분리한다. 벽 재료 입력을 고정해도 기하평균 규칙에 따라 AM–벽의 쌍 점착은 함께 변한다.

## 실행 및 회수

같은 GO로 L020과 L050을 각각 NP20, 단일 노드, 최대 48시간으로 한 번씩 제출한다. STATUS는 조회, RETURN은 회수다. 7:3 UB 등 사용자 큐의 실행·대기 코어를 모두 더한다. 첫 제출 직전에 두 팔 40코어를 합쳐 60 이하인지 보고, 두 번째 직전에도 다시 본다. 첫 잡이 새 큐 조회에 아직 등장하지 않아도 20코어를 반영한다. 새 합이 60을 넘거나 큐 행을 해석할 수 없으면 그 시점에서 제출을 중단한다. 일부만 제출됐으면 앞 잡의 감시와 회수는 유지한다. 응답이 끊기거나 불명확하면 기존 요청을 STATUS로 확인한다.

두 팔에 대한 런타임 신원을 먼저 확인한다. 각 잡 접수 뒤 독립 감시를 분리 실행해 종료 직후 W9를 확인하고, 보고·전체 TAR의 SHA256SUMS와 팔별 JSON을 만든다. 정상 회수는 Slurm COMPLETED 0:0, 같은 잡의 실행기 rc 0, 정확한 234장, LIVE_TERMINAL_MATCH가 필요하다. 48시간 TIMEOUT은 기술 결측이고, 늦은 수집만으로는 실시간 W9를 채우지 않는다. 기술 결측도 원 상태·해시와 함께 보존하며 이어 돌리기는 별도 GO다.

## 판독

docs/reviews/mixer_b2_prereg_20261124/ladder.md의 두 주지표는 SE 군집 몫과 전체 SE 중 한 개 이상의 AM에 순간 접촉한 몫이다. 134–233번 100개 원프레임을 같은 회전 위상으로 짝짓는다. 프레임명·step·ID와 원자료 신원을 확인한 뒤 0.50−0.20의 차이와 부호를 한 시드 개발 비교로 기록한다. 34번은 별도 기준 프레임이다. 인접 중간 수준 0.31은 이번 표에서 미측정이다. 판독기 결속은 원래 B2 두 끝의 덱을 재현하고 새 팔의 덱과 메타데이터를 대조한 뒤 기존 관측기의 기하·시드·프레임 산술을 사용한다. 프레임 산포는 시드 반복으로 세지 않는다.

## 재현

build.py는 앞선 B2-C 배포 TAR의 전체 지문을 확인하고, 원 생성기의 기하평균·강성 보정으로 새 점착 행렬 두 개를 만든다. B2-U와 B2-C의 실행 덱에서 점착 행 외의 명령이 모두 같은지, 양 끝 행렬을 인쇄 정밀도까지 재현하는지, 각 쌍의 힘 비가 기하평균인지 확인한다. 기존 B2가 사용한 job_start와 런타임 명세를 그대로 담는다. 접속 정보는 배포용 TXT에만 넣는다.

test_ladder.py는 범위·중복·모호한 제출·부분 제출·자원 경계와 판독 조건을 검사한다. check_packet.py는 실제 패키지를 읽고 모의 스케줄러와 더미 MPI를 사용해 배포된 job_start, 정상 반환 및 시간 초과 반환을 검사한다. observer_binding.py는 기존 관측기 꾸러미를 검증하고 각 새 덱이 같은 시드의 같은 원프레임 100장을 선택하는지 확인한다.
