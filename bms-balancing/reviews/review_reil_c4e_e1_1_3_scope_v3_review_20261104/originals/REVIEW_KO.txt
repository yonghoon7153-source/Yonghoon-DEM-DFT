2. 기존 지적의 종결

N2_F1: DOCUMENT_CORRECTION_CLOSED.
66–68행 및 113–116행은 실제 v6 meta 필드로 정정됐다. 저장된 launcher 624–632행은 group.status == empty, deadline_hit == false, 조건부 timed_out/exited_after_kill 및 errors를 본다. 803–806행은 정리 결과를 child 기록에 넣고, 899–906행은 postcheck/stage/errors 및 precheck_ok를 연결한다. 오류가 없다는 것은 빈 오류 목록의 의미로 읽으며, 필요한 키 자체의 누락을 정상으로 간주하지 않는다. 정확 필드형·누락·실패 조건은 예정된 판정기 초안에서 고정한다.

N2_F2: DOCUMENT_CORRECTION_CLOSED.

N2_F3: DOCUMENT_CORRECTION_CLOSED.
71–74행은 run 외의 outer stdout/stderr/meta/rc까지 대상으로 삼는다. R2와 R1 이후 잔류·불명 모두 원본 보존, 읽은 시점의 고정 관측 사본, INCOMPLETE 및 비원자성 원칙에 묶었다. 작성기 117–118행, 공개 124행, 실패 기록 136–137행도 연결된다. 정확 가변 파일 목록과 사본·공개 조건은 후속 요청서에서 고정할 기존 요구다.

P2_01: CLOSED.
88–90행은 PID 기록, sleep rc=0, 완료 쓰기/게시의 성공을 연결한다. 대기 실패가 완료 표지 생성으로 진행하던 경로는 제거됐다. 92–100행은 별도 호출에서 반환 뒤 생존을 관측하고 완료 시각·로그·종료 상태를 함께 본다.
t_ret는 호출 안에서 찍은 반환 전 시각이다. 반환 이후 관측이라는 근거에는 실제로 앞 호출의 반환을 받은 다음 관측 1을 별도 호출하는 순서가 함께 필요하다. 문서에 그 순서가 적혀 있다. 이 수용을 실제 대상 셸·프로세스 관측이나 긴 수명 보장으로 확대하지 않는다.

3. P2_02 — 관측 명령의 경로 이동 실패 뒤 쓰기

위치: v3 93행과 95행.
우선순위: P2. P2 즉시 탐침에는 정정 필요. P1 문서 초안 작성은 차단하지 않음.

현재 구조:
  cd 지정경로 && until ...; do ...; done; 후속_기록

cd가 실패하면 && 오른쪽의 until만 생략된다. 세미콜론 뒤의 obs1 기록 또는 t_obs2 기록은 호출자의 원래 작업 폴더에서 계속한다. 그곳에 같은 이름의 파일이 있으면 덮어쓸 수 있으며, 마지막 기록이 성공하면 앞의 cd 실패가 호출 rc에서 가려질 수 있다. 지정 SP 한정과 실패 중지 조건에 어긋나는 정적 분기다. 실제로 실행해 재현하지 않았다.

요구:
- 각 관측 호출에서 cd 실패 즉시 비영 반환으로 종료한다. 예: cd "<정확한 SP 경로>/detach_probe_20261104" || exit 21
- 또는 루프와 후속 기록 전체를 cd 성공 조건 안에 묶는다. 전체 묶음의 출력 redirection을 cd 앞에서 수행하지 않도록 한다.
- cd 실패 원문·rc는 도구 기록에 보존하고, 해당 관측을 정상으로 기록하거나 후속 관측으로 진행하지 않는다.
- 수정할 대상은 관측 1과 관측 2 모두다. 기존 launcher나 받은 프로그램 수정·새 실행은 필요하지 않다.

근거: GNU Bash Reference Manual, Lists of Commands:
https://www.gnu.org/s/bash/manual/html_node/Lists.html
공식 문서 검색 결과에 제공된 본문으로 순차 목록(;)과 성공 조건(&&) 의미를 대조했다. 직접 페이지 열기는 시간 초과였으며, 대상 환경의 /bin/sh 종류·실효 동작을 확인한 것은 아니다.

4. 다음 단계와 수용 한계

권장 P1 경로에서는 P2_02를 승인 요청서에 함께 고쳐 넣고 다음 사전 검토를 진행하면 된다. v4 범위안만을 별도로 만들거나 탐침·재시험을 선행해야 한다는 요구는 없다.
사용자가 실제로 선택할 범위/launcher·잔류 방식/탐침/판정·기록/공개/절차 Git은 아직 이 검토에서 대신 선택하지 않았다. 과거 다른 과제의 선택이나 첨부 문서의 권고안을 실제 채택으로 바꾸지 않는다.
E113_N2 전체의 정확 wrapper 명령·증거 형식·정리 권한, 판정 조건, 미완 기록 예산, F3 사본 목록은 후속 승인 요청서에서 구체화해야 한다. 문구 정정 종결은 실행 준비 완료 판정이 아니다.
P1 탐침을 E 생성 전 수행한다는 134–137행은 범위 설명으로 수용한다. 기존 경로 발견 시 중지·재시도 0은 유지되며, 실패 후 경로를 삭제하거나 바꾸어 자동 재시도할 권한을 추가하지 않는다.
E1-0b a2 한정 기능 수용·A2_PROC_01은 유지한다. 실제 identity/fetch/data import/run, C4-A/B 또는 COMSOL 성공·승인으로 확대하지 않는다. COMSOL 수신자 ACK 검토와 이 REIL 범위 검토는 별개다.

수행: 입력·기존 검토·소스 텍스트 읽기, 바이트/해시·고정 커밋 차이·명령 제어 흐름 대조, 검토 산출물과 새 검토 ZIP 작성.
받은 프로그램/import/시험/탐침·신호 발송·실제 identity/fetch/run·COMSOL 실행 0, 원본/후보 수정 0, Git 변경·외부 발송 0.
