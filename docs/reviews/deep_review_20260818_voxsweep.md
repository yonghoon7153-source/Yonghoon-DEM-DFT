# 심층 리뷰 ① — 구-스탬프 **격자 스윕** 실행 전 검토 (2026-08-18)

사용자 지시: "1번, 2번 걸리기 전에 코드 리뷰 다시 받아보고 걸자."
대상 = **다음 GPU 런(항목 ①)**: 구 스탬프 σ_e 비(1.1232 @ vox 0.15)가 수렴했는지 확인하는
격자 스윕.  적대 리뷰로 돌렸고, **결론은 "계획대로는 못 돈다"** 였다.

읽은 것: `sdcp_gain_vox015_8arm.sh` · `sdcp_gain_verdict.py` · `step3_sigma.py` ·
`sr01_stamp_compare.py` · `mpm_webapp_payload.py` · `docs/reviews/sdcp_gain_prereg_v2_20260816.md`.

---

## 결론 (먼저)

`{0.25, 0.2, 0.15}` 스윕은 **원리적으로 불가능**하고, 그대로 실행하면 **조용히 반쪽만 돈다** —
SBE 8팔은 정상 완주(GPU 수 시간)하고 DBE 8팔은 게이트에서 죽는데 **exit 0 으로 끝나 캐시까지 된다**.
그리고 지금 설계로는 스윕이 "SDCP 이득의 수렴" 을 재지 않는다 — **σ_VGCF 와 탄소 상의 기하가
vox 와 함께 같이 움직여** CL-19(게이트 ⑤ 대각선 비교)의 결함이 그대로 재발한다.

## BLOCKER

### B1 — `d/vox ≥ 2` 게이트가 vox ≥ 0.2 를 전부 막는다.  스윕은 **고운 쪽으로만** 가능하다

`step3_sigma.py:286`  `if len(_p5) and _d / vox < 2.0: raise …`, d = 0.30 µm.

| vox | 0.4 | 0.3 | 0.25 | 0.2 | **0.15** | 0.125 | 0.1 | 0.075 |
|---|---|---|---|---|---|---|---|---|
| d/vox | 0.75 | 1.00 | 1.20 | 1.50 | **2.00** | 2.40 | 3.00 | 4.00 |
| 구 스탬프 | ✗ | ✗ | ✗ | ✗ | ✓ | ✓ | ✓ | ✓ |

- vox 0.15 는 `0.30/0.15 == 2.0` 이 IEEE754 로 **정확히** 성립해 여유 0 으로 통과한다.
  SDCP 직경 앵커가 나중에 0.29 로 정밀화되면 **vox 0.15 자체가 거부**된다 — 게이트와 앵커가
  한 수치에 물려 있다.
- 게이트를 1.5 로 완화하면 vox 0.2 가 늘지만, 게이트 자신의 오류문이 "1.5 에서 소실 1.24 %,
  전소실 절벽 √3≈1.732" 라고 적고 있어 **가장 나쁜 점 하나를 사는 것**이다.  게다가 prereg
  개정 사안이지 실행자 재량이 아니다.
- **가능한 최대 스윕 = {0.15, 0.125, 0.10}** (정밀화비 1.2, 1.25 — 거의 균일해 겉보기 차수
  추정에 적합).  0.075 는 메모리로 죽는다(아래).

### B2 — 게이트의 `ValueError` 가 payload 의 blanket `except` 에 **삼켜진다** (fail-open + 캐시 오염)

`mpm_webapp_payload.py:861 try:` … **`:1645 except Exception as _e:`** → `step3['status']='failed'`
로 적고 **계속 진행**, payload 를 **정상적으로 쓰고** `main()` 이 None 반환 → **exit 0**.

연쇄:
1. `sdcp_gain_vox015_8arm.sh` 의 `bash "$TAG.sh"` 이 성공으로 판정 → `run_arm` return 0.
2. 루프의 fail-fast 가 **발화하지 않는다** → 8팔이 끝까지 돈다.
3. `[ -s "$OUT" ] && SKIP` — 그 **쓰레기 JSON 이 영구 캐시**된다.
4. SBE 는 `len(_p5)==0` 이라 게이트가 아예 안 열려 **정상 완주** → 8팔 × 수 시간 GPU 를
   전액 낭비하고 끝에 판정기가 HOLD 를 낸다.

대조: `--fibre` 실패 경로는 `SystemExit`(BaseException) 로 던져 이 except 를 **통과**한다
(`:852, :883`).  구 스탬프 게이트만 `ValueError` 라 잡힌다 — **비대칭이 곧 결함이다.**

→ **수정 완료** (`fa1145d1`): `SystemExit` 승격 + 회귀 `sdcp-gate-fail-closed`.
   러너 재개 판정을 `[ -s ]` → `sr01_stamp_compare --check-arm` 으로 교체 (그 검사기는 이미
   있었고 이 러너만 안 썼다 — CLAUDE.md 작업규율 ① "이 리포에 이미 있나" 사례).

## HIGH

### H1 — σ_VGCF 가 vox 의 함수인데 σ_SDCP 는 고정.  격자 스윕이 **재료계수 스윕과 섞인다**

`diameter_preserving_sigma(100.0, ·, D_REF=0.15, VOX)` = `σ_eff = 100·πd²/(4·vox²)`.
**D_REF=0.15 자체는 옳다** (VGCF 의 물리 공칭 Ø, 복셀이 아니다).  ⚠ vox 0.15 에서 D_REF==VOX 라
계수가 π/4 로 떨어지는 **우연** 때문에 이 구분이 안 보인다 — 나중에 누가 "VOX 로 고쳐야지" 하고
만지면 전부 무너진다.

| vox | 0.15 | 0.125 | 0.10 | 0.075 |
|---|---|---|---|---|
| σ_VGCF | **78.540** | 113.097 | 176.715 | 314.159 |
| σ_VGCF / σ_SDCP(250 고정) | **0.314** | 0.452 | 0.707 | 1.257 |

세 점 사이에서 **탄소 백본 대비 SDCP 의 상대 전도도가 2.25배 바뀐다**.  우리가 재는 양
R = σ_e^DBE/σ_e^SBE 는 정확히 "이 백본 위에 SDCP 를 얹으면 얼마나 더 흐르나" 이므로 **정의상
σ_VGCF 의 함수**다.  근거: CL-11 이 σ_VGCF ÷9.054 → σ_e ÷6.617 (지수 0.858) 로 실측했고,
CL-15 가 SDCP 소산분담 9.77 % 를 실측했다.

⇒ **이대로면 "vox 를 조였더니 R 이 움직였다" 를 격자 수렴으로 읽을 수 없다.**  CL-19 가
`sr01_gate5_2x2.sh` 에서 스탬프와 σ 를 동시에 바꿔 retired 된 것과 **같은 구조**다.

**할 것 (권장 순)**
- (B) **vox 0.15 고정 · σ_VGCF 만 78.54 → 113.10** 인 SBE/DBE 1쌍(GPU ~1–2 h)으로
  `dR/dlnσ_VGCF` 를 직접 측정 → 스윕을 사후 보정.  **전체 스윕을 이 2런으로 디리스크한다.**
- (A) 또는 σ_VGCF 를 세 격자에 78.5398 로 **고정**해 순수 기하 수렴을 재고, 직경-보존 규약은
  별도 축으로 보고.

### H2 — 탄소 상의 **기하**는 격자 불변이 아니다 (1-셀 관)

VGCF 는 선분 래스터라 언제나 **1 셀 굵기 관**이다 → 셀 수 ∝ 1/vox, 표현 부피 ∝ vox².
SDCP 구 스탬프는 부피 보존(실측 0.986×).  vox 0.15 실측 원장에서 투영한 SDCP:VGCF 셀 비는
0.25 → 0.36 → **0.56** (0.15 → 0.125 → 0.10) 로 2.2배 이동한다.

`diameter_preserving_sigma` 의 docstring 자신이 적어 놨다 — "**단면** 보정만이다.  계단식 여분
길이 k 와 격자가 만드는 **가짜 상호연결**은 미보정이고 **경쟁**하므로 부호를 정할 수 없다."
그리고 k 는 실측으로 격자 의존이다 (1.4855@0.4 · 1.4917@0.3 · 1.4461@0.25).

⇒ σ 를 고정해도 이 축은 남는다.  **정직한 라벨: 이 스윕은 "격자 수렴" 이 아니라 "격자 규약
민감도" 다.**

### H3 — plate band = `vox + 0.10` 은 **CLI 로 못 고정한다**

`step3_sigma.py:425` `band = plate_band_um if … else (vox + 0.10)`; payload 는 그 인자를
넘기지 않고 `--plate-band` CLI 는 **존재하지 않는다**.  band/vox = 1.67 / 1.80 / 2.00.
prereg 가 브리지에 대해 "격자마다 달라지면 CL-22 를 반복한다" 고 선언한 것과 **정확히 같은
성질의 두 번째 노브**가 노출조차 안 돼 있다.  두 침대는 서로 다른 MPM 압밀 결과라(porosity
7.86 vs 7.386 %) 상쇄가 보장되지 않는다.
부수: docstring 이 "capped 1.4·vox" 라고 적었는데 **코드에 캡이 없다** (vox 0.15 에서
1.4·vox = 0.21 ≠ 0.25) — 문서가 틀렸다.

### H4 — OUTDIR / SKIP 이 vox·(구/점) 외에 아무 것도 구분하지 않는다

디렉터리 이름에 **없는 것**: `BRIDGE_UM`, σ_VGCF, `ARMS`, 코드 SHA.  ⇒ 같은 vox 를 다른

게이트는 팔들이 **전부 같이 낡았으면 통과**한다 (게다가 bridge 축은 애초에 죽어 있다 — H5).
→ **수정 완료**: OUTDIR 에 `_b048` 태그 (`sr01_grid_converge_e.sh:34` 가 이미 쓰던 규약).

### H5 — 판정기의 `bridge_um` 고정인자 게이트가 **죽어 있다** (no-op)

`sdcp_gain_verdict.py:50` 이 `man.get('bridge_um')` 을 읽는데 **매니페스트에 그 키가 없다**
(`_bru` 는 rasterize-only 원장에만 실림).  ⇒ 고정-인자 루프에서 항상 `None` → **절대 발화하지
않는다.**  prereg §5 가 명시적으로 못 박으라고 한 바로 그 인자의 검사가 **가짜 보증**이었다.
→ **수정 완료**: 매니페스트에 `bridge_um`·`sigma_vgcf_S_cm`·`sigma_sdcp_S_cm` 추가 ·

   selftest 픽스처가 실제 매니페스트 필드를 전부 싣도록 교체 (⑨⑩⑪).

### H6 — GPU 경로는 **AMG 를 쓸 수 없다**.  그리고 CG 반복수가 어디에도 기록되지 않는다

`step3_sigma.py:164-177` GPU 블록이 Jacobi 로 풀고 **return** 한다 → `AMG_SOLVE` 는 CPU 경로만.
킷은 `--step3-gpu` 를 항상 붙인다.  SR-03 노트가 스스로 "Jacobi 는 dof^0.36 으로 자란다 …

### H7 — 팔당 **무조건 4회 이상 풀솔브**가 돌고, 끌 CLI 가 없었다

`_res3`(전자) · `_res3w`(collector wetted) · `_res3b`(collector bare) · `_res3i`(이온) +

   **밖**이라 둘은 독립이고, 그리드는 여전히 저장된다.

## 메모리·타당성

vox 0.15 실측(`docs/data/prereg_v2/phase_ledger_grid.json`, SBE 54,662,440 셀 · 전도 26.5 M)에서
투영.  VRAM ≈ 140 B/dof (CSR 7 nnz + CG 벡터), 호스트 ≈ 415 B/dof (COO 조립이 rows/cols 를
**int64** 로 6·n_dof 개 쌓고 concatenate 에서 한 벌 더 복제한 뒤 tocsr).

| vox | 총 셀 | dof | VRAM | **호스트 RAM** | 판정 (3090 24 GB · 호스트 ~62 GB) |
|---|---|---|---|---|---|
| 0.15 | 54.7 M | 26.5 M | 3.7 GB | **12.4 GB** | 실측 완주 ✓ |
| 0.125 | 93.2 M | 44.5 M | 6.2 GB | **20.9 GB** | 여유 ✓ |
| 0.10 | 180.2 M | 85.0 M | 11.9 GB | **40.0 GB** | 빠듯 — `LEAN=1` 필수 |
| 0.075 | 423.6 M | 197.9 M | **27.7 GB ✗** | **93.1 GB ✗** | 양쪽 OOM |

호스트 계수는 vox 0.15 에서 12.4 GB 를 주는데 prereg §3 실측 "12.8 GB" 및
`sdcp_phase_ledger.sh` 의 "~13 GB" 와 일치 — **검산됨**.

⇒ **먼저 깨지는 것은 VRAM 이 아니라 호스트 RAM 이다.**  prereg §3 의 "87M 셀 ≈ 12.8 GB →
RTX 3090 24 GB 에 들어간다" 는 **CPU 조립 수치를 VRAM 예산으로 읽은 것**이고, 이 혼동은
vox 0.10 에서 정확히 반대로 배신한다 (VRAM 11.9 GB 로 넉넉해 보이는데 호스트가 40 GB).

   0.98–1.00 이면 **"기전 변수는 이미 수렴했고 남은 R 이동은 전부 H1/H2 교란" 이라는 판정이
   GPU 없이 선다** — 이 한 줄이 스윕을 아예 불필요하게 만들 수도 있다.
2. `/usr/bin/time -v` 로 1의 peak RSS → 호스트 한계 확정.
3. **vox 0.125, origin=0, SBE+DBE 2팔만** GPU 로 → 벽시계·VRAM·CG 반복수 실측 (1/8 비용).
4. **H1 의 σ_VGCF 감도 2런** — 이것 없이 나온 스윕 곡선은 해석 불가다.
