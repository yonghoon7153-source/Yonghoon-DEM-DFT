# 다음 작업 범위 초안 — S1-O 판정 코드의 한정 오프라인 정정

비활성 초안. 사용자 별도 승인 전에는 착수하지 않는다. 현재 검토 회신의 생성/수신은 구현·시험 승인이 아니다.

## 제안 작업

현재 ZIP과 CODE_MANIFEST 및 원본 실패 기록을 그대로 두고 새 정정본에서 다음만 다룬다.

1. consumer의 charge 원자료/시간 결속: native의 실제 저장 격자와 같은 정확 집합·시작·끝, global Li 항과 charge 재고 항의 동일 출처/시각을 검사한다. 정상 끝과 보호중단 실제 끝, 수치 비교 safe prefix를 구분한다.
2. charge의 누적 잔차와 별도로 구간 Δq_N/Δq_P 방향/deadband를 검사하고 최초 위반 구간을 기록한다. 기존 단위·deadband·잔차 허용치를 완화하지 않는다.
3. 부모의 coverage 배열을 신뢰된 기대 목록과 대조한다. 기대값을 결과 count에서 복사하지 않는다. 중복·비유한·잘못된 순서·동일 길이 다른 시각·교집합 모순을 거부한다.
4. P0의 tsteps 저장 설명을 맞춘다. 물리/초기조건/σ/OCP/해상도/cap/출력 API는 변경하지 않는다.
5. 영향받는 출력 schema·계약·검증안·CODE_MANIFEST만 함께 갱신한다. 소비자와 부모가 같은 새 구조를 보게 한다. 원본의 의미를 조용히 바꾸지 않는다.

## 제출 전에 고정할 검증안

- 정상 전체 charge와 끝/중간 누락·같은 길이 격자 변이.
- 양의 누적량 속 역방향 증분, 정확 deadband 경계, deadband 안의 수치 미세 변화.
- 실제 Python 출력→봉인 JSON→PowerShell 양성, 같은 길이 중복/다른 시각/비유한 음성.
- 보호중단 safe-prefix 기대값의 독립 유도와 목표 PROTECTIVE_STOP 분기 도달.
- PAIRED04 D/S/E_D/E_S 전부 및 Decimal→double 경계의 명시적 판정.
- 각 ID의 양성·음성·정확 이유·도달 단계, 기존 98 ID와의 대응, 새 실제 사례 수.

이번 제안은 정정·정적 확인·새 봉인·갱신 검증안 제출까지다. 기능 시험은 그 제출물을 검토한 뒤 별도 승인한다. 새 작업 폴더·횟수·정정 예산은 착수 승인문에서 확정한다. 이전 준비 3600초나 미실행 검증 1500초를 자동 재사용/확대하지 않는다.

## 포함하지 않는 것

받은 코드 시험/import·Java 컴파일/JVM·COMSOL·설치본 계수/초기화 probe·실제 콘솔/Job/프로세스 제어·정책 변경·approval/release/runtime/token·P/M/N 실행·기존 전체 suite 재시험·새 장시간 계산은 포함하지 않는다.

native/OS 어댑터의 OPEN을 축소하거나 true로 채우지 않는다. native_ready=false와 기존 INCOMPLETE/UNVERIFIED를 유지한다. 제출 후 멈춘다.
