# 60초 단발 실행 예산 제안 — 아직 미승인

기존 native 공유3,600초·부모 전체5,100초를 유지하는 안을 권고한다. 코드·부모의 시간 제어 본문 변경을 피하면서, 수용된30초의 compile+batch1,570.079초·전체1,653.199초보다 충분한 여유가 있는 제한 진단 상한이다. 미래60초 성공 또는 실제 소요시간 보장은 아니다. 한도를 넘으면 실패 보존·중지하며 자동 연장하지 않는다.

| 단계 | 제안 상한(초) |
|---|---:|
| 사전 확인·같은 Python의 새 두 직접입력 |180|
| compile+batch 공유 |3600|
| 기존 소유 Job 정리 합계 |120|
| 분석 |900|
| 로컬 증거 기록 |300|
| 부모 전체 |5100|

분리된 단계 합은5100이다. native 반환에는 정리 시간이 포함되지만 기존 entry의 공유 native 집계는 각 호출 elapsed에서 cleanup elapsed를 뺀다. 부모 전체 상한은 실시간 관측이며 단계별 여유를 재시도에 전용하지 않는다. -NoExit의 OS rc는 null, 자식 rc·PRE_WRITE·POST_WRITE·사용자 프롬프트 복귀를 구분한다.

근거 기록:30초 compile35.750초/batch1534.329초, Time solver 로그670초, 전체 부모1653.199초, 저장MPH1,584,874,018bytes, 시작RAM6,453,903,360bytes(약6.01GiB). 물리시간30→60만으로 모든 비용을2배하지 않는다. 초기 작은step·초기화 비용은 반복되고, 후반 적분·프로파일 출력·저장은 추가된다. 당시1,237상태에0.1초300개가 추가되는 단순 규모 모형은1,537상태, 출력량 약1.24배/MPH 약1.97GB이지만 실제 저장 상태 수·MPH/메모리 상한으로 쓰지 않는다. 비선형 solver 비용 변화도 미확인이다.

요청16코어·디스크 시작20GiB·RAM 시작값 관측을 유지한다. 실제 코어 이용률/효율과 peak working set은 미실측이다. 새RAM 문턱·8GiB 소유 상한·메모리 감시기를 추가하지 않았다. 이번 준비는 현재 자원이나 prefs를 새 native 시작 관측으로 측정하지 않았다. 실제 실행 승인 전 현재 파일/정책 식별·경로 충돌 조건을 고정하고 실행 시작 시 기존 코드의 자원 관측을 사용한다.

기존30초 CSV6개와 B0206개를 모두 읽고 비교하므로 분석 IO/메모리가 늘 수 있다. 분석900초 제안 내에서 실제 관측할 사항이며, 비교 생략 또는 자동 예산 확대는 없다. 기본/전용 prefs 보안 값 변경0, 권한 상승·다른 셸·경로 fallback0이다.
