# 믹서 M1 후속 범위 — 기존 수정 보존과 진단 계획

**문서 초안 / 신규 구현 0 / 신규 시험 작성·실행 0 / 실제 자료·현장 접근 0 / 전체 HOLD.** 새 코드 반례를 확보하지 않았으므로 기존 생성기·소비자·D3 정정을 다시 고치지 않는다. 이 문서는 원장 변경이나 한정 종결 판정의 재개방 요청이 아니다.

근거 고정 핀은 `c571a27119ace92ca34d3d6f2b61135219a3f1b4`다. 원본 경로·길이·SHA256·Git blob은 `scope_provenance.json`에만 기록하며 source 본문·원자료를 복사하지 않았다. 앞선 범위 진단의 원장 스냅샷 핀은 `f4647f2b7c218a6df7def3292c092273f9d4e35f`이고 MXD2-01–07·MIX-11의 원문 상태는 `open`이었다. 아래 숫자는 **작성 측 후속 분류**이며 원장 status를 대체하지 않는다.

상태: **0 = 기존 구현/문서 정정 존재**, **1 = 후속 정책·등록 범위가 남음**, **2 = 최초 원인 미확정**, **3 = 실제 자격·승인 미완료**. `0`은 새 독립 판정·운영 GO·원장 종결을 뜻하지 않는다.

## 4. MIX-11 관측 계획 — 미실행

권고안 전제(**Q-M1-4**): 실제 reader·실제 run/ref·engine·전체 selftest를 호출하지 않는다. 가상 reader, 고정 가상 clock, 메모리의 exclusive 생성 모형 또는 격리된 작은 합성 scratch만 사용한다. 이것은 앞으로 만들 시험의 계획이며 이번에는 시험 코드도 쓰지 않았다.

## 5. 진단 영수증 초안

`diagnostic_receipt_template.json`은 **서식이며 실제 영수증이 아니다**. 값이 없는 칸은 `null`, `NOT_RUN`, `UNKNOWN`으로 둔다. 예상 rc와 관측 rc, 계획된 source pin과 실제 호출한 source SHA를 분리한다. 실제 실행·등록·운영 봉인·GO 플래그는 모두 false다.

각 시도는 고유 attempt ID, source/wrapper/reader/harness hash, fake clock/reader/파일 생성 모형 식별자, scratch alias, 시작/끝/단조시계 경과, rc·예외·timeout/interrupt, full stdout/stderr의 길이·SHA·완전성·근거 별칭을 갖는다. 출력의 마지막 몇 줄만을 full output으로 부르지 않는다. 실패/부분 수집의 rc가 없으면 `null`이며 0으로 채우지 않는다. 해시와 alias만 리포 문서에 연결하고 원 출력·리포 밖 절대 경로·주소·포트는 넣지 않는다.

현재 wrapper에도 reader stdout/stderr·예외·source hash 보존이 있으므로 이 초안은 그 기능 부재를 주장하지 않는다. 향후 진단의 process/attempt 경계, 고유 scratch 및 현재 실패 영수증이 서로 결속되어야 한다는 계획이다. source SHA와 rc0만으로 실제 사용·실행 당시 출처·물리 자격·승인 진위를 인증하지 않는다.

## 7. 이번 확인의 한계

이 세 파일은 문서·서식·출처 메타 초안이다. 코드·시험·원장·공유 기록·운영 봉인 변경 0, 프로젝트 실행 0, 실제 자료/원 로그/host 읽기 0, 제출/연구 실행/결과 0이다. 고정 Git source/test 문장과 지정 수령 문서만 읽었다. 규약 파일의 넓은 앞부분 및 검색 줄에 무관한 역사 수치 문장이 포함된 일이 있었으나 해당 수치를 설계나 판정에 사용하지 않았고 실제 원자료를 읽지 않았다. “모든 수치 노출 0”으로 확대하지 않는다.

기존 독립 검토/시험 개수를 이번 수행 수로 합산하지 않는다. 이번 새 bug 반례가 없어 새 구현·시험은 0이다. 이번 산출물은 범위표·진단 영수증 서식·출처 메타 3파일과 인계 쪽지 1파일이다. B 반입·새 독립 판정은 아직 없다. 전체 HOLD를 유지한다.
