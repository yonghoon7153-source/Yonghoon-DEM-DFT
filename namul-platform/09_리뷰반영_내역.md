# 리뷰 반영 내역 (2026-10-30)

Codex 리뷰(`08_리뷰요청_codex.md` 기준, v3 상세본 25장 검토)와 발표자 요청을 v4 제출본에 어떻게 반영했는지 정리했다. 슬라이드 번호는 **v4 기준**이다. v3 상세본은 `상세본_v3/` 에 있다.

## Codex 리뷰: 코드 (프로토타입)

| 지적 | 반영 |
|---|---|
| AI 수량 응답이 이스케이프 없이 `innerHTML` 에 들어간다. | AI·파서 결과를 모두 `cleanItems()` 로 통과시킨다. 수량은 1~999 정수, 단가는 100~300,000 정수만 받는다. 품목명은 한글·영숫자만 남긴다. 화면에는 숫자나 이스케이프한 문자열만 넣는다. HTML이 섞인 응답을 넣어 실험한 결과 이미지 요소 삽입은 0개였다. |
| 확인 전부터 '재고 등록 완료'가 표시되고, 확인을 눌러도 재고가 바뀌지 않는다. | '재고 등록안 · 확인 필요'로 표시하고, 확인을 누르면 매장 재고(가격·단위·손질 가능 여부·입고 시각)를 실제로 갱신한다. 범위를 벗어나거나 도감에 없는 품목은 '확인 필요'로 빼고 올린다. |
| `3,500원 손질 불가` 를 500원·손질 가능으로 읽는다. | 쉼표 숫자와 '3천5백' 같은 표기를 처리하고, '손질 불가·안 돼·안 됨·못' 같은 부정 표현을 인식하게 했다. 지금은 3,500원 · 손질 불가로 읽는다. |
| 장바구니에 여러 품목을 담아도 결제는 한 품목만 계산한다. | 화면에 "시연은 한 번에 한 품목씩 주문해요"와 장바구니의 다른 품목 이름을 표시한다. |
| 아이 선호도·참여 수·예측 91%가 상수이고 예시 표시가 모바일에서 숨는다. | 앱 홈 상단에 '시연용 프로토타입 · 매장·가격·선호도는 예시 데이터' 줄을 추가하고, 수치 옆에 '예시'를 달았다. 91%는 삭제했다. |
| viewport meta 부재, 포커스 이동 없음, 이력 중복 갱신 | viewport meta를 추가했다. 화면을 바꾸면 제목으로 포커스를 옮긴다. 내부 이동 스택을 없애고 브라우저 이력 하나로 정리했다(pushState·history.back). |

점검: `capture_src/check2.js` 로 위 시나리오를 다시 돌린 결과 콘솔 오류 0, 390px 폭 가로 넘침 0이었다. 게시본도 같은 링크(Version 3)로 갱신했다.
