# 이번에 바뀐 것 — 쓰는 법

2026-08-26 까지 붙은 것들을 **화면에서 어떻게 쓰는지** 로 적었습니다. 왜 그렇게
만들었는지는 각 항목의 ADR 에, 무엇을 언제 고쳤는지는 `docs/log.md` 에 있습니다.
처음 쓰는 분은 [[getting-started]] 를 먼저 보세요.

---

## 0. 일단 띄우기

터미널(WSL 이면 Ubuntu 터미널)에서 저장소 폴더로 가서:

```bash
bml
```

이 한 줄이 **최신화 → 의존성 확인 → 빌드 → 실행** 을 순서대로 합니다. 끝나면
브라우저에서:

```
http://localhost:5003
```

| 하고 싶은 것 | 명령 |
|---|---|
| 그냥 띄우기 | `bml` |
| 고치면서 띄우기 (핫 리로드) | `bml dev` |
| 내리기 | `bml stop` |
| 환경이 이상할 때 | `bml doctor` |
| 커밋 전 검사 전부 | `bml check` |

`bml` 이 없다고 나오면 한 번만:

```bash
make install-bml
```

자세한 건 [[bml-command]], Windows/WSL 준비는 [[wsl-setup]] 입니다.

> **중요.** 이 워크벤치는 `claude/battery-charge-discharge-webapp-dq4ja3` 브랜치에
> 삽니다. 다른 브랜치로 옮기면 파일이 사라져서 `bml` 이 "No such file" 만
> 뱉습니다. 폴더 하나에서 브랜치를 오가지 마세요.

## 1. Knee — 이제 두 점이 나옵니다

**어디**: 대시보드, 셀 상세의 리포트 카드.

전에는 "knee at cycle 120" 하나였는데, 이제 **시작(onset)** 과 **지점(point)**
둘이 나옵니다:

```
knee onset at cycle 96, point at cycle 131
```

- **onset** = 완만한 fade 가 꺾이기 *시작* 하는 곳 — 이중 Bacon-Watts 의 첫 전환
- **point** = knee 그 자체 — **별도의 단일** Bacon-Watts 적합의 전환

두 값이 서로 다른 적합에서 나오는 것이 Fermín-Cueto 2020 의 정의이고,
2026-08-26 에 그쪽으로 맞췄습니다 (그 전에는 이중 적합의 두 번째 전환을
point 로 썼는데, 그건 전환이 *끝나는* 자리라 늘 5~8 사이클 늦게 나옵니다 —
같은 이름으로 남들보다 늦은 숫자를 내면 비교하는 쪽이 그 차이를 셀 차이로
읽습니다). 두 번째 전환도 사라지지 않고 `second_transition` 으로 남습니다.

자세한 건 ADR 0021 입니다. 대시보드의
knee 칸에는 `96→131` 로 적히고, 옆의 작은 그래프에도 **두 자리가 다 그어집니다**
— 시작은 옅은 점선, 지점은 진한 점선입니다.

**쓸 때 볼 것**

- 한 점만 나오면 (onset 이 없으면) DBW 가 두 번째 전이를 세울 근거를 못 찾은
  겁니다. 지어내지 않고 하나만 말합니다.
- `knee_status` 가 `insufficient` 면 "아직 안 꺾였다" 가 아니라 **"판정할 사이클이
  모자란다"** 입니다. 둘은 다른 말이고 화면도 다르게 씁니다.
- 기준은 여전히 **3번 사이클** 입니다 (formation 없는 스케줄이면 1번). knee 탐색도
  거기서 시작합니다 — formation 손실을 열화로 세지 않기 위해서입니다.

## 2. EIS — 셀 종류를 6가지에서 고릅니다

**어디**: EIS · DRT → 스펙트럼 → 업로드 / 스펙트럼 상세.

`.mpr` 을 올릴 때 두 가지를 고릅니다:

| 드롭박스 | 값 |
|---|---|
| 전해질 | 액체 / 전고체 |
| 셀 구성 | 풀셀 / 하프셀 / 대칭셀 |

이 **조합** 이 기본 회로를 정합니다. 같은 액체 전해질이라도 리튬 대극을 쓴
하프셀은 대극 계면이 아크를 하나 더 얹고, 대칭셀은 같은 전극이 둘이라 아크가
두 배로 나옵니다(한쪽 값은 절반입니다). 아크의 **이름** 도 조합을 따릅니다 —
전고체 대칭셀의 두 아크는 벌크·입계지만, 전고체 풀셀의 두 아크는 그게 아닙니다.

파일 이름이 힌트를 주면 (`..._70um_sym_01`) 드롭박스 옆에 보여 주지만, 고르는
건 사람입니다. 이름은 기록이 아니니까요.

> 전고체 피팅 회로는 아직 랩의 기본값 그대로입니다. 쓰시는 회로 코드를 주시면
> 프리셋을 교체합니다.

### 목적 칸

업로드할 때, 또는 나중에 스펙트럼 상세에서 **목적** 을 적을 수 있습니다 —
`200 사이클`, `SOC별`, `온도별` 처럼 자유 입력입니다. 목록에서 이걸로 구분이
됩니다.

SOC 스캔처럼 **파일이 스스로 말하는 경우에는 자동으로 채웁니다** (`SOC별`).
직접 적으면 적은 쪽이 이깁니다.

## 3. SOC 스캔 — 새 섹션입니다 ★

**어디**: EIS · DRT → **SOC 스캔**

`.mpr` 하나에 임피던스 스윕이 16~21개 들어 있는 파일 — SOC 5 % 마다 찍은
스캔 — 을 다루는 화면입니다. 실측 하프셀 파일이 정확히 이 모양이었습니다
(행의 98 % 는 EIS 가 아니라 GCPL 사이클링이고, EIS 는 그 사이에 끼어 있습니다).

### 쓰는 순서

1. **올리기**: EIS · DRT → 스펙트럼 → 파일 올리기. 평소와 똑같습니다.
   스윕이 여럿이면 **스윕마다 한 줄** 이 생기고, 각 줄이 그때의 전위·용량을
   들고 있습니다.
2. **피팅**: 스펙트럼 목록에서 그 스윕들을 체크하고 → 위의 **「고른 N개 맞추기」**.
   한 회로로 스무 개를 한꺼번에 맞춥니다.
3. **보기**: **SOC 스캔** 링크로 갑니다. 파일 하나가 한 줄입니다.
   `4 / 21` 처럼 몇 개를 맞췄는지가 적혀 있습니다.
4. **열기**: 줄을 누르면 **파라미터 vs SOC** 그래프가 나옵니다. 오른쪽 위의
   **파라미터** 드롭박스로 R0, R1, CPE1_Q … 를 갈아 가며 봅니다. 아래 표에는
   스윕별 값이 다 있고, 그래프 밑에 **「Origin 으로」** 복사 버튼이 있습니다.

### 이 화면이 하는 약속

- **x축은 용량(mAh)** 입니다. 절반 이상이 비어 있으면 전위(V) 로 바뀝니다.
  둘 다 파일이 스윕마다 들려 보낸 실측이라 추정이 섞이지 않습니다.
- **오차막대가 값을 삼킨 점은 빼고 그립니다.** 그래서 선이 중간에 끊어지는데,
  그게 맞습니다. 몇 개가 빠졌는지는 그래프 아래에 적히고, 표에서는 그 칸이
  `0` 이 아니라 `—` 입니다. 클립보드에도 안 들어갑니다.
- **각 SOC 에서 쓰는 피팅은 "가장 최근" 이 아니라 "가장 잘 맞은 것"** 입니다
  (수렴한 것 중 χ² 최소). 몇 점을 회로 바꿔 다시 맞춰도 추세선이 안 튑니다.
- **스윕이 셋 이상인 파일만** 여기 나옵니다. 두 장짜리 전·후 비교는 스캔이
  아니라 EIS 목록에서 나란히 봅니다.

## 4. GITT

**어디**: **GITT** → pseudo-OCV · 확산계수

Smart Interface 가 남긴 `.wrd` 를 그대로 올리면 됩니다 — 텍스트로 내보낼
필요 없습니다. 펄스와 휴지를 갈라서 준평형 전압 곡선과 Weppner-Huggins
확산계수를 냅니다.

**확산계수가 안 나올 때**: 목록의 "확산계수" 칸이 `N개 부족` 이라고 말합니다.
몰부피·활물질 몰질량·전극 면적처럼 파일에 없는 값이 필요한 것들이고, 셀 상세에
넣으면 채워집니다. **없는 값을 추정해서 내지 않습니다.**

## 5. 화면이 빨라졌습니다 (할 일 없음)

긴 셀에서 화면이 느리다고 하셨던 것 — 고쳤습니다. 재 본 값입니다
(12 셀 × 400 사이클, 200 사이클 6.5 MB `.wrd` 하나):

| 화면 | 전 | 첫 요청 | 두 번째부터 |
|---|---|---|---|
| 대시보드 | 4.4 초 | 3.4 초 | **0.14 초** |
| 프로파일 (사이클 20개) | 0.71 초 | 0.045 초 | **0.029 초** |
| dQ/dV (사이클 10개) | 0.37 초 | 0.042 초 | **0.030 초** |
| 셀 리포트 | 0.056 초 | 0.046 초 | **0.011 초** |

**프로파일과 dQ/dV 는 첫 요청부터 15배** 빠릅니다 — 한 요청 안에서 같은 파일을
40번 풀던 것이 한 번이 됐습니다. 대시보드는 셀마다 knee 를 계산하는 값이라
서버를 새로 띄운 뒤 **첫 화면 한 번** 은 여전히 몇 초 걸리고, 그 다음부터
빠릅니다.

**할 일은 없습니다.** 캐시가 입력을 키로 쓰기 때문에 파일을 새로 올리거나
사이클이 늘면 알아서 다시 계산합니다. 비울 것도, 끌 것도 없습니다.

메모리가 걱정되면 (기본 256 MB):

```bash
WORKBENCH_COLUMN_CACHE_MB=64 bml      # 줄이기
WORKBENCH_COLUMN_CACHE_MB=0  bml      # 아예 끄기 (느려집니다)
```

## 6. 자주 막히는 곳

| 증상 | 볼 것 |
|---|---|
| `bml: command not found` | `make install-bml` 한 번 |
| `bad interpreter: No such file` | 줄바꿈이 CRLF 로 체크아웃된 것. `bml doctor` 가 고치는 명령까지 알려 줍니다 |
| 포트 5003 이 이미 잡혀 있다 | `bml stop`. 남의 프로세스면 일부러 안 죽입니다 — 실험이 돌고 있을 수 있어서 |
| SOC 스캔 그래프가 비어 있다 | 아직 피팅을 안 한 것. 목록의 `0 / 21` 이 그 뜻이고, 화면도 무엇을 하면 되는지 한 줄로 말합니다 |
| 추세선이 중간에 끊긴다 | 그 SOC 에서 그 파라미터가 결정되지 않은 것. 회로를 바꿔 다시 맞춰 보세요 |
| 화면이 여전히 느리다 | 서버 띄우고 **첫** 대시보드는 원래 몇 초입니다. 두 번째도 느리면 알려 주세요 |
| 밖에서 봐야 한다 | [[central-server]] — 터널은 공유 암호를 걸어야만 열립니다 |
