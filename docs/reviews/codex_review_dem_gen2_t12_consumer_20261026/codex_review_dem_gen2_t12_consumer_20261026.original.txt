## 5. 영수증과 기존 판정의 사용

1. **ULPRI 종결 수용.** `scoped-external-receipt.json`의 보고서/반입 증거 hash를 재계산했다. GO 범위는 표지 두 경계이며, 원본 제출 ZIP과 외부 검토 ZIP도 서로 구분돼 있다. 앞선 실제 208/208·43/43·4/4를 이번 새 실행으로 다시 세지 않았다.
2. **과거 문구 보존 수용.** 과거 T12 문서/빈 사실 양식의 HOLD/PENDING은 해당 시점 상태다. 새 종결 문서가 날짜·핀·범위를 가진 후속 상태를 제공하므로, 옛 문장을 고치지 않은 것을 거짓 HOLD로 취급하지 않는다. 후속 자동 소비자는 날짜/핀/범위를 읽어야 하고 문자열 `GO`만 검색해서는 안 된다.
3. **155 기록의 좁은 사용 수용.** `full_gate.log` SHA256은 `f27982bb9f2497c32dcea0a3e50130c6dea2dac16492d1fde3b32750bd8656c3`와 일치한다. 성공 표지 155·실패 0, 영수증 rc 0이며 대상은 `f1da507e…`다. 로그·영수증의 내부 연결을 감사한 것이고 해당 실행 환경이나 전체 155를 독립 재실행한 것은 아니다.
4. **직접 52와 공용 게이트 분리 수용.** `new_t12_suite_in_shared_gate=false`가 보존돼 있다. “155+52가 통합 CI에서 돌았다”는 식으로 바꾸면 안 된다.
5. **검토자 칸**은 현재 외부 회신의 출처·범위·핀으로 연결하면 된다. 본 검토는 미제공 지정 검토자 신원이나 canonical verifier 값을 만들어 주지 않는다. 실제 물리 GO 필드는 계속 별도다.

## 6. 다음 작업 순서와 최소 수용 조건

새 설계 선택을 추가하는 요구가 아니다. 요청서에 이미 남긴 사실들을 **어떤 코드 관문으로 증명할지**를 구체화한 것이다.

### A. P2 사실과 등록을 먼저 연결

실제 bed/arm·generation·params·활성 머리, h0의 기준/단위 환산/정수 step화, dt와 시간창, 중력 예외·resume 전이를 원문 기록과 연결한다. P1 필드 이름이 같다는 이유로 P2 등록을 채우지 않는다. 아직 없는 측정값·생산값은 결손 그대로 유지한다.

### B. 구현 전 양성·음성 시험

- 정상 P2 입력은 **실제 생산자 형식 → 소비자 → 최종 상태**까지 한 번 통과시킨다. helper에 직접 dict를 넣은 시험만으로 끝내지 않는다.
- P1 이름을 재사용한 P2, 잘못된 generation/params, 같은 ID의 type/radius/mass/omega 변경, S0 재고 누락/추가/중복, BOX/mesh/벽 위치 변화, 틀린 R-a 끝 step, 시간창/중력 불일치에 대한 판정을 명시한다.
- 입력이 불완전하면 관측 결손, 관측한 값이 다르면 수치 불일치로 남긴다. 지금의 `_atom_frame` 또는 G2 단독이 그 검사를 이미 한다고 쓰지 않는다.
- G2c의 torque·periodic flag 제외를 유지할 경우 그 제외 이유와 별도 관측을 등록한다. 접촉 0행·식별력 없는 접촉망의 동일성을 이력 복원 증거로 승격하지 않는다.

이 항목은 기존 P1 소비자를 곧바로 넓게 고치라는 지시가 아니다. P2에 필요한 지원/거부/대체 관측을 등록하고, 실제 연결할 구현에서 시험한다.

### C. 실제 R-a/S0와 자격

S0를 **고정판 R-a 완료 시점**에 연결한다. 원자/상/질량 재고, atom/contact/wall/mesh/restart/state, 활성 fix와 바이너리/run/hash를 같은 실행의 증거로 결합한다. 실제 숨은 이력은 지정 바이너리에서의 이력 양성/음성 대조가 필요하다. T10은 같은 물리 시간에서 dt/2, T11은 등록 서보 조건, T12는 복원·판독·관문까지, T13은 실제 checkpoint 단계별 재개로 확인한다. 합성 52·이번 729 상태 조합으로 어느 칸도 닫지 않는다.

### D. 통합

핀을 고정한 52 시험은 역사적 소비자를 검증한다. **향후 합친 트리의 소비자 파일에 결함이 생겨도 계속 옛 핀만 읽을 수 있다.** 따라서 CI에는 (i) 고정 핀 회귀와 (ii) 실제 통합 생산자/소비자 및 기대 모델 계약의 검사를 구분해야 한다. 실제 통합 commit·파일 hash·직접 검사·공유 게이트 영수증을 그 트리에서 남긴다. 고정 핀 52 PASS 또는 과거 155 PASS를 통합 트리 PASS로 복사하지 않는다.

Q7–Q9의 질량·지름·두께·불확도·측정 상태/시각은 별도 실측 축이다. 이를 채우는 일과 T12 소프트웨어 계약 수용을 혼동하지 않는다. 기준 밀도/공극률에 맞춘 역추정으로 대체하지 않는다.

## 7. 재현·반환 자료

검토 ZIP을 **새 폴더**에 펼쳐 실행:

```bash
python3 -I -X utf8 -B reproduce_review.py --output ./fresh_review_replay
```

- Python 표준 라이브러리와 Git 필요. Git 객체는 동봉된 원본 metadata/여섯 blob으로 새 검토 저장소 안에 재구성하며 객체 ID를 검증한다. 기존 리포 checkout을 요구하지 않는다.
- 변이 harness는 검사 목적의 임시 사본만 수정한다. 실제 소스·키트·원고·원장은 수정하지 않는다.
- `probe_promisor.py`만 의도적으로 자동 fetch 경계를 시험하며, **로컬 file 프로토콜만 허용**한다. 외부 서버·WSL·스케줄러를 호출하지 않는다.
- 새 출력 경로를 사용한다. 기존 영수증을 덮어써 성공처럼 보이게 만들지 않는다.
- `evidence/direct52.json`, `loader/report.json`, `mutants/report.json`, `scope_probes/result.json`, `scope_probes/restore_truth_table.json`, `promisor_probe/result.json`, `audit_result.json`이 판정 근거다.
- `review_scope.json`은 이 외부 회신의 한정된 범위를 기계 판독용으로 옮긴 것이며 물리 실행 영수증이 아니다.

**최종: P1 소비자 계약 발췌·52 관측 해석·ULPRI 좁은 종결은 수용. T12R-01(P2) 오프라인 실행 보장은 수정 필요. 실제 P2 T12는 NOT_RUN / 물리 GO는 부여하지 않음.**
