## 2. N1 [P2] 실제 1파 중지 뒤 계획·미실행 집계가 빠지고 미완 단위를 UNFIT으로 센다

**좌표:** `scripts/reil_c4_hb.py:1070–1076`, `:1305–1310`.
관련 경로 `:1020–1035`, `:1046–1069`; monitor의 중단 상태 기록 `scripts/reil_c4_monitor.py:187–205`.

요청서 §2의 39–41행은 선행 중단/미완이면 ρ 실행 0과 `NOT_RUN:RHO_PRECONDITION` 사유 기록을 함께 요구한다. §4 c_7 (102행)은 계획 = 실행 + 미실행 및 UNFIT/미해결의 분리를 요구한다.

그러나 `stage_a`는 1파의 상태를 저장한 뒤 `global_stop`이면 즉시 예외를 낸다. 요청된 ρ를 분류하는 `rho_wave`에는 도달하지 않는다. `plan_counts`는 `phase_a`에 키가 있다는 이유로 단위를 실행에 넣고, 완료 여부 없이 유효 증인이 없으면 UNFIT에 넣는다. 실행 횟수에는 COMPLETED만 세고, NOT_STARTED/STARTED_INTERRUPTED는 별도 칸에 세지 않는다.

**정적 반례:** J_V A0·J_D A0·ρ A0의 같은 셀 3단위를 요청하고, 작업자 1개의 첫 지역 실행에서 등록된 구조 오류가 나면 제공 실행기는 1개 STARTED_INTERRUPTED와 255개 NOT_STARTED를 남긴다. ρ는 시작하지 않는다. 이 상태에서 현재 집계식은 다음과 같다.

| 항목 | 현재 집계 |
|---|---:|
| 계획 단위 | 3 |
| phase_a 키가 있는 단위 | 2 |
| 단위 미실행 분류 | 없음 |
| 계획 지역 실행 | 384 |
| COMPLETED로 세는 실행 | 0 |
| 미실행 실행 수 | 0 |
| UNFIT 단위 | 2 |

이것은 오류 이후 최적화를 계속하는 우회가 아니라 **중지 결과의 결손·오분류**다. 첫 단위는 중단, 둘째는 시작 전이며 “전체를 끝냈지만 유효 증인 0”이라는 UNFIT 근거가 없다. 시작된 중단도 완료나 단순 미착수로 합치면 안 된다.

**한정 정정:** 중지 원문을 보존한 채 남은 ρ의 선행 미완 사유를 기록하고, COMPLETED / STARTED_INTERRUPTED / NOT_STARTED / 단위 gate 미실행을 서로 겹치지 않게 집계한다. 실행을 “착수”로 정의하든 별도 중단 칸을 두든 항등식의 정의를 명시한다. UNFIT은 완결된 Phase A의 유효 증인 0 등 등록된 근거로만 판정한다.

**추가 고정할 대조:** 실제 `stage_a` + 제공 runner의 첫 구조 중지 → ρ 호출 0·사유 존재·모든 계획 행의 분류·UNFIT 오승격 0. 기존 c_1은 주입한 미완 행에서 `rho_wave`를 직접 부르고, c_7은 완료/게이트 사례, c_8은 성공 연결이어서 이 중지 경로를 단언하지 않는다. 이번에 해당 대조를 실행한 것은 아니다.

## 3. N2 [P2] 프로파일 중심·순회에 저장 float 격자가 아닌 반올림 전 분수를 쓴다

**좌표:** `scripts/reil_c4_hb.py:491–494` (핵심 491행); 영향 경로 `:497–503`.
근거: 부속 A §3-3, 213–218행; `scripts/reil_c4_h.py:188–207`.

등록 격자는 십진/유리수에서 float로 변환한 뒤 중복을 제거하고 정렬한 점이다. 실제 실행도 `g["t"]`를 쓴다. 그런데 `run_profile_k`는 최근접 중심과 나머지 순서에 `g["t_fraction"]`을 전달한다. 두 표현의 미세한 차이가 동률 선택을 바꿀 수 있다.

**정확 분수 반례 (실자료 결과가 아닌 가능한 입력):**

- A0, #1, 좌표 m_P. 범위 [0.6, 1.1]의 41점 중 index 1은 float(0.6125), index 2는 0.625다. #1 명목 m_P=1에서 추가하는 .95/.98/1/1.02/1.05는 이 사이에 없다.
- 유효한 Phase A 최적 증인이 `(float(0.61875), 0.75, 0.25, 0.125)`라고 하자. 상자 안이며 Δ=1/8 > 1/10000다. 유한 목적의 유효 재평가를 얻었다는 조건의 합성 반례이고, 실제로 그 증인을 얻었다는 주장이 아니다.
- a = float(0.6125) = 2758454771764429/4503599627370496.
- m = float(0.61875) = 5573204538870989/9007199254740992.
- b = 0.625 = 5/8.
- 실제 저장점의 두 거리는 **m−a = b−m = 56294995342131/9007199254740992**다. 등록된 동률 규칙은 작은 t인 **index 1**을 고른다.
- 현재 코드가 쓰는 반올림 전 a′=49/80이면 m−a′는 더 크다. 따라서 **index 2**를 고른다.

부동소수점 오차가 목적값에 미치는 정도를 문제 삼는 것이 아니다. 중심 여부와 s2의 안쪽 이웃/Phase A 대체 사슬이 달라져 등록된 결정적 탐색 경로가 바뀐다는 문제다. 검토자 자체 IEEE754 비트 판독·BigInt 정확 산술을 `CENTER_COUNTEREXAMPLE.json`에 남겼다. 후보 함수는 부르지 않았다.

**한정 정정:** 중심·순회와 실제 실행에 같은 저장 float 격자를 사용한다. 정확 비교를 유지하려면 저장된 float를 정확 분수로 바꾸어 비교하면 된다. 기존 배열·seed·label 재생성이나 자료 맞춤은 필요하지 않다.

**시험의 빈틈:** p_1 (`tests/test_reil_c4_0b2.py:295–304`)은 helper에 수동 분수 또는 `F(g["t"])`를 직접 넣어 운영 경로의 다른 표현을 검사하지 않는다. p_6 (387–394행)은 전체 점 수·index 집합·값을 보지만 중심/순서는 보지 않는다. 위 입력의 `run_profile_k` 중심·순서·s2 근거가 동일 격자 표현을 따르는 대조를 사전에 고정해야 한다.

## 4. N3 [P2] 발견 폭 판독에 근거 증인의 부가 라벨·등급 수가 연결되지 않는다

**좌표:** `scripts/reil_c4_hb.py:830–849`, `:882`.
관련 `:756–800`, `:875–878`.
근거: v2 203행, 부속 A §7, 부속 B §1-3 84–91행, 요청서 §4 l_3.

`width`는 value/unresolved/observed만 돌려준다. `_read_unit`은 그 값을 그대로 저장한다. 부가 라벨 함수는 양립 판정 `_compat`를 통해서만 연결되고, 개별 양립의 근거는 명목값 근처 구간에 있는 증인으로 제한된다.

따라서 #0/#4/#5의 LII에서 명목 ±0.05 밖의 충족 증인 둘이 0.1보다 넓게 떨어져 있으면 WIDE를 얻으면서, 개별 양립은 모두 NOT_FOUND와 빈 extra가 될 수 있다. 폭 결과에는 등록된 **제약 절단**이 없고, 그 폭의 근거가 budget 종료·외삽·목적 경계에 기대더라도 해당 라벨이 붙지 않는다. 수치 수용 증인으로 얻은 WIDE (수치 경계 의존)에도 별도로 요구된 **선형 제약 경계**가 없다. 등급별 증인 수 역시 폭 판독에 없다.

기본 WIDE의 정확 증인 둘 규칙과 “수치 경계 의존 + UNRESOLVED” 본문자체는 맞다. 결함은 **그 주장의 근거와 함께 붙어야 하는 별도 축을 다른 양립 주장에 맡긴 것**이다. 이는 후속 H1 머리말·U-a…U-e 보고 서식의 유보와 다르다.

**한정 정정:** 각 폭 주장의 실제 근거 증인 식별/좌표·등급 수·부가 라벨을 폭 결과에 직접 결속한다. 무조건 WIDE를 지지하는 정확 증인 쌍이 있으면 그 근거를, 수치 수용에 기대는 폭이면 그 근거를 분명히 한다. 경계 행 LII의 제약 절단은 폭 판독 자체에 붙인다.

**추가 고정할 대조:** 명목 양립 NOT_FOUND + WIDE, 경계 행 LII, 수치 수용에만 기대는 WIDE, budget/외삽/목적 경계가 함께 붙는 경우를 최종 `_read_unit`/연결 판독에서 단언한다. l_2는 폭 본문, l_3는 `extra_labels` helper를 따로 검사하므로 지금 연결 누락을 잡지 못한다.
