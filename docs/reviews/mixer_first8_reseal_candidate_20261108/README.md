## 운영 봉인과의 구분

기존 `docs/reviews/mixer_first8_launch_preparation_20261106/submit_one.py.txt`는 **자신 옆** `source_seal.json`과 `static_asset_manifest.json`을 읽는다. 그 파일들은 그대로다. 따라서 기존 드라이버가 이 후보를 자동으로 채택하지 않는다. 기존 승인 source_pin 동등성 검사는 옛 핀과 새 핀을 다르게 본다. 이 설명은 소스의 경로·조건식 정적 대조이며 드라이버를 실행한 결과로 표시하지 않는다.

후보는 `source_pin` 대신 `validation_source_pin`, 별도 schema와 `operational_activation=false`를 사용한다. 실행 코드가 읽는 봉인 자리에 복사·이름 변경하지 않는다. 새 approval·허용 제출 목록·GO 파일도 만들지 않았다. 외부 후보 수용 뒤에도 MLA 재확인, 최종 드라이버·runner·physical manifest 일괄 결속과 검토를 거쳐야 운영 준비가 이어진다. 후보 JSON 하나의 수용으로 운영 재봉인이 완료되는 것은 아니다.

R01 소비자 seed 범위 CLOSED는 유지한다. 생성기 단독 최대 층상 부적격 덱 출력, MLA-01–03, 예약 해제/정책 전환, 실제 100k 양성·로그·binary/MPI·자원/시간/디스크, 저자 NP/동시 팔/순서·실제 GO는 별도다. 11-06의 ibb 빈 상태 전달을 11-08 현재 자원 확인으로 사용하지 않는다. NP20·E0 단독→N0 단독→B1/B2/B3 U/C·자격 뒤 최대2팔은 여전히 권고이지 승인값이 아니다.
