## 재현과 수정 확인

외부 집중 반례 여섯 개를 실제 arm CLI에서 먼저 재실행했다. 정상·복구 대조는 OK이고 literal 소수 RESUME는 인증 없음·옛 행 제외 0·UNIDENTIFIED/null이다. 반면 앞 판의 끝 space/NBSP 표지와 다른 문자열 뒤 U+2028 manifest는 모두 인증을 유지하고 옛 행 5개를 제외하여 OK/rank true를 냈다. CSV 원문은 변하지 않았다. 외부 판정과 같은 결과이며 새 물리 오차 주장이 아니다.

초기 수정의 parsed-event 검사 앞에서 공용 CSV의 splitlines가 단일 RESUME 앞의 VT/FF/FS/GS/RS/NEL/LS/PS를 빈줄처럼 제거하는 반례도 확인했다. 정확한 정수값을 유지한 단일 표지 교체 22개 중 8개가 인증을 유지했다. 최종 수정은 공용 CSV 파서가 이 문자를 지우기 전에 원래 물리 줄의 event 셀을 검사한다. 공용 파서 자체는 바뀌지 않았다.

각 음성 CLI는 인증 없음, 옛 행 제외 0, 문제 기록 존재, UNIDENTIFIED/null, rank 불가, 원 CSV 보존을 함께 확인한다. 확장 검사는 manifest와 상태 파일도 실행 전후 hash가 같다. CLI rc 0 자체를 합격이나 생산 발사 허가로 해석하지 않았다. 숫자들은 서로 중복되는 보증을 포함하므로 합산하지 않는다.

변이 검사에서는 정상+변형 표지 공존을 대상으로 auth 차단 제거를 공격해야 한다. 최초 자극을 단일 비정규 표지로만 두었을 때는 canonical RESUME 자체가 없어 해당 변이가 살아남았다(5/6). 올바른 공존 자극으로 수정한 뒤 동일 생산 소스에서 6/6을 확인했다. 첫 결과는 `candidate-v2-mutants/report.json`에 보존했다. 이는 검사 자극 수정이며 생산 코드의 추가 변경이 아니다.

## 변경 범위와 문구

reader에서 생산 동작을 바꾼 함수는 `_resume_auth`, `read_run`이다. 별도로 새 R40 시험 함수와 selftest 연결이 추가됐다. `_i`, `_csv` AST는 기준과 같다. 숫자 교정 R39, 파라미터, 생성기, 생산 덱, history는 유지된다. seal 도구의 변화는 현재 재개 규칙 설명과 R40 증인 등록이다. 사전등록 문서에는 물리 수치를 바꾸지 않는 날짜 있는 무결성 설명이 한 줄 추가됐다.

RESUME의 앞뒤 whitespace 근접 표지는 정상화하지 않고 오류로 취급한다. manifest는 키 선별 전에 VT·FF·FS·GS·RS·NEL·LS·PS를 거부하고 정상 LF·CRLF·CR을 유지한다. 임의의 모든 사건 이름이나 모든 악성 파일 문법을 새로 검증했다는 주장은 없다. canonical RESUME를 사용하는 UTc의 별도 continuation 계약에도 새 manifest 필수조건을 넣지 않았다.

검사 뒤 README 한 문장만 바뀌어, 10-23에 남았던 소수 반올림 한계와 10-24 R39 교정 수용의 시점을 명확히 했다. reader·seal·규칙·등록 바이트는 그대로다. `final-doc-only-review.json`과 patch로 대조했다.

최소 사본의 첫 실행은 r8 archive 의존 파일이 없어 사례 실행 전에 종료했다. 정확한 기준 Git blob을 복원한 뒤 새 출력 경로에서 위 결과를 얻었다. 실패한 부분 디렉터리는 보존했고 소스 결함으로 세지 않았다.

공용 저장소 전체 게이트와 Git 반입·push는 root의 별도 작업이다. 이 독립 검토는 공용 155개를 실행했다고 주장하지 않는다. ULPRI-01/02는 로컬 수정·독립 재현 완료로 넘기며, 지정 새 핀의 외부 재확인과 기존 실제 실행 조건은 남는다.
