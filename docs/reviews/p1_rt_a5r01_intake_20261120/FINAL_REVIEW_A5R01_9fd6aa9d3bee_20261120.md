검토일: 2026-11-20. 수정 핀: `9fd6aa9d3bee52f95dfed507a953da3d985544bb`, 가지 `codex/p1-a5r01-1120`. 비교 핀: `a230b908546f7851da0dad2b80adfc6d866c4dd9`.

| ID / 등급 | 원 반례 | 수정 및 해결 증거 | 처분 |

### 3-1. 생산자 기록 실패

- `candidate/run_unload_a5_candidate.sh:203`: `printf '%s\n' ... >> "$MAN"` 실패 시 오류를 표시하고 `exit 2`로 종료한다. 다음 reader나 마지막 성공 줄이 이전 실패를 지우지 않는다.
- `:297–303`: reader rc를 기록하는 경로가 이 note를 사용한다.
- `:321–329`: select 의무를 정하고 restore 발행·kebase 판독을 실행한다.
- `:384–389`: 저장한 select 결정으로 판독한 뒤 마지막 end도 note로 기록한다. note 실패 시 이후 bundle/성공 종료에 도달하지 않았다.

독립 producer 시험은 위 후보 구간을 그대로 추출하고 수치 판독기·bundle을 모의 대체했다. 실제 `issue()`와 `admits()`는 후보 것을 사용했다.

| 조건 | 실제 종료 | 후속 소비 | 원시 오류/관측 |
|---|---:|---|---|
| 정상, UB 없음/있음 | 각각0 | 허용 | 필요한 select만 기록 |
| kebase rc2 | 2 | 거부 | 최종 reader_rc2 보존 |
| restore rc120 | 120 | 거부 | 최종 reader_rc120 보존 |
| kebase 행 쓰기 대상이 디렉터리 | 2 | 거부 | 실제 `Is a directory`, end 미도달 |
| 마지막 end 쓰기 대상이 디렉터리 | 2 | 거부 | 실제 `Is a directory`, 성공 end 없음 |
| 위 두 위치에서 `/dev/full`로 쓰기 | 각각2 | 거부 | 실제 ENOSPC, 성공 end 없음 |
| 위 두 위치에서 8 B 기록 후 닫힌 fd로 나머지 쓰기 | 각각2 | 거부 | 실제 EBADF, 잘린 tail 보존·마지막 LF 없음 |
| 발행 뒤 UB 생성/삭제 | 각각0 | 허용 | 발행 전 결정대로 select 의무 유지 |

12사례는 각1회이며 반복·하위 조건을 합산하지 않았다. `/dev/full`은 로컬 Git Bash의 장치 오류이고 실제 현장 파일시스템의 용량 소진 시험이 아니다. 8 B 부분 기록은 printf를 계측하여 일부를 쓴 다음 fd를 닫은 주입 시험이다. 일반 파일의 실제 ENOSPC 부분 쓰기라고 주장하지 않는다. 생성/삭제 후 select 자체의 수치 판독은 모의 성공이며, 여기서는 **호출 의무의 고정**만 확인했다.

### 3-2. 소비자의 완료 영수증 문법

- `candidate/a5_certificate.py:24–43`: 발행 전 접두부의 완료/reader 행을 거부한다. select 표지는 없음 또는 정확히 `a5_select_required=1` 한 줄만 받는다.
- `:76–94`: 검증한 접두부 원바이트 해시를 증서에 넣고 증서 원바이트 해시를 장부에 넣는다. select 결정은 이 접두부에 포함된다.
- `:97–117`: 발행 뒤 tail은 증서 SHA, `reader_restore_rc=0`, `reader_kebase_rc=0`, 필요 시 `reader_select_rc=0`, 실패0·reader_rc0의 end, 마지막 LF로 정확히 일치해야 한다. 뒤에 행이 더 붙거나 개행이 없으면 거부한다.

독립 소비자 검사는 **191/191 기대 일치**다. tail 변형156, 발행 후 접두부·해시 변형22, UB 상태 변화4, 발행 전 잘못된 접두부9로 구분한다. 기존 원 네 조건·작성 측 회귀와 겹치므로 별도 총합을 만들지 않는다. 정상 시퀀스와 제어문자/행 분리·공백 변형, 필수행 삭제·반복·비영·순서 뒤집기·미등록행·end/LF 훼손, select 표지의 사후 변경을 확인했다.

UB 폴더를 소비 시점에 다시 조회해 과거 의무를 바꾸지 않는다. 소비자는 이미 결속된 접두부 결정을 따른다. 단독 `issue(report)` API가 현재 UB 상태를 직접 측정한다는 뜻은 아니며, 실제 생산자의 발행 전 결정 연결과 함께 수용한다. 임의 API 호출자가 UB와 맞지 않는 접두부를 직접 주는 경계 관찰2건은 정상 러너의 우회가 아니므로 새 finding으로 세지 않았다.

## 5. 재현과 남는 경계

증거 ZIP의 `REPRODUCE_REVIEW.md`에 새 폴더 재현 순서를 적었다. 핵심은 다음과 같다.

```text
python -I -X utf8 -B input/reproduce.py --build-only --work baseline_build
python -I -X utf8 -B run_local_regressions.py
python -I -X utf8 -B consumer/reproduce_consumer.py
python -I -X utf8 -B producer/probe_producer.py
```

재현 스크립트는 자신의 새 scratch에만 쓰며, 입력 후보는 보존한다. 원시 영수증에 포함된 작업 경로는 해당 실행 신원의 일부이므로 다른 위치에서 재사용할 때 경로를 편집하지 말고 스크립트로 새 합성 증서를 만든다.

이번 수정에 추가로 요구할 필수 고침은 없다. 새 P1/P2/P3도 없다. 비차단 포장 설명 한정 외에 기존 수용을 다시 열지 않는다.

계속 별도로 남는 것은 원 A3 위치/45파일의 실제 보존과 현장 preflight, 지정 바이너리·실제 MPI/RT 자격, 운영 봉인과1저자 발사 결정, 새 RJ의 RT1/RT2·연속성·완료 자료와 물리 판정이다. 기존 B의 일반 장부 소비자·모든 실패/재큐 이력 한계도 이번 완료 행 수정으로 해소된 것은 아니다. 실제 원자료·연구 값·현장·전체 gate는 열람하거나 실행하지 않았다.

**최종: A5R-01(P2) 한정 종결 가능. 해당 사유의 A5 봉인 후보 HOLD 해제 가능. 운영 봉인·현장 실행·물리 GO는 별도 미승인.**
