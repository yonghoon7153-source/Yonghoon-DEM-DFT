# 격리 모드 재검증 — 2026-10-23

Package audit에서 재생 명령과 두 도구의 Python 자식 실행에 `-I`가 빠진 것을 확인한 뒤 수행한 **새 실행**이다. 원래 검토문과 `reviewer/`, `root_reproduction/`의 결과는 바꾸지 않았다. 그 이전 실행이 격리 모드였다고 소급하지 않는다.

네 도구를 각각 `python -I`로 새 출력 폴더에서 실행했다. `mutations.py`와 `provenance_replay.py`가 만드는 Python 자식도 `-I`를 쓴다. 필요한 저장소 경로는 명시적으로 추가한다. 보강 전후 도구 해시는 `tool_changes.json`, 실제 명령·도구 해시·시간·결과는 `summary.json`에 있다.

| 새 실행 | 결과 |
|---|---|
| audit | rc 0. 독립 진리표 512가지 불일치 0, 실제 문서 반례 7가지 rc 1 |
| pin_probe | rc 0. 정상·LF는 P0–P10 통과, CRLF·space·NUL은 P7/P10 실패, 다른 마지막 hex는 P10 실패. 프로브를 포함한 원본 자체시험 123/123 |
| mutations | 도구 rc 0. 네 고의 변이는 각각 122/123·rc 1, 실패는 S11g 하나씩 |
| provenance_replay | 도구 rc 0. 날짜 자리 8개·7개의 비준 diff가 비준 커밋 바이트와 일치. 수정 전 도구는 121/122·rc 1, S0b만 실패 |

검토 소스 40파일의 해시는 원래 source manifest와 같다. 격리 모드 추가는 생산 코드나 판정식 수정이 아니다. LF 반례의 영향 한정도 그대로다: 다른 승인 커밋을 허용한 반례가 아니다. 새 결과를 기존 실행 수에 더해 시험 범위를 부풀리지 않는다.

이 검증은 전체 저장소 게이트, 실제 WSL 사전 점검, 외부 반박 세션 GO 또는 발사 승인이 아니다. 재생 명령은 [상위 안내](../README.md)에 있다. 생성 픽스처와 변이 소스는 반입하지 않고 도구로 다시 만든다.
