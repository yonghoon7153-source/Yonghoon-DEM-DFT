## 2. A - 부속 D 판정

### RV2C-N1: 종결

D §1은 명목 목표값의 Table 1/Fig. 6/A.4 대응과 **출판 추정치의 정규화 분모 동일성 미확인**을 나눴다. 상대 잔존량 `z/z_F`, 일반식 `z_F = m_P,F − (d_P,F − d_N,F)/max_q`, 명목 Fresh 설정의 충분조건/실제 fitted Fresh 구분, 상대 LLI 미등록, H1 강제 머리말이 모두 들어 있다. C1-core §4-4의 옛 주장은 취소선이고 §8-1로 연결된다.

### RV2C-N2: 종결

D §2 및 C1-core §8-2는 CE 비들의 곱을 재고 잔존율로 바꾸는 해석과 약 17% 손실 추정을 철회했다. 첫 세 formation cycle과 cycle 1–4 곱의 범위도 구분한다. 위키 엔티티는 과거 주장을 보존하면서 철회 참조를 달았고 raw digest는 불변이다.

같은 줄의 약 0.82 추정을 크기 근거에서 제외한 것도 적절하다. 두 가정 기반 비율의 근접은 그 가정의 독립 검증이 아니다. 이 이유를 한 문장 추가하면 읽기 쉽지만 **종결 조건으로 새 정정을 요구하지 않는다**. U-a 크기 미정, 명목점/허용오차 불변이면 충분하다.

### RV2C-N3: 종결

D §3은 cycle과 방향을 별도 축으로 기록하고 세 상태와 종합 우선순위를 고정한다. 명시적 cycle metadata/자료 README/저자 문서의 행 결속을 요구하며 추측·NaN 순번·그림으로 cycle을 채우지 않는다. 충돌/미확인은 판정 불가이고, 확인된 불일치가 종합에서 우선한다.

논문 p3은 완전지 충전에서 PE 탈리튬, NE 리튬화라는 읽기를 지지한다. **기대 물리 반응**의 근거이지 실제 xlsx 두 기준곡선의 방향을 확인한 증거는 아니다. D §3-1이 반쪽전지의 장비 charge 명칭/전류 부호를 완전지와 같게 강제하지 않는 점도 맞다.

19개 이름을 분석 11 + 기준 2 + 밖 6으로 분리한 목록은 기존 명세와 일치한다. 밖 6은 시트 12/13/**14**/17/18/19이며 15는 기준에 남는다. 실제 시트 집합이 다르면 자동 이름 대응이나 재선택 없이 사용자 결정을 기다리는 규칙이 있다. 문서화된 매핑은 현재 적힌 출처 범위와 위치·행 결속/충돌 시 판정 불가 규칙으로 충분하다. 실제 대응은 P0까지 미확인이다.

### A의 질문별 답

1. N1/N2/N3 모두 종결한다.
2. PE/NE 기대 반응의 p3 해석은 맞다. 장비 이름/부호까지 자동 확인한 것은 아니다.
3. 문서화된 매핑의 출처와 근거 위치 규칙을 수용한다. 실제 선택 행과 연결되지 않으면 판정 불가다.
4. 0.82를 크기 단서에서 빼는 것은 적절하다. 추가 이유 문장은 비차단이다.
5. D §4의 U-e 비특이적/미확인 가설, Eq. 15 적용 가정, 명목값과 물리 참값 구분, 추가 불확실성 한계는 앞선 수용 범위와 맞는다.

## 3. B - 남는 국소 사항

### C6-N1 (P2): 관측된 LICENSE 충돌과 일반 예외 규칙을 분리해야 한다

위치: C6 README 36–39행, 상태 문서 142–144행, lock의 collision 줄.

현재 기록된 한 건은 `about-time`/`alive-progress`의 `../../../LICENSE`다. 이 **고정된 관측을 설명된 설치 충돌로 보존하는 것**과, `site-packages 밖 + 다른 배포판 RECORD와 일치`이면 어떤 충돌도 허용하는 **재사용 규칙**은 다르다. 후자는 LICENSE로 제한되지 않는다.

문서 조건만의 반례: 두 배포판이 `../../../bin/tool`을 서로 다른 해시로 주장하고 실제 파일이 두 번째 RECORD와 맞으면, 제시한 두 조건을 모두 만족한다. 실행 진입점이 덮여도 같은 예외가 된다. PyPA RECORD 명세도 site-packages 밖 스크립트 경로를 정상 예로 든다. 이는 **문서 규칙의 논리 반례**이며, 실제 C6에서 실행 파일이 충돌했다거나 제공 구현을 실행해 재현했다는 뜻은 아니다. [PyPA RECORD 명세](https://packaging.python.org/en/latest/specifications/recording-installed-packages/)

최소 종결 조건:

- 이 고정 LICENSE 관측만 허용한다면 승인된 상대 위치, 두 배포판/버전/RECORD 식별, 두 expected 해시와 실제 파일 해시를 근거에 결속한다. 절대 venv 경로는 달라져도 되지만 정규화 위치/범위는 같아야 한다.
- 나머지 충돌은 불일치로 중지한다. 단순히 경로가 밖이거나 다른 소유자가 맞는다는 사유만으로 새 충돌을 허용하지 않는다. 실행 파일, venv 밖 해석, 경로 우회가 이 예외에 섞이지 않도록 계약에 명시한다.
- 실제 코드가 이미 이보다 좁다면 현재 요청의 코드 열람 금지와 충돌하지 않도록, 다음 회신에서 해당 부분의 **정적 열람 허용**을 명시하고 위치/고정 SHA를 제시하면 된다. 지금 자동 수정·시험을 요구하거나 승인하지 않는다.

현재 봉인 10개를 실패/변조로 재분류하지 않는다. 이 항목은 재사용할 C6 검사 규칙의 수용 조건이다.

### C6-N2 (P2): 실제 옵션 전달과 검사 실적의 원문 연결이 부족하다

위치: C6 README 26, 40–41, 53–62행; COBYQA_OPTIONS.json 10–66행; 상태 문서 154–159행.

MANIFEST는 자료의 바이트를 확인하지만 그 자료에 적힌 실행 주장의 진위를 독립 증명하지 않는다. 현 고정 tree에는 C6_RUN.log가 없고, 12개 변이/538개 시험의 원문도 이번 수신 경로에서 확인하지 못했다. 9/12/538 통과는 현재 **제출자 보고**로 기록한다. 실패했다고 판단하는 것은 아니다.

COBYQA JSON에는 8개 `planned` 값/문서와 합성 함수 성공 boolean은 있지만, 실제 전달된 typed `options`/호출 인자와 그 호출의 원문 반환을 확인할 수 없다. 경고 0과 단순 이차 함수 성공만으로는 모든 옵션을 명시 전달했다고 구별할 수 없다. 예를 들어 `disp=False`, `f_target=-inf`, 4차원의 `maxfev=2000`/`maxiter=4000`은 문서상 기본값과 겹치며, 제약 없는 이차 함수는 feasibility tolerance 전달 여부를 입증하지 않는다. 실행을 잘못했다고 단정하는 것이 아니라 **계획과 실제 전달의 증거를 구분**하는 것이다. [SciPy COBYQA 옵션 문서](https://docs.scipy.org/doc/scipy/reference/optimize.minimize-cobyqa.html)

최소 종결 조건:

1. 남아 있는 당시 C6_RUN.log, emit/check·archive 대조·12개 변이의 원문 출력/rc와 고정 소스/환경/manifest 관계를 별도 보충한다. 538개 전체 회귀를 주장하려면 그 원문도 함께; 핵심 C6 근거와 별개로 원문 미보존이라고 낮춰 기록하는 선택도 가능하다.
2. 당시 합성 호출이 8개 값을 전달한 것을 확인할 기존 호출 기록이 있으면 포함한다. 없으면 그렇게 적고, 해당 호출부와 출력 생성부의 **좁은 정적 코드 검토 허용**을 다음 요청에 명시한다. 새 실행 결과를 과거 기록처럼 만들지 않는다.
3. 로그가 소실됐다면 미보존을 신고한다. 원문 보완을 이유로 자동 재설치/재시험/538개 재회귀를 요구하지 않는다. 기존 자료 또는 좁은 정적 확인으로 해결되지 않는 부분만 별도 승인 범위로 제안한다.

Sobol의 `rng`와 이전 `seed` 경로를 구분하는 것은 공식 전환 설명과 맞는다. 64점 전체의 성질을 임의 앞 12점에 확대하지 않는다. 이 공식 문서는 호출 의미의 참고이며, 제출한 1.17.1 바이너리의 실측 대신 쓰지 않는다. [SciPy 1.17.0 Sobol 문서](https://docs.scipy.org/doc/scipy-1.17.0/reference/generated/scipy.stats.qmc.Sobol.html)

검사가 보증하지 않는 것:

- `unhashed=5301`은 내용 해시 검증 PASS가 아니다. RECORD 자체 해시와 설치 파일 전부의 내용 동일성은 다르다. 무엇이 unhashed인지 근거 없이 모두 pyc라고 추정하지 않는다.
- PROFILE의 NumPy/SciPy `build_dependencies`는 빌드 메타데이터다. 실제 로딩 라이브러리/스레드수/CPU dispatch/프로세스 환경 전체의 직접 관측으로 확대하지 않는다.
- 버전+RECORD 식별은 설치 배포물까지 내려받아 고정한 재설치 lock과 다르다. 다른 OS/휠/빌드에서 같은 버전만 맞췄다고 동일 환경으로 승격하지 않는다. 같은 판 재구축 뒤 exact check 불일치는 중지 조건이다.
- 신뢰 기준인 checker/emitter와 현재 환경까지 함께 바뀐 자기일관 재작성, 해시 없는 파일 내용, 미래 연구 코드의 옵션 사용, 모든 연구 계산의 bitwise 재현성까지 검증하지 않는다. 고정 커밋과 기대 manifest를 외부 기준으로 유지해야 한다.
- 12개 변이는 제출된 유한 사례이지 모든 위조·판 이동의 완전성 증명은 아니다. 이에 대한 새 무제한 보안 시험이나 OS sandbox를 C6 요구로 추가하지 않는다.

## 5. 다음 최소 회신 범위

부속 D는 접수/종결 기록만 남긴다. C6는 **현재 LICENSE 예외의 정확 범위 + 남아 있는 호출/검증 원문 + 필요한 경우 좁은 정적 코드 열람 허용**만 보충한다. 받은 10개 봉인과 과거 실패는 유지한다. 새 profile/manifest를 만들 필요가 생기면 과거 것을 덮지 말고 변경 이유와 새 식별을 따로 제시한다.

지금 자료 개봉/맞춤/설치/실행을 시작하지 않는다. 이 보완이 수용된 뒤 P0의 대상 파일 식별, 출력, 시간·메모리·디스크 예산, 중단 조건, 금지 범위를 사용자에게 별도 요청한다. 자동 연구 실행이나 진행 중 Gate/PyBaMM/COMSOL 작업과의 병합은 없다.
