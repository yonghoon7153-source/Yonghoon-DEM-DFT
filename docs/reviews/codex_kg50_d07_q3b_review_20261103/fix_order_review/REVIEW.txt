3. Exact fixed-version replacement/restart semantics

Primary source:
https://github.com/CFDEMproject/LIGGGHTS-PUBLIC/blob/3d5c00f20519e6bb6eb6756f51f1ad36564e649d/src/modify.cpp

- L784–813: reusing an existing ID of the same style destroys/recreates that fix in its existing slot; new style mismatch errors. The existing slot index remains.
- L814–859: a newly created ID appends to the list.
- L947–962: unfix removes the slot and shifts following slots down; a subsequent fix with that ID appends.
- L1325–1335: ordinary per-hook lists are built by filtering fix slots in their existing order.
- L863–909: global and per-atom restart data are restored by fix ID plus style (or explicit accepted style), not by declaration slot. A changed slot alone does not detach restart data.
- L1190–1200: reading restart data does not itself recreate all fixes.
- L1338 onward has special contact-history-first pre_exchange handling; our simple model is not a universal representation of all runtime hook ordering.

Therefore same-ID replacement, unfix/re-add and restart redeclaration are distinct operations. "Sort to last declaration" is not a correct generic runtime-order reconstruction.

7. What the actual -T can and cannot establish

The fixed-source analysis supports a conditional "same specified force law and intended control sequence, with numerical restart differences". It does not prove bitwise restart equivalence, bounded long-term divergence, a guaranteed identical threshold-crossing cycle or physical validity. Roundoff can propagate through contact evolution; a short passing test checks that window only. A pressure threshold can amplify tiny later differences if it is very near the threshold.

For the current one case, inspect the actual generated preparation, source/restart identities and real trial G0–G3 records. Confirm same IDs/styles and absence of additional force-overwriting/controller fixes, expected checkpoint and restored mesh/history paths. This is evidence completion, not a request to redesign the general tool.

For future checkpoints/Q4, this source argument can carry forward only while the same physical deck/styles and relevant order persist; a fresh trial and original-log phase evidence remain necessary. It is not an unconditional future-run GO.
