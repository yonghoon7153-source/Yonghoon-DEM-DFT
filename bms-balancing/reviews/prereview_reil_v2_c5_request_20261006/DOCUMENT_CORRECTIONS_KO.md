# REIL C5 승인문 수정 문안 제안

원문 좌표는 커밋 `7def9238c8fdac605decc5bf17c1428a93faad1d` 기준이다. 아래는 작성자가 정정본에 반영할 **제안**이지 원문 편집이나 사용자 승인문 채택이 아니다. 숫자 한도·시험 목록의 미확정 부분을 작성자가 고정한 뒤 사용자에게 보여 준다.

## 1 봉인 시점

§9 Q1 109행의 “후자 … Codex 확인을 받는다”를 다음으로 정정하는 것을 기본 경로로 권고한다.

> 현재 부속 B §2-1을 유지하므로 첫 실제 C5 지역 실행 전에 자료 무관 고정 배열 전부를 정식 봉인한다. 기존의 동일 봉인 배열은 재사용 식별을 연결한다. 필요한 생성·대조의 범위와 예산은 실행 전에 사용자에게 승인받으며, 이번 문서 검토는 생성 권한이 아니다. 파일럿만 예외로 전체 봉인을 C4 전까지 미루려면 결과 관측 전에 별도 사전 정정과 사용자 결정을 받아야 한다.

§4 64행도 선택된 경로와 맞춘다. 예외를 택할 경우 “A §3-9가 자동 면제한다”는 문장은 쓰지 않는다.

## 2 환경

§4 62행과 §11 128–129행의 자동 재구축 경로를 다음 기본 경로로 바꾼다.

> 지정된 reil_c6_rebuild_20261006 봉인의 venv가 존재하고 같은 실제 interpreter에서 check가 통과할 때만 다음 단계로 간다. 실행 기록에는 interpreter 경로와 lock/manifest의 실제 SHA를 연결한다. 부재·불일치면 자료 맞춤 전에 중지한다. 환경 재구축·설치·새 RECORD 차이 수용·변이 증명은 자동 대체 경로가 아니며, 필요한 범위·횟수·예산을 따로 제시해 새 사용자 승인을 받는다. P0의 한정 환경 결정은 그대로 보존한다.

## 3 전역 중단과 예산

§3 50행과 §5 71행의 “시간 상한 → 미실행”을 바꾼다.

> 전역 시간·자원 상한에 도달하면 신규 지역 실행을 시작하지 않고 소유 작업자를 정해진 종료 절차로 중단한다. 시작하지 않은 항목만 미실행으로 적는다. 시작된 항목은 실제 도달 단계와 중단 사유를 남기고, 반환점이 있으면 그대로 보존한다. 독립 재평가가 끝나지 않은 점은 유효 증인으로 승격하지 않는다. 중단된 계산의 평가 수가 확정되지 않으면 마지막 관측값과 미확인을 표시한다. 재시도·재배정은 하지 않는다.

§3·§6·§7에 다음 항목의 **실제 수치/경계**를 채운다. 이 검토가 임의 값을 정하지는 않는다.

- 측정의 monotonic 원점과 준비·대조·측정·소유 정리·최종 기록의 단계 한도, 7,200초 안의 종료 여유.
- 새 산출 폴더의 정확 경로, 기존 폴더 충돌 시 중지, 최대 크기와 실행 중 크기/디스크 여유 관측 주기.
- 부모+작업자 RSS 표본, 감시 불가·누락·초과 시 처리, 종료 확인 실패 시 미완 기록.
- 부모 최종 기록 후 snapshot과 실제 외부 rc. 반환 뒤 시간까지 측정했다고 소급하지 않음.
- 내부 평가·재평가 시도·라벨 계산을 따로 세고, 라벨은 동일 재평가 산출을 사용함.

## 4 오류 우선순위와 재평가

§2 35–40행과 §3 48행에 다음 구분을 추가한다.

> 예상된 x 의존 목적 평가 실패는 지역 실행의 solver_error로 기록하며 유한 벌점을 만들지 않는다. 구조·코드·환경·입출력·메모리·기록 오류 및 전역 자원 중단은 지역 오류 규칙보다 우선하여 파일럿 전체를 멈춘다. 예외 형뿐 아니라 발생 단계와 근거를 기록한다.
>
> 반환점 없는 optimizer 오류는 독립 재평가 0회다. 반환 후 독립 재평가에서 실패한 경우는 반환 x와 원 solver status/termination을 보존하고 재평가 시도 1회·재평가 오류·증인 판정 미완/무효를 별도로 기록한다. 해당 이유 값은 실행 전에 고정한다. 원래 SOLVER_ERROR의 “반환점 없음” 정의를 조용히 확장하지 않는다.
>
> nan/inf를 임의의 유한 벌점으로 바꾸지 않는다. 비유한 전달, optimizer 반환/예외, 재평가 결과는 서로 다른 기록이다.

§6 86행에는 다음 우선순위를 붙인다.

> 전역 중단 조건이 없을 때만 지역 budget/solver_error/무효 증인 기록 후 다음 예정 실행을 계속한다.

## 5 구현 승인 범위

§5 72·75행, §10 (1) 118–119행, §11의 “bms 전체”를 정정한다.

> 구현은 고정된 소스 범위와 무자료 합성 시험·합성 건조 실행까지만 한다. 구현·RED/GREEN·건조 실행·보존의 단계/전체 한도와 허용 횟수, 정확한 시험 집합·명령은 아래 표에 고정한다. 합성 건조 실행의 시작점 4개·maxfev·maxiter·시간 한도를 실행 전에 정한다.
>
> 기존 bms 시험을 포함하려면 수집 단계까지 포함하여 실제 REIL 자료·pickle·노트북 개봉, 정식 Sobol 재생성, 설치/환경 재구축, 실제 파일럿 호출이 없음을 정적으로 확인한 목록만 승인한다. 확인되지 않은 “전체 시험”을 묵시적으로 실행하지 않는다.
>
> 구현 결과·첫 실패·후속 정정·환경/코드/시험 식별·최종 기록을 제출한 뒤 멈춘다. 실제 자료 사용과 비용 측정은 별도 승인이다.

아직 채워야 할 표는 구현 시간, 시험별 상한/횟수, 건조 실행 옵션/횟수, 보존·전달 한도, 출력 폴더/충돌 처리다. 이 값이 비어 있는 문구를 완성된 사용자 승인문으로 전달하지 않는다.

## 6 비용 통계 표현

§7 96행의 “실제 병렬 효율”을 “작업자 4에서 관측한 wall·CPU·점유·대기·부하 불균형”으로 바꾼다. 완료/지역 오류/전역 중단 비용을 구분하고, 중단 시간은 완료 시간으로 대체하지 않는다. 추가 직렬 실험은 요구하지 않는다.
