## 5. Q1–Q8 답

### Q1. 새 봉인본과 인자 누락 — 수용

새 파일에 정준 계획·두 해시를 넣고 원본은 핀 판+표지 한 줄로 남기는 꼴을 수용한다. 도구로 후보 출력 **4파일을 두 번 재생성해 제출본과 바이트 동일**함을 확인했다. `maker:249,267,282,288,346`은 입력 신원·계획 꼴·두 계획·final 필수값·출력 파서 검사를 수행한다. chain:1145–1169의 원본 해시 공란 거부, :6654–6659의 사다리 선행 검사, :6880/:7347의 예측/합치기, :7715–7735의 최종 대조가 연결된다. census:943–1000은 지정 커밋의 등록·계획을 읽는다.

등록 경로를 명시한 sh 사슬 **13개+14개**, 각 문서의 S0 명령 **1개씩**을 따로 대조했다. 같은 명령을 독립 시험 수로 합산하지 않았다. `ledger --init`이 등록을 안 읽는 점과 누락 인자가 시도·폴더를 소비하는 점은 이미 한정되어 있다. 결과 수용 전 거부와 모든 단계의 무부작용은 다르다. 이번 작은 반례에서는 정직한 옛 경로·다른 계획·폴더 이동으로 틀린 결과를 받는 길을 찾지 못했다.

### Q2. 5M·168 h·8·112 h — 정책 후보로 조건부 수용, NOT_COMPUTED 방지 보증은 거부

산술은 위 표와 맞는다. **측정에서 유일하게 도출되는 필연값은 아니다.** 5M는 관측 한 점과 옛 시간비를 이용한 자원 선택이며, 미측정 DBE/R_j/origin의 반복 상한을 증명하지 않는다. 시간 한도가 먼저 걸릴 수도 있다. 따라서 “5M이면 결과 뒤 NOT_COMPUTED를 막는다”는 문장은 쓸 수 없다.

168 h는 명시한 보수 시나리오 일부를 덮고 결합 시나리오 193.6 h는 못 덮는다. 8회는 재시도 정책이다. **원장 차례로 처음 결과 전 멈춤이 아닌 시도를 채택**하는 규칙을 보존하면 좋은 결과를 골라 받는 횟수로 바뀌지 않는다. 112 h 역시 운영 여유값이며, 둘 다 넘으면 정지하고 1저자에게 돌아가는 규칙을 유지해야 한다.

기계 allowlist와 env_unit은 허용 범위 선언이다. 특히 v100은 이번 kgy/gabia 근거만으로 현장 자격이 생기지 않는다. Python/NumPy/SciPy 판 일치도 BLAS·SIMD·스레드 고정을 대신하지 않는다.

고칠 필요가 생기는 주장 문장: “등록된 시간·반복·시도 한도로 실행하며, 미수렴 또는 시간 초과는 등록한 실패/NOT_COMPUTED 규칙으로 남긴다. 관측 기반 예산은 완료 보증이 아니다.” 현재 문서의 추정 한정을 유지하면 새 수정 요구는 없다.

검토 고정물의 `12 / none / 2.0 / all3`는 **파서의 정상 경로를 확인한 시험 입력**이다. 실제 값의 선택·승인이 아니며 최종 계획에 복사하면 안 된다.

### Q4. 12 단위·원장·저장본·넘침 — 조건부 수용

2 법칙×2 c×3 R 역할의 12 단위는 고유 12개, 누락·중복 없이 배정된다(K:752–757). recover는 같은 부팅에서 부모의 종료가 확실해야 하고 다른 부팅/기계에는 별도 확인을 요구한다. 폴더 이동은 거부된다. 사슬과 송신 문서의 잠금 파일도 같다(chain:3164–3170,3383–3386; K:708). 단, 실제 Linux 경합·재부팅·두 기계는 이번에 실행하지 않았다.

캐시는 기계마다 새 빈 폴더를 사용하고 R 동안 바꾸지 않는 규칙을 유지한다(RS:789,809; K:806,809). 기존 1/2 계약 `codex_rebuttal1_fixes_README.md:109–113`의 BLAS·SIMD·스레드 환경 고정은 후보에도 남아 있다. `env_unit`/cache key가 이를 자동 인증하지 않는 것은 기존 경계다. 재부팅·새 셸에서 누가 어떤 기준 기록을 대조할지 실행 절차에서 그 계약을 직접 참조해야 한다. 환경이 달라지면 캐시를 임의 교체하여 계속하지 말고 정지 후 저자 처분을 받는다.

넘침 운영식의 실측 r는 모서리 SV 추가 풀이를 포함하므로 3판의 단일 팔 r보다 보수적으로 커질 수 있다(K:761). 이 한정은 이미 명시되어 있고, 112 h 양쪽 초과 시 자동 우회 대신 정지하므로 수용한다.

### Q5. 외부 참조·claims·q14 — 수용

3판을 복사하지 않고 고정 커밋+경로+blob/tree로 가리키는 방식은 수용한다. 실제 `b3481336c`의 README blob `8e4781ac4e89b5968e788ed21d486824ed3fcf45`, v3 tree `b07ecf38e1fa620b3b9e81fc51b0f282670cfb1f`를 확인했다. 최종 수령 위치에서 해당 객체를 읽을 수 있는지는 봉인 직전 확인한다.

claims 비교에서 주장 내용·상태 및 모든 비-ban 항목은 같다. 42개 패턴 중 두 항목의 allowed_in에 **11-13/11-16 S0 사본의 정확 경로만 추가**됐고 삭제·와일드카드 확대는 없다. candidate claims blob은 제출 stoic blob과 같다. q14 두 파일도 후보 blob과 첨부 바이트가 같다. 이 변경은 철회값의 새 과학적 채택이 아니다. 증거: `seal_form_review/logs/audit_pin_boundary.json`.

### Q6. 코드 핀 측정 승계·⑥ 재실행 생략 — 후보 범위에서 수용

코드 핀→후보는 A79/M4/D0이며 **원장에 명시된 풀이 경계 다섯 경로 전체**, CODE_FILES20, S0 일곱 파일의 변경이 없다. 단순히 scripts 몇 개만 확인한 것이 아니다. 측정의 소스 지문도 해당 핀에 귀속된다. 따라서 이 문서 봉인 방식 때문에 ⑥을 다시 재야 할 근거는 찾지 못했다.

이 승계는 준비비용·저장본·수치 구현 근거의 승계다. 탐침 결과를 R 보정·예측·판정값으로 쓰는 승인은 아니다(개발 원장:22,54,70–71). 최종 봉인 때 다섯 경계가 다시 같아야 한다. 이후 코드 변경이나 다른 실행 환경으로 무제한 승계하는 판정도 아니다.

### Q7. RCA-11 — 이 R의 선택 자유는 조건부로 닫을 수 있고, 전체 finding은 부분

u=0.14762508571060265/2=**0.07381254285530132 µm**, tol_ff=min(u,0.075 µm), tol_P=tol_sj=tol_ff, s_min=0 µm의 일치를 확인했다. 원입력 역할의 해시+S0 계획+최종 R 계획을 결속하면 같은 R에서 재표본화하거나 결과를 보고 s_min을 바꾸는 길은 닫힌다(R:72–76,99–107).

그러나 거리 0.18 µm, 반경 0.075 µm의 기존 반례에서 점 간격 0.10→0.02 µm로 바꾸면 u 0.05→0.01 µm, 연결 문턱 0.20→0.16 µm가 되어 분류가 달라지는 원리 자체가 사라지지 않는다. 고정은 물리적 표본화 독립성의 증명이 아니다.

따라서 RCA-11을 현재 `findings.json:12454–12461`의 넓은 범위 그대로 전부 verified로 올리는 것은 받지 않는다. **봉인 절차 부분만 한정 종결**, 전체는 부분/후속 관측 대기로 구분한다. 권고 문구: “이 R의 원입력 표본화·S0 계획·u/tol·s_min을 봉인하여 결과 뒤 재선택을 금지한다. 표본화 독립성·전체 면/SV 분류 동등성은 주장하지 않으며 등록한 DBE 기술 보고는 남긴다.” 원장 수정은 수행하지 않았다.

## 6. 알려진 한정의 처분

요청서 §10은 모두 그대로 남긴다. null 첫 실패만 보는 문제는 별도 정상 고정물·잘못된 tol/법칙/해시 음성으로 일부 보강했다. check-doc의 블록 동일성과 계획 바이트 동일성은 구분했다. 원장 init, 누락 인자의 시도 소비, 원본 한 줄 밀림, env_unit 선행 검사 위치, out/단위 배정 검사 범위, 참조 검사기의 commit:path 미지원은 수용 가능한 명시 한정이다. 후보 전체 gate/e2e/e2e12와 실제 현장은 독립 미실행이다. 기존 P3/RTR/RTRR의 지위도 변경하지 않는다.

두 알려진 사항은 전달 시 의미를 유지해야 한다.

1. **기존 R3-19**: 보조 `time_budget_v3.py:213–219`는 주 풀이 반복당 시간을 두 번 써 5M 주+이어 29.1/42.4 h를 출력한다. 이어 반복당 시간을 따로 쓰면 **29.7659/43.3396 h**이고 현재 본문 :709–714는 올바른 29.8/43.3 h다. 내부 리뷰 :156–158에 이미 있는 P3다. 새 finding으로 세지 않으며 이번 단일 풀이14.6/21.2 h·5M·168 h 선택을 바꾸지 않는다. 옛 helper 출력 재사용 시 현재 본문과 동기화해야 한다.
2. **넘침 r의 보수성**: 모형상 gabia 60.4 h인 점을 운영식이 112 h 초과로 판단할 수 있다. 문서가 이미 SV 몫 팽창을 한정했다. 완료 보증도, 배정 누락 없는 최적화도 아니다. 시간 내 가능한 점을 보수적으로 멈출 수 있음을 수용한 규칙으로 읽는다.

## 7. 최소 남은 조건과 GO 경계

**봉인 준비 조건**

1. 1저자가 네 값과 실제 봉인 날짜·가지·정책을 결과 전에 확정한다. 후보의 20261120/네 null은 최종 등록이 아니다. 점 수 등 시간 가정이 바뀌면 기존 모형으로 예산도 함께 갱신한다.
2. 확정 입력으로 도구 `--final`을 사용해 새 문서·계획·명령을 만들고, 두 계획/해시/등록 경로·원본 공란·고정 참조·풀이 코드 다섯 경계가 맞는지 최종 커밋에서 대조한다. 필요한 기존 봉인 관문은 실제 그 커밋의 영수증으로 남긴다. 이번 소형 시험이나 과거 506/506을 최종 트리 전체 게이트로 전용하지 않는다. 이번 리뷰가 새 전체 연구 계산 또는 무조건 전체 게이트 반복을 요구하는 것은 아니다.
3. “완료 보장 아님”, RCA-11 한정 종결, env_unit과 전체 실행 환경의 차이를 최종 수령 문구·실행 절차에 유지한다. 기존 환경 고정 계약의 기준 기록과 확인 담당을 명확히 한다. 연구 결과를 미리 열어 이 조건을 채우지 않는다.

**봉인 뒤 실제 실행 전 별도 조건**

실제 봉인 핀의 두 기계 수령·origin·venv/GPU/드라이버·필요한 조립 동일성, 현장 Git/잠금/넘김 자격, 새 빈 기계별 캐시, 감도 경로와 저자 실행 승인은 이번에 닫지 않았다. DBE 저장본 크기·gabia 실침대 C 속도 등 아직 없는 사실도 생기지 않았다. R 런·S0 단계 2 실행 명령을 이 리뷰에서 발사하지 않는다.
