# ADR 0002 — `.wrd` 를 직접 파싱한다

- 상태: 채택 (2026-08-20)
- 관련: `packages/wrdkit/nrbf.py`, `packages/wrdkit/wrd.py`,
  `docs/raw/specs/wrd-binary-format.md`

## 맥락

`.wrd` 는 공개 스펙이 없다. 선택지는 셋이었다.

1. Smart Interface 로 손수 CSV 내보내기 → 자동화의 반대. 애초의 문제.
2. .NET 런타임을 붙여 `BinaryFormatter` 로 역직렬화 → Windows/mono 의존이
   생기고, 애초에 파일의 99.9 % 인 데이터 블록은 NRBF 가 아니다.
3. 포맷을 해독해서 직접 읽는다.

## 결정

3번. MS-NRBF 중 **장비가 실제로 쓰는 레코드 타입만** 구현하고, 모르는 레코드는
조용히 넘기지 않고 `NrbfError` 를 던진다. 데이터 블록의 행 레이아웃은
**파일이 선언한 컬럼 목록에서 계산**하고 하드코딩하지 않는다.

## 결과

- 의존성이 numpy 하나다. 어디서든 돈다.
- 장비가 컬럼 구성을 바꿔도(온도 센서 추가 등) 파서가 따라간다.
- 148,493 행 0.37 s. 남는 바이트 0 으로 파일 끝까지 소비한다.
- 검증: 보고된 방전용량과 전류 적분값이 0.06 % 안에서 일치
  (사이클 5: 4.9114 vs 4.9085 mAh). 두 값은 파일 안에서 독립적으로 계산된
  경로이므로, 일치는 파싱 전 구간이 옳다는 강한 증거다.
- 대가: 못 본 `eFormat`/`eCtrlType` 값은 여전히 미지수다. 스펙 문서의
  "아직 모르는 것" 절에 적어 두고, 만나면 추가한다.

## 검증 방법

`packages/wrdkit/tests/synthetic.py` 가 스펙대로 `.wrd` 를 **쓴다**.
스펙이 틀리면 라운드트립 테스트가 깨진다. 20 MB 실측 파일을 저장소에 넣지 않고도
전 경로가 검증된다.
