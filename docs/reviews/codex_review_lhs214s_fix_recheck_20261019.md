### 3-2. L214S-CX01 [P3] — 빈 ATX 제목 뒤의 값을 활성 등록으로 받아들임

**결론 영향:** “지원 범위 내 R03 전체 종결”이 무너진다. 현재 실제 등록값 오독, 수치 계산 오류, 발사 승인 우회가 실측됐다는 뜻은 아니다. 이전 핀에도 있는 결함이며 이번 패치의 회귀는 아니다.

문제 자리: **`scripts/supp20_input_receipt.py:108`**, 경계 소비 `:160–168`, 값 추출 `:182–194`.

```python
_MD_HEADING = re.compile(r'^(#{1,6})[ \t]+(\S.*?)[ \t]*$')
```

이 식은 `#` 마커 뒤 공백과 비공백 제목 내용을 모두 요구한다. 그러나 0열의 `##` 자체도 유효한 빈 2단계 제목이다. 새 1·2단계 제목은 활성 2단계 절을 끝내야 한다. 이는 요청서가 지원한다고 정한 **0열 ATX 제목** 안의 문제다. [CommonMark 0.31.2 §4.2](https://spec.commonmark.org/0.31.2/#atx-headings)

실제 등록 문서의 다른 조건을 유지한 고립 사본에서 이전 활성 §3을 비활성 번호로 바꾸고 대기 선언을 제거한 뒤, 아래를 넣었다.

```markdown
## 3. Active section without a value

##

`code_fp 2149f8738bb20b6a311b3c5b344b9745271a3f1324cabfb4582c175c3983c3eb`
```

독립 Markdown 파서는 마지막 값을 **§3 밖**으로 분류한다. 현재 실제 `receipt()`는 **rc0, `bad=[]`**, 그 값을 활성 지문으로 받아들인다. 단순 helper 출력이 아니라 전체 영수증의 반례다.

| 새 경계 시험 | 결과 |
|---|---|
| h1/h2 × 줄끝·space·tab·space+tab·space+NBSP·space+U+2003 | **12/12 잘못 수용** |
| 정상 활성 값 → 빈 h1/h2 → 다른 역사 값 | **2/2 잘못 거부** (`code_fp=None`, R0/D1) |
| 이름 있는 경계·코드 블록 값·정상 활성 값 등 대조 | **5/5 기대대로** |

Unicode 두 형태는 제목이 완전히 비었다는 주장 대신, `\S`로 제목 내용을 제한한 같은 정규식의 추가 사각으로 구분한다. 핵심 반례에는 plain `##` 하나면 충분하다.

**최소 해결:** 활성 “§3” 식별과 일반 절 경계 인식을 분리하고, 지원하는 0열 ATX 경계의 빈 제목도 인식한다. 지원하지 않을 형태라면 묵살하지 말고 문서를 명시적으로 거부해야 한다. 다만 정상 활성 값 뒤의 빈 경계와 역사 값은 정상 등록으로 보존하는 쪽이 원래 계약에 맞다. 위 양방향 반례와 기존 114 문서·코드 블록 값을 상주 시험으로 남긴다. 소스는 수정하지 않았다.

재현: `python -X utf8 -B probes/s01_parser_audit.py all`. 대표 입력 `evidence/s01_new_cases/h2_empty.md`; 결과 `evidence/s01_receipt_h2_empty.json`; 전체 `s01_heading_boundary_cases.json`. 독립 oracle은 markdown-it-py 3.0.0의 commonmark preset이다. 울타리 조합은 [CommonMark §4.5](https://spec.commonmark.org/0.31.2/#fenced-code-blocks)와 대조했다.

### 4-2. 남은 P3 — 고정 기하에서 목표 q가 건너뛰어짐

`scripts/test_l214r_r01_restored_full.py:66–72`의 고정 면적 `.500000001`, `box_x=.7281737983374794`에서 `:259–278`은 `box_y` 하나만 이동한다. 목표는 `nextafter(1.5, −∞) = 1.4999999999999998`이다.

실제 생산 함수로 계산한 인접 입력:

| `box_y` | raw q |
|---:|---:|
| 0.7281737983374861 | 1.5000000000000002 |
| 0.7281737983374862 | 1.5 |
| 0.7281737983374863 | 1.5 |
| 0.7281737983374864 | 1.4999999999999996 |

마지막 두 입력은 인접한 double이다. 그 사이에 목표 `1.4999999999999998`을 만드는 입력이 없다. 탐색은 512 한도를 다 써서가 아니라 **18번째의 목표 통과**로 멈춘다. 고정 입력 주변 ±512 ULP, **1,025개 box_y 입력의 실제 생산 함수 평가**를 독립 식으로 읽어도 q는 비증가하고 `prev`를 한 번도 만나지 않는다. 해당 구간에서 `I_bottom`도 일정하다. 따라서 **탐색 상한만 올리는 것으로 이 건을 해결할 수 없다**. 모든 환경·모든 기하에서 불가능하다는 주장은 아니다.

현재 실패 처리 `:327–332`, `:345–348`은 정직하다. 이 실패가 생산 정책 `q > 1.5`의 오류를 뜻하지 않는다. 생산 상수·엄격 비교와 소비자 비교는 바이트 그대로다 (`network_conductivity.py:171,1471`, `tau_flux.py:807`).

### 4-3. 닫힌 부분과 탐색 방식의 정당성

- `restore()` `:123–129`: 없는 `q_withheld`에 설명 있는 예외, 레코드 무변경.
- `:309–317`: E3 전제 실패 시 E4 복원하지 않음.
- `:365–384`, `:568–573`: E5 독립 실행. 실제 E0 실패 및 별도 예외 주입에도 E5가 수행됨.
- 독립 3노드 증서: prev/equal 수용, next/2.0 거부.

raw q가 정확한 입력을 찾은 뒤 고정 정책을 시험하는 것은 **경계 픽스처 구성으로는 타당**하다. 그러나 솔버의 정확도를 독립 검증하는 시험은 아니다. E1은 주로 선택한 전제를 재확인하면서 보류 q(`q_withheld`)도 대조하고, E2–E5가 정책을 공격한다.

이 구분을 확인하기 위해 과거 독립 탐침의 면적 `.500000001001`을 사용한 **진단용 양성 대조**를 별도로 돌렸다. 그 기하에서는 세 목표가 모두 정확히 나오고 원래 E1–E4가 통과한다. 이는 제출 원본 30/30의 대용이 아니다. 해당 대조에서 다음 변이도 실제 발화했다.

| 탐침 프로세스 안에서만 바꾼 정책 | 잡힌 검사 |
|---|---|
| 생산 `>`를 `>=`로 변경 | E2·E4 |
| 반올림 q로 생산 비교 | E1·E3·E4 |
| 생산 가드 제거 | E1·E2·E3·E4 |
| 소비자 가드 제거 | E4·E5 |

진단 기하에서는 ±18·±64·±512 출발 모두 회복하고, 범위 밖 ±513은 못 찾는 경우를 명시 실패한다. 따라서 탐색이 이 네 정책 결함을 숨기는 구조는 아니다. 독립 탐침 **32/32**에는 “제출 원본이 전제 실패해야 함”이라는 검사도 포함되며, 이것 역시 제출 시험 30/30을 의미하지 않는다.

**최소 해결:** 독립 3노드 시험과 명시적 탐색 실패를 유지한다. 실사슬에서 세 exact 값을 반드시 얻어야 한다면 공개된 유한 탐색으로 두 번째 기하 자유도까지 사용하고 전제를 검증한다. 또는 정확 경계 보증의 주체를 독립 3노드 시험으로 명시하고 실사슬 시험의 보증을 구분한다. 등록 입력을 조용히 다시 맞추거나 비교 허용 폭·생산 문턱을 늘리지 않는다. 실제 지원 환경의 원본 시험 로그로 닫는다.

남기는 한정:

1. **S05 유지:** 정상 입력 중 `percolation_pct`만 null로 바꾸면 loader 뒤 전체 GET은 두 핀 모두 500. `single.html:29`의 머리 배지가 null을 `%.1f`로 형식화한다. 세 툴팁보다 먼저 죽는 별도 경로다. 다음 세대 P3로 분리하는 데 동의한다.
2. `is number`는 유한 실수 검사가 아니다. bool·NaN·inf를 받아들이는 기존 동작은 남는다. NaN/inf 대조는 Python JSON 확장이지 표준 JSON이라고 주장하지 않는다. 새 회귀나 새 P2로 올리지 않는다.
3. 누락된 보조 인자 전부를 `—`로 만드는 변경은 아니다. f_perc=1, 식의 τ=1 및 뒤쪽 τ 표기=0 같은 기존 누락값 설명 규약을 null에도 적용한다. 이 설명 인자와 실제 제공된 `sigma_ratio`가 독립적으로 일치한다고 인증하지 않는다.
4. 정상 생산자는 `sigma_ratio=None`이면 키 자체를 생략한다 (`scripts/analyze_contacts.py:649–650`). 이번 null 반례는 과거·외부 입력의 강건성 문제이며 정상 생산물 오염의 증거로 확대하지 않는다.
5. 실제 Flask 응답과 툴팁 문자열을 검증했다. 브라우저의 JavaScript 이벤트·what-if 실행까지 시험한 것은 아니다.

새 시험은 `scripts/check_all.sh:222`에 배선됐다. CI는 별도의 inventory 실행 경로이며 새 no-flag 시험의 포함은 확인되지 않는다. 요청이 약속한 **check_all 배선**은 성립하고, “CI도 포함”이라고 덧붙이면 안 된다.

영수증의 Git 메타데이터 어댑터는 저장소 부재/검토 핀을 기록하는 용도로만 사용했다. 실제 등록 대조의 어댑터는 git 정보를 None으로, S01의 고립 탐침은 검토 핀과 합성 `dirty=False`를 제공한다. 후자는 판정 뒤에 기록되는 메타데이터이며 **실제 clean working tree나 발사 승인 증거가 아니다**. 원본·수정 스냅샷은 검증 종료 시 manifest와 다시 대조했다. 반례 변경은 고립된 입력 사본 또는 프로세스 안에서만 수행했다.

실행 격리의 한정도 남긴다. 일부 시험의 app import가 스냅샷 안에 빈 uploads/results/archive/mpm_lab 디렉터리를 만들었다. 검토 소스 파일 바이트 변경은 없지만 “소스 폴더에 어떤 생성도 없었다”는 뜻은 아니다. 재현 README에는 이 네 경로와 캐시를 리뷰 `tmp/`로 보내는 환경 설정을 명시했다. ZIP에는 manifest에 없는 소스측 런타임 파일을 넣지 않는다.
