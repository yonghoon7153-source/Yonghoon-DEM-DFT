# S1-O 발송문 명확화 부속안

2026-10-07. 원문 b54d77218d67faf3258908fb2ff5f4f5972e0cd2 / SHA256 0fff3e1fffe29b7e448c5f61ea4c9464cbb59691d2a301ee2089ee9a54e47127에 붙일 검토자 제안이다. **새 실행 승인문이나 실제 approval 파일이 아니다.** 원문·사용자 승인 인용은 수정하지 않는다. 원 승인보다 넓은 구현·시험·계산 권한을 만들지 않는다.

## 1. §2 항목 3 — 비활성 구현의 의미

실행 연결의 소스와 계약을 작성하되, 이번에는 저장·정적 확인만 한다. 소스는 활성 경로 밖의 비활성 텍스트 등으로 보관하고 후보 실행/import/컴파일/기능 시험을 하지 않는다. 파일명이나 경고 주석만을 실행 차단 근거로 삼지 않는다.

미래 실행 설계는 같은 manifest에 결속한 검증 수용 및 별도 native 승인 없이는 COMSOL 시작·실제 runtime 쓰기 전에 거부하도록 작성한다. 실제 approval/release/token/runtime/USER_DECISION은 생성하지 않는다. 샘플이 필요하면 fixture임을 명시한 비활성 텍스트만 사용한다.

공유 의존 파일과 새 파일, 엔진 식별 범위, run/variant, σ·초기조건·시간창, argv/cwd·입출력·승인 경로, 횟수·자원·시간 상한을 승인 단위에 연결한다. 실행 기기에서만 확인할 수 있는 값은 미관측으로 둔다. “소스 작성 완료”, “검증 미실행”, “native 미승인”을 각각 기록한다. 후속 활성화에 바이트 변경이 있으면 새 식별 및 필요한 변경부 검증·승인을 먼저 확정한다.

## 2. §2 항목 1·2 — readback 단계

- 구성 후 solve 전: 설정값·단위·영역·확인 가능한 생성식/계수 연결을 기록하고 불일치 시 다음 단계로 가지 않는다.
- 일관 초기화의 명시한 t=0 또는 0+: 전극별 평균/표면 조성·고체/전해질 재고와 σ별 전위/전류를 기록한다. 같은 농도·재고 목표와 σ에 따라 달라질 대수 전위를 구분한다.
- 완료 후: 실제 시각·저장·guard·결과·외부 종료 증거를 기록한다.

설정 readback과 실제 유효 계수 소비의 증거 등급은 다르다. 설치본 변수/API·초기화 시점이 미확인인 것은 OPEN으로 남긴다. 별도 초기화/solve가 필요한 경우 호출 수·시간·승인 영향을 명시하며, 기존 1회 solve에 숨겨 넣지 않는다. 오프라인 계약 작성으로 실제 초기화 통과를 주장하지 않는다.

## 3. §2 항목 6 — near-zero 수지와 부호

절대·상대 허용오차 외에 부호 판정의 절대 deadband를 명시한다. t=0의 q=0, near-zero의 분해 불가능한 농도/전하 변화는 엄격한 양수·단조 감소/증가의 실패로 세지 않는다. 다만 허용 범위를 넘는 역방향 수지와 신호 분해능 부족은 별도 상태로 남긴다. 분해능 부족을 임의로 PASS로 바꾸거나 허용오차를 결과에 맞춰 넓히지 않는다.

j·RN/RP [A/m²], I [A], 면적당 q [C/m²] 또는 총 q [C]의 변환을 고정한다. qI의 적분 격자·기법·오차 판정을 명시하여 출력 성김에 따른 적분 오차와 Li 수지 오류를 구분한다. 실제 허용 수치는 S1-O에서 근거와 함께 제안하고 주 결과 전에 고정한다.

## 4. §2 항목 7 — 감시와 소유 종료

“terminate → grace → kill” 대신 지원 확인된 협조적 중지 요청 → 정해진 대기 → 남은 소유 Job의 강제 종료 → root/Job 잔여 종료 확인으로 정의한다. 협조적 수단이 없으면 없다고 기록하고 강제 종료 경로를 별도 제안한다. hard cap을 넘길 수 있는 대기나 무관한 프로세스 일괄 종료 fallback은 없다. 대기·종료·확인·기록도 기존 상한 안에 포함한다.

counter·단위·root/자식/Job 집계 범위·샘플 주기·탐지 지연, sampled_max와 OS peak/강제 상한, 디스크 증가 범위와 최소 여유를 구분한다. 샘플/기록/소유 증명 실패는 값0/PASS가 아니다. 실제 API·소유 증거와 검증 필요 부분을 다음 변경부 검증안에 적되 이번에는 실행하지 않는다.

## 5. 나머지 산출물의 수용 조건

- K에는 D_k/S_k를 위한 동일 설정의 near-zero 대조를 포함한다. 공유 가능한 실행은 중복 집계하지 않고, 설정이 다른 기준을 임의 재사용하지 않는다.
- 300초 이후 cap 해소안은 창·σ·설정·실행 수·M/N과의 순서/재사용을 적는다. P≤4에 숨은 추가 계산이 없다. 짧은 후기 검사로 2700–3600초 기울기를 검증했다고 하지 않는다.
- pilot 비용의 외삽 가정·안전 여유·불확실성을 적는다. 모든 σ/격자/후기 비용을 실측한 것으로 부르지 않는다.
- OCV 사전 예측·평균 조성 OCV·단자전압·paired D를 구분한다. 예측에 맞추기 위한 σ/OCP 수정은 하지 않는다.
- 후속 검증안은 실제 대상 함수·엔진·사례·정확한 거부 이유·도달 단계·횟수·상한을 적는다. 독립 모형의 통과를 실제 parent/consumer 통과로 대체하지 않는다.
- 전체3,600초·단계별 원 상한을 유지하고 미완 종결 시간을 먼저 남긴다. 마지막 수정 후 정적 확인, manifest 자기참조 제외, 선택 원본 전후 같은 집합 비교, 포장/readback/snapshot/반환의 시간 경계를 기록한다.
- S1-O의 done/partial/open은 오프라인 산출물 상태다. 실제 초기화·정책·수치·자원 PASS가 아니며 native_ready=false를 유지한다. 검증 실행 및 P/M/N은 모두 별도 승인이다.
