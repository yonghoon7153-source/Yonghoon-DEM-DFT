# Q12 조립 기록 수집 연결 — 구현 전 계약

## 1. 고정 지위

바탕 fa8bbe954f3d1897c9cfc9572a7babf029b8f743의 docs/reviews/rint2_q12_registration_draft_20261114/q12_preregistration.md §3–5를 연결한다. 실행 소스64e4d213e8267bafaf3ae5af00a42996cefd3f33 및 기존 S0/Q11/⑥ 블록 변경0. 실제 조립·값·σ·현장 실행0. 새 수집기 구현0·전체 HOLD.

권고안 전제 Q12-PREP-1(양쪽 실제 원DOF 순서 명시)은 새 등록 초안이며 실제 등록 동결 때 확인한다. 1저자가 비준한 환경 밖 열쇠 정책과 6slot 계획은 유지한다.

## 2. 연결 지점과 소유권

| 순서 | 입력→출력 | 반드시 묶을 것 |
|---|---|---|
| 1 | 동결 등록+6slot+환경 선언→시도 envelope | 등록digest·code pin·입력사슬·환경·slot·mode·attempt, 누락이면 시작 전 보류 |
| 2 | 해당 시도의 조립 완료 객체→기록 | graph/CSR/RHS/판 결합/원DOF를 같은 완료 객체와 같은 시점에서 얻음 |
| 3 | assembly_record→원형 record | descriptor·complete·reason 보존, 지문을 다른 시도에서 가져오지 않음 |
| 4 | 기록+출처→수령 사본 | schema/version·record hash·원 실행rc/완료·원본참조, 파일명으로 결속 대체 금지 |
| 5 | 두 수령 사본→compare 출력 | comparable와 graph_equal/bytes_equal·claims·why 전부 보존 |
| 6 | 고정 등록 대조→개발 관측 줄 | 누락 쌍 분모 유지, 실제 실행/풀이 자격으로 승격 금지 |

아직 연결할 함수/호출 지점·기록 수집 모드·소유 객체 수명·동시 변경 차단은 미정이다. 한 배열의 descriptor를 읽는 동안 다른 배열이 바뀌면 같은 시도 기록이 아니다. immutable snapshot/호출 구간 소유권 중 어떤 방법을 쓸지는 합성 연결 시험과 비용표를 보고 결정한다. 배열을 임의 정렬/재합산/형변환하여 두 환경의 원 출력을 같게 만들지 않는다. 기존 DOF ids의 int64 규약은 원 ID 배열dtype 보증으로 확대하지 않는다.

Q-A는 같은 환경의 독립 건설 대 저장본 경로, Q12는 서로 다른 지원 환경 대조다. 같은 저장본을 두 번 읽고 Q-A 독립 건설 또는 두환경 조립으로 표시하면 부적격이다. 실제 전체 source/환경/입력 결속이 없는 예제 record는 개발 합성으로만 남긴다.

## 3. 먼저 만들 시험 — 미실행10행

| ID | 작은 반례 | 기대 |
|---|---|---|
| CAP01 | 두 attempt의 graph와 CSR 섞음 | 출처 결속 거부 |
| CAP02 | 조립은 미완료인데 complete만 true | 실행 완료 증거 없음으로 보류 |
| CAP03 | CSR 기록 뒤 RHS를 바꾸고 같은 snapshot으로 제출 | 수집 일관성 거부 |
| CAP04 | 두 record의 source/input/등록 revision 다름 | 같은 비교쌍으로 채택 거부 |
| CAP05 | 원DOF 한쪽 누락 | 기존 도구 why 보존+새 등록 바이트 주장 보류 |
| CAP06 | 비교 rc0이지만 bytes_equal=false | 바이트 같음 주장 없음 |
| CAP07 | graph-only 기록 두 개가 같음 | graph 주장만, assembly 주장 없음 |
| CAP08 | 6쌍 중 한 쌍 누락 | 분모6 유지·전체완료 아님 |
| CAP09 | 같은 저장본을 독립 조립으로 이름만 변경 | Q-A 독립성 미충족 |
| CAP10 | 파일 쓰기 실패 뒤 이전 attempt 파일 발견 | 새 기록 미수령, 예전 파일 채택 금지 |

위 기대는 수집기 구현 전 시험 설계이며 기존 comparator의 실패/결함 판정이 아니다. CAP10은 RTR-01에서 확인한 시도 귀속 원칙을 새 문서에 적용한 것일 뿐 기존 audit 코드 재수정이 아니다. 실제 신뢰한 실행에서 어떤 출처 증거가 나오는지는 연결 구현 전 고정해야 한다. 자체 hash만으로 진위를 인증하지 않는다.

## 4. 다음 고정할 항목

수집 함수 핀/모드, 원객체 소유권, 필드별 추출 출처, 실패 시 output 부재와 재사용 금지, 저장본/독립 건설 독립성, 원본 보관/접근 범위, 추가메모리/시간 비용은 모두 null이다. 새 구현이 필요하면 작은 expected-correct 시험부터 작성하고 고정 핀·사전 공격·독립 반박 뒤 기존 최종 핀 재확인 범위에 준 영향을 기록한다. 이번 준비로 소스64e4d213e를 바꾸거나 시도3·4/S0/Q11 GO를 추가하지 않는다.
