## §5 남은 기록 계획

배포 v1.3 계획 §2b의 세 수확 폴더에서 케이스 파일명만 확인하고, 코호트 명부에서 각 ID가 한 번씩 나타나는지 대조했다. 아래 ‘확인’은 이번 정본 반환으로 검산한 수다.

| 기록 | 기대 명부 | 확인 | 추가 근거가 필요한 명부 |
|---|---|---:|---|
| lhs | lhs00_000–129, 130건 | 30 | lhs00_000–099, 100건 |
| lhsx | lhsx_001–064, 64건 | 0 | 같은 64건 |
| lhss | lhss_001–020, 20건 | 0 | 같은 20건 |
| 합계 | 고유 214건 | 30 | 184건 |

1. **남은 184건의 출처부터.** 자료 담당자는 기존 메타 영수증이 있는지 확인한다. 각 케이스의 정본 후보·화면 사본·실행/재개 구간·현재 덱과 수확 덱 지문·하베스트 step/atom 지문을 값 없이 대조한다. 이번 WSL30에서 선택한 파일 역할은 나머지에 자동 적용하지 않는다. 실제 원본 재고 조회가 필요하면 담당·범위를 적어 1저자에게 메타 조회 GO를 요청한다.
2. **명부 동결과 별도 값 GO.** 세 묶음별로 출처가 입증된 구간·끝점·필드를 값 열람 전에 고정한다. 여러 로그가 별개 구간이면 순서·겹침 규칙이 확정될 때까지 해당 행을 보류한다. 그 뒤 승인 범위에서 기존 B7로 같은 마지막 가압 기준을 적용해 OK·NOT_REACHED·REFUSED·출처 보류와 사유를 전 행에 보존한다. WSL30은 이번 반환 영수증을 재사용한다.
3. **§5 전체 대조.** 검증한 행을 코드로 케이스 ID에 결속해 정식 lhs 130행·lhsx 64행·lhss 20행 기록을 구성하고, 수확 덱 SHA·정본 지문·스키마·누락·중복·목표 도달을 다시 점검한다. 과거 214건 REFUSED 보고는 이력으로 유지한다. 하나라도 미도달·거부·출처 미확정이거나 명부가 다르면 해당 사유를 보고하고 단계 A를 보류한다.
4. **그 뒤 τ와 v1.3.** §5를 검토한 다음 τ 출처·상태의 판독 여부를 결정한다. production194·supp20의 봉인·재판독, 인계표와 전달본 검토 및 v1.3 생성·배포는 별도 결정이다.
