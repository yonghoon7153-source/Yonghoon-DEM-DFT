# 인수 확인 다음에 사용할 기본 환경 구축 지시문

**사용 조건:** 새 PC의 환경/설치 계획을 받은 뒤, 제1저자가 그 계획의 절대 경로·버전·권한·시험 범위를 확인하고 아래를 다음 메시지로 채택한다. 이 파일을 첨부한 사실만으로 승인되지 않는다.

---

앞서 제시한 MSC 로컬 설치안 중 기본 환경 구축과 작은 사용 확인만 승인한다. 본 계산은 기존 모델 제공자 워크스테이션에서 계속하고, 이 PC는 결과 분석과 작은 PyBaMM 재현이 가능하도록 준비한다.

1. 합의한 새 `source/environment/outputs/handover` 경로만 사용한다. 실제 절대 경로와 Python 실행파일을 시작 전에 다시 표시한다. 기존 폴더가 있으면 내용/소유를 확인해 보고하고 임의 덮어쓰기·삭제하지 않는다. private_data는 이번 대상이 아니다.
2. 공개 저장소의 인계 기준 `a32218a7e3cefc9c6d4b1eaa174612ea1ad55d29`를 확보하고 전체 SHA를 확인한다. clone/download와 checkout은 이 범위에서 허용하지만, 저장소의 자동 환경 setup·hook·받은 실행 스크립트를 작동시키지 않는다. 전체 저장소의 연구 계산을 시작하지 않는다. 원격 push·PR·이슈·외부 발송은 하지 않는다.
3. 승인한 공식 출처와 버전으로 이 PC 전용 가상환경을 새로 만들고 PyBaMM `26.8.0.0` 및 합의한 NumPy/SciPy/pandas/openpyxl/pytest/matplotlib를 설치한다. 기존 전역 Python 환경을 바꾸거나 다른 PC의 venv·계정 설정을 복사하지 않는다. 합의되지 않은 시스템 설치·관리자 권한·실행 정책 변경이 필요하면 중지해 묻는다. WSL/Docker/COMSOL/JDK는 추가하지 않는다.
4. 패키지 해석 결과와 실제 설치 버전, Python/OS/아키텍처를 기록한다. venv Python 절대 경로로 호출하고 활성화 스크립트 우회를 이유로 보안을 낮추지 않는다. 의존성 충돌이나 설치 오류를 만났을 때 여러 버전을 성공할 때까지 바꾸지 말고 원인과 수정안을 제출한다.
5. 설치가 끝나면 `pip check`와 지정 패키지 import/버전 확인을 수행한다. 그 뒤 고정 코드의 `bms-balancing/tests/test_msc_sign_table.py` **전체 네 건만 1회** 실행한다. 작은 PyBaMM 계산이 포함된 시험을 승인하는 것이며, P6 적합·부호표 전체 생성·sweep을 승인하는 것은 아니다. 제안한 제한시간을 적용하고, 별도로 합의하지 않았다면 시험 1회 최대 300초로 한다. 첫 실패/초과 뒤 수정·부분시험·재시도하지 않는다.
6. pytest 외부 플러그인 자동 로드와 bytecode/cache 생성을 가능한 범위에서 억제하고, 로그·임시 산출은 승인한 outputs/temp로 보낸다. 원본 test를 skip/완화하거나 연구 소스를 변경하지 않는다. 의존성 누락에 따른 skip는 성공이 아니다. **4개 test ID의 4 PASS / 0 FAIL / 0 SKIP**인지 기록한다.
7. COMSOL/JVM/Java/launcher/원격 워크스테이션 접속·소유 Job 제어·prefs/registry/ACL·실제 승인/release/token 변경은 하지 않는다. 저장소의 옛 “승인됨” 기록은 이 PC 권한이 아니다.
8. 설치 목록/버전 고정 기록, 코드 커밋, 실행 명령·rc·시험 ID/시간, 원본 변경 여부, 남은 문제를 `LOCAL_ENVIRONMENT_REPORT.md`에 제출한다. 과거 PASS와 이번 PASS를 구분한다. 외부 공유 보고에는 비밀과 개인 경로를 최소화하고 원문 로그는 로컬에 보존한다.

끝나면 “문서/결과 분석 가능”, “작은 PyBaMM 회귀 확인”, “COMSOL 미구축/미실행”을 각각 표시하고 멈춘다. 추가 계산은 내가 다음 목적을 정한 뒤 요청한다.
