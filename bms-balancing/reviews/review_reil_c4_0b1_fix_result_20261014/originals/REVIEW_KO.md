## 2. 남는 P2 한 건

### C4-0B1-N1 잔여: 옵션 경고 중지 전에 받은 반환값이 partial에 없다

위치: `bms-balancing/scripts/reil_c4_h.py:788–791`. 관련 구간은 `736–747`, `779–780`, `797–799`이다.

1. `779–780`에서 최적화기가 정상 반환하면 `res`에는 반환점·status·message 등이 이미 있다.
2. `788–791`은 Unknown solver options 경고를 확인해 구조 중지한다.
3. 반환점과 상태를 `row`에 옮기는 것은 그보다 뒤인 `797–799`다.
4. `_partial`은 `acc.row`·계수·경고만 복사한다. `res`는 누적기에 없으므로 이 경고 경로의 partial에는 이미 얻은 `x/status/message/termination`이 남지 않는다.

승인 요청문 §2, 24행은 **“반환점이 있으면 x · status · message · termination”** 보존을 명시한다. 현재의 새 `test_n1_b`(113–123행)는 평가 수·비유한 수·경고·stop_error·task_id만 확인한다. 따라서 66 PASS와 이 누락은 양립한다.

이 경로는 이미 구조 중지하므로 잘못된 성공이나 실자료 수치 오류를 발견했다는 뜻은 아니다. 다만 이미 확보한 결과를 잃는 실패 기록 문제는 N1의 종결 조건에 남는다. 본 검토는 소스 순서로 확인한 정적 반례이며 새 실행/traceback 재현을 주장하지 않는다.

**한정 닫힘 조건**

- 정상 반환한 결과가 있으면 경고 중지 전 그때 확보한 반환 필드를 partial에 결속한다. 중지 이유는 OptimizeWarning으로 유지하고, 재평가·증인 생성·정상 완료로 진행하지 않는다.
- 반환이 없으면 x/status/termination 등을 성공값이나 0으로 채우지 않는다. 기록 보강이 원래 오류를 덮거나 새로운 정상 판정을 만들지 않게 한다.
- 경고와 알려진 정상 반환을 함께 주는 대조에서 반환 필드·계수·경고·중지 오류의 보존 및 재평가 미진입을 단언한다. 같은 경로의 무경고 양성 및 반환이 없는 오류 대조도 구분한다. worker→supervisor에서 보존된 partial이 그대로 남는지 연결한다.
- 생산 변경 파일·대조·정확한 실행 횟수·예산을 먼저 고정해 별도 사용자 승인을 받는다. 기존 66 PASS와 실패 원문은 보존한다. 전체 suite·배열 재봉인·실자료 실행을 기본 요구로 확대하지 않는다.

## 3. 수용하는 보완

**N1의 핵심 반례는 해소됐다.** `acc`에 행·평가/비유한 계수·경고를 연결하고 `_partial`로 보낸다. `test_n1_a`의 실제 fork worker 대조는 NaN 두 번 뒤 MemoryError에 대해 STARTED_INTERRUPTED, 평가 3/비유한 2, 원 오류와 소유 worker 종료를 확인한다. `n1_d`는 같은 경로 정상 대조이며 `n1_c`는 이후 wrapper 오류의 행 보존을 확인한다. 단, RSS/disk는 시험 대역값이므로 OS 자원 관측 증거가 아니다.

**N2는 닫는다.** H 635–638행은 기존 C5 분류를 사용하고, 798–804행은 원 status/message/x를 기록한 뒤 unclassified를 구조 중지한다. 재평가는 809행 이후다. 새 시험 151–190행은 알려진 오류 enum·999·성공 아닌 status 0, 성공/예산 양성, 재평가 미진입, 실제 worker의 전역 중지를 나눠 확인한다.

**N3는 닫는다.** H 626–631행과 810–817행은 지역 재평가 예외를 REEVAL_ERROR로, 정상 NaN 반환을 NONFINITE로 분리한다. 구조 재평가 오류는 전체 중지하고 원 termination을 보존한다. 855행 집계 및 새 시험 194–226행이 이를 연결한다.

**A1 처리는 수용한다.** 상태 문서 §48(1008–1018행)은 이전 05 합성 20회를 사전 승인 없는 실행으로 유지하고 원 결과와 로그를 보존한다. §49의 승인은 이번 이후의 보완에 대한 것이며 과거 권한을 소급하지 않는다.

향후 `dryrun`은 PLAN.json만 쓰고, 최적화·목적 평가·util import·Sobol 생성 경로를 제거했다. H 422–461행의 바이트 모드는 수용된 외부 MANIFEST SHA에 대해 정확 파일 집합·바이트·P0·계획/label/seed·RULES·NPY dtype/차원/행 수·INDEX의 블록 SHA를 대조한다. 재생성 검증은 하지 않으며 `mode=bytes`, `regenerated_match=null`로 구분한다. 새 시험 a1_a/b/c는 호출 금지 대조, NPY+manifest 항목 변조, 정상 봉인을 각각 다룬다. 가짜 identity를 사용한 함수 시험과 별도 실제 identity 관측을 혼동하지 않는다.
