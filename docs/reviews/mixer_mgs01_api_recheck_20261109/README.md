# MGS-01 직접 API 문자열 하위형 수정 후보 — 2026-11-09

**P3 한정 수정 후보 · 독립 재확인 대기 · 실제 연구 결과 0건 · 전체 HOLD.** 일반 내장 정수·문자열과 CLI에 대한 앞선 생성기 seed 보강의 한정 수용을 보존하고, `deck()` 직접 API에 전달한 사용자 정의 문자열 하위형에서 남은 MGS-01만 다룬다. 이 작업은 실제 연구 실행·호스트·원자료/값 열람·운영 봉인·원장·실행 GO를 변경하지 않는다.

## 신원과 판정 범위

| 역할 | 고정 핀 또는 기록 |

원 독립 판정은 일반 내장 `int`/`str`·CLI의 삽입 seed 검사, 지정 양성 바이트와 CLI 정규화, 소비자/변조 fixture 보존 및 기존 시험 기록을 한정 수용했다. **새 P1/P2는 없고 직접 API의 MGS-01/P3 한 건이 남았다.** 호출자가 실행 가능한 `__int__` 메서드를 가진 `str` 하위형 객체를 직접 넘기는 경우다. 일반 문자열·CLI의 텍스트 주입이나 운영 제출 우회로 확대하지 않는다. 이번 수정 후보를 아직 독립 수용된 것으로 쓰지 않는다.

외부 원 판정·증거 ZIP은 리포에 그대로 반입하지 않는다. `receipt.json`의 신원과 범위, 후보의 최소 변경 및 로컬 합성 근거를 구분한다. 앞선 seed 검토 문서는 당시 기록으로 보존하고 새 P3의 상태는 이 폴더에 따로 적는다.

## 최소 변경

`scripts/make_mixer_deck.py`의 `_insert_seed`는 정수에 `type(value) is int`를 요구하지만 원 문자열 분기는 `isinstance(value, str)`였다. 표기가 유효하고 짧은 하위형이 `__int__`에서 `2147483659`를 반환하면 변환 후 상한을 다시 검사하지 않아 상한 `2147483647`보다 큰 소수가 출력될 수 있었다. 소비자는 그 덱을 범위 초과로 거부하므로 이 반례가 소비자 승인이나 실행 허가를 만든 것은 아니다.

후보는 문자열 분기 한 조건을 **`type(value) is str`**로 제한한다. 내장 정수의 기존 exact-type 정책과 맞추며 사용자 정의 문자열 하위형의 정수 변환 메서드를 호출하는 경로 자체를 받지 않는다. 표기·범위·소수·층상 파생 seed 규칙이나 정상 seed 값을 대신 바꾸지 않는다. 지원하지 않는 입력이라는 문서만 추가하고 기존 부적격 출력 경로를 남기는 대응이 아니다.

보존할 경계는 다음과 같다.

- 일반 내장 정수 및 정규 ASCII 문자열의 기존 수용/거부 정책. bool·float·비정규 직접 API 토큰을 정규 입력으로 승격하지 않는다.
- 균일 `2147483647`, 층상 `2147483629`에서 파생 `2147483647`의 양성과 2상/3상 덱 바이트. 층상 첫 seed `2147483647`의 파생 범위 초과는 계속 거부한다.
- CLI의 기존 `type=int` 정규화. 선행 `+`/0·밑줄·Unicode 숫자·공백을 정규 정수로 바꾸는 CLI 동작과 직접 API의 exact-type/표기 검사를 구분한다.
- 소비자 운영 소스, 이미 결속된 부적격 덱 변조 fixture와 구체적인 상한 거부 이유. 새 API 타입 거부를 소비자 계약 완화로 연결하지 않는다.

## 시험과 재현 범위

기존 `scripts/test_mixer_generator_seeds.py`의 8메서드 본문을 보존하고 직접 API 하위형 거부 및 내장값 보존에 필요한 두 회귀를 추가했다. 추가 시험을 먼저 둔 수정 전 실패와 같은 시험의 수정 후 결과, 기존 소비자 회귀는 `evidence.json`에서 구분한다. 메서드·하위 관측·2상/3상 반복을 합산하거나 연구 관측으로 보고하지 않는다. 정확한 최종 수·rc·Python 신원·소스/로그 해시는 해당 증거가 기준이다.

추가 두 메서드는 다음 경계를 확인한다. `test_str_subclass_rejected_before_custom_int_conversion`은 `__int__`가 `2147483659`를 반환하는 하위형을 E1/D2 균일 `deck()` 경로에서 타입/토큰 사유로 거부하고 변환 hook을 호출하지 않는지 확인한다. `test_builtin_int_and_str_keep_equal_boundary_deck_bytes`는 각 수정 전/후 실행 안에서 E1/D2 각각의 기본 균일·최대 균일·층상 경계에 대해 내장 int/str 덱 바이트와 실제 출력 seed를 대조한다. 이 여섯 양성 쌍을 메서드 수에 더하지 않는다.

| 구분 | 보존된 결과 | 의미 |
|---|---|---|
| 수정 전 생성기 + 같은 새 10메서드 | rc1 · 10메서드 · 하위 관측 failure 2 · error 0 | E1/D2 두 경로의 범위 초과 출력 반례 재현 |
| 수정 후보 + 같은 10메서드 | rc0 · 10/10 | E1/D2 하위형 거부·변환 hook 호출 0, 내장값 양성 보존 |
| 변경 없는 소비자 시험 | rc0 · 34/34 | 기존 소비자 계약/변조 fixture의 합성 회귀 |

기존 8메서드 본문은 정확히 보존됐다. 여섯 int/str 양성 쌍과 기존 2상/3상 경계 golden 해시 네 개도 유지됐다. 이 결과는 Windows Python 3.12.14의 지정 합성 시험이며 전체 gate나 별도 플랫폼 통과가 아니다.

ZIP의 `before/`에 있는 옛 생성기와 옛 8메서드 시험 파일은 변경 전 문맥이다. **정식 red는 후보의 새 10메서드 시험을 그대로 두고 생성기만 수정 전 것으로 대체한 별도 복사본**에서 얻었다. 원본을 수정하지 않으며, `before/`의 옛 8메서드만 실행한 결과를 red 10메서드로 쓰지 않는다.

새 바탕 B에는 이 시험 파일을 실행하는 기존 test target이 있다. 이번 후보는 새 gate/CI 연결을 만들지 않으며 같은 파일의 추가 회귀가 기존 대상에 포함된다. 이번 직접 확인은 지정한 생성기 seed/소비자 합성 시험 범위이며 **전체 gate·생성기 전체 selftest·현장 자격의 재실행이 아니다.**

재현은 전달 검토 ZIP의 `snapshot` 리포 루트를 현재 폴더로 사용한다. NumPy 등 기존 시험 의존성이 있는 검토용 Python을 사용하고, `TMP`/`TEMP`는 이 검토 복사본에서 쓸 수 있는 새 임시 작업 폴더로 먼저 지정한다. 쓰기 불가·준비 오류를 제품 회귀 실패나 통과로 세지 않는다. 원본 전달물과 기존 결과를 덮어쓰지 않는다.
