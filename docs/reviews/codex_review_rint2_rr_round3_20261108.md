### RR3-01 · P2 — 검사 실패 때 보존한 파일 해시 목록을 ‘앞 런 판독 완료’로 오인

**영향: PC12-03의 같은 부류가 남는다. 재개 자격이 거짓으로 참이 되고 다음 원장 항목도 허용된다. 실제 재개 재판독은 실패하므로 잘못된 연구 값 생성까지 보인 반례는 아니다.**

고정 핀 위치:

- `scripts/rint_r_chain.py:4168–4175`: `prior_runs_problem`은 `exit_ok`와 비어 있지 않은 `arms_read` 목록만으로 앞 런의 완료를 인정한다.
- `:4993–4995`: 실제 `read_run`이 실패해도 `arms_read = arm_file_shas(outdir)`를 기록한다.
- `:2131–2141`: 이 목록은 `{file,index,sha256}`이며 판독 계약 통과 결과가 아니다.
- `:4356–4359`, `:3418–3424`: 이 완료 판정을 통해 재개 자격과 다음 항목을 허용한다.
- `:5076–5079`: 복사 경로에도 실패 때 파일 신원만 보존하는 구조가 있다.

반례는 현재 생산자 함수를 호출해 만들었다. 프로세스 실행만 가짜 rc 0·종료 확인 True로 대체하고, 합성 `p2_wrong_kit_a0.json`을 생성했다. **실제 `Runner._execute → read_run`이 `ARM_JSON_COUNT`로 실패**한다. 실제 생산 기록은 `rc=0`, `group_cause=null`, `arms_read=[{file,index,sha256}]`다. 이 기록·payload·로그·그룹 끝 기록은 그대로 두고 요약의 두 칸만 바꿨다.

```text

```

원장 머리·entry·start 신원은 합성이다. 결과 줄·재계산·순서 판정은 실제 함수다. 이 새 반례에서 실제 recover CLI·OS 그룹 정리·연구 계산은 실행하지 않았다. 별도 이전 반례 재생의 실제 scratch Git 근거와 혼합하지 않는다.

**최소 해결:** 앞 런의 ‘검증을 마친 팔 기록’과 ‘실패 때 보존한 파일 신원 목록’을 생산·복사·합치기·자격 소비자가 공유하는 계약으로 구분한다. 현재 성공 경로의 완성 `ARM_PUBLIC` 구조와 요청 팔 대응을 검사하거나, 명시적 판독 완료 상태를 생산하고 검증할 수 있다. 비어 있지 않은 목록이라는 조건만으로는 부족하다. 위 실제 판독 실패를 음성으로, 성공 앞 런과 복사된 성공 앞 런을 양성으로 보존한다. 수치 모형·등록 문턱 변경은 필요 없다.

## 5. Q4 — 봉인 전에 필요한 것

1. **RR3-01 보완이 필요하다.** 앞 런 판독 실패를 timeout으로 바꿔도 재개 자격과 다음 원장 항목이 열리지 않아야 한다. 기존 성공·복사 성공 양성, 원 PC12 반례, 결과 재계산 경로를 함께 확인한다.
2. **RR3-02 현행 한정표 정정.** 이전 보고를 지우지 않고 현재 남은 경계를 명확히 한다.
3. 선언된 PC11-05–08 및 PC12 한정을 자동으로 전부 새 차단 결함으로 격상하지 않는다. 다만 최종 실제 계획·시도 기록이 그 미검증 영역을 쓰지 않는지, 즉 요청 필드·유일 런 이름·실제 순서·launch/end 결합·필요한 chain_end·복사 출처가 맞는지 봉인 전 확인에 포함한다. 결손을 조용히 구형 예외로 흡수하고 일반 정책 GO를 주장할 수 없다.
4. 실제 환경의 프로세스/잠금/권한/파일시스템 자격, 원인 미확정 최초 실패 기록, 검토 핀→봉인 핀 diff 및 의존 지문은 기존 조건대로 남는다. 이번 합성 PASS로 이 조건을 대체하지 않는다.

모든 사본을 일관되게 편집한 위조까지 암호학적으로 막는 요구를 새로 추가한 것이 아니다. RR3-01은 실패 payload와 run 기록을 그대로 남기고 **stop 두 칸만** 바꾸어 기존 정책이 이미 차단하려던 부류를 통과하는 반례다.

`carbon_junction.py:1295–1318`의 동률 정준화는 수용한다. 단 `:895–908`의 동률 면 배정에 영향을 줄 수 있으므로 단순 출력 순서 변경으로 축소하지 않는다. 보고서가 이 예외의 하류 지문 영향까지 이미 밝혔다.

## 7. Q6 — 남은 일과 허용되는 판정 문안

**‘코드·설계·문서 GO(재개 정책 포함)+봉인 전 확인’은 현재 핀에 사용할 수 없다.** RR3-01과 문서 정리가 남는다. 네 작업 이름만으로 자동 종결 조건을 만들 수도 없다.

고침 뒤에도 기존 순서는 유지된다:

```text
S0 단계1 → s_min 개발 → ⑥ 값 비열람 비용·반복 수
→ 기하·반복 수 확인 → 숫자·실행 정책 → 새 계획/핀 봉인
→ S0 단계2 → 등록 R 실행의 별도 진입 판단
```

현장 자격과 12단위 끝-끝/합치기 검증은 이 사슬에 필요한 별도 증거다. 단계2·새 계획 결속·현재 수정→봉인 핀 diff를 ‘봉인’ 한 단어로 완료 처리하지 않는다. ⑦ SBE 탐침 및 빠진 물리·다음 트랙은 이번 판단 밖이다.

이번 회신으로 사용할 수 있는 문장:

> 지정된 rc·로그·형식·끝 기록 대조 수정과 S0 후보 검색 변경은 명시한 코드·합성 범위에서 수용한다. 앞 런의 판독 실패를 완료로 오인하는 RR3-01이 남아 재개 정책 전체는 HOLD다. 실제 환경 자격·S0 실침대 개선·12단위 통합·새 계획 봉인과 실제 연구 실행 승인은 별도다.
