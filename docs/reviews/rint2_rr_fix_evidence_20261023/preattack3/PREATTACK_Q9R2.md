## D. 질문 (1저자 몫)

1. 시도 안 첫 payload 뒤의 자원 · 인프라 멈춤 (OOM · 정전 · 컨테이너 재시작) = 폴더 규칙상 결과 뒤 → 이 등록의 주 판정 = 판정 없음.  그대로 (엄격) 둘지, **같은 기계 · 같은 환경에서 멈춘 런만** 다시 돌리는 것 (단위 = 한 기계 성질 유지) 을 허용할지.
2. 자기 폴더를 못 만든 시도 (기계 · 디스크 소실 · OUTDIR_NOT_EMPTY 처럼 아무것도 안 쓰는 거부) = 개정 2 에서 영원히 `ATTEMPT_LEDGER_MISMATCH`.  엄격하게 둘지, 기계적으로 확인되는 예외 (예: 시작 기록을 원장 리포에 먼저 남김) 를 둘지.
3. 같은 단위의 시도를 동시에 허용할지, 차례로만 (k+1 = k 결과 줄 커밋 뒤) 할지.
4. no-op 를 따로 도는 단위 (환경 지문 전체 대조 · 클라우드 VM 이 바뀌면 다시 맞출 길 없음) 로 둘지, 사다리 단계 끝에서 같은 프로세스로 돌릴지 (등록 §4-1 문구 개정 필요).
5. 등록 칼날 문장 = "명목값 문턱 비교 전부 (origin W0 · 판정 끝 · 등급 · 증서 · 수렴) + SV 걸침" 으로 넓힐지, 둘로 남기고 나머지를 한정어로 둘지.
