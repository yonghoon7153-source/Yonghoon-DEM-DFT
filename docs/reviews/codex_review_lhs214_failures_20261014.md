∞ 탐침은 실제 침대에 무한 두께가 있었다는 주장이 아니다. **새 허용 범주의 필요조건을 사유 문자열만으로 정의할 수 없다는 반례**다. 또한 `1.5`는 기존 출력 거부 문턱이지 물리적으로 타당한 값의 경계나 오차막대가 아니다.

**최소 처방 / 닫힘 증거:**

1. 수치·입력·경계 검사를 먼저 통과해야 한다. 기하·배율·전류·변환계수·재구성 q는 유한해야 하며 필요한 양은 양수여야 한다. NaN/∞/잘못된 타입을 수로 묵인하지 않는다.
2. 적용 범위는 해당 **단상 이온·전자 FULL**. q가 유한하고 원 정밀도에서 엄격히 `>1.5`일 때만 모형 한계다. 열의 다른 정규화와 병렬 상한 검사를 이 예외에 넣지 않는다.
3. 기존 보존·잔차 허용치 `1e−6`, 수치 사다리, 양의 G·병렬 상한은 바꾸지 않는다. 예외·미수렴·증서 실패·경계 중첩은 여전히 기술 실패다. 앞 단계가 실패했으면 높은 q라는 사후 주장으로 구제하지 않는다.
4. accepted FULL σ와 차원 σ는 null, 진단 q는 **별도 키**, 수치 증서는 보존한다. FULL에서 유도되는 f·τ·소산 몫·비에도 값을 만들지 않는다. 정상적으로 따로 푼 CF/협착 진단은 기존 정책대로다.
5. 위 표와 상태/증서 변이체가 생산자부터 소비자까지 같은 판정을 내는 시험으로 닫는다.

## 3. Q1–Q5 답

### Q1. WEB-03 Q1·C1-5와 양립하는가?

**조건부 동의.** FULL 값의 거부는 유지하고 진짜 수치 실패도 계속 막는다면 두 취지를 지킬 수 있다. 기존 10-06 판정문도 FULL 과전도를 CG 오수렴과 동일시하지 않았다(`source/docs/reviews/codex_review_gen2_network_20261006.md:208–214`).

하지만 **이름만 바꾸는 수정은 아니다.** 과거에는 막혔던 레코드의 게시·인계가 가능해지는 **허용 정책 변경**이다. 결과를 본 뒤의 개정임을 기록하고, 기존 실패 기록·문턱·코호트를 보존해야 한다. 이번 검토는 기존 14건의 사후 “성공” 전환을 승인하지 않는다.

### Q2. Physics만인가, 모드 공통인가? Hertz가 걸리면?

**모형/수치 분류는 H0·H12·Physics 공통, 배포 자격은 역할별**로 한다. 같은 원인을 Physics에만 허용하면 분류 자체가 결과 선택이 된다. 단상 이온·전자 FULL만 해당하며 열의 q>1.5는 여기에 넣지 않는다.

- Physics만 적법한 모형 한계이고 나머지 필수 계약이 유효: 레코드 게시 및 선택 부록의 명시적 공란은 허용 가능.
- Hertz 주 타깃이 모형 한계: 진단 레코드는 남길 수 있으나 **이번 v1.3 주 타깃 배포는 HOLD** 권고. Physics/H12/0/1.5로 대체하거나 행을 없애면 안 된다.
- 주 타깃 결측을 허용한 마스크 기반 부분 배포를 원하면 별도 명시적 등록·저자 결정·집계/학습 규약이 필요하다. 선택 부록 예외에서 자동으로 유도되지 않는다.
- 진짜 수치 실패·기하/세대 무효·잘못된 증서: 종전 차단을 유지한다. 모형 한계 사유가 다른 실패를 덮지 않는다.

### Q3. Physics 14건을 공란으로 v1.3에 실어도 되는가?

**표현 방식은 조건부 허용. 현재 14건의 일괄 자격 인증은 불가.** 각 새 실행이 새 범주를 실제로 만족하고, Hertz 주 값 및 다른 필수 계약을 모두 통과해야 한다. “이번 214에는 Hertz 문제가 없다”도 현재 발췌만으로 전건 재검증한 사실은 아니다.

등록 214 ID를 유지하고 Physics 타깃은 공란, 정확한 사유·가용성 수를 함께 낸다. 미퍼콜 0과 구분한다. 기존 `MODEL_BELOW_CONTINUUM_BOUND` 값 유지 정책은 임의로 바꾸지 않는다. 높은 q에 의해 빠지는 Physics는 무작위 결측이 아니므로 남은 사례만으로 전 코호트의 모형 성능을 대표한다고 쓰면 안 된다. 비교에는 실제 쌍대응 N·제외 사유를 밝힌다. 주 타깃 학습에는 부록 결측 때문에 사례를 조용히 삭제하지 않는다.

권장 설명: “등록 사례를 모두 유지하였다. 수치 풀이 인증을 통과했으나 사전 고정된 FULL 출력 상한을 넘은 모드의 전도도와 유도 타깃은 미제공으로 표시했으며, 거부된 q와 수치 증서는 별도 진단으로 보존하였다.” 이 문구는 해당 검사가 실제 통과한 뒤에만 쓴다.

### Q4. 재발사 최소 증거는?

다음 §4를 충족해야 한다. fast16·real4·두 영수증은 필요하지만, **신설 예외의 직렬화·게시·화면 회귀를 대신하지 못한다.** 214 원 입력을 다시 DEM 실행할 필요는 없다. 비준한 망 재계산의 두 새 ROOT 194+20이면 된다.

### Q5. 그 밖의 문제는?

1. **audit=0 / reread=1은 정상적인 구분이다.** SEALED는 등록 집합 전체의 완료·가용한 타깃을 뜻하지 않는다. reread의 meta 실패 2개는 M2·M3 두 검사이지 실패 침대가 2개라는 뜻이 아니다. 이를 풀기 위해 전체 집합 검사를 느슨하게 하면 안 된다.
2. **사후 영수증은 배포 완료 증서가 아니다.** `supp20_postrun_receipt.json:341`의 scope는 `launch`다. 39항 통과는 그 범위의 입력·봉인 대조다. fast16/real4·저자 승인은 `verified_by_tool=false`이며 원 preflight 로그/영수증도 발췌에 없다. 운영자가 갖고 있을 수 있으나 이 묶음만으로 대신 확인하지 않는다.
3. 실패 RSS 기록은 **527.8–1937.9 MiB**다. 최소는 `lhss_011`. 계산은 `ru_maxrss/1024`이며 트리 합산 RSS가 아니다(`run_network_194_parallel.py:2211`). 망 프로세스 rc0·내용 거부는 직접 OOM 종료를 지지하지 않지만, “메모리 원인 절대 아님”을 RSS 하나로 확정하지 않는다.
4. progress 시각상 두 실행 구간은 **30분33초 + 5분23초**, 첫 시작부터 마지막 끝까지 **36분19초**다. printed elapsed 합은 33분36초로 시계/포함 구간이 다르다. “약 40분”은 계획 추정이지 새 실행의 시간 보증이 아니다.
5. `MODEL_BELOW_CONTINUUM_BOUND`는 q>1의 동의어가 아니다. 판정은 보정 f와 φ로 만든 τ²<1을 쓴다(`tau_flux.py:1133–1136`). 제출 reread에도 이 상태인데 q<1인 사례가 있다. 요청서의 1.04–1.48은 일부 높은 q의 예시로만 읽어야 한다.

## 4. 최소 해제 목록 — 구현 검토와 실행 승인 분리

### A. 구현·시험에서 먼저 닫을 것

1. **공용 범주 계약:** L214-01·02를 닫는다. 상태·정확한 사유·유한 q·수치 증서·세대/역할/가지·기하/σ₀ 결합, accepted 값 null, 다른 실패 우선순위를 하나의 계약으로 검사한다. CF·협착 진단도 숫자를 싣는 가지의 증서 요건을 유지한다.
2. **양성/음성 행렬:** q=1.5와 바로 위/아래, H0/H12/Physics, 이온/전자, 열 예외, CF/협착 진단 유지, 비관통 valid_zero, 경계 중첩, 예외·미수렴·인증 실패·병렬 상한·NaN/∞를 포함한다. 높은 q+나쁜 증서, 모형 한계+다른 채널 실패, 세대 결손, 틀린 q 재구성도 차단해야 한다. 기존 case15 음성 대조는 계속 거부해야 한다.
3. **실제 소비 경로:** 생산자 파일 → 일반/정지 게시 → 활성 세대 → τ → reread → 인계 → 배포 → 화면을 통과시킨다. helper 시험만으로 끝내지 않는다. 실패 시 기존 유효 세대 보존·첫 실패 active 없음도 유지한다. L214-03의 모드 복사와 가짜 Δ=0%를 제거한다.
4. **무영향 대조:** 동일 환경의 정상 사례에서 타깃 수치는 비트 동일, 메타/사유 변경은 별도 비교한다. 상태 변경으로 수치가 달라진 것을 “분류만 변경”이라고 승인하지 않는다.
5. **실패 원인별 증거:** 확보 가능한 옛 staging 증서 또는 입력 digest·핀·명령·종료코드가 묶인 승인된 소수 진단으로 실제 가드를 확인한다. 이번 14건을 case ID 허용목록으로 만들지 않는다. 옛 13건의 원인 확인이 불가능하면 unknown으로 남기고, 새 실행에서 사례별 증거로 판정한다. 이를 이유로 검토자가 무단 14건 재실행을 요구/실행하지 않는다.

### B. 새 발사 전에 봉인할 것

6. **등록 개정:** 두 등록 §3의 코드 해시뿐 아니라 §5 결과 자격·공란 의미·예외 범위·Hertz 주 타깃 규칙도 개정한다. 결과 열람 후 정책 개정 이력을 남긴다. 문턱 1.5·수치 허용치·ID 집합·원 입력을 결과에 맞춰 바꾸지 않는다.
7. **새 승인 핀:** 봉인 파일 및 실제 추가 의존성을 다시 점검하고 한 code_fp로 두 새 ROOT를 만든다. fast16·real4, 전체 preflight 로그와 그 로그에 묶인 완료 영수증, 등록 손 대조, 저자 발사 승인을 갖춘다. 기존 ROOT·실패 기록은 보존한다. 이 판정이 발사 승인을 대신하지 않는다.

### C. 새 실행 뒤에만 닫히는 배포 조건

8. **194+20 전건 새 실행:** 각각 audit0 및 정확한 expect-set reread0, ID 누락/추가/중복 0, 읽은 사례 194/20, 양쪽 코드/물성/세대 일치를 확인한다. 기대 실패 수를 14로 고정하지 않는다. 새 결과에서 다른 진짜 실패가 나오면 그대로 차단한다.
9. **인계·배포 실물:** canonical 결과·관측 로그·provenance·인계·배포 감사로 상태/공란/진단 q의 역할을 대조한다. Hertz 주 타깃 가용성과 Physics 모형 한계 수를 별도로 보고하고, 제출 때에는 입력 영수증과 결과 완료 증서를 구분한다.
