## 5. R4 — 탄소 우회 한정어 (판정문 §5)

- T1-10 `carbon_cover_law` 의 2 Ω · 1 Ω 기대 = **막 소자만의 시험** (순수 막 회로 · raster 에서는 막 원장 총량 비 N_c^surv/N_c^0).  탄소가 이어진 raster 의 **전체 단자 저항**에 그 숫자를 요구하지 않는다 — 올바른 구현을 거부한다.  판정문 회로 (`carbon_bypass` · 재현 비트 같음): 2 Ω 막 ∥ 0.02 Ω 탄소 = 0.019801980198019802 Ω · 1 Ω ∥ 0.02 Ω = 0.0196078431372549 Ω · 막 0 + 탄소 = 0.02 Ω · 첫 회로의 탄소 전류 몫 99.0099009901 % · 막 로그 민감도 0.9900990099 % — 실침대 예측이 아니라 *"두 막 법칙이 비슷해도 미정 탄소 접합의 영향은 작다고 말할 수 없다"* 는 반례다.
- `unrealized` = **AM–AM 막이 남지 않음** — 전체 절연이 아니다 (탄소 경로가 전도할 수 있다).  기록 · 웹앱 표지도 같은 뜻으로.
- 쓰지 않는 문장: *"전체 계면저항을 보정했다"* · *"두 판 (2 Ω · 1 Ω) 이 물리적 불확실성의 상·하한이다"* · *"탄소 계면까지 식별됐다"*.  가능한 것 = 조건부 기구 · 감도 구현 — ② · ④ 를 기다리는 제한을 소비자 표지에 유지.
- 구현 검사: 같은 canonical 접점 · 면 키에서 **S_surv ⊆ S_0** · N_0 = 0 · N_surv = 0 은 나눗셈 **전에** 상태로 처리 · N_surv/N_0 = **격자 support 면 비율** (실측 원판의 노출 면적 비율 아님 — CNC 라는 이름과 편향 검증이 필요한 이유).

## 6. R6 · R7 — β 추출 · 실행 영수증 (D12-V)

### 6-1. β 추출 규칙 (T2-2a · T2-2m · 판정문 §7-1)
- 정확 외곽 Dirichlet 에 정답 β 를 넣었으므로 **경계 입력에서 β 를 도로 읽으면 검증이 아니다**.  판정문 반례 (`sphere_bc` · 재현 비트 같음 · annulus 맞춤만 lstsq 끝자리): a 1 · σ_m 1 · σ_i 10 · rσ_m/a 1 · E∞ 1 · L/a 5 → β_true −0.03125 · 북극 경계값 −5.00125 · 막 삭제 오답 (β 0.75) 도 같은 Dirichlet 을 만족 (바깥 해 φ = (−A R + B/R²) cosθ · A 1.006287726358149 · B 0.7547157947686116) · 경계값으로 역산한 β = −0.03125000000001043 (오답을 정답으로 읽는다) · 풀이 안 외부상 annulus (R 2 · 3 · 4) 에서 A · B 를 독립 추출하면 B/(A a³) = 0.75 · R 2 전위 정답 −2.0078125 ↔ 오답 −1.8238965040241448.
- D12-V 가 봉인할 것 (숫자 = 1저자 · 실행 전): β 의 **관측 위치** (외부상 annulus — 계면과 외곽에서 떨어진 R 범위) · **회귀법** (l = 1 기저 −A R + B/R² 의 2 모수 맞춤 또는 같은 뜻의 독립 추출) · **독립 관측량** (내부 전위 · jump ↔ r·J_n · 막 flux · 막 에너지).
- mutant (막 삭제 · 단위 · 부호) 를 넣을 때 **바깥 정답 Dirichlet 을 오답에 맞춰 바꾸지 않는다**.
- 이 반례는 v3 의 jump · flux · 에너지 · 내부 관측이 모두 뚫린다는 뜻이 아니다 — β 추출만 자기입력으로 닫히지 않게 하는 실행 조건이다.

### 6-2. `seal_order` → 실행 영수증 (판정문 §8)
- 커밋 순서 비교만으로는 사전등록의 증명이 아니다 (결과를 로컬에서 먼저 본 뒤 문서를 커밋하고 결과를 나중에 커밋해도 통과한다).
- D12-V 실행 영수증 = ① 봉인 문서 · 동결 픽스처 · 코드 (쓰는 모듈 blob) · 매개변수의 **해시 묶음** ② **실행 전 영수증** (UTC 시각 · 첫 검증 실행 **전**에 커밋 · 푸시) ③ **최초 실행 · 열람 이력** (봉인 전에 돌리거나 본 것 — 개발 실행은 숨기지 않고 development 로 분류).
- **"실행 전 봉인" ≠ "검증 결과 전 봉인"** — 영수증에 어느 쪽인지 적고 같은 뜻으로 느슨하게 쓰지 않는다.
- D12 숫자가 정해지기 전에 돌린 개발 결과를 나중에 **독립 검증 결과로 재분류하지 않는다**.  D12 숫자 없이도 개발 도구 · ①′ 구현은 진행 가능 · T2/T3 검증 PASS 발행은 불가 (판정문 §4 · §8).
- D16-dev (CNC 편향 예산) 를 표시 숫자로 끝내지 않는다 — *"어떤 국소 지표 범위를 생산 적용에서 허용하며 초과 시 무엇을 하는가"* 를 동결 검증과 연결한다 (T3-B 를 같은 모형 수렴 PASS 로 바꾸라는 뜻 아님).
