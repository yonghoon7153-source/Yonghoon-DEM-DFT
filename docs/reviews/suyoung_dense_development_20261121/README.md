# 수영 2D · 설정 ①의 조밀 충전 비교

**이 묶음은 WSL CPU 1개에서 1저자가 한 번 실행하는 개발 계산이다.** 49개 원판을 같은 배열로 눌러 충전율이 같을 때 아래판 반력을 S(공유 속도장)와 F(원판별 속도장)에서 비교한다. F8에서는 세 물체 이상이 한 노드를 함께 쓰는 순간의 접촉도 함께 기록한다.

| 항목 | 실행과 판독 |
|---|---|
| 기존 반환 | F12·F16은 11-20 반복 계산의 SHA256에 맞는 trace를 그대로 읽는다. 같은 팔을 다시 제출할 필요가 없다. |
| 새 계산 6개 | S8 → F8 → S12 → S16 → S24 → F24를 차례로 실행한다. 숫자는 지름당 격자 셀 수다. F8의 접촉 관측과 U6(b) 응력 판독은 같은 궤적을 쓴다. |
| U6(b) 공통점 | Φ_m 0.84·0.90·0.95 가운데 두 팔의 네 해상도가 1.2 MPa 이내에 도달한 점을 비교한다. 압력이 부족하거나 기술 실패가 있으면 각 점의 상태를 따로 남긴다. |
| U6(c) 접촉 | 첫 스텝부터 25스텝마다 조밀 F 노드를 관측한다. 최종 충격량·마찰 일, 접촉 전후 에너지·운동량 등의 관측과 유효 분모를 반환한다. 침투 기하, 장 순열, 두 배 해상도 대조 등 남은 조건은 HOLD로 기록한다. |
| 자원 | 기존 WSL venv(Python 3.12.3·NumPy 2.5.2), CPU 0 한 개, 스레드 1. 새 팔마다 내부 예산 3,570초, 바깥 강제 종료까지 최대 3,600초. 새 팔을 모두 합한 계산 상한은 약 6시간이며 포장과 읽기 시간은 별도다. |
| 시간 근거 | 같은 환경에서 이전 F12는 약 316초, F16은 약 720초였다. F24·S24 및 관측을 켠 F8의 실측은 아직 없다. |
| 종료·수령 | 새 팔의 기술 오류 또는 시간 초과 시 그 팔에서 멈춘다. 아직 돌지 않은 팔을 자동으로 재개하지 않는다. 반환은 별도 폴더에 둔 `suyoung_dense_result.tar.gz`, `screen.txt`, `SHA256SUMS`다. 명령 rc·각 팔 기록·F8 관측·비교 요약을 읽어 개발 판정을 기록한다. |

## 1저자 WSL

1. 배포용 단일 TXT에 `CHECK_ONLY`를 넘기면 새 폴더에서 핀과 파일 해시를 확인한다. 연구 계산 횟수는 0이다.
2. 실행하기로 정하면 같은 TXT에 `GO_SUYOUNG_DENSE_ONCE`를 넘긴다. 시작 전에 출력하는 `RETURN_DIRECTORY`를 보존한다. 직접 압축을 푼 경우 같은 폴더의 `PASTE_SUYOUNG_DENSE.txt`가 같은 인자를 받는다. 내부 스크립트의 실행 인자는 `GO_SUYOUNG_DENSE_ONCE`다.
3. 종료 시 `COMMAND_RC`와 반환 SHA256을 확인한다. F8의 U6(c) 상태와 U6(b)의 기술적 완료는 별도다. 미확정 접촉 조건을 전부 통과로 올리지 않는다.

1저자의 설정 결정은 `docs/reviews/a5_seal_u6_decision_20261120/suyoung/decision.json`, 기록된 반복 trace 해시는 `docs/reviews/nonrint_returns_cd_20261120/repeat/author_comparison.json`에 있다. 세부 판독은 `docs/reviews/suyoung_u6b_development_20261121/README.md`와 `docs/reviews/suyoung_u6c_development_20261121/README.md`를 따른다. 물리 자격·논문 숫자·단계 3 진입은 별도다.
