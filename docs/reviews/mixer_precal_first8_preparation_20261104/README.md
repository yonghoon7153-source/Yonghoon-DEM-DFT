## 1. 저자 결정과 첫8 범위

`author_decisions.json`은 사용자 “ㅇㅇ 권고대로…” 및 기존 인계 ZIP을 Claude에 보냈다는 응답을 기록한다. 전달 완료는 사용자 보고이며 통합 완료가 아니다. 이전 수용 기록의 Q1–Q4 미결정은 당시 상태로 보존하고 이번 결정이 그 뒤를 잇는다.

첫8은 r=0.10에서 B=0.21244/21.244/212.44 × U/C의6조건과 점착0·층상·2바퀴 N0, 점착0·균일·0바퀴 E0다. seed32452843, lab20261014, N계획100000, CGF151.4, SE×20·쌍별 힘 보존, dt_factor1, Fr0.0827, 배플0, 전 정밀도 덤프를 고정한다. NP20은 제안 자원이며 실제 rank 인증이 아니다. 나머지 r=0.35/0.50의12조건은 이번 API가 거부하며 별도 결정으로 남긴다.

## 2. 새 입력 연결과 별도 기준군

- `scripts/mixer_precal_prepare.py`: 첫8의 덱·메타를 메모리에서 만들고 고정 조건에 결속한다. 양의 Bo6조건은 기존 `read_d2`와 U→C 짝 검사, N0/E0는 **별도 미등록 zero-CED 계약**을 사용한다. legacy schema1의 등록 주장을 새 기준군에 옮기지 않고 표준 GM의 양수 조건도 그대로 둔다. 현재 생성기 출력과의 정확한 일치는 독립 물리 증명이 아니다.
- `scripts/mixer_precal_observe.py`: 검증된 새 입력에 순간 접촉·기존 M을 연결한다. 실제 인쇄 반경·타입·드럼 mesh scale의 기하·seed·밀도·E0 신원을 묶는다. 드럼 scale로 계산한 선언 기하이며 실제 STL을 검사한 것은 아니다. 원래 M 기본 반경을 사용하지 않는다.
- D13은 초기 총누락0–10·ID1..N·후속 ID/type/radius 보존을 검사하고 계획수와 관측 상별 수를 함께 남긴다. MPI 삽입의 상별 차이를 숨기지 않고 새 상별 상한을 만들지 않는다. NP가 실제20인지나 동역학 수용 여부는 이 관측 계약 밖이다.
- M은 기존 자기 t0/E0 정착 분모와 원 분산·QC를 같이 보고, 16×16×4/12×12×3/8×8×2, n_min20, axis=x를 명시한다. n_min20은 기존 M 규약 재사용이며 결과를 본 선택이 아니다. 분모 미정의·비유한 M은 UNDEFINED, 구조·신원·중단 오류는 TECH로 값을 내지 않는다. 이론 분모/무작위 초과분은 아직 미지원이다.
- 정상 프레임 자격만으로 물리 실행 GO가 생기지 않는다. 새 관측 연결은 독립 반박 검토 대상이며, 기존 MXD2R 재확인 대기도 유지한다.

## 3. 실행 자원·시간 어림의 적용 시점

**시간 어림·실행 준비의 적용 시점은 “50kg D0.7 종료 후·1저자 승인 후”뿐이다. 지금 제출 명령·큐 계획은 없다.** Claude의 11-04 밤 전달에 따르면 D0.7 실행 시56코어를 사용한다(11-03 기준, QoS cpu-60). 현재 호스트 상태는 이번에 조회하지 않았으며 가용 슬롯을 가정하지 않는다.

## 4. 체크포인트와 중단 처리

첫8 준비는 **처음부터 실행하는 fresh 입력만** 지원한다. 체크포인트 이어 돌림을 비트 동일하다고 주장하지 않는다. 중단은 TECH이며 새 결정 전 재개·재시도·후속 제출을 제안하거나 실행하지 않는다. 기존 생성기가 쓰는 주기 restart와 구간 끝 write_restart는 그대로 두며 새 이어 돌림 정책을 만들지 않는다.

Claude의 11-04 밤 전달은 LIGGGHTS `3d5c00f` 소스에서 주기 restart가 한 step 전 접촉 이력을 쓸 가능성과 write_restart의 쓰기 전 정렬을 관찰했다고 한다. 이는 **시험 전 원인 후보**이며 이 창에서 재현·확정하지 않았다. 예정 정본 `p1_g2c_source_check_20261104.md`는 Claude 다음 push 뒤 대조할 자료다. P1 소스·RJ323957·허용폭은 손대지 않고 옛 L/LC/DEV 판정도 다시 열지 않는다.

새 관측기는 fresh 완료 로그 조건을 프레임 자격과 함께 묶는다. ERROR·불완전/연결된 로그는 TECH이며 지표를 내지 않는다. 로그 조건 일치는 실제 프로세스 exit code·MPI rank·바이너리·체크포인트 이력 또는 물리 완료의 독립 인증이 아니다.

## 5. “믹서 판독 전용” 관측 정의

출력 이름은 **“믹서 판독 전용 AM–SE 접촉 부착”**이다. 엄격한 구 겹침에 따른 순간 접촉이며 분모는 전체 SE 수다. AM_P/AM_S 분율은 겹칠 수 있고 두 분율의 합이 합집합 분율은 아니다. AM당 SE 수는 접촉쌍 수/AM 수로 피복 면적이 아니다.

Ⓑ의 간격0·AM 자유 표면 분모·power diagram 소유 기반 피복 정의와 구분한다. Claude 정본은 reviews 폴더의 `mpm_coverage_interface_design_memo_20261103.md` §4다(이 가지에는 아직 미반입; 이번 정의는1저자 전달문 기준). 정의 통일 구현은 Rint② 발송 뒤 Claude 담당이며 이 창은 피복 코드를 만들거나 같은 이름으로 효과를 주장하지 않는다. SE 군집도 순간 겹침 연결성분이고 지속 결합·실물 응집 크기는 아니다.

## 6. 검증 근거와 한정

원본 실행 로그·소스 해시·정적 첫8 보고서는 같은 폴더 `evidence/`에 보존한다. 준비 시험의 최초 실패는 구현 모듈 부재이고 시험메서드0건이다. 관측 시험도 최초 import 실패와 이후 내부 반례의 assertion 실패를 구분한다. 합성 시험의 통과를 실제 출력 자격이나 전체 게이트 통과로 세지 않는다.

새 두 시험은 `scripts/check_all.sh`와 CI의 별도 항목에 연결한다. 이번에는 관련 직접 합성 시험·최소 문서/등재 검사를 수행하며 전체 게이트의 이전 HOLD를 새 통과로 바꾸지 않는다. 기존 봉인 생성기/판독기는 수정하지 않는다. 준비기가 메모리에서 만든 입력·작은 합성 덤프·단위 mock의 범위와 실제100000입자 런 미검증을 구분해 요청서에 적는다.

최종 직접 시험은 Python3.11.17/3.8.20에서 각각 준비14개·관측20개가 통과했다. 첫8 정적 입력8개와 U/C3짝의 대조는 별도 범위이며 시험 수와 합산하지 않는다. 실제 준비 API와 관측 API를 모의 없이 연결한 추가 확인은8조건의 정상 입력이 프레임 부재에서 멈추고, 위조 해시 입력은 그 전에 거부되는 **음성 경계 확인**뿐이다. 실제100000입자 양성 전체 경로는 검증하지 않았다.

로그는 고정된 다섯 thermo 열과 각 run 누적 종료 step에 결속한다. 헤더 누락·무관한 숫자·중간 미완료·비유한값·열 부족의 합성 반례를 보완 전후로 보존했다. 실제 LIGGGHTS 로그 호환성은 아직 검증하지 않았다. 원본 시험 로그에 있는 기존 생성기/판독기의 ResourceWarning도 삭제하지 않았다.
