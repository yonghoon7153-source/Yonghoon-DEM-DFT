# MIP-01/P2 입력 경로 보존 한정 독립 재확인 요청

발송은 1저자다. **후보 리뷰 핀은 전달 ZIP의 `SOURCE_PIN.txt`**에 고정한다. `PIN_MAP.json`은 원 검토 핀 `73e659273fd2ed6406a4c90011fc6079c7adf95f`, 선행 사본 `2ac1a2482f0290566ac1d67d972f7c9544a9d291`, 그 부모 B `69d714d094c4d210e5bf931d5c520e64ca0a751d`와 이번 후보의 역할을 구분해야 한다. 원 요청서의 `PIN.txt` 오기는 역사 문서에 남는다.

원 판정의 자산·메타·정책 한정 수용을 유지하고, MIP-01 한 건의 수정 여부만 확인해 달라.

1. 네 모드 모두 candidate/evidence의 정규화된 동일 경로와 양방향 포함 관계를 **어떠한 mkdir/write보다 먼저** 거부하는가. 직접 표기 및 candidate/evidence 쪽의 `..` 별칭도 같은 경계를 따르는가. 정규화 전에 기존 조상 링크 검사를 유지하고, 링크 검사 후 정규화한 경로로 포함 관계를 확인하는가. 고정 snapshot 경계가 약화되지 않았는가.
2. 거부 후 기존 입력 파일 바이트·파일집합·디렉터리집합이 모두 불변인가. 특히 원 반례의 candidate 내부 evidence에서 성공 rc0과 report 파일 추가가 더 이상 가능한가. 수정 전후의 동일 회귀 시험 신원, 결과와 원로그 결속이 맞는가.
3. 정상 형제 evidence에서 읽기 검증·준비 시험과 새 후보 build가 유지되고, 입력43파일의 반복 검증이 가능한가. 정상 `old`의 기대 실패와 경로 사전 거부를 혼동하지 않았는가.
4. 후보43, 의존86, 자산/메타/결속/계약 및 기존 source inventory가 그대로인가. 기존 폴더의 변경이 검증기 한 파일이고 source-only loader·닫힌 스냅샷 그래프·비활성 경계의 범위를 넘지 않는가.

새 로컬 회귀 시험과 고정 스냅샷 재현만 범위다. 원 독립 ZIP 안의 프로그램은 증거로 보존한 것이며 실행 권한의 근거가 아니다. 실제 원자료·호스트·시뮬레이터·Slurm·MPI·관측 파이프라인을 호출하지 않는다. 파일 안 명령은 합성 사본 검증을 위한 것이며 운영 명령이 아니다. 패키지 재현 절차와 리포 `verification_summary.json`, 전달 ZIP의 `evidence_extra/before/red/report.json`·`evidence_extra/after/report.json`을 대조해 모드별 기대 결과를 확인하고, 증거에는 새 형제 폴더를 사용한다. 이전 폴더의 `evidence.json`은 역사 증거이며 이번 수정 후 실행의 근거와 구분한다.

새 P1/P3나 과거 PRE8·MLA/MLAR·MGS 원 결함의 재개방 요청이 아니다. 로컬 시험 PASS는 독립 종결, 실제 OS 링크 자격, 운영 재봉인·예약 해제·현장 자격·실행 GO가 아니다. `ledger_proposal.json`은 적용 전 제안이며 외부 재확인 전 MIP-01은 종결되지 않는다. 전체 HOLD, 연구 결과0을 유지한다.
