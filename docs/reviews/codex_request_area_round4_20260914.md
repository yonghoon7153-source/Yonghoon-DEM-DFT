## 3. 검토 요청 ① — **`§5-v4 A` 가 새 구멍을 만들었는가** (핵심)

A 는 v3 ② 를 대체하며 `B_ch` 정의역과 **하한 0 · 상한 +∞** 의 순서통계 경계를 도입했다.
그 자체가 새 조작 경로를 열지 않았는지 봐 달라.

1. **`B_ch` 를 "S3 결과 열람 전 확정" 으로 정의한 것이 충분한가?**  `B_ch` 는 baseline
   (세대 1) 의 `σ_old > 0` 으로 정해지는데, **baseline solve 자체도 결과다.**  어느 ID 가
   `OLD_ZERO` 인지 보고 나서 판정 집합이 정해진다 — 이것이 S0 를 본 뒤의 선택과 같은
   부류의 오염인가, 아니면 *"전환과 무관한 입력 상태"* 로 분리 가능한가?
2. **상한 `+∞` 가 유인을 만드는가?**  A-4 는 `B_ch` 안의 `REFUSED` 에 하한 0 · 상한 +∞ 를
   넣어 중앙값의 두 경계를 계산하고, *"상한 중앙값이 무한대이면 고정 ρ 에서 `d → ∞` 의
   극한(h1)"* 으로 평가한다.  ⇒ **REFUSED 가 많을수록 상한 라벨이 h1 로 가기 쉬워진다.**
   두 라벨이 같을 때만 발행하므로 그 자체로는 h1 을 못 얻지만, 물어야 할 것은:
   ⓐ 하한·상한이 **갈라지는 조건**이 무엇인가 (REFUSED 수 k 와 `|B_ch|` 의 관계),
   ⓑ k 가 작을 때 두 경계가 **이웃 순서통계**라 자동으로 같은 라벨이 나오는 것이
   *"미정을 무해로 읽는"* v2 의 오류와 **실질적으로 같은가**,
   ⓒ `UNDETERMINED_COHORT` 를 피하려고 **REFUSED 를 줄이는 방향으로 설정을 바꾸는**
   경로가 B 의 *"유리한 라벨이 나올 때까지 바꾸지 않는다"* 로 실제로 막히는가.
3. **판정 수가 늘었다.**  3채널 × (하한·상한) = 최대 6 라벨이고 다중 판정 보정은 없다.
   3라운드에서 물었던 *"세 채널을 묶어야 하는가"* 가 경계가 둘로 늘어 **더 커졌는가?**
4. **A-7 이 구속력이 있는가** — *"채널 하나의 h1 을 사후에 전체 성공으로 합치는 규칙도
   만들지 않는다"*.  이 문장이 실제로 무엇을 금지하는가, 아니면 보고 단계에서 우회 가능한가?
5. **A-6 의 읽기 규약** — *"h0 를 모든 케이스에 무해로 읽지 않는다 (66개가 0 %, 64개가
   100 % 여도 중앙값은 0 % 다)"*.  전 케이스 표·상위 꼬리를 같이 싣는 것으로 충분한가,
   아니면 **주 지표를 중앙값 아닌 것으로** 바꿔야 하는가?

## 5. 검토 요청 ③ — **C 의 양성 대조와, 우리가 한 픽스처 정정**

## 9. 원하는 산출물

항목마다 **CONFIRMED / REFUTED / UNVERIFIABLE** 과 재현 경로.

특히:

1. **§3 과 §4 에 명시적 GO / NO-GO** — *"이 규칙과 이 봉인으로 S3 를 돌려도 되는가."*

   그 판단 자체가 우리 것이라 검증이 필요하다.
