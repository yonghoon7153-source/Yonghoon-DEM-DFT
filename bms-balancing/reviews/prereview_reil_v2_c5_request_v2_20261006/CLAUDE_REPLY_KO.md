# Claude 전달용 REIL C5 v2 검토 회신

판정은 **주요 정정 수용, 환경 확인 호출의 범위 충돌 1건 정정 필요**입니다. 구현·측정 승인은 아닙니다.

첨부 v2는 24,568 bytes / SHA-256 3ee657da0b531e3e477f2871ca4662eabbc9576c3f40bdb2036da9794efda75f이며, 검토 시 고정한 HEAD 032886301fd9ccbddcfe48b7a06d1fe5b334d1d8의 문서와 같은 바이트입니다.

C5-N1의 사전 정정 방식, 자동 환경 재구축 철회, 진행 중/반환 뒤 중단 구분, 표본 감시, 구조 오류 우선과 REEVAL_ERROR, 한정 시험·건조 실행 횟수는 수용할 수 있습니다.

**C5V2-N1 P1:** §4-2의 실제 reil_c6_profile.py check는 읽기 확인만 하지 않습니다. check(:237–246) → emit(:222–234) → cobyqa_options(:149–181)와 sobol(:185–219)로 이어져 합성 최적화 1회와 A0/A1-A2/unit 배열 및 옛 seed 비교를 수행합니다. 시험 안에서 emit을 가짜로 바꾼 사실은 이 실제 명령에 적용되지 않습니다. 이전 회신의 check 권고도 이 내용에 맞춰 좁혀 정정합니다.

권고는 현재 금지 범위를 유지하는 최소 경로입니다.

- 구현 단계에는 full check를 호출하지 않고, 현재 설치 환경의 실제 interpreter·RECORD/lock/profile·봉인/옵션/구현 파일 식별만 대조하는 경로를 두 허용 파일 범위에서 정의합니다. 봉인 파일끼리의 자기일관 대조만으로 현재 환경을 검증했다고 쓰지 않습니다.
- 측정 단계도 같은 환경 식별 뒤 A0 seed 0·1 배열만 재생성·대조합니다. 전체 C6 check와 중복하지 않습니다.
- full check는 NOT_RUN으로 남기며, 좁은 확인을 전체 C6 기능 PASS로 표시하지 않습니다.
- full check를 꼭 유지하려면 그 안의 추가 합성 최적화·배열·임시 파일·횟수·예산을 별도 환경 자기검사로 명시 승인받아야 합니다. “환경 확인”에 묵시적으로 넣지 않습니다.

같은 정정본에서 작은 문구도 맞춰 주세요.

1. 128개 행은 지역 실행 상태 4개 중 하나이고, RECORD_INCOMPLETE는 별도 전체 기록 상태입니다.
2. test_reil_p0.py는 보존 NOTEBOOK_SOURCE_EXCERPTS.json도 읽습니다. 원 notebook 실행은 아니지만, 이 텍스트 입력을 식별과 함께 명시하거나 관련 node를 제외한 목록을 고정하세요.
3. 3,600초가 명령 시간 합이라는 정의를 유지해 전체 벽시계로 오기하지 마세요. RED timeout·환경/보존 명령의 누적 포함·증거 폴더 충돌 처리 및 pytest 실행 경로도 승인 전에 적으세요.

범위를 다시 넓히거나 개괄 계획을 반복할 필요는 없습니다. 위 정정 후 사용자가 구현만 따로 승인하고, 한정 검증·건조 실행 결과 제출 뒤 멈추는 순서입니다. 128회 실제 비용 측정은 그다음 별도 승인입니다.

이번 검토는 정적 읽기뿐이며 xlsx·pickle·노트북·발췌 JSON 내용 개봉, import·시험·Sobol 생성·맞춤·설치·재구축·COMSOL 실행은 하지 않았습니다. C3 한정 수용과 P0 기록 미완을 유지합니다.
