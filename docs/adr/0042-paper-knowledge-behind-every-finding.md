# ADR 0042 — 논문 지식 DB: 검수의 판정마다 근거를 쪽까지

- 상태: 채택 (2026-09-23)
- 관련: ADR 0040, ADR 0041,
  `packages/wrdkit/src/wrdkit/eis/knowledge/`, `packages/wrdkit/src/wrdkit/eis/audit.py`
  (`REFERENCES`), `apps/api/app/routers/eis_audit.py`, `docs/raw/papers/`,
  `docs/syntheses/eis-paper-knowledge.md`

## 맥락

EIS 검수(ADR 0040·0041)의 판정은 논문에 기댄다.

- 어느 커패시턴스가 어느 과정인지는 Irvine–Sinclair–West 의 표 1 이 정한다.
- CPE 에서 유효 커패시턴스를 낼 때 어느 저항을 넣는지는 Hirschorn 외가 정한다.
- 벌크 반원이 창 밖이면 절편이 벌크라는 것은 Irvine 외 그림 4b 의 읽기다.

그 근거는 코드 주석에 흩어져 있었다. 규칙이 늘수록 "왜 그 기준인가" 를 따라가기
어려워졌고, 인용이 맞는지 검사할 길도 없었다.

사용자가 논문 여섯 편을 줬다. 에이전트 여섯이 나눠 읽고, 기록 191개와 우리 코드와의
대조를 냈다. 그 대조에서 **커밋 전 코드의 오류 둘**이 나왔다.

- 막는 꼬리의 커패시턴스를 아크 자신의 R (맞춤 경계) 로 냈다. Brug 식은 옴 저항을
  쓴다.
- 벌크가 절편에 있고 입계가 아크로 보이는 펠릿에서 σ 를 R0 만으로 냈다. 맞는 값은
  R0 + R1 이다.

근거를 데이터로 두고 판정이 그것을 가리키게 하는 이유가 이것이다.

## 결정

1. **논문마다 JSON 하나를 `wrdkit.eis.knowledge` 에 둔다.** 불러오는 코드에는 numpy 가
   없다.
   - 기록 하나는 **우리 말 요약**(`claim_ko`, `claim`), 인쇄된 쪽(`page`)과 자리
     (`where`), `math`·`values`·`conditions`, `confidence` 로 이루어진다.
   - id 는 `SOURCE.slug` 이고 바꾸지 않는다. 인용이 그 id 를 가리킨다.
   - PDF 쪽 번호(받은 파일의 쪽)는 넣지 않는다. 인용은 인쇄 쪽으로 한다.
2. **원문은 코드가 인용하는 기록에만, 25 단어까지 싣는다.** 저장소는 공개이고 논문은
   우리 것이 아니다. PDF 는 넣지 않는다.
   - 시험이 이것을 강제한다. 원문을 실은 기록은 코드 어딘가가 그 id 를 적고 있어야
     하고, 코드가 적은 id 는 원문을 가져야 한다.
   - 새로 인용하면 원문을 더하고, 인용을 거두면 원문도 거둔다.
3. **판정 코드 → 기록은 `audit.REFERENCES` 한 곳에 둔다.**
   - `Finding.refs` 는 코드에서 나온다. 판정을 만드는 곳마다 근거를 적지 않는다.
   - API 는 판정마다 `refs` 를, 보고서에 `references`(인용 문장과 요약)를 싣는다.
   - `bml audit` 글은 판정 끝에 `[근거 1·3]` 을 달고, 끝에 쪽 번호가 든 목록을 붙인다.
   - 근거가 없는 판정(경계 붙음, 점 수, 단위, 실측에서 나온 규칙)에 근거를 지어
     붙이지 않는다.
4. **코드가 기록 id 를 적으면 시험이 그 id 를 찾는다.** docstring 이라도 그렇다.
   표 1 의 경계와 `capacitance.PROCESSES` 가 같은지도 시험이 묶는다.
5. **에이전트의 노트는 `docs/raw/papers/<KEY>.md` 에 둔다** (불변). 노트의 "우리 코드와
   어긋나는 것" 은 그날 작업 트리 기준이다. 무엇을 고쳤고 무엇이 남았는지는 종합
   페이지 `docs/syntheses/eis-paper-knowledge.md` 가 따라간다.
6. **표 1 의 두 행은 `PROCESSES` 에 넣지 않는다.**
   - "minor, second phase" (10⁻¹¹ F) 는 입계가 시작하는 자리에 정확히 겹친다. 넣으면
     입계 판정을 흐리기만 한다.
   - "bulk ferroelectric" (10⁻¹⁰–10⁻⁹ F) 은 우리 전해질에 없다.
   - 두 행은 기록에 그대로 남아 있다.

## 결과

- 판정 하나를 논문의 쪽까지 되짚을 수 있다. "왜 R0 가 전해질인가" 에 Irvine 외 1990,
  p. 135 (그림 4b) 와 Vadhva 외 2021 이 답한다.
- 논문이 **권하는데 없는 것**(lin-KK, 막는지의 판정을 꼬리 방향으로, 진폭 등)이 종합
  페이지의 목록이 됐다. 아무도 잊지 않는다.
- 논문을 그대로 옮기면 틀리는 곳도 기록이 됐다. 예: Vadhva 식 5 의 위상 역수, Gupta 가
  CPE 의 Q 를 커패시턴스로 적은 것.

## 비용

- 기록은 **요약**이다. 요약이 원문과 어긋날 수 있고, 원문 조각이 없는 기록은 쪽과
  자리로만 되짚는다. `confidence` 와, 그림에서 읽은 값이라는 표시(`conditions`)가 그
  위험을 적는다.
- 에이전트가 읽은 것을 그대로 믿지 않았다. 인용이 남은 기록은 PDF 텍스트와 글자
  단위로 대조했다. 텍스트 층이 망가진 ISW1990 은 표 1 과 그림 4b 를 쪽 그림으로
  확인했다. 그래도 사람의 확인은 아니다 (`verificationStatus: unverified`).
- 인용 하나를 더하면 JSON, 원문, 시험 세 곳이 움직인다.

## 대안

**코드 주석에만 인용한다.** 흩어지고, 오타를 잡을 수 없고, 같은 근거가 여러 벌이 된다.

**PDF 를 저장소에 넣는다.** 저작권 때문에 안 된다. 받은 파일의 쪽 번호도 판마다 다르다.

**전문 검색(임베딩)을 붙인다.** 판정이 기대는 기록은 수십 개다. 검색이 아니라 id 로
가리키는 편이 검사할 수 있다.
