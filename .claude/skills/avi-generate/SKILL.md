## 3. 공개 영상 내용 규칙

### 3-1. 넣는 것 — 정보전달
문제 → 원리 → 문헌이 보인 것 → 의미.  "우리 연구가 어디까지 왔나" 가 아니라 "이 현상이 왜 그런가" 를 말한다.  첫 편이 승인되면 그 판이 다음 편들의 본보기다.

### 3-2. 넣지 않는 것 — 공개 안전 (하나라도 걸리면 정확성 0 점 · 납품 안 함)

- 우리 시뮬레이션 값 — 봉인 런 · 등록 문서의 결과 · 판정 전 값 · 개발 자료 (공개 논문이 나오기 전 전부 · 1저자 허락 전).
- 내부 표지 — 잡 번호 · 기계 이름 · 주소 · 포트 · 가지 이름 · 커밋 · 원장 번호 (SELF · RCA …) · 내부 단계 코드 · 시도 번호.  (꾸러미 도구가 커밋 식별자 · 제작 표지를 자동으로 본다 — §13-4 · 자동 검사 통과 ≠ 공개 승인.)
- 사람 — 허락 없는 랩 구성원 · 협업자 이름 · 교수님 발언 · 과제 · 회사 보고 내용 · 1저자 이름 · 소속 표시도 1저자 결정.
- 철회 · 인용 금지 값 (`docs/reviews/claims.json` `quotation_ban`).

### 3-3. 숫자 · 출처
- 화면 · 말의 숫자는 **litdb 정본 카드** (`origin/claude/friendly-meitner-lldvar` 의 `litdb/papers/`) 에 있는 값만 쓴다 · 카드 슬러그를 장면 표에 적는다.

## 4. 대본 규칙 — 귀로 듣는 글 (기계 음은 대본에서 먼저 잡는다)

레퍼런스에서 잰 것 (A · B 전사 · `reference_analysis.md`): 도입 24–30 s (최근 사건 한 줄 → 묻는 것 → 오늘 볼 틀) · 절 머리 = 짧은 물음 · 이정표 · 자막 한 줄 = 뜻 덩어리 · 중앙 15–17 자 (최대 27) · 중앙 1.5–1.75 s · 절 경계 = 자막 없는 1.25–2.0 s · 말 빠르기 8.4 음절/s (A · 쉼 뺌) · 문장 끝 쉼 80 % 가 0.24–0.46 s · 물음 끝도 평서처럼 떨어짐 (−4.9 ↔ −5.1 반음) — 1저자가 "군데군데 기계 같다" 고 한 자리의 후보.

1. **귀로 쓴다** — 문장 ≤ 40 음절 (넘으면 쉼 자리를 적는다) · 주어와 서술어를 멀리 두지 않는다 · 명사를 셋 넘게 잇지 않는다 · "이것 · 그것" 의 대상이 바로 앞 문장에 있다.
2. **끝 꼴 섞기** — ~습니다 · ~요 · ~죠 · ~거든요 · 물음 · 같은 끝 꼴 세 문장 연속 금지 (검사기가 센다).
3. **쉼을 역할마다 다르게** — `[쉼 0.35]` 문장 끝 · `[쉼 0.55]` 뜻 바뀜 · `[쉼 0.9]` 문단 끝 · 물음 뒤 · `[절 1.5]` 절 경계 · 긴 문장 쉼표 `[쉼 0.2]`.
4. **빠르기를 문장마다** — 기본 ≈ 7.2 음절/s (레퍼런스보다 ≈ 14 % 느리게) · 숫자 · 정의 · 처음 나온 용어 0.9 배 · 이음말 1.1 배.
5. **읽는 꼴을 따로 적는다** — 대본에 '화면 자막' 칸과 'TTS 읽는 꼴' 칸 (예: 66.5 % → "육십육 점 오 퍼센트" · 10⁻⁴ → "십의 마이너스 사 제곱" · DEM → "디이엠" · MPM → "엠피엠" · 화학식은 1저자가 정한 읽는 법).  사전 = `docs/avi/pronunciation.md` 에 쌓는다.
6. **물음은 물음처럼** — 물음 문장에 표지 → TTS 억양 · 감정 설정 → §7 억양 점검.
7. **강조 낱말 하나** — 문장마다 있으면 표시 (화면 쌓기 · 남보라와 같은 낱말).
8. **맺음** — 요약 한 줄 + 시청자에게 물음 하나 (레퍼런스 A 꼴) · 판매 안내 없음 · ★ 끝맺음 (1저자 11-25 · ep01 v3.4 P3-3) = *"지금까지 「<제목>」 (이)라는 제목으로 발표했습니다. 시청 (청취) 해 주셔서 감사합니다."* 꼴 (제목 = 그 편의 제목 그대로 · ep01 v3.4 = 두 문장 s11_l11a · s11_l11b).

TTS 시트 (`docs/avi/<편>/tts_sheet.tsv`) 칸: 번호 · 장면 · 화면 자막 · 읽는 꼴 · 빠르기 배율 · 톤 · 감정 · 뒤 쉼 (s) · 물음 · 강조 낱말 · 메모.

### 4-1. 대본 내부 반박 리뷰 (정본 S3 · S4 · 1저자 11-25)

1저자 11-25: *"스크립트를 쓸때 쓰고 마무리하지 말고 내부 반박 리뷰"* · *"기승전결 뿐만 아니라 각 슬라이드 전환에서 그 흐름이 가장 최적의 내용 흐름에서의 전환인지도 판단"*.  ep01 은 리뷰 없이 마쳐 내용은 이어져도 기승전결이 약했다 (1저자 평).

- **누가** — 대본을 쓰지 않은 독립 조수.  쓴 쪽의 설명 없이 동결 사본 (`script.md` · 장면 표 · `timeline.json` · `sources.md`) 만 받아 처음 보는 시청자처럼 차갑게 읽는다 — 첫 질문과 끝 답을 자기 말로 먼저 적은 뒤에 다른 자료 · 저자 의견을 본다.  리뷰는 글을 고치지 않는다 — 고침은 대본 조수 (S4).
- **보는 것**
  1. **기승전결 지도** — 장면마다 이야기 역할 (기 · 승 · 전 · 결) + 한 줄 요지 표.
  2. **갈고리** — 첫 20–30 초 안에 궁금증이 선다.
  3. **질문 하나가 일찍** 선다 (§9 대본 ①).
  4. **전** — 반전 · 긴장이 있다.
  5. **결 = 그 질문의 답** — 다른 이야기로 끝나지 않는다.
  6. **늘어짐** — 같은 말 되풀이 · 할 일 없는 장면 · 길이.
  7. **강조 낱말** — 문장마다 힘줄 낱말 하나 (§4 의 7).
  8. **이음** — 문장 사이를 합치기 / 짧은 쉼 / 다시 쓰기 중 무엇으로.
  9. **긴 문장 숨** — 숨 쉴 자리 (§4 의 1).
  10. **전환 판단표** (1저자 11-25) — 모든 장면 전환 · 장면 안 화면 (shot) 전환마다 한 줄: 시각 · 앞 화면 → 뒤 화면 · 그 순간 나레이션 · 판정 (최적 / 늦음 / 이름 (일찍 넘어감) / 자리 틀림 / 불필요 / 빠짐) · 이유 · 고칠 안 (자르는 자리의 문장 · 낱말 · 합치기 / 나누기 / 순서).  S3 의 시각 = 미리보기 모형 시각 (`timeline.json`) — 장면 점검 (S5 · S8) 에서 같은 표를 실제 렌더 시각으로 다시 본다 (§8 의 8).
- **꼴** — 지적마다 등급 + 구체 다시 쓰기 (지금 문장 → 바꿀 문장 그대로).  P1 = 이 편의 질문 · 기승전결이 서지 않음 (다음 단계로 못 감) · P2 = 듣기 · 이음 · 전환이 걸림 · P3 = 다듬기.
- **바꾸지 않는 것** — 사실 · 숫자 · 출처 · 공개 범위 (§3).  다시 쓰기 문장도 같은 숫자 · 같은 출처 · 같은 한정어를 쓴다.
- **파일** — `docs/avi/<편>/review/script_review_rN.md` (N = 1, 2, … · 하위 폴더라 꾸러미에는 안 들어간다).
- **S4** — 대본 조수가 P1 · P2 를 고친다 → 같은 리뷰 조수가 다시 본다 (범위 = 아래 판정문 문장의 S4 부분 · `script_review_r(N+1).md`) → **P1 0 · P2 마다 고침 / 저자 수용 / 보류** 일 때만 다음 (★ 1저자 대본 승인 → S5).  남은 P2 (처분과 함께) · P3 은 보고에 적는다.
- **판본 동결** (AVI-01 · Codex 11-25 Q2 · 판정문 문장 그대로) — “S3 시작 때 대본·장면·전환표·출처와 생성 입력을 읽기 전용 사본으로 묶고 해시를 기록한다. 리뷰어는 별도 파일에만 쓴다. 재시작·종료 때 같은 사본임을 확인한다. P1은 0건, 각 P2는 고침·저자 수용·보류 중 하나여야 한다. 승인한 사본이 바뀌면 이 규칙을 다시 적용한다.”  해시 = 묶은 사본 파일마다 sha256 (리뷰 파일 머리에 적는다) · 문장 수로 같은 판인지 보지 않는다 (ep01 r2 = 15 줄을 고친 뒤에도 128 문장 그대로였다).

### 7-1. 음성 단계 자동 판단 (1저자 11-25 · "이런 권고안들은 저절로 판단되게 백그라운드 에이전트로")

음성 단계 (정본 S6 음성 → S7 강약 · 이음 점검 → 걸린 문장 다시 만들기) 는 백그라운드 조수가 이 절대로 스스로 정하고, 끝에 한 번 보고한다.  **공개판 편만** (Typecast) — 내부 자료 편 (작업 폴더 `internal/` 아래 · Typecast 도구가 폴더 · episode · 제목 이름으로 거부) = 로컬 TTS (정본 표 S6).  명령 = `python3 -I docs/avi/tools/avi.py voice-auto docs/avi/<편>` (작업 폴더 = `python3 -I tools/avi.py voice-auto <편>`).  기본은 **미리 보기** (API 호출 0 · 파일 안 씀 · 만들 줄 · 글자 · 예산 · 지금 이음매) · `--run` 이 실제로 만든다 (무거우니 `nice -n 19`) · 기본값 `--rounds 2 --takes 2 --budget-x 3`.  종료 코드 0 = 끝 (남은 뜀은 보고에) · 2 = 멈추고 1저자에게 묻기.

**조수가 스스로 정하는 것** (묻지 않는다)
1. 목소리 · 방식 (공개판 편 · 내부 자료 편 = 로컬 TTS · 정본 표 S6) = 문정 (`tc_68f9c6a72f0f04a417bb136f` · `ssfm-v31`) · smart (앞뒤 문장을 같이 보냄) · 빠르기 1.0 한 값 · 톤 (프리셋) 을 섞지 않음 · 문장별 빠르기를 보내지 않음 (1저자 11-24 밤 — 1.0 · 1.1 · 1.2 비교 뒤 "1 이 가장 자연스러운데" · V0 프리셋 섞음 · V1 모두 normal · V2 smart 중 V2).
2. 길이 = S0 에서 편마다 정한 값 (기본 5–8 분 · ep01 = 1저자 11-24 "길이는 상관없엉" = 그 편의 예외) — 그 안에서 빠르기 1.0 으로 늘어난 길이 그대로 쓴다 · 정한 길이를 넘으면 대본을 줄이지 말고 1저자에게 묻는다.
3. 만들 줄 = 원장 (`audio_in/typecast_ledger.json`) 과 안 맞는 줄만 (글 · 앞뒤 문장 · 빠르기 · 방식 · 파일 해시) — 맞는 판은 다시 찍지 않는다.  원장에 없는 파일 (손으로 넣은 판) 은 덮어쓰지도 다시 찍지도 않는다 (묻기).
4. 이음매 점검 — 이웃 문장 높이 (F0 중앙) 차 ≥ 2.5 반음 = 뜀.
5. 다시 찍기 — 뜀마다 이웃 기하평균에서 더 먼 문장 하나 (거의 같으면 뜀이 더 많은 문장 · 첫 · 끝 문장은 이웃이 하나뿐) · 2 판씩 × 2 회 · 지금 판과 새 판 중 이웃 높이에 가장 가까운 판을 쓴다.  뜀 0 이면 멈춘다.
6. 끝말 고침 — 다시 찍기 2 회 × 2 판 (원래 판까지 다섯 판) 을 다 썼는데도 튀는 문장 (보고의 '끝말 고침 후보') 만.  **뜻 그대로 끝말만 차분하게** (예 '~거죠' → '~셈입니다' · '~죠' → '~ㅂ니다') · 끝말 바꿈이 원인 주장을 만들거나 (예: 부연을 '…때문' 으로) 숫자 · 부정 · 가설 · 범위를 바꾸면 뜻이 바뀐 것 → S4 (1저자) · `build_scenes.py` 의 그 줄만 고친다 (자막이 따로 적힌 줄은 자막도) → 대본 글이 바뀌었으니 새 사본 해시 + S4 규칙 다시 (그 문장 · 양옆 전환 · 첫 질문 · 끝 답 · §4-1) → `avi.py tts` → `avi.py plan` → voice-auto 한 번 더 (그 문장 + 앞뒤가 원장과 안 맞게 되어 다시 만들고, 다시 찍기 횟수는 0 부터 · 글자 예산은 0 부터가 아니라 이어 쓴다 — 아래 예산 원장).  이미 차분한 꼴 (~ㅂ니다 · ~다) · 이어지는 말 (~는데요 · ~고요) · 물음은 끝말을 바꾸지 않는다.  명령은 글을 고치지 않는다.
7. 남은 작은 뜀 (< 3.5 반음) = 그대로.  두 번째 voice-auto 뒤에도 남은 큰 뜀 (≥ 3.5 반음) = 더 돌리지 않고 보고 (1저자 귀).
8. 기록 — 명령이 판마다 `audio/voice_auto_report.md` (+ `.json`) 와 `DECISIONS.md` 요약 한 줄을 쓴다 · 명령이 쓰는 칸 = 판단마다 한 줄 (번호 · 무엇 (문장 판단이면 그 문장 ID) · 어느 규칙 · 숫자 전 → 뒤) + 남은 뜀 · 끝말 고침 후보 · 쓴 글자 · 남은 예산.  판정문 Q3 의 나머지 칸 (판 해시 · 원인 · 처분) 은 명령이 쓰지 않는다 → **조수가** 그 판단의 `DECISIONS.md` 한 줄을 이 칸으로 적는다 (문장 ID · 판 해시 · 원인 · 처분 · 전후 값 · 남은 예산 · 보고 파일의 그 줄을 잇는다 · 두 번 쓰지 않는다 · 자동 결정 = 보고 · 원장 · 수동 판단 · 예외 = `DECISIONS.md` 한 줄이 그 원장을 잇는다 · 판정문 Q3).  조수가 정한 것 (끝말 고침 · 그대로 둔 뜀 · 멈춤) 도 판단마다 `DECISIONS.md` 한 줄.  끝에 1저자에게 §10 꼴로 보고.

**글자 예산 원장** (AVI-06 · Codex 11-25 Q3) — S4 (★ 대본 승인) 에서 **절대 예산** (글자 수) 과 그 **분모** (승인 대본의 글자 수 · 사본 해시 · 배수) 를 `brief.md` · `DECISIONS.md` 에 적어 고정한다 · 같은 편의 **자동 · 수동 · 실패** 호출을 한 원장에 누계한다 (Typecast 화면에서 손으로 만든 판 · 문맥 재합성 · 실패한 호출 포함 · 손으로 넣은 판은 글자를 같이 적는다) · 재시작 · 끝말 바꿈 · 문장 고침 뒤에도 **남은 예산을 이어 쓴다** (voice-auto 는 지금 대본으로 분모를 다시 재므로, 고정한 절대 예산을 넘지 않는지 조수가 원장 누계로 확인한다) · 청구가 모호한 중단은 확인 전에 다시 부르지 않는다 · 다른 시점의 누계를 섞지 않는다 · **원장 글자 (보낸 글의 합) 와 공급자의 실제 과금 확인 (요금 화면) 을 구분해** 적는다 · 이 편에 따로 승인된 배수 (예: ep01 = 누계 × 4) 는 다음 편의 기본 (× 3) 에 더하지 않는다.

**여전히 1저자에게 묻는 것** (명령은 멈추고 보고의 '1저자에게 물을 것' 에 적는다)
- 결제 · 계정 (API 403 등 실패) · 글자 예산 넘김 (예산 = 승인 대본 글자 × 3 · S4 고정 · 에피소드 원장 전체 · 넘기 전에 멈춤 — `--budget-x` 를 올리는 것도 1저자) · 공개 범위 · 바깥 TTS 전송 범위 (S0 · AVI-03) · 뜻이 바뀌는 고침 (끝말 꼴 말고 낱말 · 내용) · 목소리 바꿈 (원장과 목소리 · 모델이 다르면 명령이 멈춘다) · 손으로 넣은 파일을 API 로 다시 만들지.

**명령 순서**
1. `voice-auto <편>` (미리 보기) → `voice-auto <편> --run`
2. 보고의 끝말 고침 후보를 위 6 대로 처리 (없으면 3 을 건너뛴다)
3. `voice-auto <편> --run` 한 번 더
4. 렌더 (정본 S8 · 확정 음성 · 렌더는 한 번에 하나)
5. 촘촘한 장면 점검 (정본 S8 · §8 · 전환 판단표를 실제 렌더 시각으로)

⇒ 한 편에 voice-auto 는 많아야 두 번 + 끝말 고침 한 번.  그래도 남으면 더 돌리지 않고 보고한다.

**측정의 한계** (보고에 그대로 적는다)
- 높이 차 = 귀의 대리 지표 — "자연스럽다" 고 쓰지 않는다 · 듣기 확인은 1저자.
- 두 높이 측정법의 차 ≤ 1.05 반음 (판을 고를 때 = 문장 파일마다 · 이음매 점검 = 이어 붙인 음성).
- 문턱 2.5 반음 · 작은 뜀 3.5 반음 = ep01 경험값 (표준 아님 · 다음 편 뒤 1저자와 다시 정한다).
- 글자 = 보낸 글 (공백 포함 · 실패한 호출도 셈) 의 합 — Typecast 가 실제로 세는 값은 요금 화면으로 확인.

ep01 실측 (11-24 밤 ~ 11-25): 처음 preset 판 뜀 27 (최대 6.7) → smart 113 줄 뜀 15 → 다시 찍기 2 회 → 끝말 고침 2 줄 → 4 곳 (최대 3.36 · 95 % 2.42) → 마지막 voice-auto 1 회 (다시 만들 줄 0 · 다시 찍기 2 회) = 3 곳 (최대 2.99 · 모두 작은 뜀 → 그대로 · 기록 = `docs/avi/ep01_mixer/DECISIONS.md` · 기준표 최종판 절).

### 7-2. 청취 후보 (정본 S7 · AVI-05 · Codex 11-25 Q4)

v3 가 S7 수치 점검을 지난 뒤에도 1저자가 끝소리 · 한 문장의 지나친 음량 · 문장 안 숨을 짚었다 — 높이 · 전체 음량 · 쉼 길이로는 셋 다 잡을 수 없었다.  그래서 S7 은 합격선보다 **먼저 들을 곳을 고르는 규칙** 을 쓴다.  아래 문턱은 판정문 Q4 표의 **다음 편 잠정 청취 기준** 이다 (ep01 한 편에는 검출률 · 오탐률을 잴 독립 정답 집합이 없다).

| 문제 | 측정 · 잠정 선별 기준 (판정문 Q4) | 함께 볼 것 |
|---|---|---|
| 문장 끝 기계음 | 끝 0.35 초의 저주파 · 비주기 프레임 비율과 끝 0.25 초의 10 ms 구간 레벨 변동을 함께 본다 · 같은 목소리 · 비슷한 종결형에서 두 지표가 각각 상위 10 % 면 먼저 듣는다 · 하나만 높아도 저자가 지정한 시각은 담는다 · 표본이 적은 편은 순위 판단을 보류한다 | 110 Hz 기준은 이 목소리에 쓰인 대리값 · 무성 종성 · 낮은 목소리 · 질문 끝을 나누고 앞뒤 문장과 함께 듣는다 · 레벨 변동을 성대 주기 jitter 로 해석하지 않는다 |

## 8. 촘촘한 장면 점검 (정본 S5 무음 미리보기 · S8 최종 렌더 · 0.5–1 초 간격 · 도구 자리 `docs/avi/tools/scene_check.py` — **아직 없음** · 지금은 `avi.py stills` + 작업 폴더의 프레임 대조표 스크립트)

왜: 영상 C (2:24–2:39) 가 말한 실패 — AI 가 검사 항목을 전부 통과했다고 보고했는데, 장면마다 사진 한 장씩만 보고 통과시켜 손이 책상 아래서 나오는 화면을 놓쳤다.  영상 B (6:23–6:34) 는 5 초마다 한 장 뽑아 같은 그림이 이어지는지 (지루함) 를 봤다.  ⇒ 우리는 **장면마다 한 장이 아니라 영상 전체를 0.5 s 간격으로 다 본다** (1 s 는 1저자가 허락한 긴 편만) + 움직이는 구간은 더 촘촘히.

1. **뽑기** — `nice -n 19 ffmpeg -threads 1 -i <렌더>.mp4 -vf "fps=2,scale=640:-1" <폴더>/f_%04d.png` (8 분 ≈ 960 장) → 대조표 (장마다 시각 표지 · 한 장에 12–16 칸).
2. **전부 본다** — 대조표를 빠짐없이 · 보고에 "본 장 / 전체 장" 을 적는다.
3. **움직임은 0.1 s** — 전환 · 쌓기 · 세어 올라감 · 옮겨 감 구간은 10 fps 필름스트립으로 따로 (중간 상태의 어색한 동작 · 겹침 · 깜빡임).
4. **자동 검사** (시험 먼저 만든다) — ① 같은 그림 5 s 넘게 = 표지 (지루함 · 1저자 판단) ② 한 프레임만 튀는 깜빡임 ③ 자막 상자가 그림 · 출처 줄을 가림 ④ 글자 · 개체가 가장자리 띠 (좌우 10 % · 위 8 %) 안으로 들어감 — 레퍼런스 내용 경계 p5–p95 = 가로 0.16–0.83 W · 세로 0.17–0.76 H ⑤ 숫자 장면에 출처 줄 없음 ⑥ 자막 한 줄 · 22 자 넘음 ⑦ 자막 바뀜이 말보다 늦음.
5. **세 곳 대조** — 화면 숫자 · 낱말 = 대본 = 카드 (`sources.md`).
6. **휴대폰 크기** — 대조표를 1/3 로 줄여 자막 · 큰 숫자가 읽히는지.
7. **기록** — `docs/avi/<편>/qc_report.json` (판 · 뽑은 장 · 본 장 · 걸린 곳 = 시각 · 장면 번호 · 무엇 · 고친 판).  대조표 그림은 리포 밖.  보고 칸 (AVI-07) = **표본** (간격 · 뽑은 장 수) · **직접 본 곳** (장 · 구간) · **이전 판 근거** (같은 자산 · 대본이라 앞 판 점검을 물려받은 구간) · **미측정** · **허용한 예외** (빈 화면 후보 등 처분) — '자동 걸림 0' 은 그 범위와 같이 적는다 (2 fps / 10 fps 표본 사이에 있는 30 fps 한 프레임 이상 · 직접 안 본 장은 '검출 0' 의 범위가 아니다 · '이번 판 전 프레임 · 전 검사항목 직접 통과' 로 읽히게 쓰지 않는다).
8. **전환 판단표 다시** — S3 의 전환 판단표 (§4-1 의 10) 를 실제 렌더 시각으로 다시 본다 (S5 = 무음 미리보기 · S8 = 최종 렌더) — 판정이 바뀐 줄은 이유와 함께 QC 기록에.

## 10. 보고 꼴 · 판 관리 · 멈춤

판마다 1저자에게 드리는 것:
1. 판 번호 · 앞 판에서 바뀐 것.
2. **확인한 것과 그 방법** — 검사기 rc · 대조표 본 장 / 전체 · 음성 점검 통과 항목 수 — 표본 · 직접 본 곳 · 이전 판 근거 · 미측정 · 허용 예외로 나눠 적는다 (AVI-07 · §8 의 7).

4. 자기 점수 (§9) · 걸린 장면 · 문장 번호.
5. 1저자가 정할 것 (물음 + 권고 한 줄).

- "다 됐습니다" · "완벽" 한 마디로 끝내지 않는다.

- 유튜브 재생목록 꼴을 **참고만** (로고 · 이름 · 상표 · 색 흉내 없음): 왼쪽 = 재생기 (controls · poster = 썸네일 · 한국어 자막 track = srt 를 WebVTT 로 즉석 변환) · 제목 · 한 줄 (길이 · 갱신 · 배지) · 받기 단추 셋 (mp4 · 자막 srt · 대본 md) / 오른쪽 = 재생목록 판 (시리즈 이름 · n / N · 편마다 썸네일 · 제목 · 길이 · 지금 편 강조 · 다른 시리즈 링크) · 좁은 화면 (폰) 에서는 판이 재생기 아래로.
- 아래 토글 (`<details>`): 챕터 (누르면 그 시각으로 · 장면 첫 문장 시각 − lead_in) · 대본 (`script.md`) · 장면 목록 (`scenes.json` 요약) · 참고 문헌 (대본의 "## 참고 문헌" 절) · QC 요약 (`qc_report` 의 그 편 칸 + `qc.md` · QC 가 본 영상 sha256 = 이 영상인지) · 10 점 기준표 (`rubric*.md`) · 파일 해시.  내부판 README 가 있으면 맨 위에 "편 설명".  공개판에는 QC · 기준표 · README 가 없다 (토글 = "없음" 안내 · 대본 = 시청자 대본 · 장면 목록 · 챕터 = 공개 장면과 `chapter_lead_s` 로 그대로).
- 글은 꾸러미 파일에서 읽는다 (템플릿 · 코드에 자료 값 · 문장을 베끼지 않는다) · md 는 철회값 가림 → markdown → 허용 태그만 (스크립트 · 이벤트 속성 · javascript: / data: 링크 · 그림 태그 = 무력화).
- 파일 주소 = 등록된 편 · 등록된 역할만 (그 밖 · 경로 꼴 · 모르는 편 = 404) · 재생 = Range (206) · 받기 = attachment (이름 = 등록 이름) · 보일 때마다 크기 · sha256 대조 (캐시) — 어긋난 편은 목록에서 빠지고 무엇이 깨졌는지 안내한다 (fail-closed · 파일은 그대로 둔다).
- 올리기 = 이 컴퓨터에서만 (루프백 · 프록시 머리 없음) · 같은 출처만 · 상한 = 꾸러미 1.5 GiB.
- 지우기 (11-25) = 편 화면의 작은 "삭제" 단추 (이 컴퓨터 화면에만 · 확인 창 · POST) 또는 `python3 -I scripts/avi_register_episode.py --delete <편 id>` (같은 함수 `video_library.delete_episode`) — 영구 삭제가 아니다: 편 폴더를 `<폴더>/.deleted/<id>__<UTC 시각>/` 로 옮기고 옆에 기록 (`<id>__<UTC 시각>.json` · 언제 · 명령 / web) · 되돌리기 = 그 폴더를 손으로 옮김 · 올리기와 같은 관문 (이 컴퓨터 · 같은 출처).
- **공개 보류 (Q4 P1-2 · fail-closed)** — 등록된 공개판이 지금 공개판 기준 (공개 안전 검사 · 공개판 역할 · 장면 투영 · 판 대조 기록 = 지금 판 · 다 잰 통과) 에 맞지 않으면, 다른 컴퓨터 (루프백이 아닌 요청) 에는 목록 · 재생목록 · 첫 편 · 화면 · 대본 토글 · 재생 · 받기 · 자막이 없다 (등록 안 된 편과 같은 404).  이 컴퓨터에는 빨간 "공개 보류 · 걸림" 배지 + "이 컴퓨터에서만 보임" + 까닭 (규칙 · 파일 이름만 · 값 없음) 으로 보인다 → 1저자가 고친 꾸러미로 바꿔 등록한다 (S11 · `--replace`).  판정은 편마다 30 s 캐시 (열쇠 = 편 폴더 · `SHA256SUMS` — 바꿔 넣은 판은 바로 다시 재고 · 철회값 · 커밋 목록이 바뀐 것은 30 s 안에 따라간다).
- **등록 = 같은 기준** — 공개판 등록 (명령 · 웹 올리기) 은 꾸러미의 판 대조 기록이 지금 판 (`build_check/2`) · 통과 · 미측정 없음 · MP4 를 잰 길이일 때만 받는다 (기록이 없는 옛 도구 · 손 꾸러미 · `--no-probe` 꾸러미 = 거부 · Q4 3 회차 N10) · ⚠ 등록은 기록을 본다 — 영상을 다시 재지 않는다.
- **내부판 = 이 컴퓨터에서만 (1저자 11-24 Q1)** — 같은 판정 (루프백 · 프록시 머리 없음) 의 요청에만 내부판이 목록 · 재생목록 · 다른 시리즈 · 첫 편 · 편 화면 (README · 대본 · 장면 토글) · 재생 · 받기 · 자막에 있다 (배지 옆 "이 컴퓨터에서만 보임").  다른 컴퓨터 (웹앱이 0.0.0.0 으로 떠 LAN 에서 열릴 때 등) 에는 등록 안 된 편과 바이트까지 같은 404 · 깨진 내부판의 안내도 안 보인다.
