- **창 나누기 (Codex · Antigravity 같은 꼴)** — 반박 창 = 반박 리뷰 · 실무 교차검증 (§5-2 · §5-4) · 판정문과 증거만 쓴다.  실무 창 = 대피 · 1저자가 맡긴 실무 (§5-3) · 코드 · 기록을 쓴다.  두 창은 서로 다른 가지를 쓰고, 반박 창은 같은 앱의 실무 창이 만든 커밋도 남의 것처럼 독립으로 본다.
- 왕복은 **1저자가 손으로** 한다 (프롬프트 붙여넣기 · 파일 올리기 · "반입").  셋은 서로 직접 말하지 않는다.
- **어디서 돌리나 (Codex · Antigravity 같은 꼴 · 1저자 11-26)** — 앱은 1저자 PC 에서 **로컬 폴더**로 일하고 결과도 로컬에 저장한다.  GitHub 에서는 받기만 하고 (`git fetch`) push 하지 않는다 (1저자 11-26 *"지금 codex는 완전 github에 저장하거나 그러진 않고 로컬에다가 저장"* · *"그 결과물들을 내가 너한테 반입시켜주잖아"*).  **결과 넘기기** = 에이전트가 Claude 인계 ZIP (지금 Codex 가 만드는 꼴: 반입할 커밋의 패치 · stable patch-id · 바꾼 파일 사본 · sha256 목록 · 필요하면 git bundle) + 쪽지 (바탕 커밋 · 가지 · 반입할 커밋) 를 만들고 → 1저자가 Claude 세션에 올려 "반입" → Claude 가 검사 뒤 cherry-pick -x.  조건: ① 처음 폴더는 GitHub 에서 새로 clone (`git clone --config core.autocrlf=false …`) — PC 의 기존 클론과 그 venv 는 실행 블록이 쓰므로 열지 않는다 ② 시험용 Python 은 그 폴더 안에 따로 venv ③ PC 에서 실행 블록이 도는 동안 무거운 시험을 돌리지 않는다 (팔마다 시간 한도가 있는 블록이 있다) ④ 연구실 서버 (kgy · gabia · ibb) 에는 연결하지 않는다.
- GO · 비준 · 발송 · "반입" 은 늘 1저자다.  리뷰어의 GO 판정은 1저자 GO 를 대신하지 않는다.
- Codex · Antigravity 의 금지 다섯: ① 작업 가지 · 동결 가지 · 봉인 가지에 쓰기 ② GitHub 에 push (받기 `git fetch` 만) · 넘긴 커밋을 rebase · amend 로 고치기 (고칠 것은 새 커밋으로) ③ 서버 (kgy · gabia · ibb) 접속 · 잡 발사 · 취소 ④ Rint σ (`verdict_results.json`) 열람 ⑤ 주소 · 포트 · 계정 · 홈 경로 · 동료 이름 · 메일을 리포에 쓰기 (리포 공개).

## 2. 가지 지도 — 본 세션 · 서브 세션 (일을 보내기 전에 꼭 읽는다)

- Claude 세션은 **둘이 번갈아** 작업 가지를 쥔다.
  - **본 세션** = 가지 `claude/stoic-knuth-NObVQ` (stoic)
  - **서브 세션** = 가지 `claude/sdcp-dem-manuscript-si-pqwtv8` (B · 본 세션 토큰이 떨어졌을 때 이어받는 쪽)
  - 한 때에 한쪽만 쓴다.  다른 쪽은 SHA 를 고정해 **동결** (push 금지 · push 직전마다 그 SHA 그대로인지 확인).
- **지금 누가 쥐었나** = CLAUDE.md 맨 위 ★ 줄 가운데 가장 최근의 *"본 세션 → 서브 세션 인계"* 또는 *"서브 세션 → 본 세션 복귀"* 줄과, 그 줄이 가리키는 인계 문서의 '가지' 절.  기억으로 정하지 않는다.
  - 예 (11-26) = **서브 세션** · 작업 가지 B · stoic = `49f60159a` 동결 · 인계 `docs/handoff_to_subsession_20261125.md`.
- **복귀** = 1저자 "메인 복귀" → 작업 가지의 마지막 커밋 `docs/handoff_return_to_stoic_knuth_<날짜>.md` → 본 세션이 stoic 을 B 끝으로 fast-forward.  그 뒤로는 Codex · Antigravity 가지의 바탕도 stoic 이다.
- 그 밖의 가지: 봉인 가지 `claude/rint2-seal-20261118` (push 금지) · litdb 정본 `claude/friendly-meitner-lldvar` (litdb 카드만 · CLAUDE.md litdb 절).
- ⚠ Codex · Antigravity 에 일을 줄 때는 **늘 가지 이름 + 커밋 (리뷰 핀)** 을 같이 준다.  서브 세션 동안 B 의 새 커밋은 stoic 에 없다 — 기본 가지 (default branch) 만 보면 엉뚱한 판을 리뷰한다.  리뷰어는 그 핀에서 자기 가지를 만든다.
- ⚠ 같은 가지에 둘이 동시에 쓰지 않는다 (Claude 둘 · Claude 와 리뷰어 · 리뷰어 둘 모두).

## 3. 반박 리뷰 · 실무 교차검증 보내기

1. **Claude — 요청서** `docs/reviews/<받는쪽>_<주제>_request_<YYYYMMDD>.md` (받는쪽 = `codex` · `agy` · 둘 다면 `codex_agy`).  맨 위 *"이번에 닫는 것 / 닫지 않는 것"* · 리뷰 핀 (가지 + 커밋) · 질문 (번호) · 재현 명령 · 증거 자리.  사전 공격 리뷰 (CLAUDE.md ①–⑤) 는 논문 숫자 · 봉인 직전 · 수영 인계표 때만 (11-16 실행 우선).
2. **Claude — 커밋 → 게이트 → push.**  요청서가 GitHub 의 작업 가지에 있어야 리뷰어가 `git fetch` 로 받아 핀으로 읽는다.  큰 묶음 · 리포 밖 자료는 ZIP (선례 = 세미나 덱 ZIP v4–v9).
3. **1저자 — 반박 창에 붙여넣기**: §5-1 공통 + §5-2 (반박) 또는 §5-4 (교차검증).  실무 창에는 §5-1 + §5-3 (대피) 또는 맡긴 실무의 쪽지.  Claude 가 자리 표시를 채운 판을 채팅으로 드린다.  두 리뷰어에게 같이 맡길 때는 **서로의 판정문을 보여 주지 않는다** (독립).
4. **판정문 받기** — 리뷰어가 Claude 인계 ZIP (판정문 · 증거 커밋의 패치 · patch-id · 사본 · sha256 목록) 을 만들고, 1저자가 Claude 세션에 올린다.
   - 판정문 = `docs/reviews/<리뷰어>_review_<주제>_<YYYYMMDD>.md` (리뷰어 = `codex` · `agy`)
   - 증거 = `docs/reviews/<리뷰어>_<주제>_evidence_<YYYYMMDD>/` (바이트 그대로 — `.gitattributes` 가 `codex_*_evidence_*` · `agy_*_evidence_*` 를 변환하지 않는다)
5. **두 판정을 함께 반입 (1저자 11-26 *"같이 반입해서 너가 정리"*)** — 같은 요청서를 둘에게 줬으면 두 ZIP 을 함께 올린다.  기본 = 둘 다 온 뒤 한 번에 · 한쪽이 오래 늦으면 먼저 온 쪽만 '한쪽만' 표지로 정리하고 나머지는 온 뒤 덧붙인다.
6. **Claude 통합 정리** — 대조표 `docs/reviews/<주제>_cross_review_<YYYYMMDD>.md` (항목 · Codex 판정 · agy 판정 · 일치 여부 · 우리 트리 재현 · 처분) · 엇갈린 칸은 조용히 고르지 않고 1저자 Q (권고 한 줄).
7. **1저자 "반입" → Claude** — ZIP 의 sha256 목록부터 대조 → 그 안의 커밋 (bundle 또는 패치) 을 `cherry-pick -x` (patch-id 대조 · 충돌 0 확인) · 커밋 없이 파일만이면 그대로 넣는다 → 우리 트리에서 재현 (판정값 차이) → 원장 (`docs/reviews/findings.json`) 처분 → 수정 계획 (Q · 권고 한 줄) → 1저자.

### 5-2. 반박 리뷰

```
할 일 = 반박 리뷰. 요청서 <요청서> (리뷰 핀 = <작업가지> 의 <리뷰핀>) 를 읽고,
고친 사람의 설명이 아니라 diff · 시험 출력 · 네가 직접 만든 작은 반례로 판정한다.
판정문 하나 = docs/reviews/<리뷰어>_review_<주제>_<YYYYMMDD>.md
  - 맨 위: 결론 (GO / 조건부 GO / HOLD) 과 그 범위
  - 새 P1 · P2 · P3 (번호 · 반례 · 재현 명령 · 기대값과 실제값)
  - 닫힌 항목 · 닫지 않은 것 · 네가 돌린 명령
증거는 docs/reviews/<리뷰어>_<주제>_evidence_<YYYYMMDD>/ 에 바이트 그대로 둔다.
다른 리뷰어의 판정문이 리포에 있어도 열어 보지 않는다.
ZIP 이름 = <AGY|CODEX>_<요청 ID>_review.zip · 그 안 REVIEW.md 첫 줄 = [<AGY|CODEX> 독립 리뷰] <요청 ID> — <판정> · 둘째 줄 = 요청: docs/reviews/<요청서>.
근거마다 표지: 직접 재현 · 원자료 대조 · 요청자 보고 · 추론 · 미확인.
시작 전에 1저자에게 추론 강도를 묻는다. '좁은 재확인' 이면 요청서가 정한 범위만 본다.
HOLD = 보고 숫자나 주장이 바뀌는 새 P1 만 (P2 · P3 = 알려진 한계로 적는다).
끝나면 네 가지에 커밋하고 Claude 인계 ZIP 을 만든다 — 반입할 커밋의 패치 (git format-patch <리뷰핀>..<내가지>) · stable patch-id · 바꾼 파일 사본 · sha256 목록 · 쪽지 (바탕 커밋 · 가지 · 반입할 커밋).
그리고 1저자에게 ZIP 이름 · 판정 한 줄을 알린다.
```

### 5-3. 대피 (Claude 토큰이 없을 때)

```
할 일 = 대피. <인계문서> 의 '할 일' 을 네 가지에서 이어받는다.
계산 · 서버 실행이 필요한 단계는 명령 블록만 만들어 1저자에게 주고, 1저자 GO 뒤에만 다음으로 간다.
기록 = 쪽지 새 파일 docs/collab/<리뷰어>_to_claude/YYYYMMDD-HHMM_<주제>.md (UTC · 이미 있는 쪽지는 고치지 않는다).
쪽지에 네 커밋 SHA 를 쓰지 않는다 (cherry-pick 뒤 바뀐다) — 자리 표시 <<sha:커밋 제목 앞 낱말>> 를 쓴다.
끝날 때마다 Claude 인계 ZIP (반입할 커밋의 패치 · stable patch-id · 바꾼 파일 사본 · sha256 목록 · 쪽지) 을 만들어 1저자에게 준다.
Claude 가 돌아오면 1저자가 ZIP 을 올려 "반입" 이라고 하고, Claude 가 cherry-pick -x 로 합친다.
```

### 5-4. 실무 교차검증

```
할 일 = 실무 교차검증. <요청서> 의 계산 · 판독을 같은 입력으로 네가 독립으로 다시 해서,
숫자가 같은지 표로 보고한다 (칸 · 우리 값 · 네 값 · 차이 · 허용폭).
다르면 어디서 갈렸는지 줄 단위로 찾는다. 결과 파일은 5-2 의 판정문 · 증거 꼴로 남긴다.
```
