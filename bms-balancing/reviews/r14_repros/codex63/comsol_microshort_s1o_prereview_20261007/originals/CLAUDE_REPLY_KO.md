2026-10-07. **판정: S1-O 오프라인 준비 범위로 적합. 아래 네 문구를 명확히 반영해 준비하면 된다.** S0 물리 설계를 다시 열거나 지금 계산할 필요는 없다.

검토한 요청문은 커밋 b54d77218d67faf3258908fb2ff5f4f5972e0cd2, blob 4d68dca65e0868f634f61e163a846462c488b7b6이다. 첨부 7,732 bytes / SHA256 0fff3e1fffe29b7e448c5f61ea4c9464cbb59691d2a301ee2089ee9a54e47127와 같다. 같은 커밋의 원장 §72·73 및 S0 근거를 대조했다.

## 반영할 명확화 네 가지

1. **33행 — 실행 가능한 소스와 활성 실행본을 분리.** S1-O는 launcher/consumer/parent의 소스와 결속 설계를 작성하는 단계다. 단순한 경고 표시만 두지 말고, 비활성 소스 보관과 승인/release 부재 시 외부 동작 전 거부 원칙을 명시한다. 실제 approval/release/token/runtime은 만들지 않는다. 구현 작성·검증 완료·native-ready는 서로 다른 상태다.
2. **31–32행 — readback 시점을 분리.** 구성 후 solve 전의 설정/생성식 확인, 일관 초기화 t=0 또는 명시한 0+의 재고·전위·전류, 완료 후 결과를 구분한다. 설치본 변수/API가 미확인인 것은 OPEN이다. 설정 문자열을 읽은 사실만으로 실제 유효 계수 소비를 입증했다고 쓰지 않는다. 별도 초기화/solve 호출이 필요하면 횟수와 승인에 드러낸다.
3. **36행 — near-zero·t=0 부호 판정.** 상대 분모뿐 아니라 부호도 절대 허용 범위와 함께 정의한다. t=0의 이동 전하 0과 near-zero의 분해 불가능한 이동을 엄격한 N 감소/P 증가 실패로 세지 않는다. 충분히 분해되는 신호의 역방향 수지 오류와 신호 분해능 부족을 구분하고, j/RN/RP·I·q의 단위 및 qI 적분 규칙을 고정한다.
4. **37행 — 협조적 중지와 강제 종료를 구분.** Windows TerminateJobObject는 graceful 요청이 아니다. 지원되는 협조적 중지 → 한정 대기 → 남은 소유 Job 강제 종료 → 실제 종료 확인의 의미를 명시한다. 협조적 수단이 없으면 없다고 기록한다. 샘플 최대와 실제 peak/OS 강제 상한, 감시 실패와 0 관측도 구분한다.

세부 대체 문안은 S1O_CLARIFICATION_ADDENDUM_KO.md에 있다. 원 승인문과 원 발송문은 보존하고 보완 문안으로 연결하면 된다. 이것은 native 제어 실행이나 승인 범위 확대를 요구하는 문서가 아니다.

## S1-O 제출 때 볼 기준

- 8개 미결 항목이 산출물에 대응하는 현재 구조는 타당하다. 미작성 산출물·미관측 설치본 값 자체를 이번 발송문의 새 결함으로 세지 않았다.
- P0→P1 저장만 →P2 요청만 →P3 cap만의 대조 및 공통 255시각은 맞다. 120초 P가 300초 이후 cap을 검증하지 못한다는 점도 요청문이 이미 인정했다. 해소안의 단계·창·설정·고유 실행 수·재사용 조건을 적되 P의 최대 4회에 추가 solve를 숨기지 않는다.
- K의 D_k/S_k에는 같은 설정의 near-zero 짝대조가 필요하다. 기준 재사용은 조건이 같은 때만 허용하고 실제 고유 실행 수를 센다. 후기 창을 검사하지 않은 짧은 대조로 2700–3600초 기울기 수렴을 대신하지 않는다.
- 120초 높은 σ 비용은 다른 σ·3600초·세분 격자 비용의 보장이 아니다. S0 OCV 예측, 평균 조성 OCV, 단자전압, paired D를 구분한다. P의 1mV 기준은 약한 0.096mV 신호의 분해능 보장이 아니다.
- 검증안은 실제 소비자/parent 함수와 엔진·이유·도달 단계·횟수·상한을 제시한다. 이번에는 실행하지 않는다. S1-O 전체 3,600초 및 단계 상한을 유지하고 마지막 수정 뒤 정적 확인·전달 시간을 예약한다.

다음은 이 조건을 반영한 **비활성 S1-O 산출물 제출 → 변경부 검증 별도 승인 → 검증 결과와 native 미결 수용 → S1-P 별도 승인** 순서다. 지금 S1-O 구현 완료나 native-ready를 수용한 것이 아니다.
