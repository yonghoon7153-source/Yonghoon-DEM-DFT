# 입자 해상도 민감도 비교의 준비 범위

2026-10-04. **문서상 범위 확정만 완료했다.** 후보 코드 작성·변경부 검증·COMSOL/JVM/compile/solve·입력 gate·설정 변경은 미승인이다. 이 문서에는 실행 명령이나 실제 승인 파일이 없다.

## 질문과 기준

질문은 “현재 near-zero 누설·정전류 조건에서 입자 반경 방향 해상도를 320에서 640으로 늘리면, 120–150초의 선언된 전압과 표면 조성이 기존 비교 한도보다 달라지는가”다. 물리 두께 방향 해상도·실험 타당성·유한 σ 신호·장기 수렴은 묻지 않는다.

비교 기준은 **수용된 NORMAL480 하나**로 고정한다. NORMAL240나 새 정상 control로 결과를 본 뒤 바꾸지 않는다. 기준 재계산은 제안하지 않는다.

## 비교 구간의 근거와 표본

이 창은 새 후보 결과를 보기 전에 고른 최소 비교창이다. 기존 수용된 NORMAL480 분석의 같은 좌표 표면−입자평균 분율 차는 다음과 같다. 새 CSV 수치 분석을 반복한 것이 아니라 보존된 `SUMMARY.json` 값을 읽었다.

| 기존 관측 | 5초 | 120초 |
|---|---:|---:|
| N 차이의 좌표별 범위 | 0.0018360–0.0018593 | 0.0074228–0.0076248 |
| P 차이의 좌표별 범위 | −0.0006296–−0.0004209 | −0.0015317–−0.0011983 |

120초에는 이미 초기 0–5초와 다른 입자 비균일 상태가 관측된다. 따라서 120–150초는 초기 창 밖을 최소 비용으로 확인하는 선택이다. **150초가 가장 위험한 상태·480초의 대표 상태라는 증거는 없다.** 30초 폭은 운영상 최소안이며 물리적 포화 시간이나 통계적 보장으로 부르지 않는다.

- 전체 요청 집합: 기존 CONTRACT의 `requested_times_s`에서 0≤t≤150인 원문 항목을 순서대로 재사용한다. **1,637개**다. 저장 실제 시각 수는 고정하지 않는다.
- 주 비교 집합: 같은 목록의 120≤t≤150, **301개**. 120.0부터 150.0까지 0.1초 간격이다. 끝점 150초와 149.9초를 임의 제외하지 않는다.
- 공간: CONTRACT의 좌표 배열 원문을 재사용한다. N/domain1 0–52µm 241점, P/domain3 77–121µm 241점. 새 float 격자를 만들어 근접점으로 대체하지 않는다.
- 두 관측량: 경계4−경계1 단자전압, 같은 시각·domain·좌표의 표면 x. signed 차이는 후보−NORMAL480이다. 최대 절대차와 그 시각·전극·좌표를 함께 남긴다.
- 모든 필수 요청 시각·좌표가 양쪽에 있어야 한다. 실제 저장 시각의 교집합만 좁혀 PASS로 만들지 않는다. 정확 공통 추가 저장 시각은 별도 보조 표로 보고하고 필수 집합과 섞어 개수를 부풀리지 않는다.
- 0–5초와 5–120초의 차이는 같은 실행의 보조 관측으로 기록할 수 있다. 과거 시험을 재실행하거나 그 구간에서 새 독립 수용을 자동 선언하지 않는다. 범위·유한값·Li·보호 검사는 실행 전체에 유지한다.

## 결과를 나누는 규칙

`native_completion`, `evidence_validity`, `mesh_comparison`을 별도 필드로 기록한다. 종료 rc0만으로 비교 PASS가 되지 않으며, 유효한 비교의 한도 초과도 solver 실패로 바꾸지 않는다.

| 조건 | mesh 비교 판정 | 다음 해석 |
|---|---|---|
| 정상 150초·필수 증거 유효 + max abs ΔV≤0.001V **그리고** max abs Δx≤0.0001 | `WITHIN_LIMITS_THIS_WINDOW` | 이 입력·입자 축·120–150초·선언 표본의 세분 민감도만 한도 안 |
| 정상 종료·증거 유효 + 어느 한 값이 해당 한도보다 **엄격히 큼** | `EXCEEDS_LIMITS` | 해당 관측량의 해상도 의존을 기록. 기준 결과를 삭제하지 않고 다음 선택을 별도 요청 |
| 보호 중단·solver 오류·예산 실패·증거/필수 시각/좌표 누락·기준 불일치 | `INCONCLUSIVE` | 확보한 수치와 원인별 상태는 보존하되 정상 창 비교 PASS로 승격하지 않음 |

Li 상대량 변화≤1e−6, 전압 분해 잔차≤1e−8V 등 기존 유지 검사는 그대로 적용한다. NaN/Inf·단위/표면 범위 오류·mesh read-back 불일치는 증거 유효성 실패다. 전해질 차이는 별도 관측으로 남기되 새 합격 문턱을 만들지 않는다.

통과해도 오차 상한·수렴 차수·참값 정확도·물리 600 축·480초 후반·유한 σ 검증을 주장하지 않는다. 기존 0–5초 입자 160→320 전압 차 0.617mV 및 rtol30 전압 차 2.381µV는 **설정 간 관측 차이**이지 “오차 바닥”이 아니다. L3는 입자 축의 이 창에 한해서만 갱신한다.

## 예상 비용과 아직 승인되지 않은 자원 한도

다음은 **계획용 산술 시나리오**다. 성능 실측이나 실행 예산 승인이 아니다. SPEC §37–39의 300/320 기록은 compile+batch 120초 모델 2,650.203초, 240초 모델 4,059.516초, 480초 모델 6,500.453초다. solver 내부 시간과 구분한다.

120–240초 두 관측으로 단순 보간한 300/320의 150초 비용은 `2650.203 + (4059.516−2650.203)×30/120 = 3002.53125초`다. 그 전체 비용이 가정상 2배라면 약 **6,005초, 100분**이다. 입자 요소 수가 2배라는 이유로 전체 DOF·실행시간·메모리가 정확히 2배라고 보증하지 않는다. 이 수치는 비용 규모를 비교하기 위한 한 시나리오이며 상한이 아니다.

실제 준비본은 소스상의 DOF 증가 범위, 이전 로그의 peak memory, 결과 저장 구조와 여유 디스크를 근거로 native·분석·정리·전달·전체의 새 한도를 제안해야 한다. 480초의 9,000/11,400초 또는 50GiB를 자동 재사용하지 않는다. 새 기준 해나 성능 probe를 이 비용 추정을 위해 돌리지 않는다. RAM·실제 코어·디스크를 이번에 실행 환경에서 실측했다고 쓰지 않는다.

## 다음 준비본이 제출할 것

사용자가 오프라인 후보 작성을 별도로 승인하면, 새 전용 경로와 run 식별·소스/manifest·최소 diff·요청/좌표 목록·NORMAL480 기준 해시·비활성 명령/승인문·새 자원 예산을 제출한다. 경로가 있으면 덮어쓰기·다른 이름 우회 없이 중지한다. 생산 원본·기준 CSV·과거 실패·pending·영수증은 변경하지 않는다.

변경부 검증안은 최소한 입자 축 외 변이 거부, 기준 위조 거부, 필수 끝점 누락, 동일 개수의 잘못된 시각/좌표, 한도와 정확히 같은 값·한도 초과·NaN, 정상/보호/오류 분리, 실제 부모 판정의 예산·종료코드 연결을 다룬다. 실제 함수·엔진·횟수·ID·시간을 준비본에서 고정하되 **그 검증을 문서 권한으로 실행하지 않는다**. 기존 전체 suite를 일괄 반복하지 않는다.

후보 작성 수용 → 변경부 검증 별도 승인·수용 → 정책 경로와 고정 실행본의 native 최대 1회 별도 승인 순서다. 현 정책을 바꾸거나 All files를 자동 적용하지 않는다. 현재 `candidate_implementation_approved=false`, `validation_approved=false`, `native_approved=false`다.
