## 3. 감사 소비자 입력·출력 계약 초안

입력은 읽기 전용 복사본이다. metadata 원문 SHA256·장부 원문 SHA256·각 archive/compare JSON SHA256·PROVENANCE 실행 핀·대조기 MD5·실행 파일/덱/runner·MPI 신원을 하나의 입력 목록으로 결속한다. 원 경로는 비공개 별칭표에서 realpath 대응을 확인하고 리포에는 별칭과 해시만 둔다. 다른 폴더 이름을 새 시도로 빠뜨리지 않는다.

순서:

1. 장부 **전체**·scheduler 모집단·OUT 전체의 빠짐/중복·종료 여부를 먼저 확인. `(cluster, JobID, DBIndex)`는 관측 레코드 식별에 쓰되 그것만으로 재큐 검출 충분하다고 하지 않는다. 동일 잡의 반복 attempt/다른DB행은 정상 한 줄로 접지 않는다.
2. §8 기준으로 pending 취소/rc3 사전 멈춤/건식/내용시도/어긋남을 분류. rc3+attempt, prestop+rc4, 꼴 밖 N, 누락OUT, 실행 중 잡은 추정 복구 없이 어긋남.
3. NP별 N40000의 시도만 센다. 내용 판정 한 칸이라도 있으면 그 NP의 최초 내용 시도를 동결. 한도 잔여가 있어도 내용 판정 뒤 재시도 불허. 혼합 내용+NOT_COMPUTED도 동결.
4. 두 NP의 첫 내용 입력만 §4 표에 연결하고 판/대조기/실행 파일/덱/MPI 동일성을 확인. 이후 생성한 감사 도구 핀과 과거 실행 핀은 서로 다른 필드로 둔다.
5. 출력은 sidecar: 분류·사유·원자료 해시·선택된 두 잡·결측 목록. `registered_conclusions_adoptable`은 이번 준비/합성 단계에서는 false. 실측값을 새로 계산하거나 원 OUT/장부/원장을 수정하지 않는다.

`cases.json`의24행은 **미실행 기대 명세**다. 표본 숫자/잡 번호는 합성 이름뿐이며 실제366288·366290의 기록과 합치지 않는다. 기대 판정을 써둔 것을 구현 통과로 세지 않는다.

## 4. 실패 경로 실행 전 명세

| 순서 | 작은 반례 / 관측 | 합성 완료 때 말할 수 있는 것 | 현장에 남는 것 |
|---|---|---|---|
| 1 | 고정 runner의 preflight 거부; attempt 기록 전 장부 쓰기 실패 | rc3·OUT/가짜 엔진 호출 없음·장부 상태 | 실제 공유 파일시스템 오류 형태 |
| 2 | attempt 줄 직후 OUT mkdir 실패/중단 | rc4·attempt1줄·해당 실패를 시도에 셈 | 원자적 append와 실제 전원/프로세스 실패 |
| 3 | 복사 장부에 동시 writer·부분/중복 줄 | 관측된 행 집합·손상 거부. 실제 runner가 충돌을 막는지와 소비자가 손상을 거부하는지 구분 | 실제 shared FS의 동시성·내구성 |
| 4 | fake mpirun→fake child TERM 전달, timeout/KILL, STOP 뒤 쓰기 | 정한 PID 이름공간의 자기 자식 수명·rc·기록 순서 | 실제 OpenMPI/Slurm 랭크 정리와 노드 경계 |
| 5 | 재큐·누락OUT·판 혼합·불완전 압축·두 번째 내용 판정 사본 | 소비자가 거부하고 첫 선택 유지 | 실제 accounting 보존·누락 검출 범위 |

신호 시험은 등록 §7 그대로 `unshare -pf --mount-proc --kill-child` 안의 직접 만든 자식·pid>1만 대상으로 한다. 지금은 실행하지 않는다. 도구/권한이 없으면 자격 미실행으로 남기며 호스트에서 대신 signal을 보내지 않는다. 실물 lmp·MPI를 부르는 가짜 도구 fallback은 허용하지 않는다.

성공한 정상4런에 실패를 주입하거나 과거 장부를 고쳐 시험하지 않는다. 새 실패 자격에서 B 실행 코드 결함이 발견되면 현재 결과를 새 코드 결과와 섞지 않고, 영향·필요한 새 등록을1저자에게 보고한다. 여기서는 그 재실행을 승인하지 않는다.

## 5. 현재 추가 메타 블록을 발급하지 않는 이유

이미 확보한 이름/지정 -D조회·DBIndex·장부 전후 해시·과거 job_detail은 충분히 회수됐다. 같은 조회 반복은 만료된 레코드나 원래 없는 Restarts 필드를 복원하지 못한다. 현재 남은 실패 경로도 읽기 전용 메타 한 번으로 실행 검증할 수 없다. 따라서 **이번 새 현장 블록0**이며, 유지 중인 accounting/운영 기록의 별도 원천이 확인될 때만 그 원천을 읽는 한 블록을 준비한다. root 권한·scheduler 설정 변경·재큐 재현을 요구하지 않는다.

표현 고정: n_rb는 **표지0 랭크 경계 쌍**41/95; 내부 랭크 경계 전체는155/331. 표지1 내부 쌍114/236을 지우지 않는다. 기존 쌍3144/3103, 다·라 결과, n_rb 해석은 수령 문서 그대로다. 이 문서는 결론①–③의 채택문이 아니다.
