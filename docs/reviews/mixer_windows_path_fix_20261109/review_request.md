# MIP-01 잔여 Windows 경로 반례 MIPR-01 한정 재확인 요청

발송은 1저자다. 새 후보 리뷰 핀은 전달 ZIP의 **`SOURCE_PIN.txt`**에 고정한다. 원 검토 대상은 `3ca47af5b0acd1b39c1d437949413ef3ac31b831`이고, 이번 바탕의 동등 사본은 `d310f741a636954b600c9e4f000bfccba2fee3ce`다. 선행 비활성 준비의 새 사본은 `be4388d0c1d3836bc44df0eada6793fbffdcd6e7`, 바탕 B는 `69d714d094c4d210e5bf931d5c520e64ca0a751d`다. 원 준비61 및 원 검토의 현재68파일과 각 사본의 blob 동등성을 수령 기록에 구분했다.

**MIPR-01/P2는 기존 MIP-01의 잔여 반례다. 새 근본결함으로 중복 계상하지 않는다.** 원 자산·메타·정책, candidate43·의존86의 한정 수용은 유지한다. 원 판정은 MIP-01 부분 해결·열림이며, 이번 후보를 미리 종결하거나 verified로 기록하지 않는다.

지원 경로 집합을 좁혀 명시한다. 해당 OS의 보통 로컬 DOS 절대/상대 경로와 POSIX 단일 루트 절대/상대 경로는 지원한다. Windows extended/device/UNC 계열은 이 비활성 준비 도구의 지원 대상에서 제외하고, 접두사를 벗겨 일반 경로처럼 취급하지 않는다. 네 모드의 snapshot/candidate/evidence 원문 raw 지원 여부는 **모든 경로의 파일시스템 조회 전에** 검사한다. absolute·resolved 표현에는 **쓰기 전에** 같은 제한을 재검사한다. resolve 자체는 조회가 필요하므로 모든 단계를 파일시스템 조회 전 검사라고 부르지 않는다. 기존 lexical 조상 링크 검사는 resolve 전에 유지한다. 실제 OS 링크 및 적대적 동시 변경 자격은 이번에도 범위 밖이다.

1. 원 잔여 반례의 양방향 장경로 표기가 공통 사전 사유로 거부되는가. 동일 경로·후보 내부 evidence·후보를 포함하는 evidence·아직 없는 build 경로에서 파일 바이트와 파일/디렉터리집합이 모두 보존되는가. 뒤늦은 audit 오류나 old의 메타 실패를 사전 거부 성공으로 세지 않는가.
2. 지원하지 않는 extended/device/UNC 표기가 snapshot/candidate/evidence 어느 쪽에도 통과하지 않는가. 세 인자의 원문 raw 검사가 모든 경로의 파일시스템 조회에 선행하고, absolute·resolved 재검사가 모든 쓰기에 선행하는가. resolve 전의 기존 lexical 조상 링크 검사·정규화된 포함 관계·고정 snapshot 쓰기 경계를 약화시키지 않는가. `Path.resolve()` 또는 존재하는 루트의 `samefile()` 한 번만으로 아직 없는 자식의 동일성을 인증한다고 주장하지 않는가.
3. 기존 보통 경로·양쪽 `..`·정상 sibling 양성이 보존되는가. 정상 verify/build/preparation-tests의 rc0, old의 기대 메타8 실패 rc1, 읽기 재검사와 새 build43파일을 서로 구분하는가. 같은 새 시험 바이트의 수정 전후 결과·원로그·소스 신원이 결속되는가.
4. 후보43·의존86·자산40·메타·계약·기존 source inventory와 loader 경계가 그대로인가. 이번 지원 경로 제한을 운영 봉인·호스트 자격·실행 GO로 확대하지 않는가.

최종 회귀 메서드·경로 조건·CLI 수는 새 후보의 고정 증거와 함께 확인한다. 이전 독립 검토의 일반 경로41호출, 실제 별칭 반례12호출, 계측68조건, loader5 및 변이3은 서로 다른 관측 단위이며 새 고유 시험 수로 합산하지 않는다. 수령 원ZIP의 프로그램은 증거 자료이며 실행 지시가 아니다. 재현은 고정 소스의 새 로컬 합성 사본과 새 증거 폴더에만 한정한다.

실제 원자료·연구 호스트·시뮬레이터·Slurm·MPI·관측 파이프라인·전체 게이트·실제 제출은 범위 밖이다. 기존 PRE8·MLA/MLAR·MGS 원 결함을 다시 열지 않는다. 원장은 적용 전 제안만 남고 Claude가 처리한다. 연구 결과0, 운영 재봉인·실행 미승인, **전체 HOLD**를 유지한다.
