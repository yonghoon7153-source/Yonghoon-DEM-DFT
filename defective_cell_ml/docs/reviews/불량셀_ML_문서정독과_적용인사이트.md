## 3. 현재 코드에 특히 중요한 다섯 가지

### 3.1 정규화는 필요하지만, 먼저 평가의 독립성이 확보되어야 한다

첨부 Excel의 full 입력은 36특성, OCV를 더하면 37특성이고 셀은 7개다. D03 p.14의 보통최소제곱 역행렬 해는 설계행렬의 열이 독립이라는 조건이 필요하다. 이처럼 특성이 셀보다 많은 경우 비정규화 계수의 유일성을 주장할 수 없다. 의사역행렬로 하나의 해를 계산할 수 있다는 것과 물리적으로 유일한 계수를 알아냈다는 것은 다르다.

양의 정규화 강도를 사용하는 Ridge는 추정을 안정화하므로 현재 기준선으로 유지할 이유가 있다. 반면 Lasso가 어느 주파수를 0으로 만들었다고 그 주파수에 물리 정보가 없다고 결론 내릴 수는 없다. 상관된 특성 중 다른 특성이 역할을 대신했을 수 있다. ElasticNet이나 인접 주파수 계수의 변화를 제한하는 방식은 후속 후보지만, 먼저 기존 Ridge의 검증을 바로 세워야 한다. **D03 p.20–28, D26 p.18–21.**

현재 코드에서는 전체 데이터로 alpha/C를 선택한 후 그 선택값을 고정해 CV 예측을 계산한다. StandardScaler가 Pipeline 안에 있는 것은 올바른 구성이나, 선택 과정까지 독립화된 것은 아니다. 바깥 평가 셀을 제외한 안쪽 데이터에서만 선택해야 한다. 여러 대역 중 최고 점수를 보고 대역을 고르는 과정도 선택에 포함된다. [scikit-learn의 중첩 교차검증 설명](https://scikit-learn.org/stable/auto_examples/model_selection/plot_nested_cross_validation_iris.html)

단, nested CV를 적용해도 7셀이라는 제한과 배치 편향은 남는다. 셀·배치 분리와 중첩 검증은 각각 다른 문제를 다룬다. 기존 ZIP은 셀 하나를 행 하나로 구성하므로 **주파수를 독립 표본으로 나눠 학습한 코드라는 지적은 해당하지 않는다.** 반복 측정이나 시계열을 추가할 때 그 위험을 새로 관리해야 한다.

### 3.2 네 EIS 성분은 네 번의 독립 측정이 아니다

원시 데이터의 같은 주파수에서 복소 임피던스를 Z = a + ib라고 하면, 크기는 √(a²+b²), 위상은 atan2(b,a)로 정해진다. 실수부·허수부·크기·위상은 서로 관련된 표현이다. 허수부의 부호 관례도 확인해야 한다. 현재처럼 각 성분을 따로 보간하면 보간된 점에서 이 관계가 정확히 유지되지 않을 수 있어, 원시 데이터와 구분해 점검할 필요가 있다.

따라서 1 kHz의 네 특성이 모두 도움이 된다는 결과가 나와도 독립적인 물리 원인 네 개를 발견한 것은 아니다. 크기·위상을 추가하면 원시 실수부·허수부에 대한 비선형 표현이 들어가 예측에 도움을 줄 수는 있다. 그 추가 가치는 동일한 평가 셀에서 비교해야 한다. **D03 p.24–28, D15 p.3–9, D22 p.13–17, D26 p.17–21.**

우선 비교할 질문은 다음과 같다.

1. `|Z|@1 kHz` 하나에 비해 같은 주파수의 네 성분이 얼마나 더 설명하는가?
2. OCV만으로 설명되는 부분에 EIS가 추가 정보를 주는가?
3. 고·중·저주파 대역을 추가했을 때 같은 바깥 평가 셀의 오차가 줄어드는가?
4. 특정 셀 하나를 제외하면 계수 부호·선택 대역·결론이 크게 바뀌는가?

이 질문들은 비교 계획이다. 저장된 Excel의 1 kHz 결과는 네 성분 또는 OCV 포함 다섯 특성을 쓴 결과이므로, `|Z|` 단일특성 기준선의 성능으로 인용하면 안 된다.

### 3.3 ‘불량 기준’과 ‘분류 확률’을 분리해야 한다

현재 라벨은 **실측 용량 Q ≤ q₀ = 0.01802088 Ah**인 경우다. 이는 지정 조건의 용량 미달 기준이며, D26의 Normal/Severe 예시와 자동으로 같은 라벨이 되지 않는다. 안전 결함·수명 저하·원인별 결함은 각각 별도 정의와 자료가 필요하다.

| 층위 | 뜻 | 이번 코드에서의 예 |
|---|---|---|
| 물리적 기준 q₀ | 무엇을 용량 미달로 부를 것인가 | 설계용량의 90% |
| 모델 출력 | 용량 추정, 분류 점수 또는 모델 확률 | Ridge의 Q̂, Logistic의 p̂ |
| 운영 판정 t | 어떤 출력에서 재검사·불량 판정을 할 것인가 | p̂ ≥ t |
| 평가 | 불량 누락과 오검출이 얼마나 발생하는가 | FN/TP/FP/TN, 민감도, 오차 |

D14 p.16의 클래스 편향과 임계값 설명은 출발점일 뿐이다. 임계값은 불량 누락 비용, 정상 오검출 비용, 운영 집단의 분포를 고려해야 한다. 평가 정답을 보고 가장 좋은 임계값을 고르면 그것도 튜닝이 된다. [scikit-learn의 분류 임계값 설명](https://scikit-learn.org/stable/modules/classification_threshold.html)

AUC는 점수의 순위 구분 능력을 평가한다. 확률 0.8인 셀 집단에서 실제 약 80%가 용량 미달인지는 별도 문제다. 보정 곡선·Brier/log loss도 데이터 규모와 해석 조건이 필요하며, Brier 개선만으로 보정 자체의 개선을 단정하지 않는다. 현재 7셀에서 촘촘한 보정 곡선을 만들어 신뢰도 검증을 완료했다고 주장하기는 어렵다. [scikit-learn의 확률 보정 설명](https://scikit-learn.org/stable/modules/calibration.html)

특히 현재 불량은 3셀이다. 불량 셀 하나를 놓치면 민감도는 100%에서 약 66.7%로 바뀐다. 저장된 완전 분류 결과는 탐색 결과로 남기고, 성능 표에 분모와 셀별 판정을 함께 보여야 한다.

### 3.4 ‘중요도 평균’은 수정해서 차용해야 한다

D26 p.23은 멤버 모델의 중요도를 평균해 앙상블 중요도를 만드는 설명을 제시한다. 그러나 선형 계수, 트리 불순도 감소, GPR의 역길이척도, permutation에 따른 F1 감소는 정의와 척도가 다르다. 단순 평균에는 공통된 해석이 없다. 각 중요도를 합이 1이 되게 정규화하더라도, 그것이 최종 앙상블 예측의 중요도를 자동으로 측정하는 것은 아니다.

후속 데이터가 확보되면 **최종 예측기 전체를 대상으로, 동일한 독립 평가 자료와 공통 지표에서 특성의 추가 가치를 평가**하는 방향이 적절하다. 상관된 EIS 성분은 묶음별 제거 비교나 permutation을 검토하되, 섞인 입력이 물리적으로 가능한지까지 살펴야 한다. 이 값 역시 모델의 의존도를 설명하며 결함의 인과적 기여를 증명하지 않는다. 상관 특성이 서로를 대신하면 하나씩 섞는 중요도가 작아질 수 있다. [scikit-learn의 permutation importance 설명](https://scikit-learn.org/stable/modules/permutation_importance.html)

**현재 7셀 LOOCV의 평가 fold는 셀 하나이므로, 그 fold 안에서 행을 섞는 일반적인 permutation은 아무 변화도 만들지 않는다.** 이 조건에서 형식적으로 중요도 도구를 실행하는 방식은 피한다. 지금은 계수와 셀별 예측의 민감도를 탐색적으로 기록하고, 중요도 비교는 충분한 평가 셀 또는 사전에 정의한 교차적합 평가 설계가 있을 때 수행하는 편이 낫다.

D26 p.13의 트리 간 중요도 오차막대도 새 제조 배치에 대한 통계적 신뢰구간과 같지 않다. D13 p.12의 attention 시각화 역시 참고 신호다. Attention과 설명의 불일치를 보인 NLP 원전은 배터리 직접 실험은 아니지만, 가중치만으로 원인 설명을 확정하지 말아야 한다는 제한을 뒷받침한다. [Jain & Wallace, 2019](https://aclanthology.org/N19-1357/)

### 3.5 GPR의 좋은 차용점은 ‘추가 검사가 필요한 셀’을 생각하게 한다는 것이다

D26 p.6–7은 GPR의 평균 예측과 불확실성을 설명한다. 이것은 단일 판정값 외에 판단의 불확실성을 기록한다는 점에서 유용하다. 다만 GP는 커널과 잡음 가정을 사용하고, 잡음이 있는 관측에서는 모든 관측점을 정확히 통과할 필요가 없다. 길이척도도 학습 조건에 좌우되며, 특성별 역길이척도를 곧바로 물리 중요도로 해석할 수 없다. [scikit-learn의 Gaussian Process 설명](https://scikit-learn.org/stable/modules/gaussian_process.html)

향후 용량의 예측 분포를 충분히 검증할 수 있다면, **P(Q ≤ q₀ | X)**를 재측정 우선순위에 활용할 수 있다. 이때 잠재 평균 함수의 불확실성과 새 용량 측정값의 잡음을 포함한 예측 불확실성을 구분해야 한다. 커널이 출력하는 분산 자체는 실제 오차에 맞게 보정되었다는 증거가 아니다.

현재 7셀에 특성별 길이척도 수십 개를 추가로 추정하는 방식은 우선순위가 낮다. 소수의 물리 특징, 제한된 커널, 단순 회귀 기준선과의 비교부터 검토한다. 불확실성이 큰 셀만 후속 수집하면 평가 집단이 편향될 수 있으므로 대표성 있는 독립 검증 셀도 별도로 확보한다.

## 4. 딥러닝·생성모델 자료에서 가져올 것과 유보할 것

| 문서 묶음 | 차용할 관점 | 현재 도입 판단 |
|---|---|---|
| CNN, D04·D07 | 이웃 주파수와 여러 대역의 구조. 작은 구조를 공유해 표현하는 관점 | 우선 log-frequency 순서와 소수 대역 특징으로 검토. 7셀에 새 CNN 학습은 유보 |
| 역전파·Dropout·BN, D05·D06 | 손실·정규화·최적화를 구분하고 학습 통계를 평가와 분리 | 현재 Ridge/Logistic을 교체할 근거로 쓰지 않음 |
| RNN·LSTM·GRU·Attention, D09–D13 | 순서, 긴 이력, 미래 입력 차단 | 충방전 시계열과 충분한 독립 셀이 생겼을 때 검토. EIS 주파수축을 시간축과 혼동하지 않음 |
| AE·VAE·EM, D19·D23·D24 | 표현 압축, 잠재적 이질성, 이상 점수의 후보 | 재구성 오차나 군집을 불량 라벨·물리 원인으로 치환하지 않음 |
| GAN·조건부 생성, D21 | 분포 모사와 도메인 차이의 관점 | 생성 결과를 독립 실측으로 세지 않음. 시뮬레이션→실험 변환도 별도 검증 필요 |
| Diffusion, D25 | 잡음 모델과 복원 절차를 명시하는 관점 | 데이터 증강·노이즈 제거 모두 유보. 미약한 불량 신호를 지우는지 검증 필요 |

주파수의 작은 이동이 물리적 시간상수 변화일 수 있으므로 CNN의 pooling이나 주파수 이동 증강을 무조건 불변 변환으로 취급하면 안 된다. D04의 이미지 예제를 EIS에 이전할 때 생기는 조건이다.

VAE에서 표준정규 사전분포를 두었다는 이유만으로 각 잠재축이 접촉손실·전하전달·확산처럼 분리되어 학습되는 것은 아니다. D24 p.6의 해석은 추가 조건이 필요한 설명이다. 잠재축의 물리 의미를 주장하려면 별도 물리 측정이나 제약이 필요하다. 비지도 표현의 분리 가능성에 관한 원전도 추가 가정 없이 이를 보장할 수 없다는 한계를 다룬다. [Locatello et al., 2019](https://proceedings.mlr.press/v97/locatello19a.html)

또한 **D25의 생성형 Diffusion은 잡음을 넣고 되돌리는 확률 과정이며, 배터리의 리튬 확산을 학습했다는 뜻이 아니다.** 모델 이름만으로 확산계수나 Warburg 기전을 얻었다고 연결할 수 없다. 전기화학 모델과의 연결은 별도의 방정식·조건·실측 검증이 있을 때 판단할 사안이다.

## 6. 2차 반증 계획에 반영한 우선순위

### 6.1 먼저 기존 결과의 성립 조건을 확인한다

| 기존 ID | 다음에 확인할 내용 | 이번 문서에서 보완한 관점 | 필요한 근거 |
|---|---|---|---|
| V01 | 7셀과 주석의 약 54셀 결과의 관계, 실행 버전 | 모델 비교보다 모집단·입력 추적이 우선 | 입력 파일 목록, 원본 또는 X·y, 실행 설정 |
| V02 | alpha/C·대역 선택과 평가 분리 | 선택한 모델 전체 절차가 평가 대상 | 별도 재현 환경과 원시 특징 |
| V03 | LOOCV에서 AUC 튜닝의 유효성 | fold별 AUC와 모은 예측의 AUC 구분 | 버전·경고·탐색 결과 로그 |
| V04·V05 | 제외·중복·결측 라벨 처리 | 품질 문제와 실제 불량을 구분; 애매한 셀을 점수 때문에 제외하지 않음 | 파일별 포함/제외 기록, 라벨 생성 경로 |
| V06·V07 | 용량·CC 구간, EIS/OCV의 시점과 조건 | 운영 시점에 사용할 수 있는 입력만 허용 | cycler/EIS 원본, 프로토콜·메타데이터 |
| V08–V10 | 인자명·보간 경계·파일명 규칙 | 보간 후 성분 일관성과 누락 경로도 함께 확인 | 정적 검토 및 추후 제한된 검증 입력 |

V03의 핵심은 AUC에 양쪽 클래스가 필요하다는 점이다. 검증 셀 하나뿐인 각 LOOCV fold의 AUC는 정의되지 않는다. 여러 fold의 예측을 모으면 AUC를 계산할 수 있지만, 그것이 안쪽 C 선택까지 유효했다는 뜻은 아니다. 저장된 C가 모두 탐색 하한이라는 사실만으로 실제 경고 발생을 확정하지 않고, 로그와 재현으로 확인해야 한다.

### 6.2 비교 후보는 작게 시작한다

| 순서 | 비교 대상 | 확인하려는 질문 |
|---|---|---|
| 1 | 학습 셀의 평균 용량/기본 분류 기준선, OCV 단독, 1 kHz 임피던스 크기 단독 | 복잡한 입력 없이 설명되는 수준은 얼마인가? |
| 2 | 기존 Ridge·L2 Logistic, 사전에 제한한 EIS 대역 | EIS와 OCV의 추가 가치가 독립 평가에서도 유지되는가? |
| 3 | 필요가 확인된 경우만 ElasticNet 또는 선형 SVM, 저차원 GPR | 희소성·마진·불확실성 중 실제 목적에 필요한 이점이 있는가? |
| 이후 | 트리/TabPFN·앙상블·시계열/생성모델 | 더 많은 독립 셀·명확한 개선 가설이 마련되었는가? |

이 목록은 지금 모두 학습하자는 계획이 아니다. 같은 바깥 분할을 사용하고, 결과를 본 뒤 선택한다면 선택 과정까지 중첩해야 한다. 현재 표본 수에서 유효한 안쪽 분할이 구성되는지도 먼저 확인한다. 분할을 성립시키기 어려우면 탐색 폭을 줄이고 사전에 고정한 설정의 한계를 명시한다.

현재 단계에서 D26의 9개 모델을 모두 경쟁시켜 최고 정확도를 선택하는 방식은 권하지 않는다. 모델 수가 늘면 선택의 자유도도 늘고, 7셀에서 최고점이 의미하는 바가 더 불명확해진다.

### 6.3 설명과 다음 실험까지 연결한다

추가 검토 항목은 세 가지다.

- **설명 안정성:** 셀 하나에 따라 대역·계수 부호·판정이 달라지는지 기록. 중요도는 예측 의존도로 보고 물리 원인은 별도 검증한다.
- **조건 의존성:** 압력·SOC·온도·배치·휴지시간·측정 순서를 기록하고, 이들이 EIS–용량 관계를 함께 설명하는 가설을 검토한다. 변수를 무조건 모두 보정하지 않고 시간 순서와 가설 관계를 먼저 정한다.
- **후속 실험:** 임계값 근처, 모델 간 불일치, 큰 잔차를 보이는 셀의 재측정을 검토하되 독립 검증 집단의 대표성을 유지한다. 셀을 더 모으는 것과 같은 셀을 반복 측정하는 것은 목적과 정보량이 다르다.

## 7. 이번 단계에서 확정된 것과 남은 것

**확정된 작업:** 추가 PDF 전수 판독, 문서별 기록, 현재 코드·브랜치·관련 litdb와의 연결, 차용 시 보정할 설명 정리, 2차 질문의 우선순위 보완.

**아직 판단할 수 없는 것:** 어떤 모델이 실제로 가장 좋은지, nested CV에서 점수가 얼마나 달라지는지, 어떤 EIS 특성이 불량 원인인지, 7셀이 전체 데이터를 대표하는지. 원본 `.txt/.mpt` 또는 셀별 X·y가 없으므로 성능 재현에 필요한 입력이 부족하다. 기존 Excel의 예측·계수만으로 재학습 입력을 복원할 수는 없다.

다음 2차의 출발점은 **V01 데이터 출처 → V03 AUC 선택 조건 → V02 선택/평가 분리**다. 원시 입력 없이 할 수 있는 정적 반증과 실제 데이터가 있어야 계산할 수 있는 성능 영향을 구분해 진행한다. 3차 변경은 확인된 문제별로 수정안을 검토한 뒤 다룬다.
