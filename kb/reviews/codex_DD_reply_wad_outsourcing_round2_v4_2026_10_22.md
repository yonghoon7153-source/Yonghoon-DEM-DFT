P1-2. 삭제한 Bash rc 검사는 awk 검사와 동등하지 않습니다
위치: 배포 run_all.sh:44, awk 전달:50.
awk -v는 전달받은 문자열의 이스케이프를 해석합니다. 따라서 원문과 awk가 검사하는 값이 항상 같지 않습니다. 이 동작은 GNU 공식 문서에도 명시돼 있습니다. GNU Awk 매뉴얼
예를 들어 손상된 attempt.json에 따옴표 없이 다음 값이 있으면:
"rc": \060,
처리는 다음과 같습니다.
1. 새 grep/sed가 원문 \060 전체를 가져옵니다.
2. awk -v rc="$rc"가 이를 문자 0으로 변환합니다.
3. 정수 정규식이 통과합니다.
4. 나머지 출력이 정상 종료·수렴 조건이면 OK가 됩니다.
\061은 1이 되어 RUN_FAILED가 되고, 사다리 재시도 대상으로 들어갈 수 있습니다. 반면 Python 검사기는 두 기록 모두 JSON 오류로 ATTEMPT_MISMATCH를 냅니다.
즉, “손상된 rc는 승격 없이 보류한다”는 새 계약이 깨집니다. 최종 Python 검사가 이를 거부한다는 점에서 과학값의 최종 통과를 재현한 것은 아니지만, 업체 러너의 채택·재시도 동작이 갈립니다.
이 건은 원문 추출과 Python 거부는 실행 확인했고, awk 변환 이후는 코드와 공식 언어 규약으로 확인했습니다. 이 환경에서 Linux 러너를 직접 재실행한 결과는 아닙니다.
최소 수정은 둘 중 하나입니다.
- awk 전달 전 원문 정수 검사를 복구하고, 실패하면 BAD 같은 값을 넘겨 기존 rc_unknown 경로로 처리.
- 값을 변환하지 않는 전달 방식으로 바꾸고 그 원문을 검사.
F15가 기존 변이시험에서 살아남았다는 사실만으로 중복이라고 판단하면 안 됩니다. 그 시험 집합에는 두 검사를 구별하는 입력이 없었던 것입니다. \060·\061을 gawk/mawk 음성시험에 넣어 둘 다 SCF_UNVERIFIED rc_unknown, 승격 없음인지 확인하면 됩니다.
