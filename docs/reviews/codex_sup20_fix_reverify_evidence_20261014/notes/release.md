## Q2 답의 경계

- **allowed 목록 강제에 동의.** 실제 생산자는 `:1150–1170`에서 승인 철자를 정규화하고 `allowed=[...]`를 반환한다. 정상 소비자 JSON에서는 tuple/set이 될 수 없으므로 이들의 거부는 정상 경로 과잉차단이 아니다. 무변경일 때 키 누락/null을 승인 없음으로 취급하는 종전 규약은 보존된다. 문자열을 거부해 부분문자열 승인 문제를 닫는다.
- **cross_batch.roots 대조에 동의.** `:2550–2552`는 경로 문자열 그대로가 아니라 `_v13_same_path`(realpath·normcase)로 비교한다. 같은 위치의 정상 철자 차이는 통과했다. 생성 당시 배치 디렉터리를 다른 위치로 옮기면 기존 audit/reread도 원래 ROOT에 결합돼 있으므로 단순 경로 재명명만으로 검증할 수 없는 것이 기존 계약이며, 이번 새 과잉차단으로 분류하지 않는다.
- 한 배치 전체의 일관된 증거를 다른 정상 배치의 증거로 전부 바꾸면 여전히 통과한다. 이는 사본 내부 모순을 검출하는 검사이지 외부 진위 서명·수치 재계산이 아니라는 요청서 §5의 공개 한계다. 이번 반례는 그 한계를 없앴다고 주장하지 않는다.
- `code_identity`가 기록한 변화 목록의 진위를 검사기가 새로 재계산하는 것은 아니다. 현행 관문 강화의 정확한 주장은 **두 배치에 같은 기록 계약을 강제**한다는 것이다. 전체 source의 진위·승인의 외부 권한까지 보증한다고 확대하지 말 것.

## 해제 의견

SUP20-01의 네 최소 조건은 구현·합성 검사 층에서 충족한다. 새 194/20 배치를 재계산해야 닫히는 결함이 아니며, 루트 에이전트의 전체 회귀 및 옛 반례 재현 결과가 일치하면 이 건은 verified로 닫아도 된다. 이것이 아직 없는 WSL 발사 핀 사전 점검·입력 영수증·저자 발사 승인을 대신하지는 않는다.
