### CA-P2-01 — 고정 AM의 반력을 “하중을 지지하지 않음”으로 바꿔 말할 수 없다

- 최소 수정: “얼린 AM은 구속 반력을 흡수하지만 AM–AM 하중 전달/강체 운동을 계산하지 않아 물리적인 상별 하중 몫 f를 얻지 못한다. 과압축 원인은 미분리다”로 한정한다. 기존 등록의 f 판정선을 바꾸라는 요청은 아니다.

### CA-P2-03 — 판 변위 간격만으로는 K_safe의 안전성이 보증되지 않는다

- 위치: 메모 `:253–254`의 “지지 폭 + 다시 칠할 사이 최대 변위” 안전 그래프와 판 변위 0.5·1·2셀 재칠 간격.

## Q3: 항복 식의 독립 재계산과 코드 판독

F=diag(b,b,a), R=I, J=ab²로 두었다. 코드의 Kirchhoff 응력은 τ=2μ(F−I)Fᵀ+λJ(J−1)I다. 3D Hencky 편차 노름은 √(2/3)|ln(a/b)|이므로 q=a/b=exp[±√(3/2)σ_y/(2μ)]. 횡응력 0은 `2μb(b−1)+λqb³(qb³−1)=0`이다. q를 대입하고 b 한 변수의 이 식을 풀어 τ_aa/J를 계산했다. 코드의 `dn+1e−9`를 넣어도 아래 반올림은 변하지 않는다(최대 변화 약 2.1×10⁻⁸GPa).

| 재료 | Cauchy 압축 크기 GPa | Cauchy 인장 GPa | Kirchhoff 압축/인장 GPa |
|---|---:|---:|---:|
| E=1.53, ν=.49, σ_y=.30 | .3181717854 | .4535471585 | .3163429172 / .4553701396 |
| E=22.06, ν=.36, σ_y=.30 | .3633297257 | .3716534324 | .3616176571 / .3733687909 |

메모 `:133,534–536`의 .318/.454와 .363/.372는 맞다. √(3/2)×.3=.3674234614GPa는 작은 변형 극한이며 연화 재료에 그대로 쓰면 틀린다. 이 계산은 첫 항복점, 단조 일축 응력, 횡응력 0, 첨가제 없는 `COH=0` 조건이다. 경화·구속 압축·체적 항복 법칙을 의미하지 않는다. `mpm3d_compaction.py:2958–2960`에는 선택적인 응집 응력도 있으므로 그 옵션을 켠 모든 런으로 확대하면 안 된다.

2D 하니스는 3D dev를 그대로 쓰는 것이 아니라 in-plane trace/2를 뺀다(`mpm_dem_match.py:212–218`). NZ22 문턱 .4√(2/3)=.326598632MPa를 이 2D 식에 넣고 plane-strain의 σ_zz=λ(J−1)를 복원하면 3D von Mises 첫 항복응력은 압축 .399315577, 인장 .403195284MPa다. .4와 −.1711%/+ .7988% 차이므로 메모의 “약 1%” 한정 안이다. 이는 작은 변형/plane-strain 독해를 전제로 한 대조이며 3D 일축 숫자와 별개다.

코드 확인 사항:

- AM 전방향 고정, z 구속 충격량만 집계, 판 조건이 그 뒤 z를 덮음: 맞음. 단, 하중 반력이 0이라는 문장에는 CA-P2-01 적용.
- 바닥·비주기 측벽의 상대 접근 성분만 차단하고 접선 마찰 없음: 맞음. `--periodic`에서는 측벽 대신 x/y wrap.
- 3D 판 양방향 고정/2D 판 단방향 차단: 맞음. 압축 중 영향 배제에는 CA-P2-02 적용.
- 한 `grid_v/grid_m`를 공유: 맞음. 다만 “같은 칸을 쓰면 영구적으로 절대로 떨어질 수 없다”는 수학적 구속은 코드에 없다. G2P 위치별 가중합은 서로 다른 물질점에 서로 다른 속도를 줄 수 있다. 직접 확인된 결함은 입자별 속도 불연속/접촉 법칙/traction-free 계면을 별도로 표현하지 않는다는 것이다.
- `dem3d_plastic.py`는 구의 Hertz→소성→lock 하중곡선과 탄성 unload/분리를 가진다. “형상 변형 없음(구)”은 코드와 맞는다. 경도 C_H와 lock 값을 구분해야 한다.

## Q13: 질량 보존·메모리 산술은 조건부로 분리해야 한다

CSV에서 직접 세면 AM_P 36×r6µm, AM_S 421×r2µm, SE 32,832×r.5µm다. 구 부피 합은 AM 46,679.878042, SE 17,190.795000µm³, κ_SE=.2691500525다. `V_p0=(4πr³/3)/N_p`를 원래 입자마다 사용하면 정확한 초기 질량을 보존한다. 같은 V_p0가 질량과 응력 전사 부피 모두에 쓰여야 하고 부모 ID를 유지해야 한다. 이 조치는 겹친 압축 끝 union geometry를 자동으로 복구하지 않으며, 새 느슨한 위치와 무겹침의 확인은 여전히 필요하다.

## Q16: 런 수는 맞고 CPU 기간은 아직 추정이다

기본 런 수는 3a27 + 3bκ1 27 + 3bκ.2 30 + 3c12 = **96**이다. `memo:348`은 24셀 연장을 3a와3bκ1에만 허용하므로 둘 다 연장하면18개를 더해 **114**다. 보고용 A(μ0)를 빼면 각각3개 적다. 약100/약115 표현은 적절하다. 단위시험·수정후 재실행은 이 수에 포함되지 않는다.

부록과 같은 equal-area-fraction PSD 독해에서 number PDF∝d⁻²라 ⟨d²⟩=d_min d_max다. 이를 이용해 면적, 정사각 폭, dx, `dt=.3dx/c_L`, 판속도 `V=Mach·c_S`로 계산했다.

부록의 약값은 재현된다. 3b의 실제 PSD를 개수균일로 해석하면 ⟨d²⟩=1.013333d²이고 equal-area 값 .96d²보다 점·노드는5.56% 커진다. 메모 `:304`의 단순 “균일”과 부록 `:584`의 “면적 분율 균일”을 생성기 등록 때 같은 정의로 적어야 한다. 이 차이는 CPU 추정을 확정치로 쓰지 말아야 할 이유이며 새 분포를 선택하라는 요청은 아니다.

3a와3bκ1만 부록 목표 Φ까지 전부 진행한다고 가정해도 8/12/16셀×9팔은 약6.70×10¹¹ particle updates다. 이를 쉬지 않고7/14일에 끝내려면 약1.108/.554 million updates/s가 필요하다. 여기에 κ.2·3c·접촉·단위시험·재시도가 빠져 있다. 실제 CPU 처리율을 측정하지 않았으므로 1–2주를 긍정/부정할 근거는 없다. 메모의 [추정] 표지는 유지해야 한다.

GPU를 Rint②에 남기고3D를 R런 뒤로 둔 순서는 `docs/session_20260923_progress.md:1268`과 부합한다. 다만 “CPU만 사용”은 같은 서버의 CPU/RAM/개발시간 충돌까지 없다는 증거가 아니다. CPU 장소/코어·RAM·우선순위가 등록되기 전에는 자원 충돌 없음도 조건부다. 이번 검토는 실제 호스트나 최신 일정을 조회하지 않았다.
