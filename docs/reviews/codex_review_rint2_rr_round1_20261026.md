## 3. RR1-01 [P2] — 알려진 k=0 경계가 실제 거짓 clear를 만든다

**영향:** RCA2-04의 끝 증서 귀속, “위상 수가 같으면 같은 반사실 계를 인증한다”는 해석. 정상 producer의 자연 오계산이나 RCA2-01 구간 산술 오류는 아니다. 현재 등록 문턱에서 실침대가 오판됐다는 주장도 아니다.

### ① 같은 프로세스라는 문구를 실제 보장으로 고칠 것

Q9 :34,57,171,196은 “같은 프로세스”라고 한다. 실제 `rint_r_chain.py:1472–1474,1531–1532`는 한 사슬 부모가 환경을 캡처하고 **런마다 새 bash 자식**을 만든다. 사전 공격 4차 원문 :37의 해석도 같은 coordinator의 자식들이다. 사다리 끝으로 옮기기만 해서 같은 solver 프로세스가 되는 것은 아니다.

또 Q9 :144는 끝난 확인 팔을 복사한 뒤 실패한 no-op만 새로 실행한다. 부모가 죽은 뒤 재개라면 같은 부모조차 아니다.

권고 문구:

> 정상 경로의 확인 팔과 no-op은 같은 사슬 부모가 동결한 실행 환경에서 수행한다. 재개는 새 프로세스에서 수행하며 원 시도의 전체 환경 지문을 대조한다. 남은 payload는 bytes를 대조하고, 없는 결과의 동일성은 결정성 가정으로 남긴다.

부모 PID만 같으면 “같은 solver 프로세스 보장”이라고 통과시키지 말라. 문자 그대로 같은 solver 프로세스가 필요하다면 persistent worker와 죽은 worker의 재개 예외를 별도로 설계해야 한다. 새 수치 오계산으로 세지는 않는다.

### ② 부모 사망에도 종료 확인이 살아남아야 한다

Q9 :128의 불변식, **그룹 전체 종료 후 결과 줄 확정**, 은 옳다. 하지만 SIGKILL당한 부모 자신의 finally로는 정리할 수 없다. 별도 supervisor/recovery 또는 실행 격리 단위가 종료를 확인한 뒤 표지·payload·폴더 해시를 확정해야 한다. 확인 못 한 호스트는 미확인으로 남기고 다음 시도 채택을 막는다.

독립 무해 프로세스 시험(Windows, solver 없음): 부모 종료 직후 표지 없음 → 살아남은 자식이 뒤늦게 표지를 썼다. 이는 Linux 구현 시험을 대체하지 않는다. **부모 사망+현재 표지 없음이 전체 그룹 종료 증거가 아니라는 반례**다. §8 :222의 러너만 죽이는 시험과 :223의 사슬 부모를 죽이는 시험을 분리하라. 다음 결과 줄을 쓰기 전에 끝났다는 불변식이 구현되면 이 반례는 차단된다.

### ③ 구조가 같아도 최종 등급이 다르면 다시 판정 동일이 아니다

실제 `grade_W`는 W=`0.4539694765685022`에서 PASS_INFORMATIVE, 한 ULP 위 `0.45396947656850223`에서 CONSISTENT_WEAK다. 이는 특정 두 플랫폼의 실제 libm 차이를 측정한 결과는 아니다.
