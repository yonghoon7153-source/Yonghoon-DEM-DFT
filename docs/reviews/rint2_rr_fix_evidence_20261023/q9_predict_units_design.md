## 0. 이번에 정하는 것 / 정하지 않는 것

- 정하는 것 (설계): 예측 단계의 실행 단위 · 합치기 · 넘침 런의 순서 · 출처 대조 항목 · 시도 원장 (개정 1) · no-op 의 기계 (개정 1).

## 1. 왜 나누나

- 지금 사슬 (`scripts/rint_r_chain.py`):

## 3. 설계

### 3-1. 단위 (1저자 Q9 (가) · 개정 1 Q15 (가))
- 단위 = (c, 법칙, R) 12 개.
  - 한 단위 = 그 점의 모서리 arm 0 (+ SV 반사실 아래 · 필요하면 위끝) + origin 표본 arm 1 · 2.
  - 한 단위는 한 기계에서 끝까지 돈다.  그래서 origin 퍼짐 비교 (arm 0 ↔ arm 1 · 2) 는 한 기계 안이다.
- **no-op 단위 (개정 1 · Q15 (가))** = 법칙마다 하나 (no-op_P0 · no-op_P1).  **그 법칙의 사다리를 돈 기계에서 돈다** — 사다리 요약의 기계 이름 = no-op 단위의 기계 이름 (다르면 합치기 멈춤 `NOOP_MACHINE_MISMATCH`).
  - 이유 (사전 공격 D2 · 실측): 같은 코드 · 같은 스레드 수라도 BLAS 계산 경로 (`OPENBLAS_CORETYPE`) 만 바뀌면 σ 가 상대 1.3e-10 – 5.8e-10 다르다.  no-op 은 사다리 값과 float 같음을 대조하므로 (등록 §4-1 · ⑩ 그대로) 기계를 넘으면 정상 런도 `SAME_P_CONSISTENCY` 로 멈춘다.
  - 이 규칙은 지금 사슬을 두 대로 돌릴 때 (사다리는 나누고 예측은 한 기계) 도 같다 — 예측 기계가 한 법칙의 사다리 기계와 다르면 그 법칙의 no-op 은 사다리 기계에서 따로 돈다.

### 3-2. 세 명령 (이름 · 인자는 구현 때 정하는 꼴)
1. 단위 실행 — `--stage predict --units <단위…> --machine <이름> --attempt <원장 항목>`.
   - 고른 단위의 늘 필요한 런만 돈다.  단위 폴더 요약에 출처 (§3-3) 와 원장 항목 (§3-5) 을 남긴다.
2. 합치기 — `--stage predict --merge <단위 · 넘침 시도 폴더 전부…> --ledger <시도 원장> --out <예측 폴더>`.
   - §3-4 · §3-5 를 대조한 뒤 채택된 시도의 런으로 다시 계산한다 (같은 판정 함수 · fetch = 키로 찾기 · 한 번씩).
   - **fetch = 지금 사슬의 `read_run` 을 채택된 단위 폴더의 런 폴더에 그대로 돌린다 (개정 1 · D4)** — 러너 기각 표지 (`.rejected_*`) · 영수증 없음 · 증서 · 기록 계약 실패 = 한 기계 사슬과 같은 멈춤.  통과한 런 폴더는 **통째로** (팔 · 영수증 · 표지 · 로그) 바이트 그대로 복사한다 (sha256 대조).  팔 파일만 옮기지 않는다.
   - **첫 합치기 = origin 판정까지만 (개정 1 · D5)** — no-op · 모서리 · same_p · W0 · origin 표본 판정을 같은 함수로 다시 계산해 넘침 목록 (모서리, R) 을 정한다.  지금 코드처럼 모서리마다 origin8 을 바로 부르지 않는다 (그 순서로는 첫 넘침 모서리에서 끊겨 목록 전체가 안 나온다).  origin8 · 8 팔 평균 · R 단조는 자리 표시 값으로 돌리지 않는다.
     - 넘침 없음 → 바로 끝까지 (아래 "끝 합치기" 와 같음).
     - 넘침 있음 → 상태 `EXPANSION_NEEDED` + 결정 기록 (넘침 목록 · 채택된 단위 폴더 요약 sha256 집합 · W0 · 원장 sha256).  멈춤도 판정 입력도 아니다.
   - **끝 합치기** = 넘침 런까지 모인 뒤: 첫 합치기 계산을 다시 해 결정 기록과 대조 (넘침 목록 · 단위 sha 집합 · W0 같아야 · 다르면 `UNIT_PROVENANCE_MISMATCH`) → 지금 `Predict.run` 과 **같은 요청 순서**로 끝까지 (origin8 · 8 팔 평균 · R 단조 · 값) → 지금과 같은 꼴의 예측 폴더.
     - 런 기록 (`runs`) = `Predict.run` 이 요청한 런만 · 요청 순서 그대로 (판정 단계 `Replay` 가 지금 그대로 읽는다).
   - **등록된 결과로 일찍 끝날 때 (개정 1 · D1)** — `NOT_COMPUTED` (단락 · 증서 실패) · 등록 멈춤으로 다시 계산이 일찍 끝나면 그 결과가 곧 예측 결과다 (한 기계 사슬과 같은 상태 · 같은 런 수).  요청되지 않고 남은 단위 런은 출처 칸 `unused_runs` (폴더 · sha256) 에만 남긴다 — 멈춤 아님 · `runs` 에 넣지 않음 · 판정 입력 아님.
   - 다시 계산이 끝까지 갔는데 남는 런 = 멈춤 `UNIT_EXTRA` (요청되지 않은 origin8 등) · 요청된 런이 없음 = `UNIT_MISSING` (넘침 런만 없으면 `EXPANSION_NEEDED`).
3. 넘침 실행 — `--stage predict --expand <결정 기록> --points <(모서리, R)…> --machine <이름> --attempt <원장 항목>`.
   - 결정 기록이 요구한 origin8 런만 돈다.  결정 기록 sha256 을 출처에 남긴다.  끝나면 끝 합치기.
- 지금처럼 `--stage predict` 한 번 (단위 전부 · 한 기계) 도 그대로 둔다.  끈 경로 = 비트 같음.

- 침대 지문 (Q3: 시작 직전 킷 파일을 다시 해시).
- 환경 지문 (Q2 ⑤: python · numpy · scipy 판 = 같아야 한다 · cupy · CUDA · GPU 이름 · BLAS 계산 경로 (`OPENBLAS_CORETYPE` · 라이브러리 정보) = 기록만 — 기계를 넘는 float 같음 비교는 §3-1 로 없앴고, 남은 기계 간 비교 (W0 · same_p · 판정) 는 등록 허용폭이 있는 비교다).
- 두 사다리 요약 sha256 · 변이 · after_main.
- 기계 이름 (필수 · 계획의 허용 목록 안 · Q11) · 원장 항목 (§3-5 · 시도 번호는 폴더 자기 신고가 아니라 원장에서 온다).

### 3-4. 합치기 대조
- 단위 12 개 · no-op 2 개마다 **채택된 시도가 정확히 하나** (§3-5 규칙으로 고른다 · 폴더 수가 아니라 채택 수).
- 넘침 런 = 결정 기록이 요구한 것만, 채택된 시도가 정확히 하나씩.
- 위 출처 칸이 모든 채택 폴더에서 같다.  다를 수 있는 것 = 기계 이름 · 원장 항목 · 단위 이름뿐.
- 기계 = 허용 목록 안 · 빈 이름 = 멈춤 · no-op 기계 = 그 법칙의 사다리 기계 (§3-1).
- 합친 예측 폴더 요약에 `units` (채택 폴더 · 요약 sha256 · 기계 · 원장 항목) · `unused_runs` · 결정 기록 sha256 · 원장 sha256 을 남긴다.  판정 · 다시 판정 (`--reverify`) 이 같은 대조를 다시 한다.

### 3-5. 시도 원장 (개정 1 · Q16 (가) · 사전 공격 D3)
- 원장 = 덧붙이기만 하는 파일 하나 (계획 봉인과 같은 리포 · 계획 sha256 에 묶임).  시도를 시작하기 **전에** 항목을 커밋한다: (단위 | no-op | 넘침 점) · 기계 · 시도 번호 (원장 안 순서) · 계획 · 코드 · 침대 · 환경 지문.
- 시도가 끝나면 결과 줄을 덧붙인다: 완주 / 멈춤 (원 사유 · 결과 전 멈춤 (관문 · 환경 · 기계 자원) 인지 결과 뒤 멈춤 (불수렴 · 사다리 소진 · 수치 · 물리) 인지 = Q4 분류 그대로).
- 합치기는 단위마다 **원장의 시도 전부와 그 폴더 전부**를 받는다:
  - 원장에 없는 폴더 · 폴더 없는 원장 시도 (결과 줄에 사유가 없는 것) = 멈춤 `ATTEMPT_LEDGER_MISMATCH`.
  - 채택 = 원장 순서로 처음 완주한 시도.  그 앞의 시도는 결과 전 멈춤이어야 한다 — 결과 뒤 멈춤이 앞에 있으면 그 단위는 같은 등록의 재시도가 아니다 → 합치기 결과 = 그 멈춤 (Q4 · 뒤 시도를 채택하지 않는다).
  - 최대 시도 수 (Q4 · 숫자 = 봉인 때 1저자) 넘침 = 멈춤.
- 그래서 단위 ↔ 기계 배정은 봉인하지 않아도 된다 (기계 하나가 멈추면 다른 기계가 이어받는다) — 대신 어떤 시도를 썼는지는 사람이 아니라 원장과 규칙이 정한다.
- 기계마다 비트가 조금 다르므로 (§3-1) 칼날 판정 (origin W0 · SV 걸침 · 단조 띠) 은 배정에 따라 뒤집힐 수 있다 (빈도 = 작을 것 · 추정).  원장은 결과를 본 뒤 배정을 고르는 길을 막는다 — 칼날 자체를 없애지는 않는다 (한정).

## 4. 같음의 근거 (같은 팔 기록 → 같은 요약 · 같은 판정)

- 끝 합치기는 지금 `Predict.run` 과 같은 판정 함수 · 같은 요청 순서로 돈다.  바뀌는 것은 fetch 하나뿐이다: "기록을 순서대로 읽기" (`Replay`) 대신 "채택된 단위 폴더에서 키로 찾기 (한 번씩) + 같은 `read_run`".
- 첫 합치기 (origin 판정까지) 는 같은 판정 함수의 앞부분을 따로 부른다 — 넘침 목록이 한 기계 사슬과 같아야 한다 (시험).
- 판정 규칙 코드 (W0 · origin · same_p · SV · R 단조) 는 한 곳에 그대로 있다.
- 한 기계 사슬과 같지 않을 수 있는 것 (한정): 기계마다 다른 비트 (§3-1 · §3-5) — 같은 팔 기록을 넣으면 같은 결과지만, 같은 단위를 다른 기계에서 돌린 팔 기록은 비트가 다를 수 있다.
- 시험: 같은 합성 계약에서 (a) 한 번에 돈 예측 (b) 12 단위 + no-op 2 → 첫 합치기 (→ 넘침 → 끝 합치기) 두 길의 공개 칸 (상태 · 검사 · origin · 값) 과 판정 단계 결과가 같아야 한다.

## 5. 기계가 섞일 때

- 단위 안의 비교 (origin 퍼짐) = 한 기계.  no-op ↔ 사다리 (float 같음) = 한 기계 (§3-1).
- 기계를 넘는 비교 = W0 (12 모서리의 퍼짐 — 물리적으로 다른 점끼리) · same_p (c 0 ↔ c 1 · τ_mono = 1e-3 · 기계 간 실측 차 ≤ 5.8e-10 = CPU 경로 · GPU 는 미확인 · 추정 = 같은 자릿수 이하) · R 단조 (증서 구간 · 같은 모서리의 세 R 는 서로 다른 단위 = 다른 기계일 수 있다) · 판정.
- 팔마다 증서 ⓓ 가 있다.  증서 계산은 CPU numpy (`scripts/step3_conv_cert.py` · cupy 를 쓰지 않음) 이고, GPU 풀이 결과를 팔마다 따로 검증한다.
- 대안 (§9 Q-C): 단위 = (법칙, R) 6 개 (c 0 · c 1 을 한 단위로).  same_p 도 한 기계 안이 되고, 두 대 · 세 대에서 시간은 같다 (§6).  사전 공격 리뷰 답 = same_p 는 기계를 넘어도 된다 · 6 단위로 해도 no-op 문제 (D2) 는 안 풀린다 (§3-1 로 푼다).
