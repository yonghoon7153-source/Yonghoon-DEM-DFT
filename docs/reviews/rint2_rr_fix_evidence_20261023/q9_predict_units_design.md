## 0. 이번에 정하는 것 / 정하지 않는 것

- 정하는 것 (설계): 예측 단계의 실행 단위 · 합치기 · 넘침 런의 순서 · 출처 대조 항목.
- 정하지 않는 것: 숫자 (시간 상한 · 최대 시도 수) · 판정 규칙 · 단위 ↔ 기계 배정 (봉인하지 않는다 — §9 Q-D).

## 1. 왜 나누나

- 지금 사슬 (`scripts/rint_r_chain.py`):
  - 사다리 = 법칙마다 한 단계 (`--stage ladder --law P0` · `P1`) → 두 기계에 나눌 수 있다.
  - 예측 = 한 단계 = 한 기계 (`stage_predict` 가 네 모서리 × 세 R + origin + SV 를 한 프로세스에서 차례로 · 등록 ㊵).
- 시간의 대부분은 DBE 예측 풀이다.  그래서 기계를 늘려도 지금 사슬은 거의 안 빨라진다 (§6 표).

## 2. 예측 단계 안의 의존 (지금 코드 `Predict.run`)

1. SBE no-op — 법칙마다 c 1 · R_j0 · SBE 킷 한 런.  사다리 값과 비트 대조.
2. 모서리 arm 0 — 법칙 × R × c 12 런 (+ SV 반사실 · all3 · arm 0).  서로 독립.
3. same_p 검사 — 같은 (법칙, R) 의 c 0 ↔ c 1 쌍.
4. W0 · W_pos — 12 모서리 arm 0 값 전체의 퍼짐.  **모든 모서리가 끝나야** 정해진다.
5. origin 표본 — 모서리 × R 마다 arm 1 · 2 한 런.  런 자체는 결과와 무관하게 늘 필요하다.  넘침 판정 (`dbe_origin_ok(vv, W0)`) 만 W0 에 달린다.
6. 넘침 — 한 R 이라도 넘으면 그 모서리 세 R 전부 origin8 (8 팔) 런 → 8 팔 평균.

⇒ 1 · 2 · 5 의 런은 늘 필요하므로 나눠 돌릴 수 있다.  4 · 6 은 모든 단위가 모인 뒤에만 정해진다.

## 3. 설계

### 3-1. 단위 (1저자 Q9 (가))
- 단위 = (c, 법칙, R) 12 개.
  - 한 단위 = 그 점의 모서리 arm 0 (+ SV 반사실 아래 · 필요하면 위끝) + origin 표본 arm 1 · 2.
  - no-op 두 런은 법칙마다 (c 1, 법칙, R_j0) 단위에 붙인다.
- 한 단위는 한 기계에서 끝까지 돈다.  그래서 origin 퍼짐 비교 (arm 0 ↔ arm 1 · 2) 는 한 기계 안이다.

### 3-2. 세 명령 (이름 · 인자는 구현 때 정하는 꼴)
1. 단위 실행 — `--stage predict --units <단위…> --machine <이름>`.
   - 고른 단위의 늘 필요한 런만 돈다.  단위 폴더 요약에 출처 (§3-3) 를 남긴다.
2. 합치기 — `--stage predict --merge <단위 · 넘침 폴더…> --out <예측 폴더>`.
   - §3-4 를 대조한 뒤, `Predict.run` 을 그대로 다시 돈다 (fetch = 키로 찾기 · 한 번씩).
   - 필요한 런이 다 있으면: 지금과 같은 꼴의 예측 폴더를 만든다.
     - 런 기록 = `Predict.run` 의 요청 순서.  팔 파일 = 단위 폴더에서 바이트 그대로 복사 (sha256 대조).  `units` 출처 칸을 더한다.
     - 판정 단계 (`--stage verdict`) 는 지금 그대로 이 폴더를 읽는다.
   - origin8 런이 없는데 넘침이면: 상태 `EXPANSION_NEEDED` 와 필요한 (모서리, R) 목록을 결정 기록으로 쓴다.  멈춤도 판정 입력도 아니다.
   - 그 밖의 런이 없으면 멈춤 (`UNIT_MISSING`).  쓰이지 않은 런이 남으면 멈춤 (`UNIT_EXTRA` — 요청되지 않은 origin8 등).
3. 넘침 실행 — `--stage predict --expand <결정 기록> --points <(모서리, R)…> --machine <이름>`.
   - 결정 기록이 요구한 origin8 런만 돈다.  결정 기록 sha256 을 출처에 남긴다.  끝나면 다시 2 (합치기).
- 지금처럼 `--stage predict` 한 번 (단위 전부 · 한 기계) 도 그대로 둔다.  끈 경로 = 비트 같음.

### 3-3. 단위 · 넘침 폴더 출처 (묶음 B · C 의 칸을 그대로 쓴다)
- 계획 sha256 · S0 계획 · S0 보고 기록.
- 코드 기록 (Q2: git 엄격 · 저장소 상대 경로 지문 · chain ↔ runner).
- 침대 지문 (Q3: 시작 직전 킷 파일을 다시 해시).
- 환경 지문 (Q2 ⑤: python · numpy · scipy 판 = 같아야 한다 · cupy · CUDA · GPU 이름 = 기록만).
- 두 사다리 요약 sha256 · 변이 · after_main.
- 기계 이름 (필수 · 계획의 허용 목록 안 · Q11).  시도 번호 (Q4).

### 3-4. 합치기 대조
- 단위 12 개가 정확히 한 번씩 있다 (빠짐 · 겹침 = 멈춤).
- 넘침 런 = 결정 기록이 요구한 것만, 정확히 한 번씩.
- 위 출처 칸이 모든 폴더에서 같다.  다를 수 있는 것 = 기계 이름 · 시도 번호 · 단위 이름뿐.
- 기계 = 허용 목록 안.  빈 이름 = 멈춤.
- 같은 단위의 시도가 여럿이면 Q4 규칙: 처음 완주한 시도를 채택 · 결과 뒤 멈춤의 재시도 = 같은 등록이 아님.
- 합친 예측 폴더 요약에 `units` (폴더 · 요약 sha256 · 기계 · 시도) 와 결정 기록 sha256 을 남긴다.  판정 · 다시 판정 (`--reverify`) 이 같은 대조를 다시 한다.

## 4. 같음의 근거 (같은 팔 기록 → 같은 요약 · 같은 판정)

- 합치기는 `Predict.run` 을 그대로 돈다.  바뀌는 것은 fetch 하나뿐이다: "기록을 순서대로 읽기" (`Replay`) 대신 "키로 찾기 (한 번씩)".
- 판정 규칙 코드 (W0 · origin · same_p · SV) 는 한 곳에 그대로 있다.
- 시험: 같은 합성 계약에서 (a) 한 번에 돈 예측 (b) 12 단위 → 합치기 (→ 넘침 → 합치기) 두 길의 공개 칸 (상태 · 검사 · origin · 값) 과 판정 단계 결과가 같아야 한다.

## 5. 기계가 섞일 때

- 단위 안의 비교 (origin 퍼짐) = 한 기계.
- 기계를 넘는 비교 = W0 (12 모서리의 퍼짐 — 물리적으로 다른 점끼리) · same_p (c 0 ↔ c 1 · τ_mono = 1e-3) · 판정.
- 팔마다 증서 ⓓ 가 있다.  증서 계산은 CPU numpy (`scripts/step3_conv_cert.py` · cupy 를 쓰지 않음) 이고, GPU 풀이 결과를 팔마다 따로 검증한다.
- 대안 (§9 Q-C): 단위 = (법칙, R) 6 개 (c 0 · c 1 을 한 단위로).  same_p 도 한 기계 안이 되고, 두 대 · 세 대에서 시간은 같다 (§6).
