## 검증 수의 구분

외부 실행 기록은 Python3.11.17/3.8.20 각각 기존20·출력13·독립18 통과다. 독립 JSON의 19번째 기록은 느린 입력 관찰이며 회귀 통과 수에 넣지 않는다. 외부 보호 제거 변이5개는 각 suite rc1(의도한 음성 대조), runner rc0이다. missing_flush는 11 PASS/1 FAIL/1 ERROR로, ERROR를 누락하거나 별도 정상 실패라고 세지 않는다.

이 창에서는 완료된 전체 suite·변이·느린 입력을 반복하지 않았다. 새 OBS 기전만 원본 probe의 해당 블록을 그대로 추출해 현재 명령/기존 시험 소스에 실행했다. 각 Python에서 **합성 기준1회 rc0 → 무관 sibling 생성·삭제 주입1회 CHANGED/rc2**를 확인했다. 연구 root가 아닌 TemporaryDirectory의 30개 합성 case만 사용했다. `_repro_ours_20261104/`에 추출 provenance와 두 버전 결과가 있다. 새 관측과 외부18개를 더해 시험 수를 만들지 않는다.

최초 test17의 assertion은 inventory 반환값 기대0/관측2에서 멈췄다. 쓰기 검출 assertion에 도달하기 전이므로 “쓰기 발생을 검출했다”는 뜻이 아니다. 최초 로그에는 어느 root/case가 왜 거부됐는지 없어서 위 합성 기전을 최초 사건의 원인으로 단정하지 않는다. 과거 실패·순차 통과·외부 재검증은 원본 ZIP과 이전 수정 폴더에 그대로 보존한다.
