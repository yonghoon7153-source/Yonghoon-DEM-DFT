# ADR 0006 — Canva PDF 전수조사는 사람이 아니라 검사기가 한다

- 상태: 채택 (2026-09-27)
- 관련: `scripts/audit-canva.mjs`, `data/raw/canva-text.json` · `canva-audit.json`, ADR 0002 · 0005, 체크리스트 #34 · #37

## 맥락

1차 전수조사(#34)는 "PDF 글줄이 데이터 어딘가에 들어 있나" 를 **부분 문자열**로 찾았다.
그래서 지도 둘레의 北(きた) · 東(ひがし) · 西(にし) · 南(みなみ) · 右(みぎ) · 左(ひだり) 가 빠진 걸 못 봤다 —
「きた」 는 「あきた」 안에, 「にし」 는 「にしんそば」 안에 있었으니까. 사용자가 직접 찾아냈고
"이렇게 빠진 거 없는지 확실하게" 를 부탁했다. 같은 방식으로는
- 같은 말이 두 번 나오는 것(「治安が悪い」 두 곳, 「高い」 네 곳)의 한 쪽이 빠져도,
- 예전에 말없이 고쳐 둔 오타(「約束1時間」→「約1時間」)도,
- 내가 붙인 말이 사용자의 말처럼 notes.json 에 들어간 것도
보이지 않는다.

## 결정

1. PDF 의 글줄 837개(글자 · 위치 · 크기 · 색)를 `data/raw/canva-text.json` 에 둔다.
2. `nihon audit` 가 글줄을 하나씩 데이터에서 **소모**하며 찾는다.
   - 메모 칸(notes.json 등)의 글자는 나온 횟수만큼만 쓸 수 있다 — PDF 에 두 번이면 데이터에도 두 번.
   - 이름(県 · 지방 · 도시 · 区 · 산맥 · 방위 · 화면 제목)은 몇 번이든 쓸 수 있다 — PDF 가 지도와 칸에 되풀이하니까.
     마스코트 이름은 통째로만 (「치바」 는 「치바쿤」 안에서 찾지 않는다).
   - 통째로 없으면 괄호 · 쉼표에서 나눠 조각마다 찾고, 하나라도 없으면 그 줄은 없는 것.
3. 데이터에 일부러 그대로 두지 않은 줄은 `data/raw/canva-audit.json` 에 **이유와 함께** 적는다.
   `fixed` = 사용자 비준으로 고침, `pending` = 사용자 답을 기다림.
4. `nihon check` 가 이 검사를 돌린다 — 이유 없이 빠진 줄이 있으면 push 전에 멈춘다.
5. `nihon audit --list` 는 줄마다 어디로 갔는지와, 거꾸로 **PDF 에 없는데 데이터에 있는 말**(내가 붙인 말)을 보여 준다.

## 결과

- 2차 대조에서 찾아 넣은 것: 방위(지도 둘레, 라벨 모드를 따름), 다리 박스 제목 「四国につなぐ大きな橋」 과 노선별 캡션,
  23区 지도의 순위(犯罪率↓ 2·3위, 治安が悪い 1·2·3위)와 빨간 읽기, 根釧台地 동그라미, 中央高地 「山↑」.
- 예전에 말없이 고친 오타 7개와 표준과 다른 한글·かな 박스 표기 4개는 notes.json(사용자의 말)을 고쳐야 해서
  사용자 답을 기다린다 (`pending`).
- 사용자가 캔바를 고쳐 PDF 를 다시 주면 `canva-text.json` 만 새로 뽑으면 된다.
