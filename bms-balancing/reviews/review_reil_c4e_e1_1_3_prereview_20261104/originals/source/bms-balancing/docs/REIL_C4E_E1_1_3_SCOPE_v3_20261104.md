## 3. 정할 것 1 — launcher 를 어떻게 띄우나 (E113_N2 · F1–F3 반영)

- **사실:** 셸 도구의 상한은 전경 600 s · 배경 7,200 s 이고, 배경 상한에 닿으면 명령을 멈춘다. run 의 자식 timeout 은 10,800 s 이고, identity · fetch 도 명시
  timeout 의 합이 실제 반환의 상한이 아니다 (§1). launcher 는 자식을 새 세션으로 띄운다 (786 행) · meta 쓰기에 실패하면 외부 stderr 에 첫 오류
  (`meta_write_failed`) 를 쓰고 rc 4 를 낸다 (908–912 행) · 그 밖에는 외부 stdout 에 단계 요약 한 줄을 쓰고 0 (complete) / 1 을 낸다.
- **A (권장) — 세 단계 모두 같은 분리 실행 wrapper + 읽기 전용 감시 + 정해 둔 실패 종결.** 범위의 요구는 아래이고, 정확한 명령 · 형식 · 관측과 허용 정리
  행위는 요청서에 고정해 승인을 받는다.
  1. **외부 출력 보존:** wrapper 가 launcher 의 stdout · stderr 를 `<E>/<단계>.outer_stdout.txt` · `<E>/<단계>.outer_stderr.txt` 로 배타 생성해 받는다
     (`/dev/null` 0). 자식의 `<단계>.stdout.log` · `stderr.log` 와 다른 자료다.
  2. **실행 식별 · 시작 상태:** wrapper 가 launcher 를 띄우기 전에 `<E>/<단계>.outer_start.txt` 를 배타 생성한다 — UTC · wrapper PID (= `setsid` 의 세션 id) ·
     감시 절대 기한.
  3. **완전한 반환 게시:** wrapper 는 launcher 반환을 임시 이름에 쓰고 닫은 뒤 최종 이름 `<E>/<단계>.outer_rc.txt` 로 배타 게시한다 (이미 있으면 실패 — 최종
     이름이 보이는 순간 내용이 완전하다). 감시와 판정은 최종 이름의 존재와 형식 (`^[0-9]+\n$`) 을 함께 본다 — 존재만으로 판정을 시작하지 않는다.
  4. **첫 절대 감시 기한:** 시작 기록의 절대 시각 하나 — identity 착수 + 900 s · fetch + 1,800 s · run + 12,600 s (자식 timeout + 여유 · 여유는 정책 값이지 실제
     반환 상한의 보증이 아니다). 감시는 셸 도구 배경 실행의 읽기 전용 루프이고, 도구 상한 (2 h) 에 끊기면 같은 절대 시각으로 다시 건다 — 새로 세지 않는다.
     감시를 다시 거는 것은 run 을 다시 띄우는 것이 아니다.
  5. **실패 종결 (모두 다음 단계 차단 · 재시도 0 · 미완 기록 · 끝 기록 작성기가 사유를 그대로 남김):** 시작 실패 (띄운 뒤 60 s 안에 시작 기록 · 외부 출력
     파일이 없음) · 기한까지 반환 미게시 · 형식이 틀린 반환 (부분 기록 · 임시 이름만 남음) · 감시 기한 도달. 반환이 0 이 아니면 launcher 의 단계 실패다.
