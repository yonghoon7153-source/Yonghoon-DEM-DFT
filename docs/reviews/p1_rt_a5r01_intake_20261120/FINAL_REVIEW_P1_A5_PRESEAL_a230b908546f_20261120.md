**제목: kebase 완료 기록 쓰기 실패가 전파되지 않고, 누락된 완료 영수증도 다음 관문이 허용함.**

| 영향 | 계산이 성공했더라도 완료 기록이 빠진 작업을 후속 관문이 완료로 소비함. 사후 모순 입력도 같은 누락 검사로 허용 |

`note()`는 `echo ... >> "$MAN"` 실패를 반환하지만 `reader()`는 그 반환을 검사하지 않고 원 판독기 rc만 반영한다. 한편 `admits()`는 발행 전 접두부·증서 원바이트 SHA·`reader_restore_rc=0`·마지막 고유 end만 확인하며, 발행 뒤 필요한 `reader_kebase_rc`의 존재·개수·값은 확인하지 않는다. 이 tail은 증서의 접두부 해시에 포함되지 않는다.

**실제형 최소 반례:** 후보 reader 함수·restore/kebase 호출·종료 부분을 그대로 추출하고 계산기 대신 rc만 반환하는 모의 판독기를 사용했다. 성공한 kebase의 `note` 한 번에만 쓰기 장애를 주입했다. 원래 echo가 디렉터리에 쓰려 하면서 실제 `Is a directory` 오류를 냈고, 마지막 end 쓰기는 정상 파일로 복귀시켰다. 후보 원본·원 영수증 사후 편집은 하지 않았다. 이는 한 번의 I/O 실패를 격리하는 주입 시험이며 전체 러너나 현장 저장장치 시험은 아니다.

기대: 완료 기록 저장 실패를 비영 반환으로 전파하거나 후속 소비자가 거부.

실제: 셸 **rc0**, 다음과 같은 tail, **`admits=True`**.

```text
a5_certificate_sha256=<정상 발행 증서 SHA256>
reader_restore_rc=0
end=<시각> fails=0 reader_rc=0
```

누락된 줄은 `reader_kebase_rc=0`이다. 동일 쓰기 장애에서 kebase 자체가 rc2이면 셸 rc2·최종 reader_rc2·소비 거부였다. 정상 경로의 늦은 kebase rc2, restore 출력 rc120, 선행 단계 실패도 모두 거부됐다. 따라서 **“실패한 계산을 성공으로 통과시킨다”는 표현은 쓰지 않는다.**

더 작은 소비자 회귀는 정상 발행 증서에 다음 tail 네 가지를 넣는다. 후보 코드·수치 보고서는 같고 영수증 조건만 달리한다.

| kebase 행 | 계약 기대 | 후보 실제 |
|---|---|---|
| `reader_kebase_rc=0` 1개 | 허용 | 허용 |
| 없음 | 거부 | **허용** |
| `reader_kebase_rc=0` 2개 | 거부 | **허용** |
| `reader_kebase_rc=2`, 마지막 end의 reader_rc=0 | 거부 | **허용** |

뒤 두 가지는 수동 모순 입력이다. 정상 러너가 계산 rc2를 마지막 0으로 바꾸는 경로는 재현하지 않았으므로 별도 finding으로 세지 않는다.

재현 명령은 증거 ZIP을 새 폴더에 푼 뒤 다음과 같다. Python 표준 라이브러리 및 셸 반례용 로컬 Bash만 필요하다.

```text
python -I -X utf8 -B probe_receipt_minimal.py
python -I -X utf8 -B a5_certificate_review/shell_tail_check.py
```

첫 명령은 **올바른 거부를 기대하는 회귀**이며 현재 후보에서 rc1이다. 정상 1개만 기대 일치하고 세 음성은 부적합 수용이다. 두 번째 스크립트의 `matched=true`는 문제 동작을 예상대로 관측했다는 뜻이지 수정 green이 아니다. 계약 기대 false/관측 true는 `a5_certificate_review/review_classification.json`과 `minimal_receipt_results.json`에 별도 기록했다.

**최소 수정:**

1. 새 A5 소비자는 이 7:3 RJ 경로의 `reader_restore_rc=0`와 `reader_kebase_rc=0`을 각각 정확히 한 번 요구한다. 허용되는 다른 reader 행은 존재 조건·순서·중복·비영/모순을 명시적으로 검사한다.
2. 새 A5 러너의 기록 실패는 반환값·최종 상태에 반영하고 이후 성공으로 지워지지 않게 한다. 마지막 완료 행 자체의 쓰기 실패도 성공 종료로 보고하지 않는다.
3. 같은 누락·중복·모순·기록 I/O 실패 회귀에서 수정 전 실패→수정 후 거부를 확인한다. 정상 성공과 실제 rc2/rc120의 거부는 보존한다. 새 후보를 재조립·해시하고 해당 범위만 재확인한다.

기존 `candidate/README.md:278`의 최소 완료 요약은 마지막 `fails=0/reader_rc=0`이다. 반면 이번 요청 Q3와 새 README는 완전 영수증을 요구한다. 본 지적은 옛 요약 규칙 전체를 소급 기각하는 것이 아니라 **새 A5 소비자의 강한 완료 증거 주장에 대한 좁은 미충족**이다.
