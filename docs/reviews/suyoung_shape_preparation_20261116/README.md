## 2. 준비한 내용

- `F_total`을 물리 상태 밖에서 운반한다. 실제 완료된 step의 `C`를 읽어 `(I + dt C) F_total`을 누적하며, `stress`·접촉·경계·입자 업데이트에 입력하지 않는다. 구성식의 `F`는 별도 `F_elastic`으로 출력한다.
- 원 입자 ID·물질점 ID·참조/현재 좌표·속도·질량·참조 면적·시각·판 위치를 저장한다. 초기와 실제 선택 step만 출력하며 시간 보간은 없다.
- SVG는 `x + F_total × 참조 사각형`의 각 물질 셀을 같은 입자 색으로 그린다. 좌표와 지도에서 직접 그리며 원판 재삽입·convex hull 채움은 없다. 초기 사각 셀의 원판 경계 근사와 셀 겹침은 남는다. 합집합 공극률·겹침 면적은 아직 계산하지 않고 null로 둔다. 면적 합을 합집합으로 바꾸어 보고하지 않는다.
- 매 step 압력을 별도로 저장한다. 출력 켬/끔 trace 바이트와 마지막240 step 평균의 float 비트가 S·F 모두 같다. 현재 기본값1200 step일 때 평균 창은240이며, 일반 길이는 기존 `max(1, steps//5)` 그대로다.
- `--arm S` / `--arm F`로 별도 호출할 수 있어 초안은 각 팔에 외부600초 제한을 건다. 출력 오류·시간 초과·불완전 팔은 완료/응력비로 승격하지 않는다.

실행 초안 `PASTE_WSL_CPU_DRAFT.txt`는 ASCII이며 **현재 무조건 rc2로 멈추는 미결속 초안**이다. 코드가 아직 커밋되지 않아 실행 핀·소스 tar 해시를 만들어 넣지 않았다. 문서 바탕 핀을 실행 핀으로 바꾸어 쓰지 않는다. DONE 뒤 고정 코드 묶음에서 이 세 칸을 결속한 새 실행본을 제공한다. 기존 개발 계산을 지금 다시 돌리라는 요청이 아니다.

## 3. 검사와 한정

`implementation_and_tests.md`와 `local_preparation_receipt.json`에 신원·시험 단위·보존 범위를 기록했다. 최종 같은14메서드: 구본16 실패 관측/오류0(하위 시험 포함) → 후보14/14. 기존9/9도 보존. 초기13메서드를 구현 전에 실행했고, 팔별 호출의 새1메서드도 해당 구현 전 실패를 확인했다. 최종 구본 반복은 같은14로 비교를 맞춘 것이며 추가 고유 시험으로 세지 않는다.

Windows Python3.12.14·NumPy2.3.5의 로컬 합성 회귀다. WSL/NumPy2.5.2 현장 자격·실제 출력 시간·그림의 시각 검수·물리 수렴 자격은 아직 수행하지 않았다. 새 SVG의 수치 꼭짓점·파일 결속·원 ID는 시험으로 확인했지만, 실제 WSL 결과 그림을 이미 만들었다고 하지 않는다. 전체 게이트와 문서 참조 검사96건 재실행 없음.

현장·연구 실행0, 새 원자료/값 열람0, 운영 재봉인0. 50kg 응력은 이미 Love–Weber이므로 재확인·재계산·재작도 없음. 후막은 계획 없음으로 보드에서 제외했다. Rint·공유 MPM 코드·Claude 지정 네 경로·공유 원장에는 쓰지 않았다.
