## C4-0 범위 정정 — 사용자 재확인 필요

“env_identity·기록 구조·자원 감시 구조는 근거로 재사용하되, C4-N2/N3의 관측 간격·조회 지연·산출 경로/용량·Git 자체 산출 분류를 보완한다. 기존 C5 생산 코드/증거는 덮어쓰지 않는다. C4용 변경 diff와 합성 시험만 새로 제출한다.”

필수 추가 합성 사례:

- 늦은 성공 표본이 RSS 5초/디스크 15초 공백을 덮지 못함; None·예외·최초 지연 구분.
- 조회 후 현재 시각으로 마감 검사, 마감 이후 신규 작업 시작 없음.
- 본체·래퍼·임시/최종 기록의 합산; 최종 쓰기 뒤 용량 한도 위반도 성공으로 종결하지 않음.
- 정확 경로/하위 경로 양성, 비슷한 접두사 형제 경로 음성, Git 원문 보존.
- 연구 자료 없는 합성 입력만 사용. OS 하드 제한의 입증으로 확대하지 않음.

“별도 C4-ENV 승인 아래 수행하고 수용한 check 1회를 C4의 전체 C6 자기점검 1회로 인정한다. 같은 코드/환경/봉인 식별이 유지될 때만 적용하며 C4-0에서 중복 check를 호출하지 않는다. 봉인 자체의 읽기·해시 대조와 전체 check의 합성 계산을 구분한다.”
