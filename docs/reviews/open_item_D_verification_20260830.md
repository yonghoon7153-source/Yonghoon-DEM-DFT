## D-1. SDCP `anchor_status` — 마커는 옳고, 그 값을 쓰는 계산 경로가 **없다**

`mpm3d_compaction.py:2351` 이 침대 metadata 에 적는다:

```
_add_meta[nm]['anchor_status'] = 'INVALID_WRONG_MONOMER_recompute_pending'
```

사유(같은 자리 주석): 옛 `E_bind` 는 **곧은-pentyl C11H15O5S2** 로 계산됐는데 실제 SDCP 는
**ether-O 링커 + methyl-분지 2차 술폰산**(C11H16O6S2)이다.  ether-O 의 Li 배위 채널이
빠졌으므로 값·기하 전면 재계산이 필요하다.

**확인한 것 — `E_bind` 가 수치로 읽히는 자리가 리포에 하나도 없다.**  전수 grep
(`*.py *.js *.sh`, docs 제외) 결과 셋뿐이고 **전부 문자열**이다:

| 자리 | 무엇 |
|---|---|
| `scripts/additives.py:203` | 주석 — `⚠INVALID(wrong-monomer …) — do NOT cite −4.8 eV` |
| `scripts/mpm3d_compaction.py:2351` | 위 마커 자신 |
| `scripts/coating_presets.py:70` | 프리셋 `anchor` **설명 문자열** — `E_bind DFT 잔여` |

⇒ **판정: 마커는 유효하고 위험은 0 이다.**  `E_bind` 는 DFT 결합에너지이고 압밀이 쓰는 것은
**별개 양**인 `E_anchor = ADD_E_SET_20260818_9.0GPa` 다.  둘이 이름이 비슷해 섞이기 쉬운데,
metadata 가 **둘을 따로** 적어 침대가 자기 세대를 스스로 신고한다.

⚠ **남는 것**: 마커를 **지우는 조건**은 DFT 재계산이지 이 확인이 아니다.  A4′(SDCP) 백로그의
잔여 한 칸이 정확히 이것이고, 원고는 `E_bind` 를 인용하지 않으므로 **투고를 막지 않는다.**

## D-2. 판정기 SE 라벨 — **출력 문구는 이미 고쳐져 있고, 남은 것은 JSON 키 이름이다**

원장 `table_s3_data_20260827.md` 머리말이 *"판정기 출력이 아직 `표준오차 / SE` 라고 적는다"*
라고 남긴 항목.  실제로 돌려서 확인했다 (`--dir docs/data/w4_ptfe_centerline_20260827`):

```
비의 상대 origin-위상 산포 = 0.3027 % (문턱 1.17 %, 비대응 = 게이트 규약) = 절대 0.3959 %p
쌍대응(origin-key join) 평균 = 1.30782 · 산포 0.0805 % · n = 8 위상
⚠ 이 산포는 **표준오차가 아니다** — 8 위상은 한 침대의 완전 {0,½}³ factorial 이라
  복제 오차 자유도가 0 이다 (R8 Q1).  신뢰구간을 함의하지 않는다.
```

★ **화면에 나오는 말은 이미 `origin-위상 산포`** 이고, `표준오차` 는 **부정문 안에만** 나온다.
R8 Q1 이 요구한 철회가 출력에 반영돼 있다.  docstring(:11)도 같은 문장을 싣는다.

**그래서 실제로 남은 것 셋:**

| | 무엇 | 판단 |
|---|---|---|
| ⓐ | JSON 키가 `se_ratio_rel_pct` · `se_ratio_paired_rel_pct` · `se_ratio_abs_pp` · `se_note` | ⛔ **지금 고치지 않는다** (아래) |
| ⓑ | 면책 문장이 `if _prel is not None:` 안에 있다 — **쌍대응 산포가 있을 때만** 찍힌다 | 8팔 생산 cohort 는 항상 그 가지를 타므로 실무 위험은 작다.  1팔·짝 안 맞는 팔에서는 안 찍힌다 |
| ⓒ | `--collect-only` 는 산포를 **아예 안 찍는다** (2683 에서 `SystemExit(0)`) | 결함 아님 — 그 모드는 팔별 raw σ 만 낸다.  ⇒ 내가 cohort 값을 읽을 때 쓰는 경로에는 오라벨이 **원리적으로 없다** |

### ⛔ 키 이름을 지금 바꾸면 안 되는 이유 (셋)

1. **러너가 물고 있다.**  kgy 에서 8arm 6개 + 이온런이 살아 있고, 러너가 판정기를 부른다.
   키를 바꾸면 도는 런의 소비 경로가 갈린다.
2. **이미 커밋된 증거가 그 키를 쓴다.**  `docs/data/w4*/` 의 감사 패키지와 `--out` JSON 이
   `se_ratio_*` 로 봉인돼 있다.  키를 바꾸면 제3자 재도출이 **옛 패키지에서 실패**한다.
3. **`se_ratio_pct` · `se_ratio_paired_pct` 는 이미 deprecated 별칭**(CDXR2-3)으로 남겨 둔
   전례가 있다.  같은 방식(새 이름 추가 + 옛 이름 유지)이 아니면 호환이 깨진다.

⇒ **권고**: 이름 교체는 **런이 다 끝난 뒤** `origin_phase_spread_*` 를 **추가**하고
`se_ratio_*` 를 별칭으로 남기는 방식으로 한다 (③의 전례 그대로).  지금은 **확인 완료 · 교체
보류**로 둔다.  ⚠ 이것은 *"고치기 싫어서"* 가 아니라 **살아 있는 런과 봉인된 증거** 때문이다.

★ 원고 산출물 쪽은 이미 막혀 있다 — `fig4b_sigma_conventions.py:14` 가 *"표준오차·신뢰구간을
암시하는 어떤 표기도 쓰지 않는다"*, `build_methods_docx.py:64-66` 이 *"sd/√8 은 표준오차가
아닙니다"* 를 싣는다.  ⇒ **독자가 보는 자리에는 오라벨이 없다.**
