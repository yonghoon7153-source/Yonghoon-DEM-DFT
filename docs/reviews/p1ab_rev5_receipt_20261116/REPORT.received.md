## 3. 새 지적

### P1AB5-01 · P2 — 최소 쌍 수를 못 채우는 역사 샌드박스에도 PASS를 요구하는 활성 반례 표

- **대상 핀:** `5ae5acdd5e77b86004e2a3603e4e963e7256413a`.
- **위치:** A:1245, §15-10의 “정직 B · C (샌드박스 다섯 격자 · 칸 최대 0.0604) → 통과해야”. 같은 행의 “6×4 … 칸 W 1.0 → 잡혀야”도 유효 N 조건 없이 적혔다. A:1247의 “샌드박스 정직 B … 통과”는 전역 W 단독 판정인지 구분해야 한다.
- **상충 근거:** A:969는 6×4의 칸별 안쪽 하중 쌍 수 29–98, 11×1의 97–189를 기록하며, 두 격자의 정직 B/C도 UNCONFIRMED라고 명시한다. A:1144–1145·1185와 Q:55도 같은 규칙이다. 이 기존 수를 원자료로 다시 계산한 것은 아니다.
- **최소 반례:** 합성 6×4 칸마다 양의 하중 쌍 99개, 같은 쌍 집합, 모든 비교 힘 동일. 전역 W=0, 모든 W_c=0이지만 N 하한 때문에 **UNCONFIRMED**다. “정직 다섯 격자 PASS”와 동시에 만족할 수 없다.
- **거부 쪽 경계:** 같은 24칸 중 한 칸만 전부 reset-like라면 균일 하중에서 W=1/24≈0.041667이다. 그 칸 N=99이면 W_c=1을 유효 칸 위반으로 채택하지 못하므로 UNCONFIRMED다. 모든 칸 N=100이면 같은 W와 W_c에서 VALUE_MISMATCH다. 다른 유효 칸의 W_c=0.6 또는 전역 W=0.06이 확인되면 N 부족보다 VALUE_MISMATCH가 우선한다.
- **영향:** 정정된 요청 Q2를 읽어도 구현자가 §15-10을 시험 정답표로 삼으면 역사 입력을 PASS로 만들기 위해 N 조건을 우회하거나, 올바른 구현을 실패 처리하게 된다. 실제 B 실행기의 결함을 발견한 것은 아니다.
- **최소 수정:** 역사 샌드박스와 N≥100을 만족시키도록 만든 합성 fixture를 분리한다. §15-10에는 “역사 6×4·11×1 정직 B/C는 UNCONFIRMED, 나머지 세 격자는 PASS; 하한을 만족하는 새 합성 fixture의 칸 소실만 VALUE_MISMATCH 기대”라고 적는다. §15-8 A:1215의 “칸 하나 통째 소실은 잡는다”에도 유효 N·힘 변화 가정의 한정을 붙인다. 문턱을 바꾸지 않는다.
- **닫힘 증거:** 원 역사 입력 기대와 새 합성 N99/N100 경계를 직접 구분하는 문서 회귀가 필요하다. 제공 12개 시험의 통과만으로는 이 잔여가 닫히지 않는다.
- **재현:** `python -I -X utf8 -B independent_probe.py --input input --report probe-new.json` → rc1, `P1AB5-01`과 7개 경계 결과. 이는 독립 산술/문서 탐침이며 실제 cont_guard 실행이 아니다.

## 6. 허용되는 다음 단계와 남은 조건

**B 구현 착수에 한정한 설계 GO가 가능하다.** 이 수용으로 할 수 있는 다음 일은 B §7의 가짜 실행기·작은 합성 입력 시험을 먼저 작성하고, 그 실패를 확인한 뒤 MPI 지원 코드와 대조기를 구현하는 것이다. 이 보고서는 그 코드를 작성하거나 실행하지 않았다.
