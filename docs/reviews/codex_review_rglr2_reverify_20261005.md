## 3. 새 발견

### RGLR3-01 — P2 — 같은 HEAD의 dirty retry가 발사 봉인을 우회한다

**자리:** `scripts/run_network_194_parallel.py:967` (`cmd_retry`), `:972`, `:1003`, `:939`–`:950`, `:717`–`:725`, `:808`–`:825`.

최초 `run`의 preflight는 dirty를 거부한다. 그러나 `retry`는 **Git HEAD가 같은지만** 보고, dirty는 이력에 적을 뿐 거부하지 않는다. 재시도 시작 전에 수치 코드를 편집하면 다음이 동시에 성립한다.

1. 발사 때와 HEAD는 같다.
2. 재시도 직전·직후 해시 h0=h1이므로 `code_changed_during_run=[]`.
3. 워커 기록의 git_sha도 같다.
4. 발사 manifest와 다른 실제 해시는 `code_changed_since_launch`에만 들어가며 병합 거부 조건에는 들어가지 않는다.

**재현:** 실제 `cmd_retry`에 동일 HEAD·dirty=True와 발사 후 달라진 `network_conductivity.py` 지문을 주입했다. OS 잠금·환경 조회·워커만 대역이며, 재시도 판단과 실행 기록·병합은 대상 함수다.

```text
retry_worker_called = true
retry_rc = 0
code_changed_during_run = []
mixed_generation = []
allow_mixed_generation = false
code_changed_since_launch = ["scripts/network_conductivity.py"]
```

바뀐 코드를 실행한 것으로 기록된 재시도가 일반 성공으로 묶인다. 단지 **완료 후** 현재 트리만 편집된 경우와 구별하지 못하는 것이 핵심이다. 현재 해시가 다르다는 이유만으로 이미 끝난 정상 배치를 일괄 기각하라는 뜻은 아니다.

**무너지는 결론:** “같은 HEAD·manifest·merge 성공이면 모든 케이스가 발사 봉인 코드로 계산됐다.” 결과 σ가 이미 틀렸다는 실측 증거는 아니다.

**최소 해제 증거:**

- retry도 최초 발사 지문과 실행 코드 바이트를 비교하고 dirty·미봉인 변경을 거부한다. 사후에 현재 트리만 달라졌을 가능성을 허용하려면 **각 실행/각 시도의 실제 코드 지문**을 남겨 비교해야 한다.
- 동일 HEAD의 코드 변경, 재시도 사이 변경, worker dirty=True를 거부하는 음성 대조와 변경 없는 재시도 양성 대조.
- 이미 실행된 케이스는 manifest만이 아니라 시도별 실행 증거로 구분한다. 입증할 수 없는 재시도 케이스만 재실행 대상으로 삼는다.

기존 입력 (1073.1, 1073.1, 1073.1000001073098)과 오프셋 없는 쌍은 정확 유리수로 같은 VM을 갖는다. 이번 결과는 Python·NumPy 둘 다:

- 정확 VM = 1.0730991562013514e-7 sim Pa
- CV = **0.0%**
- 정확 정수압 = VM 0
- 영 텐서는 안정식 재계산 입자로 세지 않음

독립 난수 5,000개를 입력 float의 정확 유리수 차이식과 대조했다. 안정식 3,542개, 옛 식 유지 1,458개. 유지된 VM의 최대 상대 차이는 **2.8497664377023494e-8**, 명시된 보수적 한도 위반 0. 이는 제출자 표본의 2.2e-8과 다른 표본에서 나온 최대치이며, 보편 최대치 경쟁으로 해석하지 않는다.

**K=2^20 채택을 수용한다.** 이는 물리 허용오차를 넓히는 선택이 아니라 같은 양을 계산할 때 어느 수치식을 쓸지 정한 것이다. B가 전개식 절대 오차 상한이면 유지 조건 R̂>KB에서 정확 R>(K−1)B이므로 근호 상대 오차 <1/(K−1)이라는 논리는 맞다. 단 엄밀성은 코드가 명시한 유한 binary64 연산·반올림·pow 오차 가정에 조건부다. 오버플로/아래넘침까지 모든 입력에서 작은 상대 오차를 보장한 것으로 확장하지 않는다.

real_14의 “변경 입자 0”은 이번 자리에서 원 gz를 얻지 못해 재생산하지 않았다. 이 값은 위 독립 5,000개 시험과 별개다. 194 결과에서는 안정식 재계산 수·v3 계약·바뀐 옛 응력 열을 함께 보존해야 한다.

## 5. 질문 2 — 격리 병렬 배치와 amendment

그러나 **문서 지문 일치 ≠ 실제 각 워커가 그 지문으로 계산했다는 증거**다. RGLR3-01 때문에 재시도 경로의 봉인은 아직 아니다. 인계 생성기의 동일 세대 관문 역시 RGLR3-02가 남는다.

현재 격리 결과의 보관·진단을 배포와 분리하는 운영은 수용 가능하다. 이번 회신은 캠페인 추가 실행·재시도 승인이나 이미 제출한 194건의 성공 인증이 아니다. OOM 입장 관문은 추정 기반이며, 최대 RSS도 동시에 살아 있는 프로세스 트리의 합계는 아니다. 따라서 20 레인/메모리 안전을 독립 실환경 검증한 것으로 쓰지 않는다.

새 발견은 망 선형 풀이 자체의 수치 변경을 요구하지 않는다. 코드 봉인이 정상이고 canonical 결과가 온전한 케이스는 **인계 검사를 보강해 다시 읽는 것**으로 해결될 수 있다. 출처가 입증되지 않는 재시도·혼합 케이스만 선택적으로 재실행한다. 정상 케이스까지 194건 전부 재실행하라는 결론은 근거가 없다.

## 7. 질문 4 — RGL-06·RGL-08
