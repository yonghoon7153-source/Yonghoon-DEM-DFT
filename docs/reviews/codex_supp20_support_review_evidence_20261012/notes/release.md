## Finding SUPP-REL-01 — P2: cross-batch recheck uses an unbound second set of roots

Location: `scripts/lhs_release_build.py:2504–2510`, related `:2497–2503` and `:2478–2490`.

`_v13_gate_recheck_one` obtains the actual per-batch roots from `batch_gate.batch_root` and `supp_batch.batch_gate.batch_root`. However, `v13_batch_gate_recheck` obtains the roots used for the same-code-fingerprint check from separate `batches[name].root` metadata. These two sets are never required to name the same directories. If any `batches` root is missing or nonexistent, the entire cross check is silently omitted.

Actual reproduction (`probes/release_probe.py`; machine-readable results `evidence/release_probe.json`):

1. Build the supplied synthetic 130 + 64 + 20 fixture using the real `build_v13`. It produces 27 files, `n_total=214`, and `check_v13` returns `[]`.
2. Construct another individually valid `supp20` fixture with a different `code_fp` (one extra current-file entry in its manifest code hashes). Its own gate returns `[]`; a normal `build_v13` with this supplement is correctly refused for cross-batch `code_fp` mismatch.
3. Replace only the release manifest's `supp_batch` object with that new root's correct gate, evidence hashes, manifest hash and code identity; leave `batches.supp20.root` pointing to the original supplement. Unmodified `check_v13` returns `[]` although the two batches whose gates were accepted have different fingerprints.
4. Set `batches.supp20.root` to the new root: `check_v13` reports two cross problems. Set it to a nonexistent directory instead: `check_v13` again returns `[]`.

Evidence fields: `baseline_check`, `normal_build_different_fp`, `other_supp_gate`, `actual_cross_problem`, `different_fp_gate_original_cross_roots`, `different_fp_gate_matching_cross_root`, `different_fp_gate_missing_cross_root`, `missing_cross_root`.

This is a recheck/manifest-consistency bypass introduced by the multi-batch change. It does not show that an unmodified normal build spontaneously emits differing fingerprints. Fix by deriving the cross roots from the same validated batch-gate roots, requiring all redundant `batches` roots to match, and treating absent/non-directory roots as problems. Add regression tests for both inconsistent roots and a missing root. Existing V21k (`test_lhs_release_v13.py:2102`) tests changed supplement evidence files, not this inconsistent manifest structure.
