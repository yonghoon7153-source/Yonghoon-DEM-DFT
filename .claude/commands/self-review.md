외부 게이트 리뷰를 보내기 전에 우리 쪽에서 먼저 적대적으로 턴다. 대상:
$ARGUMENTS (비우면 직전 리뷰 이후의 변경 전체)

superpowers 의 dispatching-parallel-agents / requesting-code-review 를 이 프로젝트
형태로 적응한 것이다. 10차 라운드에서 실제로 이 방식이 19건을 탐색해 3건을
CONFIRMED 로 확정했고, 그 3건 모두 외부 리뷰가 독립적으로 같은 축을 지적했다.

## 전제

**이 커맨드는 subagent 를 여러 개 띄운다** (토큰·시간 비용이 크다). 사용자가
명시적으로 요청했을 때만 실행한다.

## 절차

### 1. 탐색 (병렬 렌즈)

렌즈마다 독립 subagent 를 띄운다. 렌즈는 이 저장소가 실제로 뚫렸던 축이다:

| 렌즈 | 무엇을 찾는가 |
|---|---|
| sig-완전성 | 서명이 고정하지 **못하는** 계산 축 (설정은 같은데 결과가 달라질 수 있는 것) |
| validator-우회 | 형식은 맞는데 의미가 틀린 산출물이 통과하는 경로 |
| 순서-TOCTOU | 검증 시점과 사용 시점 사이가 벌어지는 곳 (캐시·스냅샷·resume) |
| 파생-보고서 | 저장본과 재계산본이 갈릴 수 있는 렌더 경로 |
| archive-이식성 | 묶기·복원·OS 경계에서 깨지는 것 |
| 공정성-의미 | 비교가 같은 모집단·같은 예산인가 (통계적 함정) |

각 subagent 규칙:
- **tracked 파일 수정 금지**, 산출물은 `mktemp -d` 안에만
- 주장마다 **실제 실행한 반례**(명령 + 출력)를 붙인다. 코드 읽기만으로 나온
  주장은 채택하지 않는다
- 심각도: `결론이_바뀜` / `숫자가_바뀜` / `서술만_바뀜` / `사소`

### 2. 선별

전체 발견을 모아 중복을 합치고, **이미 닫힌 것**을 걸러낸다. 현행 트리에서
실측으로 확인한다 — "고쳤을 것이다" 로 거르지 않는다. 남은 것을 심각도 순으로
정렬해 상위만 검증 단계로 보낸다.

### 3. 적대적 검증

선별된 발견마다 **반박을 목표로** 하는 subagent 를 띄운다. 기본값은 "반증됨" —
격리 환경에서 반례를 재현해야만 CONFIRMED 다. 재현 출력 전문을 남긴다.

### 4. 보고

CONFIRMED 만 보고한다. 각 항목: 주장 · 파일:행 · 재현 명령과 실측 출력 ·
심각도 · 수정 힌트. 제외한 것도 **왜 제외했는지** 한 줄씩 (닫힘 확인 실측 포함).

## 이후

CONFIRMED 는 `/finding` 으로 하나씩 닫는다 (RED 테스트부터). 그 다음
`/gate-request` 로 외부 리뷰 요청문에 **자체 리뷰 결과도 함께** 싣는다 — 우리가
무엇을 이미 찾았고 무엇을 신뢰 경계로 남겼는지 밝히면 외부 리뷰가 그 위에서
시작한다.
