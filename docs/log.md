## [2026-08-21] create | 중추 서버 한 대 — 데이터는 git 으로 옮기지 않는다
두 번째 노트북에서 라이브러리가 비어 보이는 것이 출발점이었다. `bml` 이 자동
push 하게 만드는 길은 막혀 있다 — `.wrd` 가 20 MB 이고 git 은 모든 판본을
영구히 보관하며, push 된 히스토리는 rewrite 하지 않는다. 대신 인스턴스를 하나만
두면 동기화 단계 자체가 없어진다 (ADR 0011).

넣은 것 넷. `.bml/env` 로 그 기계에만 남는 설정(`WORKBENCH_DATA`,
`WORKBENCH_HOST`), 드라이브가 안 잡혔으면 시작을 거부하는 가드(그냥 두면 빈
data/ 를 새로 만들고 데이터가 날아간 것처럼 보인다), 원본 `.wrd` 를 그대로
돌려주는 내려받기(되받을 수 없으면 아무도 유일본을 맡기지 않는다),
`bml backup` — 원본과 DB 만 복사하고 파싱 캐시는 뺀다.

화면은 30초마다 스스로 갱신된다. 탭이 숨으면 멈추고 돌아오면 바로 한 번 읽는다.

## [2026-08-21] create | 노션처럼 — 남이 바꾼 것이 내 화면에 바로 나타난다
서버가 "무엇인가 바뀌었다" 를 번호 하나로 흘려보내고(SSE `/api/events`), 각
화면은 자기가 보여 주는 것만 다시 읽는다. 무엇이 바뀌었는지는 보내지 않는다 —
엔드포인트마다 자기 변화를 설명하게 하면 새 편집 종류가 생겼을 때 한 군데를
빠뜨리고, 그러면 그 종류만 남의 화면에서 안 보인다.

bump 는 미들웨어에 뒀다(성공한 쓰기만; 422 는 아무것도 안 바꿨다). 쓴 사람은
응답 헤더로 자기 공지를 무시한다. EventSource 를 못 쓰면 15초 폴링으로 내려간다.

같이 고친 것 둘. 타이핑 중인 칸은 갱신이 건드리지 않는다(질량·조성). 그리고
저장 뒤의 로컬 sample 이 서버를 영원히 가리던 것을 updated_at 비교로 바꿨다 —
공유 서버에서는 한 번 편집하면 그 셀에 대한 남의 편집이 안 보인다는 뜻이었다.
