**S3 (ψ 자리 교정) 를 돌리기 전에, 사전등록 v3 를 적대적으로 검토해 달라.**

## 3. 검토 요청 ① — **v3 의 판정 규칙이 조작 가능한가** (핵심)

v3 ① 의 판정표(계약 §5-v3 ①)를 그대로 읽고 다음을 봐 달라.

1. **모든 실현 가능한 결과가 정확히 하나의 라벨을 받는가?**  v2 는 `ρ=4 %, median 3.5 %` 를
   h0 로 만들었다 (미식별을 무효과로 읽는 오류).  v3 에 같은 종류의 구멍이 남아 있는가?
   특히 `ρ > 3 %` 이면서 `median ≥ 10 %` 이지만 `< 2ρ` 인 경우 — 우리 표는 이것을
   `UNRESOLVED_NUMERIC` 으로 두는데, **라벨이 비어 있는 구간은 없는가?**
2. **문턱 3 %/10 % 를 결과를 보고 움직일 수 있는 경로가 남아 있는가?**  우리는 "ρ 는 문턱을
   낮추지도 넓히지도 못하고 상태만 바꾼다" 고 적었다.  이 문장이 실제로 구속력이 있는가,
   아니면 `UNRESOLVED_NUMERIC` 을 경유해 사실상 재량이 생기는가?
3. **주 지표가 `median(|Δ|)` 인 것**(v2 ③)이 이 전환에 적절한가.  우리는 케이스가 독립
   표본이 아니므로 **검정이 아니라 기술 통계**라고 명시했다.  그런데 채널마다 하나씩 총
   **세 판정**을 낸다 — 다중 판정 보정을 안 하는 것이 정당한가, 아니면 세 채널을 묶어
   하나로 봐야 하는가?
4. **음성 대조**(v2 ⑦)가 S3 에 대해 충분한가.  우리가 등록한 것은 ⓐ coverage 가 셀 단위로
   불변 ⓑ `contact_mode == 'hertzian'` 간선의 `R_constriction` 이 bitwise 불변, 둘이다.
   **ψ 자리를 고쳤는데도 통과해 버리는 대조는 아닌가?**  (전자 채널이 음성 대조가 **아니라는**
   우리 판단도 같이 봐 달라 — 계약 §5 ⑦ 마지막 항.)

## 4. 검토 요청 ② — **SELF-31 의 "σ 무해" 판정이 과한가**

사실관계: 생산 코드가 `cg(L, b, atol=1e-8)` 만 넘긴다.  scipy ≥1.12 의 정지 조건은
`‖r‖ ≤ max(rtol·‖b‖, atol)` 이고 **기본 `rtol=1e-5`** 라, `‖b‖ ~ 1` 에서 atol 은 한 번도 안
걸리고 **의도(상대 1e-8)보다 1000배 느슨하게** 돈다.

런 **전에** 판정선 3 % 를 등록하고, LHS 30 에서 사다리를 돌렸다 (scipy 1.18.1):

| tighten | 실제 rtol | 이온 ρ | 열 ρ |
|---|---|---|---|
| 0.1 | 1e-6 | 5.921028751e-07 % | 1.107819076e-05 % |
| 0.01 | 1e-7 | 5.985227898e-07 % | 1.122655279e-05 % |
| 0.001 | **1e-8 (의도값)** | **6.000686495e-07 %** | **1.122641757e-05 %** |

우리 판정: **결함은 실재하나 σ 에는 무해** — 1e-7 에서 이미 포화하고(열은 다섯째 자리가
오히려 미세 감소 = 수치 바닥), 판정선의 다섯 자릿수 아래다.  ⇒ 등급 P1 → P2, **기존 결과를
다시 돌릴 이유 없음**.

**묻는 것**:
1. 이 실측으로 *"σ 에 무해"* 라고 말해도 되는가, 아니면 **LHS 30 · scipy 1.18.1 · 이 조건수
   범위**로 한정해야 하는가?  (전자 채널은 직접해뿐이라 이 축이 없다.)
2. 포화를 *"솔버 허용오차에 대해 수렴"* 으로 읽는 것이 맞는가?  **CG 가 같은 부분공간에서
   멈추는 인공적 포화**일 가능성은 없는가?
3. ρ 를 **수치 민감도 진단**으로 쓰고 **오차 상한으로 쓰지 않는다**는 우리 규약이 이 결론에
   일관되게 적용됐는가?

## 5. 검토 요청 ③ — **AREA-11 (아직 open) 의 처방**

이종쌍 협착에서 코드가 `min(σ₁, σ₂)` 를 쓴다.  참값은 두 반공간 spreading 의 **직렬**이다.

```
참값   R_c = ψ(a/b₁)/(4 σ₁ a) + ψ(a/b₂)/(4 σ₂ a)
현 코드 R_c = ψ /(2 a · min(σ₁,σ₂))
비     = 2σ₁σ₂ / (σ_min(σ₁+σ₂))  ∈ [1, 2)
```

독립 기준해(양쪽 σ 를 다르게 푼 수치해)가 직렬식에 붙었고 `min(σ)` 식과 어긋났다.
2라운드는 **16/9 는 계수비일 뿐 근거가 아니다**라고 지적했고 우리는 그것을 받아들여
실측 비(1.6857)로 바꿨다.

**묻는 것**: ⓐ 직렬식이 이 기하에서 옳은 참값인가 ⓑ 생산 영향 범위를 *"전자 모드의
AM_P 관련 간선뿐"* 으로 좁힌 우리 판단이 맞는가 (이온·열은 양쪽 `sigma_rel` 이 1.0)
ⓒ 이것을 **S3 와 같은 런에서 고치면 안 되는** 별도 축으로 둔 것이 맞는가.

## 6. 검토 요청 ④ — **코호트와 사후 유입(addendum) 규약**

봉인 결과 (`area_s2_cohort.tsv`, 커밋 `892ae1623` 의 계약 문단이 정본):

```
케이스 131 · RAW_OK 127 · RAW_MISSING_CONTACT 3 · DECK_MISSING+RAW_MISSING_ATOM 1
설계족  bimodal 100 · mono_AM_S 15 · mono_AM_P 15 · UNKNOWN 1
```

- **판정 코호트 = 130**.  `UNKNOWN` 1 은 `perc/`(설계 밖 보조 디렉터리).
- `RAW_MISSING_CONTACT` 3 = `lhs00_034·089·098` — 지금 클러스터에서 실행 중이라 접촉 덤프가
  아직 없다.  **봉인 후 완주분은 코호트에 섞지 않고 addendum 으로 따로 적는다** (결과를 보고
  대상 집합을 넓히지 않기 위해).

**묻는 것**: ⓐ 이 addendum 규약이 충분한가, 아니면 **지금 3건을 코호트에서 명시적으로
제외하고 그 사실을 주 판정에 붙여** 보고해야 하는가 ⓑ 코호트를 **데이터 가용성**으로 정의한
것(계약 §5 ①)이 S0 를 본 뒤의 선택으로 오염됐다고 볼 여지가 있는가.

## 7. 우리가 주장하지 **않는** 것 (미리 못 박는다)

- S2·S3 의 σ 결과 — **런이 없다.**
- S0 삭제 비율(이온 20.728 % · 전자 0.000 % · 열 26.850 %)을 **σ 변화 크기의 예측**으로 쓰지
  않는다.  간선 개수는 I²R 기여도가 아니다.
- `clamp_zero` 99.436 % 를 *"접촉이 실제로 이상적"* 으로 읽지 않는다 — 면적을 원판으로 읽어
  **강제된** s=1 이다.
- ρ 를 오차 상한으로 쓰지 않는다.
- **AREA-12 (S2 항등)** 는 2라운드가 실제 `build_network` 로 CONFIRMED 했고, 그 결과 S2 는
  σ 를 움직이는 축이 아니다 ⇒ **S3 가 유일한 σ 축**이다.
