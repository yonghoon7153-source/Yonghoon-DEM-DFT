## ⛔ R-1 [R-I] 3 상 덱은 `dump … mol` 에서 **확정적으로 죽는다** — `mol` 은 `fix multisphere` 만 할당한다

- **원장 문장**: §13 *"덱 확인(LA · 10만 · CGF 151.4): create_box 4 · 메시 type 4 · … 75.0 rpm → Fr 0.0827 … ✓"* · §7 *"게이트 미실행"*.
- **반론**: 확인한 것은 덱 **텍스트**이지 실행이 아니다.  `deck()` 는 섬유 유무와 무관하게
  `dump dmp all custom … id type mol x y z …` 를 쓴다 (생성 덱 실측: `dump dmp all custom 45333 post/mix_*.liggghts id type mol x y z vx vy vz fx fy fz radius`,
  `fix integr  all multisphere` **없음**).  LIGGGHTS-PUBLIC 에서
  · `atom_style granular` = `AtomVecSphere` (`atom_vec_sphere.h:56`) 이고 `molecule` 을 **할당하지 않는다** (`atom.cpp:176 molecule_flag = 0`);
  · `molecule_flag = 1` 을 세우는 곳은 `fix_multisphere.cpp:175` 와 `atom_vec_molecular.cpp:77` **둘뿐**;
  · `dump_custom.cpp:1057-1059`: `"mol"` 이면 `if (!atom->molecule_flag) error->all(FLERR,"Dumping an atom property that isn't allocated")`.
  ⇒ 3 상 덱(섬유 0 = `fix multisphere` 0)은 `run 1` 직후 `dump` 명령에서 **ERROR 로 종료**한다.  옛 5 상 덱이 살았던 이유는 `fix integr all multisphere` 가 있어서다.
  셀프테스트 ⑪a 는 "multisphere 가 **없다**" 만 보고 dump 줄은 안 본다 = **선언 안 한 축은 검사도 안 된다** (Phase A 교훈 그대로).
- **정량**: 10/10 런 · 0 step 진행 · 손실 = 셋업 시간뿐.  다만 `gen_all.sh` 가 `runs/` 를 만들어 두므로 `watch.sh` 에는 *"⛔죽음 step -"* 로 보인다 — 조용한 실패는 아니다.
- **판정 근거**: 아무 덱 1 개 `lmp -in in.mixer` 1 step (또는 위 소스 세 줄).  후처리 쪽은 안전 — `check_contact_validity.contacts(…, D.get('mol'))` 는 `mol` 없으면 `n_intra 0`, `measure_mixing_index` 는 `mol` 을 안 쓴다.

## ⛔ R-2 [R-G] 캠페인에 **읽을 도구의 기준 런이 없다** — Lacey `M` 은 `--ref`(균일 삽입, 같은 시드·같은 덱) 없이는 정의되지 않는다

- **원장 문장**: §10 *"6 팔 · 10 런 … 전부 층상 삽입"* · §13 *"캠페인 실행 파일 … 10 런 생성"*.
- **반론**: Lacey `M` 은 리포에 **있다** (`scripts/measure_mixing_index.py`, §24-3 정의) — 그러나
  `M(t) = (S₀² − S²(t)) / (S₀² − S_R²)` 의 **`S_R²` 를 균일 삽입 런의 정착-끝 프레임에서 실측**한다 (`analyse()` 는 `ref_dir` 필수, `main()` 은 `--ref` 없으면 `ap.error`).
  캠페인 6 팔은 전부 `layered=True` 이고 균일 삽입 팔은 **0 개**.  옛 `E0` 기준 런(시드 32452843/49979687/91648301)은 **옛 덱**
  (R 20.56 mm · 7,999 원자 · 5 상 · SE 3 µm) 이라 칸·입자수·`S_R²` 가 다르고, 셋째 시드(91648301)는 새 캠페인 시드(67867967)와 다르다.
  또 `--r-container` 기본값이 **0.02056 = 옛 드럼**이라 새 드럼(0.013138)에 그대로 쓰면 칸이 드럼 밖으로 나간다.
- **정량**: 기준 런은 **정착-끝 프레임 한 장**만 쓰므로 회전 0 바퀴면 된다 — 삽입 + 2×192,668 step = 385k step ≈ **3.6 h/시드** (2.99e6 p·step/s 기준) × 3 = 11 h (캠페인의 1.3 %).
  §24-4·§25-2 의 판정선(칸 8×8×2/20 → 16×16×4/6, 문턱 0.30/0.10, SE_시드 합동/√3)은 **옛 드럼·옛 AM_P 지름**에 등록된 것이다 — 새 덱의 칸 한 변 = 2R/16 = 1.64 mm = **1.2·d_AM_P**(옛 2.5 mm = 1.0·d_AM_P) 로 규모가 달라졌고 재등록이 없다.
- **판정 근거**: 캠페인 목록에 균일-삽입 기준 팔(시드 3)이 있고, 새 덱 기준의 사전등록(칸 사다리·`r_container`·판정선)이 **런 전에** 파일로 있는가.

## ⛔ R-3 [R-A] 코팅 규약 변경으로 `LC` 는 **사다리 바닥과 수치적으로 같은 팔**이 됐다 — §10 의 덮개 표와 "곡선 위/밖" 판정이 무너졌다

- **원장 문장**: §13 ② *"사다리 표(§10)의 LC 점은 0.0011(AM_P) 로 옮긴다.  씽키 앵커 0.0112 · LB1 0.1 사이 덮개는 그대로 성립"* ·
  §10 *"LC 가 곡선 위에 있으면 '코팅 = Bo 낮추기', 벗어나면 '코팅에 Bo 외 효과가 있다'"* · *"점 사이 최대 간격 5.0×, 최악 보간 2.14×"*.
- **반론 (재계산)**:
  · `LC` 의 AM 쌍 CED: AM_P–AM_P **1.088e5** (Bo_code 0.001093) · AM_S–AM_S 1.426e5 (0.005532) · AM_P–AM_S 1.088e5 (min 규칙, AM_S 무게 기준 0.0047).
    AM_P–AM_P 평형 점착력 = 0.00109 × W(6.24e-5 N) = **6.8e-8 N**.  같은 쌍의 Hertz 충돌력(v_tip 0.103 m/s, δ_max 1.54 µm) ≈ **0.026 N** = **4×10⁵ 배**, 무게의 1/900.
    ⇒ `LC` 의 AM–AM 점착은 **수치 잡음 수준** = `LC` ≡ "AM 쌍 Bo 0 · SE 기준 0.212".  헤드라인은 *"코팅"* 이 아니라 *"AM–AM 점착을 끄면"* 으로 축소됐다.
  · 덮개 표 재계산 (LC 0.00109 · LB1 0.1 · LB2 0.5 · LB3 1.5 · LA 3.0): 점 사이 최대 간격 **91.7×** (원장 5.0×) · 씽키 앵커 0.0112 최근접 LB1 → **8.9×** (원장 2.10×).  *"덮개 그대로 성립"* 은 **틀렸다**.
  · `L0` 는 사다리 위 점이 **아니다** — `bond=0` 이라 SE–SE(0.212)·AM–SE(0.176)도 0 이다.  x 축(AM 쌍 Bo, SE 기준 고정)에서 0 ~ 0.1 사이에 SE 기준을 유지한 점이 **없다** ⇒ "곡선 위/밖" 을 판정할 곡선이 그 구간에 없다.
  · 이 규약에서 LC 가 바닥에 붙는 것은 **구조적**이다: Bo_AM = Bo_SE/194 인데 SE 기준을 천장(SE 1 % 겹침 ≈ Bo 10)까지 올려도 0.05 다.  코팅이 "Bo 외 효과" 를 가질 자리가 규약상 없다.
- **정량 대비**: `LA`(3.0) vs `LC`(0.00109) = **2,750배** (원장 "128배").
- **판정 근거**: 재등록된 판정선에서 (a) LC 를 바닥으로 선언하고 헤드라인 문장을 *"AM–AM Bo 3.0 vs ≈0, SE 기준 0.212 고정, 층상 시작"* 으로 고치거나, (b) 별도 바닥 팔 `LB0`(층상 · AM 쌍 Bo 0 · SE 기준 0.212 · 시드 1)을 두고 LC 와의 동일성을 실측으로 보이는가.  (a) 면 **추가 런 0**.

## ⛔ R-4 [R-F·R-D] `LA = 문헌 앵커 Bo 3.0` 은 **계산 가능한 두 인자**만큼 어긋난다 — 6.75(정의) × 1.9(밀도) = **12.8배**

- **원장 문장**: §10 *"LA 3.0 ★ 헤드라인 무코팅 (문헌 앵커)"* · §12 *"LA 의 Bo = 3.0 은 hare2026 의 γ 0.25 J/m² 에서 나오는데"* · §23(설계문서) R-4 반박 *"정의 차이로 O(1) 불확실 … 환산 계수를 계산할 수 없다"*.
- **반론 ① 정의 (계산 가능하다)**: 코드의 `bond_for_ced` 는 **평형 겹침에서의 인력 성분** `F_eq = CED·2πR*·δ_eq` 를 무게로 나눈다.  문헌 Bo 는 **pull-off** 힘이다.
  SJKR+Hertz 의 pull-off 는 준정적 분리곡선의 최대 인력 = `dF_net/dδ = 0` 에서 **δ_po = (4/9)·δ_eq**, `F_po = (2/3)πR*·CED·δ_po = (8/27)·F_eq`.
  ⇒ **Bo_code = 6.75 × Bo_po**.  이 인자는 접촉면적 상수(π R δ vs 2π R δ)와 무관하다.  `LA` Bo_code 3.0 = **Bo_po 0.444**.
- **반론 ② 밀도**: 정본 카드 §3.2 — hare 의 DEM 입자는 **ρ_p 2500 kg m⁻³** (bulk, 실고체 4650 의 0.54배)이고 카드 §4.3 의 자체 산술은 **F_po/W ≈ 5.7** 이다.
  원장·설계문서 §19-2 의 "3.0" 은 ρ 4650 을 넣은 값(3.08)이다.  전이해야 할 것이 *조립 입자의 bulk 유동 보정값*(§19-3)이라면 그 입자의 실제 무게, 즉 **5.7** 이다.
- **정량**: pull-off 로 맞춘 앵커 = Bo_code **38.7**(ρ 2500) / 20.8(ρ 4650).  `LA` 3.0 은 그 **1/12.8 · 1/6.9**.  사다리 최댓값(3.0)이 앵커 아래다.
  실현 가능성: Bo_code 38.7 의 AM_P 겹침 = **0.046 %** (E 1.037e9 덕에 천장 1 % 의 1/22) — 옛 덱(E 1e7)에서는 불가능했던 점이 지금은 싸다.
  기계 배치도 규약이 섞여 있다: §4 *"볼텍스 앵커 Bo 0.215 = 경계의 0.43×"* 는 **JKR-pull-off 값 3.0 을 code-규약 경계 0.5 로 나눈 것**.  같은 규약으로는 38.7/14.0 = **2.76 → 경계의 5.5배 초과**(뭉침), 씽키 38.7/268 = 0.144(여유 3.5배, "45배" 아님).  볼텍스 판정의 **부호가 뒤집힌다**.
- **살아남는 것**: SJKR↔JKR 이 같은 Bo_po 에서 같은 bulk 유동을 내는지는 여전히 **모른다**(SJKR 은 δ<0 인장가지가 없다) — 그 잔여가 O(1) 이다.  6.75 와 1.9 는 잔여가 아니라 **제거 가능한 편차**다.
- **판정 근거**: (a) 두 규약을 나란히 적은 라벨(*"LA = Bo_code 3.0 = Bo_po 0.44 = hare DEM 입자 Bo_po 5.7 의 1/13"*), (b) 앵커를 덮으려면 Bo_code ≈ 20–39 점 1 개(시드 1, 84 h) 추가 — 1저자 결정.  런 뒤에는 라벨을 못 바꾼다.

- **판정 근거**: 캠페인 덱 1 개를 정착 + 1 바퀴(≈ 1.5M step)만 돌려 ① `atoms = 100000` ② `Total wall time` 으로 처리율 ③ `post/` 에 `check_contact_validity.py --n-expected 100000` 과 `measure_mixing_index.py --ref … --r-container 0.013138` 를 **끝까지** 통과시키는 것.

## ⚠ R-7 [R-C] 벽 타입 — `F ∝ CED³` 는 소스로 확인, 그러나 "힘비 1/6.25 재현" 은 **R\*(벽) = r 과 쌍 E\*** 를 빠뜨렸다
