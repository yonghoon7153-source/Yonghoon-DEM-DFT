# LHS 압력 재고 — LPI-01/02 짧은 재확인 요청

**이번에 종결을 요청하는 것:** LPI-01의 출력/종료 재시도 결함과 문구 과장, LPI-02의 크기 제한을 시간 제한으로 읽을 여지를 줄이는 문구·반례 보존.
**닫지 않는 것:** 처리 시간 상한 구현, 실제 ibb/WSL·POSIX/Lustre 자격·압력 적격성·단계 A·배포·전체 게이트 HOLD. 이 요청 자체는 종결 판정이 아니다.

리뷰 핀 = `codex/lhs-v13-1104`에 push된 수정 커밋, ZIP의 `PIN.txt`에 전체 값. 현재 명령·README·두 시험과 이 증거 폴더는 그 핀의 blob 그대로다. 과거 독립 판정·원본 ZIP·초기 실패도 보존했다.

1. 최초/부분/지속 write 실패, short write, flush 실패 후 추가 JSON이 없고, 실제 CLI 종료 때 버퍼 재flush가 막히는가? 정상 buffered stdout은 한 개 JSON으로 보존되는가?
2. 계산/직렬화 실패와 출력 실패가 구분되며, shell exec가 시작 rc2·다른 비0·신호 종료 뒤 fallback을 만들지 않는가? 정상 stdout 한정과 프로세스 rc 검사의 문구가 충분한가?
3. LPI-02는 시간 상한 부재를 명시하고 원래 합성 반례를 보존했는가? B7/압력 규칙·등록값을 바꾸거나 느린 입력을 해결했다고 과장하지 않았는가?
4. 최초 기존20개 시험에서 한 번 나온 expected0/observed2와 후속 진단/순차 통과를 숨기지 않았는가? 이 관찰이 이번 출력 변경과 별도로 추가 조사가 필요한지 판단해 달라. 실제 원인은 아직 미확정이다.

사전 공격 ① 숫자/전칭: 20개 기존·13개 출력 시험을 해석기별로 구분하고 before6FAIL·최초20개중1FAIL을 함께 보존. ② HOLD: 전체 게이트·실제 실행/배포 GO 없음. ③ 계약: 정상 stdout과 장애 stdout을 구분, 단일 write 원자성 주장 없음. ④ 반례/변이: 출력 재시도·flush·종료·short write·shell fallback 보호 제거 다섯 변이 실패를 기록. 처음 7,179개 외부 파서 대조를 이번 재실행 숫자로 세지 않는다.

수정자는 자체 CLOSED하지 않았다. 발송은 1저자, 판정은 별도 독립 반박 리뷰 창이다.
