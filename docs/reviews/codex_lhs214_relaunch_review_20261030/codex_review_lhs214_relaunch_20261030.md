## 3. Q2 — 등록된 순서의 발사 확인 GO

수용하는 순서는 **⑤ 승인 → B7/환경/ROOT 현장 확인 → 194 → 실제 완료·audit·재시도 예외 확인 → 보충 20 → 두 실제 manifest와 전체 승인 SHA를 대조하는 영수증**이다.

### 3-1. 끝 블록은 자동 중단 스크립트가 아니다

- 핀 불일치 줄은 경고를 출력한다. 셸의 자동 `exit`가 아니다.
- `run`에는 `--approved-sha` 인자가 없다. 보충 실행기는 194 완료를 직접 조회하지 않는다.
- `tee | tail`은 앞 실행기의 실패 코드를 자동으로 보존하여 다음 명령을 차단하지 않는다.
- 382행은 주석이다. 복붙만 하면 audit가 실행되지 않는다.

따라서 **194 실패 후 성공한 tail을 거쳐 보충 명령까지 도달하는 전체 블록 자동 실행**은 가능한 반례다. 그러나 이는 문서가 명시한 수동 확인을 생략한 사용법이다. 이를 등록된 수동 절차 자체의 새 P1로 중복 등재하지 않는다. Bash/WSL에서 이 반례를 실행한 것은 아니며, 셸 구문과 호출 관계에서 확인한 한계다.

운영 표현은 “각 단계를 따로 실행하고 기준 불충족 시 진행하지 않음”으로 유지해야 한다. 전체 블록을 무인 자동 발사 스크립트라고 소개하거나, 이번 GO를 그 자동화의 검증으로 붙이면 안 된다.

### 3-2. L214P-02 — 열림 유지, 전체 40자리 대조의 방어는 실재

`run_network_194_parallel.py:1140`의 `_HEX40.match()`는 마지막 LF를 여전히 허용한다. 수정되지 않은 결함을 닫힘으로 바꾸지 않는다. 실제 `launch_eligibility()`와 `_manifest_checks()`에 합성 manifest를 넣어 다음 경계를 재현했다. [기존 형식 검사](https://github.com/yonghoon7153-source/Yonghoon-DEM-DFT/blob/bf8cf21c6466cdb9411f9320711b871c2d1c651e/scripts/run_network_194_parallel.py#L1140), [F7/G7의 실제 대조](https://github.com/yonghoon7153-source/Yonghoon-DEM-DFT/blob/bf8cf21c6466cdb9411f9320711b871c2d1c651e/scripts/supp20_input_receipt.py#L357)

| manifest SHA | 승인 인자 | 형식 자격 | F7 |
|---|---|---|---|
| 정확한 B7 40자리 | B7 40자리 | current | 통과 |
| B7 + LF | B7 40자리 | current | **거부** |
| B7 + LF | B7 앞 7자리 | current | **거부** |
| B7 + LF | 생략 | current | 검사 없음 |
| 마지막 자리만 다른 유효 40자리 | B7 40자리 | current | **거부** |
| 같은 오값 40자리 | B7 앞 7자리 | current | 통과 |
| 같은 오값 40자리 | 생략·빈 문자열 | current | 검사 없음 |

7자리도 LF 자체는 거부한다. 7자리의 문제는 **같은 접두의 다른 유효 커밋**을 허용한다는 것이다. 전체 40자리 승인값이면 `fullmatch`와 `startswith`의 조합이 정확한 SHA 일치가 된다. F7/G7은 같은 함수를 사용한다.

탐침은 SHA 경계 10형과 상태 경계 3형이다. 이 합성 사본에는 수확 자료가 없어 F2가 실패했으므로 표를 “전체 발사 영수증 rc 0”이라고 표시하지 않았다. 이번 실제 24/24는 §2의 **원 preflight** 재현이고, 위 표는 특정 검증 함수의 경계 확인이다.

이번 운영에서 승인값을 생략하거나 7자리로 줄이면 GO의 전제가 깨진다. 알려진 한 줄 수정의 발사 후 처리 결정은 그대로 수용하며, 수정 완료로 기록하지 않는다.

### 3-3. current·preflight PASS는 생산 완료가 아니다

완료 필드 부재, `completed=false`, dirty/mixed override가 기재된 retry 기록을 넣은 합성 manifest도 `launch_eligibility()`는 current로 분류했다. 이는 실행 **형식** 자격의 정의와 맞는다. 실제 완료·재시도 정책 승인까지 인증하는 함수가 아니다.

보존·재현한 24칸 receipt는 `manifest=null`, `primary_manifest=null`, `scope=preflight`다. 실제 F/G/H, 완료 audit, 등록 §5, 배포 관문이 아직 수행되지 않았다는 사실을 바꾸지 않는다. 실제 영수증 실패를 사전 점검 PASS로 덮을 수 없다.
